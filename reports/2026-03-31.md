### 第二模块：核心架构解释

LOME 的核心架构建立在预训练的视频扩散模型（Wan2.1-VACE-14B）之上，通过引入空间动作图和联合去噪机制来实现精准的物理交互模拟。

**数据预处理与特征提取流程：**
1. **环境初始化**：输入参考图像 $I$ 通过 VAE 编码为干净的图像潜变量 $x^I$。
2. **相机位姿注入**：将每帧的相机外参 $\zeta$ 和内参 $K$ 转换为射线图（Plücker embeddings），通过轻量级相机适配器提取特征 $z$，并与加噪的视频潜变量 $x$ 逐元素相加。
3. **动作图光栅化**：将 3D 人体/手部关键点 $P_t$ 投影到 2D 图像平面，光栅化为带有背景掩码的 2D 动作图 $\hat{A}$，再通过 VAE 编码为动作潜变量 $a$。

**联合去噪与生成流程：**
1. **潜变量拼接**：将干净的图像潜变量 $x^I$ 与注入相机特征的加噪视频潜变量 $(x+z)$ 在时间维度拼接，得到环境潜变量 $\hat{x}$。随后，将加噪的动作潜变量 $a$ 与 $\hat{x}$ 再次在时间维度拼接，构建联合分布输入。
2. **DiT 联合去噪**：扩散 Transformer（DiT）在文本提示 $c$ 的条件下，同时预测动作和视频的噪声/速度场。
3. **修正的无分类器引导（Modified CFG）**：在推理阶段，由于动作 $a$ 本身也是被模型去噪的输出，传统的 CFG 不再适用。模型采用了一种修正的引导公式，综合考虑文本/相机条件以及动作变量的非独立性。

```python
    def __init__(self, pretrained_vae, pretrained_dit, camera_adapter):
        super().__init__()
        self.vae = pretrained_vae
        self.dit = pretrained_dit # Wan2.1-VACE-14B (Frozen DiT + LoRA on VACE)
        self.camera_adapter = camera_adapter
        
    def forward(self, image_I, video_V, action_maps_A, camera_poses, text_c, t):
        # 1. Encode inputs via VAE
        x_I = self.vae.encode(image_I) # Clean image latent
        x_V = self.vae.encode(video_V) # Clean video latent
        a_clean = self.vae.encode(action_maps_A) # Clean action latent
        
        # 2. Add noise to video and action latents (Flow Matching / Diffusion)
        noise_V = torch.randn_like(x_V)
        noise_a = torch.randn_like(a_clean)
        x_noisy = (1 - t) * x_V + t * noise_V
        a_noisy = (1 - t) * a_clean + t * noise_a
        
        # 3. Process camera features
        ray_maps = compute_plucker_embeddings(camera_poses)
        z_cam = self.camera_adapter(ray_maps)

        # x_I is noise-free anchor, x_noisy is conditioned on camera
        x_env = torch.cat([x_I, x_noisy + z_cam], dim=time_axis) 
        
        # 5. Joint Action-Environment Modeling (Temporal Concatenation)
        # Crucial innovation: concatenate action and environment along time
        joint_latent = torch.cat([a_noisy, x_env], dim=time_axis)
        
        # 6. Denoise using DiT
        # Predicts velocity field for both action and video
        pred_velocity = self.dit(joint_latent, text_c, t) 
        
        # Loss computation (Flow Matching objective)
        target_velocity_V = noise_V - x_V
        target_velocity_a = noise_a - a_clean
        target_velocity_joint = torch.cat([target_velocity_a, target_velocity_V], dim=time_axis)
        
        loss = mse_loss(pred_velocity, target_velocity_joint)
        return loss

    def inference_step(self, joint_latent, text_c, t, w1=5, w2=3):
        # Modified CFG implementation based on Eq. 7
        # v_cond: conditioned on text and camera
        # v_uncond_text: conditioned on camera only (text = empty)
        # v_uncond_all: no text, no camera
        
        v_cond = self.dit(joint_latent, text_c, t)
        v_uncond_text = self.dit(joint_latent, empty_text, t)
        v_uncond_all = self.dit(joint_latent, empty_text_and_cam, t)
        
        # Modified guidance formula
        v_guided = (1 + w1 + w2) * v_cond - w1 * v_uncond_text - w2 * v_uncond_all
```

### 第二模块：核心架构解释

ManipArena 并非单一的算法模型，而是一个软硬件结合、虚实同步的标准化评估系统。其核心架构与实验流程可拆解为以下四个维度：

1. **受控物理环境与统一硬件**
系统采用绿幕封闭空间（Green-screen enclosure）与固定人工光源，彻底消除背景和光照变化带来的视觉干扰。硬件上统一使用 X2Robot 双臂系统（桌面级与移动底盘级），确保性能差异仅来源于策略模型本身，而非硬件或环境噪声。

2. **系统化多样性与分级 OOD 测试**
训练数据在外观（材质/颜色）、空间布局和语义组合三个层级进行均匀采样。评估时，每个任务的 10 次测试（Trials）被严格分级：T1-T4 为域内测试（In-domain），T5-T8 为视觉偏移（Visual Shift），T9-T10 为语义分布外（Semantic OOD）。这种设计允许在单次评估中直接绘制出模型的泛化衰减曲线。

3. **服务端推理协议（Server-Side Inference）**
强制执行“一模多用（One-model-for-all-tasks）”规则。参赛者不接触物理硬件，只需部署一个 HTTP 端点。评估系统将实时摄像头图像和本体感受数据（包含 56D/62D 的位置、速度、电机电流）发送至该端点，模型返回动作指令。

4. **细粒度部分计分制（Partial Credit Scoring）**
摒弃传统的二元成功率（Success/Failure），将每个任务拆解为多个有序子任务（如：抓取 -> 移动 -> 倾倒 -> 复位）。按完成的子步骤给予 0-10 的部分得分，从而精确诊断模型是死于“粗粒度空间规划”还是“细粒度接触控制”。

### 第二模块：核心架构解释

ProgressVLA 的架构与运行流程可解构为三个核心阶段：预训练、进度引导推理、以及在线强化学习微调。

1. **模块预训练 (Pretraining)**
模型包含三个独立预训练的组件：
- **进度评估器 (Progress Estimator)**：输入语言指令、初始图像和当前图像，输出 $[0, 1]$ 的标量表示任务完成度。训练时巧妙地利用专家轨迹中的归一化时间步 $t/T$ 作为伪标签。
- **世界模型 (World Model)**：包含编码器（逆动力学，从前后帧提取隐动作）和解码器（前向动力学，根据当前帧和隐动作预测未来隐状态）。
- **隐动作专家 (Latent Action Expert)**：一个在紧凑隐空间中运行的扩散策略模型。

2. **进度引导的扩散推理 (Progress-Guided Diffusion Inference)**

- 给定当前带噪隐动作，世界模型预测其导致的未来视觉特征。
- 进度评估器对该未来特征进行打分。
- 计算进度分数对带噪隐动作的梯度，利用该梯度修改扩散模型的去噪方向。

3. **在线 RL 微调 (Online RL Finetuning)**

- 挖掘非单调的进度异常点（即动作成功了但预测进度却下降的时刻），施加单调性惩罚损失。
- 使用 KL 正则化的策略改进，将进度最大化目标蒸馏回扩散策略本身。

```python
    obs: 当前视觉观察

    future_latent_state = world_model.decode(obs, x_t)

    progress_score = progress_estimator(instruction, initial_obs, future_latent_state)

    grad = torch.autograd.grad(outputs=progress_score, inputs=x_t)[0]

    # 7. 执行标准 DDIM/DDPM 步更新
    x_prev = ddim_step(x_t, t, guided_noise_pred)
    
    return x_prev.detach()
```

### 第二模块：核心架构解释

StreamingVLA 的核心架构通过两个维度的异步并行重构了 VLA 的推理流程：

**维度一：生成与执行的并行（基于状态的动作流匹配）**
传统的 Diffusion 策略需要完整的去噪步数才能输出一个可用的动作块。StreamingVLA 将动作建模从“预测绝对动作值”重构为“预测物理状态的更新量”。模型输出的是动作轨迹流的速度场 $v_\theta(x_t, t|o)$，通过积分（离散化后为累加）即可逐个生成动作 $a_t$。这使得模型生成第一个动作后，机械臂即可立即执行，后续动作的生成与当前动作的执行完全重叠。

**维度二：执行与观测的并行（动作显著性感知的自适应提前观测）**
为了掩盖 VLM 处理视觉 Token 的巨大延迟，系统需要在当前动作块执行完毕前，提前启动下一次 VLM 观测。但如果当前动作会引起环境剧变（如拉开抽屉），提前观测会导致 VLM 看到“错误”的旧画面。因此，架构中加入了一个轻量级 Transformer 预测器，输入当前图像特征和剩余动作，预测执行这些动作后的图像特征变化量（$\Delta embedding$）。如果变化量低于阈值（动作显著性低），则安全触发提前观测。

**核心逻辑伪代码 (Python 风格):**

```python
def streaming_vla_inference(vla_model, saliency_predictor, env, threshold_eta):
    observation = env.get_observation()
    action_state = 0.0  # 初始化动作空间状态
    t = 0
    horizon = 10
    need_new_obs = True
    
    while task_not_finished:
        # 1. 异步观测处理 (与执行重叠)
        if need_new_obs:
            vlm_latents = vla_model.process_observation(observation)
            need_new_obs = False
            
        # 2. 流式动作生成 (Action Flow Matching)
        # 预测速度场并计算当前步的动作
        velocity = vla_model.action_expert(action_state, t/horizon, vlm_latents)
        action = velocity * (1.0 / horizon) 
        
        # 3. 自适应提前观测评估 (Adaptive Early Observation)
        if horizon - t == early_obs_step:
            # 预测剩余动作对视觉特征的影响
            delta_embed = saliency_predictor(vlm_latents, remaining_actions)
            if norm(delta_embed) <= threshold_eta:
                need_new_obs = True  # 动作显著性低，安全触发提前观测
                
        # 4. 边界条件：如果到最后一步仍未观测，强制触发
        if horizon - t == 0:
            need_new_obs = True
            t = 0
            continue
            
        # 5. 立即执行并更新状态
        env.execute_async(action)
        action_state = action_state + action # 保持动作空间与物理空间的对齐
        t += 1
```

### 第二模块：核心架构解释

本研究的核心架构分为两个主要部分：**LIBERO-Para 数据集生成管线** 与 **PRIDE 评估指标及失败分类机制**。

**1. LIBERO-Para 数据集生成管线**
采用模块化的 LLM 代理工作流，确保生成的复述指令既保持原意又符合语法：
- **单轴生成 (Axis-wise Generation)**：针对原始指令，分别在“动作轴”（10种类型，如词汇替换、句法重构、语用暗示）和“对象轴”（3种类型，如同义词替换、添加修饰）生成候选。
- **单轴验证 (Verification)**：过滤掉改变核心语义或不符合物理场景的候选。
- **双轴合并 (Merging)**：将验证通过的动作和对象变体进行组合，生成复合复述指令。
- **最终验证 (Final Verification)**：确保合并后的指令自然且无歧义，最终生成 4,092 条测试指令。

**2. PRIDE 评估指标与 DTW 失败分类**
- **PRIDE (Paraphrase Robustness Index)**：传统成功率是 0 或 1。PRIDE 将成功率与指令的“语言偏离度”结合。偏离度由两部分组成：关键词相似度（$S_K$，基于 Sentence-BERT 提取内容词的余弦相似度）和结构相似度（$S_T$，基于依存句法树的树编辑距离 TED）。
- **失败分类**：利用动态时间规整（DTW）算法计算失败轨迹与成功轨迹（伪真实轨迹 GT）的距离。距离小于阈值判定为执行级失败（Near-GT），大于阈值判定为规划级失败（Far-GT）。

**核心逻辑伪代码实现**：

```python
import numpy as np
from sentence_transformers import SentenceTransformer
from zss import simple_distance, Node # For Tree Edit Distance
from fastdtw import fastdtw

class PRIDEEvaluator:
    def __init__(self, alpha=0.5):
        self.alpha = alpha
        self.encoder = SentenceTransformer('all-MiniLM-L6-v2')
        
    def compute_keyword_similarity(self, orig_words, para_words):
        # 提取内容词并计算余弦相似度
        emb_orig = self.encoder.encode(orig_words)
        emb_para = self.encoder.encode(para_words)
        
        sim_scores = []
        for e_o in emb_orig:
            # 找到最相似的词
            cos_sims = np.dot(emb_para, e_o) / (np.linalg.norm(emb_para, axis=1) * np.linalg.norm(e_o))
            sim_scores.append(np.max(cos_sims))
        return np.mean(sim_scores)
        
    def compute_structural_similarity(self, tree_orig, tree_para):
        # 计算依存句法树的树编辑距离 (TED)
        ted = simple_distance(tree_orig, tree_para)
        size_orig = self.get_tree_size(tree_orig)
        size_para = self.get_tree_size(tree_para)
        return 1.0 - (ted / (size_orig + size_para))
        
    def calculate_pride(self, orig_inst, para_inst, is_success):
        if not is_success:
            return 0.0
            
        s_k = self.compute_keyword_similarity(orig_inst.content_words, para_inst.content_words)
        s_t = self.compute_structural_similarity(orig_inst.dep_tree, para_inst.dep_tree)
        
        # 计算复述距离 (Paraphrase Distance)
        pd = 1.0 - (self.alpha * s_k + (1 - self.alpha) * s_t)
        return pd

def classify_failure(failed_traj, success_trajs, threshold):
    # 计算伪真实轨迹 (Pseudo-GT)
    pseudo_gt = np.mean(success_trajs, axis=0)
    
    # 仅使用末端执行器(EEF)的绝对位置 (x, y, z)
    failed_eef = failed_traj[:, :3]
    gt_eef = pseudo_gt[:, :3]
    
    # 计算 DTW 距离
    distance, _ = fastdtw(failed_eef, gt_eef, dist=lambda x, y: np.linalg.norm(x - y))
    normalized_distance = distance / len(failed_eef)
    
    if normalized_distance <= threshold:
        return "Near-GT" # 执行级失败 (底层控制误差)
    else:
        return "Far-GT"  # 规划级失败 (任务识别错误)
```

### 第二模块：核心架构解释

Uni-World VLA 的核心架构是一个统一的自回归多模态大语言模型（基于 Phi-1.5 的 Show-o 架构），其数据流转与实验流程可拆解为以下三个关键阶段：

1.  **多模态输入与分词 (Tokenization & Depth Integration)**
    *   模型接收历史图像序列，使用 MagVIT-v2 将其离散化为两类视觉 Token：高分辨率的上下文 Token（捕捉静态语义）和低分辨率的动态 Token（捕捉高频运动）。
    *   使用 Depth Anything 3 提取单目深度图，通过两个深度编码器（CDE/DDE）提取深度特征。
    *   **深度融合**：将视觉 Token 作为 Query，深度特征作为 Key 和 Value，通过交叉注意力机制（Cross-Attention）将几何空间信息注入到视觉 Token 中。
2.  **交替自回归生成 (Interleaved Autoregressive Generation)**
    *   将系统提示词、用户提示词、融合后的历史视觉 Token 以及历史自车状态 Token 拼接为一维序列输入 LLM。
    *   LLM 按照严格的时间因果顺序进行自回归预测：生成 $t+1$ 时刻的画面 Token $\rightarrow$ 生成 $t+1$ 时刻的动作 Token $\rightarrow$ 生成 $t+2$ 时刻的画面 Token $\rightarrow$ ...
    *   在生成过程中，利用 KV-Cache 机制缓存历史特征，避免重复计算，实现高效的步进式推理。
3.  **解码与监督 (Decoding & Supervision)**
    *   预测的视觉 Token 通过 MagVIT-v2 解码器还原为 RGB 视频帧，使用动态焦点损失（Dynamic Focal Loss）进行监督，以强化对画面中运动物体的预测。
    *   预测的动作 Token 通过 MLP 映射为具体的轨迹坐标，使用 L1 损失进行监督。

```python
        key=depth_features, 
        value=depth_features
    )

    future_actions = []

    for t in range(future_steps):
        # 预测 t 时刻的未来画面 Token
        frame_tokens_t = llm.generate_visual_tokens(context)

        action_tokens_t = llm.generate_action_tokens(context)

        trajectory_waypoint = mlp_head(action_tokens_t)

        future_actions.append(trajectory_waypoint)
        
    return future_frames, future_actions
```

### 第二模块：核心架构解释

LOME 的核心架构建立在预训练的视频扩散模型（Wan2.1-VACE-14B）之上，通过引入空间动作图和联合去噪机制来实现精准的物理交互模拟。

**数据预处理与特征提取流程：**
1. **环境初始化**：输入参考图像 $I$ 通过 VAE 编码为干净的图像潜变量 $x^I$。
2. **相机位姿注入**：将每帧的相机外参 $\zeta$ 和内参 $K$ 转换为射线图（Plücker embeddings），通过轻量级相机适配器提取特征 $z$，并与加噪的视频潜变量 $x$ 逐元素相加。
3. **动作图光栅化**：将 3D 人体/手部关键点 $P_t$ 投影到 2D 图像平面，光栅化为带有背景掩码的 2D 动作图 $\hat{A}$，再通过 VAE 编码为动作潜变量 $a$。

**联合去噪与生成流程：**
1. **潜变量拼接**：将干净的图像潜变量 $x^I$ 与注入相机特征的加噪视频潜变量 $(x+z)$ 在时间维度拼接，得到环境潜变量 $\hat{x}$。随后，将加噪的动作潜变量 $a$ 与 $\hat{x}$ 再次在时间维度拼接，构建联合分布输入。
2. **DiT 联合去噪**：扩散 Transformer（DiT）在文本提示 $c$ 的条件下，同时预测动作和视频的噪声/速度场。
3. **修正的无分类器引导（Modified CFG）**：在推理阶段，由于动作 $a$ 本身也是被模型去噪的输出，传统的 CFG 不再适用。模型采用了一种修正的引导公式，综合考虑文本/相机条件以及动作变量的非独立性。

```python
import torch.nn as nn

class LOME(nn.Module):

        super().__init__()
        self.vae = pretrained_vae
        self.dit = pretrained_dit # Wan2.1-VACE-14B (Frozen DiT + LoRA on VACE)
        self.camera_adapter = camera_adapter
        
    def forward(self, image_I, video_V, action_maps_A, camera_poses, text_c, t):
        # 1. Encode inputs via VAE
        x_I = self.vae.encode(image_I) # Clean image latent
        x_V = self.vae.encode(video_V) # Clean video latent
        a_clean = self.vae.encode(action_maps_A) # Clean action latent
        
        # 2. Add noise to video and action latents (Flow Matching / Diffusion)
        noise_V = torch.randn_like(x_V)
        noise_a = torch.randn_like(a_clean)
        x_noisy = (1 - t) * x_V + t * noise_V
        a_noisy = (1 - t) * a_clean + t * noise_a
        
        # 3. Process camera features
        ray_maps = compute_plucker_embeddings(camera_poses)
        z_cam = self.camera_adapter(ray_maps)

        # x_I is noise-free anchor, x_noisy is conditioned on camera
        x_env = torch.cat([x_I, x_noisy + z_cam], dim=time_axis) 
        
        # 5. Joint Action-Environment Modeling (Temporal Concatenation)
        # Crucial innovation: concatenate action and environment along time
        joint_latent = torch.cat([a_noisy, x_env], dim=time_axis)
        
        # 6. Denoise using DiT
        # Predicts velocity field for both action and video
        pred_velocity = self.dit(joint_latent, text_c, t) 
        
        # Loss computation (Flow Matching objective)
        target_velocity_V = noise_V - x_V
        target_velocity_a = noise_a - a_clean
        target_velocity_joint = torch.cat([target_velocity_a, target_velocity_V], dim=time_axis)
        
        loss = mse_loss(pred_velocity, target_velocity_joint)
        return loss

    def inference_step(self, joint_latent, text_c, t, w1=5, w2=3):
        # Modified CFG implementation based on Eq. 7
        # v_cond: conditioned on text and camera
        # v_uncond_text: conditioned on camera only (text = empty)
        # v_uncond_all: no text, no camera
        
        v_cond = self.dit(joint_latent, text_c, t)
        v_uncond_text = self.dit(joint_latent, empty_text, t)
        v_uncond_all = self.dit(joint_latent, empty_text_and_cam, t)
        
        # Modified guidance formula
        v_guided = (1 + w1 + w2) * v_cond - w1 * v_uncond_text - w2 * v_uncond_all
        return v_guided
```

4. **细粒度部分计分制（Partial Credit Scoring）**

```python
class ManipArenaEvaluator:
    def __init__(self, robot_hardware, task_config):
        self.robot = robot_hardware
        self.task = task_config
        self.max_score_per_trial = 10.0
        
    def evaluate_model(self, model_endpoint):
        total_score = 0.0
        
        # 严格的 10 次分级测试: T1-T4(域内), T5-T8(视觉偏移), T9-T10(语义OOD)
        for trial_idx, trial_condition in enumerate(self.task.get_stratified_trials(10)):
            self.robot.reset_environment(trial_condition)
            sub_tasks = self.task.get_subtasks()
            trial_score = 0.0
            
            # 运行单次 Trial
            while not self.task.is_timeout() and not self.robot.is_unsafe():
                # 1. 获取丰富传感器数据 (包含关节速度与电机电流)
                obs = self.robot.get_observation(include_currents_and_velocities=True)
                
                # 2. 服务端推理调用 (强制单一模型处理所有任务)
                action = model_endpoint.predict(obs, self.task.language_instruction)
                
                # 3. 执行动作
                self.robot.step(action)
                
                # 4. 细粒度子任务状态机检测
                current_subtask = sub_tasks[0]
                if current_subtask.check_success(self.robot.state, self.task.objects):
                    trial_score += current_subtask.weight_score
                    sub_tasks.pop(0) # 进入下一个子任务
                    
                    if len(sub_tasks) == 0:
                        break # 完整任务成功
                        
            total_score += trial_score
            self.log_diagnostic_data(trial_idx, trial_condition.ood_level, trial_score)
            
        return total_score
```

### 第二模块：核心架构解释

ProgressVLA 的架构与运行流程可解构为三个核心阶段：预训练、进度引导推理、以及在线强化学习微调。

1. **模块预训练 (Pretraining)**
模型包含三个独立预训练的组件：
- **进度评估器 (Progress Estimator)**：输入语言指令、初始图像和当前图像，输出 $[0, 1]$ 的标量表示任务完成度。训练时巧妙地利用专家轨迹中的归一化时间步 $t/T$ 作为伪标签。
- **世界模型 (World Model)**：包含编码器（逆动力学，从前后帧提取隐动作）和解码器（前向动力学，根据当前帧和隐动作预测未来隐状态）。
- **隐动作专家 (Latent Action Expert)**：一个在紧凑隐空间中运行的扩散策略模型。

2. **进度引导的扩散推理 (Progress-Guided Diffusion Inference)**
在推理阶段，模型采用两阶段生成：先生成高维隐动作，再解码为底层物理动作。在隐动作的去噪过程中，引入分类器引导：
- 给定当前带噪隐动作，世界模型预测其导致的未来视觉特征。
- 进度评估器对该未来特征进行打分。
- 计算进度分数对带噪隐动作的梯度，利用该梯度修改扩散模型的去噪方向。

3. **在线 RL 微调 (Online RL Finetuning)**
为了解决评估器在分布外失效的问题，作者引入在线经验收集：
- 挖掘非单调的进度异常点（即动作成功了但预测进度却下降的时刻），施加单调性惩罚损失。
- 使用 KL 正则化的策略改进，将进度最大化目标蒸馏回扩散策略本身。

```python
def progress_guided_denoising_step(x_t, t, obs, instruction, world_model, progress_estimator, guidance_scale):
    """
    x_t: 当前时间步 t 的带噪隐动作
    obs: 当前视觉观察
    """
    # 1. 扩散模型预测基础噪声 (无引导)
    noise_pred = diffusion_model(x_t, t, obs, instruction)
    
    # 2. 开启梯度追踪以计算分类器引导
    x_t.requires_grad_(True)
    
    # 3. 世界模型前向预测：基于当前观察和带噪动作，预测未来隐状态
    future_latent_state = world_model.decode(obs, x_t)
    
    # 4. 进度评估器打分：评估未来状态的任务完成度
    progress_score = progress_estimator(instruction, initial_obs, future_latent_state)
    
    # 5. 计算进度分数对带噪动作的梯度
    grad = torch.autograd.grad(outputs=progress_score, inputs=x_t)[0]
    
    # 6. 注入分类器引导：修改去噪方向，使其偏向高进度区域 (对应论文 Eq. 11 / Eq. 19)
    # 注意：实际实现中会根据 variance-preserving 扩散公式调整缩放系数
    guided_noise_pred = noise_pred - guidance_scale * grad
    
    # 7. 执行标准 DDIM/DDPM 步更新
    x_prev = ddim_step(x_t, t, guided_noise_pred)
    
    return x_prev.detach()
```

**1. LIBERO-Para 数据集生成管线**

**2. PRIDE 评估指标与 DTW 失败分类**
- **PRIDE (Paraphrase Robustness Index)**：传统成功率是 0 或 1。PRIDE 将成功率与指令的“语言偏离度”结合。偏离度由两部分组成：关键词相似度（$S_K$，基于 Sentence-BERT 提取内容词的余弦相似度）和结构相似度（$S_T$，基于依存句法树的树编辑距离 TED）。
- **失败分类**：利用动态时间规整（DTW）算法计算失败轨迹与成功轨迹（伪真实轨迹 GT）的距离。距离小于阈值判定为执行级失败（Near-GT），大于阈值判定为规划级失败（Far-GT）。

**核心逻辑伪代码实现**：

```python
import numpy as np
from sentence_transformers import SentenceTransformer
from zss import simple_distance, Node # For Tree Edit Distance
from fastdtw import fastdtw

class PRIDEEvaluator:
    def __init__(self, alpha=0.5):
        self.alpha = alpha
        self.encoder = SentenceTransformer('all-MiniLM-L6-v2')
        
    def compute_keyword_similarity(self, orig_words, para_words):
        # 提取内容词并计算余弦相似度
        emb_orig = self.encoder.encode(orig_words)
        emb_para = self.encoder.encode(para_words)
        
        sim_scores = []
        for e_o in emb_orig:
            # 找到最相似的词
            cos_sims = np.dot(emb_para, e_o) / (np.linalg.norm(emb_para, axis=1) * np.linalg.norm(e_o))
            sim_scores.append(np.max(cos_sims))
        return np.mean(sim_scores)
        
    def compute_structural_similarity(self, tree_orig, tree_para):
        # 计算依存句法树的树编辑距离 (TED)
        ted = simple_distance(tree_orig, tree_para)
        size_orig = self.get_tree_size(tree_orig)
        size_para = self.get_tree_size(tree_para)
        return 1.0 - (ted / (size_orig + size_para))
        
    def calculate_pride(self, orig_inst, para_inst, is_success):
        if not is_success:
            return 0.0
            
        s_k = self.compute_keyword_similarity(orig_inst.content_words, para_inst.content_words)
        s_t = self.compute_structural_similarity(orig_inst.dep_tree, para_inst.dep_tree)
        
        # 计算复述距离 (Paraphrase Distance)
        pd = 1.0 - (self.alpha * s_k + (1 - self.alpha) * s_t)
        return pd

def classify_failure(failed_traj, success_trajs, threshold):
    # 计算伪真实轨迹 (Pseudo-GT)
    pseudo_gt = np.mean(success_trajs, axis=0)
    
    # 仅使用末端执行器(EEF)的绝对位置 (x, y, z)
    failed_eef = failed_traj[:, :3]
    gt_eef = pseudo_gt[:, :3]
    
    # 计算 DTW 距离
    distance, _ = fastdtw(failed_eef, gt_eef, dist=lambda x, y: np.linalg.norm(x - y))
    normalized_distance = distance / len(failed_eef)
    
    if normalized_distance <= threshold:
        return "Near-GT" # 执行级失败 (底层控制误差)
    else:
        return "Far-GT"  # 规划级失败 (任务识别错误)
```

### 第二模块：核心架构解释

Uni-World VLA 的核心架构是一个统一的自回归多模态大语言模型（基于 Phi-1.5 的 Show-o 架构），其数据流转与实验流程可拆解为以下三个关键阶段：

1.  **多模态输入与分词 (Tokenization & Depth Integration)**
    *   模型接收历史图像序列，使用 MagVIT-v2 将其离散化为两类视觉 Token：高分辨率的上下文 Token（捕捉静态语义）和低分辨率的动态 Token（捕捉高频运动）。
    *   使用 Depth Anything 3 提取单目深度图，通过两个深度编码器（CDE/DDE）提取深度特征。
    *   **深度融合**：将视觉 Token 作为 Query，深度特征作为 Key 和 Value，通过交叉注意力机制（Cross-Attention）将几何空间信息注入到视觉 Token 中。
2.  **交替自回归生成 (Interleaved Autoregressive Generation)**
    *   将系统提示词、用户提示词、融合后的历史视觉 Token 以及历史自车状态 Token 拼接为一维序列输入 LLM。
    *   LLM 按照严格的时间因果顺序进行自回归预测：生成 $t+1$ 时刻的画面 Token $\rightarrow$ 生成 $t+1$ 时刻的动作 Token $\rightarrow$ 生成 $t+2$ 时刻的画面 Token $\rightarrow$ ...
    *   在生成过程中，利用 KV-Cache 机制缓存历史特征，避免重复计算，实现高效的步进式推理。
3.  **解码与监督 (Decoding & Supervision)**
    *   预测的视觉 Token 通过 MagVIT-v2 解码器还原为 RGB 视频帧，使用动态焦点损失（Dynamic Focal Loss）进行监督，以强化对画面中运动物体的预测。
    *   预测的动作 Token 通过 MLP 映射为具体的轨迹坐标，使用 L1 损失进行监督。

```python
    depth_maps = depth_anything_v3(history_frames)
    depth_features = depth_encoder(depth_maps)

    fused_visual_tokens = cross_attention(
        query=visual_tokens, 
        key=depth_features, 
        value=depth_features
    )

    future_frames = []
    future_actions = []

    for t in range(future_steps):
        # 预测 t 时刻的未来画面 Token

        # 预测 t 时刻的自车动作 Token (Conditioned on 刚预测的画面)
        action_tokens_t = llm.generate_action_tokens(context)
        context = concat([context, action_tokens_t]) # 将新动作加入上下文
        
        # 解码
        rgb_frame = magvit_decoder.decode(frame_tokens_t)
        trajectory_waypoint = mlp_head(action_tokens_t)
        
        future_frames.append(rgb_frame)
        future_actions.append(trajectory_waypoint)
        
    return future_frames, future_actions
```

### 第二模块：核心架构解释

FlowRL 框架在逻辑上分为理论分类体系与工程软件架构两部分。

**理论分类体系 (Taxonomy)**
论文将现有的 Diffusion RL 算法映射到一个二维矩阵中：
1.  **引导机制 (Guidance Method)**：决定如何利用 Q 值优化策略。包含四类：Q 值引导（直接注入动作梯度）、加权匹配（将 Q 值转化为样本权重进行监督学习）、重参数化（通过去噪链反向传播梯度）、策略梯度（近似或离散化计算策略比率）。

1.  **网络架构层**：支持标准 MLP 以及现代高容量架构（如 SimBa、BroNet）。
2.  **模型层**：统一封装离散/连续时间 DDPM、连续标准化流（CNF）以及 Actor-Critic 价值网络。
3.  **算法层**：将 RL 逻辑拆分为初始化、JIT 编译的更新逻辑和开箱即用的采样逻辑。
4.  **工作流层**：基于 Hydra 的配置管理，支持多后端日志记录，并集成大规模并行仿真环境（IsaacLab）。

### 第二模块：核心架构解释

HiFlow 的架构摒弃了复杂的两阶段训练，实现了一个完全在连续空间中运行的端到端单阶段生成流程。其核心由三个关键步骤构成：

**1. 无分词器的多尺度动作表示 (Tokenization-Free Multi-Scale Representation)**
给定一个长度为 $T$ 的专家动作序列，模型不使用 VQ-VAE，而是直接在时间轴上进行分组平均池化（Downsampling）。尺度 $i$ 越小，池化窗口越大，代表全局粗略轨迹；尺度 $i$ 越大，分辨率越高，代表局部精细动作。

**2. 尺度级自回归 Transformer (Scale-Wise Autoregressive Transformer, ScaleAR)**
视觉和本体感觉输入被编码为全局条件向量。ScaleAR 接收上一尺度上采样后的动作作为输入，通过因果掩码（Causal Mask）确保当前尺度只能关注比它更粗的尺度。其输出作为当前尺度的局部条件特征。

**3. 尺度级流匹配 (Scale-Wise Flow Matching)**
一个共享权重的轻量级 Transformer（ActionFlowNet）负责在每个尺度上生成连续动作。它接收高斯噪声、时间步和 ScaleAR 提供的条件特征，预测将噪声映射到真实动作分布的连续速度场（Velocity Field）。所有尺度联合计算 MSE 损失，端到端优化。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class HiFlow(nn.Module):
    def __init__(self, scales=[1, 2, 4, 8]):
        super().__init__()
        self.scales = scales
        self.vision_encoder = VisionBackbone()
        self.scale_ar = ScaleARTransformer()
        self.action_flow_net = ActionFlowNet() # Shared across scales
        
    def temporal_pooling(self, action_chunk, scale):
        # action_chunk: [B, T, D]
        # Downsample to 'scale' timesteps via average pooling
        B, T, D = action_chunk.shape
        window_size = T // scale
        reshaped = action_chunk.view(B, scale, window_size, D)
        return reshaped.mean(dim=2) # [B, scale, D]

    def forward(self, obs, action_chunk):
        # 1. Encode global condition
        c_global = self.vision_encoder(obs)
        
        total_loss = 0
        
        # 2. Process each scale autoregressively
        for i, scale in enumerate(self.scales):
            # Create ground truth for current scale
            a_target = self.temporal_pooling(action_chunk, scale)
            
            # Prepare input from previous scale (teacher forcing during training)
            if i == 0:
                z_input = self.learnable_task_token
            else:
                a_prev = self.temporal_pooling(action_chunk, self.scales[i-1])
                z_input = F.interpolate(a_prev.transpose(1,2), size=scale).transpose(1,2)
                
            # 3. Get conditioning features from ScaleAR
            s_hat = self.scale_ar(z_input, c_global)
            
            # 4. Flow Matching Loss Computation
            noise = torch.randn_like(a_target)
            tau = torch.rand(a_target.shape[0], 1, 1).to(a_target.device) # Flow time
            
            # Interpolate between target and noise
            x_tau = (1 - tau) * a_target + tau * noise
            target_velocity = noise - a_target
            
            # Predict velocity
            pred_velocity = self.action_flow_net(x_tau, tau, s_hat)
            
            # Scale-proportional weighting: finer scales get higher weight
            weight = scale / self.scales[-1] 
            loss_i = weight * F.mse_loss(pred_velocity, target_velocity)
            total_loss += loss_i
            
        return total_loss
```

### 第二模块：核心架构解释

RAD-LAD 框架由两个独立但可协同的规划器组成：基于语言的 LAD 和基于规则的 RAD。

**1. LAD (Language-Based Autonomous Driving) 架构流程**
- **场景编码与对齐**：使用 PlanTF 编码器将矢量化地图（Map）和智能体（Agents）转化为高维特征，通过 MLP 适配器投影到 LLM 的 Token 空间，作为伪 Token（Pseudo-tokens）注入。
- **多模态提示与可中断推理**：将场景 Token 与自然语言提示拼接。核心创新在于**推理截断**：如果延迟要求苛刻，直接在提示词后追加 `<|plan|>` Token，模型通过单次前向传播（Prefill 阶段）提取该 Token 的隐藏状态，经过 MLP 规划头输出轨迹分类 Logits；如果算力允许，则先自回归生成一段解释性文本（Reasoning Tokens），再输出 `<|plan|>` Token。
- **轨迹分类**：不使用自回归生成坐标点，而是将规划建模为在预计算的离散轨迹词表（Trajectory Vocabulary）上的分类任务。

**2. RAD (Rule-Based Autonomous Driving) 架构流程**
- **动态拓扑重规划**：在每个时间步，根据自车当前状态重新进行图搜索（GraphSearch），提取候选路径，而不是像 PDM-Closed 那样依赖初始化时的静态路径。
- **车道变更与目标导向**：将相邻车道（甚至对向车道）加入候选拓扑，并引入欧几里得“距离目标点（Distance-to-goal）”的成本惩罚，迫使车辆在开阔区域主动推进，避免死锁。
- **上下文感知规则放松**：检测到前方拥堵死锁时，动态降低对“逆行”或“压线”的惩罚权重，允许短期的违规绕障。

**3. RAD-LAD 混合集成**
- LAD 输出粗略的轨迹原型，并通过一个零初始化的微调头（Refinement Head）预测坐标偏移量。
- 将 LAD 的微调轨迹作为额外的候选提案（Proposal）加入 RAD 的候选池中。
- 最终由 RAD 的物理规则打分器（Scorer）对所有候选轨迹进行统一评估，选出安全性与语义合理性兼备的最优轨迹。

```python
class LADPlanner:
    def __init__(self, llm_backbone, map_encoder, agent_encoder, traj_vocab):
        self.llm = llm_backbone
        self.map_enc = map_encoder
        self.agent_enc = agent_encoder
        self.plan_head = MLP() # Outputs logits over traj_vocab
        self.vocab = traj_vocab

    def forward(self, map_data, agent_data, text_prompt, compute_budget_ms):
        # 1. Encode scene to pseudo-tokens
        map_tokens = self.map_enc(map_data)
        agent_tokens = self.agent_enc(agent_data)
        
        # 2. Construct prompt
        context = [text_prompt, map_tokens, agent_tokens]
        
        # 3. Interruptible Inference Logic
        if compute_budget_ms < STRICT_LATENCY_THRESHOLD:
            # Fast path: No reasoning, single forward pass (~20Hz)
            input_seq = context + ["<|plan|>"]
            hidden_states = self.llm.prefill(input_seq)
        else:
            # Slow path: Generate reasoning tokens first (~10Hz)
            reasoning_tokens = self.llm.generate(context, max_tokens=10)
            input_seq = context + reasoning_tokens + ["<|plan|>"]
            hidden_states = self.llm.prefill(input_seq) # KV cache reused
            
        # 4. Extract plan from the specific <|plan|> token hidden state
        plan_hidden = hidden_states[-1] 
        traj_logits = self.plan_head(plan_hidden)
        best_traj_idx = argmax(traj_logits)
        
        return self.vocab[best_traj_idx]

class RADPlanner:
    def __init__(self, pdm_scorer):
        self.scorer = pdm_scorer
        
    def step(self, ego_state, map_graph, lad_trajectory=None):
        # 1. Dynamic Topological Replanning (Every step!)
        centerlines = GraphSearch(ego_state, map_graph)
        
        # 2. Topology Augmentation (Add adjacent lanes for lane-changing)
        augmented_lines = centerlines + get_adjacent_lanes(centerlines)
        
        # 3. Generate Proposals (IDM + Vocab)
        proposals = generate_idm_trajectories(ego_state, augmented_lines)
        if lad_trajectory:
            proposals.append(lad_trajectory)
            
        # 4. Goal-Directed Scoring with Rule Relaxation
        best_score = -inf
        best_traj = None
        is_blocked = check_deadlock(ego_state, map_graph)
        
        for traj in proposals:
            # Relax rules if blocked
            rule_weights = relax_weights() if is_blocked else strict_weights()
            
            # PDM cost + Euclidean distance to goal
            cost = self.scorer.compute_pdm_cost(traj, rule_weights) 
            cost += compute_goal_distance_cost(traj, global_goal)
            
            if cost > best_score:
                best_score = cost
                best_traj = traj
                
        return best_traj
```

### 第二模块：核心架构解释

$AutoDrive\text{-}P^3$ 的系统架构分为数据构建、冷启动微调、强化学习微调和双模式推理四个阶段。

1. **$P^3$-CoT 数据集构建**：从现有数据集中提取视频帧、自车状态和历史轨迹。人工与规则结合，仅筛选对驾驶决策有直接影响的“关键目标（Key Objects）”。使用 Qwen2.5-VL-72B 生成严格遵循“感知（定位目标）->预测（预测目标未来动作）->规划（生成自车轨迹）”顺序的思维链文本。
2. **冷启动监督微调（SFT）**：使用上述数据集对基础 VLM（Qwen2.5-VL-3B）进行监督微调，使模型掌握自动驾驶领域的结构化输出格式，消除领域鸿沟。
3. **$P^3$-GRPO 强化微调**：在 SFT 模型的基础上，给定相同的输入，模型生成一组（$G$ 个）不同的思维链响应。系统解析每个响应中的感知、预测和规划结果，分别与 Ground Truth 计算奖励。感知奖励基于 3D 边界框的 IoU；预测奖励基于动作分类的准确度，并被感知 IoU 加权（强制要求先看准，再预测）；规划奖励基于轨迹的 L2 距离。总奖励为三者加权和，随后使用 GRPO 算法更新模型权重。
4. **双思考模式推理**：在实际测试中，提供“详细思考（输出完整推理文本和最终答案）”和“快速思考（仅输出结构化答案，跳过自然语言推理过程）”两种模式，以在可解释性和推理延迟之间进行权衡。

```python
def generate_correspondence_qa(multi_view_images, camera_params, point_cloud):
    # 1. 采样在多个视角中均无遮挡的3D点
    target_3d_point = sample_visible_point(point_cloud, camera_params)
    
    # 2. 利用相机内外参，将3D点投影到参考视角和目标视角的2D像素平面

    # 3. 在目标视角中生成具有空间分离度的干扰点 (Distractors)
    distractor_pixels = generate_spatial_distractors(target_pixel, min_distance=50)
    
    # 4. 组装VQA样本
    qa_sample = format_vqa(
        images=multi_view_images,
        question=f"Which point in the target image corresponds to the marked point in reference images?",
        correct_answer=target_pixel,
        choices=[target_pixel] + distractor_pixels
    )
    return qa_sample

# 模块2：XVR增强的VLA前向传播逻辑
class XVR_VLA_Policy(nn.Module):

        super().__init__()
        self.vlm = xvr_vlm # 经过XVR数据集微调的Qwen3-VL
        self.dit = dit_action_head
        
    def forward(self, multi_view_obs, language_instruction, proprioception):
        # 1. 提取跨视角空间感知特征 (提取Transformer第12层特征)
        spatial_features = self.vlm.extract_features(
            images=multi_view_obs, 
            text=language_instruction, 
            layer=12
        )
        
        # 2. 动作生成：DiT结合本体感受状态与VLM空间特征进行去噪
        noisy_action = sample_gaussian_noise()
        denoised_action = self.dit(
            x=noisy_action,
            state=proprioception,
            cond=spatial_features # 跨视角几何特征作为Cross-Attention条件注入
        )
        return denoised_action
```

### 第二模块：核心架构解释

**架构与实验流程**：

1. **多模态特征编码**：输入环境图像与语言指令，分别通过预训练的视觉编码器和语言模型提取特征，生成密集的视觉 tokens 和语言 tokens。
2. **聚焦注意力 (Focus Attention)**：在视觉特征处理阶段，模型根据当前任务指令和历史上下文，计算每个视觉 patch 的相关性得分。动态选择最相关的 Top-K 个视觉 patches，并对选出的 patches 进行权重调制（Modulation），放大关键特征，抑制无关背景噪声。
3. **模态级联注意力 (Modality Cascaded Attention)**：在动作解码阶段，改变传统 Transformer 中所有 token 混合注意力的扁平结构。强制动作查询（Action Query）必须先与经过筛选的视觉 tokens 进行交叉注意力交互，随后再融合语言特征。这一级联设计从物理架构上阻断了仅依赖语言或历史动作生成当前动作的捷径。
4. **自回归动作解码**：基于经过强制视觉交互和筛选调制的融合特征，自回归地解码出下一步的机器人动作。
5. **实验验证**：在仿真环境和真实机械臂平台上，对比 FocusVLA 与主流基线模型在多任务成功率、灵巧操作精度及训练收敛步数上的差异。

**核心逻辑伪代码**：

```python
def focus_vla_step(image, instruction, history_actions):
    # 1. 编码阶段
    visual_tokens = vision_encoder(image) # [N, D]
    lang_tokens = language_encoder(instruction) # [L, D]
    action_query = get_action_query(history_actions) # [1, D]

    # 2. 聚焦注意力 (Focus Attention)
    # 计算视觉 patch 与当前任务上下文的相关性
    context = cross_attention(query=action_query, key=lang_tokens, value=lang_tokens)
    relevance_scores = compute_relevance(visual_tokens, context)
    
    # 动态选择 Top-K 相关的视觉 tokens，控制信息量
    topk_indices = topk(relevance_scores, k=K)
    focused_visual_tokens = visual_tokens[topk_indices]
    
    # 权重调制，显式抑制任务无关噪声
    modulated_visual_tokens = modulate(focused_visual_tokens, relevance_scores[topk_indices])

    # 3. 模态级联注意力 (Modality Cascaded Attention)
    # 强制 action_query 先与视觉特征交互，切断捷径
    visual_attended_query = cross_attention(
        query=action_query, 
        key=modulated_visual_tokens, 
        value=modulated_visual_tokens
    )
    
    # 再融合语言特征
    final_query = cross_attention(
        query=visual_attended_query, 
        key=lang_tokens, 
        value=lang_tokens
    )

    # 4. 动作解码
    next_action = action_decoder(final_query)
    
    return next_action
```

### 第二模块：核心架构解释

ROVED 框架的运行流程是一个交替优化的闭环，主要包含轨迹收集、混合标签生成、样本过滤与模型协同更新四个阶段：

1.  **轨迹收集与初始打标:** 策略网络与环境交互，将轨迹存入经验回放缓冲区。系统从中采样轨迹片段对，利用冻结主体但带有可学习附加层的 VLE，计算文本描述与图像观测的余弦相似度，从而生成初始的机器偏好标签。
2.  **不确定性感知过滤:** 计算奖励模型预测的偏好分布与 VLE 生成标签之间的 KL 散度。系统设定动态下界阈值和固定上界阈值。
3.  **样本分流与预言机介入:** 
    *   KL 散度低于下界的样本被视为“干净样本”，直接保留。
    *   KL 散度高于上界的样本被视为“高置信度噪声样本”，将其标签翻转后保留。
    *   KL 散度介于两者之间的样本被视为“不确定样本”，系统根据预算从中抽取子集，交由真实的预言机（人类或大模型）进行精确打标。
4.  **模型协同更新:** 使用上述所有处理后的样本（干净、翻转、预言机标注）更新奖励模型。同时，利用预言机标注的样本以及无监督的逆动力学损失（强制 VLE 的图像表征能够预测相邻帧之间的实际动作），对 VLE 的附加层进行微调。

**核心逻辑伪代码 (Python 风格):**

```python
def ROVED_iteration(policy, reward_model, vle, replay_buffer, oracle, budget):
    # 1. 采样轨迹片段对
    segment_pairs = replay_buffer.sample_pairs(batch_size=128)
    
    # 2. VLE 生成初始标签
    vle_labels = vle.predict_preference(segment_pairs, task_description)
    
    clean_samples, noisy_samples, uncertain_samples = [], [], []
    
    # 3. 不确定性感知过滤
    for pair, y_vle in zip(segment_pairs, vle_labels):
        # 计算奖励模型预测与 VLE 标签的 KL 散度
        y_pred = reward_model.predict_prob(pair)
        kl_div = compute_kl_divergence(y_vle, y_pred)
        
        # 动态阈值判断
        if kl_div < tau_lower:
            clean_samples.append((pair, y_vle))
        elif kl_div > tau_upper:
            # 翻转高置信度噪声标签
            noisy_samples.append((pair, flip_label(y_vle)))
        else:
            uncertain_samples.append(pair)
            
    # 4. 预言机介入 (受预算限制)
    oracle_samples = []
    num_queries = min(len(uncertain_samples), budget)
    selected_uncertain = random.sample(uncertain_samples, num_queries)
    
    for pair in selected_uncertain:
        y_oracle = oracle.query(pair)
        oracle_samples.append((pair, y_oracle))
        
    # 5. 模型协同更新
    # 更新奖励模型
    training_data = clean_samples + noisy_samples + oracle_samples
    reward_model.update(training_data)
    
    # 微调 VLE (结合预言机偏好损失与逆动力学损失)
    vle.update_preference_loss(oracle_samples)
    vle.update_inverse_dynamics_loss(replay_buffer.sample_transitions())
    
    # 6. 策略优化
    policy.update(reward_model, replay_buffer)
    
    return policy, reward_model, vle
```

### 第二模块：核心架构解释

HMPDM 的整体架构建立在潜在扩散模型（Latent Diffusion Model）之上，其核心流程分为特征编码、条件注入与迭代去噪三个阶段：

1.  **潜在空间映射**: 预训练的 VAE 将历史帧序列和未来帧序列分别压缩到低维潜在空间，得到干净的历史特征 $h$ 和待去噪的未来特征 $z_\sigma$。
2.  **TaLC (时序感知潜在条件)**: 将 $h$ 和 $z_\sigma$ 在通道维度直接拼接。为了让模型区分“确定的历史”和“充满噪声的未来”，作者设计了帧级时间嵌入掩码（Frame-wise Time Embedding），强制历史帧的噪声水平为极小值。
3.  **MaPE (运动感知金字塔编码器)**: 将历史特征 $h$ 切分为 Patch，送入由 3D 时空 Transformer 块和 Patch Merging 组成的金字塔网络。该网络输出三个不同尺度的 Token 序列 ($M_1, M_2, M_3$)，分别捕获细粒度的短期运动和语义级的长期依赖。
4.  **交叉注意力去噪**: 3D U-Net 接收拼接后的特征，在其内部的不同深度层，利用 Cross-Attention 机制将 $M_1, M_2, M_3$ 作为 Key 和 Value 注入，指导去噪过程。
5.  **SC (自条件策略)**: 在训练和推理时，将上一步预测的干净潜变量拼接作为当前步的额外输入，以此抑制长序列生成的误差累积。

A3: 实验设计的巧妙之处在于严格的消融对比与推理机制的剥离分析。作者不仅证明了 HMPDM 在 FVD 上的绝对优势，还坦诚地分析了其在 SSIM/PSNR 上略逊于 SOTA 的原因（单次长序列生成 vs 自回归短步长生成）。此外，通过改变历史条件帧数（2帧到6帧）的实验，量化了“历史运动信息量”对未来生成质量的边际递减效应，为自动驾驶系统的上下文窗口选择提供了经验支撑。

**Q4: 这篇论文最显著的贡献点（Top 3）是什么？**

A4:
1. 提出了 MaPE 模块，证明了无需依赖光流等显式运动表征，仅通过时空 Transformer 金字塔即可从纯 RGB 潜在空间中提取出足够强大的历史运动先验。
2. 设计了 TaLC 模块，通过帧级时间嵌入掩码（Frame-wise Time Embedding），在扩散前向过程中优雅地统一了确定性的历史条件与随机性的未来噪声。
3. 构建了一个高效的单阶段训练框架，在 Cityscapes 数据集上以更少的优化步骤和单一模态输入，实现了长时空一致性（FVD）的大幅 SOTA 刷新。

**Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）**

A5:
1. **SVD (Stable Video Diffusion)**: HMPDM 继承了 SVD 的基础 3D U-Net 架构和 EDM（Elucidated Diffusion Model）连续时间步去噪范式，并复用了其预训练权重。
2. **VDT / LGC-VD**: 这些前置工作探索了历史帧作为条件注入扩散模型的基础机制，HMPDM 在此基础上推进，解决了它们难以对齐局部与全局运动先验的问题。

**Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？**

A6: 
**局限性与漏洞**：模型完全在低维 VAE 潜在空间（128x128）中进行学习和采样，这不可避免地导致高频纹理细节的平滑。在自动驾驶场景中，这意味着远处的行人或小尺寸交通标志可能会在预测中变得模糊甚至消失，这对于安全性是致命的。此外，单次生成长序列虽然保证了宏观 FVD，但牺牲了逐帧的像素级保真度。
**科研启发**：这篇论文证明了“纯 RGB 序列内部蕴含的隐式运动先验，只要提取方式得当（如时空金字塔），完全可以匹敌甚至超越显式的光流注入”。后续研究可以探索如何结合“单次长序列生成”的宏观一致性与“自回归生成”的微观保真度，或者在 Latent 空间中引入局部高频特征增强机制，以解决小目标丢失的问题。
