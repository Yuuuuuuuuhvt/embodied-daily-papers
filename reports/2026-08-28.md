### 第二模块：核心架构解释

Instruct-to-Act 框架在架构上分为两个完全独立的模块：规划器（Planner）和控制器（Controller）。

**1. 规划器 (VLM Planner)**
规划器是一个现成的视觉语言模型（如 GPT-4o 或 Qwen-VL）。它接收环境的视觉观测和任务上下文，输出一段简短的自然语言指令（如“砍伐树木”）。在推理时，规划器在独立的线程中异步运行，不需要等待底层动作执行完毕，从而掩盖了 VLM 的高延迟。

**2. 控制器 (World-Model Controller)**
控制器是一个引入了语言条件分支的 DreamerV3 风格的循环状态空间模型（RSSM）。它接收当前观测和规划器下发的文本指令的 Embedding，在隐空间中输出高频的底层动作。此外，控制器增加了一个 Stop Head，用于在每个时间步预测当前指令是否已经执行完成。

**3. 训练流程 (无专家数据)**
控制器不需要人类专家示范。它首先在环境中随机探索或基于内在奖励收集轨迹存入回放缓冲区。随后，系统从缓冲区采样轨迹片段，将其输入给 VLM，让 VLM 总结这段轨迹“完成了什么指令”。得到这些事后标注的指令后，控制器将行为克隆损失（BC Loss）、Stop 预测损失与标准的 Dreamer 损失（重建、动态预测、Actor-Critic 奖励最大化）相加，进行联合梯度更新。

**4. 多智能体扩展**
在多智能体场景下，每个智能体实例化一个独立的 VLM 规划器，但共享同一个底层控制器的权重。规划器之间通过一个共享的文本收件箱（Inbox）进行离散回合制的自然语言通信，协商子目标，随后各自向底层的控制器下发指令。

```python
import torch
import threading

class InstructToActAgent:
    def __init__(self, vlm_planner, rssm_controller):
        self.planner = vlm_planner
        self.controller = rssm_controller
        self.current_instruction = None
        self.stop_flag = True
        self.inbox = None # 用于多智能体通信或指令缓冲
        
    def asynchronous_inference_loop(self, env):
        # 启动后台 VLM 规划线程
        planner_thread = threading.Thread(target=self._run_planner, args=(env,))
        planner_thread.start()
        
        # 主线程运行高频控制器
        obs = env.reset()
        while not env.done:
            # 如果上一条指令已完成且有新指令，则更新
            if self.stop_flag and self.inbox is not None:
                self.current_instruction = self.inbox
                self.inbox = None
                self.stop_flag = False
                
            # 控制器高频输出动作和完成概率
            action, stop_prob = self.controller.step(obs, self.current_instruction)
            obs, reward, done = env.step(action)
            
            # 触发指令完成信号
            if stop_prob > 0.5:
                self.stop_flag = True

    def _run_planner(self, env):
        # 异步运行，不阻塞环境 step
        while not env.done:
            if self.stop_flag:
                # 结合当前观测生成新指令
                obs = env.get_latest_observation()
                new_instruction = self.planner.generate_instruction(obs)
                self.inbox = new_instruction

    def compute_training_loss(self, replay_buffer):
        # 1. 采样无标注轨迹
        trajectories = replay_buffer.sample()
        
        # 2. VLM 事后标注 (Post-hoc Relabeling)
        # 将轨迹片段转换为文本指令标签
        labeled_segments = self.planner.summarize_trajectory(trajectories)
        
        # 3. 计算 Dreamer 世界模型损失 (重建 + 奖励 + 动态)
        wm_loss, actor_loss, value_loss = self.controller.compute_dreamer_loss(trajectories)
        
        # 4. 计算行为克隆损失 (仅在有 VLM 标注的片段上)
        bc_loss = 0
        stop_loss = 0
        for segment, text_instruction in labeled_segments:
            pred_actions, pred_stops = self.controller.forward(segment.obs, text_instruction)
            bc_loss += cross_entropy(pred_actions, segment.actions)
            stop_loss += binary_cross_entropy(pred_stops, segment.is_completed)
            
        # 5. 联合优化
        total_loss = wm_loss + actor_loss + value_loss + bc_loss + stop_loss
        total_loss.backward()
```

### 第二模块：核心架构解释

R2M-Bench 的评估流程不涉及重新训练模型，而是对模型生成的视频进行后处理与指标计算。其核心流程分为四个步骤：

1.  **数据构建:** 选取 100 个初始场景图像，搭配 3 种固定的相机导航轨迹（原路折返、平移旋转、闭环），组合成 300 个测试实例。
2.  **生成与采样:** 驱动世界模型生成视频。在生成的视频中，基于相机的空间坐标挖掘三类帧对：
    *   **重访帧对 (Revisit Pairs):** 空间位置重合、时间跨度大的两帧。
    *   **基准帧对 (Baseline Pairs):** 时间跨度与重访帧对相同，但无空间重合要求的两帧。
    *   **短距离帧对 (Short-range Pairs):** 时间上相邻极近的两帧。
3.  **五维特征提取:** 对上述三类帧对，分别计算 5 个维度的客观得分：外观保真度（像素级差异）、场景身份（全局语义特征）、对象身份（目标检测与特征比对）、局部几何（特征点匹配）、持久状态（视觉语言模型打分）。
4.  **相对分数计算:** 计算 MemoryGain (MG) 和 Normalized Memory Ratio (NMR)。

**核心逻辑伪代码：**

```python
def evaluate_revisit_memory(video_frames, camera_poses):
    # 1. 挖掘三类帧对
    revisit_pairs = mine_revisit_pairs(camera_poses) 
    baseline_pairs = mine_baseline_pairs(video_frames, revisit_pairs)
    short_range_pairs = mine_short_range_pairs(video_frames)
    
    # 2. 计算五维度的绝对一致性得分 (以某个评估维度 q 为例)
    score_revisit = compute_consistency(video_frames, revisit_pairs, metric='q')
    score_baseline = compute_consistency(video_frames, baseline_pairs, metric='q')
    score_short = compute_consistency(video_frames, short_range_pairs, metric='q')
    
    # 3. 计算相对指标
    # MemoryGain (MG): 重访得分超出常规长间隔得分的部分
    memory_gain = score_revisit - score_baseline
    
    # Dynamic Range (DR): 短距离得分与常规长间隔得分的差值 (代表模型的性能上限与下限之差)
    dynamic_range = score_short - score_baseline
    
    # Normalized Memory Ratio (NMR): 归一化记忆比率
    epsilon = 1e-8
    if dynamic_range > epsilon:
        nmr = memory_gain / (dynamic_range + epsilon)
    else:
        nmr = None # 动态范围过小，数据不可靠
        
    return memory_gain, nmr
```

PAWBench 的核心逻辑是从“像素级视觉评估”跃迁到“结果级物理分布评估”。其评估流程分为四个关键阶段：

1. **场景与分布定义 (Scenario Definition)**：构建具有明确物理随机性的场景（例如物体碰撞后的反弹方向、抛硬币的结果）。为每个场景定义初始观测 $X$、动作/条件 $A$，以及真实世界中可能结果 $Y$ 的参考概率分布 $P(Y|X, A)$。
2. **随机采样生成 (Stochastic Rollout)**：给定相同的初始观测和条件，向待测的视频生成模型（世界模型）输入 $N$ 个不同的随机噪声种子，生成 $N$ 个独立的视频轨迹。
3. **结果级解析 (Outcome Extraction via PAWEval)**：使用自动化脚本或视觉大模型（VLM）对生成的 $N$ 个视频进行解析，提取每个视频最终的物理状态或行为结果（例如：硬币最终是正面还是反面）。
4. **分布对齐计算 (Distribution Alignment)**：统计提取出的物理结果，构建模型生成的经验分布 $\hat{P}(Y|X, A)$。使用统计学距离度量（如总变差距离 Total Variation Distance 或 KL 散度）计算经验分布 $\hat{P}$ 与真实参考分布 $P$ 之间的差异。

```python
def evaluate_probabilistic_alignment(world_model, scenarios, num_samples=100):
    benchmark_results = {}
    
    for scenario in scenarios:
        initial_obs = scenario.get_initial_observation()
        action = scenario.get_action()
        true_distribution = scenario.get_reference_distribution()
        
        generated_outcomes = []
        
        # 核心步骤1：对同一初始状态进行多次随机采样
        for _ in range(num_samples):
            noise = sample_gaussian_noise()
            # 视频生成模型作为随机采样器进行 rollout
            video_trajectory = world_model.generate(initial_obs, action, noise)

            outcome = extract_physical_outcome(video_trajectory, scenario.rules)
            if outcome in scenario.valid_outcomes:
                generated_outcomes.append(outcome)
                
        # 核心步骤3：计算经验分布
        empirical_distribution = compute_empirical_distribution(generated_outcomes)
        
        # 核心步骤4：量化概率对齐程度
        alignment_error = calculate_total_variation_distance(empirical_distribution, true_distribution)
        benchmark_results[scenario.name] = alignment_error
        
    return benchmark_results
```

### 第二模块：核心架构解释

Instruct-to-Act 框架在架构上分为两个完全独立的模块：规划器（Planner）和控制器（Controller）。

**1. 规划器 (VLM Planner)**
规划器是一个现成的视觉语言模型（如 GPT-4o 或 Qwen-VL）。它接收环境的视觉观测和任务上下文，输出一段简短的自然语言指令（如“砍伐树木”）。在推理时，规划器在独立的线程中异步运行，不需要等待底层动作执行完毕，从而掩盖了 VLM 的高延迟。

**2. 控制器 (World-Model Controller)**
控制器是一个引入了语言条件分支的 DreamerV3 风格的循环状态空间模型（RSSM）。它接收当前观测和规划器下发的文本指令的 Embedding，在隐空间中输出高频的底层动作。此外，控制器增加了一个 Stop Head，用于在每个时间步预测当前指令是否已经执行完成。

**3. 训练流程 (无专家数据)**
控制器不需要人类专家示范。它首先在环境中随机探索或基于内在奖励收集轨迹存入回放缓冲区。随后，系统从缓冲区采样轨迹片段，将其输入给 VLM，让 VLM 总结这段轨迹“完成了什么指令”。得到这些事后标注的指令后，控制器将行为克隆损失（BC Loss）、Stop 预测损失与标准的 Dreamer 损失（重建、动态预测、Actor-Critic 奖励最大化）相加，进行联合梯度更新。

**4. 多智能体扩展**
在多智能体场景下，每个智能体实例化一个独立的 VLM 规划器，但共享同一个底层控制器的权重。规划器之间通过一个共享的文本收件箱（Inbox）进行离散回合制的自然语言通信，协商子目标，随后各自向底层的控制器下发指令。

**核心逻辑伪代码 (Python 风格)**

```python
import torch
import threading

class InstructToActAgent:
    def __init__(self, vlm_planner, rssm_controller):
        self.planner = vlm_planner
        self.controller = rssm_controller
        self.current_instruction = None
        self.stop_flag = True
        self.inbox = None # 用于多智能体通信或指令缓冲
        
    def asynchronous_inference_loop(self, env):
        # 启动后台 VLM 规划线程
        planner_thread = threading.Thread(target=self._run_planner, args=(env,))
        planner_thread.start()
        
        # 主线程运行高频控制器
        obs = env.reset()
        while not env.done:
            # 如果上一条指令已完成且有新指令，则更新
            if self.stop_flag and self.inbox is not None:
                self.current_instruction = self.inbox
                self.inbox = None
                self.stop_flag = False
                
            # 控制器高频输出动作和完成概率
            action, stop_prob = self.controller.step(obs, self.current_instruction)
            obs, reward, done = env.step(action)
            
            # 触发指令完成信号
            if stop_prob > 0.5:
                self.stop_flag = True

    def _run_planner(self, env):
        # 异步运行，不阻塞环境 step
        while not env.done:
            if self.stop_flag:
                # 结合当前观测生成新指令
                obs = env.get_latest_observation()
                new_instruction = self.planner.generate_instruction(obs)
                self.inbox = new_instruction

    def compute_training_loss(self, replay_buffer):
        # 1. 采样无标注轨迹
        trajectories = replay_buffer.sample()
        
        # 2. VLM 事后标注 (Post-hoc Relabeling)
        # 将轨迹片段转换为文本指令标签
        labeled_segments = self.planner.summarize_trajectory(trajectories)
        
        # 3. 计算 Dreamer 世界模型损失 (重建 + 奖励 + 动态)
        wm_loss, actor_loss, value_loss = self.controller.compute_dreamer_loss(trajectories)
        
        # 4. 计算行为克隆损失 (仅在有 VLM 标注的片段上)
        bc_loss = 0
        stop_loss = 0
        for segment, text_instruction in labeled_segments:
            pred_actions, pred_stops = self.controller.forward(segment.obs, text_instruction)
            bc_loss += cross_entropy(pred_actions, segment.actions)
            stop_loss += binary_cross_entropy(pred_stops, segment.is_completed)
            
        # 5. 联合优化
        total_loss = wm_loss + actor_loss + value_loss + bc_loss + stop_loss
        total_loss.backward()
```

### 第二模块：核心架构解释

R2M-Bench 的评估流程不涉及重新训练模型，而是对模型生成的视频进行后处理与指标计算。其核心流程分为四个步骤：

1.  **数据构建:** 选取 100 个初始场景图像，搭配 3 种固定的相机导航轨迹（原路折返、平移旋转、闭环），组合成 300 个测试实例。
2.  **生成与采样:** 驱动世界模型生成视频。在生成的视频中，基于相机的空间坐标挖掘三类帧对：
    *   **重访帧对 (Revisit Pairs):** 空间位置重合、时间跨度大的两帧。
    *   **基准帧对 (Baseline Pairs):** 时间跨度与重访帧对相同，但无空间重合要求的两帧。
    *   **短距离帧对 (Short-range Pairs):** 时间上相邻极近的两帧。
3.  **五维特征提取:** 对上述三类帧对，分别计算 5 个维度的客观得分：外观保真度（像素级差异）、场景身份（全局语义特征）、对象身份（目标检测与特征比对）、局部几何（特征点匹配）、持久状态（视觉语言模型打分）。
4.  **相对分数计算:** 计算 MemoryGain (MG) 和 Normalized Memory Ratio (NMR)。

**核心逻辑伪代码：**

```python
def evaluate_revisit_memory(video_frames, camera_poses):
    # 1. 挖掘三类帧对
    revisit_pairs = mine_revisit_pairs(camera_poses) 
    baseline_pairs = mine_baseline_pairs(video_frames, revisit_pairs)
    short_range_pairs = mine_short_range_pairs(video_frames)
    
    # 2. 计算五维度的绝对一致性得分 (以某个评估维度 q 为例)
    score_revisit = compute_consistency(video_frames, revisit_pairs, metric='q')
    score_baseline = compute_consistency(video_frames, baseline_pairs, metric='q')
    score_short = compute_consistency(video_frames, short_range_pairs, metric='q')
    
    # 3. 计算相对指标
    # MemoryGain (MG): 重访得分超出常规长间隔得分的部分
    memory_gain = score_revisit - score_baseline
    
    # Dynamic Range (DR): 短距离得分与常规长间隔得分的差值 (代表模型的性能上限与下限之差)
    dynamic_range = score_short - score_baseline
    
    # Normalized Memory Ratio (NMR): 归一化记忆比率
    epsilon = 1e-8
    if dynamic_range > epsilon:
        nmr = memory_gain / (dynamic_range + epsilon)
    else:
        nmr = None # 动态范围过小，数据不可靠
        
    return memory_gain, nmr
```

### 第三模块：核心学术问答

**Q1: 这篇论文试图解决什么核心问题？**

A1: 现有的世界模型评估方法在测试“模型是否记住了之前的场景”时，直接计算前后两帧的画面相似度。这导致了一个严重漏洞：如果模型生成的视频画面几乎不动，或者动作极其缓慢，前后两帧自然高度相似。这篇论文试图解决这种“绝对相似度”无法区分“模型真有记忆”还是“模型根本没动”的核心问题。

**Q2: 作者提出的核心解决方案（创新点）是什么？**

A2: 作者提出了“同视频相对一致性”评估方法。他们不再单纯看重访画面的绝对得分，而是从同一个生成的视频中，截取时间间隔相同的普通画面作为“基准”。用重访画面的得分减去基准画面的得分。如果相减后的结果为正，说明模型在回到原点时确实恢复了场景，而不是因为整个视频本来就没怎么变化。

**Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？**

A3: 实验设计的巧妙之处在于“自我校准”。因为基准画面和重访画面来自同一个模型生成的同一段视频，所以模型自身的画质差、渲染风格、或者动作缓慢等全局缺陷，都会同时体现在基准画面和重访画面上。通过简单的减法，这些全局干扰因素被直接物理抵消，逼迫模型必须在“重访”这一特定行为上展现出优势才能得分。

### 第二模块：核心架构解释

PredVLA 的系统架构分为两个完全解耦的部分：冻结的多模态前端（提取特征）和可训练的层次化预测编码循环网络（生成动作与在线修正）。

2. **层次化循环动力学**：网络包含四个具有不同时间常数（$\tau$）的模块：顶层模块 T（接收语言）、视觉模块 V、动作顶层模块 Atop、动作底层模块 Abottom。模块间存在自上而下的先验传递，以及横向的视觉-动作耦合路径。
3. **在线误差回归（核心推理流程）**：在控制执行时，网络权重被冻结。每个时间步，模型先根据历史隐变量生成对当前视觉和本体感觉的预测。随后，计算预测值与真实观测值之间的均方误差（自由能目标函数）。通过梯度下降，在线更新当前时间窗口内的后验隐变量 $c_q$。更新后的隐变量重新驱动确定性状态，最终解码出动作。

```python
front_end = FrozenFrontEnd()
rnn_dynamics = HierarchicalPCRNN()
action_decoder = GMMDecoder()

# 部署时的在线控制循环
def control_step(obs_img, obs_q, lang_inst, inference_window, nitr=10, lr=0.05):
    # 1. 前端特征提取 (固定不变)
    lang_feat = front_end.encode_language(lang_inst)
    v_feat = front_end.encode_vision(obs_img)
    
    # 将当前观测加入滑动推理窗口
    inference_window.append((v_feat, obs_q))
    
    # 2. 在线误差回归 (Online Error Regression)
    # 针对推理窗口内的后验隐变量 c_q 进行 nitr 次梯度下降迭代
    for _ in range(nitr):
        # 前向传播：基于当前隐变量 c_q 生成预测
        pred_v, pred_q = rnn_dynamics.forward_predict(inference_window.c_q, lang_feat)
        
        # 计算自由能 (Free Energy) = 预测误差 (Accuracy) + 先验约束 (Complexity)
        error_v = mse(inference_window.v_feat, pred_v)
        error_q = mse(inference_window.obs_q, pred_q)
        complexity = mse(inference_window.c_q, inference_window.c_p) # c_p 为先验隐变量
        
        free_energy = error_v + error_q + complexity
        
        # 计算梯度并更新后验隐变量 c_q (网络权重保持冻结)
        grad_c_q = compute_gradient(free_energy, inference_window.c_q)
        inference_window.c_q = inference_window.c_q - lr * grad_c_q
        
    # 3. 动作生成
    # 使用优化后的隐变量重新计算当前步的确定性状态，并解码动作
    final_state = rnn_dynamics.compute_state(inference_window.c_q[-1])
    action_dist = action_decoder(final_state)
    action = action_dist.get_highest_weight_mean()
    
    return action
```

### 第二模块：核心架构解释

SpatialCrafter 的系统架构分为两个独立且连续的阶段：全局 3D 代理生成（Stage 1）与生成式延迟细化（Stage 2）。

**阶段一：全局 3D 代理生成 (Global 3D Proxy Generator)**
该阶段将无约束的 3D 生成转化为条件补全问题。首先，将输入图像和深度图反投影为局部 3D 点云，并体素化为条件稀疏体素。随后，PaSS Flow 模块以这些体素为几何锚点，生成完整的场景稀疏结构。最后，通过 SLAT（Structured LATent）流匹配生成体素特征，并由 3D 高斯解码器输出全局 3D 代理。

**阶段二：生成式延迟细化 (Generative Deferred Refiner)**
给定相机轨迹，系统首先从全局 3D 代理中渲染出粗糙的 RGB-D 序列。为了防止细化器对代理的伪影过拟合，训练时引入代理感知破坏（PAC）机制，对粗糙渲染图施加随机模糊、噪声或深度擦除。随后，通过并行几何注入机制，将粗糙 RGB-D 潜变量与噪声视频潜变量在通道维度拼接，送入冻结了预训练权重、仅微调 LoRA 的视频 DiT 中，最终输出高保真视频。

```python
def spatialcrafter_pipeline(image, depth, camera_trajectory, text_prompt):
    # ==========================================
    # Stage 1: Global 3D Proxy Generation
    # ==========================================
    # 1. Unproject input to partial point cloud and voxelize
    partial_points = unproject(image, depth)
    V_cond = voxelize(partial_points)
    
    # 2. PaSS Flow: Generate complete sparse structure aligned with input
    # V_t is noisy structure, optimized via Flow Matching
    V_complete = pass_flow_model(V_t, V_cond, image) 
    
    # 3. SLAT Flow & Decoding: Generate latent features and decode to 3D Gaussians
    latent_features = slat_flow_model(V_complete, image)
    global_3d_proxy = gaussian_decoder(latent_features)
    
    # ==========================================
    # Stage 2: Generative Deferred Refiner
    # ==========================================
    # 1. Render coarse RGB-D sequence along trajectory
    coarse_rgb, coarse_depth = render_trajectory(global_3d_proxy, camera_trajectory)
    
    # 2. Proxy-Aware Corruption (PAC) - Applied during training for robustness
    if is_training:
        coarse_rgb, coarse_depth = apply_random_corruption(coarse_rgb, coarse_depth)
        
    # 3. Parallel Geometry Injection
    z_rgb = vae_encode(coarse_rgb)
    z_depth = vae_encode(coarse_depth)
    z_geo = concat_width(z_rgb, z_depth)
    
    z_ref = vae_encode(image)
    z_noisy_video = sample_gaussian_noise()
    
    # Channel-wise concat geometry, token-wise concat reference image
    dit_input = concat_channel(z_noisy_video, z_geo)
    dit_input = concat_token(z_ref, dit_input)
    
    # 4. Video DiT (LoRA tuned) generates final clean video latents
    clean_video_latents = video_dit(dit_input, text_prompt)
    fine_rgbd_video = vae_decode(clean_video_latents)
    
    return fine_rgbd_video
```

### 第二模块：核心架构解释

FlashVLA 的核心架构通过改变动作块的解码方式，将原本串行的多次去噪过程转化为并行的流水线作业。其整体流程分为推理架构与训练适配两个部分：

**1. 流式缓冲区与块级因果注意力 (Streaming Buffer & Chunk-wise Causal Attention)**
模型维护一个长度为 $N$ 的缓冲区，存放 $N$ 个动作块。这 $N$ 个块的噪声水平呈严格的单调递减阶梯状：队首是即将执行的干净块，队尾是刚初始化的纯噪声块。在 Transformer 的注意力机制中，施加块级因果掩码：噪声较高的未来块可以 attend 到噪声较低的当前块，但反之被阻断。这使得未来动作的生成隐式地条件化在当前正在生成的轨迹上，消除了异步错位。

**2. 分摊去噪与流式推理 (Amortized Denoising)**
单次网络前向传播会同时让缓冲区内的所有 $N$ 个块向前推进一步去噪。推理分为两个阶段：
- **冷启动 (Cold Start)**：初始状态下缓冲区为空，模型需要执行 $N-1$ 次前向传播来填满缓冲区。此阶段机器人保持静止或执行安全默认动作。
- **稳态流式输出 (Steady Streaming)**：缓冲区填满后，每次前向传播都会在队首弹出一个完全去噪的可执行块，其余块向前移动，并在队尾补充一个新的纯噪声块。

**3. 多缓冲区联合微调 (Multi-Buffer Joint Fine-tuning)**
为了让预训练的 VLA 适应这种流式输入，作者将冷启动到稳态的 $N$ 种不同缓冲区配置打包成一个单一的训练样本。这些配置共享同一个视觉观察特征提取结果，仅通过注意力掩码在动作解码端进行隔离，极大提升了微调效率。

**核心逻辑伪代码 (Python 风格)**：

### 第二模块：核心架构解释

TemporalFlow-VLA 的核心架构分为离线物理监督构建、训练期的分层时间查询，以及部署期的异步缓存推理三个部分。

**1. 离线物理监督构建**
利用记录的机器人关节状态、URDF 几何文件和相机标定参数，通过正向运动学计算出机器人在 $t-15$ 到 $t$ 以及 $t-8$ 到 $t$ 两个时间段内的 3D 表面位移。将这些位移投影到 2D 图像平面，生成仅包含机器人表面的真实时间流（Temporal Flow）标签。

**2. 分层时间查询与联合注意力（训练期）**
模型在基础 VLA 的基础上引入了两个可学习的时间查询向量 $Q_8$ 和 $Q_{15}$。
$Q_8$ 负责读取 $t-8$ 和 $t$ 时刻的图像特征，提取近期运动摘要。
$Q_{15}$ 负责读取 $t-15$ 和 $t$ 时刻的图像特征，并强制读取 $Q_8$ 的输出，以整合长程历史。
动作生成专家（Action Expert）被掩码机制限制，无法直接读取历史图像特征，只能通过读取 $Q_8$ 和 $Q_{15}$ 来获取历史信息。同时，$Q_8$ 和 $Q_{15}$ 的输出被送入一个解码器，计算与离线构建的真实时间流的 Huber 损失。

**3. 异步缓存机制（部署期）**
在实际机器人执行时，不计算时间流，也不评估解码器。为了避免处理历史帧带来的延迟，模型在后台异步提取并缓存历史帧的视觉特征。在当前步规划时，直接从缓存中读取 $t-15$ 和 $t-8$ 的特征，主线程仅需处理当前帧 $t$ 的视觉编码和动作生成。

### 第二模块：核心架构解释

LEON 的核心逻辑是将复杂的非线性状态转移，转化为在一个学习到的高维空间中的“矩阵乘法（算子传播）+ 向量加法（附加力）”过程。其前向传播流程分为四个客观步骤：

1.  **可观测映射（Observable Map）**：将输入的视觉潜在特征 $X$ 通过神经网络映射到特定的可观测坐标系 $H$ 中。
2.  **上下文构建（Context Construction）**：将当前的可观测特征 $H$ 与动作/语义条件 $Z$ 结合，生成用于控制转移的上下文向量 $\xi$。
3.  **算子结构化演化（Operator-Structured Evolution）**：
    *   基于上下文 $\xi$ 计算系数 $\alpha(\xi)$。
    *   将系数作用于共享的低秩基矩阵 $U$ 和 $V$，加上独立基线 $D$，生成当前时刻的演化矩阵 $A(\xi)$。
    *   计算附加力向量 $b(\xi)$。
    *   执行状态更新：$\tilde{H} = H + \eta[A(\xi)H + b(\xi)]$。
4.  **读出映射（Readout）**：将更新后的特征 $\tilde{H}$ 映射回原始的潜在空间，得到未来状态预测 $\hat{X}^+$。

**核心伪代码实现**：

```python
import torch
import torch.nn as nn

class LEONLayer(nn.Module):
    def __init__(self, state_dim, obs_dim, context_dim, rank, residual_scale=0.1):
        super().__init__()
        self.eta = residual_scale
        
        # 1. Observable Map & Readout
        self.phi = nn.Linear(state_dim, obs_dim)
        self.psi = nn.Linear(obs_dim, state_dim)
        
        # 2. Context Function (Simplified as MLP for demonstration)
        self.context_net = nn.Sequential(
            nn.Linear(obs_dim + context_dim, 256),
            nn.ReLU(),
            nn.Linear(256, 256)
        )
        
        # 3. Operator Components
        self.D = nn.Parameter(torch.randn(obs_dim)) # Context-independent baseline
        self.U = nn.Parameter(torch.randn(obs_dim, rank)) # Shared basis U
        self.V = nn.Parameter(torch.randn(obs_dim, rank)) # Shared basis V
        
        # Coefficient and Forcing generators
        self.alpha_net = nn.Linear(256, rank)
        self.b_net = nn.Linear(256, obs_dim)

    def forward(self, X, Z):
        # X: [batch, tokens, state_dim]
        # Z: [batch, tokens, context_dim]
        
        # Step 1: Map to observable space
        H = self.phi(X) # [batch, tokens, obs_dim]
        
        # Step 2: Construct transition context
        # Concatenate state and action context
        HZ_concat = torch.cat([H, Z], dim=-1) 
        xi = self.context_net(HZ_concat) # [batch, tokens, 256]
        
        # Step 3: Operator-structured evolution
        alpha = self.alpha_net(xi) # [batch, tokens, rank]
        b = self.b_net(xi)         # [batch, tokens, obs_dim]
        
        # Construct A(xi) = D + U * Diag(alpha) * V^T
        # Efficient computation without explicitly forming the large matrix A:
        # A(xi)H = D * H + U * (alpha * (V^T * H))
        
        D_term = self.D * H
        V_T_H = torch.einsum('od, bto -> btd', self.V, H)
        alpha_V_T_H = alpha * V_T_H
        U_term = torch.einsum('od, btd -> bto', self.U, alpha_V_T_H)
        
        A_H = D_term + U_term
        
        # Residual update
        H_next = H + self.eta * (A_H + b)
        
        # Step 4: Readout to original space
        X_next = self.psi(H_next)
        
        return X_next
```

### 第二模块：核心架构解释

TrapVLA 的整体架构分为数据合成与模型训练两个核心阶段。

**阶段一：TrapEngine 数据引擎**
1. **元数据收集**：回放专家演示，过滤失败轨迹，记录时间步、末端执行器位置、目标物体位置等几何元数据。
2. **目标轨迹生成**：根据攻击配置（如空间偏移量 $\Delta$），在特定操作阶段（如抓取或放置）修改动作，生成包含“任务一致阶段”和“目标偏差阶段”的毒化轨迹。
3. **后门数据集组装**：利用 LLM（如 GPT-5.4）生成上下文连贯的自然语言前缀（如 "From the robot's perspective, "）作为文本触发器，与毒化轨迹配对。

**阶段二：TrapVLA 模型训练与目标残差引导 (TRS)**
在训练阶段，模型接收成对的数据（干净样本与对应的毒化样本）。传统的后门训练容易被大量正常的“任务一致”动作淹没触发器信号（即稀疏动作偏差问题）。TrapVLA 引入 TRS 损失，将轨迹分为目标偏差子集 $\mathcal{S}$ 和任务一致子集 $\mathcal{S}^c$。在 $\mathcal{S}$ 中，强制模型预测的动作残差对齐设定的恶意残差；在 $\mathcal{S}^c$ 中，将残差压制在容差 $\epsilon$ 内。

**核心伪代码实现：**

```python
import torch
import torch.nn.functional as F

def trapvla_loss(policy_model, clean_batch, backdoor_batch, lambda_trs=1.0, epsilon=0.01):
    """
    TrapVLA 核心训练逻辑与 TRS (Target Residual Steering) 损失计算
    """
    # 1. 解析干净数据与后门数据
    obs_clean, text_clean, action_clean = clean_batch
    obs_bad, text_bad, action_bad = backdoor_batch
    
    # 2. 获取模型预测动作
    pred_action_clean = policy_model(obs_clean, text_clean)
    pred_action_bad = policy_model(obs_bad, text_bad)
    
    # 3. 计算基础的模仿学习损失 (Vanilla Backdoor Objective)
    # 保证模型在干净指令下正常工作，在触发指令下拟合毒化轨迹
    loss_clean = F.l1_loss(pred_action_clean, action_clean)
    loss_bad = F.l1_loss(pred_action_bad, action_bad)
    loss_vanilla = loss_clean + loss_bad
    
    # 4. 计算目标残差引导损失 (Target Residual Steering, TRS)
    # 预测的残差 (触发器引起的动作变化)
    pred_residual = pred_action_bad - pred_action_clean
    # 真实的残差 (数据引擎注入的恶意偏差)
    target_residual = action_bad - action_clean
    
    # 区分目标偏差阶段 (S) 和任务一致阶段 (Sc)
    # 假设 target_residual 绝对值大于阈值的为目标偏差阶段
    deviation_mask = (torch.abs(target_residual) > 1e-4).float()
    consistent_mask = 1.0 - deviation_mask
    
    # 在目标偏差阶段，强制预测残差对齐真实恶意残差
    loss_trs_deviation = torch.sum(deviation_mask * torch.abs(pred_residual - target_residual)) / (torch.sum(deviation_mask) + 1e-8)
    
    # 在任务一致阶段，抑制预测残差，允许 epsilon 的容差
    residual_magnitude = torch.abs(pred_residual)
    loss_trs_consistent = torch.sum(consistent_mask * F.relu(residual_magnitude - epsilon)) / (torch.sum(consistent_mask) + 1e-8)
    
    loss_trs = loss_trs_deviation + loss_trs_consistent
    
    # 5. 总体损失
    total_loss = loss_vanilla + lambda_trs * loss_trs
    
    return total_loss
```

FLARE 框架的运行逻辑分为数据生成与训练阶段（离线）和闭环控制阶段（在线）。

**1. 数据生成与训练阶段**
- **针对 ID 错误（Retry 能力）**：系统对原始专家轨迹注入随机的运动学扰动（Perturbation），使机械臂偏离标准姿态，随后生成一段桥接轨迹（Bridging）将其拉回下一个有效任务节点的起始姿态。模型通过学习“桥接+后续任务”的轨迹，强制解耦姿态与环境状态的绑定。
- **针对 OOD 错误（Reset 能力）**：利用 MLLM（如 Gemini）离线分析 VLA 的失败视频，提取导致灾难性失败的特定环境状态（如杯子倾倒）。基于这些状态收集少量人类恢复演示，并应用上述的扰动-桥接增强技术扩充数据。
- **模块化训练**：使用统一的预训练 VLA 作为基座，主任务和各个特定对象的 Reset 技能分别通过独立的 LoRA 适配器进行微调，避免多任务梯度冲突。

**2. 闭环推理阶段**
- 系统默认加载主任务 LoRA 执行动作。
- 在线 MLLM 作为监控器实时评估视觉观测。
- 若发生 ID 错误，MLLM 不干预，VLA 依靠训练获得的原生鲁棒性自动纠正（Retry）。
- 若发生 OOD 错误，MLLM 识别错误对象，系统切换至对应的 Reset LoRA 执行恢复动作；环境恢复后，切回主任务 LoRA 继续执行。

**核心逻辑伪代码**：

```python
class FLARE_System:
    def __init__(self, base_vla, main_lora, reset_loras, mllm_monitor):
        self.vla = base_vla
        self.main_lora = main_lora
        self.reset_loras = reset_loras  # Dictionary of object-centric LoRAs
        self.mllm = mllm_monitor
        self.active_lora = self.main_lora

    def offline_data_augmentation(self, trajectory):
        """
        Perturbation & Bridging to decouple robot pose from environment state.
        """
        augmented_data = []
        for subtask in trajectory:
            # Inject random kinematic perturbation
            perturbed_pose = apply_random_rotation_and_translation(subtask.start_pose)
            # Generate bridging trajectory back to valid state
            bridging_traj = kinematic_interpolation(perturbed_pose, subtask.next_valid_pose)
            # Train on bridging + subsequent task to learn 'Retry'
            augmented_data.append(bridging_traj + subtask.actions)
        return augmented_data

    def online_inference_loop(self, instruction, environment):
        """
        Closed-loop orchestration with MLLM monitor.
        """
        self.vla.load_adapter(self.active_lora)
        
        while not environment.is_task_complete():
            current_obs = environment.get_observation()
            
            # MLLM arbitrates the current state
            error_type, reset_target = self.mllm.analyze_state(current_obs)
            
            if error_type == "OOD_Error":
                # Catastrophic failure: Switch to specific Reset skill
                self.active_lora = self.reset_loras[reset_target]
                self.vla.load_adapter(self.active_lora)
                
                # Execute reset until environment is valid
                while not environment.is_valid_for_main_task():
                    action = self.vla.predict_action(current_obs, f"reset the {reset_target}")
                    current_obs = environment.step(action)
                
                # Switch back to main task
                self.active_lora = self.main_lora
                self.vla.load_adapter(self.active_lora)
            
            elif error_type == "ID_Error" or error_type == "Normal":
                # Minor deviation or normal: Rely on innate Retry robustness
                action = self.vla.predict_action(current_obs, instruction)
                environment.step(action)
```

### 第二模块：核心架构解释

GameWAM 的核心架构围绕“联合生成”与“闭环执行”展开，其工作流程可拆解为以下四个关键阶段：

1. **层次化历史与上下文构建**
模型维护一个跨周期的持久记忆（Persistent History）。在每个决策周期开始时，模型将长期的压缩记忆与当前周期的真实观测（Realized Observations）结合，形成“干净视觉前缀”（Clean Visual Prefix）。
2. **平行流匹配与块因果掩码（Block-Causal Masking）**
在预测未来时，Video DiT 和 Action DiT 并行工作。Video DiT 负责编码干净历史，并将特征共享给 Action DiT。但在去噪生成当前块的未来画面和动作时，视觉和动作分支被严格物理隔离——它们只能看到过去的干净历史，不能看到彼此当前正在生成的噪声变量。这避免了动作生成过度依赖不确定的未来画面。
3. **异构动作路由（Per-Action Routing）**
面对游戏中完全不同的操作逻辑（如视角的连续滑动 vs 鼠标在背包里的精准点击），模型在每个时间步使用一个 Router 预测当前处于 Gameplay 还是 GUI 模式，并动态激活对应的动作解码头，从而在统一的键鼠动作空间内处理截然不同的统计分布。
4. **块循环控制（Block-Cycle Control）**
采用“预测长、执行短”策略。模型一次性预测未来 P 步的动作（如 16 步），但只在环境中真实执行前 E 步（如 8 步）。执行完毕后，获取环境的真实反馈，丢弃未执行的预测，重新开始下一轮规划。

**核心逻辑伪代码 (Python 风格)**:

```python
class GameWAM:
    def __init__(self):
        self.video_dit = VideoDiT()
        self.action_dit = ActionDiT()
        self.router = ActionRouter()
        self.history_memory = HierarchicalMemory()
        
    def block_cycle_rollout(self, env, instruction, P=16, E=8):
        # P: 预测步数 (Predict), E: 执行步数 (Execute)
        current_obs = env.get_observation()
        
        while not env.is_done():
            # 1. 构建干净的因果前缀 (包含长期记忆与当前真实观测)
            clean_prefix = self.history_memory.get_context(current_obs)
            
            # 2. Video DiT 编码干净前缀，提取共享的 K/V 特征
            shared_kv_cache = self.video_dit.encode_clean_prefix(clean_prefix)
            
            # 3. Action DiT 结合共享特征与指令，去噪生成未来 P 步动作
            # 注意：推理阶段可省略未来 Video 的去噪，仅生成 Action 以提高帧率
            noisy_actions = sample_gaussian_noise(steps=P)
            predicted_actions = self.action_dit.denoise(
                noisy_actions, shared_kv_cache, instruction
            )
            
            # 4. 异构动作路由与执行 (仅执行前 E 步)
            executed_obs_buffer = []
            for t in range(E):
                action_t = predicted_actions[t]
                
                # 动态判断当前是跑图打怪(Gameplay)还是切背包(GUI)
                mode = self.router.predict_mode(action_t)
                native_action = self.decode_action(action_t, mode)
                
                # 与环境交互
                next_obs, reward, done = env.step(native_action)
                executed_obs_buffer.append(next_obs)
                
                if done:
                    break
                    
            # 5. 更新真实发生的历史，丢弃未执行的 (P-E) 步预测
            self.history_memory.update(executed_obs_buffer)
            current_obs = next_obs
```

### 第二模块：核心架构解释

GSSC 框架将语义场景补全统一在一个离散扩散架构下，包含三个核心工作流：

**工作流 1：PS$^3$ (Paired Sparse-Dense Scene Synthesis)**
该流程用于数据合成。模型无条件或弱条件生成密集的 3D 语义场景，随后通过模拟 LiDAR 射线投射（Ray-casting）生成对应的稀疏点云。这构建了大量成对的“稀疏-密集”训练数据，直接从数据源头增加了长尾类别（如自行车、摩托车）的样本密度。

**工作流 2：SGSC (Semantic-Guided Generative Scene Completion)**
该流程是核心的场景生成器。输入为纯噪声的 3D 体素网格。条件输入包含两部分：由稀疏 LiDAR 提取的 BEV 语义图，以及稀疏 3D 特征流。模型通过多项式离散扩散过程（Multinomial Discrete Diffusion），在条件特征的引导下，逐步预测每个体素的类别概率，最终生成密集的语义体素网格。

**工作流 3：S$^2$D$^2$ (Structured Source Discrete Diffusion)**
该流程作为即插即用的细化器（Refiner）。它不从纯噪声开始，而是将任意现有 SSC 基础模型（或 SGSC 自身）的粗糙输出作为结构化源。通过单步流匹配（Flow-matching），模型计算从结构化源到目标真实分布的转移概率，直接对基础模型的预测错误进行修正，全程无需重新训练基础模型。

```python
import torch
import torch.nn.functional as F

class GSSC_Framework:
    def __init__(self, diffusion_model, feature_extractor, ray_caster):
        self.model = diffusion_model
        self.feat_extractor = feature_extractor
        self.ray_caster = ray_caster
        self.num_classes = 20
        self.timesteps = 100

    def ps3_data_synthesis(self):
        # 从噪声生成密集场景
        noise = torch.randint(0, self.num_classes, (1, 256, 256, 32))
        dense_scene = self.sgsc_generate(noise, condition=None)
        # 模拟 LiDAR 射线投射获取稀疏点云
        sparse_lidar = self.ray_caster(dense_scene)
        return sparse_lidar, dense_scene

    def sgsc_generate(self, sparse_lidar):
        # 提取 BEV 语义图和 3D 稀疏特征作为条件
        bev_map, sparse_3d_feat = self.feat_extractor(sparse_lidar)
        condition = (bev_map, sparse_3d_feat)
        
        # 初始化纯噪声体素
        voxel_grid = torch.randint(0, self.num_classes, (1, 256, 256, 32))
        
        # 离散扩散去噪过程
        for t in reversed(range(self.timesteps)):
            # 预测去噪概率分布
            logits = self.model(voxel_grid, t, condition)
            probs = F.softmax(logits, dim=-1)
            # 根据多项式分布采样下一步状态
            voxel_grid = torch.multinomial(probs.view(-1, self.num_classes), 1).view(1, 256, 256, 32)
            
        return voxel_grid

    def s2d2_refine(self, base_model_output, sparse_lidar):
        # 提取条件
        bev_map, sparse_3d_feat = self.feat_extractor(sparse_lidar)
        condition = (bev_map, sparse_3d_feat)
        
        # 将基础模型的输出作为结构化源 (t=1)
        structured_source = base_model_output
        
        # 单步流匹配修正 (One-step Flow-matching)
        logits = self.model(structured_source, t=1, condition=condition)
        refined_probs = F.softmax(logits, dim=-1)
        refined_scene = torch.argmax(refined_probs, dim=-1)
        
        return refined_scene
```

### 第二模块：核心架构解释

SCG 的核心运行流程是一个严格的“监控-试探-验证-回滚”闭环，其底层逻辑依赖于结构不变性（Structural Invariance）以保证优化轨迹的连续性。

**1. 初始化与监控阶段**
模型初始化为一个极小的 ViT 编码器（1 个注意力头，2 层，283K 参数）。在每个 epoch 结束时，系统监控纯预测损失 $L_{pred}$（排除 SIGReg 正则化损失，因为正则化项的波动与预测能力无关）。当连续 2 个 epoch 的 $L_{pred}$ 改善幅度小于等于 2% 时，判定为训练停滞，触发扩展机制。

**2. 保函数扩展阶段 (Function-Preserving Expansion)**
扩展分为两种，且在扩展完成的瞬间，模型的输出矩阵与扩展前必须做到比特级完全一致（Bit-exact）：
- **宽度扩展（解决表征瓶颈）**：增加一个注意力头。复制现有头的 QKV 权重，但将新头的输出投影（Output Projection）权重严格初始化为零。这使得新头在初始状态下对网络输出的贡献为零，但拥有合理的特征提取起点。
- **深度扩展（解决计算瓶颈）**：增加一个 Transformer 块。将该块的输出投影和 MLP 的第二层权重初始化为零，LayerNorm 初始化为恒等映射。这使得新块在初始状态下等效于 $g(x) = x$。

**3. 验证与回滚阶段 (Test-and-Verify)**
在执行扩展前，系统对当前的模型权重和优化器状态（包括 Adam 的动量向量）进行深拷贝（Deepcopy）。使用扩展后的架构继续训练 2 个 epoch。如果 $L_{post} < 0.98 \times L_{pre}$，则确认扩展有效，保留新架构并进入冷却期；如果未达到阈值，则直接用深拷贝的状态覆盖当前状态，如同扩展从未发生过，随后尝试另一种扩展方向或判定模型已收敛。

### 第二模块：核心架构解释

GRAFT 的架构设计本质上是一个异步的 Actor-Learner 强化学习系统，其核心流程可拆解为感知、生成与高效更新三个部分：

1. **冻结前缀与特征提取**：输入多视角图像（侧视、腕视）和语言指令，通过冻结的 VLM 前缀提取视觉 Token 和全局上下文。
2. **视角专属视觉锚点（View-Specific Visual Anchors）**：为不同视角分配独立的 Learnable Queries（锚点）。这些锚点通过交叉注意力机制从对应的视觉 Token 中提取局部特征，并由全局上下文进行权重重分配。
3. **训练期专属的定位监督（FreeDice Loss）**：在训练阶段，利用离线生成的 Proposal Masks 对锚点的注意力图进行监督。采用软匹配机制，不强制特定锚点绑定特定物体，只要求所有有效区域都被锚点覆盖，且锚点之间尽量不重叠。
4. **高效动作生成与更新**：Actor 采用单步一致性模型（Consistency Model）直接输出动作块（Action Chunk），避免自回归或多步扩散的延迟。Learner 在更新时，直接复用经验回放池中数据的 VLM 前缀 KV 缓存，仅对锚点网络、动作头和 Critic 网络进行梯度更新。

**核心逻辑伪代码**：

```python
# 核心前向传播与高效更新逻辑
class GRAFT_Policy(nn.Module):
    def __init__(self, vlm_prefix, anchor_net, action_head, critic):
        super().__init__()
        self.vlm_prefix = vlm_prefix.eval() # 冻结的 VLM 前缀
        self.anchor_net = anchor_net        # 包含侧视和腕视的视觉锚点
        self.action_head = action_head      # 单步一致性动作头
        self.critic = critic
        
    def forward_actor(self, obs, lang):
        # 部署时/在线交互时：正常前向传播，无掩码依赖
        with torch.no_grad():
            # 提取视觉特征
            visual_tokens, context, kv_states = self.vlm_prefix(obs, lang)
            
        # 锚点提取局部特征
        anchor_features, raw_attention = self.anchor_net(visual_tokens, context)
        
        # 单步生成动作块
        action_chunk = self.action_head(anchor_features)
        return action_chunk, kv_states
        
    def update_learner(self, replay_batch, offline_masks=None):
        # 经验回放更新时：直接复用缓存的 kv_states，跳过 VLM 前向传播
        cached_kv = replay_batch['kv_states']
        visual_tokens = replay_batch['visual_tokens']
        context = replay_batch['context']
        
        # 仅计算可训练部分
        anchor_features, raw_attention = self.anchor_net(visual_tokens, context)
        
        # 1. 强化学习损失 (Actor-Critic)
        q_values = self.critic(anchor_features, replay_batch['actions'])
        rl_loss = compute_rl_loss(q_values, replay_batch['rewards'])
        
        # 2. 行为克隆损失 (BC)
        pred_actions = self.action_head(anchor_features)
        bc_loss = mse_loss(pred_actions, replay_batch['demo_actions'])
        
        # 3. 视觉定位损失 (仅在有离线掩码的 Demo 数据上计算)
        grounding_loss = 0
        if offline_masks is not None:
            # FreeDice Loss: 确保 raw_attention 覆盖 offline_masks，且无固定身份绑定
            grounding_loss = compute_freedice_loss(raw_attention, offline_masks)
            
        total_loss = rl_loss + bc_loss + grounding_loss
        total_loss.backward()
        return total_loss
```

- **存疑的试验结果**：论文汇总了各方法在 FVD、FID、SSIM 等通用视觉指标上的得分，但明确指出这些数据**不具备跨数据集的可比性**，且**无法反映临床合理性**。一个在 FVD 上得分极好的视频，可能在物理逻辑上完全违背了组织形变规律或手术规范。

### 第二模块：核心架构解释

作为一篇综述，本文的核心架构是对现有手术视频生成技术的概念化重构。作者将技术演进划分为三个核心范式，其底层逻辑与实验流程如下：

1. **无条件生成 (Unconditional Generation)**：
直接从纯噪声中采样，利用扩散模型学习手术视频的全局数据分布。模型不接收任何外部指令，仅负责生成“看起来像手术”的视觉帧。
2. **有条件生成 (Conditional Generation)**：
引入控制信号（文本、掩码、手术阶段标签、器械轨迹等）。模型学习条件分布，使得生成的视频在语义或空间布局上服从用户的显式指令。
3. **世界模型生成 (World Modeling Generation)**：
彻底改变生成逻辑，不再直接映射“条件到像素”，而是引入“状态 (State)”和“动作 (Action)”。模型首先在隐空间或符号空间计算物理状态的转移，随后将更新后的状态渲染为视觉帧，从而保证组织-器械交互的因果一致性。

**核心逻辑伪代码 (Python 风格)**:
```python
class SurgicalVideoGenerationSurvey:
    def __init__(self, diffusion_model, world_model, renderer):
        self.diffusion = diffusion_model
        self.world_model = world_model
        self.renderer = renderer

    def unconditional_generation(self, noise, num_frames):
        # Paradigm 1: p(V) - Generate directly from noise
        video = self.diffusion.denoise(noise, steps=50)
        return video

    def conditional_generation(self, noise, condition, num_frames):
        # Paradigm 2: p(V | C) - Generate guided by text/mask/trajectory
        # Cross-attention injects condition into the denoising process
        video = self.diffusion.denoise_with_guidance(noise, condition, steps=50)
        return video

    def world_modeling_generation(self, initial_state, actions):
        # Paradigm 3: p(s_{t+1} | s_t, a_t) - Causal state transition
        video_frames = []
        current_state = initial_state
        
        for action in actions:
            # 1. Predict next physical/semantic state based on current state and action
            next_state = self.world_model.transition(current_state, action)
            
            # 2. Render the state into a visually plausible frame
            frame = self.renderer.decode(next_state)
            video_frames.append(frame)
            
            # 3. Update state
            current_state = next_state
            
        return video_frames
```
