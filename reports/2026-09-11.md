### 第二模块：核心架构解释

UniMPA 的核心逻辑是将“记忆（Memory）”、“预测（Prediction）”和“动作（Action）”统一到一个共享的接口下。其前向传播流程分为三个关键阶段：

1. **持久-选择性未来预测（Persistent-Selective Future Prediction）**：
   采用双流架构解决状态歧义。**持久潜变量流（Persistent latent stream）**负责在宏观层面持续追踪任务级别的进度；**转移关键像素流（Transition-critical pixel stream）**负责在微观层面选择性地解析细粒度的交互变化。两者结合生成意图未来的状态演化。
2. **视觉-动作记忆检索（Visual-Action Memory Retrieval）**：
   为了解决预测的未来在物理上不可执行的问题，模型将上一步预测的“状态转移”作为 Query，去查询时序视觉-动作记忆库。检索出历史上真实执行过的视觉-动作经验，从而将未来的预测锚定在可执行的物理证据上。
3. **动作-视觉记忆检索与原型偏置流（Action-Visual Memory Retrieval & Prototype-Biased Flow）**：
   为了让历史经验适应当前的新场景，模型进一步查询动作-视觉记忆库，提取出具有视觉锚定的“动作原型（Action Prototypes）”。随后，通过原型偏置流技术，将动作生成的源头向历史上被验证过的动作流形（Action Manifold）偏移，实现上下文感知的动作微调。

```python
        self.flow_generator = PrototypeBiasedFlow()
```

### 第二模块：核心架构解释

IMLE-VLA 的架构设计遵循“重感知，轻生成”的原则。其核心流程分为特征提取、候选生成、最近邻分配和参数更新四个步骤。

1. **观测编码（Observation Encoding）**：在时间步 $t$，视觉图像和语言指令输入到冻结的大型 VLM 主干中，提取出高维条件特征 $f_{VLM}(o_t)$。
2. **噪声采样（Noise Sampling）**：从标准高斯分布 $\mathcal{N}(0, \mathbf{I})$ 中独立采样 $m$ 个潜变量噪声向量。
3. **候选生成（Candidate Generation）**：轻量级的单步生成器 $G_\theta$ 将 VLM 特征与这 $m$ 个噪声向量结合，在单次前向传播中直接输出 $m$ 个完整的动作块（Action Chunks）候选者。
4. **最近邻分配（Nearest Neighbor Assignment - 仅训练阶段）**：在无梯度计算的情况下，计算这 $m$ 个候选动作与 Ground Truth 动作之间的 L2 距离，选出距离最近的候选者索引 $j^*$。
5. **参数更新（Parameter Update - 仅训练阶段）**：仅针对选出的最近邻候选者计算回归损失，并反向传播更新生成器 $G_\theta$ 的参数。其余 $m-1$ 个候选者不产生惩罚，从而允许模型覆盖其他动作模式。
6. **推理阶段（Inference）**：仅采样 1 个噪声向量，通过单次前向传播直接输出动作块，交由机器人开环执行前 $H$ 步。

**核心伪代码实现 (Python/PyTorch 风格)**：

```python
import torch
import torch.nn as nn

def cimle_train_step(vlm_features, ground_truth_actions, generator, m=2):
    """
    vlm_features: [Batch, Feature_Dim] (Frozen VLM output)
    ground_truth_actions: [Batch, Chunk_Size, Action_Dim]
    generator: Single-step action head G_theta
    m: Number of candidates to sample
    """
    batch_size = vlm_features.shape[0]
    action_shape = ground_truth_actions.shape[1:]
    
    # Step 1: Sample m noise vectors
    # noise shape: [Batch, m, Chunk_Size, Action_Dim]
    noise = torch.randn(batch_size, m, *action_shape, device=vlm_features.device)
    
    # Step 2 & 3: Generate m candidates (Gradient tracking temporarily disabled for assignment)
    candidates = []
    for j in range(m):
        # generator maps (feature, noise) -> action chunk
        cand = generator(vlm_features, noise[:, j]) 
        candidates.append(cand.unsqueeze(1))
    
    # candidates shape: [Batch, m, Chunk_Size, Action_Dim]
    candidates = torch.cat(candidates, dim=1)
    
    # Step 4: Nearest Neighbor Assignment (Gradient-free)
    with torch.no_grad():
        # Calculate L2 distance between each candidate and ground truth
        # gt_expanded shape: [Batch, 1, Chunk_Size, Action_Dim]
        gt_expanded = ground_truth_actions.unsqueeze(1)
        distances = torch.norm(candidates - gt_expanded, p=2, dim=(2, 3)) # shape: [Batch, m]
        
        # Find the index of the closest candidate for each item in the batch
        best_indices = torch.argmin(distances, dim=1) # shape: [Batch]
    
    # Step 5: Parameter Update (Compute loss ONLY for the best candidate)
    # Recompute the best candidate with gradients attached
    best_noise = noise[torch.arange(batch_size), best_indices]
    best_candidates = generator(vlm_features, best_noise)
    
    # Calculate cIMLE loss (L2 loss on the nearest neighbor)
    loss = nn.functional.mse_loss(best_candidates, ground_truth_actions)
    
    return loss
```

### 第二模块：核心架构解释

UniMPA 的核心逻辑是将“记忆（Memory）”、“预测（Prediction）”和“动作（Action）”统一到一个共享的接口下。其前向传播流程分为三个关键阶段：

1. **持久-选择性未来预测（Persistent-Selective Future Prediction）**：

2. **视觉-动作记忆检索（Visual-Action Memory Retrieval）**：

3. **动作-视觉记忆检索与原型偏置流（Action-Visual Memory Retrieval & Prototype-Biased Flow）**：

```python
        self.latent_stream = PersistentLatentStream()
        self.pixel_stream = TransitionCriticalPixelStream()
        self.flow_generator = PrototypeBiasedFlow()

    def forward(self, current_obs, task_instruction):
        # 阶段 1: 持久-选择性未来预测 (解决状态歧义)
        # 追踪宏观任务进度
        task_progress = self.latent_stream(current_obs, task_instruction)

        fine_grained_changes = self.pixel_stream(current_obs, task_progress)
        # 融合得到预测的未来状态转移

        # 用预测的转移去检索历史经验，确保物理可执行性

        # 阶段 3: 动作-视觉记忆检索与动作生成 (解决经验与实现不匹配)
        # 提取动作原型
        action_prototypes = self.memory_bank.query_action_visual(historical_experience, current_obs)
```

### 第二模块：核心架构解释

### 第二模块：核心架构解释

IMLE-VLA 的架构设计遵循“重感知，轻生成”的原则。其核心流程分为特征提取、候选生成、最近邻分配和参数更新四个步骤。

1. **观测编码（Observation Encoding）**：在时间步 $t$，视觉图像和语言指令输入到冻结的大型 VLM 主干中，提取出高维条件特征 $f_{VLM}(o_t)$。
2. **噪声采样（Noise Sampling）**：从标准高斯分布 $\mathcal{N}(0, \mathbf{I})$ 中独立采样 $m$ 个潜变量噪声向量。
3. **候选生成（Candidate Generation）**：轻量级的单步生成器 $G_\theta$ 将 VLM 特征与这 $m$ 个噪声向量结合，在单次前向传播中直接输出 $m$ 个完整的动作块（Action Chunks）候选者。
4. **最近邻分配（Nearest Neighbor Assignment - 仅训练阶段）**：在无梯度计算的情况下，计算这 $m$ 个候选动作与 Ground Truth 动作之间的 L2 距离，选出距离最近的候选者索引 $j^*$。
5. **参数更新（Parameter Update - 仅训练阶段）**：仅针对选出的最近邻候选者计算回归损失，并反向传播更新生成器 $G_\theta$ 的参数。其余 $m-1$ 个候选者不产生惩罚，从而允许模型覆盖其他动作模式。
6. **推理阶段（Inference）**：仅采样 1 个噪声向量，通过单次前向传播直接输出动作块，交由机器人开环执行前 $H$ 步。

**核心伪代码实现 (Python/PyTorch 风格)**：

```python
import torch
import torch.nn as nn

def cimle_train_step(vlm_features, ground_truth_actions, generator, m=2):
    """
    vlm_features: [Batch, Feature_Dim] (Frozen VLM output)
    ground_truth_actions: [Batch, Chunk_Size, Action_Dim]
    generator: Single-step action head G_theta
    m: Number of candidates to sample
    """
    batch_size = vlm_features.shape[0]
    action_shape = ground_truth_actions.shape[1:]
    
    # Step 1: Sample m noise vectors
    # noise shape: [Batch, m, Chunk_Size, Action_Dim]
    noise = torch.randn(batch_size, m, *action_shape, device=vlm_features.device)
    
    # Step 2 & 3: Generate m candidates (Gradient tracking temporarily disabled for assignment)
    candidates = []
    for j in range(m):
        # generator maps (feature, noise) -> action chunk
        cand = generator(vlm_features, noise[:, j]) 
        candidates.append(cand.unsqueeze(1))
    
    # candidates shape: [Batch, m, Chunk_Size, Action_Dim]
    candidates = torch.cat(candidates, dim=1)
    
    # Step 4: Nearest Neighbor Assignment (Gradient-free)
    with torch.no_grad():
        # Calculate L2 distance between each candidate and ground truth
        # gt_expanded shape: [Batch, 1, Chunk_Size, Action_Dim]
        gt_expanded = ground_truth_actions.unsqueeze(1)
        distances = torch.norm(candidates - gt_expanded, p=2, dim=(2, 3)) # shape: [Batch, m]
        
        # Find the index of the closest candidate for each item in the batch
        best_indices = torch.argmin(distances, dim=1) # shape: [Batch]
    
    # Step 5: Parameter Update (Compute loss ONLY for the best candidate)
    # Recompute the best candidate with gradients attached
    best_noise = noise[torch.arange(batch_size), best_indices]
    best_candidates = generator(vlm_features, best_noise)
    
    # Calculate cIMLE loss (L2 loss on the nearest neighbor)
    loss = nn.functional.mse_loss(best_candidates, ground_truth_actions)
    
    return loss
```

### 第二模块：核心架构解释

ActSafeGuard 的核心逻辑是将连续的流匹配过程离散化，并在每一步离散更新中插入一个几何求交运算。

1. **离散流匹配基础**：模型不直接输出连续速度场，而是预测一个离散步长方向 $d_\phi$。
2. **射线求交（Ray Shooting）**：给定当前状态 $x_k$ 和预测方向 $d_\phi$，计算该射线与所有已知线性约束边界（凸多面体）的交点。计算出到达最近边界的最大允许缩放因子 $\alpha$。
3. **安全更新**：定义安全缩放因子 $s_\phi = \min(1, \alpha)$。如果 $\alpha \ge 1$，说明原更新步安全，保持不变；如果 $\alpha < 1$，说明原更新步越界，将其缩放至恰好落在边界上。
4. **边界感知梯度（反向传播）**：当发生边界截断（$\alpha < 1$）时，由于 $\alpha$ 的计算依赖于 $d_\phi$，梯度可以通过 $s_\phi$ 回传。数学上，这等效于一个斜投影矩阵 $Q_i$，它会过滤掉垂直于边界的梯度分量，保留平行于边界的梯度分量，迫使神经网络在后续训练中输出更贴合边界的动作方向。

**核心伪代码实现**：

```python
import torch

def act_safeguard_step(x_k, v_phi, A, b, N):
    """
    x_k: 当前动作状态 [batch_size, action_dim]
    v_phi: 动作头预测的速度场 [batch_size, action_dim]
    A, b: 约束多面体参数 A*x <= b
    N: 离散化步数
    """
    # 1. 计算标称更新方向与步长
    d_phi = v_phi / N 
    
    # 2. 射线求交 (Ray Shooting)
    # 计算 A * d_phi (分母) 和 b - A * x_k (分子)
    denom = torch.matmul(A, d_phi.unsqueeze(-1)).squeeze(-1)
    num = b - torch.matmul(A, x_k.unsqueeze(-1)).squeeze(-1)
    
    # 仅考虑指向边界外的方向 (denom > 0)
    # 为避免除零，加上极小值 epsilon
    eps = 1e-8
    valid_mask = denom > eps
    
    # 计算所有有效边界的 alpha 值
    alphas = torch.where(valid_mask, num / denom, torch.inf)
    
    # 找到最近的边界交点对应的 alpha
    alpha_min, _ = torch.min(alphas, dim=-1, keepdim=True)
    
    # 3. 计算安全缩放因子 s_phi
    # 如果 alpha_min >= 1，说明未越界；否则缩放至边界
    s_phi = torch.clamp(alpha_min, max=1.0)
    
    # 4. 应用安全更新 (前向传播安全，反向传播可微)
    delta_phi = s_phi * d_phi
    x_next = x_k + delta_phi
    
    return x_next, delta_phi
```

### 第二模块：核心架构解释

FARM 的核心思想是“特征提取与轻量级监督解码分离”。其运行流程如下：

1. **状态提取 (Frozen WM-State Extraction)**：在每个重规划时间步 $t$，系统将历史观测输入冻结的 VLA-JEPA 模型。FARM 截取预测器最后一层（第 12 层）在归一化和输出投影之前的隐藏状态，剥离动作条件 Token，保留 768 个世界状态 Token，形成维度为 $768 \times 1024$ 的张量 $H^{WM}_t$。
2. **轻量级读出 (Lightweight Failure Readout)**：使用一个共享权重的线性层将 1024 维特征降维至 32 维。随后通过基于内容的注意力机制（Attention Pooling）计算 768 个 Token 的权重并进行加权求和，得到 32 维的全局故障感知表征 $z^F_t$。最后通过一个小型 MLP 输出当前步的故障概率分数 $s_t \in [0, 1]$。
3. **因果风险聚合 (Causal Execution Monitoring)**：为了防止局部状态波动导致分数下降，FARM 采用严格的因果聚合逻辑，当前时刻的轨迹风险 $q_t$ 定义为历史所有单步分数 $s_\tau$ 的最大值。

以下是 FARM 核心前向传播逻辑的 Python 伪代码实现：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class FARMReadout(nn.Module):
    def __init__(self, hidden_dim=1024, bottleneck_dim=32):
        super().__init__()
        # 1. Token Projection (Shared across all 768 tokens)
        self.proj_linear = nn.Linear(hidden_dim, bottleneck_dim)
        self.proj_ln = nn.LayerNorm(bottleneck_dim)
        
        # 2. Attention Pooling
        self.attn_vector = nn.Parameter(torch.randn(bottleneck_dim))
        
        # 3. Output MLP
        self.mlp = nn.Sequential(
            nn.Linear(bottleneck_dim, bottleneck_dim),
            nn.GELU(),
            nn.Linear(bottleneck_dim, 1),
            nn.Sigmoid()
        )
        
        # Causal risk state (maintained during online rollout)
        self.current_trajectory_risk = 0.0

    def forward(self, h_wm_t):
        """
        h_wm_t: Frozen WM state tensor at step t, shape [batch_size, 768, 1024]
        """
        # Step 1: Token Projection
        # [batch_size, 768, 1024] -> [batch_size, 768, 32]
        u = F.gelu(self.proj_ln(self.proj_linear(h_wm_t)))
        
        # Step 2: Content-dependent Attention Pooling
        # Calculate attention scores: [batch_size, 768]
        attn_logits = torch.matmul(u, self.attn_vector)
        alpha = F.softmax(attn_logits, dim=1)
        
        # Weighted sum over tokens: [batch_size, 32]
        r = torch.sum(u * alpha.unsqueeze(-1), dim=1)
        
        # Step 3: Failure Score Generation
        z_f = F.gelu(r) # Simplified MLP hidden logic
        s_t = self.mlp(z_f).squeeze(-1) # Step-wise failure score [0, 1]
        
        return s_t
        
    def update_causal_risk(self, s_t):
        """
        Aggregates step score into monotonically increasing trajectory risk
        """
        self.current_trajectory_risk = max(self.current_trajectory_risk, s_t.item())
        return self.current_trajectory_risk

# Execution Flow
# 1. vla_jepa is strictly frozen (requires_grad=False)
# 2. Extract block 12 tokens before normalization
h_wm_t = vla_jepa.extract_predictive_state(observation_history) 

# 3. Pass to FARM
farm_model = FARMReadout()
step_score = farm_model(h_wm_t)
trajectory_risk = farm_model.update_causal_risk(step_score)
```

### 第二模块：核心架构解释

本文的架构由两个核心部分组成：诊断基准（VWG-Bench）与生成增强模块（Vid-PRE）。

**1. VWG-Bench（评估端）：**

*   视频级流畅度（Video-level fluency）：仅评估视频的视觉连贯性与时空一致性。
*   任务级规则遵循（Task-level rule adherence）：评估视频是否违背了该类任务的通用物理或逻辑规则。
*   样本级目标实现（Sample-level goal realization）：评估视频是否完成了特定 prompt 要求的具体动作或状态变化。

**2. Vid-PRE（增强端）：**
一个模型无关的提示词推理与增强器。
*   **训练阶段：** 使用强化学习（RL）对 VLM 进行微调。奖励函数不依赖视频生成结果，而是通过另一个裁判 VLM 评估重写后的提示词是否包含了清晰的约束、物理定律和动作细节。
*   **推理阶段：** 接收用户的原始 prompt，Vid-PRE 将其重写为结构化、强约束的 detailed prompt，随后输入给冻结的视频生成模型进行渲染。

```python
class VWGBenchEvaluator:
    def __init__(self, vlm_judge):
        self.vlm_judge = vlm_judge
        
    def evaluate(self, video, original_prompt, task_rules):
        # Level 1: 视觉流畅度 (独立于文本)
        fluency_score = self.vlm_judge.score_fluency(video)
        
        # Level 2: 任务规则遵循 (物理/逻辑定律)
        rule_score = self.vlm_judge.score_rule_adherence(video, task_rules)
        
        # Level 3: 样本目标实现 (指令跟随)
        goal_score = self.vlm_judge.score_goal_realization(video, original_prompt)
        
        return fluency_score, rule_score, goal_score

class VidPRE:
    def __init__(self, base_vlm):
        self.rewriter = base_vlm
        
    def train_step_rl(self, raw_prompt, text_reward_model):
        # 生成重写后的提示词
        enhanced_prompt = self.rewriter.generate(raw_prompt)
        
        # 纯文本奖励：评估提示词是否包含物理约束、逻辑步骤等
        reward = text_reward_model.compute_reward(raw_prompt, enhanced_prompt)
        
        # PPO 或其他 RL 算法更新重写器权重
        self.rewriter.update_weights(reward)
        
    def inference(self, raw_prompt, video_generator):
        # 认知卸载：由 VLM 处理逻辑推理
        enhanced_prompt = self.rewriter.generate(raw_prompt)
        
        # 视频模型仅负责视觉渲染
        video = video_generator.generate_video(enhanced_prompt)
        return video
```

### 第二模块：核心架构解释

2AM 的核心架构是一个双时钟频率的分层系统，包含 Agent Model、Action Model 以及连接两者的 Compositional Steering Contract（组合引导契约）。

1.  **Agent Model (高频决策，持有记忆):** 接收当前全局视角的 RGB 图像和历史交互记录。输出一个组合指令 $c_k$。
2.  **Compositional Steering Contract (高带宽接口):** 指令 $c_k$ 包含四个元素：局部语言指令、2D 抓取点、2D 放置点、2D 移动方向点。这些 2D 点均投影在当前全局 RGB 图像的像素坐标系中。
3.  **Action Model (低频执行，无状态):** 接收当前全局 RGB、腕部 RGB、机器人本体状态以及指令 $c_k$。它不读取任何历史帧，直接预测未来 $L$ 步的绝对末端执行器动作块（Action Chunk）。
4.  **Robust Training (鲁棒性训练):** 为了让 Action Model 容忍 Agent 在推理时产生的坐标偏移或指令缺失，训练阶段直接从离线演示数据中提取 2D 标签（无需 VLM 标注），并对这些 2D 提示施加结构化丢弃（Dropout）、空间噪声（Spatial Noise）和时间抖动（Temporal Jitter）。

### 第二模块：核心架构解释

SoftPrompt 的核心逻辑在于摒弃对模型权重的修改，转而在输入序列的特定物理位置构建一个“梯度汇聚点”。其架构与实验流程如下：

1. **输入编码**：将图像和文本查询分别通过冻结的编码器，得到视觉 Patch Embeddings 和文本 Token Embeddings。
2. **跨模态边界注入（核心创新）**：放弃 NLP 惯用的前缀（Prefix）注入，将 $L$ 个连续的可学习 Soft Tokens 插入到视觉特征和文本特征之间，形成 `[Image; Soft; Text]` (IST) 的序列顺序。这个位置是多模态注意力的天然瓶颈。
3. **无损初始化**：Soft Tokens 不使用随机或任务相关的语义初始化，而是统一初始化为“空格符（Space Token）”的 Embedding。这遵循了残差学习的理念：初始状态下 Prompt 不改变任何语义，确保起点即是预训练模型的 Baseline。
4. **冻结前向与局部反向传播**：整个 VLM 处于冻结状态。前向传播计算 Next-token 损失；反向传播时，梯度穿透所有冻结层，最终只更新输入端的 Soft Tokens。

**核心伪代码实现 (Python 风格)**:

```python
import torch
import torch.nn as nn

class SoftPromptVLM(nn.Module):
    def __init__(self, frozen_vlm, num_soft_tokens=2):
        super().__init__()
        self.vlm = frozen_vlm
        # 冻结 VLM 的所有参数
        for param in self.vlm.parameters():
            param.requires_grad = False
            
        self.num_soft_tokens = num_soft_tokens
        self.embedding_dim = self.vlm.config.hidden_size
        
        # 定义可学习的 Soft Tokens
        self.soft_tokens = nn.Parameter(torch.empty(1, num_soft_tokens, self.embedding_dim))
        
        # 核心：使用"空格符"的 Embedding 进行初始化 (无语义初始化)
        space_token_id = self.vlm.tokenizer(" ", return_tensors="pt").input_ids[0]
        space_embedding = self.vlm.get_input_embeddings()(space_token_id).detach()
        nn.init.constant_(self.soft_tokens, space_embedding.item()) # 简化表达

    def forward(self, images, text_queries):
        # 1. 获取冻结的视觉和文本特征
        image_embeds = self.vlm.encode_image(images) # Shape: [B, N_I, D]
        text_embeds = self.vlm.encode_text(text_queries) # Shape: [B, N_T, D]
        
        # 扩展 Soft Tokens 以匹配 Batch Size
        batch_size = image_embeds.shape[0]
        batch_soft_tokens = self.soft_tokens.expand(batch_size, -1, -1)
        
        # 2. 核心创新：跨模态边界拼接 (IST 顺序: Image -> Soft -> Text)
        # 拒绝 Prefix (SIT) 或 Suffix (ITS)
        multimodal_sequence = torch.cat([
            image_embeds, 
            batch_soft_tokens, 
            text_embeds
```

### 第二模块：核心架构解释

CAP 框架摒弃了传统的多策略路由机制，采用单一策略网络处理多模态输入。其核心架构与实验流程可拆解为以下三个关键部分：

1. **感知世界模型编码器（Perceptive World-Model Encoder）**：
该模块本质上是一个去噪自编码器的编码部分。输入为受损或带有噪声的深度图，训练目标是重建干净的深度图。其输出的隐变量（Latent）包含了去噪后的环境几何信息。
2. **本体感觉变分编码器（Proprioceptive Variational Encoder）**：
独立处理机器人的本体感觉数据（如关节角度、速度、IMU 数据），提取与视觉无关的身体状态上下文特征，确保在视觉完全失效时提供基础的运动维持能力。
3. **耦合训练机制（Coupled Training Recipe）**：
在训练阶段，系统在输入端引入**深度噪声课程（Depth-noise curriculum）**，逐步增加深度图的损坏程度；同时在策略网络的输入前，对世界模型输出的隐变量施加**特征 Dropout（Feature dropout）**。这种双重扰动迫使策略网络学会在不同感知质量下动态调整对视觉特征和本体感觉特征的依赖权重。

**核心逻辑伪代码（Python/PyTorch 风格）**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class CAP_Framework(nn.Module):
    def __init__(self):
        super().__init__()
        # 1. 去噪世界模型编码器与解码器
        self.world_model_encoder = PerceptiveEncoder()
        self.world_model_decoder = DepthDecoder()
        
        # 2. 本体感觉变分编码器
        self.proprio_encoder = ProprioceptiveEncoder()
        
        # 3. 单阶段控制策略网络
        self.policy_network = SingleStagePolicy()

    def forward(self, corrupted_depth, proprioception, is_training=True, dropout_prob=0.5):
        # 提取本体感觉特征
        proprio_latent = self.proprio_encoder(proprioception)
        
        # 提取并去噪深度特征
        vision_latent = self.world_model_encoder(corrupted_depth)
        
        # 重建干净深度图（用于计算去噪损失）
        reconstructed_depth = self.world_model_decoder(vision_latent)
        
        # 核心机制：特征层面的 Dropout，模拟视觉完全失效
        if is_training:
            # 以 dropout_prob 的概率将视觉特征置零
            mask = (torch.rand(vision_latent.shape[0], 1) > dropout_prob).float().to(vision_latent.device)
            policy_vision_latent = vision_latent * mask
        else:
            policy_vision_latent = vision_latent
            
        # 拼接特征并输出动作
        combined_latent = torch.cat([policy_vision_latent, proprio_latent], dim=-1)
        action = self.policy_network(combined_latent)
        
        return action, reconstructed_depth

# 训练步逻辑
def train_step(batch, model, optimizer):
    clean_depth, proprioception, target_action = batch
    
    # 核心机制：深度噪声课程，向干净深度图注入不同程度的噪声/遮挡
    corrupted_depth = apply_noise_curriculum(clean_depth)
    
    # 前向传播
    pred_action, reconstructed_depth = model(corrupted_depth, proprioception, is_training=True)
    
    # 损失计算：动作克隆/RL损失 + 世界模型去噪重建损失
    policy_loss = compute_rl_or_bc_loss(pred_action, target_action)
    denoising_loss = F.mse_loss(reconstructed_depth, clean_depth)
    
    total_loss = policy_loss + lambda_weight * denoising_loss
    
    optimizer.zero_grad()
    total_loss.backward()
    optimizer.step()
```

**阶段一：视觉证据构建 (Visual Evidence Construction)**

1. 目标视图场景证据：利用深度估计将源视频像素重投影到目标相机视角，提供空间布局参考。
2. 渲染几何证据：针对相机运动暴露出的未见区域，利用 3D 身体模型（如 SMPL-X）渲染目标视角的形状和外观提案。
3. 检索生成证据：维护一个全局历史库，当相机返回已生成但被滚动缓存（Rolling Cache）淘汰的区域时，检索相关的历史 K/V 状态。

**阶段二：状态转换与缓存 (State Conversion)**
将上述证据输入冻结的视频主干网络（设定扩散时间步 $t=0$），提取每一层注意力块的 Key 和 Value，作为干净的视觉状态缓存（Clean K/V）。

**阶段三：注意力路由与引导 (Attention Routing and Guidance)**
在目标帧的去噪生成过程中，当前 Token 的 Query 不仅与原生缓存交互，还与辅助证据的 K/V 交互。通过 CGAR 引入几何匹配偏置，通过 EWA 在注意力响应层面调节引导强度。

**核心底层逻辑伪代码 (Python 风格)**：

```python
def EWA_attention_forward(query, native_k, native_v, evidence_list, geom_matches, guidance_scales):
    """
    模拟单层自注意力机制中的 CGAR 与 EWA 过程
    """
    # 1. 计算原生注意力响应 (Native Response)
    attn_native = softmax(query @ native_k.T / sqrt(d))
    out_native = attn_native @ native_v
    
    final_output = out_native.clone()
    
    # 2. 遍历所有辅助视觉证据 (Auxiliary Evidence)
    for i, evidence in enumerate(evidence_list):
        ev_k, ev_v = evidence['k'], evidence['v']
        
        # --- CGAR: 对应引导的注意力路由 ---
        # 计算基础注意力分数
        score_ev = query @ ev_k.T / sqrt(d)
        # 注入几何匹配先验 (对应公式 4)
        if geom_matches[i] is not None:
            score_ev += torch.log(geom_matches[i]) 
            
        # 联合归一化计算当前证据的响应
        attn_joint = softmax(torch.cat([query @ native_k.T / sqrt(d), score_ev], dim=-1))
        attn_ev_weight = attn_joint[:, native_k.shape[-1]:]
        out_ev = attn_ev_weight @ ev_v
        
        # --- EWA: 证据级注意力 CFG (对应公式 5) ---
        # 计算余弦相似度以判断方向一致性
        cos_sim = cosine_similarity(out_ev, out_native)
        cos_sim_clamped = torch.max(torch.zeros_like(cos_sim), cos_sim)
        
        # 移除沿原生响应方向的投影，提取互补信息
        proj_ev_on_native = projection(out_ev, out_native)
        complementary_info = out_ev - proj_ev_on_native
        
        # 施加独立的引导强度
        g_e = guidance_scales[i]
        out_ev_adjusted = out_ev + g_e * cos_sim_clamped * complementary_info
        
        # 累加修正量
        final_output += (out_ev_adjusted - out_native)
        
    # 3. 幅度裁剪，防止过度引导破坏生成质量
    final_output = bound_magnitude(final_output, reference_norm=norm(out_native))
    
    return final_output
```

### 第二模块：核心架构解释

DLSRL 的核心逻辑在于“冻结主体，双路干预”。其架构与实验流程可拆解为以下四个阶段：

1.  **双潜变量生成 (Dual-Latent Generation):** 给定当前环境观测 $o_t$，双潜 Actor 网络 $\pi_\theta$ 输出两个变量：初始噪声潜变量 $z_t$ 和动作表示潜变量 $u_t$。
2.  **特征映射 (Feature Mapping):** $u_t$ 通过一个轻量级的适配器特征映射网络 $\mathcal{A}_\omega$，被转换为与 Transformer 动作 token 维度一致的适配器特征 $f_t$。
3.  **残差注入与动作解码 (Residual Injection & Decoding):** 冻结的基础策略（Diffusion 或 Flow-Matching）开始解码。在选定的 Transformer 层，特征 $f_t$ 乘以一个全局标量 $\lambda_{inj}$ 后，通过残差相加的方式注入到动作 token 的隐藏状态中。最终输出动作块 $a_t$。
4.  **价值蒸馏与策略更新 (Value Distillation Optimization):** 采用离策略 TD 学习训练动作空间 Critic $Q^{act}_\psi$；随后将 $Q^{act}_\psi$ 的价值评估“蒸馏”给潜空间 Critic $Q^{lat}_\nu$；最后，通过最大化 $Q^{lat}_\nu$ 并结合熵正则化来更新 Actor 网络 $\pi_\theta$ 和映射网络 $\mathcal{A}_\omega$。

**核心前向传播伪代码实现：**

```python
import torch
import torch.nn as nn

class DLSRL_Policy(nn.Module):
    def __init__(self, base_policy, actor, feature_mapper, lambda_inj, target_layer_idx):
        super().__init__()
        # 冻结的基础生成策略 (如 Diffusion Transformer)
        self.base_policy = base_policy 
        for param in self.base_policy.parameters():
            param.requires_grad = False
            
        # 可训练的双潜 Actor 与特征映射器
        self.actor = actor
        self.feature_mapper = feature_mapper
        
        self.lambda_inj = lambda_inj
        self.target_layer_idx = target_layer_idx

    def forward(self, obs):
        # 1. Actor 生成双潜变量
        # z_t: 初始噪声潜变量, u_t: 动作表示潜变量
        z_t, u_t = self.actor(obs) 
        
        # 2. 映射为适配器特征
        f_t = self.feature_mapper(u_t) 
        
        # 3. 基础策略解码与残差注入
        # 假设 base_policy 内部按层执行
        hidden_states = self.base_policy.get_initial_condition(obs, z_t)
        
        for i, layer in enumerate(self.base_policy.transformer_blocks):
            hidden_states = layer(hidden_states)
            
            # 在指定层进行动作 token 的隐藏状态调制
            if i == self.target_layer_idx:
                # 仅对 action tokens 对应的位置进行残差注入
                action_token_mask = self.base_policy.get_action_token_mask()
                delta_t = self.lambda_inj * f_t
                hidden_states[action_token_mask] += delta_t
                
        # 输出最终动作块
        action_chunk = self.base_policy.action_head(hidden_states)
        return action_chunk
```

### 第二模块：核心架构解释

LTLDiff 的系统架构分为三个核心阶段：逻辑生成与编码、逻辑引导的数据生成、以及多智能体逻辑引导扩散策略（LTLMAG）。

**1. $LTL_f$ 生成与编码 (Logic Generation & Encoding)**
*   **生成:** 使用大语言模型（Qwen）接收自然语言任务描述，输出包含时序操作符（如 F, G, U, X）和逻辑操作符的 $LTL_f$ 公式。
*   **编码:** 将 $LTL_f$ 公式解析为抽象语法树（AST）。叶子节点为原子命题（One-hot 编码），内部节点为操作符。通过自底向上的递归计算，最终将根节点映射为一个 128 维的固定长度向量 `z_phi`。

**2. 逻辑引导的离线数据生成 (Logic-Guided Data Generation)**
*   将 `z_phi` 作为偏置信号，调节底层运动规划器（Motion Planner）的参数（如速度、加速度平滑度、目标位置）。
*   强制生成的轨迹在物理可行的基础上，严格符合 $LTL_f$ 定义的时序阶段（Phases），从而构建出高质量的离线数据集 $D = \{(\tau^{(k)}, \phi)\}_{k=1}^K$。

**3. LTLMAG: 多智能体逻辑引导扩散策略 (Multi-Agent Diffusion Policy)**
*   在标准的条件扩散模型基础上，引入了双重逻辑约束：
    *   **全局条件 (Global Conditioning):** 扩散策略 $\pi_\theta$ 直接接收 `z_phi` 作为条件输入，使模型在早期高噪声阶段就能获得任务一致性的先验。
    *   **回归器引导 (Regressor Guidance):** 训练一个前馈神经网络 $g_\phi$ 作为满意度评估器。在反向去噪过程中，计算联合轨迹对 $LTL_f$ 的满足度梯度，并将其作为引导信号注入到去噪步骤中。

**核心底层逻辑伪代码 (Python 风格):**

```python
def LTLMAG_sampling(diffusion_steps, num_agents, z_phi, policy_model, regressor_model, guidance_scale):
    """
    多智能体 LTL_f 引导的扩散策略采样过程 (对应 Algorithm 1)
    """
    # 初始化联合轨迹为纯高斯噪声
    tau_all = torch.randn(num_agents, trajectory_length, action_dim)
    
    for i in reversed(range(1, diffusion_steps + 1)):
        alpha_i = get_alpha(i)
        tau_next_list = []
        
        # 阶段一：单智能体局部去噪 (Conditioned on LTL_f embedding)
        for n in range(num_agents):
            noise = torch.randn_like(tau_all[n]) if i > 1 else 0
            
            # 策略网络预测去噪方向，z_phi 作为全局条件注入
            predicted_action = policy_model(tau_all[n], condition=z_phi)
            
            # 标准 DDPM/DDIM 去噪步
            tau_next_n = (1 / sqrt(alpha_i)) * (tau_all[n] + (1 - alpha_i) * predicted_action) + sqrt(1 - alpha_i) * noise
            tau_next_list.append(tau_next_n)
            
        # 拼接所有智能体的局部去噪轨迹
        tau_all_next = torch.stack(tau_next_list)
        
        # 阶段二：跨智能体联合逻辑引导 (Regressor Guidance)
        # 计算当前联合轨迹满足 LTL_f 逻辑的梯度方向
        satisfaction_gradient = regressor_model.get_gradient(tau_all_next, z_phi, step=i)
        
        # 将梯度引导注入联合轨迹，强制修正时序和协同错误
        tau_all = tau_all_next + guidance_scale[i] * satisfaction_gradient
        
    return tau_all # 返回最终干净的协同动作轨迹
```

### 第二模块：核心架构解释

RCWM 的核心逻辑是将复杂的 3D 场景重建任务转化为一个可执行的递归代码工程。其架构由三个关键部分组成：

1. **递归场景程序 (RSP, Recursive Scene Program)**：将 3D 世界表示为模块化、可组合的场景代码，支持层级化的结构表达。
2. **全局-局部-全局递归求解器 (Global-Local-Global Recursive Solver)**：
   * **建立整体 (Establish the whole)**：生成当前层级场景的粗略全局代码结构。
   * **递归局部 (Recursively reconstruct)**：识别当前层级未解决的局部细节，将相机视角对齐后，对局部进行独立的“感知-编辑”循环（即递归调用自身）。
   * **重访整体 (Revisit the whole)**：局部构建完成后，返回上一级，处理边界、空间关系并修正局部细化引入的全局共享错误。
3. **视觉-语言编码智能体 (VLM Coding Agent)**：作为核心驱动引擎，通过直接对比“参考图像”与“当前代码渲染图”，提供视觉反馈，指导代码的细化、递归下降和返回。

**核心伪代码实现逻辑**：

```python
def recursive_construct(reference_image, current_target, shared_camera_proj):
    """
    RCWM 核心递归求解器
    """
    # 1. 建立整体 (Global)
    # VLM 智能体根据参考图生成当前层级的初始代码
    scene_code = vlm_agent.generate_initial_code(reference_image, current_target)
    rendered_img = render_engine.render(scene_code, shared_camera_proj)
    
    # VLM 对比渲染图与参考图，进行初步修正
    scene_code = vlm_agent.refine_code(reference_image, rendered_img, scene_code)
    
    # 2. 递归局部 (Local)
    # 识别当前层级中粗糙或未解决的局部组件
    unresolved_parts = vlm_agent.identify_unresolved_parts(reference_image, rendered_img)
    
    for part in unresolved_parts:
        # 传递共享的相机投影矩阵，确保局部坐标系与全局对齐
        local_code = recursive_construct(reference_image, part, shared_camera_proj)
        # 将局部精细代码组合回当前场景代码中
        scene_code.integrate(local_code)
        
    # 3. 重访整体 (Global)
    # 局部组合完成后，重新渲染整体场景
    final_rendered_img = render_engine.render(scene_code, shared_camera_proj)
    
    # VLM 修复局部拼接产生的边界冲突、空间关系错误或共享错误
    scene_code = vlm_agent.fix_boundaries_and_relations(
        reference_image, final_rendered_img, scene_code
    )
    
    return scene_code
```

### 第一模块：一分钟核心速写

**论文领域**：World Model

**TL;DR**: 本文提出了一种基于反事实分支（Counterfactual Branching）的 Fork Ledger 评估框架，以解决连续世界模型（Continual World Models）更新时机与实际控制收益脱节的问题，在 CartPole、Walker 和 Cheetah 等模拟控制基准上实现了对单次模型更新真实价值的精确测量与归因。

**研究动机**: 现存方案最大的痛点在于，决定世界模型何时更新的现有方法（如固定频率或预测误差触发器）无法证明某次具体的更新是否真的提升了控制性能。因为在单一的部署流中，反事实（即“如果当时不更新，模型表现会怎样”）是不可观测的。本文的切入点极其巧妙：利用仿真环境的可重置性，在决策点同时运行“更新”和“不更新”两个平行分支，直接计算两者的回报差值。
**核心机制**: 剥离复杂的数学公式，其本质创新是引入了“公共随机数（CRN）”同步的平行宇宙测试法。在模型准备更新的瞬间，克隆出两个完全相同的环境与状态，一个应用梯度更新，另一个保持冻结，在绝对一致的物理参数和噪声下运行，从而纯粹地剥离出“更新”这一动作带来的因果收益。

**关键数据**:
- **最能证明其有效性的核心数据**：在 CartPole 任务中，采用“始终更新”的固定策略会导致总回报相对于“从不更新”暴跌 $-26,441$；而使用 Fork Ledger 筛选出的“残差触发器（Residual Trigger）”指导更新，则获得了 $+2,198$ 的正向收益。这直接证明了盲目更新是有害的，且该框架能有效筛选出有价值的更新时机。
- **存疑/局限的试验结果**：在 Cheetah 任务中，更新的平均收益为 $-3.9$，且 95% 置信区间跨越零点（$[-17.5, +13.0]$），结果高度依赖于环境漂移的方向。此外，在 Walker 任务上，几乎所有的触发器信号都无法有效区分正负收益。这说明作者测试的触发器信号缺乏跨任务的泛化能力，当前并不存在一个通用的世界模型更新法则。

### 第二模块：核心架构解释

Fork Ledger 框架的运行流程严格分为三个阶段，其核心在于通过控制变量法消除环境噪声对模型评估的干扰。

**1. 参考流部署（Reference Stream）**
将预训练的世界模型部署在物理参数随时间漂移（Volatility）且存在动作噪声（Stochasticity）的环境中。在此阶段，模型不进行任何更新，仅记录每一步的预测误差等前置信号（Pre-fork signals）。

**2. 配对分支评估（Paired Continuations）**
在预先设定的决策点（Decision Points），系统保存当前仿真器状态，并分叉出两个独立的评估分支：
- **UPDATE 分支**：使用最近收集的 $W$ 步数据，对世界模型执行 $N$ 步梯度更新。
- **HOLD 分支**：模型参数保持冻结，不作任何改变。

**3. 严格对齐的收益计算（Scoring with CRN）**
两个分支在完全相同的初始状态、相同的注入动作噪声、相同的规划器采样噪声（即公共随机数 Common Random Numbers）下运行 $m$ 个回合。最终计算两者的真实回报差值 $\Delta R = R_{\mathrm{update}} - R_{\mathrm{hold}}$。

**核心伪代码实现逻辑**：

```python
def fork_ledger_evaluation(env, pretrained_model, decision_points, W_buffer, N_steps, m_episodes):
    ledger_results = []
    
    # 1. 运行参考流
    for step in range(total_steps):
        transition = env.step(pretrained_model.act(env.obs))
        W_buffer.add(transition)
        
        if step in decision_points:
            # 记录前置信号（如预测误差），用于后续评估触发器
            pre_fork_signal = compute_residual(pretrained_model, transition)
            
            # 2. 准备配对分支
            # 保存当前环境的精确物理状态和随机数种子
            saved_env_state = env.get_state()
            crn_seeds = generate_common_random_numbers(m_episodes)
            
            # 分支 A: UPDATE
            model_update = pretrained_model.clone()
            model_update.train(W_buffer, steps=N_steps)
            R_update = evaluate_model(model_update, saved_env_state, crn_seeds, m_episodes)
            
            # 分支 B: HOLD
            model_hold = pretrained_model.clone()
            R_hold = evaluate_model(model_hold, saved_env_state, crn_seeds, m_episodes)
            
            # 3. 计算因果收益
            delta_R = R_update - R_hold
            
            ledger_results.append({
                'step': step,
                'pre_fork_signal': pre_fork_signal,
                'delta_R': delta_R
            })
            
    return ledger_results

def evaluate_model(model, env_state, seeds, m_episodes):
    total_return = 0
    for seed in seeds:
        # 严格对齐物理状态与随机噪声
        eval_env = restore_env(env_state)
        eval_env.set_seed(seed) 
        total_return += run_episode(eval_env, model)
    return total_return / m_episodes
```
