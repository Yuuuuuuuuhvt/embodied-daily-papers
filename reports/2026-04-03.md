### 第二模块：核心架构解释

UniDriveVLA 的核心逻辑是**“分而治之，受控交互”**。整个前向传播流程和实验流程如下：

1. **特征初始化**：图像和指令通过 Vision Encoder 和 Tokenizer 生成**理解 Token**；通过 K-Means 初始化的稀疏查询生成**感知 Token**；通过高斯噪声和目标速度插值生成**动作 Token**。
2. **专家解耦投影**：在进入 Transformer 层时，三种 Token 不再共享 QKV 投影矩阵，而是分别进入各自的“专家”线性层，映射到独立的参数子空间。
3. **掩码联合注意力**：将三组 Token 拼接，进行全局 Attention，但施加严格的可见性掩码：
   - 理解 Token：仅做因果注意力，不看感知和动作（保护原生语言能力）。
   - 感知 Token：可以看前面的理解 Token（获取语义上下文）。
   - 动作 Token：可以看所有 Token（聚合语义和空间信息用于规划）。
4. **稀疏感知解码与动作生成**：感知 Token 输出 3D 检测、建图、占据网格等；动作 Token 通过 Flow-Matching（流匹配）生成最终的自车轨迹。
5. **三阶段渐进式训练**：第一阶段用 VQA 数据微调 VLM 锚定语义能力；第二阶段用 LoRA 联合优化感知与语言；第三阶段冻结 VLM，专精微调感知与动作专家。

**核心底层逻辑伪代码 (Python-style)**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class MoTLayer(nn.Module):
    def __init__(self, dim):
        super().__init__()
        # 1. 专家解耦：为理解、感知、动作分配独立的 QKV 投影
        self.expert_und = nn.Linear(dim, dim * 3) # Understanding
        self.expert_per = nn.Linear(dim, dim * 3) # Perception
        self.expert_act = nn.Linear(dim, dim * 3) # Action
        
        self.ffn_und = FFN(dim)
        self.ffn_per = FFN(dim)
        self.ffn_act = FFN(dim)

    def forward(self, t_und, t_per, t_act, attention_mask):
        # t_und: [B, L_u, D], t_per: [B, L_p, D], t_act: [B, L_a, D]
        
        # 2. 独立投影获取 Q, K, V
        qkv_und = self.expert_und(t_und).chunk(3, dim=-1)
        qkv_per = self.expert_per(t_per).chunk(3, dim=-1)
        qkv_act = self.expert_act(t_act).chunk(3, dim=-1)
        
        # 3. 拼接 Q, K, V 用于联合注意力
        Q = torch.cat([qkv_und[0], qkv_per[0], qkv_act[0]], dim=1)
        K = torch.cat([qkv_und[1], qkv_per[1], qkv_act[1]], dim=1)
        V = torch.cat([qkv_und[2], qkv_per[2], qkv_act[2]], dim=1)
        
        # 4. 掩码联合注意力 (Masked Joint Attention)
        # attention_mask 确保:
        # - t_und 只能看到 t_und (Causal)
        # - t_per 可以看到 t_und 和 t_per
        # - t_act 可以看到所有
        attn_scores = torch.matmul(Q, K.transpose(-2, -1)) / (Q.size(-1) ** 0.5)
        attn_scores = attn_scores + attention_mask 
        attn_output = torch.matmul(F.softmax(attn_scores, dim=-1), V)
        
        # 5. 拆分回各自的专家流并进行 FFN
        out_und, out_per, out_act = torch.split(attn_output, [t_und.size(1), t_per.size(1), t_act.size(1)], dim=1)
        
        t_und = t_und + self.ffn_und(out_und)
        t_per = t_per + self.ffn_per(out_per)
        t_act = t_act + self.ffn_act(out_act)
        
        return t_und, t_per, t_act
```

### 第二模块：核心架构解释

WAV 框架的核心逻辑是一个反向的自我验证循环，具体包含三个执行步骤与一个更新步骤：

1. **子目标生成 (Subgoal Generation)**：系统首先利用在大量无动作视频上预训练的生成模型，基于当前状态生成多个符合物理规律的候选未来状态。这一步利用了视频数据易于获取的优势，确保生成的未来状态在物理上是合理的。
2. **稀疏逆向推断 (Sparse Inverse Inference)**：系统使用一个带有特征掩码的逆向动力学模型。该模型强制忽略复杂的背景环境，仅提取与动作直接相关的局部状态变化（例如机械臂末端的位置变化），从而反推出实现上述候选未来状态所需的具体动作。
3. **正向验证与计算分歧 (Forward Verification)**：系统将反推得到的动作输入给当前正在训练的世界模型，让其进行正向预测。随后，计算世界模型的预测结果与第一步生成的候选未来状态之间的物理距离（分歧度）。
4. **数据采集与自我改进 (Data Collection & Self-Improvement)**：分歧度最大的样本代表了当前世界模型的认知盲区。系统将选择该样本对应的动作在真实环境中执行，收集真实的交互数据，并用这些新数据同步更新世界模型和逆向动力学模型。

```python
def wav_guided_exploration(current_state, world_model, subgoal_generator, sparse_inverse_model, env, data_buffer, K_candidates):
    # 步骤 1: 基于当前状态，生成 K 个符合物理规律的候选未来状态
    candidate_subgoals = subgoal_generator.sample(current_state, K_candidates)
    
    # 步骤 2: 利用稀疏逆向模型，从局部特征变化中反推实现这些状态所需的动作
    inferred_actions = sparse_inverse_model.predict_action(current_state, candidate_subgoals)
    
    # 步骤 3: 世界模型接收反推的动作，进行正向的未来状态预测
    predicted_outcomes = world_model.predict_next_state(current_state, inferred_actions)
    
    # 步骤 4: 计算生成的候选状态与世界模型预测状态之间的差异得分
    disagreement_scores = calculate_distance(candidate_subgoals, predicted_outcomes)
    
    # 步骤 5: 找出差异得分最大的动作（即模型最不擅长预测的动作），在环境中实际执行
    best_action_idx = argmax(disagreement_scores)
    selected_action = inferred_actions[best_action_idx]
    actual_next_state = env.step(selected_action)
    
    # 步骤 6: 将最具信息量的真实交互数据存入经验池，并更新模型
    data_buffer.append(current_state, selected_action, actual_next_state)
    world_model.update(data_buffer)
    sparse_inverse_model.update(data_buffer)
```

### 第二模块：核心架构解释

LatentUM 的核心架构围绕“潜在空间内的闭环流转”展开，其工作流程可拆解为三个关键阶段：

1. **统一编码阶段（Unified Encoding）**：无论是文本还是图像输入，均通过各自的编码器映射到同一个共享的语义潜在空间中，转化为统一格式的潜在 Token 序列。
2. **潜在空间交错推理（Latent-Space Interleaved Reasoning）**：这是模型的核心。自回归 Transformer 骨干网络直接处理这些潜在 Token。当模型需要生成视觉内容（如预测下一步的视觉状态或进行视觉思考）时，它输出的是视觉潜在 Token。这些 Token **直接**被追加到上下文中参与下一步的推理，完全跳过了像素解码步骤。
3. **按需解码阶段（On-Demand Decoding）**：只有在整个推理流程结束，且最终任务需要向人类展示具体的图像或文本时，模型才会调用解码器，将最终的潜在 Token 映射回像素空间或自然语言空间。

```python
import torch
import torch.nn as nn

class LatentUM(nn.Module):
    def __init__(self, text_encoder, image_encoder, unified_transformer, image_decoder, text_decoder):
        super().__init__()
        self.text_encoder = text_encoder
        self.image_encoder = image_encoder
        self.unified_transformer = unified_transformer
        self.image_decoder = image_decoder
        self.text_decoder = text_decoder

    def forward(self, interleaved_inputs, num_reasoning_steps):
        """
        interleaved_inputs: list of tuples, e.g., [('text', text_data), ('image', image_data)]
        """
        latent_sequence = []

        # 1. Unified Encoding: 将所有模态映射到共享潜在空间
        for modal_type, data in interleaved_inputs:
            if modal_type == 'text':
                latent_sequence.append(self.text_encoder(data))
            elif modal_type == 'image':
                latent_sequence.append(self.image_encoder(data))
        
        latent_context = torch.cat(latent_sequence, dim=1)
```

```python
class Bench2DriveVL_Framework:
    def __init__(self, vlm_model):
        self.simulator = CARLA_Environment()
        self.vlm = vlm_model
        self.drive_commenter = DriveCommenter()
        self.interface = UnifiedProtocolInterface()

    def evaluate_closed_loop(self, max_steps=1000):
        obs = self.simulator.reset()
        done = False
        step = 0
        
        while not done and step < max_steps:
            # 1. 获取当前环境的多模态视觉输入与车辆底层状态
            visual_inputs, ego_state = obs
            
            # 2. DriveCommenter 动态生成当前状态的上下文/QA
            # 关键：即使车辆处于偏航(OOD)状态，也能生成对应的纠偏上下文

            # 3. VLM 基于图结构思维链进行推理
            # 输入：视觉图像 + 动态生成的上下文提示
            # 输出：思维链推理过程 + 文本格式的控制意图
            cot_reasoning, text_action = self.vlm.graph_cot_inference(
                vision=visual_inputs, 
                prompt=behavior_grounded_context
            )
            
            # 4. 统一接口将文本动作解析为底层物理控制指令 (油门, 转向, 刹车)
            control_cmd = self.interface.parse_to_control(text_action)
            
            # 5. 在闭环仿真中执行指令，获取下一步状态
            obs, reward, done, info = self.simulator.step(control_cmd)
            step += 1
            
        return self.simulator.get_driving_score()
```

### 第二模块：核心架构解释

POCO 框架采用离线到在线（Offline-to-Online）的两阶段训练范式，其核心架构与执行流程如下：

1.  **离线预训练 (Offline Pre-training):** 使用人类遥操作收集的专家演示数据，通过标准的行为克隆（BC）损失对生成式策略（如 Flow Matching 模型）进行监督学习，建立初始的策略先验。
2.  **在线微调 - Critic 预热 (Critic Warmup):** 冻结策略网络参数，利用重放缓冲区中的数据训练一个块级（Chunk-level）的 Q 网络。该网络直接评估整个时间动作块的预期回报，缓解长视野信用分配问题。
3.  **在线微调 - 隐式 E 步 (Implicit E-Step):** 针对当前状态，从冻结的参考策略中采样 $N$ 个候选动作块。将这些动作块输入 Critic 获取 Q 值，并通过带温度系数的 Softmax 计算归一化的重要性权重，构建隐式后验分布。
4.  **在线微调 - 截断 M 步 (Clipped M-Step):** 计算每个候选动作块的监督损失（对于流匹配模型为向量场 MSE 损失）。将该损失与 E 步计算的权重相乘，并应用阈值 $\zeta$ 进行截断。最终通过最小化这个截断的加权目标函数来更新策略网络参数。

**核心伪代码实现逻辑：**

```python
def poco_update_step(state, actor, actor_ref, critic, replay_buffer, params):
    # params: N (num_samples), temp (temperature), beta (guidance_scale), zeta (clip_threshold)
    
    # 1. Critic Update (Standard TD Learning for Action Chunks)
    transitions = replay_buffer.sample_batch()
    critic_loss = compute_td_loss(critic, transitions)
    update_network(critic, critic_loss)
    
    # 2. Implicit E-Step: Evaluate Posterior
    with torch.no_grad():
        # Sample N candidate action chunks from the reference policy
        candidate_actions = actor_ref.sample_actions(state, num_samples=params.N)
        
        # Evaluate Q-values for all candidates
        q_values = critic(state, candidate_actions)
        
        # Calculate normalized importance weights
        weights = torch.softmax(q_values / params.temp, dim=-1)
        
    # 3. Clipped M-Step: Policy Improvement
    # Calculate standard Behavior Cloning loss (e.g., Flow Matching vector field MSE)
    bc_loss_current = compute_bc_loss(actor, state, candidate_actions)
    
    # Apply clipping to the weighted surrogate objective
    # clip(loss, min=0, max=zeta) prevents catastrophic updates from OOD actions
    clipped_surrogate = torch.clamp(bc_loss_current, min=0.0, max=params.zeta)
    
    # Final POCO Objective: Base BC loss on replay buffer + Weighted Clipped Surrogate
    base_bc_loss = compute_bc_loss(actor, state, transitions.actions)
    poco_loss = base_bc_loss + params.beta * torch.sum(weights * clipped_surrogate)
    
    # Update actor network
    update_network(actor, poco_loss)
    
    return actor
```

### 第二模块：核心架构解释

UniDriveVLA 的核心逻辑是**“分而治之，受控交互”**。整个前向传播流程和实验流程如下：

1. **特征初始化**：图像和指令通过 Vision Encoder 和 Tokenizer 生成**理解 Token**；通过 K-Means 初始化的稀疏查询生成**感知 Token**；通过高斯噪声和目标速度插值生成**动作 Token**。
2. **专家解耦投影**：在进入 Transformer 层时，三种 Token 不再共享 QKV 投影矩阵，而是分别进入各自的“专家”线性层，映射到独立的参数子空间。
3. **掩码联合注意力**：将三组 Token 拼接，进行全局 Attention，但施加严格的可见性掩码：
   - 理解 Token：仅做因果注意力，不看感知和动作（保护原生语言能力）。
   - 感知 Token：可以看前面的理解 Token（获取语义上下文）。
   - 动作 Token：可以看所有 Token（聚合语义和空间信息用于规划）。
4. **稀疏感知解码与动作生成**：感知 Token 输出 3D 检测、建图、占据网格等；动作 Token 通过 Flow-Matching（流匹配）生成最终的自车轨迹。
5. **三阶段渐进式训练**：第一阶段用 VQA 数据微调 VLM 锚定语义能力；第二阶段用 LoRA 联合优化感知与语言；第三阶段冻结 VLM，专精微调感知与动作专家。

**核心底层逻辑伪代码 (Python-style)**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class MoTLayer(nn.Module):
    def __init__(self, dim):
        super().__init__()
        # 1. 专家解耦：为理解、感知、动作分配独立的 QKV 投影
        self.expert_und = nn.Linear(dim, dim * 3) # Understanding
        self.expert_per = nn.Linear(dim, dim * 3) # Perception
        self.expert_act = nn.Linear(dim, dim * 3) # Action
        
        self.ffn_und = FFN(dim)
        self.ffn_per = FFN(dim)
        self.ffn_act = FFN(dim)

    def forward(self, t_und, t_per, t_act, attention_mask):
        # t_und: [B, L_u, D], t_per: [B, L_p, D], t_act: [B, L_a, D]
        
        # 2. 独立投影获取 Q, K, V
        qkv_und = self.expert_und(t_und).chunk(3, dim=-1)
        qkv_per = self.expert_per(t_per).chunk(3, dim=-1)
        qkv_act = self.expert_act(t_act).chunk(3, dim=-1)
        
        # 3. 拼接 Q, K, V 用于联合注意力
        Q = torch.cat([qkv_und[0], qkv_per[0], qkv_act[0]], dim=1)
        K = torch.cat([qkv_und[1], qkv_per[1], qkv_act[1]], dim=1)
        V = torch.cat([qkv_und[2], qkv_per[2], qkv_act[2]], dim=1)
        
        # 4. 掩码联合注意力 (Masked Joint Attention)
        # attention_mask 确保:
        # - t_und 只能看到 t_und (Causal)
        # - t_per 可以看到 t_und 和 t_per
        # - t_act 可以看到所有
        attn_scores = torch.matmul(Q, K.transpose(-2, -1)) / (Q.size(-1) ** 0.5)
        attn_scores = attn_scores + attention_mask 
        attn_output = torch.matmul(F.softmax(attn_scores, dim=-1), V)
        
        # 5. 拆分回各自的专家流并进行 FFN
        out_und, out_per, out_act = torch.split(attn_output, [t_und.size(1), t_per.size(1), t_act.size(1)], dim=1)
        
        t_und = t_und + self.ffn_und(out_und)
        t_per = t_per + self.ffn_per(out_per)
        t_act = t_act + self.ffn_act(out_act)
        
        return t_und, t_per, t_act
```

### 第二模块：核心架构解释

WAV 框架的核心逻辑是一个反向的自我验证循环，具体包含三个执行步骤与一个更新步骤：

1. **子目标生成 (Subgoal Generation)**：系统首先利用在大量无动作视频上预训练的生成模型，基于当前状态生成多个符合物理规律的候选未来状态。这一步利用了视频数据易于获取的优势，确保生成的未来状态在物理上是合理的。
2. **稀疏逆向推断 (Sparse Inverse Inference)**：系统使用一个带有特征掩码的逆向动力学模型。该模型强制忽略复杂的背景环境，仅提取与动作直接相关的局部状态变化（例如机械臂末端的位置变化），从而反推出实现上述候选未来状态所需的具体动作。
3. **正向验证与计算分歧 (Forward Verification)**：系统将反推得到的动作输入给当前正在训练的世界模型，让其进行正向预测。随后，计算世界模型的预测结果与第一步生成的候选未来状态之间的物理距离（分歧度）。
4. **数据采集与自我改进 (Data Collection & Self-Improvement)**：分歧度最大的样本代表了当前世界模型的认知盲区。系统将选择该样本对应的动作在真实环境中执行，收集真实的交互数据，并用这些新数据同步更新世界模型和逆向动力学模型。

```python
def wav_guided_exploration(current_state, world_model, subgoal_generator, sparse_inverse_model, env, data_buffer, K_candidates):
    # 步骤 1: 基于当前状态，生成 K 个符合物理规律的候选未来状态
    candidate_subgoals = subgoal_generator.sample(current_state, K_candidates)
    
    # 步骤 2: 利用稀疏逆向模型，从局部特征变化中反推实现这些状态所需的动作
    inferred_actions = sparse_inverse_model.predict_action(current_state, candidate_subgoals)
    
    # 步骤 3: 世界模型接收反推的动作，进行正向的未来状态预测
    predicted_outcomes = world_model.predict_next_state(current_state, inferred_actions)
    
    # 步骤 4: 计算生成的候选状态与世界模型预测状态之间的差异得分
    disagreement_scores = calculate_distance(candidate_subgoals, predicted_outcomes)
    
    # 步骤 5: 找出差异得分最大的动作（即模型最不擅长预测的动作），在环境中实际执行
    best_action_idx = argmax(disagreement_scores)
    selected_action = inferred_actions[best_action_idx]
    actual_next_state = env.step(selected_action)
    
    # 步骤 6: 将最具信息量的真实交互数据存入经验池，并更新模型
    data_buffer.append(current_state, selected_action, actual_next_state)
    world_model.update(data_buffer)
    sparse_inverse_model.update(data_buffer)
```

### 第二模块：核心架构解释

LatentUM 的核心架构围绕“潜在空间内的闭环流转”展开，其工作流程可拆解为三个关键阶段：

1. **统一编码阶段（Unified Encoding）**：无论是文本还是图像输入，均通过各自的编码器映射到同一个共享的语义潜在空间中，转化为统一格式的潜在 Token 序列。
2. **潜在空间交错推理（Latent-Space Interleaved Reasoning）**：这是模型的核心。自回归 Transformer 骨干网络直接处理这些潜在 Token。当模型需要生成视觉内容（如预测下一步的视觉状态或进行视觉思考）时，它输出的是视觉潜在 Token。这些 Token **直接**被追加到上下文中参与下一步的推理，完全跳过了像素解码步骤。
3. **按需解码阶段（On-Demand Decoding）**：只有在整个推理流程结束，且最终任务需要向人类展示具体的图像或文本时，模型才会调用解码器，将最终的潜在 Token 映射回像素空间或自然语言空间。

```python
    def __init__(self, text_encoder, image_encoder, unified_transformer, image_decoder, text_decoder):
        super().__init__()
        self.text_encoder = text_encoder
        self.image_encoder = image_encoder
        self.unified_transformer = unified_transformer
        self.image_decoder = image_decoder
        self.text_decoder = text_decoder

    def forward(self, interleaved_inputs, num_reasoning_steps):
        """
        interleaved_inputs: list of tuples, e.g., [('text', text_data), ('image', image_data)]
        """
        latent_sequence = []

        # 1. Unified Encoding: 将所有模态映射到共享潜在空间
        for modal_type, data in interleaved_inputs:
            if modal_type == 'text':
                latent_sequence.append(self.text_encoder(data))
            elif modal_type == 'image':
                latent_sequence.append(self.image_encoder(data))
        
        latent_context = torch.cat(latent_sequence, dim=1)

        # 2. Latent-Space Interleaved Reasoning: 在潜在空间内进行多步交错推理
        for step in range(num_reasoning_steps):
            # 自回归生成下一个潜在状态（可能是文本思考，也可能是未来视觉状态）

            latent_context = torch.cat([latent_context, next_latent_token], dim=1)

        # 3. On-Demand Decoding: 仅在需要最终输出时进行解码
        final_outputs = []
        for token in latent_context:
            if self.is_visual_token(token):

                final_outputs.append(self.text_decoder(token))
```

```python
    def __init__(self, vlm_model):
        self.simulator = CARLA_Environment()
        self.vlm = vlm_model
        self.drive_commenter = DriveCommenter()
        self.interface = UnifiedProtocolInterface()

    def evaluate_closed_loop(self, max_steps=1000):
        obs = self.simulator.reset()
        done = False
        step = 0
        
        while not done and step < max_steps:
            # 1. 获取当前环境的多模态视觉输入与车辆底层状态

            # 2. DriveCommenter 动态生成当前状态的上下文/QA

            # 输入：视觉图像 + 动态生成的上下文提示
            # 输出：思维链推理过程 + 文本格式的控制意图

            control_cmd = self.interface.parse_to_control(text_action)
            
            # 5. 在闭环仿真中执行指令，获取下一步状态
            obs, reward, done, info = self.simulator.step(control_cmd)
            step += 1
            
        return self.simulator.get_driving_score()
```

### 第二模块：核心架构解释

POCO 框架采用离线到在线（Offline-to-Online）的两阶段训练范式，其核心架构与执行流程如下：

1.  **离线预训练 (Offline Pre-training):** 使用人类遥操作收集的专家演示数据，通过标准的行为克隆（BC）损失对生成式策略（如 Flow Matching 模型）进行监督学习，建立初始的策略先验。
2.  **在线微调 - Critic 预热 (Critic Warmup):** 冻结策略网络参数，利用重放缓冲区中的数据训练一个块级（Chunk-level）的 Q 网络。该网络直接评估整个时间动作块的预期回报，缓解长视野信用分配问题。
3.  **在线微调 - 隐式 E 步 (Implicit E-Step):** 针对当前状态，从冻结的参考策略中采样 $N$ 个候选动作块。将这些动作块输入 Critic 获取 Q 值，并通过带温度系数的 Softmax 计算归一化的重要性权重，构建隐式后验分布。
4.  **在线微调 - 截断 M 步 (Clipped M-Step):** 计算每个候选动作块的监督损失（对于流匹配模型为向量场 MSE 损失）。将该损失与 E 步计算的权重相乘，并应用阈值 $\zeta$ 进行截断。最终通过最小化这个截断的加权目标函数来更新策略网络参数。

**核心伪代码实现逻辑：**

```python
def poco_update_step(state, actor, actor_ref, critic, replay_buffer, params):
    # params: N (num_samples), temp (temperature), beta (guidance_scale), zeta (clip_threshold)
    
    # 1. Critic Update (Standard TD Learning for Action Chunks)
    transitions = replay_buffer.sample_batch()
    critic_loss = compute_td_loss(critic, transitions)
    update_network(critic, critic_loss)
    
    # 2. Implicit E-Step: Evaluate Posterior
    with torch.no_grad():
        # Sample N candidate action chunks from the reference policy
        candidate_actions = actor_ref.sample_actions(state, num_samples=params.N)
        
        # Evaluate Q-values for all candidates
        q_values = critic(state, candidate_actions)
        
        # Calculate normalized importance weights
        weights = torch.softmax(q_values / params.temp, dim=-1)
        
    # 3. Clipped M-Step: Policy Improvement
    # Calculate standard Behavior Cloning loss (e.g., Flow Matching vector field MSE)
    bc_loss_current = compute_bc_loss(actor, state, candidate_actions)
    
    # Apply clipping to the weighted surrogate objective
    # clip(loss, min=0, max=zeta) prevents catastrophic updates from OOD actions
    clipped_surrogate = torch.clamp(bc_loss_current, min=0.0, max=params.zeta)
    
    # Final POCO Objective: Base BC loss on replay buffer + Weighted Clipped Surrogate
    base_bc_loss = compute_bc_loss(actor, state, transitions.actions)
    poco_loss = base_bc_loss + params.beta * torch.sum(weights * clipped_surrogate)
    
    # Update actor network
    update_network(actor, poco_loss)
    
    return actor
```

### 第二模块：核心架构解释

ActionParty 的核心架构是对标准视频 DiT 进行了多模态联合去噪的扩展，其运行流程严格遵循“状态更新”与“渲染”的解耦范式：

1. **输入构建与联合拼接**: 模型接收历史视频帧 $x_{0:t}$、历史主体状态（2D坐标）$z_{0:t}$、环境文本描述 $c$ 以及当前动作指令 $a_{0:t}$。视频 Token 与主体状态 Token 在序列维度被拼接，共同进入 DiT 模块。
2. **渲染阶段 (Self-Attention)**: 在自注意力层中，模型应用掩码 $\mathcal{M}_{SA}$。该掩码允许视频 Token 关注所有主体状态，允许主体状态关注视频 Token，但**严格禁止不同主体状态之间的相互关注**，以防状态信息污染。同时，对主体状态 Token 施加基于上一帧坐标的 3D RoPE 偏置，强制其在空间上对齐到视频画面中对应的局部像素区域。
3. **状态更新阶段 (Cross-Attention)**: 在交叉注意力层中，模型引入动作 Token。应用掩码 $\mathcal{M}_{CA}$，**强制第 $i$ 个主体的状态 Token 只能与第 $i$ 个主体的动作 Token 进行交互**，从而实现严格的动作绑定。环境文本 $c$ 仅与视频 Token 交互。
4. **自回归输出**: DiT 联合输出去噪后的下一帧视频 $x_{t+1}$ 和更新后的主体坐标 $z_{t+1}$，并将其作为下一步的上下文继续滚动生成。

```python
    video_tokens: [B, N_v, D]
    state_tokens: [B, N_s, D] (N_s = number of subjects)
    action_tokens: [B, N_s, D]
    text_tokens: [B, N_t, D]
    prev_coords: [B, N_s, 2] (2D coordinates from previous timestep)
    """
    # 1. Concatenate video and state tokens for joint processing
    joint_tokens = concat([video_tokens, state_tokens], dim=1)
    
    # 2. Rendering: Self-Attention with Spatial Biasing
    # Apply 3D RoPE based on previous coordinates to anchor states to pixels
    joint_tokens_rope = apply_3d_rope(joint_tokens, prev_coords)
    
    # M_SA prevents state_i from attending to state_j
    sa_out = masked_self_attention(
        query=joint_tokens_rope, 
        key=joint_tokens_rope, 
        value=joint_tokens, 
        mask=M_SA
    )
    joint_tokens = joint_tokens + sa_out
    
    # Split back for cross-attention
    video_tokens, state_tokens = split(joint_tokens)
    
    # 3. State Update: Cross-Attention with Action Binding
    # M_CA ensures state_i ONLY attends to action_i
    state_update = masked_cross_attention(
        query=state_tokens,
        key=action_tokens,
        value=action_tokens,
        mask=M_CA
    )
    state_tokens = state_tokens + state_update
    
    # Video tokens attend to text description
    video_update = cross_attention(
        query=video_tokens,
        key=text_tokens,
        value=text_tokens
    )
    video_tokens = video_tokens + video_update
    
    return video_tokens, state_tokens
```

**世界模型 6 层资产架构**：
1. **观测编码器（Observation Encoder）**：将原始传感器输入映射到潜在空间。
2. **动力学模型（Dynamics Model）**：核心组件（如 RSSM），基于当前状态和动作预测下一个潜在状态的分布。
3. **奖励与终止头（Reward and termination heads）**：从潜在状态预测预期奖励，用于塑造规划。
4. **推演与想象引擎（Rollout and imagination engine）**：在潜在空间中向前展开 $k$ 步的规划循环。
5. **策略与执行器（Policy and actor）**：基于想象的推演进行训练或规划的下游控制器。
6. **记忆与上下文存储（Memory and context store）**：提供给动力学模型的历史片段或上下文。

**实验验证流程（轨迹持久性攻击）**：
作者通过对比带有循环状态的世界模型（WM，使用 GRU 模拟）与无状态的单步基线模型（SS），在 $t=0$ 时刻注入 $\ell_2$ 范数有界的对抗扰动 $\delta$，随后在无扰动的情况下向前推演 $K$ 步，计算潜在状态误差的放大率 $\mathcal{A}_k$。

**核心逻辑伪代码**：

```python
import torch
import torch.nn as nn

def compute_trajectory_persistence(encoder, dynamics_gru, obs_seq, perturbation, K):
    """
    计算世界模型在多步推演中的轨迹持久性（误差放大率）
    """
    # t=0 时刻注入对抗扰动
    obs_perturbed = obs_seq.clone()
    obs_perturbed[0] = obs_seq[0] + perturbation
    
    # 1. 世界模型 (WM) 推演：具有循环状态 (GRU)
    h_clean = torch.zeros(hidden_dim)
    h_adv = torch.zeros(hidden_dim)
    wm_errors = []
    
    for t in range(K):
        # 干净轨迹
        z_clean = encoder(obs_seq[t])
        h_clean = dynamics_gru(z_clean, h_clean)
        
        # 对抗轨迹 (仅在 t=0 包含扰动，但隐藏状态 h 会传递误差)
        z_adv = encoder(obs_perturbed[t])
        h_adv = dynamics_gru(z_adv, h_adv)
        
        # 计算潜在状态误差
        wm_errors.append(torch.norm(h_adv - h_clean, p=2))
        
    # 2. 无状态基线 (SS) 推演：仅独立编码，无状态传递
    ss_errors = []
    for t in range(K):
        z_clean_ss = encoder(obs_seq[t])
        z_adv_ss = encoder(obs_perturbed[t])
        ss_errors.append(torch.norm(z_adv_ss - z_clean_ss, p=2))
        
    # 3. 计算轨迹放大率 A_k
    A_k = [wm_err / (ss_err + 1e-8) for wm_err, ss_err in zip(wm_errors, ss_errors)]
    
    return A_k
```

### 第二模块：核心架构解释

AnchorVLA 的核心架构将低频的宏观多模态规划与高频的微观闭环控制进行了解耦。其运行流程分为两个主要阶段：动作生成阶段（低频）与动作执行阶段（高频）。

1. **多模态特征提取**：轻量级 VLA 骨干网络接收当前环境的视觉观测和语言指令，提取出融合的上下文特征。
2. **锚点生成（Anchor Generation）**：基于上下文特征，网络直接预测出一条或多条粗略的“锚点轨迹”。这些轨迹作为先验，已经位于合理动作流形的附近。
3. **截断锚定扩散（Truncated Anchored Diffusion）**：扩散模型不再从纯高斯噪声开始采样。系统向锚点轨迹注入适量噪声，随后执行截断的去噪调度（仅执行少量的去噪步数）。这一步在极低的计算成本下，恢复了动作的多模态分布特性，输出一个动作块（Action Chunk）。
4. **高频残差校正（Residual Correction）**：在动作块的逐帧执行（Rollout）过程中，轻量级残差校正模块根据最新的实时观测，对当前步的动作进行高频微调。这种测试时的自校正机制有效抵消了环境动态变化和分块执行带来的开环漂移。

```python
# AnchorVLA 核心逻辑伪代码
class AnchorVLA:
    def __init__(self, vla_backbone, anchor_head, diffusion_model, residual_module):
        self.vla_backbone = vla_backbone       # 视觉-语言特征提取
        self.anchor_head = anchor_head         # 锚点轨迹预测
        self.diffusion_model = diffusion_model # 截断扩散模型
        self.residual_module = residual_module # 高频残差校正模块
        self.action_chunk = None
        self.chunk_index = 0

    def generate_action_chunk(self, observation, instruction):
        # 1. 提取多模态上下文特征
        context_features = self.vla_backbone(observation, instruction)
        
        # 2. 预测锚点轨迹 (靠近真实解流形)
        anchor_trajectory = self.anchor_head(context_features)
        
        # 3. 截断锚定扩散 (局部去噪，保留多模态性且降低延迟)
        # 注入少量噪声而非纯噪声，执行截断去噪步数 (e.g., 5 steps instead of 50)
        noisy_anchor = self.diffusion_model.add_noise(anchor_trajectory, noise_level='low')
        denoised_chunk = self.diffusion_model.denoise(
            noisy_anchor, 
            context_features, 
            schedule='truncated'
        )
        return denoised_chunk

    def step(self, current_observation, instruction):
        # 低频规划：如果当前没有动作块或动作块已执行完，则生成新的动作块
        if self.action_chunk is None or self.chunk_index >= len(self.action_chunk):
            self.action_chunk = self.generate_action_chunk(current_observation, instruction)
            self.chunk_index = 0
            
        # 获取当前步的开环基准动作
        base_action = self.action_chunk[self.chunk_index]
        
        # 高频闭环：利用轻量级残差模块，基于最新观测计算动作补偿
        residual_action = self.residual_module(current_observation, base_action)
        
        # 融合输出最终动作
        final_action = base_action + residual_action
        
        self.chunk_index += 1
        return final_action
```

### 第二模块：核心架构解释

Tex3D 的核心架构分为两个主要阶段：**前景-背景解耦渲染（FBD）** 与 **轨迹感知对抗优化（TAAO）**。

1.  **环境与渲染同步 (FBD):** 在每个时间步，MuJoCo 负责运行物理法则并渲染包含机械臂和背景的图像，同时输出目标物体的 Mask。Nvdiffrast（可微渲染器）接收来自 MuJoCo 的相机位姿、物体坐标（MVP矩阵）和光照参数，单独渲染带有对抗纹理的目标物体。
2.  **图像合成与前向传播:** 将 Nvdiffrast 渲染的前景与 MuJoCo 渲染的背景通过 Mask 进行像素级拼接，生成视觉上连贯的伪造观测图像。该图像输入冻结的 VLA 模型，输出预测动作。
3.  **关键帧权重计算 (TAAO):** 提取观测序列的视觉特征，计算其一阶导数（速度）和二阶导数（加速度）。特征变化最剧烈的帧（通常是机械臂接触物体的瞬间）被赋予极高的 Softmax 权重。
4.  **端到端反向传播:** 计算 VLA 输出动作与目标动作（或干净动作）之间的损失，结合 TAAO 计算的帧权重，将梯度穿透 VLA 模型和 Nvdiffrast，直接更新 3D 网格的顶点颜色参数，最终映射为对抗纹理。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import nvdiffrast.torch as dr

def tex3d_optimization(vla_model, mujoco_env, target_mesh, num_epochs):
    # 初始化顶点颜色参数 (低秩流形约束)
    vertex_colors = torch.rand((target_mesh.num_vertices, 3), requires_grad=True)
    optimizer = torch.optim.Adam([vertex_colors], lr=0.01)
    
    for epoch in range(num_epochs):
        trajectory_loss = 0
        frame_features = []
        actions_pred = []
        actions_target = []
        
        # 1. 收集轨迹与渲染合成 (FBD)
        obs_clean = mujoco_env.reset()
        for t in range(max_timesteps):
            # 从 MuJoCo 获取背景、Mask 和对齐参数
            bg_img, mask, mvp_matrix, light_params = mujoco_env.get_render_context()
            
            # 使用 Nvdiffrast 可微渲染目标物体
            texture_map = barycentric_interpolation(target_mesh, vertex_colors)
            fg_img = dr.render(target_mesh.vertices, target_mesh.faces, mvp_matrix, texture_map, light_params)
            
            # 场景合成 (Eq. 3)
            adv_obs = mask * fg_img + (1 - mask) * bg_img
            
            # VLA 前向传播
            action = vla_model(adv_obs, instruction)
            actions_pred.append(action)
            actions_target.append(get_reference_action(t)) # 干净动作或恶意目标动作
            
            # 提取视觉特征用于后续权重计算
            frame_features.append(extract_visual_feature(adv_obs))
            
            # 步进物理环境 (使用干净动作以保持轨迹一致性)
            mujoco_env.step(get_reference_action(t))
            
        # 2. 轨迹感知权重计算 (TAAO)
        # 计算特征速度与加速度 (Eq. 6, 7, 8)
        velocities = compute_central_difference(frame_features, order=1)
        accelerations = compute_central_difference(frame_features, order=2)
        criticality_scores = torch.max(normalize(velocities), normalize(accelerations))
        
        # 温度缩放 Softmax 获取帧权重 (Eq. 9)
        weights = torch.softmax(criticality_scores / temperature, dim=0)
        
        # 3. 计算加权对抗损失并反向传播 (Eq. 11 / 12)
        for t in range(max_timesteps):
            loss_t = compute_action_deviation(actions_pred[t], actions_target[t])
            trajectory_loss += weights[t] * loss_t
            
        optimizer.zero_grad()
        trajectory_loss.backward() # 梯度流：Loss -> VLA -> adv_obs -> fg_img -> vertex_colors
        optimizer.step()
        
    return vertex_colors
```

### 第二模块：核心架构解释

本文的核心架构是对现有 VLA 模型的损失函数进行重构。传统的 VLA 在微调时，通常将动作预测视为分类任务（Next-token prediction），目标分布是一个 One-hot 向量。本文在标准交叉熵损失的基础上，增加了一个 FAN 引导的正则化分支。

**处理流程**：
1. **状态输入与特征提取**：VLA 接收视觉图像和语言指令，输出对应动作 Token 的 Logits。
2. **构建高斯先验（FAN Prior）**：以 Ground Truth 动作为中心，在动作空间中构建一个高斯分布。距离真实动作越近的动作 Token，被赋予越高的先验概率；距离越远，概率平滑衰减。
3. **分布对齐（Regularization）**：计算模型输出的动作概率分布与构建的高斯先验分布之间的散度（如 KL 散度）。
4. **联合优化**：将标准的离散交叉熵损失与 FAN 正则化损失加权求和，进行反向传播更新模型权重。

**核心伪代码实现**：

```python
import torch
import torch.nn.functional as F

def fan_guided_loss(logits, target_actions, action_space_resolution, variance=0.1, lambda_weight=0.5):
    """
    计算带有可行动作邻域(FAN)先验的VLA微调损失
    logits: VLA模型输出的动作预测 [batch_size, num_action_tokens]
    target_actions: 真实的动作索引 [batch_size]
    action_space_resolution: 动作空间离散化后的Token总数
    variance: 控制高斯先验分布宽度的超参数（反映物理容差）
    """
    batch_size = logits.shape[0]

    # 1. 计算标准的交叉熵损失 (继承自语言模型的Next-token prediction)
    ce_loss = F.cross_entropy(logits, target_actions)

    # 2. 构建 FAN 高斯先验分布
    # 生成动作空间的索引网格
    action_grid = torch.arange(action_space_resolution, device=logits.device).unsqueeze(0).expand(batch_size, -1)
    
    # 计算所有动作Token与目标动作在物理空间/索引空间中的距离
    distances = torch.abs(action_grid - target_actions.unsqueeze(1).float())

    # 以目标动作为中心，生成高斯分布
    gaussian_prior = torch.exp(- (distances ** 2) / (2 * variance ** 2))
    
    # 归一化，使其成为合法的概率分布
    gaussian_prior = gaussian_prior / gaussian_prior.sum(dim=1, keepdim=True)

    # 3. 计算 FAN 正则化损失 (模型输出分布与高斯先验的 KL 散度)
    model_log_probs = F.log_softmax(logits, dim=1)
    fan_reg_loss = F.kl_div(model_log_probs, gaussian_prior, reduction='batchmean')

    # 4. 联合损失
    total_loss = ce_loss + lambda_weight * fan_reg_loss

    return total_loss
```

### 第二模块：核心架构解释

Omni123 的核心架构是一个完全共享参数的双流自回归 Transformer，其处理流程与实验设计可拆解为以下三个阶段：

**1. 统一分词与序列化 (Tokenization)**
模型摒弃了传统的 2D/3D 空间网格表示，强制所有模态降维至 1D 离散序列。文本通过 CLIP 和 Qwen 提取特征；图像通过改进的 1D GiGaTok 压缩为 1024 个 Token；3D 网格通过 Cube3D 的 VQ-VAE 压缩为 1024 个 Token。这种统一消除了模态特定的位置编码壁垒。

**2. 双流自回归主干 (Dual-Stream Autoregressive Backbone)**
架构分为条件流（Conditioning Stream，处理文本）和生成流（Generation Stream，处理图像和 3D）。前 24 层中，两流独立投影后拼接进行联合因果注意力计算；后 6 层仅保留生成流的自注意力计算。图像和 3D Token 在生成流中完全共享注意力权重，实现底层的跨模态特征融合。

**3. 三阶段训练策略 (Training Pipeline)**
*   **预训练 (PT):** 在异构数据集上进行 Text↔Image, Image↔3D, Text↔3D 的交替预测。
*   **持续训练 (CT):** 引入可学习的“视图标记 (View Tokens)”，将其作为前缀附加到目标序列，强制模型学习 3D 到 2D 的多视图几何一致性。
*   **监督微调 (SFT):** 引入交替多模态序列（如 Text→6个位姿图像→3D），闭环验证生成结果的跨模态一致性。

**核心前向传播伪代码实现:**

```python
import torch
import torch.nn as nn

class Omni123(nn.Module):
    def __init__(self):
        super().__init__()
        # Tokenizers
        self.text_encoder = DualTextEncoder(clip_dim=77, qwen_dim=...)
        self.image_tokenizer = OneDImageTokenizer(seq_len=1024)
        self.shape_tokenizer = Cube3DTokenizer(seq_len=1024)
        
        # Transformer Blocks
        self.dual_stream_blocks = nn.ModuleList([DualStreamBlock() for _ in range(24)])
        self.single_stream_blocks = nn.ModuleList([SingleStreamBlock() for _ in range(6)])
        
        # Output Heads
        self.image_head = nn.Linear(hidden_dim, image_vocab_size)
        self.shape_head = nn.Linear(hidden_dim, shape_vocab_size)
        
        # View Tokens for Continued Training
        self.view_tokens = nn.Embedding(num_canonical_views, hidden_dim)

    def forward(self, text, image=None, shape3d=None, target_view_idx=None):
        # 1. Encode Text into Conditioning Stream
        cond_tokens = self.text_encoder(text)
        
        # 2. Tokenize Visual/Geometric data into Generation Stream
        gen_tokens = []
        if image is not None:
            gen_tokens.append(self.image_tokenizer(image))
        if shape3d is not None:
            gen_tokens.append(self.shape_tokenizer(shape3d))
            
        # Inject View Token if performing posed generation
        if target_view_idx is not None:
            view_emb = self.view_tokens(target_view_idx).unsqueeze(1)
            gen_tokens.insert(0, view_emb)
            
        gen_tokens = torch.cat(gen_tokens, dim=1)
        
        # 3. Create Causal Mask for autoregressive prediction
        causal_mask = create_causal_mask(gen_tokens.size(1))
        
        # 4. Dual-Stream Processing (Cross-modal fusion)
        for block in self.dual_stream_blocks:
            cond_tokens, gen_tokens = block(cond_tokens, gen_tokens, causal_mask)
            
        # 5. Single-Stream Processing (Generation refinement)
        for block in self.single_stream_blocks:
            gen_tokens = block(gen_tokens, causal_mask)
            
        # 6. Decode Logits
        img_logits = self.image_head(gen_tokens)
        shape_logits = self.shape_head(gen_tokens)
        
        return img_logits, shape_logits
```

### 第二模块：核心架构解释

UAV-Track VLA 采用了一种“编码器-双分支解码器”的层级架构，旨在不牺牲连续控制能力的前提下，实现多模态特征的精确空间对齐。

**处理流程：**
1.  **多模态输入构建:** 系统接收当前帧与过去3帧的 RGB 图像序列、自然语言指令（描述目标外观与飞行意图），以及无人机当前的本体状态（3D线速度与偏航角速度）。
2.  **时空视觉-语言编码 (Spatiotemporal VLM Encoder):** 
    *   使用 SigLIP 提取图像特征。
    *   通过**时序压缩网络 (Temporal Compression Net)** 将3帧历史图像的 Token 大幅降维（每帧 256 压缩至 64），并与当前帧的 256 个 Token 在时间维度拼接，生成包含时序演化信息的 448 个视觉 Token。
    *   将视觉 Token 与指令 Token 送入 Gemma 大语言模型进行跨模态深度融合。
3.  **双分支解码 (Dual-Branch Decoder):**
    *   **空间感知辅助定位头 (Spatial-aware auxiliary grounding head):** 接收跨模态特征，预测目标相对无人机的 3D 位置与偏航角偏差。该分支仅在训练时提供辅助监督（Bypass Auxiliary Design），强制编码器注入任务特定的几何先验。
    *   **流匹配动作专家 (Flow matching action expert):** 将注入了几何先验的跨模态特征与无人机本体状态拼接，通过流匹配架构拟合连续状态空间中的位移流场，输出未来 25 步的连续位移控制序列（4-DoF）。

```python
import torch
import torch.nn as nn

class UAVTrackVLA(nn.Module):
    def __init__(self, vision_encoder, llm_backbone, action_expert):
        super().__init__()
        self.vision_encoder = vision_encoder # e.g., SigLIP
        self.llm = llm_backbone              # e.g., Gemma
        
        # Temporal Compression Net
        self.temporal_compressor = nn.Linear(256, 64)
        self.pos_embedding = nn.Parameter(torch.randn(1, 448, dim))
        
        # Dual-Branch Decoder
        self.aux_grounding_head = TransformerDecoderHead()
        self.action_expert = action_expert   # Flow Matching Expert
        
    def forward(self, curr_img, hist_imgs, instruction, uav_state):
        # 1. Vision Encoding
        curr_tokens = self.vision_encoder(curr_img) # [B, 256, D]
        hist_tokens = self.vision_encoder(hist_imgs) # [B, 3, 256, D]
        
        # 2. Temporal Compression
        # Compress historical frames to avoid feature redundancy
        hist_compressed = self.temporal_compressor(hist_tokens.transpose(-1, -2)).transpose(-1, -2) # [B, 3, 64, D]
        hist_compressed = hist_compressed.view(B, 3 * 64, D) # [B, 192, D]
        
        # Concatenate current and historical tokens
        visual_tokens = torch.cat([curr_tokens, hist_compressed], dim=1) # [B, 448, D]
        visual_tokens = visual_tokens + self.pos_embedding
        
        # 3. Cross-modal Fusion via LLM
        text_tokens = tokenize(instruction)
        cross_modal_features = self.llm(visual_tokens, text_tokens)
        
        # 4. Dual-Branch Decoding
        # Branch A: Spatial Grounding (Auxiliary)
        pred_relative_pose = self.aux_grounding_head(cross_modal_features)
        
        # Branch B: Continuous Action Generation (Flow Matching)
        action_input = torch.cat([cross_modal_features, uav_state], dim=-1)
        pred_action_trajectory = self.action_expert(action_input) # 25-step sequence
        
        return pred_relative_pose, pred_action_trajectory
```

```python
        self.vla_model = vla_model
        self.baseline_controller = baseline_controller
        self.intervention_timer = 0
        
    def causal_scene_narration(self, intent, env_data):
        # 1. 定量物理接地 & 结构化分离
        structured_state = format_quantitative_data(env_data)
        
        # 2. 冲突面分析 (筛选与当前意图相关的约束)
        relevant_constraints = []
        for constraint in structured_state.actors:
            if is_in_conflict_zone(intent, constraint.position):
                relevant_constraints.append(constraint)
                
        # 3. 意图-约束因果对齐
        narrated_text = f"Instruction: {intent}"
        for c in relevant_constraints:
            if c.type == 'blocking':
                narrated_text += f", BUT {c.action}"
            elif c.type == 'temporal':
                narrated_text += f" YIELD_BEFORE {c.action}"
            elif c.type == 'explanatory':
                narrated_text += f" BECAUSE {c.action}"
                
        return narrated_text, structured_state

    def runtime_safety_supervisor(self, intent, vla_waypoints, vehicle_state):
        # 检查语义安全包络 (方向一致性 & 停滞检测)
        direction_conflict = check_direction_consistency(intent, vla_waypoints)
        stuck_conflict = check_stuck_state(vehicle_state.throttle, vehicle_state.speed)
        
        if direction_conflict or stuck_conflict:
            return True # 触发安全接管
        return False

    def step(self, image, intent, env_data):
        # Stage 2: 生成 CSN 文本
        csn_text, _ = self.causal_scene_narration(intent, env_data)
        
        # VLA 模型推理
        vla_waypoints = self.vla_model.predict(image, csn_text)
        
        # Stage 3: 运行时安全监控
        if self.intervention_timer > 0:
            self.intervention_timer -= 1
            return self.baseline_controller.get_safe_waypoints()
            
        needs_intervention = self.runtime_safety_supervisor(intent, vla_waypoints, env_data.ego_state)
        
        if needs_intervention:
            self.intervention_timer = 20 # 强制接管 20 帧
            return self.baseline_controller.get_safe_waypoints()
            
        return vla_waypoints
```

### 第二模块：核心架构解释

DriveGATr 的核心思想是维持两条平行的特征流：一条是承载几何信息的“等变多重向量流”（Equivariant Multivectors），另一条是承载语义与状态信息的“不变标量流”（Invariant Scalars）。

**模型架构与数据流转流程：**
1. **输入编码 (Encodings)**：将智能体和地图的 2D 全局位姿（$x, y, \theta$）映射为 $\mathbb{R}^*_{2,0,1}$ 空间下的 8 维多重向量。速度、边界框尺寸、车道线属性等非几何特征通过 MLP 编码为标量。
2. **等变 Transformer 块 (Equivariant Transformer Blocks)**：
   - **交叉与自注意力**：使用多重向量点积注意力（Multivector Dot-Product Attention）。Query 和 Key 的多重向量通过特定的不变内积（Invariant Inner Product）计算出 SE(2) 不变的 Attention Logits。这使得模型可以使用高度优化的 FlashAttention 算子。
   - **等变 MLP**：包含等变线性层、几何双线性层（Geometric Bilinears，利用几何积和 Join 算子增加表达能力）以及门控激活函数。
3. **不变适配器 (Invariant Adapter)**：在每个 Block 的末尾，计算一个将全局坐标系转换到当前智能体局部坐标系的算子。利用该算子将全局等变的多重向量特征转换为局部不变特征（Agent-centric），并将其注入到标量特征流中。
4. **动作解码 (Action Decoding)**：最终仅使用标量特征流（此时已融合了丰富的局部几何上下文），通过标准 MLP 解码出离散的动作分布。

### 第二模块：核心架构解释

TrojanRobot 的核心逻辑是“中间人数据篡改”。在标准的 VLM 驱动机器人策略中，LLM 负责将用户指令分解为子任务，并将目标物体的文本描述传递给 VLM 进行视觉定位。TrojanRobot 作为一个独立的恶意模块（EVLM 或 LVLM），被植入到 LLM 和 VLM 之间。

其运行流程如下：
1. **实体提取**：利用 LLM 的上下文学习能力，从上游任务规划模块输出的复杂文本中提取出标准化的目标物体列表。
2. **条件触发判断**：恶意模块接收当前环境的图像输入和提取出的物体列表。模型内部机制会检测图像中是否存在预设的物理触发器（如特定颜色的光盘或积木）。
3. **关系映射与篡改**：
   - 若无触发器（中立关系）：输出原始物体列表。
   - 若有触发器（扰动关系）：根据攻击类型（置换、停滞、蓄意）修改物体列表。
4. **指令重构与下发**：将篡改后的物体列表重新组合成文本指令，连同原始图像一起发送给下游的 VLM 感知模块，最终导致机械臂执行错误动作。

```python
class TrojanRobotPolicy:
    def __init__(self, llm_planner, backdoor_module, vlm_perception, action_executor):
        self.llm_planner = llm_planner
        self.backdoor_module = backdoor_module # The injected TrojanRobot module (EVLM/LVLM)
        self.vlm_perception = vlm_perception
        self.action_executor = action_executor

    def execute_task(self, user_instruction, camera_image):
        # Step 1: LLM generates task plan and text description for perception
        task_plan, text_for_vlm = self.llm_planner.generate_plan(user_instruction)
        
        # Step 2: Intrinsic Text Extraction (Extract entities from text)
        object_list = self.extract_entities(text_for_vlm)
        
        # Step 3: Backdoor Module processes image and object list
        # If trigger in camera_image -> modified_list != object_list (Perturbative)
        # If no trigger -> modified_list == object_list (Neutral)
        modified_list = self.backdoor_module.forward(camera_image, object_list)
        
        # Step 4: Reintegrate text and pass to benign VLM perception
        poisoned_text_for_vlm = self.reintegrate_text(text_for_vlm, modified_list)
        object_locations = self.vlm_perception.locate(camera_image, poisoned_text_for_vlm)
        
        # Step 5: Execute actions based on manipulated locations
        self.action_executor.perform(task_plan, object_locations)
```

### 第二模块：核心架构解释

F3DGS 的核心架构分为三个连续的执行阶段，旨在在不共享原始图像的前提下，构建全局一致的 3D 场景模型：

1. **度量级位姿构建与全局初始化 (Metric-Scale Pose Construction & Initialization)**
客户端利用单目里程计和 LiDAR 数据，通过 Umeyama 对齐算法将局部轨迹对齐到全局 LiDAR 锚点，生成全局一致的度量级位姿。随后，将所有客户端的 LiDAR 点云融合，初始化一个全局的 3DGS 模型（包含高斯原语的初始位置、颜色、缩放和透明度）。
2. **局部联邦优化 (Local Federated Optimization)**
在联邦训练的每一轮中，客户端接收全局 3DGS 模型。**核心约束在于：冻结所有高斯原语的 3D 空间位置（Means）**。客户端仅使用本地图像数据，通过可微渲染计算 L1 和 SSIM 损失，更新外观参数（协方差、透明度、球谐系数）。同时，客户端会记录每个高斯原语在本地渲染中被观测到的频次（Visibility tracking）。
3. **可见性感知联邦聚合 (Visibility-Aware Federated Aggregation)**
客户端将更新后的外观参数和可见性频次发送给服务端。服务端不采用简单的平均聚合，而是根据每个高斯原语在各个客户端的可见性频次进行加权求和。观测次数越多的客户端，对该高斯原语外观的决定权越大。

```python
            visibility_counts = initialize_zero_counts(global_gaussians.num_primitives)
            
            # 局部训练步骤
            for step in range(client.local_steps):
                # 仅优化外观参数，位置参数强制使用 frozen_positions
                rendered_img, radii = render(frozen_positions, local_app, client.camera_poses)
                loss = compute_loss(rendered_img, client.ground_truth_images)
                loss.backward()
                optimizer_appearance.step()
                
                # 记录高斯原语的可见性 (投影半径 > 0)
                visibility_counts += (radii > 0).int()
                
            client_updates.append({
                'appearance': local_app,
                'visibility': visibility_counts
            })
            
        # 阶段3: 可见性感知联邦聚合
        global_appearance = zeros_like(global_gaussians.appearance_params)
        total_visibility = sum([update['visibility'] for update in client_updates]) + 1e-8
        
        for update in client_updates:
            # 计算聚合权重 (Equation 8)
            weight = update['visibility'] / total_visibility
            # 加权聚合外观参数 (Equation 9)
            global_appearance += weight * update['appearance']
            
        # 更新全局模型
        global_gaussians.appearance_params = global_appearance

    return global_gaussians
```

### 第二模块：核心架构解释

Diff-KD 采用 Teacher-Student 蒸馏架构。Teacher 模型接收全局无损点云提取完美特征；Student 模型接收各智能体局部的受损点云，通过扩散模型主动修复特征，再进行自适应融合与预测。

**核心流程拆解：**
1.  **Teacher 监督信号构建:** Teacher 模型融合所有智能体的干净点云，通过 LGM（轻量级门控调制）模块提取全局一致的 BEV 特征 $F_T^*$ 和完美预测结果，作为蒸馏的 Ground Truth。
2.  **PKD-Pre (融合前扩散修复):** 针对 Student 的每个局部受损特征 $F_S^i$，不直接进行融合，而是将其作为条件信号（Condition）。从纯高斯噪声开始，通过条件扩散模型（结合 AdaLN 注入条件），逐步去噪生成修复后的特征 $\hat{F}_S^i$，使其逼近 Teacher 的干净特征。
3.  **AGF (自适应门控融合):** 对修复后的多智能体特征集合，通过轻量级卷积网络计算空间维度的注意力权重，进行加权融合。随后利用 LGM 模块，以自车特征为主干，融合特征为条件，进行细粒度的空间-通道门控调制，输出最终融合特征 $F_S$。
4.  **PKD-Post (融合后对齐):** 将 Student 融合后的特征 $F_S$ 与预测结果，通过 KL 散度与 Teacher 的 $F_T^*$ 及预测结果进行严格对齐。

**核心逻辑伪代码 (Python 风格):**

```python
def diff_kd_training_step(clean_global_pc, corrupted_local_pcs):
    # 1. Teacher Forward (No Gradient)
    with torch.no_grad():
        F_T_star, teacher_preds = teacher_model(clean_global_pc)
    
    # 2. Student Local Feature Extraction
    local_features = [student_backbone(pc) for pc in corrupted_local_pcs] # [F_S^1, ..., F_S^N]
    
    # 3. PKD-Pre: Diffusion-based Feature Refinement (Training Diffusion)
    diff_loss = 0
    restored_features = []
    for F_S_i in local_features:
        # Forward diffusion on Teacher's clean feature
        t = sample_random_timestep()
        noise = torch.randn_like(F_T_star)
        F_T_noisy = add_noise(F_T_star, noise, t)
        
        # Predict noise conditioned on Student's corrupted feature (via AdaLN/CAM)
        predicted_noise = diffusion_denoiser(F_T_noisy, condition=F_S_i, timestep=t)
        diff_loss += MSELoss(predicted_noise, noise)
        
        # For downstream fusion, we simulate the reverse process (DDIM)
        F_S_i_restored = ddim_sample(diffusion_denoiser, condition=F_S_i, steps=10)
        restored_features.append(F_S_i_restored)
        
    # 4. AGF: Adaptive Gated Fusion
    # Calculate spatial weights and fuse
    spatial_weights = softmax([conv(f) for f in restored_features], dim=agent)
    fused_collaborative = sum(w * f for w, f in zip(spatial_weights, restored_features))
    
    # Gated modulation with ego feature (restored_features[0])
    F_S_fused = LGM_block(trunk=restored_features[0], condition=fused_collaborative)
    
    # 5. Student Prediction
    student_preds = student_head(F_S_fused)
    
    # 6. PKD-Post: Feature & Prediction Alignment
    feat_kd_loss = KL_Divergence(F_S_fused, F_T_star)
    pred_kd_loss = KL_Divergence(student_preds, teacher_preds)
    
    # 7. Total Loss
    task_loss = DetectionLoss(student_preds, ground_truth)
    total_loss = diff_loss + feat_kd_loss + pred_kd_loss + task_loss
    
    return total_loss
```

   * **最能证明其有效性的核心数据**：本文缺乏传统的量化 Benchmark 数据，其核心支撑在于 **Ontobox 平台的实际部署案例**（私人诊所管理、车贷系统、水培农场自动控制）。理由：对于这种高度抽象的顶层架构设计，能在真实世界的复杂企业级业务流中落地，证明了该符号化世界模型在处理“制度化/规范化世界”时的工程可行性与鲁棒性。
   * **存疑的试验结果**：论文声称其语义机器学习（SML）通过“选择性术语”和“增量局部更新”解决了大规模因果推理的**组合爆炸（Combinatorial growth）问题**，但**未提供任何关于计算复杂度、内存消耗或推理延迟的量化对比数据**。理由：在庞大的企业本体中进行概率因果发现，计算开销通常是指数级的，仅靠人工限定术语范围（Knowledge Engineering）来规避，掩盖了算法本身的扩展性瓶颈。

### 第二模块：核心架构解释

本论文提出的 WMAS（以世界为中心的架构）依赖于一个双层语义模型，并通过一个闭环的“感知-行动-学习”机制运行。

**架构方法与流程：**
1. **底层：对象本体（Ground Semantic Environment）**：这是系统的“事实层”。它显式定义了世界中存在什么（实体）、它们的状态、关系以及可以改变状态的合法方法（工具/事务）。
2. **上层：因果知识层（Learned Causal Knowledge Layer）**：这是系统的“规律层”。它建立在底层本体之上，包含通过逻辑-概率推理得出的因果关系（例如：“如果发生 A，则有 p 的概率导致 B”）。
3. **连接机制：语义机器学习（SML）**：当底层本体发生事务性改变时，SML 会被触发，增量式地更新上层的因果知识。学习发生在“世界”层面，而不是“智能体”层面。
4. **异构智能体接入（含 LLM）**：智能体（人类、符号规划器或大语言模型）不直接与物理环境交互，而是通过受控接口与这个语义世界模型交互。环境为 LLM 提供当前状态快照、授权的工具（API）以及自然语言化的因果解释，从而彻底消除 LLM 的幻觉并保证推理的可验证性。

**核心逻辑伪代码（Python 风格）：**

```python
class SemanticWorldModel:
    def __init__(self, initial_ontology):
        # 第一层：底层对象本体（事实与规则）
        self.ground_ontology = initial_ontology 
        # 第二层：因果知识层（概率规律）
        self.causal_knowledge_base = {} 
        # 学习引擎
        self.sml_engine = SemanticMachineLearning()

    def execute_transaction(self, agent, action, target):
        """智能体执行动作，改变世界状态"""
        # 1. 验证动作是否符合本体规范
        if not self.ground_ontology.is_action_valid(agent.role, action):
            raise PermissionError("Action violates world norms.")
        
        # 2. 更新底层事实状态
        state_changes = self.ground_ontology.apply_action(action, target)
        
        # 3. 触发世界级别的语义机器学习 (SML)
        self._trigger_world_learning(state_changes)
        
        return self.get_state_snapshot()

    def _trigger_world_learning(self, state_changes):
        """增量更新因果知识层，学习发生在世界层面"""
        new_causal_rules = self.sml_engine.infer_causality(
            current_state=self.ground_ontology.state, 
            changes=state_changes
        )
        self.causal_knowledge_base.update(new_causal_rules)

class LLMAgent:
    def __init__(self, role):
        self.role = role

    def step(self, world_model: SemanticWorldModel):
        # 1. 获取受控的语义上下文（消除幻觉的基础）
        context = world_model.ground_ontology.get_snapshot(self.role)
        causal_rules = world_model.causal_knowledge_base.get_relevant_rules(context)
        
        # 2. LLM 基于绝对事实和因果规律进行推理
        action, target = self.llm_reasoning(context, causal_rules)
        
        # 3. 通过世界模型执行动作
        world_model.execute_transaction(self, action, target)
```

### 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 论文试图解决传统“以智能体为中心（Agent-Centered）”的多智能体系统在应用于高度结构化、规则驱动的领域（如企业管理、金融系统）时，由于各智能体维护独立的局部世界模型而导致的语义碎片化、信念分歧、系统行为不透明以及决策逻辑无法验证的核心痛点。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 核心创新点是提出了“以世界为中心（World-Centered）”的架构范式（WMAS）。作者将“世界”从一个被动的环境背景，提升为首要的表征、学习和协调基底。通过构建一个包含“对象本体事实层”和“概率因果知识层”的双层语义模型，强制所有异构智能体（包括 LLM）在一个共享的、显式的、语义一致的全局模型下进行感知、推理和行动。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 本文没有使用标准化的开源数据集或传统的消融实验。其关键支撑在于工程落地验证（Existence Proof）。作者通过自主研发的 Ontobox 平台，将这套高度抽象的理论架构实例化，并成功应用于私人诊所、车贷管理和水培农场等真实的工业级/企业级系统中，以此证明该架构在处理复杂规范化世界时的实际可行性和有效性。
