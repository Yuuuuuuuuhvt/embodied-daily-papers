PhyAI 的核心架构围绕“模型语义”与“执行策略”的边界展开。其系统分为四个层级：

1.  **Scheduler (调度器):** 负责接收请求，配置数据并行 (DP)、张量并行 (TP) 和 CFG 并行。它决定请求在哪些设备上运行，但不持有模型张量。
2.  **Model Runner (模型运行器 - 有状态):** 拥有请求的生命周期状态，管理中间缓冲区、KV Cache 和 CUDA Graph 桶。它负责推进迭代求解器（如 Diffusion/Flow-matching 的去噪循环）。
3.  **Modeling Modules (模型模块 - 无状态):** 实现具体的架构计算（如多模态前缀编码、动作专家网络）。它们不保留请求之间的状态。

### 第二模块：核心架构解释

SUV 的核心架构将视频生成与动作规划在隐空间（Latent Space）中进行了深度耦合，其工作流程如下：

1. 统一的视频接口与目标构建：模型不使用人工标注，而是利用冻结的基础模型（SAM 3 和 Depth Anything 3）对未来的真实 RGB 帧进行处理，自动生成语义、深度和实例追踪的“伪真值”视频流。这四种流被统一格式化为与 RGB 相同的 3 通道视频格式。
2. 隐空间编码：历史观测帧（Observation）和四种未来视频流目标，通过一个共享且冻结的 VAE 编码器映射到统一的隐空间中。
3. 专家模型与掩码注意力：
- 视频专家（Video Expert）：基于预训练的 Wan2.2-5B 模型，负责处理视觉隐变量。
- 动作专家（Action Expert）：一个独立的 Mixture-of-Transformers 架构，负责处理轨迹 Token。
- 掩码机制（Token Interaction Mask）：这是架构的核心。在 Transformer 块中，历史观测 Token 只能看到自己；每种未来视频流 Token 只能看到历史观测和自己（阻断未来流之间的信息泄露，保持预训练先验）；动作 Token 则可以读取历史观测以及所有四种未来视频流的 Token（实现未来场景对规划的单向指导）。
4. 联合流匹配（Flow Matching）推理：在推理阶段，视频和动作在统一的时间步长上进行联合去噪。动作专家在每一步去噪时，直接读取视频专家当前生成的未来场景隐变量，最终输出规划轨迹。

**2. TL;DR:**

### 第二模块：核心架构解释

BCP 的核心架构建立在一个冻结的预训练 VLA 模型之上，整个流程分为特征提取、序列化决策、自适应执行与强化学习优化四个阶段。

1.  **特征提取 (Feature Extraction):** 冻结的 VLA 接收当前观测和指令，输出固定长度 $H$ 的动作块。BCP 提取 VLA 内部的视觉-语言 Token、去噪后的动作序列以及动作速度特征，将其拼接并投影到共享维度。
2.  **序列化决策 (Sequential Decision):** 提取的特征加上一个可学习的 `[CLS]` Token 输入到一个轻量级 Transformer 编码器中。输出不使用 Softmax，而是生成 $M-1$ 个独立的 Logit，经过 Sigmoid 转化为在每个候选截断点“继续执行”的伯努利概率。
3.  **自适应执行 (Adaptive Execution):** 策略根据概率分布采样出一个具体的执行长度 $E_t$。机器人仅执行动作块的前 $E_t$ 步，随后丢弃剩余动作，获取新观测并再次查询 VLA。
4.  **强化学习优化 (RL Optimization):** 由于无法获得每一步最佳执行长度的真实标签，BCP 采用 GRPO 算法在轨迹级别进行训练。奖励函数（Replanning-Efficiency Reward）不仅奖励任务成功，还通过对比基线轨迹的 VLA 调用次数，惩罚过度重规划（即过短的执行域），防止策略崩溃。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class BernoulliContinuationHead(nn.Module):
    def __init__(self, vla_feature_dim, hidden_dim, candidate_horizons):
        super().__init__()
        self.candidate_horizons = candidate_horizons # e.g., [15, 20, 25, ..., 50]
        self.num_decisions = len(candidate_horizons) - 1
        
        # Projections for VLA features
        self.proj_vl = nn.Linear(vla_feature_dim, hidden_dim)
        self.proj_action = nn.Linear(vla_feature_dim, hidden_dim)
        
        self.cls_token = nn.Parameter(torch.randn(1, 1, hidden_dim))
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model=hidden_dim, nhead=8), num_layers=2
        )
        self.decision_head = nn.Linear(hidden_dim, self.num_decisions)

    def forward(self, vl_tokens, action_features):
        # 1. Feature Fusion
        f_vl = self.proj_vl(vl_tokens)
        f_a = self.proj_action(action_features)
        
        # 2. Sequence Construction: [CLS, F_vl, F_a1, ..., F_aH]
        batch_size = vl_tokens.shape[0]
        cls_tokens = self.cls_token.expand(batch_size, -1, -1)
        seq_input = torch.cat([cls_tokens, f_vl, f_a], dim=1)
        
        # 3. Transformer Encoding
        encoded = self.transformer(seq_input)
        cls_output = encoded[:, 0, :] # Extract CLS representation
        
        # 4. Bernoulli Continuation Probabilities
        logits = self.decision_head(cls_output)
        continue_probs = torch.sigmoid(logits) # Shape: (Batch, M-1)
        
        # 5. Calculate probability for each candidate horizon
        # P(E = e_k) = (prod_{i=1}^{k-1} p_i) * (1 - p_k)
        horizon_probs = self._compute_horizon_distribution(continue_probs)
        
        return horizon_probs

def replanning_efficiency_reward(success, vla_calls, ref_vla_calls, delta_plus=0.7, delta_minus=0.3):
    """
    Trajectory-level reward calculation.
    """
    if not success:
        return 0.0 # Failed trajectories get 0 reward regardless of efficiency
        
    # Relative efficiency: >0 means fewer VLA calls than reference
    efficiency = torch.tanh(torch.log(ref_vla_calls / vla_calls))
    
    # Asymmetric scaling: reward efficiency, mildly penalize inefficiency if successful
    if efficiency > 0:
        reward = 1.0 + delta_plus * efficiency
    else:
        reward = 1.0 + delta_minus * efficiency
        
    return reward
```

### 第二模块：核心架构解释

Enfold 的核心逻辑是将世界模型从“未来生成器”转变为“表征教师”。其架构与流程分为训练和部署两个截然不同的阶段：

1. **输入处理**：系统接收当前时刻的视觉观测图像与语言指令。
2. **未来生成与特征提取（仅训练阶段）**：庞大的生成式世界模型（如基于扩散模型的网络）接收真实的未来轨迹（加噪后）并尝试去噪重建。在此前向传播过程中，提取网络内部多层级的中间激活特征，这些特征隐式编码了未来的物理演化与空间交互。
3. **表征对齐（核心蒸馏）**：轻量级的当前状态编码器处理当前观测和指令，输出预测性表征。通过损失函数强制该表征与世界模型提取的多层未来特征进行对齐。
4. **动作预测与梯度阻断**：预测性表征被输入到动作预测头（Task Head）以输出控制动作。关键在于，动作头的梯度被阻断（Stop-Gradient），不回传给当前状态编码器。这确保了编码器的表征完全由世界模型的未来知识塑造，而不被动作标签的捷径学习所污染。
5. **推理部署**：完全剥离世界模型的生成分支，仅保留当前状态编码器和动作预测头，实现极低延迟的端到端动作输出。

```python
    def __init__(self):
        super().__init__()
        self.current_encoder = CurrentStateEncoder()
        self.world_model_generator = WorldModelGenerator() # e.g., Diffusion U-Net/DiT
        self.action_head = ActionHead()

        # current_rep: 仅依赖当前观测和指令
        current_rep = self.current_encoder(current_obs, language_instruction)
        
        # 2. 世界模型处理未来轨迹，提取多层中间特征 (仅训练时执行)
        with torch.no_grad(): # 或根据具体设计决定是否联合微调世界模型

            _, future_features = self.world_model_generator(future_trajectory, language_instruction, extract_features=True)
            
        # 3. 表征对齐损失 (Distillation/Enfolding)
        # 强制当前表征预测世界模型在处理未来时产生的内部特征
        representation_loss = compute_alignment_loss(current_rep, future_features)
        
        # 4. 动作预测与梯度阻断
        # stop_gradient 确保动作损失不会改变 current_encoder 的权重
        detached_rep = current_rep.detach() 
        pred_action = self.action_head(detached_rep)
        
        # 5. 动作损失
        action_loss = compute_mse_loss(pred_action, action_label)
        
        total_loss = representation_loss + action_loss
        return total_loss

    def forward_inference(self, current_obs, language_instruction):
        # 部署阶段：完全绕过 world_model_generator，实现超低延迟
        current_rep = self.current_encoder(current_obs, language_instruction)
        pred_action = self.action_head(current_rep)
        return pred_action
```

### 第二模块：核心架构解释

Track4Action 的核心思想是“训练时引入未来 3D 视角，推理时回归当前 2D 观察”。其架构与实验流程可拆解为以下四个阶段：

1.  **教师网络特征提取（仅训练阶段）：** 
    给定包含 $K$ 个动作的演示片段，截取对应的 $K+1$ 帧未来视觉观察 $V_{t:t+K}$。将其输入冻结的 3D 世界追踪模型（Track4World），提取场景、运动和相机 Token，并池化为一个紧凑的 3D 追踪特征 $f_t^{trk}$。该特征代表了动作执行后真实的 3D 世界变化。
2.  **学生网络特征对齐（蒸馏瓶颈）：** 
    VLA 骨干网络（Qwen3.5-2B）接收当前图像 $I_t$ 和语言指令 $l$，输出隐藏状态 $H_t$。模型引入一组可学习的 Track Queries $Q$，通过交叉注意力机制读取 $H_t$ 生成动作表征 $Z_t$。通过 MSE 损失函数，强制 $Z_t$ 在共享潜空间中对齐教师特征 $f_t^{trk}$。
3.  **门控融合与动作生成：** 
    将对齐后的表征 $Z_t$ 通过一个可学习的特征门控（Feature-wise Gate）与原始隐藏状态 $H_t$ 融合，生成条件特征 $H_t^{cond}$。该特征随后被送入基于 DiT 的流匹配（Flow-matching）动作头，预测未来的动作块（Action Chunk）。
4.  **无追踪器部署（推理阶段）：** 
    在实际机器人部署时，完全丢弃未来视频片段、Track4World 模型以及对齐损失分支。模型仅依赖当前观察，通过已训练好的 Track Queries 隐式推断 3D 动态，并生成动作。

```python
import torch
import torch.nn as nn

class Track4Action(nn.Module):
    def __init__(self, vla_backbone, track4world, action_head):
        super().__init__()
        self.vla_backbone = vla_backbone
        self.track4world = track4world # Frozen teacher
        self.action_head = action_head # Flow-matching DiT
        
        # Learnable track queries and alignment projections
        self.track_queries = nn.Parameter(torch.randn(1, num_queries, hidden_dim))
        self.cross_attn = nn.MultiheadAttention(embed_dim=hidden_dim, num_heads=8)
        self.proj_student = nn.Linear(hidden_dim, shared_dim)
        self.proj_teacher = nn.Linear(teacher_dim, shared_dim)
        
        # Gated fusion
        self.gate = nn.Sequential(nn.Linear(hidden_dim, hidden_dim), nn.Sigmoid())

    def forward(self, image_t, text_l, future_clip_v=None, action_target=None):
        # 1. VLA Backbone encodes current observation
        H_t = self.vla_backbone(image_t, text_l) 
        
        # 2. Track Queries extract action-facing representation
        # Q cross-attends to H_t
        Z_t, _ = self.cross_attn(query=self.track_queries, key=H_t, value=H_t)
        
        loss_align = 0.0
        if self.training and future_clip_v is not None:
            # 3. Teacher extracts world-centric 3D tracker feature (No Gradients)
            with torch.no_grad():
                teacher_tokens = self.track4world(future_clip_v)
                f_trk_t = torch.mean(teacher_tokens, dim=1) # Pooling
            
            # 4. Distillation / Alignment Loss
            z_t_proj = self.proj_student(Z_t)
            f_trk_proj = self.proj_teacher(f_trk_t)
            loss_align = nn.functional.mse_loss(z_t_proj, f_trk_proj)
            
        # 5. Gated Fusion
        gate_weight = self.gate(Z_t)
        H_cond = H_t + gate_weight * Z_t
        
        # 6. Action Generation (Flow-matching)
        if self.training:
            loss_act = self.action_head.compute_loss(H_cond, action_target)
            total_loss = loss_act + lambda_align * loss_align
            return total_loss
        else:
            # Deployment: generate action chunk from noise
            action_chunk = self.action_head.sample(H_cond)
            return action_chunk
```

### 第二模块：核心架构解释

UVT 框架的运行流程分为两个独立的阶段：**UVT 提取阶段（预训练 MVAE）** 与 **VLA 微调阶段**。

**阶段一：UVT 提取（构建统一监督信号）**
1. 给定一段演示轨迹，提取当前动作块（Action Chunk）$a_t$。
2. 使用冻结的预训练 LAM（Latent Action Model），输入当前帧和未来帧，提取离散的视觉动态代码 $z_t$。
3. 训练一个多模态变分自编码器（MVAE）：
   - 动作编码器和动态编码器分别将 $a_t$ 和 $z_t$ 映射到同一个 32 维潜在空间中的高斯分布。
   - 使用加权专家乘积（Weighted Product-of-Experts）机制，根据预测方差（精度）将两个分布融合为单一的潜在向量 $u_t$。
   - 训练解码器从 $u_t$ 中重建 $a_t$ 和 $z_t$，并使用 KL 散度正则化潜在空间。

**阶段二：VLA 微调（策略学习）**
1. 使用训练好的 MVAE，为演示数据集中的所有样本预计算 UVT 目标 $u_t$。
2. VLA 模型接收视觉和语言输入，预测潜在目标 $\hat{u}_t$。
3. 将 MVAE 的动作解码器接入 VLA，将 $\hat{u}_t$ 解码为物理动作 $\hat{a}_t$。
4. 联合优化 UVT 对齐损失（L2）和动作重建损失（L1），此时动作解码器保持可训练状态以适应预测偏差。

**核心伪代码实现 (Python 风格):**

```python
import torch
import torch.nn as nn

# ==========================================
# Stage 1: MVAE Fusion (Product of Experts)
# ==========================================
def weighted_product_of_experts(mu_a, var_a, mu_z, var_z, alpha_a, alpha_z):
    # Calculate precision (inverse variance)
    tau_a = 1.0 / var_a
    tau_z = 1.0 / var_z
    
    # Fused precision
    tau_fused = alpha_a * tau_a + alpha_z * tau_z
    
    # Fused mean
    mu_fused = (alpha_a * tau_a * mu_a + alpha_z * tau_z * mu_z) / tau_fused
    var_fused = 1.0 / tau_fused
    
    return mu_fused, var_fused

# ==========================================
# Stage 2: VLA Fine-tuning Loss Calculation
# ==========================================
class UVT_VLA_Loss(nn.Module):
    def __init__(self, gamma=0.5):
        super().__init__()
        self.gamma = gamma
        self.mse_loss = nn.MSELoss()
        self.l1_loss = nn.L1Loss()

    def forward(self, vla_pred_u, target_u, decoded_a, target_a):
        """
        vla_pred_u: VLA predicted latent target (\hat{u}_t)
        target_u: Precomputed UVT from MVAE (u_t)
        decoded_a: Action decoded from \hat{u}_t (\hat{a}_t)
        target_a: Ground truth action chunk (a_t)
        """
        # 1. UVT Alignment Loss (Anchor policy to unified space)
        loss_uvt = self.mse_loss(vla_pred_u, target_u)
        
        # 2. Action Decoding Loss (Ensure executable physical actions)
        loss_action = self.l1_loss(decoded_a, target_a)
        
        # Total Loss
        total_loss = loss_uvt + self.gamma * loss_action
        return total_loss
```

### 第二模块：核心架构解释

### 第二模块：核心架构解释

SUV 的核心架构将视频生成与动作规划在隐空间（Latent Space）中进行了深度耦合，其工作流程如下：

1. 统一的视频接口与目标构建：模型不使用人工标注，而是利用冻结的基础模型（SAM 3 和 Depth Anything 3）对未来的真实 RGB 帧进行处理，自动生成语义、深度和实例追踪的“伪真值”视频流。这四种流被统一格式化为与 RGB 相同的 3 通道视频格式。
2. 隐空间编码：历史观测帧（Observation）和四种未来视频流目标，通过一个共享且冻结的 VAE 编码器映射到统一的隐空间中。
3. 专家模型与掩码注意力：
- 视频专家（Video Expert）：基于预训练的 Wan2.2-5B 模型，负责处理视觉隐变量。
- 动作专家（Action Expert）：一个独立的 Mixture-of-Transformers 架构，负责处理轨迹 Token。
- 掩码机制（Token Interaction Mask）：这是架构的核心。在 Transformer 块中，历史观测 Token 只能看到自己；每种未来视频流 Token 只能看到历史观测和自己（阻断未来流之间的信息泄露，保持预训练先验）；动作 Token 则可以读取历史观测以及所有四种未来视频流的 Token（实现未来场景对规划的单向指导）。
4. 联合流匹配（Flow Matching）推理：在推理阶段，视频和动作在统一的时间步长上进行联合去噪。动作专家在每一步去噪时，直接读取视频专家当前生成的未来场景隐变量，最终输出规划轨迹。

### 第二模块：核心架构解释

BCP 的核心架构建立在一个冻结的预训练 VLA 模型之上，整个流程分为特征提取、序列化决策、自适应执行与强化学习优化四个阶段。

1.  **特征提取 (Feature Extraction):** 冻结的 VLA 接收当前观测和指令，输出固定长度 $H$ 的动作块。BCP 提取 VLA 内部的视觉-语言 Token、去噪后的动作序列以及动作速度特征，将其拼接并投影到共享维度。
2.  **序列化决策 (Sequential Decision):** 提取的特征加上一个可学习的 `[CLS]` Token 输入到一个轻量级 Transformer 编码器中。输出不使用 Softmax，而是生成 $M-1$ 个独立的 Logit，经过 Sigmoid 转化为在每个候选截断点“继续执行”的伯努利概率。
3.  **自适应执行 (Adaptive Execution):** 策略根据概率分布采样出一个具体的执行长度 $E_t$。机器人仅执行动作块的前 $E_t$ 步，随后丢弃剩余动作，获取新观测并再次查询 VLA。
4.  **强化学习优化 (RL Optimization):** 由于无法获得每一步最佳执行长度的真实标签，BCP 采用 GRPO 算法在轨迹级别进行训练。奖励函数（Replanning-Efficiency Reward）不仅奖励任务成功，还通过对比基线轨迹的 VLA 调用次数，惩罚过度重规划（即过短的执行域），防止策略崩溃。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class BernoulliContinuationHead(nn.Module):
    def __init__(self, vla_feature_dim, hidden_dim, candidate_horizons):
        super().__init__()
        self.candidate_horizons = candidate_horizons # e.g., [15, 20, 25, ..., 50]
        self.num_decisions = len(candidate_horizons) - 1
        
        # Projections for VLA features
        self.proj_vl = nn.Linear(vla_feature_dim, hidden_dim)
        self.proj_action = nn.Linear(vla_feature_dim, hidden_dim)
        
        self.cls_token = nn.Parameter(torch.randn(1, 1, hidden_dim))
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model=hidden_dim, nhead=8), num_layers=2
        )
        self.decision_head = nn.Linear(hidden_dim, self.num_decisions)

    def forward(self, vl_tokens, action_features):
        # 1. Feature Fusion
        f_vl = self.proj_vl(vl_tokens)
        f_a = self.proj_action(action_features)
        
        # 2. Sequence Construction: [CLS, F_vl, F_a1, ..., F_aH]
        batch_size = vl_tokens.shape[0]
        cls_tokens = self.cls_token.expand(batch_size, -1, -1)
        seq_input = torch.cat([cls_tokens, f_vl, f_a], dim=1)
        
        # 3. Transformer Encoding
        encoded = self.transformer(seq_input)
        cls_output = encoded[:, 0, :] # Extract CLS representation
        
        # 4. Bernoulli Continuation Probabilities
        logits = self.decision_head(cls_output)
        continue_probs = torch.sigmoid(logits) # Shape: (Batch, M-1)
        
        # 5. Calculate probability for each candidate horizon
        # P(E = e_k) = (prod_{i=1}^{k-1} p_i) * (1 - p_k)
        horizon_probs = self._compute_horizon_distribution(continue_probs)
        
        return horizon_probs

def replanning_efficiency_reward(success, vla_calls, ref_vla_calls, delta_plus=0.7, delta_minus=0.3):
    """
    Trajectory-level reward calculation.
    """
    if not success:
        return 0.0 # Failed trajectories get 0 reward regardless of efficiency
        
    # Relative efficiency: >0 means fewer VLA calls than reference
    efficiency = torch.tanh(torch.log(ref_vla_calls / vla_calls))
    
    # Asymmetric scaling: reward efficiency, mildly penalize inefficiency if successful
    if efficiency > 0:
        reward = 1.0 + delta_plus * efficiency
    else:
        reward = 1.0 + delta_minus * efficiency
        
    return reward
```

```python
        representation_loss = compute_alignment_loss(current_rep, future_features)
        
        # 4. 动作预测与梯度阻断
        # stop_gradient 确保动作损失不会改变 current_encoder 的权重
        detached_rep = current_rep.detach() 
        pred_action = self.action_head(detached_rep)
        
        # 5. 动作损失
        action_loss = compute_mse_loss(pred_action, action_label)
        
        total_loss = representation_loss + action_loss
        return total_loss

    def forward_inference(self, current_obs, language_instruction):
        # 部署阶段：完全绕过 world_model_generator，实现超低延迟
        current_rep = self.current_encoder(current_obs, language_instruction)
        pred_action = self.action_head(current_rep)
        return pred_action
```

### 第二模块：核心架构解释

Track4Action 的核心思想是“训练时引入未来 3D 视角，推理时回归当前 2D 观察”。其架构与实验流程可拆解为以下四个阶段：

1.  **教师网络特征提取（仅训练阶段）：** 
    给定包含 $K$ 个动作的演示片段，截取对应的 $K+1$ 帧未来视觉观察 $V_{t:t+K}$。将其输入冻结的 3D 世界追踪模型（Track4World），提取场景、运动和相机 Token，并池化为一个紧凑的 3D 追踪特征 $f_t^{trk}$。该特征代表了动作执行后真实的 3D 世界变化。
2.  **学生网络特征对齐（蒸馏瓶颈）：** 
    VLA 骨干网络（Qwen3.5-2B）接收当前图像 $I_t$ 和语言指令 $l$，输出隐藏状态 $H_t$。模型引入一组可学习的 Track Queries $Q$，通过交叉注意力机制读取 $H_t$ 生成动作表征 $Z_t$。通过 MSE 损失函数，强制 $Z_t$ 在共享潜空间中对齐教师特征 $f_t^{trk}$。
3.  **门控融合与动作生成：** 
    将对齐后的表征 $Z_t$ 通过一个可学习的特征门控（Feature-wise Gate）与原始隐藏状态 $H_t$ 融合，生成条件特征 $H_t^{cond}$。该特征随后被送入基于 DiT 的流匹配（Flow-matching）动作头，预测未来的动作块（Action Chunk）。
4.  **无追踪器部署（推理阶段）：** 
    在实际机器人部署时，完全丢弃未来视频片段、Track4World 模型以及对齐损失分支。模型仅依赖当前观察，通过已训练好的 Track Queries 隐式推断 3D 动态，并生成动作。

**核心逻辑伪代码 (Python/PyTorch 风格):**

```python
import torch
import torch.nn as nn

class Track4Action(nn.Module):
    def __init__(self, vla_backbone, track4world, action_head):
        super().__init__()
        self.vla_backbone = vla_backbone
        self.track4world = track4world # Frozen teacher
        self.action_head = action_head # Flow-matching DiT
        
        # Learnable track queries and alignment projections
        self.track_queries = nn.Parameter(torch.randn(1, num_queries, hidden_dim))
        self.cross_attn = nn.MultiheadAttention(embed_dim=hidden_dim, num_heads=8)
        self.proj_student = nn.Linear(hidden_dim, shared_dim)
        self.proj_teacher = nn.Linear(teacher_dim, shared_dim)
        
        # Gated fusion
        self.gate = nn.Sequential(nn.Linear(hidden_dim, hidden_dim), nn.Sigmoid())

    def forward(self, image_t, text_l, future_clip_v=None, action_target=None):
        # 1. VLA Backbone encodes current observation
        H_t = self.vla_backbone(image_t, text_l) 
        
        # 2. Track Queries extract action-facing representation
        # Q cross-attends to H_t
        Z_t, _ = self.cross_attn(query=self.track_queries, key=H_t, value=H_t)
        
        loss_align = 0.0
        if self.training and future_clip_v is not None:
            # 3. Teacher extracts world-centric 3D tracker feature (No Gradients)
            with torch.no_grad():
                teacher_tokens = self.track4world(future_clip_v)
                f_trk_t = torch.mean(teacher_tokens, dim=1) # Pooling
            
            # 4. Distillation / Alignment Loss
            z_t_proj = self.proj_student(Z_t)
            f_trk_proj = self.proj_teacher(f_trk_t)
            loss_align = nn.functional.mse_loss(z_t_proj, f_trk_proj)
            
        # 5. Gated Fusion
        gate_weight = self.gate(Z_t)
        H_cond = H_t + gate_weight * Z_t
        
        # 6. Action Generation (Flow-matching)
        if self.training:
            loss_act = self.action_head.compute_loss(H_cond, action_target)
            total_loss = loss_act + lambda_align * loss_align
            return total_loss
        else:
            # Deployment: generate action chunk from noise
            action_chunk = self.action_head.sample(H_cond)
            return action_chunk
```

### 第二模块：核心架构解释

UVT 框架的运行流程分为两个独立的阶段：**UVT 提取阶段（预训练 MVAE）** 与 **VLA 微调阶段**。

**阶段一：UVT 提取（构建统一监督信号）**
1. 给定一段演示轨迹，提取当前动作块（Action Chunk）$a_t$。
2. 使用冻结的预训练 LAM（Latent Action Model），输入当前帧和未来帧，提取离散的视觉动态代码 $z_t$。
3. 训练一个多模态变分自编码器（MVAE）：
   - 动作编码器和动态编码器分别将 $a_t$ 和 $z_t$ 映射到同一个 32 维潜在空间中的高斯分布。
   - 使用加权专家乘积（Weighted Product-of-Experts）机制，根据预测方差（精度）将两个分布融合为单一的潜在向量 $u_t$。
   - 训练解码器从 $u_t$ 中重建 $a_t$ 和 $z_t$，并使用 KL 散度正则化潜在空间。

**阶段二：VLA 微调（策略学习）**
1. 使用训练好的 MVAE，为演示数据集中的所有样本预计算 UVT 目标 $u_t$。
2. VLA 模型接收视觉和语言输入，预测潜在目标 $\hat{u}_t$。
3. 将 MVAE 的动作解码器接入 VLA，将 $\hat{u}_t$ 解码为物理动作 $\hat{a}_t$。
4. 联合优化 UVT 对齐损失（L2）和动作重建损失（L1），此时动作解码器保持可训练状态以适应预测偏差。

**核心伪代码实现 (Python 风格):**

```python
import torch
import torch.nn as nn

# ==========================================
# Stage 1: MVAE Fusion (Product of Experts)
# ==========================================
def weighted_product_of_experts(mu_a, var_a, mu_z, var_z, alpha_a, alpha_z):
    # Calculate precision (inverse variance)
    tau_a = 1.0 / var_a
    tau_z = 1.0 / var_z
    
    # Fused precision
    tau_fused = alpha_a * tau_a + alpha_z * tau_z
    
    # Fused mean
    mu_fused = (alpha_a * tau_a * mu_a + alpha_z * tau_z * mu_z) / tau_fused
    var_fused = 1.0 / tau_fused
    
    return mu_fused, var_fused

# ==========================================
# Stage 2: VLA Fine-tuning Loss Calculation
# ==========================================
class UVT_VLA_Loss(nn.Module):
    def __init__(self, gamma=0.5):
        super().__init__()
        self.gamma = gamma
        self.mse_loss = nn.MSELoss()
        self.l1_loss = nn.L1Loss()

    def forward(self, vla_pred_u, target_u, decoded_a, target_a):
        """
        vla_pred_u: VLA predicted latent target (\hat{u}_t)
        target_u: Precomputed UVT from MVAE (u_t)
        decoded_a: Action decoded from \hat{u}_t (\hat{a}_t)
        target_a: Ground truth action chunk (a_t)
        """
        # 1. UVT Alignment Loss (Anchor policy to unified space)
        loss_uvt = self.mse_loss(vla_pred_u, target_u)
        
        # 2. Action Decoding Loss (Ensure executable physical actions)
        loss_action = self.l1_loss(decoded_a, target_a)
        
        # Total Loss
        total_loss = loss_uvt + self.gamma * loss_action
        return total_loss
```

### 第二模块：核心架构解释

UniNav 的核心逻辑是将异构的多模态数据映射到统一的隐空间，并使用预训练的视频扩散模型（Wan2.1）进行联合 Flow-Matching 训练。

**运行流程拆解：**
1. **特征编码与 Token 化**：使用冻结的 VAE 将历史帧、目标图像编码为视觉上下文 Token；将未来帧初始化为噪声 Token；将 K 步连续航点通过 MLP 映射为轨迹 Token；利用冻结的几何基础模型（DA3）提取未来视角的相机位姿/深度特征，作为相机 Token 的回归目标。
2. **联合降噪（训练阶段）**：将上述所有 Token（外加 Register Tokens）拼接成一个长序列。Transformer 预测未来视频、轨迹和相机 Token 的速度场（Velocity），通过 SmoothL1 和 MSE 损失联合优化。
3. **非对称注意力（UniNav-Fast 变体）**：在训练时修改 Attention Mask，使得轨迹 Token 看不到未来视频的噪声 Token，但视频 Token 可以看到轨迹 Token。
4. **高效推理（部署阶段）**：直接从输入序列中剔除未来视频 Token，仅从随机噪声初始化轨迹 Token，经过 1-2 步 Flow-Matching 采样，直接输出物理可执行的航点坐标。

```python
    total_loss = loss_action + lambda_weight * loss_foresight
```

### 第二模块：核心架构解释

CrossScope 的核心架构是一个双流扩散 Transformer (DiT)，其运行流程与实验设计如下：

**1. 双流独立骨干与读写契约 (Dual-Stream Backbone & Read/Write Contract)**
模型初始化为两个独立的 DiT 专家，分别处理母镜和子镜的潜在表示（Latents）。在每个路由层，模型严格执行“只读前置状态，写入目标残差”的契约，防止跨视角通信污染各自视角的原始特征。

**2. M2C：母到子运动条件 (Mother-to-Child Motion Conditioning)**
子镜视野狭窄，缺乏全局运动参考。模型通过 Pose Readout 模块从母镜特征中提取子镜在母镜平面上的运动轨迹（位置、朝向、速度等）。这些轨迹被编码为细粒度和粗粒度的运动描述符，通过交叉注意力（Cross-Attention）和 AdaLN 转化为运动残差，单向注入到子镜的 DiT 块中。

**3. C2M：子到母外观条件 (Child-to-Mother Appearance Conditioning)**
子镜能看到母镜看不到的局部高清解剖结构。模型将子镜的当前帧与历史缓存帧通过位姿对齐（Pose-align）投影到母镜平面。通过一个覆盖门控机制（Coverage Gate），仅在几何空间重合的区域，才将子镜的外观特征转化为残差注入母镜。无几何支持的区域严格为零。

**4. 实验流程**
输入为同步采样的 9 帧双视角视频（第 0 帧为观测锚点，1-8 帧为预测目标）。模型通过 Flow Matching 联合优化未来帧生成、位姿预测和 M2C 轨迹辅助损失。推理时，锚点帧保持不变，未来帧随去噪步数演进，路由条件在每步动态重计算。

```python
    # 计算写入子镜的运动残差 (Zero-initialized)
    R_M2C = compute_motion_residual(X_C_bar, motion_descriptor)
    
    # 3. C2M: 子镜补充母镜外观
    # 验证子镜特征在母镜平面上的几何覆盖率
    geom_support = compute_geometric_coverage(pose_readout, child_history)
    # 提取外观残差
    appearance_residual = compute_appearance_residual(X_C_bar, child_history)
    # 门控机制：仅在有几何支持的区域写入外观，否则为0
    R_C2M = apply_coverage_gate(appearance_residual, geom_support)
    
    # 4. 目标特定的残差注入 (Target-specific residual writes)
    X_M_next = X_M_bar + R_C2M
    X_C_next = X_C_bar + R_M2C
    
    return X_M_next, X_C_next
```

### 第二模块：核心架构解释

LiteMVS 的整体架构分为四个核心步骤，旨在将高维语义与几何先验融入轻量级多视角匹配流程中：

**步骤一：特征提取与语义注入**
给定一张参考图像和多张源图像，模型首先使用轻量级 CNN 提取所有图像的视觉匹配特征。同时，参考图像被输入到一个轻量级分割编码器（如 MobileSAM）中，提取出包含高层结构和边界信息的语义描述符。

**步骤二：语义感知 4D 代价体积构建**
利用已知的相机内外参，通过可微单应性变换（Plane-sweep warping）将源图像特征投影到参考图像的各个深度假设平面上。随后，将参考图像的语义描述符沿着深度维度进行广播，并与投影特征、几何元数据拼接，构建出一个富含语义信息的 4D 代价体积。

**步骤三：混合专家 (MoE) 代价聚合**
传统的 MVS 通常使用单一共享的 MLP 压缩 4D 代价体积。LiteMVS 引入了 MoE 架构，设置多个轻量级专家 MLP 和一个门控网络。门控网络根据输入特征预测权重，动态组合不同专家的输出。这一机制允许不同的专家网络专门处理特定的深度范围或几何模式，从而在不显著增加计算量的情况下提升聚合能力，最终输出 3D 代价体积并回归出深度图。

**步骤四：视觉基础模型先验蒸馏（仅训练阶段）**
在训练时，除了使用真实的深度标签进行监督，模型还引入了 Depth Anything V2（提供相对深度伪标签）和 StableNormal（提供表面法线伪标签）。通过尺度不变损失和法线一致性损失，LiteMVS 被迫对齐这些大模型的输出，从而在不增加任何推理网络层的情况下，吸收大模型的全局几何先验。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class LiteMVS(nn.Module):
    def __init__(self):
        super().__init__()
        self.cnn_encoder = LightweightCNN()
        self.semantic_encoder = MobileSAM_Encoder() # Frozen during training
        self.moe_aggregator = MoE_MLP(num_experts=3)
        self.depth_decoder = UNetPlusPlusDecoder()
        
    def forward(self, ref_img, src_imgs, intrinsics, extrinsics, depth_hypotheses):
        # 1. Feature Extraction
        ref_feat = self.cnn_encoder(ref_img)
        src_feats = [self.cnn_encoder(img) for img in src_imgs]
        
        # Extract semantic prior from reference image
        with torch.no_grad():
            semantic_desc = self.semantic_encoder(ref_img) 
            
        # 2. Plane-sweep warping & 4D Volume Construction
        warped_volumes = []
        for src_feat, ext in zip(src_feats, extrinsics):
            # Differentiable homography warping
            warped = self.differentiable_warp(src_feat, intrinsics, ext, depth_hypotheses)
            warped_volumes.append(warped)
            
        # Aggregate multi-view features and concatenate semantic descriptors
        volume_4d = self.variance_pooling(warped_volumes, ref_feat)
        semantic_desc_broadcast = semantic_desc.unsqueeze(2).expand_as(volume_4d)
        semantic_aware_4d_volume = torch.cat([volume_4d, semantic_desc_broadcast], dim=1)
        
        # 3. MoE Cost Aggregation (Reduce 4D to 3D)
        # Gating network assigns weights to experts based on feature context
        cost_volume_3d = self.moe_aggregator(semantic_aware_4d_volume)
        
        # 4. Depth Prediction
        predicted_depth = self.depth_decoder(cost_volume_3d)
        
        return predicted_depth

# Loss Computation (Training Only)
def compute_loss(predicted_depth, gt_depth, ref_img, foundation_models):
    # Standard MVS Loss
    loss_simple = l1_loss(predicted_depth, gt_depth)
    
    # Pseudo-label generation (Zero inference cost)
    with torch.no_grad():
        pseudo_depth = foundation_models.depth_anything(ref_img)
        pseudo_normal = foundation_models.stable_normal(ref_img)
        
    # Distillation Losses
    loss_rel = scale_invariant_loss(predicted_depth, pseudo_depth)
    pred_normal = depth_to_normal(predicted_depth)
    loss_norm = ssim_loss(pred_normal, pseudo_normal) + gradient_loss(pred_normal, pseudo_normal)
    
    total_loss = loss_simple + lambda_rel * loss_rel + lambda_norm * loss_norm
    return total_loss
```

### 第二模块：核心架构解释

RealWeather 的整体架构建立在预训练的流匹配（Flow-Matching）驾驶世界模型（Cosmos-Predict2.5）之上。其训练流程分为数据初始化、渐进式自举训练和强化学习微调三个阶段。

**1. 伪晴天生成 (Pseudo-Clear Generation - 初始化阶段)**
为了启动训练，必须构造初始的伪配对数据。给定真实的恶劣天气视频，首先使用去雨/去雪模型清理瞬态伪影，提取深度和边缘特征（用 SAM3 掩码掉积雪/水坑区域以防特征泄露）。随后，使用 FLUX.2 编辑视频第一帧作为“晴天锚点帧”，并利用几何条件世界模型将该帧的外观传播到整个视频，得到“伪晴天”视频（Pseudo-Clear）。

**2. 渐进式真实感自举 (Progressive Realism Bootstrapping)**
这是核心的流匹配训练阶段，分为三步：
*   **正向学习：** 输入“伪晴天”，目标拟合“真恶劣天气”。模型学会了真实的物理天气渲染。
*   **反向自举：** 输入“真晴天”，利用上一步的模型生成“合成恶劣天气”。将这两者配对，训练模型从“合成恶劣天气”到“真晴天”的反向去天气能力。
*   **输入自适应：** 输入“真恶劣天气”，利用反向模型生成“合成晴天”。将这两者配对，再次训练正向生成。此时输入端从“伪晴天”变成了包含真实光影的“合成晴天”，消除了 Domain Gap。

**3. 场景保真度强化学习 (Scene-Fidelity RL Optimization)**
在自举训练后，模型仍可能产生幻觉（如把路标变成树）。使用 GRPO 算法，在无文本提示（CFG=0）下生成视频。利用 SAM3 提取输入视频和生成视频中的关键元素（车道线、行人、车辆）的掩码，计算 IoU 作为 Reward。通过最大化该 Reward 更新模型策略，强制模型在渲染天气时锁定这些安全关键像素。

```python
import torch.nn.functional as F

    def flow_matching_loss(self, z_input, z_target, prompt):

        noise = torch.randn_like(z_target)
        t = torch.rand(z_target.shape[0])
        z_t = t * noise + (1 - t) * z_target
        v_pred = self.model(z_t, z_input, t, prompt)
        v_target = noise - z_target
        return F.mse_loss(v_pred, v_target)

    def progressive_bootstrapping(self, real_adverse, real_clear, pseudo_clear):

        # Phase 1: 学习真实天气效果 (Pseudo-Clear -> Real-Adverse)
        loss_phase1 = self.flow_matching_loss(pseudo_clear, real_adverse, "adverse prompt")

            bootstrapped_adverse = self.model.generate(real_clear, "adverse prompt")
        loss_phase2 = self.flow_matching_loss(bootstrapped_adverse, real_clear, "clear prompt")
        
        # Phase 3: 真实输入自适应 (Bootstrapped-Clear -> Real-Adverse)
        with torch.no_grad():
            bootstrapped_clear = self.model.generate(real_adverse, "clear prompt")
```

### 第三模块：核心学术问答

**Q1: 这篇论文试图解决什么核心问题？**

A1: 论文试图解决自动驾驶视频生成中“极端天气转换”的痛点：由于无法在现实世界中收集到同一场景下不同天气的成对视频，现有模型只能依赖合成数据或强加几何约束，这导致生成的视频要么天气效果虚假（缺乏真实的物理交互如水花、积雪），要么破坏了原始场景的物理结构（产生改变车道、车辆消失等致命幻觉），使得生成数据无法用于下游自动驾驶系统的训练和评估。

**Q2: 作者提出的核心解决方案（创新点）是什么？**

A2: 核心解决方案是将预训练的驾驶世界模型改造为视频到视频的天气编辑器，并提出双轨优化策略：一是“渐进式真实感自举（Progressive Realism Bootstrapping）”，通过模型自身的正反向生成迭代，用合成的高质量配对数据替代粗糙的伪造数据，消除输入域偏差；二是“场景保真度强化学习（Scene-Fidelity RL Optimization）”，直接将 SAM3 提取的交通关键元素（车道、人、车）的 IoU 作为奖励，用 GRPO 算法硬性约束模型，杜绝结构幻觉。

**Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？**

A3: 实验设计的巧妙之处在于引入了全新的评估指标“VLM-Realism Score”。传统的 CLIP 文本-图像相似度指标只能判断画面“像不像下雨”，无法判断“雨下得符不符合真实物理规律”。作者利用 Qwen3-VL-32B，将真实的恶劣天气驾驶视频作为上下文参考（In-context references）输入给 VLM，让 VLM 像人类一样去评估生成视频中天气与场景交互的自然度、时间一致性以及 AI 伪影。这种基于 VLM 的上下文评估方法为缺乏 Ground Truth 的生成任务提供了更可靠的真实感量化手段。

**Q4: 这篇论文最显著的贡献点（Top 3）是什么？**

A4:
1. 提出了 RealWeather 框架，通过辅助的伪晴天生成管道和自举策略，彻底摆脱了天气转换任务对 3D 引擎或模拟器合成成对数据的依赖，直接从真实视频中学习天气动态。
2. 设计了 Progressive Realism Bootstrapping 机制，不仅实现了高质量的晴天与恶劣天气双向转换，还成功弥合了伪造输入与真实输入之间的域差距（Domain Gap）。
3. 引入了 Scene-Fidelity RL Optimization，首次在驾驶世界模型中利用视觉基础模型（SAM3）的分割结果作为强化学习奖励，显式且有效地抑制了安全关键元素的结构幻觉。

**Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）**

A5:
1. **Cosmos-Predict2.5 (Ali et al., 2025):** 本文的底层架构直接建立在该预训练的流匹配（Flow-matching）驾驶世界模型之上，利用其强大的时空一致性和视频生成先验。
2. **Flow-GRPO (Liu et al., 2026a) / GRPO:** 本文的强化学习优化阶段采用了 GRPO（群体相对策略优化）算法，将其从大语言模型的对齐任务迁移到了连续视频生成的物理结构对齐任务中。

**Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？**

A6: 
**局限性与漏洞：** 
1. **推理成本极高：** 论文在附录中坦诚，在 8 张 B200 GPU 上，生成 101 帧视频的吞吐量仅为 2.5 FPS。这种基于自回归和 35 步流匹配采样的生成速度，距离实际工程部署或大规模数据合成的效率要求相去甚远。
2. **缺乏细粒度空间控制：** 目前只能通过文本提示控制天气的种类和强度，无法精确控制天气效果的空间分布（例如，无法指定“仅在左侧车道产生积水”或“仅在挡风玻璃右侧产生雪花”）。
3. **评估指标的套娃风险：** VLM-Realism 依赖 Qwen3-VL 进行打分，用一个黑盒大模型去评估另一个大模型的生成结果，存在潜在的对齐偏差（VLM 可能偏好某种特定的生成纹理而非绝对的物理真实）。

**对后续科研的启发：** 
证明了“RLHF/RLAIF”机制在视觉生成领域的巨大潜力。将确定性的计算机视觉算法（如 SAM3 分割）作为 Reward 模型，通过 GRPO 优化扩散/流匹配模型，是解决生成式 AI “幻觉”问题的一条极具前景的确定性路径。后续研究可以探索如何将这种 RL 机制用于更复杂的物理规律约束（如车辆动力学、碰撞体积）。
