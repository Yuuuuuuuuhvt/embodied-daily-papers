### 第二模块：核心架构解释

本文的模型架构（PrismWM）及实验流程可以拆解为以下几个核心步骤：

1.  **状态编码与解耦 (State Encoding):** 给定图像序列，使用小型视觉 Transformer (ViT-tiny) 提取特征，将其解耦为全局 JEPA 潜在变量 ($z$) 和一组稀疏的显式度量点锚点 ($p$)。
2.  **动力学预测 (Dynamics Prediction):** 
    *   **泄漏版本 (GoalDyn):** 预测器接收当前状态 ($z, p$)、动作 ($a$) 以及语言目标 ($g$)，预测下一步状态 ($z', p'$)。此时模型倾向于直接复制 $g$ 的信息到 $p'$ 中。
    *   **修复版本 (GoalFree):** 预测器仅接收当前状态 ($z, p$) 和动作 ($a$)，预测下一步状态 ($z', p'$)。语言目标 $g$ 被严格阻挡在预测器之外。
3.  **监督读取路径 (Supervised Read Path):** 在训练阶段，对锚点 $p$ 的生成施加监督损失，强制锚点编码真实的物理空间关系。
4.  **基于成本的规划 (Cost-based Planning):** 在测试（控制）阶段，使用交叉熵方法（CEM）进行模型预测控制。预测器在无目标状态下展开多步轨迹，规划器随后使用语言目标 $g$ 作为成本函数（Cost）来评估这些轨迹并选择最优动作。

```python
        self.encoder = ViT_Tiny()
        self.predictor = TransformerPredictor()
        self.use_goal_in_dynamics = use_goal_in_dynamics
        
    def encode(self, image):
        # 将图像解耦为潜在变量 z 和显式锚点 p
        features = self.encoder(image)
        z, p = extract_latent_and_anchors(features)
        return z, p
        
    def rollout_step(self, z, p, action, goal=None):
        # 核心差异：目标是否进入动力学预测器
        if self.use_goal_in_dynamics:
            # 泄漏模式：预测器看到目标，直接抄写答案

        else:
            # GoalFree 模式（本文修复方案）：预测器仅基于物理状态和动作进行推演
            z_next, p_next = self.predictor(z, p, action)
        return z_next, p_next

    def plan(self, initial_image, goal, candidate_actions):
        z, p = self.encode(initial_image)
        best_action = None
        lowest_cost = float('inf')
        
        for actions in candidate_actions:
            curr_z, curr_p = z, p
            # 动力学展开
            for action in actions:
                curr_z, curr_p = self.rollout_step(curr_z, curr_p, action, goal)

            cost = compute_relation_cost(curr_p, goal)
            if cost < lowest_cost:
                lowest_cost = cost
                best_action = actions[0]
                
        return best_action
```

### 第二模块：核心架构解释

NativeMEM 的核心思想是将记忆构建与策略推理进行解耦，并通过两阶段训练法实现记忆 Token 与预训练 VLA 动作空间的对齐。

**流程详解**：
1.  **阶段一：原生记忆压缩（Tokenizer 训练）**
    *   冻结预训练的 VLA 主干网络。
    *   初始化一个记忆编码器（继承自 VLA 的视觉编码器），并引入一个可学习的查询向量（`q_mem`）。
    *   将历史帧输入记忆编码器，`q_mem` 通过注意力机制将一帧画面的所有 Patch Tokens 聚合成单个 Summary Token。
    *   将这些 Summary Tokens 拼接到当前观测序列后，输入冻结的 VLA。
    *   **关键点**：仅使用 VLA 原生的动作预测损失（Action Loss）来反向传播更新记忆编码器。这迫使压缩后的 Token 必须包含对“预测动作”有用的信息，而非仅仅用于“重建图像”。
2.  **阶段二：任务特定微调（VLA 微调）**
    *   冻结阶段一训练好的记忆编码器（Tokenizer）。
    *   利用 Tokenizer 离线处理目标任务的演示数据，将所有历史帧缓存为极小体积的 Memory Tokens。
    *   解冻 VLA 主干网络，将缓存的 Memory Tokens 拼接到当前输入中，使用少量目标任务数据进行全参数或高效微调。
3.  **实时推理部署**
    *   Tokenizer 作为独立进程高频运行，将新到达的观测帧实时压缩并推入记忆队列。
    *   VLA 在需要预测动作时，直接读取最新的记忆队列进行推理，两者互不阻塞。

**核心伪代码（Python 风格）**：

```python
import torch
import torch.nn as nn

class NativeMEM(nn.Module):
    def __init__(self, pretrained_vla):
        super().__init__()
        # 阶段1：初始化记忆编码器（复用VLA视觉编码器权重）
        self.memory_encoder = copy.deepcopy(pretrained_vla.vision_encoder)
        self.q_mem = nn.Parameter(torch.randn(1, 1, embed_dim)) # 可学习的查询向量
        self.w_mem = nn.Linear(embed_dim, vla_token_dim)        # 维度对齐投影
        self.b_mem = nn.Parameter(torch.randn(1, 1, vla_token_dim)) # 序列起始Token
        
        self.vla_backbone = pretrained_vla
        
    def tokenize_memory(self, history_frames):
        # history_frames: [B, T, V, C, H, W] (Batch, Time, Views, Channels, Height, Width)
        B, T, V = history_frames.shape[:3]
        frames = history_frames.view(B * T * V, C, H, W)
        
        # 提取视觉特征
        patch_tokens = self.memory_encoder.extract_features(frames) # [B*T*V, Num_Patches, Dim]
        
        # 极致压缩：使用 q_mem 将所有 patch tokens 压缩为 1 个 token
        q = self.q_mem.expand(B * T * V, -1, -1)
        # 简化的交叉注意力机制
        summary_tokens = cross_attention(query=q, key=patch_tokens, value=patch_tokens) 
        
        # 投影到 VLA 的 Token 维度
        memory_tokens = self.w_mem(summary_tokens) # [B*T*V, 1, VLA_Dim]
        memory_tokens = memory_tokens.view(B, T * V, -1)
        
        # 拼接起始符
        b_mem_expanded = self.b_mem.expand(B, -1, -1)
        return torch.cat([b_mem_expanded, memory_tokens], dim=1) # [B, 1 + T*V, VLA_Dim]

    def forward(self, current_obs, state, instruction, history_frames):
        # 1. 获取当前观测的 Tokens
        obs_tokens = self.vla_backbone.encode_obs(current_obs)
        prompt_tokens = self.vla_backbone.encode_prompt(instruction, state)
        
        # 2. 获取历史记忆 Tokens
        # 在阶段2微调时，这一步通常是离线计算并缓存好的
        memory_tokens = self.tokenize_memory(history_frames)
        
        # 3. 拼接完整序列
        input_sequence = torch.cat([obs_tokens, prompt_tokens, memory_tokens], dim=1)
        
        # 4. 预测动作
        action_logits = self.vla_backbone.predict_action(input_sequence)
        return action_logits
```

### 第二模块：核心架构解释

WAM-TTT 的核心架构建立在 LDA（一种包含视觉专家和动作专家的扩散 Transformer）之上。其运行流程严格分为元训练（Meta-Training）和测试时部署（Test-Time Deployment）两个阶段。

**1. 架构修改**
在 LDA 的视觉专家（Video Expert）的每个 Transformer 块中，增加一个 TTT 残差分支。该分支包含慢速投影矩阵（Slow Projections）和一个多层感知机（MLP），该 MLP 的参数被称为快速权重（Fast Weights）。动作专家（Action Expert）保持不变。

**2. 元训练阶段（Meta-Training）**
输入同步对齐的“无动作人类视频”与“带动作机器人轨迹”。
内循环（Inner Loop）：人类视频通过网络，计算视频预测损失（Video Prediction Loss）和键值记忆重构损失（Key-Value Memory Reconstruction Loss）。通过梯度下降仅更新 TTT 层的快速权重。
外循环（Outer Loop）：使用更新后的快速权重处理机器人轨迹，计算标准的机器人动作扩散损失和视频扩散损失。通过反向传播更新 WAM 主干参数、TTT 慢速投影矩阵以及快速权重的初始值。

**3. 测试时部署阶段（Test-Time Deployment）**
输入目标任务的无标注人类视频。
内循环（Inner Loop）：冻结 WAM 主干、慢速投影矩阵和快速权重初始值。人类视频通过网络，计算视频预测损失和键值记忆重构损失。通过梯度下降更新快速权重。
执行（Execution）：固定更新后的快速权重。机器人根据当前观测，通过网络直接输出动作。

```python
theta_slow = initialize_slow_projections() # TTT 慢速投影矩阵 (慢速)
W_init = initialize_fast_weights() # 快速权重初始值 (慢速)

def test_time_adaptation(human_video, steps=1, lr=0.01):
    """测试时训练阶段：仅使用人类视频更新快速权重"""
    # 冻结慢速参数
    freeze(theta_WAM, theta_slow, W_init)
    
    # 从初始值加载快速权重
    W_fast = copy(W_init)
    
    for step in range(steps):
        # 前向传播人类视频
        video_features = forward_video_expert(human_video, theta_WAM)
        
        # 计算 TTT 残差输出
        queries = theta_slow.Q(video_features)
        mlp_output = MLP(queries, weights=W_fast)
        residual = theta_slow.O(mlp_output)
        
        # 将残差注入视觉特征流
        adapted_features = video_features + residual
        
        # 计算人类视频端的自监督损失
        loss_vg = compute_video_prediction_loss(adapted_features, human_video)
        loss_kvm = compute_key_value_reconstruction_loss(W_fast, human_video, theta_slow)
        total_loss = loss_vg + lambda_weight * loss_kvm
        
        # 内循环：仅更新快速权重 W_fast
        gradients = compute_gradients(total_loss, W_fast)
        W_fast = W_fast - lr * gradients
        
    return W_fast

def robot_execution(robot_obs, W_fast_adapted):
    """机器人执行阶段：使用更新后的快速权重生成动作"""
    # 视觉专家处理当前观测，注入 TTT 残差
    video_features = forward_video_expert(robot_obs, theta_WAM)
    queries = theta_slow.Q(video_features)
    mlp_output = MLP(queries, weights=W_fast_adapted)
    residual = theta_slow.O(mlp_output)
    adapted_features = video_features + residual
    
    # 动作专家基于调整后的视觉特征生成动作
    action = forward_action_expert(adapted_features, theta_WAM)
    return action
```

### 第二模块：核心架构解释

本文的模型架构（PrismWM）及实验流程可以拆解为以下几个核心步骤：

1.  **状态编码与解耦 (State Encoding):** 给定图像序列，使用小型视觉 Transformer (ViT-tiny) 提取特征，将其解耦为全局 JEPA 潜在变量 ($z$) 和一组稀疏的显式度量点锚点 ($p$)。
2.  **动力学预测 (Dynamics Prediction):** 
    *   **泄漏版本 (GoalDyn):** 预测器接收当前状态 ($z, p$)、动作 ($a$) 以及语言目标 ($g$)，预测下一步状态 ($z', p'$)。此时模型倾向于直接复制 $g$ 的信息到 $p'$ 中。
    *   **修复版本 (GoalFree):** 预测器仅接收当前状态 ($z, p$) 和动作 ($a$)，预测下一步状态 ($z', p'$)。语言目标 $g$ 被严格阻挡在预测器之外。
3.  **监督读取路径 (Supervised Read Path):** 在训练阶段，对锚点 $p$ 的生成施加监督损失，强制锚点编码真实的物理空间关系。
4.  **基于成本的规划 (Cost-based Planning):** 在测试（控制）阶段，使用交叉熵方法（CEM）进行模型预测控制。预测器在无目标状态下展开多步轨迹，规划器随后使用语言目标 $g$ 作为成本函数（Cost）来评估这些轨迹并选择最优动作。

**核心逻辑伪代码 (Python 风格):**

```python
class PrismWM:
    def __init__(self, use_goal_in_dynamics=False):
        self.encoder = ViT_Tiny()
        self.predictor = TransformerPredictor()
        self.use_goal_in_dynamics = use_goal_in_dynamics
        
    def encode(self, image):
        # 将图像解耦为潜在变量 z 和显式锚点 p
        features = self.encoder(image)
        z, p = extract_latent_and_anchors(features)
        return z, p
        
    def rollout_step(self, z, p, action, goal=None):
        # 核心差异：目标是否进入动力学预测器
        if self.use_goal_in_dynamics:
            # 泄漏模式：预测器看到目标，直接抄写答案
            z_next, p_next = self.predictor(z, p, action, goal)
        else:
            # GoalFree 模式（本文修复方案）：预测器仅基于物理状态和动作进行推演
            z_next, p_next = self.predictor(z, p, action)
        return z_next, p_next

    def plan(self, initial_image, goal, candidate_actions):
        z, p = self.encode(initial_image)
        best_action = None
        lowest_cost = float('inf')
        
        for actions in candidate_actions:
            curr_z, curr_p = z, p
            # 动力学展开
            for action in actions:
                curr_z, curr_p = self.rollout_step(curr_z, curr_p, action, goal)
            
            # 目标仅在规划器的成本函数中起作用
            cost = compute_relation_cost(curr_p, goal)
            if cost < lowest_cost:
                lowest_cost = cost
                best_action = actions[0]
                
        return best_action
```

### 第二模块：核心架构解释

NativeMEM 的核心思想是将记忆构建与策略推理进行解耦，并通过两阶段训练法实现记忆 Token 与预训练 VLA 动作空间的对齐。

**流程详解**：
1.  **阶段一：原生记忆压缩（Tokenizer 训练）**
    *   冻结预训练的 VLA 主干网络。
    *   初始化一个记忆编码器（继承自 VLA 的视觉编码器），并引入一个可学习的查询向量（`q_mem`）。
    *   将历史帧输入记忆编码器，`q_mem` 通过注意力机制将一帧画面的所有 Patch Tokens 聚合成单个 Summary Token。
    *   将这些 Summary Tokens 拼接到当前观测序列后，输入冻结的 VLA。
    *   **关键点**：仅使用 VLA 原生的动作预测损失（Action Loss）来反向传播更新记忆编码器。这迫使压缩后的 Token 必须包含对“预测动作”有用的信息，而非仅仅用于“重建图像”。
2.  **阶段二：任务特定微调（VLA 微调）**
    *   冻结阶段一训练好的记忆编码器（Tokenizer）。
    *   利用 Tokenizer 离线处理目标任务的演示数据，将所有历史帧缓存为极小体积的 Memory Tokens。
    *   解冻 VLA 主干网络，将缓存的 Memory Tokens 拼接到当前输入中，使用少量目标任务数据进行全参数或高效微调。
3.  **实时推理部署**
    *   Tokenizer 作为独立进程高频运行，将新到达的观测帧实时压缩并推入记忆队列。
    *   VLA 在需要预测动作时，直接读取最新的记忆队列进行推理，两者互不阻塞。

**核心伪代码（Python 风格）**：

```python
import torch.nn as nn

class NativeMEM(nn.Module):
    def __init__(self, pretrained_vla):
        super().__init__()
        # 阶段1：初始化记忆编码器（复用VLA视觉编码器权重）
        self.memory_encoder = copy.deepcopy(pretrained_vla.vision_encoder)
        self.q_mem = nn.Parameter(torch.randn(1, 1, embed_dim)) # 可学习的查询向量
        self.w_mem = nn.Linear(embed_dim, vla_token_dim)        # 维度对齐投影
        self.b_mem = nn.Parameter(torch.randn(1, 1, vla_token_dim)) # 序列起始Token
        
        self.vla_backbone = pretrained_vla
        
    def tokenize_memory(self, history_frames):
        # history_frames: [B, T, V, C, H, W] (Batch, Time, Views, Channels, Height, Width)
        B, T, V = history_frames.shape[:3]
        frames = history_frames.view(B * T * V, C, H, W)
        
        # 提取视觉特征
        patch_tokens = self.memory_encoder.extract_features(frames) # [B*T*V, Num_Patches, Dim]
        
        # 极致压缩：使用 q_mem 将所有 patch tokens 压缩为 1 个 token
        q = self.q_mem.expand(B * T * V, -1, -1)
        # 简化的交叉注意力机制
        summary_tokens = cross_attention(query=q, key=patch_tokens, value=patch_tokens) 
        
        # 投影到 VLA 的 Token 维度
        memory_tokens = self.w_mem(summary_tokens) # [B*T*V, 1, VLA_Dim]
        memory_tokens = memory_tokens.view(B, T * V, -1)
        
        # 拼接起始符
        b_mem_expanded = self.b_mem.expand(B, -1, -1)
        return torch.cat([b_mem_expanded, memory_tokens], dim=1) # [B, 1 + T*V, VLA_Dim]

    def forward(self, current_obs, state, instruction, history_frames):
        # 1. 获取当前观测的 Tokens
        obs_tokens = self.vla_backbone.encode_obs(current_obs)
        prompt_tokens = self.vla_backbone.encode_prompt(instruction, state)
        
        # 2. 获取历史记忆 Tokens
        # 在阶段2微调时，这一步通常是离线计算并缓存好的
        memory_tokens = self.tokenize_memory(history_frames)
        
        # 3. 拼接完整序列
        input_sequence = torch.cat([obs_tokens, prompt_tokens, memory_tokens], dim=1)
        
        # 4. 预测动作
        action_logits = self.vla_backbone.predict_action(input_sequence)
        return action_logits
```

Pelican-VLA 0.5 建立在单一的 Qwen3-VL 4B 主干网络之上，不采用分离的推理和动作专家，而是通过统一的 Token 序列和精心设计的注意力掩码来实现感知、预测与控制的解耦与协同。

**核心架构与实验流程**：
1.  **统一序列构建**：输入序列被严格划分为四个连续段：
    *   `Prefix`：视觉-语言 Token（由 Qwen3-VL 编码当前场景与指令）。
    *   `Middle`：Cosmos 潜在特征 Token（编码历史帧，用于动态感知）。
    *   `Slots`：32 个可学习的推理槽 Token（核心信息瓶颈）。
    *   `Suffix`：本体感觉状态 Token + 噪声动作 Token（用于流匹配解码）。
2.  **注意力瓶颈（Bottleneck Mask）**：通过构建二维注意力掩码，彻底切断 `Suffix`（动作）直接访问 `Prefix` 和 `Middle`（感知）的路径。动作生成必须且只能通过读取 `Slots` 来获取视觉上下文。
3.  **多任务联合优化**：除了动作流匹配（Flow-matching）损失，模型还引入了未来帧生成损失（由 Slot 门控调节，确保 Slot 包含预测性动态信息）、Slot-语言对比对齐损失（InfoNCE，确保注意力受语言指令控制）以及 Slot 正交正则化（防止 Token 坍缩）。
4.  **缓存推理（Cached Inference）**：在实际部署时，庞大的 `Prefix` 和 `Middle` 仅需计算一次并缓存。高频的动作去噪循环仅在 `Suffix` 和 32 个 `Slots` 之间进行，极大提升了控制频率。

**核心底层逻辑伪代码**：
```python
def pelican_vla_forward(prefix, middle, slots, state, noisy_actions, instruction):
    # 1. 拼接完整序列
    Z = concat([prefix, middle, slots, state, noisy_actions])
    
    # 2. 构建课程注意力瓶颈掩码 (Curriculum Bottleneck Mask)
    # 阻断动作后缀直接读取密集视觉前缀的路径
    attention_mask = build_causal_mask(Z.length)
    attention_mask[suffix_indices, prefix_middle_indices] = 0 
    attention_mask[suffix_indices, slot_indices] = 1 # 仅允许通过 Slots 路由
    
    # 3. 通过共享 Transformer 主干
    hidden_states = qwen3_vl_backbone(Z, mask=attention_mask)
    
    # 4. 提取各分支输出
    slot_out = hidden_states[slot_indices]
    middle_out = hidden_states[middle_indices]
    action_out = hidden_states[action_indices]
    
    # 5. 计算多任务损失
    # 5.1 动作流匹配损失 (Flow-matching)
    loss_action = mse_loss(action_out, target_velocity)
    
    # 5.2 未来帧生成损失 (受 Slot 门控调制)
    slot_gate = sigmoid(linear(mean(slot_out)))
    gated_middle = middle_out * slot_gate
    loss_gen = mse_loss(decode(gated_middle), future_cosmos_latents)
    
    # 5.3 Slot-语言对比对齐损失 (InfoNCE)
    loss_task = info_nce_loss(mean(action_out), instruction)
    
    # 5.4 Slot 正交正则化 (防止特征同质化)
    loss_reg = orthogonality_penalty(slot_out)
    
    return loss_action + lambda_1*loss_gen + lambda_2*loss_task + lambda_3*loss_reg
```

### 第二模块：核心架构解释

本文的核心架构并非提出一个新的神经网络，而是提出一套针对世界模型的评估与认证流程（Admissibility Ladder）。该流程包含五个递进的层级，每一层都要求模型提供特定的客观证据。

1. L0 视觉生成质量 (Generation quality)：仅评估生成的视频在视觉和时间上是否连贯逼真。输入动作指令，输出视频，计算 FVD 等视觉分布差异指标。此层级不要求模型正确响应动作。
2. L1 动作鲁棒性 (Action-robust)：评估模型是否听从指挥。输入特定的动作指令（如左转、加速），模型生成的未来轨迹必须与该指令在几何和语义上匹配。通过提取生成视频中的轨迹并与输入指令计算位移误差（ADE）来验证。
3. L2 运行边界声明 (Envelope-declared)：评估模型是否知道自己的极限。模型必须声明其训练数据的分布边界和有效预测的时间长度。输入超出分布的动作或要求过长的预测时，模型必须能够检测并拒绝，而不是生成看似合理但物理错误的幻觉。
4. L3 故障可归因 (Failure-attributable)：评估模型在边界外发生错误时的责任划分能力。当闭环测试发生碰撞时，必须通过归因协议明确区分：是世界模型生成了违背物理规律的场景导致失败，还是被测试的策略本身发出了错误的动作。
5. L4 结论可转移 (Verdict-transfer-validated)：评估仿真与现实的对应关系。在声明的边界内，必须通过实验数据证明：在世界模型中测试通过的策略，部署到真实物理世界中也必然通过。

```python
    l0_visual_scores = []
    l1_action_errors = []
    l2_valid_horizons = []
    
    for data in test_dataset:
        real_video = data.video
        action_command = data.action # e.g., "turn_left", "accelerate"
        
        # 1. Generate future rollout conditioned on action
        generated_video = world_model.generate(action_command)
        
        # --- L0: Generation Quality ---
        # Compare visual fidelity regardless of action accuracy
        fvd_score = compute_frechet_video_distance(real_video, generated_video)
        l0_visual_scores.append(fvd_score)
        
        # --- L1: Action Robustness ---
        # Extract the actual trajectory the ego-vehicle took in the generated video
        executed_trajectory = trajectory_estimator.extract(generated_video)
        expected_trajectory = get_expected_trajectory(action_command)
        
        # Calculate Average Displacement Error (ADE)
        ade = compute_euclidean_distance(executed_trajectory, expected_trajectory)
        l1_action_errors.append(ade)
        
        # --- L2: Envelope Declared (Horizon Component) ---
        # Find the maximum time step (horizon) where ADE is within acceptable physical limits (e.g., staying in lane)
        max_valid_horizon = 0.0
        for t in range(len(executed_trajectory)):
            error_at_t = compute_distance_at_time(executed_trajectory[t], expected_trajectory[t])
            if error_at_t <= 1.8: # 1.8 meters is half a standard US lane width
                max_valid_horizon = time_step_to_seconds(t)
            else:
                break
        l2_valid_horizons.append(max_valid_horizon)
        
    return {
        "L0_FVD": mean(l0_visual_scores),
        "L1_ADE": mean(l1_action_errors),
        "L2_Horizon": mean(l2_valid_horizons)
    }
```

```python
        # 加载世界模型（实时蒸馏版或高精度基础版）

        self.pilot_agent = PilotAgent()
        self.director_agent = DirectorAgent()
        
        # 初始化全局世界状态
        self.global_state = initialize_world_state()

    def interaction_step(self, user_inputs):
        """单帧/单步交互逻辑"""
        
        # 1. Pilot Agent: 解析玩家输入，规划角色动作序列
        character_actions = self.pilot_agent.plan_and_execute(self.global_state, user_inputs)

        environmental_events = self.director_agent.synthesize_elements(self.global_state)

        next_state, rendered_frame = self.world_model.causal_predict(
            current_state=self.global_state,
            actions=character_actions,
            env_events=environmental_events
        )
        
        # 4. 状态更新
        self.global_state = next_state
        
        return rendered_frame
```

# 第二模块：核心架构解释

本研究并非提出新的网络架构，而是设计了一套严密的探测机制来解剖现有的 DreamerV3 (RSSM) 架构。

1. 受控环境生成：生成低维的真实状态（Closure），通过固定映射转为高维图像，并加入高方差视觉干扰项（Distractor）。这使得单纯的重建损失必然去拟合干扰项而忽略真实状态。
2. 架构阻断设计：在标准的 RSSM 中，状态分为确定性状态 $h$ 和随机状态 $z$。作者增加了一个辅助查询头（Query Head），并强制该头仅读取随机潜变量 $z$，切断了 $h$ 的信息通路。这确保了查询目标只能强迫 $z$ 去学习特征。
3. 目标维度扫描：在训练阶段，改变查询头需要预测的目标维度 $d$（从 1 到 4）。
4. 线性探针评估：冻结训练好的模型，使用一个线性回归器从 $z$ 中预测真实的 Closure，计算恢复的方差比例（$R^2$）和安装的秩（Installed Rank）。

```python
import torch
import torch.nn as nn
from sklearn.linear_model import Ridge

class ControlledRSSM(nn.Module):
    def __init__(self, latent_dim, target_dim):
        super().__init__()
        self.encoder = Encoder()
        self.dynamics = Dynamics()
        self.recon_head = Decoder()
        
        # 核心设计：查询头只接收随机潜变量 z，严格排除确定性状态 h
        # 目标维度 target_dim 决定了施加在 z 上的监督信号维度
        self.query_head = nn.Linear(latent_dim, target_dim)

    def forward(self, obs, action, prev_h, prev_z):
        # 1. 状态推演
        h, z = self.dynamics(prev_h, prev_z, action, self.encoder(obs))
        
        # 2. 重建观测 (由于环境设计，此分支会被高方差干扰项吸引)
        recon_obs = self.recon_head(h, z)
        
        # 3. 预测目标 (迫使 z 学习任务相关的 Closure)
        pred_target = self.query_head(z)
        
        return recon_obs, pred_target, h, z

def evaluate_installed_rank(trained_z_features, ground_truth_closure, null_threshold):
    # 冻结模型后，使用线性探针从 z 中预测真实的 closure
    probe = Ridge().fit(trained_z_features, ground_truth_closure)
    
    # 计算每个维度的 R^2 得分
    r_squared_per_dim = compute_r2_per_dim(probe, trained_z_features, ground_truth_closure)
    
    # 核心结论验证：计算 R^2 超过重建基线阈值的维度数量
    # 实验表明：installed_rank 严格等于训练时的 target_dim
    installed_rank = sum(r_squared_per_dim > null_threshold)
    
    return installed_rank
```

1. **多模态对齐与特征提取**：将图像、自然语言指令和本体感受状态（如关节角度）输入预训练的 VLM，提取富含语义和空间信息的隐层表征。
2. **连续动作分块生成（Action Chunking）**：放弃逐帧预测，采用流匹配（Flow-matching）机制。以 VLM 的隐层表征为条件，将高斯噪声迭代去噪，一次性生成未来 $H$ 步的高维连续动作块（如双臂的 16 维 $\times$ 50 步）。
3. **双系统高频执行（Dual-System Execution）**：高层 VLM 以低频（如 10Hz）进行子任务分解与推理，底层动作头以高频（如 50Hz-100Hz）执行动作块，并通过时间集成（Temporal Ensembling）平滑重叠的动作块。
4. **自主强化学习（RECAP）**：模型在真实环境中自主尝试，由另一个 VLM 充当奖励函数评估成功与否，将成功的轨迹加入训练集进行微调，实现自我进化。

```python
import torch.nn as nn

class StateOfTheArtVLA(nn.Module):
    def __init__(self, vlm_backbone, flow_action_head, chunk_size=50, action_dim=16):
        super().__init__()
        self.vlm = vlm_backbone          # e.g., PaLIGemma (Slow reasoning)
        self.action_head = flow_action_head # Flow-matching head (Fast execution)
        self.chunk_size = chunk_size     # H=50 steps
        self.action_dim = action_dim     # d_a=16 for bimanual (8 per arm)
        
    def forward(self, image, instruction, proprioception, num_flow_steps=10):
        # 1. Extract semantic and spatial features (Low frequency)
        vlm_features = self.vlm(image, instruction, proprioception)
        
        # 2. Initialize pure noise for the action chunk
        noisy_action_chunk = torch.randn(1, self.chunk_size, self.action_dim)
        
        # 3. Flow-matching iterative denoising (High frequency)
        # Solves the ODE to transport noise to the action distribution
        action_chunk = noisy_action_chunk
        dt = 1.0 / num_flow_steps
        for step in range(num_flow_steps):
            t = step * dt
            # Predict velocity field conditioned on VLM features
            velocity = self.action_head(action_chunk, t, vlm_features)
            action_chunk = action_chunk + velocity * dt
            
        return action_chunk

    """

            # Add successful autonomous trials to buffer
            replay_buffer.add(trajectory)
```

### 第二模块：核心架构解释

该论文的系统架构由三个高度专业化的 LLM/VLM 智能体构成，形成了一个完整的闭环控制流：

1.  **Planning Agent (规划智能体 - 语义推理与任务分配):** 
    接收自然语言指令和粗粒度场景描述，生成有向无环图（DAG）。它不仅分解任务，还根据异构机器人的能力（如移动底盘 vs 固定机械臂）分配任务，并能识别哪些子任务可以并行执行。
2.  **Manipulation Agent (操作智能体 - 物理动作接地):** 
    作为具身执行者，它不依赖单一的端到端网络，而是动态调用工具链。通过 VLM 进行目标检测 -> SAM 进行像素级分割 -> 视觉提示（Visual Prompting）提取语义关键点 -> AnyGrasp 生成 6-DoF 抓取位姿，最终映射到预定义的底层动作图元库（如 Grasp, Move, Rotate）。它还配备了长短记忆机制以减少重复推理。
3.  **Verification Agent (验证智能体 - 局部监控与分层恢复):** 
    系统的核心护城河。通过对比动作前后的视觉状态，判断操作是否成功。若失败，触发分层恢复：
    *   **局部恢复 (Local Recovery):** 针对执行级错误（如抓取滑落），直接在操作智能体层面生成纠正动作。
    *   **全局恢复 (Global Recovery):** 针对可行性错误（如目标超出当前机器人工作空间），将错误信息反馈给规划智能体，触发全局重新分配（如调度移动机器人去协助）。

```python
def execute_multi_robot_task(instruction, scene_obs):
    # 1. 规划智能体：生成带有依赖关系和分配信息的任务图 (DAG)
    task_graph = PlanningAgent.decompose_and_allocate(instruction, scene_obs)
    
    while not task_graph.is_empty():
        # 获取当前可并行执行的子任务
        sub_tasks = task_graph.get_parallel_executable_tasks()
        
        for task in sub_tasks:
            robot = task.assigned_robot
            
            # 2. 操作智能体：调用视觉工具链，将语义转化为底层动作图元
            action_primitives = ManipulationAgent.ground_to_primitives(task, scene_obs)
            
            for action in action_primitives:
                pre_obs = robot.get_visual_state()
                robot.execute_primitive(action)
                post_obs = robot.get_visual_state()
                
                # 3. 验证智能体：闭环视觉验证
                is_success, error_type = VerificationAgent.verify(task, pre_obs, post_obs)
                
                if not is_success:
                    if error_type == "EXECUTION_ERROR":
                        # 局部恢复：例如抓取失败，原地重试或微调
                        recovery_actions = VerificationAgent.generate_local_recovery(history)
                        robot.execute_primitive(recovery_actions)
                    
                    elif error_type == "FEASIBILITY_ERROR":
                        # 全局恢复：例如物体不在工作空间，请求其他机器人协助
                        task_graph = PlanningAgent.global_replan(task_graph, error_type, scene_obs)
                        break # 中断当前并行执行，基于新任务图重新开始
```

### 第二模块：核心架构解释

PriGo 的运行流程分为离线训练分类器与在线测试时引导两个阶段。其核心逻辑在于建立连续动作空间与离散基元空间之间的可微映射。

1. **基元定义与自动标注**：基于 7-DoF 动作的平移幅度、旋转幅度以及夹爪开合度，设定硬性运动学阈值，将动作空间划分为 8 种基础基元（如 grasp, push, rotation 等）。利用该规则对演示数据集进行无人工干预的自动标注。
2. **基元预测网络 (PANet)**：使用 DINOv2 提取视觉特征，T5 提取文本特征，通过 Q-Former 融合后输入 MLP，输出当前观测下下一步动作的基元概率分布（软标签）。
3. **可微基元引导**：在推理阶段，将基座策略（Diffusion 或 Flow）生成的连续动作通过带有温度系数的 Softmax 函数映射为软基元分布。计算 PANet 预测分布与动作诱导分布之间的交叉熵损失。
4. **动作修正**：计算上述交叉熵损失对生成动作的梯度，在 Diffusion 的去噪步或 Flow 的欧拉积分步中，沿着梯度下降的方向修正动作，使其逼近目标基元流形。

**核心伪代码实现**：

```python
import torch
import torch.nn.functional as F

def compute_soft_primitive_distribution(action, tau=0.1):
    """
    将连续动作映射为软基元概率分布 (对应论文 Definition 3.2)
    action: [batch, 7] (x, y, z, roll, pitch, yaw, gripper)
    """
    # 提取运动学特征
    trans_mag = torch.norm(action[..., :3], dim=-1)
    rot_mag = torch.norm(action[..., 3:6], dim=-1)
    gripper_diff = action[..., 6] - get_previous_gripper()
    x_dir = action[..., 0]
    
    # 构建可微得分函数 f(a)
    scores = torch.stack([
        -(trans_mag + rot_mag + torch.abs(gripper_diff)), # idle
        -gripper_diff,                                    # grasp
        gripper_diff,                                     # release
        x_dir,                                            # push
        -x_dir,                                           # pull
        (rot_mag - trans_mag),                            # rotation
        x_dir + rot_mag,                                  # push+rotation
        -x_dir + rot_mag                                  # pull+rotation
    ], dim=-1)
    
    # 温度缩放的 softmax 输出概率分布
    return F.softmax(scores / tau, dim=-1)

def prigo_guided_inference(observation, base_policy, panet, num_steps, eta):
    """
    PriGo 测试时引导推理循环 (以 Diffusion 为例)
    """
    # 1. PANet 预测目标基元分布 (无需梯度)
    with torch.no_grad():
        target_prob = panet(observation) # [batch, 8]
        
    # 2. 初始化纯噪声动作
    action_t = torch.randn(batch_size, action_dim)
    
    for t in reversed(range(num_steps)):
        # 允许对当前动作求导
        action_t.requires_grad_(True)
        
        # 3. 基座策略预测去噪方向 (或 Flow 的速度场)
        noise_pred = base_policy(action_t, observation, t)
        
        # 4. 估算无噪声动作 a_hat_0
        a_hat_0 = estimate_clean_action(action_t, noise_pred, t)
        
        # 5. 计算动作诱导的基元分布
        induced_prob = compute_soft_primitive_distribution(a_hat_0)
        
        # 6. 计算交叉熵损失 (Primitive Guidance Loss)
        loss_pg = -torch.sum(target_prob * torch.log(induced_prob + 1e-8), dim=-1).mean()
        
        # 7. 计算梯度
        grad_a = torch.autograd.grad(loss_pg, action_t)[0]
        
        # 8. 执行标准的去噪更新
        action_t_minus_1 = standard_denoising_step(action_t, noise_pred, t)
        
        # 9. 应用基元引导修正动作
        action_t = action_t_minus_1 - eta * grad_a
        
        action_t = action_t.detach()
        
    return action_t
```

### 第二模块：核心架构解释

GemNav 的核心思想是将机器人的连续物理控制降维打击为纯粹的自然语言生成任务。其架构与数据流转流程如下：

1.  **输入构建 (Prompt Construction):** 接收当前相机图像、目标（目标图像或 2D 局部坐标）。图像通过完全冻结的 Gemma-4 视觉塔处理。目标坐标被转换为与输出相同的离散 Token 序列。所有输入被拼接为标准的 LLM 用户提示词（Prompt）。
2.  **动作空间离散化 (Action Tokenization):** 摒弃连续回归头。将连续的 2D 局部坐标系路点 (x, y) 在 [-15m, 15m] 范围内均匀量化为 64 个 Bin，占用 LLM 词表中的保留位（`<unusedN>`）。同时引入 `<goal_reached>` 和 `<goal_unreachable>` 作为分类停止信号。
3.  **模型推理 (Model Inference):** 视觉塔完全冻结，仅对语言塔的线性层应用 LoRA。模型像生成文本一样，自回归生成包含 8 个路点的轨迹序列（共 18 个 Token）或直接输出停止信号。
4.  **混合损失优化 (Hybrid Loss Optimization):** 基础损失为标准的 Token 级别交叉熵损失（CE）。为了弥补离散化带来的空间距离信息丢失（即相邻 Bin 的物理距离近，但 CE 惩罚相同），引入基于 Softmax 期望的软解码回归辅助损失（Soft-decoded auxiliary loss），对偏离真实物理坐标的预测施加连续性惩罚。

**核心伪代码实现 (Python 风格):**

```python
import torch
import torch.nn.functional as F

class GemNavLoss(torch.nn.Module):
    def __init__(self, vocab_size, num_bins=64, max_dist=15.0, lambda_aux=0.1):
        super().__init__()
        self.vocab_size = vocab_size
        self.num_bins = num_bins
        self.lambda_aux = lambda_aux
        
        # 构建 Bin 的物理中心坐标映射
        # bin_centers shape: (num_bins,)
        bin_width = (2 * max_dist) / num_bins
        self.bin_centers = torch.linspace(-max_dist + bin_width/2, 
                                          max_dist - bin_width/2, 
                                          num_bins)
        
        # 假设 64 个 Bin 对应的 Token ID 在词表中的起始位置
        self.bin_token_start_idx = 100000 

    def forward(self, logits, target_tokens, target_continuous_coords):
        """
        logits: (batch, seq_len, vocab_size) - LLM 原始输出
        target_tokens: (batch, seq_len) - 离散化后的 GT Token IDs
        target_continuous_coords: (batch, seq_len) - 真实的连续物理坐标 (x 或 y)
        """
        # 1. 标准的因果语言模型交叉熵损失
        loss_ce = F.cross_entropy(logits.view(-1, self.vocab_size), 
                                  target_tokens.view(-1), 
                                  ignore_index=-100)
        
        # 2. 软解码辅助回归损失 (Soft-decoded auxiliary loss)
        # 仅提取对应 64 个 Value-bin 的 logits
        bin_logits = logits[:, :, self.bin_token_start_idx : self.bin_token_start_idx + self.num_bins]
        
        # 将 logits 转化为概率分布
        bin_probs = F.softmax(bin_logits, dim=-1) # (batch, seq_len, num_bins)
        
        # 计算期望物理坐标 (Soft-decode): 概率分布与 Bin 中心的内积
        # expected_coords shape: (batch, seq_len)
        expected_coords = torch.sum(bin_probs * self.bin_centers.to(logits.device), dim=-1)
        
        # 计算与真实连续坐标的 MSE 损失
        # 注意：实际代码中会通过 mask 过滤掉非路点 Token（如 stop 信号）
        loss_aux = F.mse_loss(expected_coords, target_continuous_coords)
        
        # 3. 总损失
        total_loss = loss_ce + self.lambda_aux * loss_aux
        
        return total_loss
```

### 第二模块：核心架构解释

CARLA-GS 的整体架构遵循 Real-Sim-Real（真实-仿真-真实）的闭环范式，具体分为三个核心流程：

**1. 几何一致性场景重建 (Representation)**
基于真实驾驶数据（如 Waymo 数据集），采用 Street Gaussians 作为基础架构进行动静分离的 3DGS 重建。为了解决车载相机稀疏视角导致的表面凹凸不平问题，引入了三种几何约束：Flattening 约束（促使高斯椭球扁平化）、Normal 约束（对齐深度模型提取的法线）以及 Geometry 约束（保证局部表面平滑）。

**2. LLM 驱动的风险推理与轨迹生成 (Reasoning)**
构建了基于 Chain-of-Thought 的多智能体 LLM 架构。首先在自车周围定义四个碰撞区域（前、后、左、右）。LLM 接收场景中所有车辆的历史轨迹状态，评估风险，选择一个对抗车辆（Adversarial Vehicle）和一个目标碰撞区域，最终生成一条由离散路点（Waypoints）组成的意图级轨迹。

**3. 物理仿真与回投渲染 (Physics Simulation)**
将 LLM 生成的粗糙路点导入 CARLA 仿真器。利用 CARLA 内置的 PID 控制器驱动目标车辆追踪这些路点，从而生成符合车辆运动学和动力学约束的平滑轨迹。随后，将仿真得到的车辆位姿（Pose）逐帧更新回 3DGS 场景中。针对新视角下可能出现的渲染伪影，使用 SAM-3D 重建的高质量 3D 资产替换原有的高斯车辆模型，最终渲染出逼真的 Corner-Case 视频。

```python
    gaussian_scene = StreetGaussians()

        losses=[L_color, L_flat, L_normal, L_geo]
    )

    ego_state, background_vehicles = extract_states(real_driving_data)

    target_vehicle_id, collision_zone, waypoints = LLM_Agent(

        background_vehicles, 
        target_behavior
    )

        simulated_trajectory.append(new_pose)
        
    # Stage 4: Back-Projection & Rendering

        # Replace vehicle with SAM-3D asset to avoid rendering artifacts
```

1. 提出了首个将视觉表征、语义推理与物理仿真显式解耦的自动驾驶 Corner-Case 生成框架。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？
