### 第二模块：核心架构解释

RIFT 的核心逻辑是将“未来特征的生产”与“未来特征的消费”解耦。在部署时，它抛弃了视频扩散模型的多步去噪，转而使用一次前向传播完成 Cache 的预填充。

**模型架构与运行流程：**

1. **输入构建**：提取当前帧的观测特征 $f_0(o)$，并拼接一组固定数量的可学习预期 Tokens $E$。
2. **单次前向 Cache 预填充 (Prefill)**：将拼接后的序列输入共享的 Video Backbone。预期 Tokens 会通过自注意力机制与当前帧交互，并在各个 Transformer 层生成对应的 Key 和 Value。提取这些 K/V，形成一个固定的未来 K/V Cache。
3. **动作去噪 (Action Denoising)**：动作专家 (Action Expert) 在进行多步 Flow-matching 去噪生成动作时，不再依赖每一步更新的视频特征，而是反复通过交叉注意力读取上述固定的未来 K/V Cache。
4. **训练机制**：采用双分支前向。第一分支做原生视频预测以维持动力学理解；第二分支将预期 Tokens 注入网络，利用条件流匹配 (Conditional FM) 损失强制预期 Tokens 的表征对齐真实的未来 Latent 分布，同时基于生成的 Cache 训练动作专家。

### 第二模块：核心架构解释

G0.5 的核心架构摒弃了复杂的双流或扩散模型设计，回归了最纯粹的大语言模型范式。其处理流程与实验架构可拆解为以下四个关键环节：

1.  **视觉记忆模块 (Visual Memory Module)**：模型不依赖单帧图像，而是通过视觉编码器提取多秒历史图像的时空特征，为后续决策提供连续的物理世界上下文。
2.  **跨实体动作分词器 (Cross-embodiment Action Tokenizer)**：这是将连续控制转化为语言建模的关键。该模块通过可学习的机制，将异构机器人（不同自由度、不同控制频率）的连续动作空间（如关节角度、末端位姿）离散化，映射到一个共享的动作词表中。
3.  **原生思维链流 (Native Chain-of-Thought Stream)**：在输入序列中，模型强制将任务分解（Task Decomposition）、目标接地（Object Grounding）、动作提示（Action Hints）等文本推理过程与动作 Token 混合排列。
4.  **单一自回归解码器 (Single Autoregressive Decoder)**：接收视觉特征、文本指令和历史 Token，使用标准的 Next-token Prediction（交叉熵损失）目标，同时预测推理文本和动作 Token。推理与动作共享同一套网络权重。

### 第二模块：核心架构解释

MiDAS (Minimal-Data Adaptation Strategy) 的核心逻辑分为两个阶段：先给方向，再练精度。

**Stage I: 行为克隆锚定 (Behavior Cloning Anchor)**
使用单次或极少量演示数据，通过 LoRA 对预训练 VLA（如 $\pi_{0.5}$）的视觉骨干和动作头进行微调。这一步不求完美，只求让机器人能粗略地走向目标物体并尝试执行任务，从而在后续探索中能偶尔触碰稀疏奖励。

**Stage II: 在线残差强化学习 (Online Residual RL)**
冻结 Stage I 得到的 VLA 模型 $\pi_{base}^K$，将其作为特征提取器和动作提议器。引入一个轻量级的残差 Actor-Critic 架构进行在线交互学习：
1. **特征复用**：Critic 和 Actor 直接接收 VLA 骨干输出的降维特征，极大地提升了样本效率。
2. **动作生成**：Actor 接收 VLA 提议的动作块（Action Chunk），直接输出一个全新的完整动作块，而不是在原动作上加一个微小的 $\Delta$。这使得策略能够探索到 VLA 原始分布之外的高价值区域。
3. **成功平衡 (Success Balancing)**：由于初始策略成功率极低（2-5%），维护一个专门存储成功轨迹的 Buffer。在 Critic 和 Actor 更新时，强制从该 Buffer 中过采样（如 20%），防止价值网络被海量的失败探索数据带偏。
4. **PA-RL 提炼**：采用 Policy-Agnostic RL 范式，Actor 生成多个候选动作，Critic 选出高价值的“精英动作”并进行梯度上升优化，最后 Actor 通过蒸馏损失向这些优化后的动作靠拢。

**核心伪代码实现 (Python 风格)**：

```python
def midas_stage_2_online_rl(vla_base, env, warmup_buffer, num_episodes):
    # vla_base: 冻结的经过 Stage I 微调的 VLA 模型
    # warmup_buffer: 包含 Demo 和初始 rollout 的预热经验池
    
    actor = ResidualActor()
    critic_ensemble = CriticEnsemble(num_q=10)
    
    # 初始化经验池
    replay_buffer = ReplayBuffer()
    replay_buffer.add(warmup_buffer)
    success_buffer = SuccessBuffer()
    success_buffer.add(warmup_buffer.get_successful_trajectories())
    
    # Offline Warmup: 预热 Actor 模仿 base，预热 Critic 评估 base
    warmup_actor_critic(actor, critic_ensemble, warmup_buffer)
    
    for episode in range(num_episodes):
        state = env.reset()
        episode_transitions = []
        
        # 收集数据
        while not done:
            # 1. VLA 提取特征并提议基础动作
            vla_features = vla_base.extract_features(state)
            a_base = vla_base.propose_action(state)
            
            # 2. 残差 Actor 生成执行动作
            a_exec = actor.sample(vla_features, a_base)
            
            next_state, reward, done = env.step(a_exec)
            episode_transitions.append((state, a_base, a_exec, reward, next_state))
            state = next_state
            
        # 更新经验池
        replay_buffer.add(episode_transitions)
        if reward > 0: # 稀疏奖励任务成功
            success_buffer.add(episode_transitions)
            
        # PA-RL 更新逻辑
        for _ in range(gradient_steps):
            # Success Balancing: 混合采样
            batch = sample_mixed_batch(replay_buffer, success_buffer, success_ratio=0.2)
            
            # 更新 Critic (TD Learning)
            critic_loss = compute_td_loss(critic_ensemble, batch)
            critic_ensemble.update(critic_loss)
            
            # 更新 Actor (PA-RL 提炼)
            # a. 采样候选动作
            candidates = actor.sample_multiple(batch.vla_features, batch.a_base, num_samples=16)
            # b. Critic 评估并选出精英
            q_values = critic_ensemble.evaluate(batch.vla_features, candidates)
            elites = select_top_k(candidates, q_values, k=8)
            # c. 对精英动作进行梯度上升 (针对 Q 值)
            refined_elites = gradient_ascent_on_q(elites, critic_ensemble, steps=30)
            # d. Actor 蒸馏
            actor_loss = distillation_loss(actor, batch.vla_features, batch.a_base, refined_elites)
            actor.update(actor_loss)
            
    return actor
```

问题背景：世界动作模型（WAMs）通过预测未来的视频帧来指导机器人动作生成。然而，在部署阶段，迭代式的视频展开（Video Rollout）会带来极高的计算延迟，严重阻碍了机器人的实时闭环控制。

技术方法：作者首先通过闭环干预实验发现，部分模型在执行时并不需要动态演变的完整轨迹，仅需重放固定的最终未来K/V缓存即可保持极高的成功率。基于此，作者提出RIFT（Rollout-free Imagination via Future Tokens）。该方法利用可学习的“预期Token”（Anticipation Tokens），在单次骨干网络前向传播中直接构建完整的未来K/V缓存，从而完全绕过迭代视频生成过程，同时保留了原有的未来读取接口。

研究意义：该研究成功将世界模型中“未来缓存的消耗”与“生产”解耦，证明了无需迭代视频生成也能实现基于未来表征的动作条件化。这为具身智能中基于世界模型的策略（如VLA）提供了一种极为高效的实时部署范式，极大地推动了世界模型在真实机器人上的落地应用。

### 第二模块：核心架构解释

RIFT 的核心逻辑是将“未来特征的生产”与“未来特征的消费”解耦。在部署时，它抛弃了视频扩散模型的多步去噪，转而使用一次前向传播完成 Cache 的预填充。

**模型架构与运行流程：**

1. **输入构建**：提取当前帧的观测特征 $f_0(o)$，并拼接一组固定数量的可学习预期 Tokens $E$。
2. **单次前向 Cache 预填充 (Prefill)**：将拼接后的序列输入共享的 Video Backbone。预期 Tokens 会通过自注意力机制与当前帧交互，并在各个 Transformer 层生成对应的 Key 和 Value。提取这些 K/V，形成一个固定的未来 K/V Cache。
3. **动作去噪 (Action Denoising)**：动作专家 (Action Expert) 在进行多步 Flow-matching 去噪生成动作时，不再依赖每一步更新的视频特征，而是反复通过交叉注意力读取上述固定的未来 K/V Cache。
4. **训练机制**：采用双分支前向。第一分支做原生视频预测以维持动力学理解；第二分支将预期 Tokens 注入网络，利用条件流匹配 (Conditional FM) 损失强制预期 Tokens 的表征对齐真实的未来 Latent 分布，同时基于生成的 Cache 训练动作专家。

**核心逻辑伪代码 (Python 风格)：**

```python
class RIFT_Model(nn.Module):
    def __init__(self, video_backbone, action_expert, num_anticipation_tokens, hidden_dim):
        super().__init__()
        self.video_backbone = video_backbone
        self.action_expert = action_expert
        # 可学习的预期 Tokens
        self.anticipation_tokens = nn.Parameter(torch.randn(1, num_anticipation_tokens, hidden_dim))
        
    def forward_deploy(self, current_obs, instruction):
        """部署阶段：无 Rollout，单次前向生成 Cache"""
        # 1. 提取当前帧特征
        f0 = self.video_backbone.extract_features(current_obs, instruction)
        
        # 2. 拼接预期 Tokens
        batch_size = f0.shape[0]
        E = self.anticipation_tokens.expand(batch_size, -1, -1)
        input_sequence = torch.cat([f0, E], dim=1)
        
        # 3. 单次前向预填充，提取各层的 K/V Cache
        # 注意：这里不进行视频的扩散去噪，只做一次 forward
        fixed_future_kv_cache = self.video_backbone.get_kv_cache(input_sequence)
        
        # 4. 动作生成：动作专家在多步去噪中复用同一个固定的 Cache
        action = torch.randn(batch_size, action_horizon, action_dim) # 初始噪声
        for t in flow_matching_steps:
            # 动作专家只读取 fixed_future_kv_cache，不更新它
            action_velocity = self.action_expert(action, t, fixed_future_kv_cache)
            action = euler_step(action, action_velocity, t)
            
        return action

    def forward_train(self, current_obs, future_obs, instruction, action_gt):
        """训练阶段：双分支前向"""
        # 分支一：原生视频流匹配训练 (略)
        loss_vid = compute_video_flow_matching_loss(...)
        
        # 分支二：部署匹配的动作训练与条件流匹配
        f0 = self.video_backbone.extract_features(current_obs, instruction)
        E = self.anticipation_tokens.expand(batch_size, -1, -1)
        input_sequence = torch.cat([f0, E], dim=1)
        
        # 获取预期的隐状态和 Cache
        anticipation_states, future_kv_cache = self.video_backbone.forward_with_cache(input_sequence)
        
        # 动作损失：基于生成的 Cache 预测动作
        loss_act = compute_action_loss(self.action_expert, action_gt, future_kv_cache)
        
        # 辅助损失：强制预期状态对齐真实的未来分布 (Conditional FM)
        true_future_latents = encode(future_obs)
        loss_fm = compute_conditional_fm_loss(anticipation_states, true_future_latents)
        
        return loss_vid + loss_act + loss_fm
```

### 第二模块：核心架构解释

G0.5 的核心架构摒弃了复杂的双流或扩散模型设计，回归了最纯粹的大语言模型范式。其处理流程与实验架构可拆解为以下四个关键环节：

1.  **视觉记忆模块 (Visual Memory Module)**：模型不依赖单帧图像，而是通过视觉编码器提取多秒历史图像的时空特征，为后续决策提供连续的物理世界上下文。
2.  **跨实体动作分词器 (Cross-embodiment Action Tokenizer)**：这是将连续控制转化为语言建模的关键。该模块通过可学习的机制，将异构机器人（不同自由度、不同控制频率）的连续动作空间（如关节角度、末端位姿）离散化，映射到一个共享的动作词表中。
3.  **原生思维链流 (Native Chain-of-Thought Stream)**：在输入序列中，模型强制将任务分解（Task Decomposition）、目标接地（Object Grounding）、动作提示（Action Hints）等文本推理过程与动作 Token 混合排列。
4.  **单一自回归解码器 (Single Autoregressive Decoder)**：接收视觉特征、文本指令和历史 Token，使用标准的 Next-token Prediction（交叉熵损失）目标，同时预测推理文本和动作 Token。推理与动作共享同一套网络权重。

### 第二模块：核心架构解释

MiDAS (Minimal-Data Adaptation Strategy) 的核心逻辑分为两个阶段：先给方向，再练精度。

**Stage I: 行为克隆锚定 (Behavior Cloning Anchor)**
使用单次或极少量演示数据，通过 LoRA 对预训练 VLA（如 $\pi_{0.5}$）的视觉骨干和动作头进行微调。这一步不求完美，只求让机器人能粗略地走向目标物体并尝试执行任务，从而在后续探索中能偶尔触碰稀疏奖励。

**Stage II: 在线残差强化学习 (Online Residual RL)**
冻结 Stage I 得到的 VLA 模型 $\pi_{base}^K$，将其作为特征提取器和动作提议器。引入一个轻量级的残差 Actor-Critic 架构进行在线交互学习：
1. **特征复用**：Critic 和 Actor 直接接收 VLA 骨干输出的降维特征，极大地提升了样本效率。
2. **动作生成**：Actor 接收 VLA 提议的动作块（Action Chunk），直接输出一个全新的完整动作块，而不是在原动作上加一个微小的 $\Delta$。这使得策略能够探索到 VLA 原始分布之外的高价值区域。
3. **成功平衡 (Success Balancing)**：由于初始策略成功率极低（2-5%），维护一个专门存储成功轨迹的 Buffer。在 Critic 和 Actor 更新时，强制从该 Buffer 中过采样（如 20%），防止价值网络被海量的失败探索数据带偏。
4. **PA-RL 提炼**：采用 Policy-Agnostic RL 范式，Actor 生成多个候选动作，Critic 选出高价值的“精英动作”并进行梯度上升优化，最后 Actor 通过蒸馏损失向这些优化后的动作靠拢。

**核心伪代码实现 (Python 风格)**：

```python
def midas_stage_2_online_rl(vla_base, env, warmup_buffer, num_episodes):
    # vla_base: 冻结的经过 Stage I 微调的 VLA 模型
    # warmup_buffer: 包含 Demo 和初始 rollout 的预热经验池
    
    actor = ResidualActor()
    critic_ensemble = CriticEnsemble(num_q=10)
    
    # 初始化经验池
    replay_buffer = ReplayBuffer()
    replay_buffer.add(warmup_buffer)
    success_buffer = SuccessBuffer()
    success_buffer.add(warmup_buffer.get_successful_trajectories())
    
    # Offline Warmup: 预热 Actor 模仿 base，预热 Critic 评估 base
    warmup_actor_critic(actor, critic_ensemble, warmup_buffer)
    
    for episode in range(num_episodes):
        state = env.reset()
        episode_transitions = []
        
        # 收集数据
        while not done:
            # 1. VLA 提取特征并提议基础动作
            vla_features = vla_base.extract_features(state)
            a_base = vla_base.propose_action(state)
            
            # 2. 残差 Actor 生成执行动作
            a_exec = actor.sample(vla_features, a_base)
            
            next_state, reward, done = env.step(a_exec)
            episode_transitions.append((state, a_base, a_exec, reward, next_state))
            state = next_state
            
        # 更新经验池
        replay_buffer.add(episode_transitions)
        if reward > 0: # 稀疏奖励任务成功
            success_buffer.add(episode_transitions)
            
        # PA-RL 更新逻辑
        for _ in range(gradient_steps):
            # Success Balancing: 混合采样
            batch = sample_mixed_batch(replay_buffer, success_buffer, success_ratio=0.2)
            
            # 更新 Critic (TD Learning)
            critic_loss = compute_td_loss(critic_ensemble, batch)
            critic_ensemble.update(critic_loss)
            
            # 更新 Actor (PA-RL 提炼)
            # a. 采样候选动作
            candidates = actor.sample_multiple(batch.vla_features, batch.a_base, num_samples=16)
            # b. Critic 评估并选出精英
            q_values = critic_ensemble.evaluate(batch.vla_features, candidates)
            elites = select_top_k(candidates, q_values, k=8)
            # c. 对精英动作进行梯度上升 (针对 Q 值)
            refined_elites = gradient_ascent_on_q(elites, critic_ensemble, steps=30)
            # d. Actor 蒸馏
            actor_loss = distillation_loss(actor, batch.vla_features, batch.a_base, refined_elites)
            actor.update(actor_loss)
            
    return actor
```

# 第二模块：核心架构解释

StellaVLA 的核心逻辑分为离线数据处理、训练阶段和推理阶段三个部分：

**1. 离线结构化上下文提取 (Offline Pipeline)**
利用现成的 VLM（如 Qwen3-VL）作为标注器，零人工成本地将原始专家轨迹转化为结构化文本。
- **语义推理 (Semantic Rationale)**：将长轨迹分割为多个离散片段，并为每个片段生成高级子目标描述（如“抓住蓝色杯子的把手”）。
- **运动学推理 (Kinematic Rationale)**：通过确定性映射，将连续动作转化为 3D 空间位移文本和 2D 图像平面投影文本。

**2. 并行双重训练 (Parallel Dual-Training)**
模型主干为 Qwen3-VL，输入为“检索到的结构化演示 + 当前指令 + 当前观测”。主干网络提取共享隐式表征后，接入两个严格并行的专家头：
- **动作专家 (Action Expert)**：轻量级 MLP，回归预测未来的连续动作块（Action Chunk）。
- **空间语言专家 (Spatial-Language Expert)**：自回归语言头，预测当前步骤的子目标及 2D/3D 运动文本。
通过联合损失函数，强迫模型在预测物理动作的同时，内化其背后的空间与语义逻辑。

**3. 非对称推理与缓存 (Asymmetric Inference and Caching)**
为了满足机器人高频控制的低延迟要求，推理阶段彻底抛弃了耗时的自回归语言生成。
- 剥离空间语言专家，仅通过动作专家输出连续控制指令。
- 将检索到的结构化演示作为静态前缀（Prefix），仅在第一步计算并锁定其 KV Cache。后续步骤仅需前向传播当前单帧观测，将单步延迟压缩至约 91ms。

```python
    # Dual Objective Optimization
    loss_act = L1_loss(pred_action_chunk, target_action_chunk)
    loss_lang = CrossEntropy_loss(pred_rationale_text, target_rationale_text)
    
    total_loss = loss_act + lambda_weight * loss_lang
    total_loss.backward()

# 3. Asymmetric Inference Step
def inference_step(current_obs, instruction, retrieved_demo, kv_cache=None):
    if kv_cache is None:
        # Compute and pin KV cache for the static demonstration prefix ONCE
        demo_prompt = format_demo_prefix(retrieved_demo, instruction)
        kv_cache = vlm_backbone.compute_cache(demo_prompt)
    
    # Fast forward: only process the current observation using the pinned cache
    hidden_states = vlm_backbone(current_obs, past_key_values=kv_cache)
    
    # Action-only execution: completely bypass the language expert
    action_chunk = action_expert_mlp(hidden_states)
    
    return action_chunk, kv_cache
```

### 第二模块：核心架构解释

ForeWAM 的核心架构解耦了“预测未来动态”与“生成未来像素”这两个过程。其工作流程分为两条互补的上下文路径：分布式视觉上下文路径（Future-KV）和紧凑的过渡导向路径（动态寄存器）。

**1. 标记组与路由设计 (Token Groups and Routing)**
模型输入被划分为四组 Token：当前帧 Token (C)、动态寄存器 (D)、未来槽 Token (F) 以及动作 Token (A)。通过结构化的注意力掩码，未来槽 F 可以整合当前帧 C 和寄存器 D 的信息；而动作 Token A 在去噪时可以读取完整的视频序列特征（C, F）以及寄存器 D。

**2. Future-KV 预填充 (Future-KV Prefill)**
在推理阶段，模型不进行视频的迭代去噪。它将当前观测图像编码为潜变量放入 C，将未来槽 F 初始化为纯高斯噪声。随后，Video DiT 仅执行一次单步前向传播（Prefill）。在此过程中，每一层 Transformer 产生的 Key 和 Value 张量被提取并缓存（HKV）。这些缓存包含了时空上下文信息，直接作为 Action DiT 的条件输入。

**3. 潜在动作监督的动态寄存器 (Latent-Action-Supervised Dynamics Registers)**
为了防止通用的视频预测目标忽略了由机器人交互引起的关键物理变化，模型引入了动态寄存器 D。在训练阶段，一个冻结的 LaWM 教师模型会提取真实视觉过渡前后的“潜在动作（Latent Action）”目标。寄存器 D 通过一个投影头被强制对齐到这个目标空间，从而被注入了关于物体运动、接触变化等强交互先验。在推理阶段，教师模型被移除，寄存器仅依靠当前帧和噪声槽的单次前向传播生成状态摘要。

```python
import torch.nn as nn

class ForeWAM(nn.Module):
    def __init__(self, video_dit, action_dit, lawm_teacher):
        super().__init__()
        self.video_dit = video_dit
        self.action_dit = action_dit
        self.lawm_teacher = lawm_teacher # Frozen during training
        self.register_proj = nn.Linear(hidden_dim, latent_action_dim)
        
    def forward_train(self, current_obs, future_obs, action_chunk, instruction):
        # 1. Encode observations
        z_cur = encode(current_obs)
        z_fut = encode(future_obs)
        
        # 2. Video Branch: Flow matching on future latents
        # Video DiT processes [z_cur, registers, z_fut]
        video_loss, hidden_states, registers = self.video_dit.compute_loss(z_cur, z_fut, instruction)
        
        # 3. Dynamics Register Supervision
        with torch.no_grad():
            latent_action_target = self.lawm_teacher(current_obs, future_obs)
        pred_latent_action = self.register_proj(registers.mean(dim=1))
        la_loss = mse_loss(pred_latent_action, latent_action_target)
        
        # 4. Action Branch: Flow matching on actions
        # Action DiT cross-attends to cached KV from video branch
        action_loss = self.action_dit.compute_loss(action_chunk, hidden_states, instruction)
        
        return video_loss + action_loss + lambda_la * la_loss

    def forward_inference(self, current_obs, instruction, num_action_steps=10):
        # 1. Encode current observation
        z_cur = encode(current_obs)
        
        # 2. Initialize future slots with pure noise
        noise_f = torch.randn_like(z_cur) # Stochastic future substrate
        
        # 3. Future-KV Prefill (Single forward pass, NO iterative video denoising)
        # Extract layer-wise Key-Value cache and register states
        registers, H_kv = self.video_dit.prefill_and_cache(z_cur, noise_f, instruction)
        
        # 4. Action Denoising
        noisy_action = torch.randn(action_shape)
        for t in reversed(range(num_action_steps)):
            # Action DiT reads current obs, registers, and H_kv
            flow = self.action_dit(noisy_action, t, z_cur, registers, H_kv, instruction)
            noisy_action = update_action(noisy_action, flow)
            
        return noisy_action # Executable action chunk
```

### 第二模块：核心架构解释

HandEdit 的核心架构是一个自动化的数据清洗与生成管道（Data Curation Pipeline），用于将人类第一人称交互图像转换为机器人视角的伪真值（Pseudo-GT）图像。该管道包含五个连续的客观处理步骤：

1. **前景分割与移除 (Segmentation)**：使用 SAM3 模型识别并分割出图像中的人类手部或手臂区域，将其从原图中移除。
2. **背景修复 (Background Inpainting)**：使用 ProPainter 视频修复模型，填补因移除人手而产生的图像空缺，恢复被遮挡的背景和物体部分。
3. **运动学重定向 (Kinematic Retargeting)**：提取人类手部的 3D 姿态（如 MANO 模型），通过逆运动学（IK）求解器，在考虑目标机器人 URDF 的关节限制、连杆长度和碰撞体积的前提下，计算出对应的机器人关节角度。对于包含手臂的配置，还会进行虚拟基座（Virtual-Base）的局部搜索以对齐手腕轨迹。
4. **渲染与合成 (Rendering & Compositing)**：在与原图相同的相机视角下，渲染处于计算出关节状态的机器人 URDF 模型，并将该前景渲染图覆盖到修复后的背景图像上。
5. **图像和谐化 (Harmonization)**：使用轻量级网络调整合成图像中机器人区域的光照、色彩和边缘对比度，消除拼接痕迹，输出最终的 Pseudo-GT。

```python
def generate_pseudo_gt(source_image, human_3d_pose, target_urdf, camera_intrinsics):
    # Step 1: 分割人手
    human_mask = sam3_segmentation(source_image, prompt="human hand and arm")
    
    # Step 2: 修复背景
    background_image = propainter_inpaint(source_image, human_mask)
    
    # Step 3: 运动学重定向
    # 将人类姿态映射到机器人关节空间，包含碰撞检测和关节限制
    robot_joint_states = ik_retargeting(
        source_pose=human_3d_pose, 
        urdf_model=target_urdf, 
        optimize_contact=True
    )
    
    if not is_kinematically_valid(robot_joint_states):
        return None # 剔除运动学无解的样本
        
    # Step 4: 渲染与合成
    robot_render_rgb, robot_mask = render_urdf(
        urdf_model=target_urdf, 
        joint_states=robot_joint_states, 
        camera=camera_intrinsics
    )
    composited_image = blend_images(background_image, robot_render_rgb, robot_mask)
    
    # Step 5: 图像和谐化
    final_pseudo_gt = harmonizer_network(composited_image, robot_mask)
    
    return final_pseudo_gt
```

### 第二模块：核心架构解释

本文提出的免训练管道（Pipeline）严格遵循因果推断的三个步骤：溯因（Abduce）、干预（Action/Transport）、预测（Complete & Combine）。

1. **Abduce (溯因)**：从真实发生的未来视频帧（$F^+$）中提取世界状态。利用现成的单目深度估计模型（Depth Anything V2），将 2D 像素转换为带有 RGB 信息的 3D 点云。
2. **Transport (转移)**：执行反事实动作。保持 3D 世界静止，根据反事实查询中的目标轨迹（$a'$）计算新的相机位姿。将 3D 点云前向投影（Splatting）到新的相机视角下，生成“已知证据图像（$E_t$）”和“有效掩码（$M_t$）”。
3. **Complete (补全)**：处理视野盲区。将带有掩码的证据图像输入到冻结的驾驶世界模型（如 Vista 或 DrivingWorld）中。对于扩散模型，通过在去噪过程中不断注入已知证据（类似 Repaint 机制）来补全缺失区域；对于自回归模型，则固定已知区域的 Token，仅生成未知 Token。
4. **Combine (融合)**：消除生成伪影。由于世界模型的编解码器可能会模糊原始像素，该步骤将步骤 2 中绝对可靠的投影像素直接覆盖回补全后的图像上，并在边界处进行平滑的色彩融合。

**核心逻辑伪代码**：

```python
def counterfactual_prediction(factual_video, executed_traj, target_traj, world_model, depth_model):
    """
    factual_video: 真实发生的视频 (包含历史 H 和事实未来 F+)
    executed_traj: 真实执行的自车轨迹 (a_obs)
    target_traj: 反事实查询的目标轨迹 (a')
    """
    history_frames = factual_video[:15]
    factual_future = factual_video[15:]
    
    counterfactual_future = []
    
    for t, factual_frame in enumerate(factual_future):
        # 1. Abduce (溯因): 恢复观测到的 3D 世界
        depth_map = depth_model.estimate(factual_frame)
        point_cloud_3d = lift_to_3d(factual_frame, depth_map, executed_traj[t])
        
        # 2. Transport (转移): 移动相机，获取反事实视角下的证据
        target_camera_pose = get_camera_pose(target_traj[t])
        evidence_img, valid_mask = forward_splatting(point_cloud_3d, target_camera_pose)
        
        # 3. Complete (补全): 使用冻结的世界模型脑补盲区
        # 扩散模型中的 inpainting 逻辑或自回归模型中的 token 强制替换
        completed_frame = world_model.inpaint(
            history=history_frames, 
            action=target_traj, 
            evidence=evidence_img, 
            mask=valid_mask
        )
        
        # 4. Combine (融合): 恢复高保真证据并平滑边界
        final_frame = blend(evidence_img, completed_frame, valid_mask)
        
        counterfactual_future.append(final_frame)
        
    return counterfactual_future
```

### 第二模块：核心架构解释

**架构与实验流程详解：**

1.  **系统初始化（Initialization）**：系统载入一个参数冻结的基础模型（Foundation Model），并初始化基础的非参数化组件，包括初始技能库（Skills）、上下文提示（Context）和执行脚手架（Code Harness）。
2.  **环境交互与回放（Rollouts）**：在目标环境中，冻结的模型扮演**规划器（Planner）**的角色。它调用当前的技能库和脚手架，生成动作序列并与环境交互，收集执行轨迹、环境状态反馈以及成功/失败的信号。
3.  **自我反思与进化（Self-Evolution）**：收集到 Rollouts 数据后，同一个冻结模型切换为**优化器（Optimizer）**角色。它通过分析执行轨迹中的失败原因，对当前的非参数化组件进行反思。
4.  **组件重构与更新（Harness & Skill Update）**：优化器生成新的或改进的技能代码，调整上下文提示，并重构执行脚手架。更新后的组件被存入系统，供下一轮迭代使用，形成闭环。
5.  **实验评估流程**：在 VLABench 和 ESI-Bench 上部署该框架，针对不同的底层动作接口进行测试，并严格控制变量，与 SFT（参数更新路径）和 Voting（测试时计算扩展路径）进行对比。

**核心逻辑伪代码：**

```python
class SHAPER:
    def __init__(self, frozen_model, initial_skills, initial_harness):
        # 核心约束：模型参数绝对冻结
        self.model = frozen_model 
        # 非参数化组件
        self.skills = initial_skills 
        self.harness = initial_harness 

    def rollout(self, environment, task):
        # 角色1：模型作为规划器 (Planner)
        trajectory, success, feedback = environment.execute(
            planner=self.model,
            skills=self.skills,
            harness=self.harness,
            task=task
        )
        return trajectory, success, feedback

    def evolve(self, rollouts):
        # 角色2：模型作为优化器 (Optimizer)
        # 基于环境反馈进行自我反思
        reflection = self.model.analyze_failures(rollouts)
        
        # 进化非参数化组件（不触碰模型权重）
        new_skills = self.model.optimize_skills(self.skills, reflection)
        new_harness = self.model.optimize_harness(self.harness, reflection)
        
        # 更新系统状态
        self.skills = new_skills
        self.harness = new_harness

    def adapt_to_environment(self, environment, tasks, iterations):
        # 免训练的自适应过程
        for i in range(iterations):
            rollouts = []
            for task in tasks:
                traj, success, feedback = self.rollout(environment, task)
                rollouts.append({
                    'task': task, 
                    'feedback': feedback, 
                    'success': success
                })
            
            # 闭环进化
            self.evolve(rollouts)
```

```python
def compute_hand_prior_score(predicted_actions, current_states, std_norm, lambda_weight=1.0, epsilon=1e-6):
    """
    计算初始决策窗口内的 HandPriorScore
    """
    # 计算相对动作
    relative_actions = predicted_actions - current_states
    
    # 使用共享标准差进行归一化
    normalized_actions = relative_actions / (std_norm + epsilon)
    
    # 计算左右侧手臂和手部的动作幅度 (RMS)
    def calc_magnitude(actions):
        return np.sqrt(np.mean(actions**2, axis=-1))
    
    mag_arm_L = calc_magnitude(normalized_actions['arm_L'])
    mag_hand_L = calc_magnitude(normalized_actions['hand_L'])
    mag_arm_R = calc_magnitude(normalized_actions['arm_R'])
    mag_hand_R = calc_magnitude(normalized_actions['hand_R'])
    
    # 结合手臂与手部动作
    activity_L = np.mean(mag_arm_L + lambda_weight * mag_hand_L)
    activity_R = np.mean(mag_arm_R + lambda_weight * mag_hand_R)
    
    # 计算归一化的 HandPriorScore
    score = (activity_R - activity_L) / (activity_R + activity_L + epsilon)
    return score
```

### 第二模块：核心架构解释

该论文的模型架构摒弃了端到端黑盒输出的盲目信任，采用了一种 **Neuro $\rightarrow$ Symbolic** 的级联范式，分为三个核心执行阶段：

1.  **Read（读取场景状态）：** 拦截冻结的 E2E 策略网络（如 TFv6）的前向传播过程。不仅获取其最终的标称控制指令 $x_0$（油门/刹车、转向），还提取其已经计算好的中间层结构化特征：目标检测框、BEV 语义图、雷达速度/距离、以及规划的路点（Waypoints）。
2.  **Reason（符号规则推理）：** 将提取的感知信号输入到 5 个显式的交通安全规则中（防追尾、限速、红灯、行人路权、转向稳定性）。每个规则基于物理公式（如运动学自行车模型、RSS 责任敏感安全模型）计算出一个具体的控制边界（例如：当前距离下允许的最大油门值）。这些边界组合成一个约束向量 $g(o)$。
3.  **Restrict（指令约束与修正）：** 将上述约束转化为可行控制集 $\mathcal{C}(o)$。如果 E2E 模型的原始指令 $x_0$ 在该集合内，则直接放行；如果越界，则求解一个二次规划（QP）问题，在满足所有物理约束的前提下，找到欧氏距离上最接近原始指令的安全指令 $x^*$ 并执行。

**核心逻辑伪代码 (Python 风格):**

```python
import numpy as np
from scipy.optimize import minimize

class NeuroSymbolicGuard:
    def __init__(self, e2e_model):
        self.e2e_model = e2e_model # 冻结的端到端模型
        # 定义控制变量边界: u (纵向: -1刹车到1油门), s (横向: -1到1转向)
        self.bounds = [(-1.0, 1.0), (-1.0, 1.0)] 

    def step(self, observation, ego_speed):
        # 1. Read: 获取原始动作和中间层感知结果
        x_0, scene_state = self.e2e_model.forward_with_intermediates(observation)
        detections, bev, radar, waypoints = scene_state
        
        # 2. Reason: 基于物理规则计算安全边界
        # 例如: 计算防碰撞最大允许纵向控制量 (基于 RSS)
        g_coll = self._compute_rss_collision_bound(detections, radar, waypoints, ego_speed)
        g_speed = self._compute_speed_limit_bound(bev, ego_speed)
        g_red = self._compute_red_light_bound(bev, ego_speed)
        g_ped = self._compute_pedestrian_bound(detections, ego_speed)
        g_lat = self._compute_steering_stability_bound(ego_speed) # 基于自行车模型
        
        # 组装约束向量 g(o) 和 约束矩阵 D (Dx <= g)
        # 这里简化表达，实际中每个规则对应 D 的一行
        constraints = self._build_qp_constraints(g_coll, g_speed, g_red, g_ped, g_lat)
        
        # 3. Restrict: 检查并投影 (求解 QP)
        if self._is_safe(x_0, constraints):
            return x_0 # 原始动作安全，直接放行
            
        # 目标函数：最小化 ||x - x_0||^2
        objective = lambda x: np.sum((x - x_0)**2)
        
        # 求解二次规划，寻找最近的安全动作
        result = minimize(objective, x_0, bounds=self.bounds, constraints=constraints)
        x_star = result.x
        
        return x_star
```

### 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 解决端到端（E2E）自动驾驶模型在长尾/未见场景下，因缺乏对物理规律和交通规则的真正理解，而产生致命违规动作（如径直撞向行人或障碍物）的问题。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 提出了一种即插即用的“神经符号安全守卫”。它不改变原有 E2E 模型的权重，而是利用模型已有的中间感知输出，结合显式的运动学公式构建硬性安全边界，在指令下发给底盘前，通过数学优化（QP）将危险指令强制拉回安全范围内。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 巧妙之处在于使用了 Fail2Drive 基准测试中的“成对测试（Paired Comparison）”协议。该数据集包含同分布（In-distribution）和泛化（Generalization）两个测试集，两者的道路结构和危险逻辑完全一致，仅仅改变了障碍物的外观和排列。这种控制变量法极其精准地剥离了模型的“记忆能力”，直接暴露了其在泛化时的安全脆弱性，从而凸显了 Safety Guard 的兜底价值。

Q4: 这篇论文最显著的贡献点（Top 3）是什么？

A4: 
1. 提出了一种无需重新训练、与架构解耦的后处理安全模块，可直接外挂于现有的 E2E 驾驶模型。
2. 将 5 种核心交通安全规则（如 RSS 距离、转向稳定性）推导为闭式（closed-form）的数学约束，直接映射到车辆底盘的油门/刹车/转向控制边界上。
3. 在严格的闭环长尾测试中，证明了该方法能在不损失标称驾驶分数的前提下，将严重碰撞率降低一半，大幅提升了系统的可审计性（Auditable）。

Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）

A5: 
1. 暴露中间表征的端到端驾驶模型：如 TransFuser (TFv6)，为本研究提供了无需额外计算代价的场景感知输入。
2. 强化学习中的安全屏蔽（Safe-RL Shielding）与可微凸优化层（如 OptNet）：本文将这种在训练阶段常用的动作约束思想，成功迁移到了冻结模型的推理执行阶段。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 
局限性与漏洞：该 Guard 模块存在“感知依赖”和“轨迹僵化”两个致命弱点。首先，它的规则计算完全依赖于 E2E 模型中间层的感知结果，如果感知头漏检了前方的异形车，Guard 同样会变成瞎子，无法阻止碰撞。其次，Guard 只能在当前规划的轨迹上做纵向（刹车）或横向（限制打方向）的截断，它**无法凭空创造出一条新的避让轨迹**。如果 E2E 模型规划了一条直冲墙壁的死路，Guard 只能把车刹停在墙前导致任务超时，而无法绕开墙壁。
对后续科研的启发：后处理的 QP 投影虽然保证了下限，但牺牲了灵活性。未来的 VLA 模型研究不应仅仅将物理规则作为后处理补丁，而应考虑将这种基于物理规则的 QP 求解器作为可微层（Differentiable Layer）嵌入到端到端模型的训练图中，通过反向传播让模型在特征提取阶段就学会“敬畏”物理边界，从而在源头上规划出既安全又流畅的轨迹。
