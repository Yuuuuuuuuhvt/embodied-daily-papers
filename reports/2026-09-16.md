### 第二模块：核心架构解释

CueNav 的系统架构分为两个解耦的核心模块：一个跨形态共享的视频规划器（World Model），以及一个特定于具身形态的逆动力学模型（IDM）。

1. **观测构建 (Observation Construction):** 系统获取历史 RGB 图像序列。为了注入上下文，图像中保留了机器人本体的一部分（具身线索），并在需要长视野导航时，将全局 BEV 地图拼接在图像中（任务线索）。
2. **视频规划 (Video Planning):** 基于 Wan2.2-5B 视频扩散模型。输入历史观测序列和文本提示，模型通过自回归扩散强制（Diffusion-forcing）机制，预测未来 $M$ 帧的视觉观测。此过程无需任何动作标签。
3. **光流提取 (Flow Extraction):** 使用现成的光流估计器（AllTracker），计算历史帧与预测未来帧序列中相邻帧之间的稠密光流场。引入历史帧的光流是为了提供系统动力学（如控制延迟）的时间上下文。
4. **动作映射 (Action Grounding):** 光流场序列输入到 IDM 中。IDM 首先通过共享的卷积编码器提取空间特征，随后通过带有 3D 旋转位置编码的时空 Transformer 处理所有特征，最终通过前馈网络回归出 $q$ 步连续的机器人动作（如线速度和角速度）。
5. **闭环执行 (Closed-loop Execution):** 机器人执行预测出的 $q$ 步动作，采集新的观测数据，更新历史观测队列，进入下一轮规划。

**核心逻辑伪代码 (Python 风格):**

```python
def cuenav_closed_loop_navigation(
    video_planner, 
    idm_model, 
    flow_estimator, 
    text_prompt, 
    env
):
    # N: history context length, M: prediction horizon
    # q: action execution horizon, p: temporal padding
    
    obs_history = env.get_recent_observations(length=N) # Includes visual cues (BEV/body)
    
    while not env.is_terminated():
        # 1. Video Planning (World Model prediction)
        # Predict M future frames based on N context frames and text prompt
        future_frames = video_planner.predict(
            context=obs_history, 
            prompt=text_prompt, 
            horizon=M
        )
        
        # Combine history and future for temporal context
        combined_frames = obs_history[-p:] + future_frames[:q+p]
        
        # 2. Flow Extraction
        # Compute dense flow fields between consecutive frames
        flow_fields = []
        for i in range(len(combined_frames) - 1):
            flow = flow_estimator.compute_flow(combined_frames[i], combined_frames[i+1])
            flow_fields.append(flow)
            
        # 3. Action Grounding (IDM)
        # Infer q continuous actions from flow fields
        actions = idm_model.infer_actions(flow_fields)
        
        # 4. Execution
        for t in range(q):
            new_obs = env.step(actions[t])
            obs_history.append(new_obs)
            obs_history.pop(0) # Maintain fixed history length N
```

在状态转移建模上，WAMs 严格遵循两种核心范式：
1. **联合预测（Joint Prediction）**：模型在统一的隐空间内，同时自回归或通过扩散过程生成未来的观测（Observation）和动作（Action）。

```python
import torch
import torch.nn as nn

class WorldActionModel(nn.Module):
    def __init__(self, paradigm="joint"):
        super().__init__()
        self.paradigm = paradigm
        
        # 1. 核心组件 (Core Components)
        self.language_encoder = PretrainedLLM()
        self.visual_encoder = VideoVAE()
        self.action_tokenizer = ActionTokenizer()
        
        # 2. 预测骨干 (Predictive Backbone - e.g., DiT or Causal Transformer)
        self.spatiotemporal_backbone = DiffusionTransformer()
        
        # 3. 动作解码器 (Action Decoder)
        self.action_head = ActionDiffusionHead()
        self.inverse_dynamics_head = IDMHead()

    def forward(self, obs_history, instruction):
        # 编码上下文
        lang_tokens = self.language_encoder(instruction)
        visual_latents = self.visual_encoder(obs_history)
        
        if self.paradigm == "joint":
            # 范式一：联合预测 (Joint Prediction)
            # Eq 14: p(o_{t:t+H}, a_{t:t+H} | o_{<t}, l)
            future_latents, action_latents = self.spatiotemporal_backbone(
                visual_latents, lang_tokens, mode="joint"
            )
            future_obs = self.visual_encoder.decode(future_latents)
            actions = self.action_head(action_latents)
            return future_obs, actions
            
        elif self.paradigm == "inverse_dynamics":
            # 范式二：逆动力学 (Inverse Dynamics Model)
            # Eq 15: p(o_{t:t+H} | o_{<t}, l) * p(a_{t:t+H} | o_{t:t+H}, o_{<t})
            
            # Step 1: Visual Planning (生成未来状态)
            future_latents = self.spatiotemporal_backbone(
                visual_latents, lang_tokens, mode="video_only"
            )
            future_obs = self.visual_encoder.decode(future_latents)
            
            # Step 2: Action Inference (基于状态转移推断动作)
            actions = self.inverse_dynamics_head(visual_latents, future_latents)
            return future_obs, actions
```

   - **Grounding (基础)**：预测内容必须锚定在 Geometry（几何）、Physics（物理）、Action（动作）上。

### 第二模块：核心架构解释

CueNav 的系统架构分为两个解耦的核心模块：一个跨形态共享的视频规划器（World Model），以及一个特定于具身形态的逆动力学模型（IDM）。

1. **观测构建 (Observation Construction):** 系统获取历史 RGB 图像序列。为了注入上下文，图像中保留了机器人本体的一部分（具身线索），并在需要长视野导航时，将全局 BEV 地图拼接在图像中（任务线索）。
2. **视频规划 (Video Planning):** 基于 Wan2.2-5B 视频扩散模型。输入历史观测序列和文本提示，模型通过自回归扩散强制（Diffusion-forcing）机制，预测未来 $M$ 帧的视觉观测。此过程无需任何动作标签。
3. **光流提取 (Flow Extraction):** 使用现成的光流估计器（AllTracker），计算历史帧与预测未来帧序列中相邻帧之间的稠密光流场。引入历史帧的光流是为了提供系统动力学（如控制延迟）的时间上下文。
4. **动作映射 (Action Grounding):** 光流场序列输入到 IDM 中。IDM 首先通过共享的卷积编码器提取空间特征，随后通过带有 3D 旋转位置编码的时空 Transformer 处理所有特征，最终通过前馈网络回归出 $q$ 步连续的机器人动作（如线速度和角速度）。
5. **闭环执行 (Closed-loop Execution):** 机器人执行预测出的 $q$ 步动作，采集新的观测数据，更新历史观测队列，进入下一轮规划。

**核心逻辑伪代码 (Python 风格):**

```python
def cuenav_closed_loop_navigation(
    video_planner, 
    idm_model, 
    flow_estimator, 
    text_prompt, 
    env
):
    # N: history context length, M: prediction horizon
    # q: action execution horizon, p: temporal padding
    
    obs_history = env.get_recent_observations(length=N) # Includes visual cues (BEV/body)
    
    while not env.is_terminated():
        # 1. Video Planning (World Model prediction)
        # Predict M future frames based on N context frames and text prompt
        future_frames = video_planner.predict(
            context=obs_history, 
            prompt=text_prompt, 
            horizon=M
        )
        
        # Combine history and future for temporal context
        combined_frames = obs_history[-p:] + future_frames[:q+p]
        
        # 2. Flow Extraction
        # Compute dense flow fields between consecutive frames
        flow_fields = []
        for i in range(len(combined_frames) - 1):
            flow = flow_estimator.compute_flow(combined_frames[i], combined_frames[i+1])
            flow_fields.append(flow)
            
        # 3. Action Grounding (IDM)
        # Infer q continuous actions from flow fields
        actions = idm_model.infer_actions(flow_fields)
        
        # 4. Execution
        for t in range(q):
            new_obs = env.step(actions[t])
            obs_history.append(new_obs)
            obs_history.pop(0) # Maintain fixed history length N
```

### 第二模块：核心架构解释

本文并非提出单一模型，而是将所有 WAMs 抽象为一个通用的架构范式。一个标准的 WAM 包含四个核心功能模块：语言编码器（提供任务条件）、视觉编码器（定义预测状态）、预测骨干网络（承载时空动力学）以及动作解码器（将预测转化为控制）。

在状态转移建模上，WAMs 严格遵循两种核心范式：
1. **联合预测（Joint Prediction）**：模型在统一的隐空间内，同时自回归或通过扩散过程生成未来的观测（Observation）和动作（Action）。
2. **逆动力学模型（Inverse Dynamics Model, IDM）**：遵循“先计划后执行（Plan-then-Act）”的逻辑，先基于当前状态和指令生成未来状态（如视频帧或点云），再通过逆动力学模块推导出导致该状态转移的动作。

```python
import torch
import torch.nn as nn

class WorldActionModel(nn.Module):
    def __init__(self, paradigm="joint"):
        super().__init__()
        self.paradigm = paradigm
        
        # 1. 核心组件 (Core Components)
        self.language_encoder = PretrainedLLM()
        self.visual_encoder = VideoVAE()
        self.action_tokenizer = ActionTokenizer()
        
        # 2. 预测骨干 (Predictive Backbone - e.g., DiT or Causal Transformer)
        self.spatiotemporal_backbone = DiffusionTransformer()
        
        # 3. 动作解码器 (Action Decoder)
        self.action_head = ActionDiffusionHead()
        self.inverse_dynamics_head = IDMHead()

    def forward(self, obs_history, instruction):
        # 编码上下文
        lang_tokens = self.language_encoder(instruction)
        visual_latents = self.visual_encoder(obs_history)
        
        if self.paradigm == "joint":
            # 范式一：联合预测 (Joint Prediction)
            # Eq 14: p(o_{t:t+H}, a_{t:t+H} | o_{<t}, l)
            future_latents, action_latents = self.spatiotemporal_backbone(
                visual_latents, lang_tokens, mode="joint"
            )
            future_obs = self.visual_encoder.decode(future_latents)
            actions = self.action_head(action_latents)
            return future_obs, actions
            
        elif self.paradigm == "inverse_dynamics":
            # 范式二：逆动力学 (Inverse Dynamics Model)
            # Eq 15: p(o_{t:t+H} | o_{<t}, l) * p(a_{t:t+H} | o_{t:t+H}, o_{<t})
            
            # Step 1: Visual Planning (生成未来状态)
            future_latents = self.spatiotemporal_backbone(
                visual_latents, lang_tokens, mode="video_only"
            )
            future_obs = self.visual_encoder.decode(future_latents)
            
            # Step 2: Action Inference (基于状态转移推断动作)
            actions = self.inverse_dynamics_head(visual_latents, future_latents)
            return future_obs, actions
```

```python
    def __init__(self, config_path, checkpoint_path):
        # 1. 根据配置重建自包含的模型与数据流水线
        self.config = load_config(config_path)
        self.data_transforms = build_transforms(self.config.data.online_transforms)
        
        # 2. 替换为加速版推理模型 (如融合算子、CUDA Graph捕获)
        self.model = build_model(self.config.model.inference_version)
        self.model.load_state_dict(checkpoint_path, strict=True)
        self.model.warmup_and_capture_graph() # 静态图捕获
        
        # 3. 初始化 RTC 与轨迹后处理模块
        self.rtc_module = build_rtc(self.config.deployment.rtc)
        self.trajectory_optimizer = JointMPC(self.config.deployment.limits)
        
        self.active_trajectory = None

    def control_loop(self, raw_observation, current_time):
        # A. 观测预处理 (与训练期严格一致)
        canonical_obs = self.data_transforms(raw_observation)
        
        # B. 实时分块 (RTC): 计算与上一动作块的时间偏移，提取已知前缀
        if self.active_trajectory is not None:
            action_prefix = self.rtc_module.get_aligned_prefix(
                self.active_trajectory, current_time
            )
            canonical_obs['action_prefix'] = action_prefix
            
        # C. 模型推理 (执行 CUDA Graph)
        normalized_chunk = self.model.predict_action(canonical_obs)
        
        # D. 动作反归一化
        raw_chunk = self.data_transforms.inverse_action(normalized_chunk)
        
        # E. 轨迹后处理 (平滑、限幅、跨块拼接)
        safe_trajectory = self.trajectory_optimizer.optimize(
            reference=raw_chunk,
            previous_trajectory=self.active_trajectory,
            stitch=True
        )
        
        self.active_trajectory = safe_trajectory
        return safe_trajectory.get_next_command()
```

### 第二模块：核心架构解释

TEMPO 的核心架构在不改变原有 VLA 骨干（如基于 Flow-matching 的策略网络）的前提下，构建了两条并行的时序特征提取支路，并在输入端和网络深层进行特征融合。

**1. 视觉运动特征提取 ($TEMPO_{MOT}$)**
该分支用于捕获场景动态。系统维护一个长度为 $W-1$ 的历史帧特征缓存队列。当前帧输入后，通过冻结的视频基础模型（如 SAM 2.1-Tiny）提取 Patch 特征，并将当前帧特征作为 Query，历史缓存特征作为 Key 和 Value 进行交叉注意力计算，输出运动潜变量 $m_t$。

**2. 本体感觉历史压缩 ($TEMPO_{ACT}$)**
该分支用于提供任务阶段上下文。系统截取过去 $H$ 步的机器人本体感觉指令（如关节位置），将其划分为 $K$ 个等长的连续时间桶（Bucket）。对每个桶内的数据进行平均池化，生成固定尺寸的紧凑历史表征 $c_t$。

**3. 特征融合与策略调制**
- **前缀拼接**：将 $m_t$ 和 $c_t$ 投影至 VLM 的 Token 维度，与当前帧多视角图像 Token 及语言指令 Token 拼接，作为 VLM 的多模态前缀。
- **深层调制**：将 $c_t$ 展平，通过 MLP 映射为 AdaRMS（自适应均方根归一化）的缩放和偏移参数，直接调制下游动作专家（Action Expert）的去噪过程。

**核心伪代码实现**：

```python
import torch
import torch.nn as nn

class TEMPO(nn.Module):
    def __init__(self, pretrained_vla, video_encoder, W=10, K=10, L=30):
        super().__init__()
        self.vla = pretrained_vla # Frozen VLA backbone
        self.video_encoder = video_encoder # Frozen, e.g., SAM 2.1-Tiny
        self.W = W # Visual history window size
        self.K = K # Number of proprioceptive buckets
        self.L = L # Length of each bucket
        
        # Trainable projections
        self.mot_proj = nn.Linear(video_dim, vlm_token_dim)
        self.act_proj = nn.Linear(proprio_dim, vlm_token_dim)
        self.adarms_mlp = nn.Sequential(
            nn.Linear(K * proprio_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, action_expert_dim * 2) # scale and shift
        )
        
    def extract_tempo_mot(self, curr_frame, history_frames_cache):
        # curr_frame: [1, C, H, W]
        # history_frames_cache: [W-1, C, H, W]
        curr_feat = self.video_encoder.extract_patch_features(curr_frame)
        hist_feats = self.video_encoder.extract_patch_features(history_frames_cache)
        
        # Cross-attention: Query=curr_feat, Key/Value=hist_feats
        m_t = cross_attention(q=curr_feat, k=hist_feats, v=hist_feats)
        return m_t

    def extract_tempo_act(self, proprio_history):
        # proprio_history: [H, proprio_dim], where H = K * L
        # Reshape into K buckets of length L
        buckets = proprio_history.view(self.K, self.L, -1)
        # Mean pool over the L dimension
        c_t = buckets.mean(dim=1) # Shape: [K, proprio_dim]
        return c_t

    def forward(self, curr_frame, hist_frames, proprio_hist, text_tokens):
        # 1. Extract temporal signals
        m_t = self.extract_tempo_mot(curr_frame, hist_frames)
        c_t = self.extract_tempo_act(proprio_hist)
        
        # 2. Project to VLM token space
        m_t_tokens = self.mot_proj(m_t)
        c_t_tokens = self.act_proj(c_t)
        
        # 3. Construct multimodal prefix
        visual_tokens = self.vla.vision_encoder(curr_frame)
        prefix_tokens = torch.cat([text_tokens, visual_tokens, m_t_tokens, c_t_tokens], dim=1)
        
        # 4. Generate AdaRMS modulation parameters for Action Expert
        c_t_flat = c_t.view(1, -1)
        adarms_params = self.adarms_mlp(c_t_flat)
        scale, shift = adarms_params.chunk(2, dim=-1)
        
        # 5. Forward through VLA with modulated action expert
        action = self.vla.generate_action(prefix_tokens, modulation=(scale, shift))
        return action
```

### 第二模块：核心架构解释

GeoLAM 的整体架构分为两个解耦的阶段：阶段一是基于人类视频的无监督隐式动作预训练；阶段二是基于机器人数据的世界-动作模型（World-Action Model）微调。

**阶段一：几何基底隐式动作学习（预训练）**
1. **特征提取**：输入视频的起始帧和未来帧，通过冻结的几何基础模型（Depth Anything 3 的浅层）提取几何特征。
2. **逆向动力学（IDM）**：IDM 接收起始帧和未来帧的特征差值，通过确定性瓶颈（Deterministic Bottleneck）压缩并输出连续的隐式动作 Token。
3. **正向动力学（FDM）与重建**：FDM 结合起始帧特征和隐式动作 Token 预测未来帧的浅层特征。随后通过冻结的深层 GFM 和 RGB 解码器重建未来像素，计算像素级 MSE 损失。
4. **4D 几何教师监督**：冻结的 D4RT 模型处理两帧之间的视频片段，输出 3D/2D 位移、表面法线变化以及置信度/可见度。这些几何运动线索经过置信度加权池化后，作为目标监督隐式动作 Token（计算几何损失）。

**阶段二：世界-动作模型训练与部署（下游策略）**
1. **联合去噪**：冻结阶段一训练好的 IDM，利用其提取的隐式动作作为目标。Action DiT 联合去噪隐式动作和机器人可执行动作块（Action Chunk）。
2. **推理部署**：丢弃 4D 教师模型和未来视频预测分支。仅输入当前观测，通过 Video DiT 缓存特征，Action DiT 直接输出多步机器人控制指令。

```python
    pred_geometry = projector(latent_action)
    loss_geo = F.mse_loss(pred_geometry, teacher_target)

    total_loss.backward()
```

### 第二模块：核心架构解释

SAVLA 的核心架构分为三个阶段：输入规范化、类型化特征接口、等变流匹配动作生成。

1. **Canonicalization Head (规范化头):** 接收第三人称倾斜视角的 RGB 图像，通过一个轻量级 CNN 预测场景绕重力轴的旋转角度 $\hat{\theta}$。随后，利用基于桌面的单应性矩阵 $H(\hat{\theta})$ 将图像逆向扭曲（Warp）到规范化视角（Canonical View）。
2. **Typed Interface (类型化接口):** 冻结的 VLM 接收规范化后的图像和文本指令，输出**旋转不变（Invariant, Type-0）**的标量特征。同时，利用预测的 $\hat{\theta}$ 将预先计算好的 3D 视觉参考点进行物理旋转，生成**旋转等变（Equivariant, Type-1）**的向量特征。
3. **Equivariant Action Head (等变动作头):** 这是一个基于流匹配（Flow-Matching）的生成式策略网络。网络内部严格区分标量轨道（Scalar Track）和向量轨道（Vector Track）。标量轨道使用常规 MLP 和 LayerNorm；向量轨道使用向量神经元（Vector Neurons）、等变 RMSNorm 和等变注意力机制。最终输出去噪后的动作块（Action Chunk）。

**核心伪代码实现逻辑：**

```python
import torch
import torch.nn as nn

class SAVLA(nn.Module):
    def __init__(self, vlm_backbone, canonicalizer, equivariant_flow_head):
        super().__init__()
        self.vlm = vlm_backbone # Frozen
        self.canonicalizer = canonicalizer # Trainable CNN
        self.action_head = equivariant_flow_head # Trainable Equivariant Network
        self.reference_points = get_3d_reference_points() # Fixed 3D points

    def forward(self, img_3rd, img_wrist, instruction, state, noisy_action, time_step):
        # 1. Canonicalization
        # Predict rotation angle theta from 3rd person image
        theta_hat = self.canonicalizer(img_3rd) 
        
        # Warp image to canonical view using Homography
        canonical_img = warp_homography(img_3rd, theta_hat) 
        
        # 2. Typed Interface
        # VLM extracts Invariant (Type-0) features from canonical image
        with torch.no_grad():
            invariant_features = self.vlm(canonical_img, img_wrist, instruction)
            
        # Rotate 3D reference points to get Equivariant (Type-1) conditions
        equivariant_conditions = rotate_3d_points(self.reference_points, theta_hat)
        
        # Format state and action into Type-0 and Type-1 tracks
        state_type0, state_type1 = split_state_to_tracks(state)
        action_type0, action_type1 = split_action_to_tracks(noisy_action)
        
        # 3. Equivariant Flow-Matching Head
        # Predict velocity field for flow matching
        velocity_type0, velocity_type1 = self.action_head(
            action_type0, action_type1,
            state_type0, state_type1,
            invariant_features, equivariant_conditions,
            time_step
        )
        
        return velocity_type0, velocity_type1

# Inside Equivariant Action Head: Vector-Scalar Attention (Simplified)
class EquivariantAttention(nn.Module):
    def forward(self, q_scalar, q_vector, k_scalar, k_vector, v_scalar, v_vector):
        # Inner product of vectors is invariant. 
        # Attention score combines scalar similarity and vector similarity.
        score_scalar = torch.matmul(q_scalar, k_scalar.transpose(-2, -1))
        score_vector = torch.sum(q_vector * k_vector, dim=-1) # Vector inner product
        
        attention_weights = torch.softmax(score_scalar + score_vector, dim=-1)
        
        # Aggregate values
        out_scalar = torch.matmul(attention_weights, v_scalar)
        out_vector = torch.matmul(attention_weights, v_vector) # Invariant weight * Equivariant vector = Equivariant
        
        return out_scalar, out_vector
```

### 第二模块：核心架构解释

SWIM 框架分为两个核心阶段：**基于仿真的 SWIM-VLA 策略训练**，以及**基于虚拟推演的物理部署**。

**1. 训练阶段 (SWIM-VLA):**
模型以 OpenVLA-OFT 为主干。输入为 RGB 图像、语言指令和当前肌腱长度（本体感觉）。多模态编码器提取共享表征后，接入两个头：
*   **Diffusion Action Head:** 预测未来 $H$ 步的肌腱驱动指令块（Action Chunking），以处理同一任务下可能存在的多种全身形变解（多峰分布）。
*   **VSP Head (Visual Soft Proprioception):** 一个辅助回归头，用于预测软体机器人骨干上 $N_b$ 个锚点在图像平面的 2D 坐标。该机制强制多模态表征学习全身几何构型，仅在训练时使用。

**2. 推理与部署阶段 (Virtual Rollout):**
*   **场景初始化:** 捕获物理世界的初始 RGB 图像，通过颜色分割和平面标定，在 MuJoCo 仿真中实例化对应的预定义目标模型。
*   **虚拟推演:** 在仿真环境中，SWIM-VLA 闭环自回归地预测动作块并驱动仿真机器人，直到任务完成，收集完整的动作指令序列。
*   **物理执行:** 将收集到的完整动作序列直接在物理机器人上进行**开环执行**。物理交互中的微小误差由软体机器人的内在柔顺性（Intrinsic Compliance）自动吸收。

```python
    shared_rep = multimodal_encoder(img_sim, text, tendon_len)

    anchors_pred = vsp_head(shared_rep)
    loss_vsp = mse_loss(anchors_pred, anchors_gt)
    
    # 4. 联合优化
    total_loss = loss_act + lambda_vsp * loss_vsp
    total_loss.backward()
    optimizer.step()

        shared_rep = multimodal_encoder(obs_sim, text, tendon_sim)
        action_chunk = diffusion_head.sample(shared_rep) # DDIM 采样
        
        # 执行前 K 步 (Temporal Ensembling / Receding Horizon)
        executed_actions = action_chunk[:K]
        full_action_sequence.extend(executed_actions)
        
        obs_sim, tendon_sim = sim_env.step(executed_actions)
        
    # 3. 物理执行 (在现实中开环)
    real_robot.execute_open_loop(full_action_sequence) # 依赖物理柔顺性适应接触
```

### 第二模块：核心架构解释

sensVLA 的架构设计本质上是一个多模态特征的“分流与汇聚”系统。它放弃了将所有模态塞入单一 LLM 的做法，而是构建了三条并行的特征流，最终在动作专家网络中进行决策融合。

```python
        # 提取语义上下文
        state_token = self.state_proj(current_state)
        vlm_context = self.vlm(rgb, text, state_token)

        bev_features = self.pointpillars(lidar_cloud)

        # Layer 2 关注 bev_tokens
        # Layer 3 关注 concat(vlm_context, bev_tokens)
        expert_out = self.action_expert(
            noisy_action, t, vlm_context, bev_tokens, history_token
        )
        
        # 回归流匹配的速度场
        pred_velocity = self.flow_mlp(expert_out)
        return pred_velocity

    def inference(self, rgb, text, current_state, lidar_cloud, state_history):
        # 使用 ODE 求解器进行动作生成
        def ode_func(t, x):
            return self.forward(rgb, text, current_state, lidar_cloud, state_history, x, t)
            
        # 初始化纯噪声
        x_T = torch.randn(batch_size, 10, 6) 
        t_span = torch.linspace(1.0, 0.0, steps=10)
        
        # 积分求解得到干净的连续动作轨迹
        clean_action = odeint(ode_func, x_T, t_span, method='midpoint')[-1]
```

### 第二模块：核心架构解释

IRR 框架的运行流程分为离线参考库构建、在线内在奖励计算以及残差策略改进三个核心阶段：

**1. 离线参考库构建 (Reference Bank Construction)**
利用模仿学习阶段收集的成功演示轨迹，提取其最终状态（Endpoint）的图像。将这些图像输入到冻结的 VLA 视觉编码器（如 DINOv2 + SigLIP）中，经过池化和归一化处理，生成任务特定的目标特征向量集合，即“参考库”。

**2. 在线内在奖励计算 (Intrinsic Reward Computation)**
在机器人执行任务时，实时提取当前视角的图像特征。计算当前特征与参考库中 $k$ 个最近邻特征的欧氏距离。通过一个温度超参数将距离转化为 0 到 1 之间的相似度得分。为了防止瞬时视觉误判，引入“持久性得分（Persistence Score）”，即取动作结束后一个短时间窗口内的最低得分作为最终的终端奖励（Terminal Reward）。

**3. 残差策略改进 (Residual Policy Improvement)**
保留模仿学习训练好的 VLA 作为基础策略输出标称动作，同时训练一个有界的残差强化学习控制器（如 SAC 算法）。残差控制器根据 IRR 提供的奖励信号不断试错，输出动作补偿量，与基础动作叠加后经过安全约束层输出给物理机器人。

**核心伪代码实现：**

```python
import torch
import torch.nn.functional as F

class IntrinsicRobotRewarding:
    def __init__(self, vla_encoder, successful_endpoints, k=1, temperature=0.1):
        self.encoder = vla_encoder.eval() # 冻结的 VLA 视觉编码器
        self.k = k
        self.temperature = temperature
        
        # 1. 构建参考库 (离线)
        with torch.no_grad():
            # 提取成功演示终点的特征并归一化
            raw_features = self.encoder(successful_endpoints)
            self.reference_bank = F.normalize(raw_features, p=2, dim=-1) 
            
    def compute_frame_score(self, current_obs):
        # 提取当前观测特征
        with torch.no_grad():
            z_t = F.normalize(self.encoder(current_obs), p=2, dim=-1)
            
        # 计算与参考库的距离 (L2)
        distances = torch.cdist(z_t.unsqueeze(0), self.reference_bank)
        
        # 获取 k 个最近邻的平均距离
        topk_dist, _ = torch.topk(distances, self.k, largest=False)
        d_g = topk_dist.mean()
        
        # 转化为相似度得分
        score = torch.exp(-d_g / self.temperature)
        return score

    def compute_terminal_reward(self, post_action_observations):
        # 2. 计算持久性得分 (在线评估)
        # 评估动作结束后一个短窗口内的所有观测，取最小值防止瞬时误判
        scores = [self.compute_frame_score(obs) for obs in post_action_observations]
        persistence_score = min(scores)
        return persistence_score

# 3. 残差控制逻辑 (示意)
def execute_action(vla_policy, residual_rl_policy, obs, state, task):
    # 基础 VLA 动作
    a_base = vla_policy(obs, state, task)
    # RL 输出残差动作
    a_residual = residual_rl_policy(obs, state, task)
```

### 第二模块：核心架构解释

AdaDE 框架的运行流程分为三个核心阶段：无损转换、动态停用训练、紧凑模型导出。

**1. Dense2MoE 无损转换 (Initialization)**
将 VLA 模型中 LLM 侧的 Dense FFN 层的中间维度 $H$ 均匀切分为 $E$ 个专家。权重矩阵 $W_{gate}, W_{up}$ 按行切分，$W_{down}$ 按列切分。初始化路由器权重为 0，使所有专家获得完全相等的路由概率。这种构造确保了转换后的 MoE 模块在未经训练前，其输出与原 Dense FFN 模块在浮点精度内完全一致。

**2. AdaDE 动态停用训练 (Training)**
训练分为三个子阶段：
- **Warmup**：所有专家保持激活。模型优化任务损失和辅助路由损失（防止路由概率过早坍塌），并计算 Wanda 重要性指标以锁定前 25% 的核心专家，使其免于被淘汰。
- **Adaptive Deactivation**：每隔 $\Delta T$ 步，系统检查每个专家的 EMA 路由概率。若某非保护专家的概率低于阈值 $\tau_{deact}$，则将其掩码设为 0（永久停用）。该过程在每一层独立进行，并强制每层至少保留 $M_{min}$ 个专家。
- **Freeze**：停止掩码更新，固化当前的稀疏结构，模型继续微调以适应最终的稀疏拓扑。

**3. 紧凑模型导出 (Deployment)**
根据冻结的掩码，物理删除未激活的专家权重切片，仅保留激活的权重行/列，导出体积更小的检查点用于实际机器人推理。

```python
# 1. Dense2MoE Conversion
def dense_to_moe(W_gate, W_up, W_down, num_experts):
    H = W_gate.shape[0]
    expert_dim = H // num_experts
    experts = []
    for i in range(num_experts):
        start, end = i * expert_dim, (i + 1) * expert_dim
        # Slice weights for each expert
        e_gate = W_gate[start:end, :]
        e_up = W_up[start:end, :]
        e_down = W_down[:, start:end]
        experts.append({'gate': e_gate, 'up': e_up, 'down': e_down})
    
    # Initialize router with zeros for uniform probability
    router_weight = zeros(input_dim, num_experts) 
    return experts, router_weight

# 2. AdaDE Mask Update Step (executed every delta_T steps)
def update_expert_masks(layer_experts, ema_scores, protected_indices, tau_deact, min_active):
    active_count = sum(expert.mask for expert in layer_experts)
    
    # Sort experts by EMA score in ascending order
    sorted_experts = argsort(ema_scores)
    
    for idx in sorted_experts:
        if active_count <= min_active:
            break
        if idx in protected_indices:
            continue
            
        if ema_scores[idx] < tau_deact and layer_experts[idx].mask == 1:
            layer_experts[idx].mask = 0  # Deactivate expert
            active_count -= 1
```

策略通过 PointNet++ 处理点云，结合本体感觉和 Contact Token，输入 Transformer 预测未来 30 步的动作块（Action Chunk）。

```python
import torch.nn as nn

class UniDexViTacGeneralist(nn.Module):
    def __init__(self):
        super().__init__()
        # 视觉-触觉融合编码器
        self.pointnet = PointNetPlusPlus(input_dim=6) # 3D坐标 + 3D One-hot标签
        self.proprio_encoder = nn.Linear(42, hidden_dim) # 关节位置, 手腕位姿, 指尖位置
        self.contact_encoder = nn.Sequential(
            nn.Linear(4, hidden_dim), # 4-bit 二值触觉输入
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim)
        )
        # ACT Transformer 核心
        self.transformer = TransformerEncoderDecoder()
        self.action_head = nn.Linear(hidden_dim, 21) # 9D手腕位姿 + 12D相对指尖目标

    def forward(self, point_cloud, proprioception, contact_bits, style_latent=None):
        """
        point_cloud: [B, 512, 6] (508相机点 + 4指尖点, 包含接触状态的One-hot编码)
        proprioception: [B, 42]
        contact_bits: [B, 4] (独立的全局接触状态)
        """
        # 1. 编码观测数据
        pc_features = self.pointnet(point_cloud)           # [B, hidden_dim]
        proprio_features = self.proprio_encoder(proprioception) # [B, hidden_dim]
        contact_token = self.contact_encoder(contact_bits) # [B, hidden_dim]
        
        # 2. 序列化输入 Transformer
        # 包含: CLS, 潜变量(训练时来自CVAE), 本体感觉, 触觉Token, 点云特征
        transformer_input = torch.stack([
            style_latent, 
            proprio_features, 
            contact_token, 
            pc_features
        ], dim=1)
        
        # 3. 预测动作块 (Action Chunking)
        # 输出未来 30 步的动作
        action_chunk_features = self.transformer(transformer_input, seq_len=30)
        predicted_actions = self.action_head(action_chunk_features) # [B, 30, 21]
        
        return predicted_actions

# 部署时的执行逻辑
def deploy_step(model, obs, action_history):
    # 构建带有空间触觉标签的点云
    labeled_pc = append_contact_labels_to_fingertips(obs.point_cloud, obs.contact_bits)
    
    with torch.no_grad():
        # 潜变量在推理时设为先验均值 (0)
        latent_z = torch.zeros(1, hidden_dim) 
        action_chunk = model(labeled_pc, obs.proprioception, obs.contact_bits, latent_z)
    
    # 时间集成 (Temporal Ensembling): 融合重叠的动作块预测
    target_action = temporal_ensemble(action_history, action_chunk)
    return target_action
```

### 第二模块：核心架构解释

XRoboToolKit-T 的核心架构是一个**人在环路（Human-in-the-loop）与局部自主修正相融合**的控制流。它接收人类通过 XR 设备发出的原始位姿指令，但在下发给机器人底层控制器之前，会经过两个触觉模块的“审查与篡改”：

1.  **触觉感知层 (Tactile Perception):** 夹爪或灵巧手上的压阻式触觉传感器阵列实时采集法向压力分布，将其转化为 $x \times y$ 的压力网格（可视为一张单通道灰度图）。
2.  **接触力稳定器 (Contact Force Stabilizer - 20Hz):** 这是一个高频的启发式安全阀。它通过追踪连续两帧之间最大压力中心点的位移，估算出“伪剪切力”。如果剪切力过大（意味着物体正在滑动或发生了剧烈碰撞），稳定器会输出一个接近 0 的衰减系数，直接削弱或屏蔽人类的遥操作指令，防止破坏。
3.  **VLA 动作微调器 (VLA-based Action Refiner - 7Hz):** 这是一个低频的语义级修正器。它将触觉压力网格当作“图像”输入给 VLA 模型，同时输入任务的语言描述（如“插入医疗注射器”）。VLA 模型基于当前的触觉印记和任务目标，推理出一个微小的空间位姿修正量（$\delta_{refine}$），用于补偿人类操作的微小偏差。
4.  **指令融合 (Action Fusion):** 最终机器人的执行指令 = 当前位姿 + (衰减系数 $\times$ 人类遥操作增量) + VLA 微调增量。

**核心逻辑伪代码实现：**

```python
class XRoboToolKit_T:
    def __init__(self):
        self.vla_model = load_vla_model()
        self.alpha = 0.5 # 稳定器敏感度参数
        self.shear_threshold = 10.0
        
    def stabilizer_step(self, current_pressure_map, last_pressure_map):
        # 1. 寻找最大压力点的位置
        c_t = get_max_pressure_location(current_pressure_map)
        c_t_minus_1 = get_max_pressure_location(last_pressure_map)
        
        # 2. 估算伪剪切力 (基于压力中心位移)
        pseudo_shear_force = calculate_displacement(c_t, c_t_minus_1)
        
        # 3. 计算衰减系数 I_f (抑制人类危险指令)
        if norm(pseudo_shear_force) > self.shear_threshold:
            I_f = 0.0 # 发生剧烈滑动或碰撞，切断人类输入
        else:
            I_f = 1.0 / (1.0 + self.alpha * norm(pseudo_shear_force))
        return I_f

    def vla_refiner_step(self, tactile_image, language_instruction):
        # 将触觉阵列数据作为图像输入 VLA 模型，输出微调动作
        delta_refine = self.vla_model.predict(tactile_image, language_instruction)
        return delta_refine

    def teleoperation_loop(self, human_delta_cmd, tactile_data, instruction):
        # 运行高频稳定器 (20Hz)
        I_f = self.stabilizer_step(tactile_data.current, tactile_data.last)
        
        # 运行低频 VLA 微调器 (7Hz，此处简化为异步获取最新值)
        delta_refine = self.vla_refiner_step(tactile_data.image, instruction)
        
        # 最终指令融合：人类指令被衰减 + VLA 智能微调
        final_action = current_robot_pose + (I_f * human_delta_cmd) + delta_refine
        
        execute_on_robot(final_action)
```

### 第二模块：核心架构解释

UDAV 的运行流程分为三个核心阶段：初始采样、不确定性评估与自适应重思考。

**1. 初始采样 (Initial Sampling)**
给定无人机全局图像、起点和终点，微调后的 VLM（Qwen2.5-VL-7B）通过随机解码生成 $K$ 条（实验中 $K=5$）包含 $N$ 个航点的候选轨迹。

**2. 标称轨迹与不确定性估计 (Nominal Trajectory & Uncertainty Estimation)**
计算 $K$ 条轨迹两两之间的平均欧氏距离。选取到其他所有轨迹距离之和最小的那条轨迹作为中心点轨迹（Medoid），作为当前的标称路线。随后，针对轨迹中的每一个内部航点，计算其在 $K$ 次采样中的经验协方差矩阵，并提取最大特征值进行归一化，得到每个航点的不确定性标量。

**3. 自适应重思考 (Adaptive Reconsideration)**
提取所有航点中的最大不确定性值。如果该值小于或等于预设阈值 $\tau$，则直接输出标称轨迹。如果超过阈值，系统定位到不确定性最大的连续航点区域，构建新的文本提示（告知模型之前的预测存在分歧），并要求 VLM 重新生成 $K_{ref}$ 条轨迹。最终输出这批新轨迹的中心点轨迹。

**核心逻辑伪代码：**

```python
import numpy as np

def compute_medoid(trajectories):
    # trajectories: shape (K, N, 2)
    K = len(trajectories)
    distance_matrix = np.zeros((K, K))
    for i in range(K):
        for j in range(K):
            # 计算两条轨迹之间的平均欧氏距离
            distance_matrix[i, j] = np.mean(np.linalg.norm(trajectories[i] - trajectories[j], axis=1))
    
    # 找到到其他轨迹距离之和最小的索引
    medoid_idx = np.argmin(np.sum(distance_matrix, axis=1))
    return trajectories[medoid_idx]

def compute_uncertainty(trajectories, start_pos, target_pos):
    # trajectories: shape (K, N, 2)
    K, N, _ = trajectories.shape
    uncertainties = np.zeros(N)
    route_length = np.linalg.norm(target_pos - start_pos)
    
    # 仅计算内部航点的不确定性 (排除起点和终点)
    for i in range(1, N - 1):
        waypoints_i = trajectories[:, i, :] # shape (K, 2)
        cov_matrix = np.cov(waypoints_i, rowvar=False)
        
        # 提取最大特征值
        eigenvalues = np.linalg.eigvals(cov_matrix)
        max_eigenvalue = np.max(eigenvalues)
        
        # 归一化不确定性 (基于卡方分布和路线总长度)
        chi2_val = 5.991 # 自由度为2, 95%置信区间
        uncertainties[i] = np.sqrt(chi2_val * max_eigenvalue) / route_length
        
    return np.max(uncertainties), np.argmax(uncertainties)

def udav_planner(vlm, image, start, target, K=5, tau=0.6):
    # 1. 初始采样
    initial_trajectories = vlm.generate_stochastic_trajectories(image, start, target, num_samples=K)
    
    # 2. 计算标称轨迹
    nominal_medoid = compute_medoid(initial_trajectories)
    
    # 3. 计算不确定性
    max_uncertainty, uncertain_idx = compute_uncertainty(initial_trajectories, start, target)
    
    # 4. 自适应重思考
    if max_uncertainty <= tau:
        return nominal_medoid
    else:
        # 触发重思考，向 VLM 提供分歧信息
        reconsider_prompt = build_reconsider_prompt(uncertain_idx)
        refined_trajectories = vlm.generate_stochastic_trajectories(image, start, target, prompt=reconsider_prompt, num_samples=K)
        final_medoid = compute_medoid(refined_trajectories)
        return final_medoid
```

```python
        fused_features = torch.cat([lifted_img_features_3d, depth_features_3d], dim=1)
        fused_features = self.fusion_neck(fused_features)
        occupancy_logits = self.occupancy_head(fused_features) # [B, Num_Classes, X, Y, Z]
        
        return occupancy_logits
```

### 第二模块：核心架构解释

本文的核心架构分为两个部分：**数据集生成流水线**与**基准测试模型架构**。

**1. 数据集生成流水线 (Dataset Generation Pipeline)**
该流程的目的是将原始的3D点云和边界框转化为带有空间逻辑的自然语言。
- **数据提取**：从 KITTI-360 数据集中提取自车位姿、时间戳和3D目标边界框。
- **坐标系转换**：将全局坐标系下的3D边界框转换到以自车为原点的局部坐标系（Ego-centric Frame）。
- **属性计算**：基于纯几何关系，计算目标相对于自车的距离、方位角（通过反正切函数计算）、相对朝向（通过识别边界框前脸计算），并提取目标的运动状态和速度。
- **层级化描述生成**：利用预设的文本模板，首先生成单个对象的描述（Object-level）；然后根据目标的语义类别、动态状态和粗略的相对位置（如左前、右后）进行聚类，生成群组描述（Group-level）。

**2. 基准测试模型架构 (Modified 3DJCG)**
为了验证数据集的有效性，作者修改了现有的 3DJCG 模型。
- **移除检测头**：去除了原有的 VoteNet 目标检测模块，直接接收真实的3D边界框参数。
- **特征增强与关系编码**：将边界框参数（类别、中心点、朝向角、尺寸）通过全连接层编码，并计算目标与自车的距离作为关系特征进行拼接。
- **特征聚合与注意力机制**：在边界框中心点处聚合点云特征，随后输入多头自注意力层（Multi-head Self-attention）进行全局上下文交互。
- **双任务输出**：最终特征分别输入到 Captioning Head（生成文本描述）和 Grounding Head（进行视觉定位）。

**核心逻辑伪代码实现：**

```python
import numpy as np

def compute_ego_centric_attributes(obj_box, ego_pose):
    # 1. 将目标边界框转换到自车局部坐标系
    local_box = transform_to_ego_frame(obj_box, ego_pose)
    
    center_x, center_y = local_box.center.x, local_box.center.y
    
    # 2. 计算相对方位角 (Direction)
    direction_angle = np.arctan2(center_y, center_x)
    
    # 3. 计算相对朝向 (Orientation)
    front_center_x, front_center_y = get_front_face_center(local_box)
    bbox_heading = np.arctan2(front_center_y, front_center_x)
    orientation = abs(bbox_heading - direction_angle)
    
    # 4. 计算相对距离
    distance = np.sqrt(center_x**2 + center_y**2)
    
    return distance, direction_angle, orientation

def generate_neuro_symbolic_captions(objects, ego_pose):
    object_captions = []
    
    # 生成单目标描述
    for obj in objects:
        dist, dir_angle, orient = compute_ego_centric_attributes(obj.box, ego_pose)
        
        # 基于模板的符号化拼接
        caption = f"There is a {obj.dynamic_state} {obj.label}, {dist:.1f} meters away from you, " \
                  f"to your {angle_to_text(dir_angle)}, directed towards {angle_to_text(orient)}."
        if obj.is_dynamic:
            caption += f", moving at {obj.speed} km/h."
            
        object_captions.append(caption)
        
    # 生成群组描述
    groups = group_objects_by_attributes(objects) # 按类别、状态、粗略位置聚类
    group_captions = []
    for group in groups:
        group_cap = f"There are {len(group)} {group.dynamic_state} {group.label}s to your {group.relative_position}."
        group_captions.append(group_cap)
        
    return object_captions, group_captions

def modified_3djcg_forward(gt_bboxes, point_clouds, ego_vehicle_origin):
    # 1. 绕过目标检测，直接编码 Ground-truth 边界框特征
    bbox_features = fully_connected_layers(gt_bboxes.parameters) 
    
    # 2. 关系编码：显式加入目标与自车的距离特征
    relation_features = compute_distances(gt_bboxes.centers, ego_vehicle_origin)
    enhanced_features = concatenate(bbox_features, relation_features)
    
    # 3. 在边界框中心点进行特征聚合 (类似 Set Abstraction)
    aggregated_features = set_abstraction_at_centers(point_clouds, gt_bboxes.centers, enhanced_features)
    
    # 4. 自注意力机制处理全局上下文
    attended_features = multi_head_self_attention(aggregated_features)
    
    # 5. 任务头输出
    captions = captioning_head(attended_features)
    grounding_scores = grounding_head(attended_features)
    
    return captions, grounding_scores
```
