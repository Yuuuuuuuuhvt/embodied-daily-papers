### 第二模块：核心架构解释

WR-Arena 的核心架构并非提出一个新的生成模型，而是构建了一个针对世界模型（WMs）的标准化、多维度评估流水线（Evaluation Pipeline）。其流程主要分为任务定义、数据输入、模型仿真与多维指标计算四个阶段。

1. **任务分类与数据构建 (Task Taxonomy & Dataset Curation)**：定义了涵盖结构化与开放式环境的测试集，包含初始状态（Initial State）、多步指令（Instructions）和目标条件（Goals）。
2. **动作仿真保真度测试 (Action Simulation Fidelity)**：输入初始状态和不同的语义指令，要求 WM 生成对应的反事实轨迹（Counterfactual Rollouts），评估其指令跟随的准确性。
3. **长程预测测试 (Long-horizon Forecast)**：输入长序列动作，要求 WM 进行自回归或长程生成，评估其在长时间跨度下的物理合理性（Physical Plausibility）和时序连贯性（Temporal Coherence）。
4. **仿真推理与规划测试 (Simulative Reasoning and Planning)**：给定特定目标，要求 WM 模拟多种可能的未来分支，通过对比选择出最优路径，评估其目标导向的推理能力。

**核心逻辑伪代码 (Python-style)**：

```python
class WRArena:
    def __init__(self, world_model, evaluator):
        self.wm = world_model          # 待评估的世界模型
        self.evaluator = evaluator     # 自动化评估器（可能包含VLM或物理引擎规则）

    def evaluate_action_fidelity(self, initial_state, instructions):
        # 针对不同指令生成反事实的未来轨迹
        rollouts = self.wm.simulate(initial_state, instructions)
        # 评估轨迹是否符合语义指令及基础物理规律
        score = self.evaluator.check_semantics_and_physics(rollouts, instructions)
        return score

    def evaluate_long_horizon(self, initial_state, long_action_seq):
        # 执行长程自回归仿真
        trajectory = self.wm.simulate_long_term(initial_state, long_action_seq)
        # 评估长程时序连贯性与物理不变量（如物体不凭空消失）
        coherence_score = self.evaluator.check_temporal_consistency(trajectory)
        return coherence_score

    def evaluate_reasoning_planning(self, initial_state, goal):
        # 提出候选动作并模拟多个平行的未来分支
        candidate_actions = self.wm.propose_actions(initial_state, goal)
        futures = [self.wm.simulate(initial_state, action) for action in candidate_actions]
        # 对比不同未来，选择最优路径并验证目标达成率
        best_future = self.evaluator.select_optimal_future(futures, goal)
        success_rate = self.evaluator.check_goal_completion(best_future, goal)
        return success_rate

    def run_benchmark(self, dataset):
        # 遍历数据集，聚合三个维度的得分，输出最终诊断报告
        results = {}
        for data in dataset:
            results['fidelity'] = self.evaluate_action_fidelity(data.state, data.instructions)
            results['long_horizon'] = self.evaluate_long_horizon(data.state, data.long_actions)
            results['planning'] = self.evaluate_reasoning_planning(data.state, data.goal)
        return self.aggregate_scores(results)
```

### 第二模块：核心架构解释

DFM-VLA 的核心架构将视觉、语言和动作统一在离散 token 空间中，并通过离散流匹配实现动作序列的迭代演化。其工作流程如下：

1. **多模态分词与编码**：使用预训练的 Tokenizer 将文本指令、视觉观察（全局与腕部视角）以及连续动作转化为离散 token 序列。
2. **速度场构建（Velocity Field Construction）**：模型不直接输出最终动作，而是预测一个引导 token 演化的“速度场”。论文验证了两种方式：
   - 附加速度头：通过额外的网络头预测替换操作的速度。
   - 动作嵌入引导（最优）：在动作 token 的嵌入空间中定义距离度量，计算将当前噪声 token 转移到预测目标 token 的动力学最优速度。
3. **双阶段解码（Two-Stage Decoding）**：
   - 迭代修正阶段（Iterative Refinement）：利用连续时间马尔可夫链（CTMC）的欧拉离散化，根据速度场计算转移概率，对全序列 token 进行随机跳跃更新。
   - 确定性验证阶段（Deterministic Validation）：在解码的最后几步关闭随机性，切换为贪心解码，强制模型收敛到稳定状态。
4. **自适应 KV 缓存**：在推理时，固定文本和图像的 KV 缓存，仅根据余弦相似度动态更新动作侧的 KV 缓存，大幅降低计算延迟。

```python
def dfm_vla_decode(model, context, T_fine, T_val):
    # T_fine: 迭代修正步数; T_val: 确定性验证步数
    T_total = T_fine + T_val
    
    # 初始化：从词表中均匀采样纯噪声动作序列
    x_t = sample_uniform_noise_sequence()
    
    for k in range(1, T_total + 1):
        step_size_h = 1 / T_total
        
        # 模型基于当前状态和上下文，预测目标干净动作的概率分布
        p_theta = model.predict_logits(x_t, context)
        
        if k <= T_fine:
            # 阶段一：迭代修正 (基于速度场的随机跳跃)
            x_pred = sample_from_distribution(p_theta)
            # 根据动作嵌入距离计算动力学最优速度 (Eq. 7)
            velocity = compute_embedding_guided_velocity(x_pred, x_t)
            # 通过 CTMC 欧拉步骤更新当前 token 序列
            x_t = ctmc_euler_update(x_t, velocity, step_size_h)
        else:
            # 阶段二：确定性验证 (贪心解码，消除随机性以求稳定)
            x_t = argmax(p_theta)
            
    return x_t
```

```python
class WRArena:
    def __init__(self, world_model, evaluator):
        self.wm = world_model          # 待评估的世界模型
        self.evaluator = evaluator     # 自动化评估器（可能包含VLM或物理引擎规则）

    def evaluate_action_fidelity(self, initial_state, instructions):
        # 针对不同指令生成反事实的未来轨迹
        rollouts = self.wm.simulate(initial_state, instructions)
        # 评估轨迹是否符合语义指令及基础物理规律
        score = self.evaluator.check_semantics_and_physics(rollouts, instructions)
        return score

    def evaluate_long_horizon(self, initial_state, long_action_seq):
        # 执行长程自回归仿真
        trajectory = self.wm.simulate_long_term(initial_state, long_action_seq)
        # 评估长程时序连贯性与物理不变量（如物体不凭空消失）
        coherence_score = self.evaluator.check_temporal_consistency(trajectory)
        return coherence_score

    def evaluate_reasoning_planning(self, initial_state, goal):
        # 提出候选动作并模拟多个平行的未来分支
        candidate_actions = self.wm.propose_actions(initial_state, goal)
        futures = [self.wm.simulate(initial_state, action) for action in candidate_actions]
        # 对比不同未来，选择最优路径并验证目标达成率
        best_future = self.evaluator.select_optimal_future(futures, goal)
        success_rate = self.evaluator.check_goal_completion(best_future, goal)
        return success_rate

    def run_benchmark(self, dataset):
        # 遍历数据集，聚合三个维度的得分，输出最终诊断报告
        results = {}
        for data in dataset:
            results['fidelity'] = self.evaluate_action_fidelity(data.state, data.instructions)
            results['long_horizon'] = self.evaluate_long_horizon(data.state, data.long_actions)
            results['planning'] = self.evaluate_reasoning_planning(data.state, data.goal)
        return self.aggregate_scores(results)
```

### 第二模块：核心架构解释

DFM-VLA 的核心架构将视觉、语言和动作统一在离散 token 空间中，并通过离散流匹配实现动作序列的迭代演化。其工作流程如下：

1. **多模态分词与编码**：使用预训练的 Tokenizer 将文本指令、视觉观察（全局与腕部视角）以及连续动作转化为离散 token 序列。
2. **速度场构建（Velocity Field Construction）**：模型不直接输出最终动作，而是预测一个引导 token 演化的“速度场”。论文验证了两种方式：

   - 动作嵌入引导（最优）：在动作 token 的嵌入空间中定义距离度量，计算将当前噪声 token 转移到预测目标 token 的动力学最优速度。
3. **双阶段解码（Two-Stage Decoding）**：
   - 迭代修正阶段（Iterative Refinement）：利用连续时间马尔可夫链（CTMC）的欧拉离散化，根据速度场计算转移概率，对全序列 token 进行随机跳跃更新。
   - 确定性验证阶段（Deterministic Validation）：在解码的最后几步关闭随机性，切换为贪心解码，强制模型收敛到稳定状态。
4. **自适应 KV 缓存**：在推理时，固定文本和图像的 KV 缓存，仅根据余弦相似度动态更新动作侧的 KV 缓存，大幅降低计算延迟。

```python
def dfm_vla_decode(model, context, T_fine, T_val):
    # T_fine: 迭代修正步数; T_val: 确定性验证步数
    T_total = T_fine + T_val
    
    # 初始化：从词表中均匀采样纯噪声动作序列
    x_t = sample_uniform_noise_sequence()
    
    for k in range(1, T_total + 1):
        step_size_h = 1 / T_total
        
        # 模型基于当前状态和上下文，预测目标干净动作的概率分布
        p_theta = model.predict_logits(x_t, context)
        
        if k <= T_fine:
            # 阶段一：迭代修正 (基于速度场的随机跳跃)
            x_pred = sample_from_distribution(p_theta)
            # 根据动作嵌入距离计算动力学最优速度 (Eq. 7)
            velocity = compute_embedding_guided_velocity(x_pred, x_t)
            # 通过 CTMC 欧拉步骤更新当前 token 序列
            x_t = ctmc_euler_update(x_t, velocity, step_size_h)
        else:
            # 阶段二：确定性验证 (贪心解码，消除随机性以求稳定)
            x_t = argmax(p_theta)
            
    return x_t
```

### 第二模块：核心架构解释

VLA-OPD 的核心逻辑是一个迭代的闭环过程，包含两个角色：一个鲁棒的冻结专家模型（Teacher）和一个待训练的目标模型（Student）。整个流程分为三个阶段：

1. **阶段一：同策略采样（On-Policy Sampling）**
学生模型根据当前策略 $\pi_\theta$ 在真实环境中执行动作，收集一组轨迹（Group of trajectories）。由于学生模型能力不足，它会自然地偏离专家路径，进入分布外（OOD）状态。这主动触发了分布偏移，将“未知”的错误状态暴露出来。
2. **阶段二：密集教师标注（Dense Teacher Labeling）**
对于学生模型访问过的每一个状态 $s_t$，查询冻结的教师模型 $\pi_{tea}$，获取其在该状态下的动作概率分布（Logits）。这相当于在学生犯错的瞬间，立刻给出一个最优的纠偏指导，将延迟的稀疏奖励转化为了即时的密集监督信号。
3. **阶段三：寻态优化（Mode-Seeking Optimization）**
计算学生与教师在当前 Token 上的 Reverse-KL 散度，并将其取负作为内在奖励（Intrinsic Reward）。利用类似 GRPO 的组策略梯度方法对学生模型进行参数更新。

**底层逻辑伪代码（Python 风格）**：

```python
def train_vla_opd(student_policy, teacher_policy, env, prompts, group_size, lr):
    # 初始化迭代
    while not converged:
        for prompt in prompts:
            # Phase 1: On-Policy Sampling (Group-based)
            trajectories = []
            for _ in range(group_size):
                # 学生模型在环境中自生成轨迹，暴露 OOD 状态
                traj = env.rollout(student_policy, prompt)
                trajectories.append(traj)
            
            policy_gradients = []
            
            # Phase 2 & 3: Dense Labeling & Optimization
            for traj in trajectories:
                for state, action in traj:
                    # 获取学生和教师的动作概率分布
                    student_logits = student_policy.get_logits(state)
                    teacher_logits = teacher_policy.get_logits(state)
                    
                    # 计算当前动作的 log 概率
                    student_log_prob = compute_log_prob(student_logits, action)
                    teacher_log_prob = compute_log_prob(teacher_logits, action)
                    
                    # 计算内在奖励: Negative Reverse-KL
                    # 注意：计算奖励时对 student_log_prob 使用 stop_gradient (detach)
                    reward = - (student_log_prob.detach() - teacher_log_prob)
                    
                    # 策略梯度损失计算 (Loss = - log_prob * reward)
                    loss = - student_log_prob * reward
                    
                    # 累加梯度
                    grad = compute_gradient(loss, student_policy.parameters())
                    policy_gradients.append(grad)
            
            # 组内梯度平均并更新学生模型参数
            avg_grad = average(policy_gradients)
            student_policy.update_parameters(avg_grad, learning_rate=lr)
```

Realtime-VLA V2 的核心架构是一个解耦的、客户端-服务端分离的后处理流水线。它将 VLA 生成的原始动作块（Action Chunk）转化为机器人可以高速且稳定执行的底层指令。整个流程分为四个关键步骤：

1.  **系统标定与延迟补偿 (Calibration & Compensation):** 测量系统中的图像读取延迟、相机曝光延迟、本体感受延迟以及电机运动延迟。在将状态输入 VLA 之前，对齐图像和关节读数；在输出指令时，对目标位置进行“预放大”以抵消 PD 控制器的滞后。
2.  **速度自适应 (Speed Adaptation):** 接收 VLA 输出的动作块，利用一个通过人类干预数据训练的回归模型，动态预测当前动作块的最佳加速倍率（例如在开阔空间 3x 加速，在精密接触时 1x 速度）。
3.  **时间优化 (Temporal Optimization - Server端):** 在不改变 VLA 预测的空间轨迹点的前提下，通过求解二次规划（QP）问题，重新分配每个时间步的持续时间。其目的是在保持整体高速度的同时，消除局部的加速度突变，保证轨迹平滑。
4.  **空间优化与追踪 (Spatial Optimization & Tracking - Client端):** 在机器人本地高频运行。使用 acados 模型预测控制（MPC）算法，考虑机器人的物理极限（最大速度、加速度）和控制滞后，实时计算出当前周期应该发送给电机的实际指令，确保机器人精准追踪平滑后的轨迹。

```python
    def __init__(self):
        self.vla_model = load_vla_model()
        self.speed_adapter = load_trained_speed_model()
        self.temporal_optimizer = QPSolver()

    def client_side_control_loop(self, smoothed_chunk):
```

### 第二模块：核心架构解释

PiJEPA 的架构在逻辑上高度解耦，分为特征提取、策略先验生成、世界模型规划三个核心阶段。语言指令仅作用于策略端以保证语义对齐，而世界模型端保持语言无关，专注纯粹的视觉-动作物理动力学推演。

**运行流程拆解：**
1. **统一表征空间:** 当前观测图像 $o_t$ 和目标图像 $o_g$ 通过冻结的预训练视觉编码器（DINOv2 或 V-JEPA-2）映射为隐状态 $z_t$ 和 $z_g$。
2. **Stage 1: 策略先验 (Policy Prior):** 微调的 Octo 模型接收 $z_t$ 和语言指令 $\ell$，通过其 Diffusion 头采样出多组动作块。将这些全局坐标系下的动作转换为世界模型所需的局部机体坐标系，并计算出经验均值 $\mu_\pi$ 和标准差 $\sigma_\pi$。
3. **Stage 2: MPPI 规划 (MPPI Planning):** 规划器不再从标准正态分布 $\mathcal{N}(0, I)$ 启动，而是以 $(\mu_\pi, \sigma_\pi)$ 为初始分布采样候选动作序列。
4. **隐空间推演与执行:** JEPA 世界模型接收 $z_t$ 和候选动作，自回归地预测未来 $H$ 步的隐状态 $\hat{z}_{t+H}$。计算终端隐状态与目标 $z_g$ 的 L2 距离作为代价，通过温度加权更新动作分布。迭代 $J$ 次后，执行最优轨迹的第一个动作。

**核心逻辑伪代码 (Python 风格):**

```python
def PiJEPA_planning(obs_t, goal_img, instruction, policy, world_model, encoder, H, N, J):
    # 1. 统一特征编码
    z_t = encoder(obs_t)
    z_g = encoder(goal_img)
    
    # 2. Stage 1: 获取策略先验 (热启动参数)
    action_samples = policy.sample_diffusion(z_t, instruction, num_samples=4)
    local_actions = coordinate_transform(action_samples) # 全局转局部坐标系
    mu_0 = mean(local_actions)
    sigma_0 = clamp(std(local_actions), min=0.01, max=0.05)
    
    # 3. Stage 2: MPPI 迭代寻优
    mu_j, sigma_j = mu_0, sigma_0
    
    for j in range(J):
        # 基于当前分布采样 N 条候选动作序列
        noise = sample_normal(shape=(N, H))
        candidate_actions = clamp(mu_j + sigma_j * noise, -1, 1)
        
        costs = []
        for i in range(N):
            z_hat = z_t
            # 世界模型自回归推演 H 步
            for h in range(H):
                z_hat = world_model.predict_next_latent(z_hat, candidate_actions[i][h])
            
            # 计算终端隐状态与目标的 L2 距离作为代价
            cost = l2_distance(z_hat, z_g)
            costs.append(cost)
            
        # 计算温度加权权重 (代价越小，权重越大)
        weights = compute_temperature_weights(costs, temperature=0.8)
        
        # 更新分布参数
        mu_j = sum(weights * candidate_actions)
        sigma_j = clamp(compute_weighted_std(weights, candidate_actions, mu_j), 0.01, 0.05)
        
    # 4. 返回最优动作序列
    best_action_sequence = sample_elite(candidate_actions, weights)
    return best_action_sequence[0] # 执行第一个动作
```

### 第二模块：核心架构解释

DiffusionAnything 的核心架构是一个多任务、多尺度的图像空间扩散策略（Diffusion Policy）。其工作流程分为上下文提取、多尺度特征调制、轨迹去噪与稀疏深度预测四个阶段。

1. **上下文提取 (Context Representation):** 模型首先接收 RGB 图像，通过一个轻量级 ViT 提取空间注意力图（Attention Map）。随后，将任务模式（导航/抓取）、深度尺度（米/厘米）以及注意力图编码拼接，形成统一的上下文向量 $c$。
2. **多尺度特征调制 (Multi-Scale FiLM):** 在 UNet 的编码器阶段，模型不使用传统的交叉注意力，而是使用 FiLM（特征线性调制）。通过可学习的权重矩阵，模型在处理抓取任务时放大高分辨率（细尺度）特征，在处理导航任务时放大低分辨率（粗尺度）特征。
3. **轨迹对齐的深度预测 (Trajectory-Aligned Depth):** 为了实现 3D 空间推理而不引入稠密深度图的计算开销，模型仅在预测出的 2D 轨迹点（Waypoints）位置上预测深度值。
4. **辅助重建与去噪 (Auxiliary Reconstruction & Denoising):** 训练时引入可通行度（Traversability）和注意力图的辅助重建损失，迫使编码器理解几何与语义。最终通过标准的 DDPM 过程输出去噪后的平滑轨迹。

### 第一模块：一分钟核心速写

1. **论文领域**：VLA
2. **TL;DR**：ETA-VLA 提出了一种基于时序融合与 LLM 内部稀疏化的视觉-语言-动作模型框架，以解决自动驾驶中多视角多帧历史数据导致的 Token 膨胀与计算量爆炸问题，在 NAVSIM v2 基准测试上实现了 SOTA 的驾驶表现并大幅降低了计算成本。

### 第二模块：核心架构解释

ETA-VLA 的架构设计遵循“先时序压缩，后空间稀疏”的逻辑，整体流程分为三个主要阶段：

1. **时序融合模块 (TFM - Temporal Fusion Module)**：
位于 LLM 外部。接收过去 $n$ 帧的多视角图像特征。首先注入可学习的时间嵌入（Time Embedding），然后通过一个 Transformer 编码器捕获时序依赖，最后使用可学习的权重对时间维度进行加权求和，将 $n+1$ 帧的特征压缩为单一的紧凑视觉特征图。
2. **LLM 内部稀疏聚合器 (ILSA - Intra-LLM Sparse Aggregator)**：
位于 LLM 内部的特定层（如第 4 层）。利用文本指令（如“直行”或“左转”）作为锚点，计算视觉 Token 与文本的语义相关性。为了消除旋转位置编码（RoPE）带来的距离偏置，ILSA 在计算剪枝分数时去除了 RoPE 和因果掩码。随后采用两阶段筛选：先全局 Top-K 选出语义最相关的 Token，再通过特征多样性计算回收部分被丢弃的 Token，防止丢失盲区等关键空间信息。
3. **动作解码器 (Action Decoder)**：
不使用 LLM 自回归生成离散动作，而是将 LLM 输出的稀疏隐藏状态作为 Memory，通过一个轻量级的 Transformer Decoder 结合可学习的轨迹查询（Query），直接预测连续的未来轨迹，并由预训练的 Scorer 模块进行优化。

```python
    # hidden_states: [Batch, Seq_Len, Dim]
    
    # 1. 动态文本锚点选择 (Dynamic Text Anchor Selection)
    H_vis = hidden_states[:, visual_indices, :]
    H_text = hidden_states[:, text_indices, :]
    similarity_matrix = softmax(matmul(H_vis, H_text.transpose()), dim=-1)
    text_scores = mean(similarity_matrix, dim_vis)
    # 选出得分高于平均值的文本 Token 作为锚点
    T_rel = H_text[text_scores > mean(text_scores)] 
    
    # 2. 无 RoPE 语义评分 (RoPE-free Semantic Scoring)
    Q_raw = linear_q(hidden_states)
    K_raw = linear_k(hidden_states)
    V = linear_v(hidden_states)
    # 注意：这里不应用 RoPE，也不应用 Causal Mask
    A_prune = softmax(matmul(Q_raw, K_raw.transpose()) / sqrt(dim), dim=-1)
    
    # 计算每个视觉 Token 受到相关文本锚点的平均注意力权重
    visual_importance_scores = mean(A_prune[T_rel_indices, visual_indices], dim_text)
    
    # 3. 多样性保持的 Token 选择 (Diversity-Preserving Selection)
    # 阶段 A: 全局语义 Top-K
    I_global_indices = topk(visual_importance_scores, K_global)
    
    # 阶段 B: 视角内多样性回收
    remaining_indices = visual_indices - I_global_indices
    diversity_scores = compute_feature_distinctiveness(H_vis[remaining_indices])
    I_recycle_indices = topk(diversity_scores, K_recycle)
    
    # 合并保留的 Token
    I_final = union(I_global_indices, I_recycle_indices)
    
    # 4. 标准注意力计算 (仅在保留的 Token 上进行)
    Q_rot, K_rot = apply_RoPE(Q_raw, K_raw)
    output = standard_attention_with_causal_mask(Q_rot, K_rot, V, retained_indices=I_final)
    
    return output
```

### 第一模块：一分钟核心速写

**论文领域：** VLA (Vision-Language-Action 增强的端到端自动驾驶)

**TL;DR:** 本文提出了一种基于多实例学习（MIL）与视觉-语言模型（VLM）的轻量级碰撞检测框架 VLAAD，以解决端到端自动驾驶中碰撞违规率高的问题，在 CARLA 闭环测试和 Real-Collide 真实世界开环基准上实现了显著的驾驶分数与碰撞预测准确率提升。

**研究动机:** 现存端到端（E2E）模型在闭环测试中最大的痛点是极高的碰撞率，且现有模型缺乏显式的碰撞感知表征学习；而现有的 VLM 通常用于低频的通用场景理解，难以提供高频、精准的碰撞预警。本文的切入点极为巧妙：将碰撞检测转化为多实例学习（MIL）问题，利用 VLM 提取多模态特征，生成时间上高度局部化的碰撞风险信号，并将其作为轻量级插件无缝集成到现有驾驶策略中。

**核心机制:** 冻结 X-CLIP 骨干网络，仅训练轻量级视觉适配器和分类头；通过 Log-Sum-Exp 池化聚合视频片段特征（MIL），迫使模型将注意力集中在发生碰撞的极短关键帧上，输出稳定、时间对齐的瞬态碰撞风险分数。

**关键数据:**
- **最能证明有效性的核心数据:** 在 Real-Collide 真实世界数据集上，仅有 0.6B 参数的 VLAAD 的 AUC 达到 0.766，比经过微调的百亿参数 LLaVA-Next (0.533) 提升了 23.3%。理由：这强有力地证明了在特定高风险驾驶场景下，轻量级、针对性适配的 VLM 结合 MIL 机制，其特征提取与泛化效率远超通用大语言视觉模型。
- **存疑的试验结果:** 在 CARLA 闭环测试中，从头训练（From-scratch）的 VLAAD-MIL 模型的行驶里程（111.50 km）高于微调模型，但最终驾驶分数（DS 4.881）却低于仅微调 5 个 Epoch 的模型（DS 5.069）。理由：作者在附录中承认，从头训练的模型在非碰撞违规（如压线、偏离路线）上表现更差。这暗示引入单一的碰撞风险时间信号可能会导致模型产生因果混淆（Causal Confusion），即模型过度关注避撞而忽略了常规交通规则的遵守。

### 第二模块：核心架构解释

VLAAD 的架构设计分为两个独立阶段：基于 MIL 的碰撞检测器训练阶段，以及闭环驾驶模型的集成微调阶段。

**1. 碰撞检测器训练流程 (VLAAD Training)**
模型输入为视频片段（Video Clips）和对应的文本描述（Captions）。视频被划分为多个时间片段（Snippets）。
- **特征提取:** 使用冻结的 X-CLIP 双编码器分别提取文本特征和各视频片段的视觉特征。
- **特征适配:** 视觉特征通过一个轻量级的 MLP（Adapter）进行映射，使其与文本特征在语义空间对齐（使用余弦相似度损失）。
- **多实例学习 (MIL):** 将视频视为一个包含多个片段的 "Bag"。每个片段的视觉特征通过分类头（Detector）输出一个标量 Logit。使用温度控制的 Log-Sum-Exp (LSE) 算子将所有片段的 Logit 聚合为视频级别的碰撞概率，并使用二元交叉熵（BCE）损失进行监督。

**2. 闭环控制集成流程 (Closed-Loop Integration)**
在推理与驾驶模型微调阶段，文本编码器被完全丢弃。
- VLAAD 仅处理历史帧缓存（无未来帧），输出当前时刻的标量碰撞风险分数（Collision Risk Score）。
- 该分数与自车速度、离散导航指令拼接，作为额外的 Token 输入到 TransFuser++ 的全局编码器中。
- 冻结 VLAAD，仅以极小的学习率微调 TransFuser++ 5 个 Epoch，使其学会利用该风险信号调节 Transformer 解码器的轨迹（Waypoints）和速度预测。

**核心逻辑伪代码 (Python-style):**

```python
import torch
import torch.nn as nn

class VLAAD_MIL(nn.Module):
    def __init__(self, xclip_model, hidden_dim=256, gamma=10.0):
        super().__init__()
        self.video_encoder = xclip_model.video_encoder # Frozen
        self.text_encoder = xclip_model.text_encoder   # Frozen
        
        # Trainable lightweight components
        self.adapter = nn.Sequential(
            nn.Linear(768, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim)
        )
        self.detector = nn.Linear(hidden_dim, 1)
        self.gamma = gamma # Temperature for LSE pooling

    def forward_training(self, video_snippets, caption):
        # video_snippets shape: [Batch, T, C, H, W]
        B, T = video_snippets.shape[:2]
        
        with torch.no_grad():
            text_emb = self.text_encoder(caption)
            # Extract features for each snippet
            vis_emb = self.video_encoder(video_snippets.view(B*T, ...)) 
        
        # Adapt visual features
        adapted_vis_emb = self.adapter(vis_emb) # [B*T, hidden_dim]
        
        # Snippet-level collision logits
        snippet_logits = self.detector(adapted_vis_emb).view(B, T) # [B, T]
        
        # MIL Pooling: Log-Sum-Exp over temporal dimension T
        # \hat{z}_{bag} = (1/\gamma) * (log(\sum exp(\gamma * z_t)) - log(T))
        pooled_logits = (1 / self.gamma) * (
            torch.logsumexp(self.gamma * snippet_logits, dim=1) - torch.log(torch.tensor(T))
        )
        
        # Calculate Cosine Loss (adapted_vis_emb vs text_emb) and BCE Loss (pooled_logits vs label)
        return pooled_logits, adapted_vis_emb, text_emb

    def forward_inference(self, frame_buffer):
        # Used during driving model integration (Text encoder discarded)
        with torch.no_grad():
            vis_emb = self.video_encoder(frame_buffer)
            adapted_vis_emb = self.adapter(vis_emb)
            risk_score = torch.sigmoid(self.detector(adapted_vis_emb))
        return risk_score # Scalar passed to TransFuser++

# Integration into Driving Model
class RiskAwareDriver(nn.Module):
    def __init__(self, transfuser_agent, vlaad_module):
        super().__init__()
        self.agent = transfuser_agent
        self.vlaad = vlaad_module # Frozen during fine-tuning
        
    def forward(self, sensor_data, velocity, command, frame_buffer):
        risk_score = self.vlaad.forward_inference(frame_buffer)
        # Concatenate risk score with existing global states
        global_state = torch.cat([velocity, command, risk_score], dim=-1)
        
        # Predict waypoints and target speed
        waypoints, target_speed = self.agent(sensor_data, global_state)
        return waypoints, target_speed
```
