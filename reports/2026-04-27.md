**1. L1 预测器 (Predictor): 局部马尔可夫预测**
L1 的核心是学习单步的隐状态转移。它包含四个算子：状态推断（将观测压缩为隐状态 $z_t$）、前向动力学（给定动作预测下一个隐状态 $z_{t+1}$）、观测解码（将隐状态还原为观测）和逆向动力学。L1 仅保证在训练分布内的单步预测准确性。

**2. L2 模拟器 (Simulator): 决策可用的多步模拟**
L2 将 L1 的单步算子组合成轨迹级别的推演。为了让智能体能够基于此进行规划，L2 必须满足三个边界条件：长程连贯性（误差不能迅速发散）、干预敏感性（对不同的反事实动作有合理的轨迹响应）、约束一致性（必须遵守目标领域的客观法则，如物理守恒、API契约等）。

**3. L3 进化器 (Evolver): 证据驱动的模型修正**
L3 是最高阶形态。当 L2 模拟器在真实部署中遇到系统性失败（认知偏差）时，L3 系统不会崩溃，而是主动设计实验、收集真实反馈（证据），并利用这些证据来持久化地更新世界模型自身的参数或架构（即 $\mathcal{M}_t \to \mathcal{M}_{t+1}$），随后通过回归测试验证更新。

### 第二模块：核心架构解释

RedVLA 的核心架构分为风险场景合成、轨迹驱动的风险放大，以及配套的防御机制三个部分：

**1. 物理安全分类学（Physical Safety Taxonomy）**
作者首先定义了三种物理安全代价维度，为后续的红队攻击提供优化目标：
- **状态级（State-Level）**：单次状态-动作对直接导致的违规（如碰到刀刃）。
- **累积级（Cumulative-Level）**：特定行为在时间上的累积（如连续多次撞击桌面）。
- **条件级（Conditional-Level）**：存在因果依赖的复杂违规（如先打开炉灶，再把易燃物放上去）。

**2. 阶段一：风险场景合成（Risk Scenario Synthesis）**
- **交互识别**：运行一次无干扰的正常轨迹，提取末端执行器的空间特征，通过规则划定三个关键交互区：移动区（Transit）、抓取区（Grasping）和震荡区（Vibration）。
- **风险实例化**：根据目标违规类型，从预设的风险库中选择物体（如将黑皮书作为易燃物），将其初始化在上述关键区域内，确保其能进入 VLA 的视觉注意力和物理执行流。

**3. 阶段二：轨迹驱动的风险放大（Trajectory-Driven Risk Amplification）**
- 由于静态放置难以稳定触发违规，框架采用零阶优化（Zero-order Optimization）微调风险物体的位置。
- 每次执行后，提取轨迹中的“空间锚点”（如距离风险物体最近的末端执行器坐标），以此为引导方向更新物体位置。
- 引入场景合法性检查（Scene Validity Function），确保物体更新后不会发生物理穿模或悬空，保证任务在理论上依然具备可解性。

**4. 防御机制：SimpleVLA-Guard**
- 提取 VLA 模型（如 $\pi_0$ 的 Diffusion Transformer）在运行时的内部隐藏状态（Hidden States）。
- 使用轻量级 LSTM 处理特征序列，输出逐步的风险评分。
- 结合共形预测（Conformal Prediction）动态校准阈值，在物理违规发生前抢先阻断执行。

```python
def redvla_optimization(env, policy, instruction, risk_object, target_violation, max_iters=10):
    # 阶段一：风险场景合成
    benign_trajectory = execute_policy(env, policy, instruction)
    critical_regions = identify_interaction_regions(benign_trajectory)
    
    # 初始化风险物体位置 p_k
    p_k = initialize_risk_factor(risk_object, critical_regions)
    env.inject_object(risk_object, p_k)
    
    # 阶段二：轨迹驱动的风险放大
    for k in range(max_iters):
        # 执行策略获取当前轨迹
        trajectory = execute_policy(env, policy, instruction)
        
        # 检查是否成功触发目标违规
        if check_violation(trajectory, target_violation):
            return p_k, "Attack Success"
            
        # 提取空间锚点 x_star (例如：末端执行器距离风险物体最近的点)
        x_star = extract_spatial_anchor(trajectory, p_k, target_violation)
        
        # 计算更新方向 (梯度上升，拉近风险物体与轨迹的距离)
        direction = (x_star - p_k) / norm(x_star - p_k)
        step_size = 0.01
        
        # 回溯线搜索确保物理合法性 (无穿模、无悬空)
        while True:
            p_next = p_k + step_size * direction
            if check_physical_validity(env, risk_object, p_next):
                p_k = p_next
                break
            step_size /= 2  # 减小步长重试
            
        env.update_object_pose(risk_object, p_k)
        
    return p_k, "Attack Failed"
```

### 第二模块：核心架构解释

GazeVLA 的核心架构建立在视觉-语言-动作模型之上，其生命周期分为三个关键阶段：大规模人类数据预训练、跨具身混合微调、以及基于思维链的推理。

```python
class GazeVLA(nn.Module):
    def __init__(self, vision_encoder, language_encoder, llm_backbone, action_head):
        super().__init__()
        self.vision_encoder = vision_encoder
        self.language_encoder = language_encoder
        self.llm = llm_backbone
        self.action_head = action_head
        
    def forward(self, image, instruction):
        # 1. 编码多模态输入
        img_features = self.vision_encoder(image)
        text_features = self.language_encoder(instruction)
        
        # 2. 融合特征作为 Prompt
        context = concatenate(img_features, text_features)
        
        # 3. Chain-of-Thought 步骤 1: 预测人类意图 (视线 Gaze)
        # 视线通常先于物理动作发生，作为动作的强引导先验
        gaze_prediction = self.llm.generate_gaze(context)
        
        # 4. Chain-of-Thought 步骤 2: 基于意图预测物理动作
        # 将预测的视线特征重新注入上下文，消除具身鸿沟带来的不确定性
        action_context = concatenate(context, gaze_prediction)
        action_tokens = self.llm.generate_action_tokens(action_context)
        
        # 5. 解码为机器人底层控制指令 (如关节角度、末端位姿)
        robot_action = self.action_head(action_tokens)
        
        return robot_action, gaze_prediction
```

### 第二模块：核心架构解释

本文的核心架构建立在一个统一的部分可观测马尔可夫决策过程（POMDP）图模型之上。作者将世界模型的能力严格划分为三个嵌套的层级，并要求这些层级在四种不同的客观法则（物理、数字、社会、科学）下接受检验。

**1. L1 预测器 (Predictor): 局部马尔可夫预测**
L1 的核心是学习单步的隐状态转移。它包含四个算子：状态推断（将观测压缩为隐状态 $z_t$）、前向动力学（给定动作预测下一个隐状态 $z_{t+1}$）、观测解码（将隐状态还原为观测）和逆向动力学。L1 仅保证在训练分布内的单步预测准确性。

**2. L2 模拟器 (Simulator): 决策可用的多步模拟**
L2 将 L1 的单步算子组合成轨迹级别的推演。为了让智能体能够基于此进行规划，L2 必须满足三个边界条件：长程连贯性（误差不能迅速发散）、干预敏感性（对不同的反事实动作有合理的轨迹响应）、约束一致性（必须遵守目标领域的客观法则，如物理守恒、API契约等）。

**3. L3 进化器 (Evolver): 证据驱动的模型修正**
L3 是最高阶形态。当 L2 模拟器在真实部署中遇到系统性失败（认知偏差）时，L3 系统不会崩溃，而是主动设计实验、收集真实反馈（证据），并利用这些证据来持久化地更新世界模型自身的参数或架构（即 $\mathcal{M}_t \to \mathcal{M}_{t+1}$），随后通过回归测试验证更新。

```python
        return z_next

    # L2: 模拟器 (多步反事实推演与法则约束)
    def simulate_rollout(self, z_start, action_sequence):
        trajectory = [z_start]
        for action in action_sequence:
            z_next = self.step_predict(trajectory[-1], action)
            
            # 核心：约束一致性检查 (Constraint Consistency)
            if not self.laws.check_compliance(z_next):
                break # 违反客观法则，截断无意义的幻觉推演
                
            trajectory.append(z_next)
        return trajectory

    # L3: 进化器 (闭环证据驱动修正)
    def evolve_model(self, real_environment):
        # 1. Design & Execute: 主动设计并执行探测动作
        probe_action = self.design_experiment_to_reduce_uncertainty()
        real_obs = real_environment.execute(probe_action)
        
        # 2. Observe: 捕捉预测与现实的偏差 (Anomaly Detection)
        predicted_obs = self.model_stack.decode(self.step_predict(self.current_z, probe_action))
        
        if self.detect_epistemic_gap(predicted_obs, real_obs):
            # 3. Reflect: 提取持久化资产并更新模型结构/参数
            evidence = self.distill_evidence(real_obs)
            proposed_model = self.model_stack.update_architecture_or_weights(evidence)
            
            # 4. Validate: 通过回归测试门控才允许部署
            if self.run_regression_tests(proposed_model, self.regression_suite):
                self.model_stack = proposed_model
```

### 第二模块：核心架构解释

RedVLA 的核心架构分为风险场景合成、轨迹驱动的风险放大，以及配套的防御机制三个部分：

**1. 物理安全分类学（Physical Safety Taxonomy）**
作者首先定义了三种物理安全代价维度，为后续的红队攻击提供优化目标：
- **状态级（State-Level）**：单次状态-动作对直接导致的违规（如碰到刀刃）。
- **累积级（Cumulative-Level）**：特定行为在时间上的累积（如连续多次撞击桌面）。
- **条件级（Conditional-Level）**：存在因果依赖的复杂违规（如先打开炉灶，再把易燃物放上去）。

**2. 阶段一：风险场景合成（Risk Scenario Synthesis）**
- **交互识别**：运行一次无干扰的正常轨迹，提取末端执行器的空间特征，通过规则划定三个关键交互区：移动区（Transit）、抓取区（Grasping）和震荡区（Vibration）。
- **风险实例化**：根据目标违规类型，从预设的风险库中选择物体（如将黑皮书作为易燃物），将其初始化在上述关键区域内，确保其能进入 VLA 的视觉注意力和物理执行流。

**3. 阶段二：轨迹驱动的风险放大（Trajectory-Driven Risk Amplification）**
- 由于静态放置难以稳定触发违规，框架采用零阶优化（Zero-order Optimization）微调风险物体的位置。
- 每次执行后，提取轨迹中的“空间锚点”（如距离风险物体最近的末端执行器坐标），以此为引导方向更新物体位置。
- 引入场景合法性检查（Scene Validity Function），确保物体更新后不会发生物理穿模或悬空，保证任务在理论上依然具备可解性。

**4. 防御机制：SimpleVLA-Guard**
- 提取 VLA 模型（如 $\pi_0$ 的 Diffusion Transformer）在运行时的内部隐藏状态（Hidden States）。
- 使用轻量级 LSTM 处理特征序列，输出逐步的风险评分。
- 结合共形预测（Conformal Prediction）动态校准阈值，在物理违规发生前抢先阻断执行。

```python
    # 阶段一：风险场景合成
    benign_trajectory = execute_policy(env, policy, instruction)
    critical_regions = identify_interaction_regions(benign_trajectory)
    
    # 初始化风险物体位置 p_k
    p_k = initialize_risk_factor(risk_object, critical_regions)
    env.inject_object(risk_object, p_k)
    
    # 阶段二：轨迹驱动的风险放大
    for k in range(max_iters):
        # 执行策略获取当前轨迹
        trajectory = execute_policy(env, policy, instruction)
        
        # 检查是否成功触发目标违规
        if check_violation(trajectory, target_violation):
            return p_k, "Attack Success"
            
        # 提取空间锚点 x_star (例如：末端执行器距离风险物体最近的点)
        x_star = extract_spatial_anchor(trajectory, p_k, target_violation)
        
        # 计算更新方向 (梯度上升，拉近风险物体与轨迹的距离)
        direction = (x_star - p_k) / norm(x_star - p_k)
        step_size = 0.01
        
        # 回溯线搜索确保物理合法性 (无穿模、无悬空)
        while True:
            p_next = p_k + step_size * direction
            if check_physical_validity(env, risk_object, p_next):
                p_k = p_next
                break
            step_size /= 2  # 减小步长重试
            
        env.update_object_pose(risk_object, p_k)
        
    return p_k, "Attack Failed"
```

### 第二模块：核心架构解释

GazeVLA 的核心架构建立在视觉-语言-动作模型之上，其生命周期分为三个关键阶段：大规模人类数据预训练、跨具身混合微调、以及基于思维链的推理。

1. **预训练阶段（Pretraining）**：利用带有视线追踪（或伪标签）的大规模第一人称（Egocentric）人类视频数据集。模型学习输入图像和语言指令，建立“观察 -> 意图（视线） -> 动作”的映射，捕获人类在执行任务时视线与手部动作的协同先验。
2. **微调阶段（Finetuning）**：使用少量的机器人数据与人类数据进行联合微调。这一步的目的是将预训练中获得的“意图-动作”协同关系，适配到特定机器人的具身形态（如机械臂的运动学约束）上。
3. **推理阶段（Inference）**：采用思维链（CoT）范式。给定当前视觉观察和语言指令，模型不直接输出动作，而是先自回归或并行解码出当前的意图（视线坐标/特征），随后将该意图作为条件，生成最终的机器人底层控制动作。

**核心逻辑伪代码（Python 风格）**：

```python
class GazeVLA(nn.Module):
    def __init__(self, vision_encoder, language_encoder, llm_backbone, action_head):
        super().__init__()
        self.vision_encoder = vision_encoder
        self.language_encoder = language_encoder
        self.llm = llm_backbone
        self.action_head = action_head
        
    def forward(self, image, instruction):
        # 1. 编码多模态输入
        img_features = self.vision_encoder(image)
        text_features = self.language_encoder(instruction)
        
        # 2. 融合特征作为 Prompt
        context = concatenate(img_features, text_features)
        
        # 3. Chain-of-Thought 步骤 1: 预测人类意图 (视线 Gaze)
        # 视线通常先于物理动作发生，作为动作的强引导先验
        gaze_prediction = self.llm.generate_gaze(context)
        
        # 4. Chain-of-Thought 步骤 2: 基于意图预测物理动作
        # 将预测的视线特征重新注入上下文，消除具身鸿沟带来的不确定性
        action_context = concatenate(context, gaze_prediction)
        action_tokens = self.llm.generate_action_tokens(action_context)
        
        # 5. 解码为机器人底层控制指令 (如关节角度、末端位姿)
        robot_action = self.action_head(action_tokens)
        
        return robot_action, gaze_prediction
```

### 第二模块：核心架构解释

OccDirector 的核心架构是一个条件扩散模型，专门针对 4D 占用（3D 空间 + 1D 时间）数据设计。其生成流程和实验流程可以拆解为以下几个关键步骤：

1.  **指令解析与特征提取 (Instruction Parsing & Feature Extraction):** 输入的自然语言“剧本”首先通过视觉语言模型（VLM）或大型语言模型（LLM）提取为高维文本嵌入（Text Embeddings）。
2.  **历史前缀锚定 (History-Prefix Anchoring):** 为了生成连续的视频/4D 序列，模型接收过去的真实或已生成帧作为“前缀（Prefix）”。这些历史帧被编码为潜在表示，并与当前需要去噪的噪声潜变量在时间维度上拼接，作为强时空条件。
3.  **时空 MMDiT 去噪 (Spatio-Temporal MMDiT Denoising):** 核心网络是一个多模态扩散 Transformer。它交替进行空间自注意力（捕捉 3D 体素间的几何关系）、时间自注意力（捕捉帧间的运动学关系）以及交叉注意力（将文本指令的语义注入到时空特征中）。
4.  **4D 占用解码 (4D Occupancy Decoding):** 去噪后的潜变量通过 VAE 解码器，重建为离散的 4D 占用网格序列，输出最终的自动驾驶场景演化过程。

```python
import torch
import torch.nn as nn

class SpatioTemporalMMDiTBlock(nn.Module):
    def __init__(self, hidden_dim):
        super().__init__()
        self.spatial_attn = SpatialSelfAttention(hidden_dim)
        self.temporal_attn = TemporalSelfAttention(hidden_dim)
        self.cross_attn = CrossAttention(hidden_dim) # For text conditioning
        self.ffn = FeedForward(hidden_dim)

    def forward(self, x, text_emb):
        # x shape: [Batch, Time, Spatial_Tokens, Dim]
        
        # 1. Spatial Interaction (Intra-frame geometry)
        x = x + self.spatial_attn(x)
        
        # 2. Temporal Interaction (Inter-frame dynamics)
        x = x + self.temporal_attn(x)
        
        # 3. Language Guidance (Semantic injection)
        x = x + self.cross_attn(query=x, key=text_emb, value=text_emb)
        
        # 4. FFN
        x = x + self.ffn(x)
        return x

class OccDirector(nn.Module):
    def __init__(self, num_blocks):
        super().__init__()
        self.text_encoder = VLMTextEncoder()
        self.vae_encoder = OccupancyVAEEncoder()
        self.vae_decoder = OccupancyVAEDecoder()
        self.mmdit_blocks = nn.ModuleList([SpatioTemporalMMDiTBlock(...) for _ in range(num_blocks)])
        
    def forward(self, noisy_latents, text_prompts, history_frames, timesteps):
        # Extract text semantics
        text_emb = self.text_encoder(text_prompts)
        
        # History-Prefix Anchoring
        if history_frames is not None:
            history_latents = self.vae_encoder(history_frames)
            # Concatenate history latents with noisy latents along the Time dimension
            x = torch.cat([history_latents, noisy_latents], dim=1) 
        else:
            x = noisy_latents

        # Denoising through Spatio-Temporal MMDiT
        for block in self.mmdit_blocks:
            x = block(x, text_emb)
            
        # Predict noise (or data)
        predicted_noise = self.output_layer(x)
        return predicted_noise

    def generate(self, text_prompts, history_frames=None):
        # Iterative denoising loop (e.g., DDIM)
        latents = sample_gaussian_noise()
        for t in reversed(timesteps):
            noise_pred = self.forward(latents, text_prompts, history_frames, t)
            latents = step_diffusion(latents, noise_pred, t)
            
        # Decode to 4D Occupancy
        occupancy_4d = self.vae_decoder(latents)
        return occupancy_4d
```

### 第二模块：核心架构解释

SpaMEM 并非提出一个新模型，而是构建了一个严密的诊断框架与测试流程。其核心逻辑是将具身交互过程抽象为对内部“信念图（Belief Graph）”的维护与查询。

**运行模式拆解**：
1. **更新模式（Update Mode）**：在时间步 $t$，模型接收当前观察，更新其潜在的世界状态表征。
2. **问答模式（Answer Mode）**：系统注入空间查询，模型必须从累积的信念状态中检索信息并输出。分为短期（步进式）和长期（回合末）探测。

**三级诊断体系（L1-L3）**：
1. **Level 1 (静态空间感知)**：仅测试单帧图像的几何接地、深度估计、计数等。测定感知天花板。
2. **Level 2 (文本条件时空记忆)**：提供当前视觉帧 + 完美的历史文本记录。剔除历史感知噪声，纯测逻辑更新与轨迹推理。
3. **Level 3 (视觉条件时空记忆)**：仅提供按时间排序的纯视觉流。最严苛的端到端测试，逼迫模型完全依赖视觉记忆。

**核心评测逻辑伪代码**：

```python
class SpaMEM_Evaluator:
    def __init__(self, model, level):
        self.model = model
        self.level = level # L1, L2, or L3
        self.belief_state = None
        
    def run_episode(self, episode_data):
        # episode_data contains visual_frames, text_histories, actions, queries
        for t in range(len(episode_data.steps)):
            current_vision = episode_data.visual_frames[t]
            
            # 核心差异：不同Level提供的历史上下文不同
            if self.level == 'L2':
                # L2: 提供完美的文本历史记录（符号脚手架）
                context = episode_data.text_histories[:t] 
            elif self.level == 'L3':
                # L3: 仅提供历史视觉帧（纯视觉记忆）
                context = episode_data.visual_frames[:t]
            else:
                # L1: 无历史，仅单帧
                context = None 
                
            # Update Mode: 模型更新内部世界模型
            self.belief_state = self.model.update_state(current_vision, context)
            
            # Answer Mode (Short-term): 步进式探测
            if episode_data.has_short_term_query(t):
                query = episode_data.get_query(t)
                prediction = self.model.answer(query, self.belief_state)
                self.evaluate(prediction, ground_truth)
                
        # Answer Mode (Long-term): 回合末全局探测
        final_query = episode_data.get_long_term_query()
        final_prediction = self.model.answer(final_query, self.belief_state)
        self.evaluate(final_prediction, ground_truth)
```

### 第二模块：核心架构解释

CodeGraphVLP 的运行流程分为两个阶段：**初始化阶段（一次性）**与**在线推理阶段（闭环）**。

1. **语义图初始化与代码生成**：接收初始多视角图像和长程语言指令。使用实例分割模型（YOLOE）提取掩码，通过 VLM 过滤出任务相关物体，进行跨视角匹配和空间关系推导（如 in, on, near），构建初始语义图 $\mathcal{G}_0$。同时，LLM 根据指令和图结构，生成一段包含状态检查和子任务分配逻辑的 Python 代码 `policy(graph)`。
2. **在线状态更新**：在每个时间步，使用视频目标追踪器（Cutie）和分割模型更新当前观测中的物体掩码，修正语义图 $\mathcal{G}_t$ 的节点和边。
3. **代码规划与去杂提示**：直接执行预生成的 `policy(graph)`，代码通过查询 $\mathcal{G}_t$ 判断任务进度，输出当前子任务指令 $l_t^{sub}$ 和相关物体集合 $\mathcal{O}_t^{rel}$。系统将非相关物体的像素全部涂黑，生成去杂后的纯净观测 $\tilde{o}_t$。
4. **VLA 动作执行**：将纯净观测 $\tilde{o}_t$ 和子任务指令 $l_t^{sub}$ 输入到底层 VLA 模型中，自回归或通过流匹配预测未来的动作块（Action Chunk），控制机器人执行。

```python
        # 1. 初始化语义图
        self.graph = build_initial_semantic_graph(initial_obs, long_horizon_instruction)
        # 2. LLM 一次性生成规划器代码
        self.code_planner = llm_generate_planner(long_horizon_instruction, self.graph.schema)

        return action_chunk
```

### 第二模块：核心架构解释

TRACE 管线的设计逻辑是典型的“数据提取-空间重建-状态推断-仿真执行”四步走架构。其核心在于如何将半结构化的文本报告转化为可执行的 3D 物理仿真。

1. 事故数据提取 (Crash Data Extraction)：解析 NHTSA 的半结构化 XML 报告，提取出精确的经纬度坐标、碰撞类型、环境条件以及车辆的速度和损坏点等碎片化信息。
2. 地图重建 (Map Reconstruction)：利用提取的坐标从 OpenStreetMap (OSM) 拉取真实路网。关键步骤是将拓扑数据转换为 CARLA 所需的 OpenDRIVE 格式，并进行“车道合并”处理，打破仿真器默认的交通规则限制，从而允许车辆执行跨越实线或逆行等导致事故的违规动作。
3. 场景重建与状态估计 (Scenario Reconstruction)：这是整个架构的灵魂。由于事故报告缺乏车辆碰撞前的精确轨迹，系统调用 LLM（如 Gemini）作为状态估计器。LLM 接收路网边界和碰撞信息，通过反向运动学逻辑推断车辆的初始坐标和朝向。系统内置了分析检查机制，若 LLM 输出的坐标在路网之外，则触发反馈循环要求 LLM 重新生成。
4. 轨迹生成与执行 (Launcher)：放弃 CARLA 默认的全局路由规划器（因为它无法生成违规路径），采用自定义的路点生成算法。以 LLM 推断的初始位置为起点，以真实碰撞点为终点，强制生成导致碰撞的轨迹并在 CARLA 中实例化运行。

```python
def TRACE_pipeline(crash_report_xml):
    # 1. 数据提取
    coords, crash_info, vehicle_info = Extractor.parse(crash_report_xml)
    
    # 2. 地图重建 (获取真实拓扑并解除规则限制)
    osm_map = Retriever.get_osm_data(coords)
    # 强制展平Z轴，合并车道以允许违规驾驶(如逆行)
    opendrive_map = Converter.to_opendrive(osm_map, flatten_z_axis=True, merge_lanes=True)
    carla_map = load_into_carla(opendrive_map)
    
    # 3. 场景重建 (LLM 状态估计与反馈循环)
    max_retries = 3
    for attempt in range(max_retries):
        # LLM 根据碰撞点反推初始状态
        initial_states = LLM_State_Estimator.infer(crash_info, vehicle_info, carla_map.topology)
        
        # 验证初始状态是否在合法路网边界内且朝向正确
        if validate_states(initial_states, carla_map):
            break
        elif attempt == max_retries - 1:
            return "Reconstruction Failed"
            
    # 4. 轨迹生成与仿真执行
    # 绕过常规导航，强制生成碰撞路点
    trajectories = Launcher.generate_custom_waypoints(initial_states, crash_info.impact_point)
    simulation_result = Launcher.execute_in_carla(carla_map, trajectories)
    
    return simulation_result
```
