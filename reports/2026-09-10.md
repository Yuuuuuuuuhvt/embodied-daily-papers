### 第二模块：核心架构解释

Show-Harness 框架将 VLM 置于一个闭环的“感知-推理-动作”（Perceive-Reason-Act）迭代循环中。其核心流程如下：

1. 感知阶段（Perception）：系统捕获多视角视觉观察（全局视角与腕部视角）以及机器人的本体感受状态（如夹爪高度、开闭状态），并通过插件将其转化为文本上下文。
2. 推理阶段（Reasoning）：通过子任务规划（Subtask Planning）、情境规划（Situated Planning）和动作分块（Action Chunking）等插件，对当前上下文进行处理，生成细粒度的动作级决策提示。
3. 动作输出（Action Output）：VLM 基于处理后的上下文，从紧凑的语义动作词表 $\mathcal{A}$ 中输出一个离散动作单元（如 `MV_UP`, `ROTATE_CW`, `GRASP`）。
4. 实体具象化（Embodiment Grounding）：模型无关的、特定于机器人的解释器接收该语义动作单元，结合预设的步长（如 2cm 移动或 15° 旋转），通过运动学计算将其确定性地转化为底层控制指令（如 6-DoF 笛卡尔目标位姿），并驱动机器人执行。

```python
    def __init__(self, vlm_model, robot_interpreter, plugins):
        self.vlm = vlm_model
        self.interpreter = robot_interpreter
        self.plugins = plugins
        self.action_history = []

    def step(self, instruction, visual_obs, proprioception_state):
        # 1. 感知与推理：应用插件构建 VLM 上下文
        context = self._build_context(instruction, visual_obs, proprioception_state)
        
        # 2. 动作输出：VLM 预测离散语义动作单元
        # semantic_action 属于预定义集合 {'MV_FWD', 'MV_BACK', 'GRASP', 'RELEASE', ...}
        semantic_action = self.vlm.predict(context)
        
        # 3. 实体具象化：解释器将语义动作映射为底层物理控制
        # 根据当前末端执行器位姿，计算增量并生成新的 6-DoF 目标位姿
        low_level_control = self.interpreter.ground(semantic_action, proprioception_state)
        
        # 4. 执行并更新历史
        self.action_history.append(semantic_action)
        return low_level_control

    def _build_context(self, instruction, visual_obs, proprioception_state):
        context = {"instruction": instruction, "images": visual_obs}
        for plugin in self.plugins:
            context = plugin.process(context, proprioception_state, self.action_history)
        return context

class RobotInterpreter:
    def __init__(self, embodiment_params):
        self.step_size_translation = embodiment_params.translation_step # e.g., 0.02m
        self.step_size_rotation = embodiment_params.rotation_step       # e.g., 15 degrees
        self.kinematics = embodiment_params.kinematics_solver

    def ground(self, semantic_action, current_pose):
        if semantic_action == 'GRASP':
            return self.kinematics.close_gripper()
        elif semantic_action == 'MV_FWD':
            # 确定性计算：当前位置 + 前向向量 * 步长
            target_pose = current_pose.position + [self.step_size_translation, 0, 0]
            return self.kinematics.solve_ik(target_pose)
```

```python
class GTA2Framework:
    def __init__(self, vlm_models, low_level_controller):
        self.task_agent = vlm_models['task_decomposition']
        self.skill_agent = vlm_models['abstract_skill']
        self.param_agent = vlm_models['parameter_assignment']
        self.grounding_agent = vlm_models['visual_grounding']
        self.controller = low_level_controller

    def synthesize_and_execute(self, instruction, rgbd_obs, human_feedback=None):
        # 1. 任务分解
        subtasks = self.task_agent.decompose(instruction, human_feedback)
        
        for subtask in subtasks:
            # 2. 抽象技能构建 (定义几何与轴)
            abstract_axes = self.skill_agent.construct_axes(subtask, human_feedback)
            
            # 3. 控制器参数分配 (刚度、力阈值等)
            control_params = self.param_agent.assign_params(abstract_axes, human_feedback)
            
            # 4. 视觉接地 (将抽象轴映射到真实 3D 坐标)
            grounded_features = self.grounding_agent.ground_to_3d(
                abstract_axes, rgbd_obs, human_feedback
            )
            
            # 5. 组装最终可执行技能
            executable_skill = self._assemble_skill(control_params, grounded_features)
            
            # 6. 底层控制器执行
            success = self.controller.execute(executable_skill)
            
            if not success:
                return "Execution Failed. Requesting Targeted Human Feedback."
                
        return "Task Completed Successfully."

    def _assemble_skill(self, params, features):
        # 将 3D 坐标与控制参数打包，供底层阻抗控制器调用
        return {"target_pose": features.pose, "axes": features.axes, "stiffness": params.stiffness}
```

```python
def evaluate_motionblind_instance(model, video_A, video_B, q_0, q_1):
    """
    评估单个 MotionBlind 实例的底层逻辑
    q_0: 描述视频 A 运动特征的问题 (例如: "他向左走了吗？")
    q_1: 描述视频 B 运动特征的问题 (例如: "他向右走了吗？")

    pred_A_q0 = model.generate(video_A, q_0) # Ground Truth: Yes
    pred_A_q1 = model.generate(video_A, q_1) # Ground Truth: No

    pred_B_q1 = model.generate(video_B, q_1) # Ground Truth: Yes

    if (pred_A_q0 == "Yes") and (pred_A_q1 == "No") and \
       (pred_B_q0 == "No") and (pred_B_q1 == "Yes"):
        return 1.0  # 实例得分
    else:
        return 0.0  # 只要错一个，即判定为利用捷径，得分为 0
```

### 第一模块：一分钟核心速写

2. **TL;DR**：本文提出了一种基于多步自回归潜在展开与物理参数条件化的 SG-JEPA 模型，以解决现有世界模型在长视野和分布外（OOD）物理参数下动力学泛化能力差的问题，在 2D 物理预测和 3D 机器人控制基准上实现了显著的性能提升。

4. **关键数据**：

- **存疑/局限性数据**：在 2D 形状泛化实验中（附录 E.2），模型在平移预测上表现较好，但在旋转（Rotation）预测上的误差依然较大（如 Small T+S 模型的旋转误差比直接在 House 数据集上训练的模型高出数倍）。理由：这表明模型对复杂非对称刚体接触几何的泛化能力依然存在瓶颈，未能完全解耦形状与旋转动力学，线性理论模型在处理非线性接触时存在局限。

### 第二模块：核心架构解释

SG-JEPA 的核心架构建立在联合嵌入预测架构（JEPA）之上，其处理流程与实验设计可拆解为以下四个阶段：

1. **视觉编码阶段 (Visual Encoding)**：在时间步 $t$，环境观察图像 $o_t$ 通过视觉 Transformer（ViT）编码为低维潜在表征 $z_t$。
2. **动作与物理参数条件化 (Action & Physics Conditioning)**：将外部控制动作 $u_t$ 与标量物理参数（重力 $g$）拼接，通过多层感知机（MLP）映射为条件向量 $c_t$。
3. **自回归动力学预测 (Autoregressive Dynamics Prediction)**：预测器（采用 GRU 或 SSM，而非纯 Transformer）接收长度为 $H$ 的历史潜在状态和条件向量，递归地预测未来 $K$ 步的潜在状态 $\hat{z}_{t+1:t+K}$。在训练时，预测的输出会被反馈回预测器作为下一步的输入。
4. **联合优化目标 (Joint Optimization Objective)**：计算 $K$ 步预测表征与目标表征（由同一编码器生成，无梯度截断）之间的加权 MSE 损失（Rollout Loss），并结合 SIGReg 正则化项防止表征坍塌。梯度同时回传给预测器和编码器。

**核心伪代码实现 (Python-style)**：

```python
import torch
import torch.nn as nn

class SG_JEPA(nn.Module):
    def __init__(self, encoder, action_encoder, predictor, K=5, gamma=0.95, lambda_sig=0.72):
        super().__init__()
        self.encoder = encoder              # ViT encoder
        self.action_encoder = action_encoder # MLP for [action, gravity]
        self.predictor = predictor          # GRU or SSM
        self.K = K                          # Rollout steps
        self.gamma = gamma                  # Discount factor
        self.lambda_sig = lambda_sig        # SIGReg weight

    def forward(self, obs_seq, action_seq, gravity):
        # obs_seq: (B, H+K, C, H, W)
        # action_seq: (B, H+K, A_dim)
        # gravity: (B, 1)
        
        B, total_steps = obs_seq.shape[:2]
        H = total_steps - self.K
        
        # 1. Encode all observations to latents (no stop-gradient for targets)
        z_true = self.encoder(obs_seq) # (B, H+K, Z_dim)
        
        # 2. Condition actions with gravity
        g_seq = gravity.unsqueeze(1).repeat(1, total_steps, 1)
        a_g_seq = torch.cat([action_seq, g_seq], dim=-1)
        c_seq = self.action_encoder(a_g_seq) # (B, H+K, C_dim)
        
        # 3. Autoregressive Rollout
        z_hat_list = []
        # Initialize history context
        z_history = z_true[:, :H] 
        c_history = c_seq[:, :H]
        
        hidden_state = self.predictor.init_hidden(B)
        
        for k in range(self.K):
            # Predict next latent
            z_next_hat, hidden_state = self.predictor(z_history, c_history, hidden_state)
            z_hat_list.append(z_next_hat)
            
            # Update history (shift window, feed prediction back)
            z_history = torch.cat([z_history[:, 1:], z_next_hat.unsqueeze(1)], dim=1)
            c_history = c_seq[:, k+1 : H+k+1]
            
        z_hat = torch.stack(z_hat_list, dim=1) # (B, K, Z_dim)
        z_target = z_true[:, H:]               # (B, K, Z_dim)
        
        # 4. Compute Discounted Rollout Loss
        weights = torch.tensor([self.gamma**i for i in range(self.K)])
        weights = weights / weights.sum()
        
        loss_rollout = 0
        for k in range(self.K):
            mse = torch.mean((z_hat[:, k] - z_target[:, k])**2)
            loss_rollout += weights[k] * mse
            
        # 5. Compute SIGReg Loss on encoded latents
        loss_sigreg = compute_sigreg(z_true)
        
        total_loss = loss_rollout + self.lambda_sig * loss_sigreg
        return total_loss
```

### 第二模块：核心架构解释

Show-Harness 框架将 VLM 置于一个闭环的“感知-推理-动作”（Perceive-Reason-Act）迭代循环中。其核心流程如下：

1. 感知阶段（Perception）：系统捕获多视角视觉观察（全局视角与腕部视角）以及机器人的本体感受状态（如夹爪高度、开闭状态），并通过插件将其转化为文本上下文。
2. 推理阶段（Reasoning）：通过子任务规划（Subtask Planning）、情境规划（Situated Planning）和动作分块（Action Chunking）等插件，对当前上下文进行处理，生成细粒度的动作级决策提示。
3. 动作输出（Action Output）：VLM 基于处理后的上下文，从紧凑的语义动作词表 $\mathcal{A}$ 中输出一个离散动作单元（如 `MV_UP`, `ROTATE_CW`, `GRASP`）。
4. 实体具象化（Embodiment Grounding）：模型无关的、特定于机器人的解释器接收该语义动作单元，结合预设的步长（如 2cm 移动或 15° 旋转），通过运动学计算将其确定性地转化为底层控制指令（如 6-DoF 笛卡尔目标位姿），并驱动机器人执行。

```python
        self.vlm = vlm_model
        self.interpreter = robot_interpreter
        self.plugins = plugins
        self.action_history = []

    def step(self, instruction, visual_obs, proprioception_state):
        # 1. 感知与推理：应用插件构建 VLM 上下文
        context = self._build_context(instruction, visual_obs, proprioception_state)
        
        # 2. 动作输出：VLM 预测离散语义动作单元
        # semantic_action 属于预定义集合 {'MV_FWD', 'MV_BACK', 'GRASP', 'RELEASE', ...}
        semantic_action = self.vlm.predict(context)

        # 根据当前末端执行器位姿，计算增量并生成新的 6-DoF 目标位姿
        low_level_control = self.interpreter.ground(semantic_action, proprioception_state)
        
        # 4. 执行并更新历史
        self.action_history.append(semantic_action)
        return low_level_control

    def _build_context(self, instruction, visual_obs, proprioception_state):
        context = {"instruction": instruction, "images": visual_obs}
        for plugin in self.plugins:
            context = plugin.process(context, proprioception_state, self.action_history)
        return context

class RobotInterpreter:
    def __init__(self, embodiment_params):
        self.step_size_translation = embodiment_params.translation_step # e.g., 0.02m
        self.step_size_rotation = embodiment_params.rotation_step       # e.g., 15 degrees
        self.kinematics = embodiment_params.kinematics_solver

    def ground(self, semantic_action, current_pose):
        if semantic_action == 'GRASP':
            return self.kinematics.close_gripper()
        elif semantic_action == 'MV_FWD':
            # 确定性计算：当前位置 + 前向向量 * 步长
            target_pose = current_pose.position + [self.step_size_translation, 0, 0]
            return self.kinematics.solve_ik(target_pose)
```

### 第二模块：核心架构解释

GTA-2 框架的核心思想是“抽象到接地（Abstraction-to-Grounding）”的因式分解。整个系统由四个职责明确的 VLM 代理串联构成，最终驱动底层的任务轴控制器。

**系统工作流程**：
1. **任务分解代理 (Task Decomposition Agent)**：接收人类的自然语言指令，将其拆解为一系列逻辑连贯的语义子任务。
2. **抽象技能构建代理 (Abstract Skill Construction Agent)**：为每个子任务分配“任务轴（Task Axes）”和关键点，定义纯几何层面的约束（例如：定义一个垂直于抽屉表面的拉力轴）。
3. **参数分配代理 (Parameter Assignment Agent)**：将抽象的几何约束映射到具体的底层控制器参数，如阻抗控制的刚度、力阈值、速度限制等。
4. **视觉接地代理 (Visual Grounding Agent)**：结合 RGB-D 观测，识别并输出前述步骤所需的空间关键点和坐标轴在真实世界中的 3D 坐标。
5. **执行与反馈 (Execution & Feedback)**：将接地的参数输入底层控制器执行。由于中间决策完全透明，若执行失败，人类可以精准定位错误模块（如视觉定位偏差）并提供文本反馈进行修正。

```python
class GTA2Framework:
    def __init__(self, vlm_models, low_level_controller):
        self.task_agent = vlm_models['task_decomposition']
        self.skill_agent = vlm_models['abstract_skill']
        self.param_agent = vlm_models['parameter_assignment']
        self.grounding_agent = vlm_models['visual_grounding']
        self.controller = low_level_controller

    def synthesize_and_execute(self, instruction, rgbd_obs, human_feedback=None):
        # 1. 任务分解
        subtasks = self.task_agent.decompose(instruction, human_feedback)
        
        for subtask in subtasks:
            # 2. 抽象技能构建 (定义几何与轴)
            abstract_axes = self.skill_agent.construct_axes(subtask, human_feedback)
            
            # 3. 控制器参数分配 (刚度、力阈值等)
            control_params = self.param_agent.assign_params(abstract_axes, human_feedback)
            
            # 4. 视觉接地 (将抽象轴映射到真实 3D 坐标)
            grounded_features = self.grounding_agent.ground_to_3d(
                abstract_axes, rgbd_obs, human_feedback
            )
            
            # 5. 组装最终可执行技能
            executable_skill = self._assemble_skill(control_params, grounded_features)
            
            # 6. 底层控制器执行
            success = self.controller.execute(executable_skill)
            
            if not success:
                return "Execution Failed. Requesting Targeted Human Feedback."
                
        return "Task Completed Successfully."

    def _assemble_skill(self, params, features):
        # 将 3D 坐标与控制参数打包，供底层阻抗控制器调用
        return {"target_pose": features.pose, "axes": features.axes, "stiffness": params.stiffness}
```

### 第二模块：核心架构解释

MotionBlind 并非提出新的模型架构，而是为 World Model 的视觉前端设计了一套极度严苛的“体检流程”。其核心方法论可拆解为以下三个维度：

**1. 数据集构造（控制变量法）**
所有视频均为实验室自录，严格控制环境变量。每个实例（Instance）包含视频 A 和视频 B，两者在场景、光照、物体上 100% 相同，唯一的自变量是物理运动属性：
- 速度（Speed）：如搅拌得快与慢。
- 幅度（Magnitude）：如推得远与近。
- 方向（Direction）：如顺时针与逆时针、向左与向右。

**2. 评估协议（2x2 实例级准确率 IAcc）**
每个实例配备两个互补的 Yes/No 问题（$q_0, q_1$）。
- $q_0$ 对视频 A 为 True，对视频 B 为 False。
- $q_1$ 对视频 A 为 False，对视频 B 为 True。
模型必须在 4 次独立推理中全部给出正确答案，该实例才记为 1 分。

**3. 诊断探针（Diagnostic Probes）**
为了探究模型失败的根源，作者引入了三个维度的控制杆：
- **帧数预算**：从 1 帧递增至 24 帧，测试信息量饱和度。
- **抽帧策略**：对比均匀抽帧、随机抽帧、基于 GRPO 训练的 HORNet、免训练的 Frame2Clip。
- **完整性破坏**：移除视频（纯文本）、打乱帧序、倒放帧序。

**底层逻辑伪代码实现**：
```python
def evaluate_motionblind_instance(model, video_A, video_B, q_0, q_1):
    """
    评估单个 MotionBlind 实例的底层逻辑
    q_0: 描述视频 A 运动特征的问题 (例如: "他向左走了吗？")
    q_1: 描述视频 B 运动特征的问题 (例如: "他向右走了吗？")
    """
    # 独立进行 4 次前向推理，获取 Yes/No 预测
    pred_A_q0 = model.generate(video_A, q_0) # Ground Truth: Yes
    pred_A_q1 = model.generate(video_A, q_1) # Ground Truth: No
    
    pred_B_q0 = model.generate(video_B, q_0) # Ground Truth: No
    pred_B_q1 = model.generate(video_B, q_1) # Ground Truth: Yes
    
    # 严格的实例级准确率 (IAcc) 计算：必须 4 项全对
    if (pred_A_q0 == "Yes") and (pred_A_q1 == "No") and \
       (pred_B_q0 == "No") and (pred_B_q1 == "Yes"):
        return 1.0  # 实例得分
    else:
        return 0.0  # 只要错一个，即判定为利用捷径，得分为 0
```

2. **动作与物理参数条件化 (Action & Physics Conditioning)**：将外部控制动作 $u_t$ 与标量物理参数（重力 $g$）拼接，通过多层感知机（MLP）映射为条件向量 $c_t$。
3. **自回归动力学预测 (Autoregressive Dynamics Prediction)**：预测器（采用 GRU 或 SSM，而非纯 Transformer）接收长度为 $H$ 的历史潜在状态和条件向量，递归地预测未来 $K$ 步的潜在状态 $\hat{z}_{t+1:t+K}$。在训练时，预测的输出会被反馈回预测器作为下一步的输入。
4. **联合优化目标 (Joint Optimization Objective)**：计算 $K$ 步预测表征与目标表征（由同一编码器生成，无梯度截断）之间的加权 MSE 损失（Rollout Loss），并结合 SIGReg 正则化项防止表征坍塌。梯度同时回传给预测器和编码器。

```python
import torch.nn as nn

class SG_JEPA(nn.Module):
    def __init__(self, encoder, action_encoder, predictor, K=5, gamma=0.95, lambda_sig=0.72):
        super().__init__()
        self.encoder = encoder              # ViT encoder
        self.action_encoder = action_encoder # MLP for [action, gravity]
        self.predictor = predictor          # GRU or SSM
        self.K = K                          # Rollout steps
        self.gamma = gamma                  # Discount factor
        self.lambda_sig = lambda_sig        # SIGReg weight

    def forward(self, obs_seq, action_seq, gravity):
        # obs_seq: (B, H+K, C, H, W)
        # action_seq: (B, H+K, A_dim)
        # gravity: (B, 1)
        
        B, total_steps = obs_seq.shape[:2]
        H = total_steps - self.K
        
        # 1. Encode all observations to latents (no stop-gradient for targets)
        z_true = self.encoder(obs_seq) # (B, H+K, Z_dim)
        
        # 2. Condition actions with gravity
        g_seq = gravity.unsqueeze(1).repeat(1, total_steps, 1)
        a_g_seq = torch.cat([action_seq, g_seq], dim=-1)
        c_seq = self.action_encoder(a_g_seq) # (B, H+K, C_dim)
        
        # 3. Autoregressive Rollout
        z_hat_list = []
        # Initialize history context
        z_history = z_true[:, :H] 
        c_history = c_seq[:, :H]
        
        hidden_state = self.predictor.init_hidden(B)
        
        for k in range(self.K):
            # Predict next latent
            z_next_hat, hidden_state = self.predictor(z_history, c_history, hidden_state)
            z_hat_list.append(z_next_hat)
            
            # Update history (shift window, feed prediction back)
            z_history = torch.cat([z_history[:, 1:], z_next_hat.unsqueeze(1)], dim=1)
            c_history = c_seq[:, k+1 : H+k+1]
            
        z_hat = torch.stack(z_hat_list, dim=1) # (B, K, Z_dim)
        z_target = z_true[:, H:]               # (B, K, Z_dim)
        
        # 4. Compute Discounted Rollout Loss
        weights = torch.tensor([self.gamma**i for i in range(self.K)])
        weights = weights / weights.sum()
        
        loss_rollout = 0
        for k in range(self.K):
            mse = torch.mean((z_hat[:, k] - z_target[:, k])**2)
            loss_rollout += weights[k] * mse
            
        # 5. Compute SIGReg Loss on encoded latents
        loss_sigreg = compute_sigreg(z_true)
        
        total_loss = loss_rollout + self.lambda_sig * loss_sigreg
        return total_loss
```

1. **策略展开与世界模型想象 (Policy Rollout & World Model Imagination)**
VLA 策略根据当前状态输出动作块（Action Chunks）。世界模型接收当前图像状态和这些动作，自回归地预测未来的图像序列（即想象的轨迹）。

3. **Reward-Soft 策略优化 (Reward-Soft Policy Optimization)**
在计算强化学习的优势函数（Advantage）或奖励时，采用 Reward-Soft 机制。将步骤 2 得到的幻觉分数作为惩罚项或权重调节因子，融入组相对策略优化（GRPO）算法中。如果一段轨迹幻觉严重，其对应的奖励/优势值会被大幅削弱，从而阻止 VLA 策略向产生该动作的方向更新。

### 第二模块：核心架构解释

当前论文的核心架构建立在一个明确的结构因果模型（SCM）之上，包含三个核心方程：
1. 动作生成：$a_t = g(h_t, z_t, u_t)$，动作由操作者习惯 $h$、当前状态 $z$ 和指令 $u$ 决定。

```python
dynamics_f = PhysicsDynamics()  # 共享的物理规律 f
interface_g = HabitInterface()  # 操作者习惯/策略接口 g

def train_world_model_jointly(obs, next_obs, action, wrong_action, margin=0.1):
    """
    阶段一：在多源数据集上联合训练，强制模型对动作敏感
    """
    # 1. 状态编码
    z = encoder(obs)
    z_next_true = encoder(next_obs)
    
    # 2. 物理动力学预测
    z_next_pred = dynamics_f(z, action)
    
    # 3. 动作敏感性对比 (核心创新实现)
    z_next_pred_wrong = dynamics_f(z, wrong_action)
    
    error_true = mse(z_next_pred, z_next_true)
    error_wrong = mse(z_next_pred_wrong, z_next_true)
    
    # 强制错误动作的预测误差必须大于真实动作误差，否则产生惩罚
    hinge_loss = max(0, error_true - error_wrong + margin)
    
    # 联合优化编码器和动力学模型
    total_loss = error_true + lambda_weight * hinge_loss
    total_loss.backward()
    update_weights(encoder, dynamics_f)

def low_shot_adaptation(new_domain_data):
    """
    阶段二：面对新操作者或新视角的少样本迁移
    """
    # 严格冻结共享的物理规律和视觉编码器
    freeze(encoder)
    freeze(dynamics_f)
    
    # 仅微调轻量级接口 g
    for obs, command, true_action in new_domain_data:
        z = encoder(obs)
        pred_action = interface_g(z, command)
        
        loss = mse(pred_action, true_action)
        loss.backward()
        update_weights(interface_g) # 物理规律 f 保持纯洁，不被新数据污染
```

### 第二模块：核心架构解释

Programmable World Model 的核心架构分为三个高度协同的阶段：世界编程与引擎执行、控制信号编译、生成式渲染。

1. **世界编程与引擎执行 (Agent-Orchestrated Box World)**：系统首先利用现成的 3D 检测器从初始图像中提取实体的 3D OBB（定向边界框）。随后，一个基于 VLM 的 Coding Agent 根据用户的自然语言指令，编写出定义实体属性、阵营、动作后果（如扣血、死亡）的可执行程序。在交互过程中，轻量级引擎严格按照这些程序代码更新全局的、持久的 3D 规范世界状态（Canonical World State）。
2. **控制信号编译 (Control Compilation)**：由于视频生成模型无法直接理解抽象的 3D 状态代码，State Compiler 会将引擎输出的 3D OBB 结合目标相机轨迹，投影到 2D 图像空间。它会生成三个像素对齐的特征图：身份图（Identity Map，保持实体外观一致）、语义图（Semantic Map，指示物体类别）、方向图（Direction Map，指示物体在相机坐标系下的绝对运动方向）。
3. **生成式渲染 (Generative Rendering)**：将上述编译好的空间控制信号（Spatial Controls）与目标相机轨迹输入到一个附加了 ControlNet 的预训练视频生成底座中。底座模型负责“脑补” OBB 内部的精细几何、纹理、光影和次级物理动态，最终输出逼真的视频帧。

### 第二模块：核心架构解释

FreqFM 框架不改变现有 VLA 模型的骨干网络（如 $\pi_0$），而是将 Flow Matching 的输入、输出及损失计算转换到 DCT 频域，并利用训练集的动作功率谱（Power Spectrum）对三大核心阶段进行改造：

1.  **频谱匹配源分布（Spectrum-Matched Source）：** 传统的 Flow Matching 使用标准高斯白噪声 $\mathcal{N}(0, I)$ 作为起点。FreqFM 离线统计训练集动作在 DCT 频域的方差（功率谱 $P_{k,d}$），并以此缩放初始噪声。这使得源分布与目标动作分布在频域上具有相同的能量结构，避免了传输路径上的频率尺度突变。
2.  **PSD 归一化自适应目标（PSD-Normalized Adaptive Objective）：** 在频域计算速度回归损失时，由于低频能量极大，直接计算 MSE 会导致低频主导梯度。FreqFM 首先用功率谱 $P_{k,d}$ 对各频率的回归误差进行归一化，随后引入基于似然的多任务学习机制，为每个频率分配可学习的自适应权重。
3.  **频谱传输预算 CFG（Spectral Transport-Budgeted CFG）：** 在推理阶段使用无分类器引导（CFG）时，标准的 CFG 会对所有频率施加相同的标量外推，导致高频噪声爆炸。FreqFM 根据功率谱为每个频率设定了一个“参考传输尺度”作为预算边界。如果某个频率的 CFG 预测残差超出了该预算，则将其径向截断至边界内，从而在增强条件控制的同时保证动作平滑。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch_dct as dct # 假设存在 DCT 库

# --- 离线阶段 ---
# actions: [N, H, D] 训练集动作轨迹
# 计算 DCT 并统计功率谱 P_kd
actions_freq = dct.dct(actions) 
P_kd = torch.mean(actions_freq ** 2, dim=0) # [H, D]

# --- 训练阶段 ---
def compute_freqfm_loss(model, obs, action_target, P_kd, t):
    # 1. 频谱匹配源分布
    epsilon = torch.randn_like(action_target)
    z0_freq = torch.sqrt(P_kd) * epsilon
    
    # 目标动作转频域
    z1_freq = dct.dct(action_target)
    
    # 构建线性插值路径
    zt_freq = (1 - t) * z0_freq + t * z1_freq
    target_velocity_freq = z1_freq - z0_freq
    
    # 模型预测频域速度
    pred_velocity_freq = model(zt_freq, obs, t)
    
    # 2. PSD 归一化自适应目标
    raw_mse = (pred_velocity_freq - target_velocity_freq) ** 2
    normalized_mse = raw_mse / (P_kd + 1e-5)**0.25 # 论文中 rho=0.25
    
    # 结合可学习的自适应尺度 s_kd (多任务权重)
    s_kd = model.get_adaptive_scales() 
    loss = 0.5 * torch.exp(-s_kd) * normalized_mse + 0.5 * s_kd
    return loss.mean()

# --- 推理阶段 (单步 ODE 求解示例) ---
def freqfm_cfg_step(model, zt_freq, obs, null_obs, t, P_kd, beta=1.0):
    # 条件与无条件预测
    v_cond = model(zt_freq, obs, t)
    v_uncond = model(zt_freq, null_obs, t)
    
    # 计算原始 CFG 残差
    residual = v_cond - v_uncond
    
    # 3. 频谱传输预算 CFG 截断
    # 预算半径 R_k 基于 P_kd 计算 (简化表示)
    budget_radius = beta * compute_reference_radius(P_kd) 
    residual_norm = compute_metric_norm(residual, P_kd)
    
    # 径向截断
    clip_factor = torch.clamp(budget_radius / (residual_norm + 1e-5), max=1.0)
    budgeted_residual = residual * clip_factor
    
    # 最终引导速度
    v_guided = v_cond + budgeted_residual
    return v_guided
```

### 第二模块：核心架构解释

RoboDrop 的核心架构分为三个连续的客观执行步骤：

**1. 构建局部验证参考集 (Local Validation Reference)**
对于每一个输入的候选样本，模型首先通过 T5 文本编码器匹配具有相同任务指令的干净验证集样本。随后，利用冻结的 DINO 视觉特征提取器提取当前候选样本与验证集样本的图像特征，计算余弦相似度，检索出视觉最相似的 Top-K 个验证样本。这一步确保了梯度比对发生在相同的任务阶段和视觉状态下。

**2. 在线梯度兼容性打分 (Online Gradient Compatibility Scoring)**
在对候选数据集进行一轮预热训练（Warm-up）时，计算当前候选样本在动作专家（Action Expert）参数上的梯度。同时，提取上述 Top-K 个局部验证样本的梯度并进行加权求和。计算候选样本梯度与局部验证梯度的余弦相似度。为了捕捉模型在训练过程中的动态变化，验证集梯度每隔 M 步优化进行一次重新计算和缓存。

**3. 轨迹级聚合与自动过滤 (Episode-level Aggregation and Automatic Filtering)**
将单步样本的梯度兼容性得分在整条轨迹（Episode）的所有帧上取平均，得到轨迹级得分。利用贝叶斯信息准则（BIC）在单高斯模型和双高斯混合模型（GMM）中进行拟合选择。如果 BIC 倾向于双高斯模型，则将属于低分分布（即梯度兼容性差、被判定为有害更新）的轨迹自动剔除。

DUET-DINO 的核心逻辑在于构建一个能够同时处理并预测两个互补视角（全局侧边视角与局部腕部视角）未来潜在状态的世界模型，并将其用于零样本（Zero-shot）的模型预测控制（MPC）。

**运行流程拆解**：
1. **视觉特征提取**：在当前时间步，分别获取侧边相机和腕部相机的图像，并使用预训练的视觉基础模型（DINOv3）将高维图像压缩为低维的潜在状态表示（Latent Representations）。
2. **跨视角联合预测**：将当前双视角的潜在状态以及候选的 7-DoF 动作序列输入到 DUET-DINO 世界模型中。模型内部通过跨视角条件反射（Cross-View Conditioning，通常通过交叉注意力机制或特征拼接实现），同步预测未来时间步双视角的潜在状态。
3. **零样本潜在规划**：在规划阶段，给定一个目标图像（同样编码为目标潜在状态），规划器（如 MPPI）采样大量候选动作序列。利用 DUET-DINO 预测每个动作序列对应的未来潜在状态轨迹，计算预测状态与目标状态在潜在空间中的距离（Cost），选择代价最小的动作序列执行。

```python
import torch
import torch.nn as nn

class DUET_DINO_WorldModel(nn.Module):
    def __init__(self, vision_encoder, latent_dynamics_model):
        super().__init__()
        # 预训练的视觉编码器 (e.g., DINOv3)，冻结参数
        self.vision_encoder = vision_encoder 
        self.vision_encoder.eval()
        # 联合潜在动力学模型 (Transformer-based)
        self.dynamics_model = latent_dynamics_model 

    def encode_observations(self, img_side, img_wrist):
        """将双视角图像编码为潜在状态"""
        with torch.no_grad():
            z_side = self.vision_encoder(img_side)
            z_wrist = self.vision_encoder(img_wrist)
        return z_side, z_wrist

    def forward(self, z_side_t, z_wrist_t, action_t):
        """
        跨视角条件反射预测：
        输入当前双视角潜在状态和动作，同步预测下一时间步的双视角潜在状态
        """
        # 将双视角特征与动作融合 (具体实现可能依赖 Cross-Attention 或 Concat)
        joint_input = torch.cat([z_side_t, z_wrist_t, action_t], dim=-1)
        
        # 预测残差或直接预测下一帧状态
        z_side_next, z_wrist_next = self.dynamics_model(joint_input)
        return z_side_next, z_wrist_next

def latent_planning(current_img_side, current_img_wrist, goal_img_side, goal_img_wrist, world_model, num_samples, horizon):
    """基于 MPPI 的零样本潜在规划"""
    # 1. 编码当前状态与目标状态
    z_side_curr, z_wrist_curr = world_model.encode_observations(current_img_side, current_img_wrist)
    z_side_goal, z_wrist_goal = world_model.encode_observations(goal_img_side, goal_img_wrist)
    
    # 2. 采样候选动作序列 (7-DoF)
    # actions shape: (num_samples, horizon, 7)
    actions = sample_action_sequences(num_samples, horizon) 
    
    costs = torch.zeros(num_samples)
    
    # 3. 在潜在空间中展开预测并计算代价
    for i in range(num_samples):
        z_s, z_w = z_side_curr, z_wrist_curr
        for t in range(horizon):
            z_s, z_w = world_model(z_s, z_w, actions[i, t])
            
        # 计算预测末端状态与目标状态的潜在空间距离 (L2 或 Cosine)
        cost_side = compute_distance(z_s, z_side_goal)
        cost_wrist = compute_distance(z_w, z_wrist_goal)
        costs[i] = cost_side + cost_wrist # 联合代价
        
    # 4. 返回代价最小的动作序列的第一个动作
    best_action_idx = torch.argmin(costs)
    return actions[best_action_idx, 0]
```

### 第二模块：核心架构解释

TFGCA 是一个插入在 VLA Transformer 主干输出与最终线性动作头（Action Head）之间的轻量级模块。其核心流程分为四个步骤：

1. **动作空间投影 (Action-Space Projection)**：将 Transformer 输出的抽象隐变量 token 投影到具有实际物理意义的控制空间（如关节角度或末端执行器增量），并引入辅助对齐损失（Alignment Loss）进行监督。
2. **逐维度平稳小波变换 (Per-Dimension SWT)**：对投影后的每个动作维度序列应用可学习的平稳小波变换（不降采样，保持时间步对齐），将轨迹分解为低频近似（趋势）和高频细节（微调），生成时频 token。
3. **点积-楔积融合交叉注意力 (Dot-Plus-Wedge Cross-Attention)**：以原始时间 token 为 Query，时频 token 为 Key 和 Value。在计算注意力分数时，不仅计算传统的点积（衡量相似度），还利用柯西-施瓦茨恒等式计算楔积的模长（衡量正交性/张成的平行四边形面积），并通过可学习参数 $\beta$ 将两者融合。
4. **零初始化残差接入 (Zero-Initialized Residual)**：注意力层的输出投影矩阵被初始化为零，确保在初始状态下该模块等价于恒等映射（Identity），从而可以安全地无损接入预训练好的 VLA 模型进行联合微调。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn.functional as F

def wedge_product_magnitude_sq(q, k):
    # 基于柯西-施瓦茨恒等式计算楔积模长的平方: ||q ^ k||^2 = ||q||^2 * ||k||^2 - (q^T * k)^2
    # 避免了复杂的反对称张量构建，直接在标量层面衡量正交性
    q_norm_sq = torch.sum(q ** 2, dim=-1, keepdim=True)
    k_norm_sq = torch.sum(k ** 2, dim=-1, keepdim=True)
    dot_sq = torch.sum(q * k, dim=-1, keepdim=True) ** 2
    return torch.clamp(q_norm_sq * k_norm_sq - dot_sq, min=1e-6)

def time_frequency_geometric_cross_attention(H, F_tokens, W_q, W_k, W_v, W_o, beta_logit):
    # H: 原始时间 tokens (Queries)
    # F_tokens: SWT 提取的时频 tokens (Keys, Values)
    
    Q = W_q(H)
    K = W_k(F_tokens)
    V = W_v(F_tokens)
    
    scale = 1.0 / (Q.shape[-1] ** 0.5)
    
    # 1. 计算传统点积得分 (衡量 Alignment/相似度)
    S_dot = torch.matmul(Q, K.transpose(-1, -2)) * scale
    
    # 2. 计算楔积得分 (衡量 Orthogonality/正交性)
    # 实际实现中需处理多头和维度广播
    S_wed = torch.sqrt(wedge_product_magnitude_sq(Q.unsqueeze(-2), K.unsqueeze(-3))) * scale
    
    # 3. 独立 Softmax 后融合
    beta = torch.sigmoid(beta_logit) # 可学习的融合权重
    A_dot = F.softmax(S_dot, dim=-1)
    A_wed = F.softmax(S_wed, dim=-1)
    
    A_fused = (1 - beta) * A_dot + beta * A_wed
    
    # 4. 聚合 Value 并通过零初始化的输出层
    attended_V = torch.matmul(A_fused, V)
    H_tilde = H + W_o(attended_V) # W_o 初始化为 0
    
    return H_tilde
```

### 第二模块：核心架构解释

本论文的模型架构分为三个连续的阶段：紧凑型动作条件世界模型训练、接触包络校准（共形预测）、以及想象空间中的策略学习。

1. **状态编码与世界模型（World Model）**：
接收历史 RGB 图像、触觉观测（仿真力聚合或真实传感器数据）和本体感觉。通过 CNN 和 MLP 分别提取特征并拼接，投影到 SimNorm 潜在空间。转移网络（Transition Network）在潜在空间中展开，预测未来的末端力、区间峰值力、物体高度、接触状态和任务奖励。
2. **轨迹级校准（Trajectory-level Calibration）**：
使用分割共形校准（Split-conformal calibration）。不依赖单帧误差，而是计算整个接触轨迹上的最大残差。通过校准集计算出一个力容限（Margin $q$），用于界定预测力与真实力之间的误差上界。
3. **想象空间策略学习（Imagined Actor-Critic）**：
冻结训练好的世界模型。Actor 网络通过行为克隆（BC）初始化。在世界模型的潜在空间中向前展开 5 步进行强化学习。奖励函数不仅包含任务奖励，还显式地加入了基于预测峰值力和校准容限 $q$ 的力超载惩罚项。

```python
import torch
import torch.nn.functional as F

# 1. World Model Forward & Loss (Simplified)
def train_world_model(obs_history, actions, targets):
    # Encode history to latent state
    z_t = encoder(obs_history) 
    
    loss = 0
    z_curr = z_t
    for k in range(5): # Unroll 5 steps
        # Predict next latent and outputs
        z_next, pred_force, pred_peak, pred_height, pred_reward = transition_net(z_curr, actions[k])
        
        # Compute losses (Huber for continuous, BCE for contact)
        loss += huber_loss(pred_force, targets.force[k])
        loss += huber_loss(pred_peak, targets.peak[k])
        loss += huber_loss(pred_height, targets.height[k])
        loss += latent_consistency_loss(z_next, target_encoder(targets.obs[k]))
        
        z_curr = z_next
    return loss

# 2. Imagined Actor-Critic with Force Margin Penalty
def train_imagined_policy(z_start, world_model, actor, critic, force_budget=8.0, margin_q=0.0):
    z_curr = z_start.detach() # Freeze world model
    
    discounted_return = 0
    gamma = 0.95
    
    for k in range(5):
        action = actor(z_curr)
        z_next, _, pred_peak, _, pred_task_reward = world_model.transition_net(z_curr, action)
        
        # Core Innovation: Force penalty using predicted peak and calibration margin
        # [max(0, pred_peak) + q - B]_+ / B
        force_excess = F.relu(F.relu(pred_peak) + margin_q - force_budget)
        force_penalty = 0.5 * (force_excess / force_budget) ** 2
        action_penalty = 0.0025 * torch.norm(action, p=2) ** 2
        
        # Step reward
        step_reward = pred_task_reward - force_penalty - action_penalty
        discounted_return += (gamma ** k) * step_reward
        
        z_curr = z_next
        
    # Terminal bootstrap
    terminal_value = critic(z_curr)
    total_objective = discounted_return + (gamma ** 5) * terminal_value
    
    # Maximize objective (minimize negative)
    actor_loss = -total_objective.mean() 
    return actor_loss
```

### 第二模块：核心架构解释

ViBe 的核心架构是一个模块化的“后训练”管道，其本质是在不破坏原有底层运动控制能力的前提下，为其注入视觉感知能力。

**架构流程：**
1. **基础追踪器（Base Tracker）：** 预先训练好一个仅依赖本体感觉（Proprioception）的人形机器人全身运动追踪策略，该策略权重在后续训练中被冻结。
2. **视觉特征提取（Visual Perception）：** 输入 RGB/深度图像，通过冻结的预训练视觉大模型（如 DINOv2 等）提取高维特征。随后通过一个可训练的多查询提取器（Multi-query Extractor）将这些特征压缩并映射为任务相关的视觉反馈向量。
3. **低秩嫁接（LoRA Grafting）：** 将提取出的视觉反馈向量与本体感觉状态拼接。在基础追踪器的策略网络中插入低秩适配器（LoRA）。
4. **策略优化（Policy Optimization）：** 给定任务奖励和参考运动数据集，直接使用强化学习（如 PPO）对多查询提取器和 LoRA 参数进行端到端优化。

```python
class ViBeController(nn.Module):

        super().__init__()
        # 1. 冻结预训练的视觉编码器
        self.visual_encoder = visual_encoder
        for param in self.visual_encoder.parameters():
            param.requires_grad = False
            
        # 2. 冻结基础本体感觉追踪器
        self.base_tracker = base_tracker
        for param in self.base_tracker.parameters():
            param.requires_grad = False
            
        # 3. 可训练的多查询提取器 (提取任务相关视觉特征)
        self.multi_query_extractor = nn.Sequential(
            nn.Linear(visual_encoder.output_dim, 256),
            nn.ReLU(),
            nn.Linear(256, 128)
        )
        
        # 4. 可训练的低秩适配器 (LoRA)，注入到基础追踪器的特定层
        self.lora_A = nn.Linear(128 + base_tracker.proprio_dim, 32, bias=False)
        self.lora_B = nn.Linear(32, base_tracker.action_dim, bias=False)
        
    def forward(self, image, proprioception_state):
        # 视觉通路
        with torch.no_grad():
            dense_visual_features = self.visual_encoder(image)
        
        # 提取任务相关的视觉反馈
        visual_feedback = self.multi_query_extractor(dense_visual_features)
        
        # 状态拼接
        combined_state = torch.cat([proprioception_state, visual_feedback], dim=-1)

        with torch.no_grad():
            base_action = self.base_tracker(proprioception_state)

        lora_action = self.lora_B(self.lora_A(combined_state))
        
        # 最终动作 = 基础动作 + 视觉残差调整
```

### 第二模块：核心架构解释

FedMVLA 的核心架构是一个“客户端解耦处理 - 网络分片传输 - 服务端异构聚合”的闭环系统。

**1. 客户端处理流程 (Client-side Processing)**
客户端在本地私有数据上完成 VLA 模型的单轮训练后，提取视觉（V）、语言（L）、动作（A）三个模块的梯度更新。
- **MAPA (模态感知隐私分配)**：根据预先测定的扰动容忍度，对三者分配不同的差分隐私（DP）预算。动作模块加中等噪声，视觉模块加较小噪声，语言模块加最大噪声。
- **MACO (模态感知通信压缩)**：视觉更新采用 Top-1% 稀疏化（带误差反馈）；语言更新采用 4-bit 量化；动作更新因对控制精度极度敏感，保持 FP32 全精度不压缩。

**2. 6G 网络传输 (Modality-sliced Transport)**
- 动作流（FP32，约 1.2MB）被路由至 6G URLLC（超可靠低延迟通信）切片，确保控制信号的绝对到达。
- 视觉和语言流被路由至 eMBB（增强型移动宽带）切片，容忍一定的延迟和丢包。

**3. 服务端聚合流程 (Server-side MAFA)**
服务端采用多速率、多拓扑的聚合调度：
- **动作 (Action)**：每轮（T=1）聚合，采用**分组聚合**（仅在相同机械臂构型的客户端间聚合，避免运动学冲突）。
- **视觉 (Vision)**：每 5 轮（T=5）聚合，采用**聚类聚合**（基于梯度余弦相似度，将视觉环境相似的客户端聚为一类）。
- **语言 (Language)**：每 10 轮（T=10）聚合，采用**全局聚合**（语言指令具有高度跨域一致性）。
最后，服务端将聚合后的各模态更新重新组装为全局适配器，广播给客户端。

```python
def fedmvla_round(clients, server, round_idx):
    # 1. Local Training & Decoupling
    client_updates = []
    for client in clients:
        # Train locally
        grad_V, grad_L, grad_A = client.train_local_data()
        
        # MAPA: Modality-Aware Privacy Allocation (Adaptive Clipping & Noise)
        noisy_V = add_dp_noise(grad_V, budget='moderate')
        noisy_L = add_dp_noise(grad_L, budget='small')  # Small budget = large noise
        noisy_A = add_dp_noise(grad_A, budget='large')  # Large budget = small noise
        
        # MACO: Modality-Aware Communication Compression
        comp_V = top_k_sparsify(noisy_V, k=0.01, use_error_feedback=True)
        comp_L = quantize_4bit(noisy_L)
        comp_A = noisy_A  # FP32 Uncompressed
        
        client_updates.append({'V': comp_V, 'L': comp_L, 'A': comp_A, 'embodiment': client.type})
        
    # 2. Server-side MAFA: Modality-Aware Federated Aggregation
    # Action: Group-wise by embodiment (Every round)
    if round_idx % 1 == 0:
        server.global_A = aggregate_by_embodiment(client_updates, key='A')
        
    # Vision: Cluster-wise by gradient similarity (Every 5 rounds)
    if round_idx % 5 == 0:
        clusters = spectral_clustering([u['V'] for u in client_updates])
        server.global_V = aggregate_by_cluster(client_updates, clusters, key='V')
        
    # Language: Global FedAvg (Every 10 rounds)
    if round_idx % 10 == 0:
        server.global_L = global_average(client_updates, key='L')
        
    # 3. Reassembly and Broadcast
    global_model = reassemble(server.global_V, server.global_L, server.global_A)
    return global_model
```

### 第二模块：核心架构解释

VALERANT 的核心架构是一个无需额外训练的闭环探索系统，其运行流程分为四个主要阶段：

1.  **反事实生成（Counterfactual Rollouts）**：在当前探索步，系统冻结预训练的动作条件视频世界模型。针对预设的离散动作空间（如前进、左转、右转等），模型基于当前的视觉上下文，并行生成多条对应的未来视频轨迹。
2.  **空间重建（Spatial Reconstruction）**：将生成的每一条视频轨迹输入视觉 SLAM 系统。SLAM 负责估计相机在轨迹中的位姿变化，并将 2D 像素深度化，重建出候选的局部 3D 点云几何。
3.  **策略评估（Policy Evaluation）**：系统在重建的 3D 空间中进行物理校验。首先通过自适应地板估计和双重碰撞检测（点云级与深度级）剔除会发生穿模的非法动作；然后根据空间覆盖率和前进距离对合法动作进行打分。
4.  **状态提交与回溯（Commit & Rewind）**：系统仅将得分最高的动作对应的观测和几何体融合到全局地图中，并更新视觉上下文。如果所有动作均导致碰撞或无法前进（陷入死胡同），系统将触发回溯机制，恢复到历史检查点并封锁错误路径，重新进行探索。

**底层逻辑伪代码实现**：

```python
def valerant_exploration(initial_image, world_model, slam_system, steps):
    # 初始化状态
    visual_context = [initial_image]
    global_map = PointCloud()
    checkpoints = [] # 用于死胡同回溯
    failed_regions = set()
    
    for t in range(steps):
        # 保存当前状态检查点
        checkpoints.append(save_state(visual_context, global_map))
        
        candidate_actions = ['forward', 'turn_left', 'turn_right', 'rotate_left', 'rotate_right']
        best_score = -infinity
        best_action_data = None
        
        # 1. 反事实探索与重建
        for action in candidate_actions:
            # 世界模型生成预测视频
            predicted_video = world_model.generate(visual_context, action)
            
            # SLAM 提取相机轨迹与局部 3D 几何
            camera_trajectory, local_geometry = slam_system.process(predicted_video)
            
            # 2. 鲁棒性物理校验
            floor_plane = estimate_robust_floor(local_geometry)
            is_collision = detect_collision(camera_trajectory, local_geometry, floor_plane, predicted_video)
            
            # 3. 策略评估
            if not is_collision and not in_failed_region(camera_trajectory, failed_regions):
                coverage = calculate_exploration_coverage(local_geometry, global_map)
                progress = calculate_forward_progress(camera_trajectory)
                score = lambda_cov * coverage + lambda_prog * progress
                
                if score > best_score:
                    best_score = score
                    best_action_data = (predicted_video, local_geometry)
        
        # 4. 状态提交或回溯
        if best_action_data is not None:
            # 提交最优动作，更新全局地图与上下文
            selected_video, selected_geometry = best_action_data
            global_map.fuse(selected_geometry)
            visual_context.update(selected_video)
        else:
            # 陷入死胡同，触发回溯机制
```

### 第二模块：核心架构解释

DRiF 的核心架构分为特征提取、双阶段训练分支以及相对风险标签生成机制。

**1. 特征提取与分支结构**
模型接收多源输入（相机、激光雷达、自车状态、导航指令），通过 BEV 编码器提取共享的 BEV 特征 $F_t$。该特征被送入四个分支：
- 辅助感知分支（仅阶段 1）：预测目标检测、语义分割和深度，用于预训练编码器。
- 静态地图分支：预测道路边界、车道线等，使用密集的绝对值标签（交叉熵+Dice Loss）监督。
- 动态风险分支：预测以自车为条件的动态风险场，使用**相对风险监督**。
- 规划分支：基于上述特征输出自车未来轨迹。

**2. 相对风险监督（核心创新）**
由于动态交互风险缺乏客观的绝对真值，DRiF 采用成对排序（Pairwise Ranking）。
- **候选采样**：在自车未来轨迹、周围智能体未来轨迹及潜在冲突区域采样 BEV 点。
- **风险分级与比较**：利用规则安全先验，将点分配到三个优先级递减的风险类别：$R_1$（重叠风险）> $R_2$（走廊风险）> $R_3$（占用风险）。
- **标签生成**：比较点对 $(x_i, x_j)$。如果类别不同，高优先级类别风险更大；如果类别相同，则比较具体规则得分，生成标签 $y_{ij} \in \{+1, -1, 0\}$。
- **损失计算**：使用 Margin Ranking Loss 优化动态风险分支。

**核心逻辑伪代码（Python 风格）**：

```python
import torch
import torch.nn.functional as F

def get_risk_class_and_score(point, rules):
    """根据规则获取风险类别(优先级)和具体得分"""
    overlap_score = rules.compute_overlap(point)
    if overlap_score > rules.threshold_1:
        return 1, overlap_score  # R1: 最高优先级
    
    corridor_score = rules.compute_corridor(point)
    if corridor_score > rules.threshold_2:
        return 2, corridor_score # R2: 次高优先级
        
    occupancy_score = rules.compute_occupancy(point)
    return 3, occupancy_score    # R3: 最低优先级

def generate_pairwise_label(pt_i, pt_j, rules, epsilon=0.1):
    """生成相对风险标签"""
    cls_i, score_i = get_risk_class_and_score(pt_i, rules)
    cls_j, score_j = get_risk_class_and_score(pt_j, rules)
    
    # 1. 跨类别比较 (优先级决定)
    if cls_i < cls_j: return 1   # 类别数值越小，优先级越高，风险越大
    if cls_i > cls_j: return -1
    
    # 2. 同类别比较 (具体得分决定)
    if score_i - score_j > epsilon: return 1
    if score_j - score_i > epsilon: return -1
    return 0

def margin_ranking_loss(pred_risk_map, pairs, labels, margin=1.0):
    """计算动态风险场的排序损失"""
    loss = 0.0
    valid_pairs = 0
    
    for (idx_i, idx_j), y in zip(pairs, labels):
        if y == 0:
            continue # 忽略风险相当的点对
            
        # 从预测的风险场中提取对应位置的风险值
        r_i = pred_risk_map[idx_i]
        r_j = pred_risk_map[idx_j]
        
        # 排序损失：迫使 r_i 和 r_j 的相对大小符合标签 y
        loss += F.relu(margin - y * (r_i - r_j))
        valid_pairs += 1
        
    return loss / max(1, valid_pairs)
```
