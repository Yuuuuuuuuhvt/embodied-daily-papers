1. **输入表征**：文本通过 Qwen2.5 Tokenizer 编码；图像通过 VAE 和 SigLIP2 联合编码；动作轨迹被转换为相对位移并进行线性投影。

```python
            noisy_img, noise_i = self.add_gaussian_noise(target_img, t_noise)

            noisy_img_tokens = self.img_encoder(noisy_img)

            pred_noise_a = self.extract_action_pred(out_seq)
            pred_noise_i = self.extract_image_pred(out_seq)
            
            loss_action = nn.MSELoss()(pred_noise_a, noise_a)
            loss_image = nn.MSELoss()(pred_noise_i, noise_i)
            
            return loss_action + loss_image
            
    def mot_forward(self, seq, mask):

        for layer in self.layers:
```

### 第二模块：核心架构解释

LaMP 的核心逻辑是将 3D 运动预测与机器人动作回归解耦，再通过注意力机制进行特征级融合。其处理流程如下：

1. **多模态输入处理**：接收 2D 图像、语言指令，以及用于构建 3D 场景流的 3D 点云数据。
2. **运动专家（Motion Expert）**：负责理解 3D 运动趋势。网络接收点云和加噪的场景流，利用流匹配（Flow-matching）技术执行**单步部分去噪**。此步骤不追求输出完美的 3D 场景流，而是提取其网络内部的隐藏状态（Hidden States）作为富含 3D 运动趋势的先验特征。
3. **动作专家（Action Expert）**：负责提取常规的视觉-语言特征，并准备回归最终的控制动作。
4. **门控交叉注意力融合（Gated Cross-Attention）**：以动作专家的特征为 Query，运动专家的隐藏状态为 Key 和 Value 进行交叉注意力计算。随后通过一个可学习的门控机制（Gate），动态决定将多少 3D 运动先验注入到动作特征中。
5. **动作输出**：融合后的特征通过动作头（Action Head）回归最终的机器人末端执行器动作。

**核心逻辑伪代码（Python 风格）**：

```python
def forward(image, language, point_cloud, noisy_scene_flow):
    # 1. 基础特征提取
    img_feat = vision_encoder(image)
    lang_feat = language_encoder(language)
    
    # 2. 运动专家 (Motion Expert) - 提取 3D 运动先验
    # 仅执行单步去噪，提取隐藏状态，避免多步生成的开销
    motion_hidden_states, _ = motion_expert(
        point_cloud, 
        noisy_scene_flow, 
        condition=lang_feat, 
        steps=1 # One-step partially denoised
    )
    
    # 3. 动作专家 (Action Expert) - 提取策略特征
    action_feat = action_expert_encoder(img_feat, lang_feat)
    
    # 4. 门控交叉注意力融合 (Gated Cross-Attention)
    # 将 3D 运动先验注入到动作策略中
    attended_motion_feat = cross_attention(
        query=action_feat,
        key=motion_hidden_states,
        value=motion_hidden_states
    )
    
    # 计算门控权重，动态控制先验注入量
    gate = sigmoid(gating_network(action_feat))
    fused_action_feat = action_feat + gate * attended_motion_feat
    
    # 5. 动作回归
    predicted_action = action_head(fused_action_feat)
    
    return predicted_action
```

### 第二模块：核心架构解释

PersistWorld 的核心架构建立在预训练的动作条件视频扩散模型（如 Ctrl-World）之上，通过四个阶段的在线强化学习（RL）协议进行后训练。

**流程详细解释：**

1.  **生成共享前缀 (Generate Shared Prefix):** 从真实的初始观测状态出发，模型在闭环模式下自回归生成 $P$ 个连续的视频片段。$P$ 的长度从均匀分布 $\text{Unif}\{0, 9\}$ 中随机采样。这一步的目的是故意让模型累积自身的生成误差，构建一个逼近真实推理状态的“受损”历史缓冲区。
2.  **分支候选生成 (Branch Candidate Continuations):** 冻结上述生成的历史缓冲区状态，将其作为共享上下文。模型在此基础上独立采样 $K$ 个（实验中 $K=16$）候选的后续视频片段。由于扩散模型的随机性，这 $K$ 个候选会展现出不同的生成轨迹。
3.  **多视角奖励评分 (Score and Rank):** 将生成的 $K$ 个候选片段与保留的 Ground-truth 真实帧进行对比。在三个相机视角（两个外部，一个腕部）上分别计算 LPIPS、SSIM 和 PSNR。将这些指标聚合为一个标量奖励，并在 $K$ 个候选组内进行 Z-score 归一化，映射到 $[0, 1]$ 区间，得到相对优势权重 $r$。
4.  **对比去噪更新 (Contrastive Denoising Update):** 引入一个冻结的参考策略（EMA 模型）。对于每一个候选样本，构建两个隐式 $x_0$ 预测：正向分支（放大当前模型偏离参考模型的方向）和负向分支（反转当前模型偏离参考模型的方向）。利用奖励权重 $r$ 作为插值系数：对于高分样本（$r \to 1$），损失函数倾向于拟合正向分支以强化该生成方向；对于低分样本（$r \to 0$），损失函数倾向于拟合负向分支以惩罚该方向。最终仅通过梯度下降更新 LoRA 适配器和动作编码器。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn.functional as F

def persist_world_rl_step(model, ref_model, batch_data, K=16, beta=0.1):
    # batch_data 包含初始帧 x_0, 动作序列 actions, 真实后续帧 gt_frames
    initial_state, actions, gt_frames = batch_data
    
    # 1. 生成共享前缀 (模拟自回归误差累积)
    P = torch.randint(0, 10, (1,)).item() # 随机前缀长度
    history_buffer = encode_initial_state(initial_state)
    
    with torch.no_grad():
        for p in range(P):
            # 闭环自回归生成
            pred_chunk = model.generate(history_buffer, actions[p])
            history_buffer.append(encode(pred_chunk))
            
    # 2. 分支候选生成
    candidates = []
    for k in range(K):
        # 从冻结的 history_buffer 独立采样 K 个候选
        with torch.no_grad():
            candidate_chunk = model.generate(history_buffer, actions[P])
            candidates.append(candidate_chunk)
            
    # 3. 多视角奖励评分与组内归一化
    rewards = []
    for candidate in candidates:
        # 计算 LPIPS, SSIM, PSNR 的加权和
        raw_reward = compute_visual_reward(candidate, gt_frames[P])
        rewards.append(raw_reward)
        
    rewards = torch.tensor(rewards)
    # Z-score 归一化并缩放到 [0, 1]
    norm_rewards = (rewards - rewards.mean()) / (rewards.std() + 1e-8)
    r_weights = torch.clamp((norm_rewards + 1) / 2, 0, 1)
    
    # 4. 对比去噪更新 (Contrastive Denoising)
    loss = 0
    sigma = sample_noise_level()
    noise = torch.randn_like(gt_frames[P])
    
    for k in range(K):
        x_noisy = candidates[k] + sigma * noise
        
        # 当前模型与参考模型的 x_0 预测
        x0_pred_current = model.predict_x0(x_noisy, sigma, history_buffer, actions[P])
        with torch.no_grad():
            x0_pred_ref = ref_model.predict_x0(x_noisy, sigma, history_buffer, actions[P])
            
        # 构建正向与负向分支
        x0_pos = (1 - beta) * x0_pred_ref + beta * x0_pred_current
        x0_neg = (1 + beta) * x0_pred_ref - beta * x0_pred_current
        
        # 奖励加权损失
        r = r_weights[k]
        loss_pos = r * F.mse_loss(x0_pos, gt_frames[P])
        loss_neg = (1 - r) * F.mse_loss(x0_neg, gt_frames[P])
        loss += (loss_pos + loss_neg)
        
    # 仅更新 LoRA 和 Action Encoder
    loss.backward()
    optimizer.step()
    update_ema(ref_model, model)
```

# 第二模块：核心架构解释

MMaDA-VLA 的核心架构将多模态理解与生成统一在一个基于掩码的离散扩散 Transformer 中。其运行流程可拆解为以下四个关键环节：

1.  **统一离散分词 (Data Tokenization)**
    将所有模态强制对齐到同一离散空间：文本使用 LLaDA 分词器，图像使用 MAGVIT-v2 量化器，连续的机器人动作（如关节角度）被离散化为 256 个 Bin 的 Token。所有 Token 共享同一个词表，消除了模态间的架构壁垒。
2.  **混合注意力机制 (Hybrid Attention)**
    为了适配扩散模型的并行生成特性，模型在 Transformer 内部设计了混合注意力：**模态内**采用双向全注意力（允许图像块之间、动作维度之间进行无序的全局信息交互）；**模态间**采用因果注意力（确保指令和当前观测单向引导未来图像和动作的生成，防止信息穿越）。
3.  **掩码去噪训练 (Masked Token Denoising)**
    训练时，将输入序列分为“指令区”（当前观测+文本）和“生成区”（未来目标图像+动作块）。对“生成区”的 Token 按照余弦调度策略进行随机 Mask（替换为 `[M]`）。模型通过单一的交叉熵损失，学习根据上下文重构这些被 Mask 的 Token。
4.  **并行迭代推理 (Iterative Denoising Inference)**
    推理时，“生成区”初始化为全 Mask 状态。模型进行多步（如 24 步）前向传播，每次预测所有 Token 的概率，保留置信度最高的 Token，将低置信度的 Token 重新 Mask 并进入下一步迭代。为解决高延迟问题，引入了选择性更新的 KV Cache 机制。

**核心逻辑伪代码 (Python 风格):**

```python
import torch.nn.functional as F

class MMaDAVLA(nn.Module):
    def __init__(self, backbone, tokenizer):
        super().__init__()
        self.model = backbone # Large Diffusion Transformer
        self.vocab_size = tokenizer.vocab_size
        
    def train_step(self, instruction_tokens, goal_obs_tokens, action_tokens):
        """
        训练阶段：掩码 Token 预测
        """
        # 1. 拼接生成目标 (未来图像 + 动作块)
        target_seq = torch.cat([goal_obs_tokens, action_tokens], dim=-1)
        seq_len = target_seq.shape[-1]
        
        # 2. 采样 Mask 比例 (基于余弦调度)
        mask_ratio = sample_cosine_schedule()
        num_mask = int(mask_ratio * seq_len)
        
        # 3. 构造 Masked 序列
        mask_indices = torch.randperm(seq_len)[:num_mask]
        masked_target = target_seq.clone()
        masked_target[:, mask_indices] = MASK_TOKEN_ID
        
        # 4. 拼接完整输入序列
        input_seq = torch.cat([instruction_tokens, masked_target], dim=-1)
        
        # 5. 前向传播 (应用混合注意力掩码)
        logits = self.model(input_seq, attention_mask=self.get_hybrid_attn_mask())
        
        # 6. 计算损失 (仅在被 Mask 的位置计算交叉熵)
        pred_logits = logits[:, instruction_tokens.shape[-1]:] # 取出生成区预测
        loss = F.cross_entropy(pred_logits[:, mask_indices], target_seq[:, mask_indices])
        
        return loss

    @torch.no_grad()
    def inference_step(self, instruction_tokens, steps=24):
        """
        推理阶段：迭代去噪生成
        """
        target_len = GOAL_OBS_LEN + ACTION_CHUNK_LEN
        # 初始化为全 Mask
        current_target = torch.full((1, target_len), MASK_TOKEN_ID)
        
        for d in reversed(range(steps)):
            input_seq = torch.cat([instruction_tokens, current_target], dim=-1)
            
            # 前向传播 (利用 KV Cache 加速)
            logits = self.model(input_seq, use_kv_cache=True)
            pred_logits = logits[:, instruction_tokens.shape[-1]:]
            
            # 贪婪解码获取当前步预测
            pred_tokens = torch.argmax(pred_logits, dim=-1)
            confidence_scores = torch.max(F.softmax(pred_logits, dim=-1), dim=-1).values
            
            if d == 0:
                current_target = pred_tokens
                break
                
            # 计算下一步需要保留的 Mask 比例
            next_mask_ratio = cosine_schedule_ratio(d, steps)
            num_mask = int(next_mask_ratio * target_len)
            
            # 根据置信度重新 Mask (保留高置信度，Mask 低置信度)
            mask_threshold = torch.kthvalue(confidence_scores, num_mask).values
            remask_indices = confidence_scores < mask_threshold
            
            current_target = pred_tokens.clone()
            current_target[remask_indices] = MASK_TOKEN_ID
            
        # 拆分输出
        goal_obs = current_target[:, :GOAL_OBS_LEN]
        action_chunk = current_target[:, GOAL_OBS_LEN:]
        
        return goal_obs, action_chunk
```

### 第二模块：核心架构解释

AirVLA 的核心架构分为两个独立但互补的流程：**数据合成与微调阶段**，以及**物理引导的推理阶段**。

2. **负载感知引导（推理期）**：在实际部署时，模型采用流匹配（Flow-Matching）生成动作。AirVLA 在常微分方程（ODE）的求解步中，计算当前预测动作在特定负载质量下违反物理约束的代价（Cost），并求取该代价对动作的梯度。将此梯度作为引导项（Guidance）注入到流匹配的向量场中，从而在不改变模型权重的前提下，强制生成的动作符合无人机的飞行物理学。

```python
def payload_aware_flow_matching_inference(vla_model, observation, payload_mass, num_steps=50, guidance_scale=0.1):
    """
    带有负载感知引导的流匹配推理过程
    """
    # 1. 从标准正态分布初始化动作噪声
    x_t = sample_standard_normal(shape=vla_model.action_dim)
    dt = 1.0 / num_steps
    
    for t in reversed(range(num_steps)):
        time_step = t / num_steps
        
        # 2. VLA 模型预测当前步的向量场 (Vector Field)
        v_pred = vla_model.predict_vector_field(x_t, observation, time_step)
        
        # 3. 计算物理约束代价 (Physics Cost)
        # 评估当前动作 x_t 在给定 payload_mass 下是否会导致无人机失稳或超出推力极限
        cost = compute_physics_violation_cost(x_t, payload_mass)
        
        # 4. 计算代价关于动作 x_t 的梯度
        cost_grad = compute_gradient(cost, x_t)
        
        # 5. 注入负载感知引导 (Payload-Aware Guidance)
        # 修改向量场，使其朝着降低物理违规代价的方向移动
        v_guided = v_pred - guidance_scale * cost_grad
        
        # 6. 欧拉积分更新动作
        x_t = x_t + v_guided * dt
        
    return x_t # 返回最终符合物理约束的动作
```

### 第二模块：核心架构解释

Vega 的核心架构摒弃了传统的感知-预测-规划级联模块，采用了一种名为 Integrated Transformer 的混合架构，将自回归（用于多模态理解）和扩散（用于图像与动作生成）统一在同一个网络中。其底层逻辑是通过交错拼接历史图像、历史动作和当前指令，利用因果注意力机制（Causal Attention）和混合变压器（Mixture-of-Transformers, MoT）实现跨模态的特征对齐与联合预测。

**核心流程拆解**：
1. **输入表征**：文本通过 Qwen2.5 Tokenizer 编码；图像通过 VAE 和 SigLIP2 联合编码；动作轨迹被转换为相对位移并进行线性投影。
2. **序列构建**：将历史图像、历史动作、当前指令按时间因果顺序交错拼接。在训练时，将加噪的未来动作（Noisy Action）和加噪的未来图像（Noisy Image）附加在序列末尾。
3. **MoT 路由与注意力计算**：采用分块下三角掩码（Blocked Lower Triangular Mask）确保严格的因果关系。序列中的不同模态 Token 被路由到独立的 Transformer 权重中（理解模块、图像生成模块、动作生成模块），但在计算全局注意力时又被重新组合，实现信息互通。
4. **联合去噪优化**：在单阶段训练中，同时计算动作的 MSE 损失和未来图像 VAE 潜变量的 MSE 损失。

```python
import torch
import torch.nn as nn

class VegaModel(nn.Module):
    def __init__(self):
        super().__init__()
        # 编码器
        self.text_encoder = Qwen2_5_Tokenizer()
        self.img_encoder = VAE_plus_SigLIP2()
        self.action_proj = nn.Linear(action_dim, hidden_dim)
        
        # Mixture-of-Transformers (MoT) 独立权重
        self.understanding_transformer = TransformerBlocks(init="Qwen2.5")
        self.generation_transformer = TransformerBlocks(init="Bagel-7B")
        self.action_transformer = TransformerBlocks(hidden_size=256)
        
    def forward(self, hist_imgs, hist_actions, instruction, target_action=None, target_img=None, t_noise=None):
        # 1. 模态编码
        img_tokens = self.img_encoder(hist_imgs)
        action_tokens = self.action_proj(hist_actions)
        text_tokens = self.text_encoder(instruction)
        
        # 2. 构建交错序列 (Interleaving Sequence)
        # 格式: [I_t-T, A_t-T, ..., I_t, L_t]
        context_seq = self.build_interleaved_sequence(img_tokens, action_tokens, text_tokens)
        
        # 3. 训练阶段：注入噪声并拼接目标
        if self.training:
            noisy_action, noise_a = self.add_gaussian_noise(target_action, t_noise)
            noisy_img, noise_i = self.add_gaussian_noise(target_img, t_noise)
            
            noisy_action_tokens = self.action_proj(noisy_action)
            noisy_img_tokens = self.img_encoder(noisy_img)
            
            # 拼接完整序列
            full_seq = torch.cat([context_seq, noisy_action_tokens, noisy_img_tokens], dim=1)
            
            # 4. 生成因果注意力掩码 (Blocked Lower Triangular)
            causal_mask = self.generate_causal_mask(full_seq)
            
            # 5. MoT 前向传播 (按模态路由到不同权重，但共享注意力计算)
            out_seq = self.mot_forward(full_seq, causal_mask)
            
            # 6. 提取预测结果并计算损失
            pred_noise_a = self.extract_action_pred(out_seq)
            pred_noise_i = self.extract_image_pred(out_seq)
            
            loss_action = nn.MSELoss()(pred_noise_a, noise_a)
            loss_image = nn.MSELoss()(pred_noise_i, noise_i)
            
            return loss_action + loss_image
            
    def mot_forward(self, seq, mask):
        # 伪代码：展示 MoT 路由逻辑
        for layer in self.layers:
            # 拆分模态
            text_vis_tokens, img_gen_tokens, act_tokens = self.split_modalities(seq)
            
            # 独立 FFN/Attention 权重处理
            text_vis_out = self.understanding_transformer(text_vis_tokens)
            img_gen_out = self.generation_transformer(img_gen_tokens)
            act_out = self.action_transformer(act_tokens)
            
            # 重新组合以计算全局 Causal Attention
            seq = self.recombine_and_attend(text_vis_out, img_gen_out, act_out, mask)
        return seq
```

### 第二模块：核心架构解释

LaMP 的核心逻辑是将 3D 运动预测与机器人动作回归解耦，再通过注意力机制进行特征级融合。其处理流程如下：

1. **多模态输入处理**：接收 2D 图像、语言指令，以及用于构建 3D 场景流的 3D 点云数据。
2. **运动专家（Motion Expert）**：负责理解 3D 运动趋势。网络接收点云和加噪的场景流，利用流匹配（Flow-matching）技术执行**单步部分去噪**。此步骤不追求输出完美的 3D 场景流，而是提取其网络内部的隐藏状态（Hidden States）作为富含 3D 运动趋势的先验特征。
3. **动作专家（Action Expert）**：负责提取常规的视觉-语言特征，并准备回归最终的控制动作。
4. **门控交叉注意力融合（Gated Cross-Attention）**：以动作专家的特征为 Query，运动专家的隐藏状态为 Key 和 Value 进行交叉注意力计算。随后通过一个可学习的门控机制（Gate），动态决定将多少 3D 运动先验注入到动作特征中。
5. **动作输出**：融合后的特征通过动作头（Action Head）回归最终的机器人末端执行器动作。

**核心逻辑伪代码（Python 风格）**：

```python
def forward(image, language, point_cloud, noisy_scene_flow):
    # 1. 基础特征提取
    img_feat = vision_encoder(image)
    lang_feat = language_encoder(language)
    
    # 2. 运动专家 (Motion Expert) - 提取 3D 运动先验
    # 仅执行单步去噪，提取隐藏状态，避免多步生成的开销
    motion_hidden_states, _ = motion_expert(
        point_cloud, 
        noisy_scene_flow, 
        condition=lang_feat, 
        steps=1 # One-step partially denoised
    )
    
    # 3. 动作专家 (Action Expert) - 提取策略特征
    action_feat = action_expert_encoder(img_feat, lang_feat)
    
    # 4. 门控交叉注意力融合 (Gated Cross-Attention)
    # 将 3D 运动先验注入到动作策略中
    attended_motion_feat = cross_attention(
        query=action_feat,
        key=motion_hidden_states,
        value=motion_hidden_states
    )
    
    # 计算门控权重，动态控制先验注入量
    gate = sigmoid(gating_network(action_feat))
    fused_action_feat = action_feat + gate * attended_motion_feat
    
    # 5. 动作回归
    predicted_action = action_head(fused_action_feat)
    
    return predicted_action
```

### 第二模块：核心架构解释

PersistWorld 的核心架构建立在预训练的动作条件视频扩散模型（如 Ctrl-World）之上，通过四个阶段的在线强化学习（RL）协议进行后训练。

**流程详细解释：**

1.  **生成共享前缀 (Generate Shared Prefix):** 从真实的初始观测状态出发，模型在闭环模式下自回归生成 $P$ 个连续的视频片段。$P$ 的长度从均匀分布 $\text{Unif}\{0, 9\}$ 中随机采样。这一步的目的是故意让模型累积自身的生成误差，构建一个逼近真实推理状态的“受损”历史缓冲区。
2.  **分支候选生成 (Branch Candidate Continuations):** 冻结上述生成的历史缓冲区状态，将其作为共享上下文。模型在此基础上独立采样 $K$ 个（实验中 $K=16$）候选的后续视频片段。由于扩散模型的随机性，这 $K$ 个候选会展现出不同的生成轨迹。
3.  **多视角奖励评分 (Score and Rank):** 将生成的 $K$ 个候选片段与保留的 Ground-truth 真实帧进行对比。在三个相机视角（两个外部，一个腕部）上分别计算 LPIPS、SSIM 和 PSNR。将这些指标聚合为一个标量奖励，并在 $K$ 个候选组内进行 Z-score 归一化，映射到 $[0, 1]$ 区间，得到相对优势权重 $r$。
4.  **对比去噪更新 (Contrastive Denoising Update):** 引入一个冻结的参考策略（EMA 模型）。对于每一个候选样本，构建两个隐式 $x_0$ 预测：正向分支（放大当前模型偏离参考模型的方向）和负向分支（反转当前模型偏离参考模型的方向）。利用奖励权重 $r$ 作为插值系数：对于高分样本（$r \to 1$），损失函数倾向于拟合正向分支以强化该生成方向；对于低分样本（$r \to 0$），损失函数倾向于拟合负向分支以惩罚该方向。最终仅通过梯度下降更新 LoRA 适配器和动作编码器。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn.functional as F

def persist_world_rl_step(model, ref_model, batch_data, K=16, beta=0.1):
    # batch_data 包含初始帧 x_0, 动作序列 actions, 真实后续帧 gt_frames
    initial_state, actions, gt_frames = batch_data
    
    # 1. 生成共享前缀 (模拟自回归误差累积)
    P = torch.randint(0, 10, (1,)).item() # 随机前缀长度
    history_buffer = encode_initial_state(initial_state)
    
    with torch.no_grad():
        for p in range(P):
            # 闭环自回归生成
            pred_chunk = model.generate(history_buffer, actions[p])
            history_buffer.append(encode(pred_chunk))
            
    # 2. 分支候选生成
    candidates = []
    for k in range(K):
        # 从冻结的 history_buffer 独立采样 K 个候选
        with torch.no_grad():
            candidate_chunk = model.generate(history_buffer, actions[P])
            candidates.append(candidate_chunk)
            
    # 3. 多视角奖励评分与组内归一化
    rewards = []
    for candidate in candidates:
        # 计算 LPIPS, SSIM, PSNR 的加权和
        raw_reward = compute_visual_reward(candidate, gt_frames[P])
        rewards.append(raw_reward)
        
    rewards = torch.tensor(rewards)
    # Z-score 归一化并缩放到 [0, 1]
    norm_rewards = (rewards - rewards.mean()) / (rewards.std() + 1e-8)
    r_weights = torch.clamp((norm_rewards + 1) / 2, 0, 1)
    
    # 4. 对比去噪更新 (Contrastive Denoising)
    loss = 0
    sigma = sample_noise_level()
    noise = torch.randn_like(gt_frames[P])
    
    for k in range(K):
        x_noisy = candidates[k] + sigma * noise
        
        # 当前模型与参考模型的 x_0 预测
        x0_pred_current = model.predict_x0(x_noisy, sigma, history_buffer, actions[P])
        with torch.no_grad():
            x0_pred_ref = ref_model.predict_x0(x_noisy, sigma, history_buffer, actions[P])
            
        # 构建正向与负向分支
        x0_pos = (1 - beta) * x0_pred_ref + beta * x0_pred_current
        x0_neg = (1 + beta) * x0_pred_ref - beta * x0_pred_current
        
        # 奖励加权损失
        r = r_weights[k]
        loss_pos = r * F.mse_loss(x0_pos, gt_frames[P])
        loss_neg = (1 - r) * F.mse_loss(x0_neg, gt_frames[P])
        loss += (loss_pos + loss_neg)
        
    # 仅更新 LoRA 和 Action Encoder
    loss.backward()
    optimizer.step()
    update_ema(ref_model, model)
```

# 第二模块：核心架构解释

MMaDA-VLA 的核心架构将多模态理解与生成统一在一个基于掩码的离散扩散 Transformer 中。其运行流程可拆解为以下四个关键环节：

1.  **统一离散分词 (Data Tokenization)**
    将所有模态强制对齐到同一离散空间：文本使用 LLaDA 分词器，图像使用 MAGVIT-v2 量化器，连续的机器人动作（如关节角度）被离散化为 256 个 Bin 的 Token。所有 Token 共享同一个词表，消除了模态间的架构壁垒。
2.  **混合注意力机制 (Hybrid Attention)**
    为了适配扩散模型的并行生成特性，模型在 Transformer 内部设计了混合注意力：**模态内**采用双向全注意力（允许图像块之间、动作维度之间进行无序的全局信息交互）；**模态间**采用因果注意力（确保指令和当前观测单向引导未来图像和动作的生成，防止信息穿越）。
3.  **掩码去噪训练 (Masked Token Denoising)**
    训练时，将输入序列分为“指令区”（当前观测+文本）和“生成区”（未来目标图像+动作块）。对“生成区”的 Token 按照余弦调度策略进行随机 Mask（替换为 `[M]`）。模型通过单一的交叉熵损失，学习根据上下文重构这些被 Mask 的 Token。
4.  **并行迭代推理 (Iterative Denoising Inference)**
    推理时，“生成区”初始化为全 Mask 状态。模型进行多步（如 24 步）前向传播，每次预测所有 Token 的概率，保留置信度最高的 Token，将低置信度的 Token 重新 Mask 并进入下一步迭代。为解决高延迟问题，引入了选择性更新的 KV Cache 机制。

```python
class MMaDAVLA(nn.Module):
    def __init__(self, backbone, tokenizer):
        super().__init__()
        self.model = backbone # Large Diffusion Transformer
        self.vocab_size = tokenizer.vocab_size
        
    def train_step(self, instruction_tokens, goal_obs_tokens, action_tokens):
        """
        训练阶段：掩码 Token 预测
        """
        # 1. 拼接生成目标 (未来图像 + 动作块)
        target_seq = torch.cat([goal_obs_tokens, action_tokens], dim=-1)
        seq_len = target_seq.shape[-1]
        
        # 2. 采样 Mask 比例 (基于余弦调度)
        mask_ratio = sample_cosine_schedule()
        num_mask = int(mask_ratio * seq_len)
        
        # 3. 构造 Masked 序列
        mask_indices = torch.randperm(seq_len)[:num_mask]
        masked_target = target_seq.clone()
        masked_target[:, mask_indices] = MASK_TOKEN_ID
        
        # 4. 拼接完整输入序列
        input_seq = torch.cat([instruction_tokens, masked_target], dim=-1)
        
        # 5. 前向传播 (应用混合注意力掩码)
        logits = self.model(input_seq, attention_mask=self.get_hybrid_attn_mask())
        
        # 6. 计算损失 (仅在被 Mask 的位置计算交叉熵)
        pred_logits = logits[:, instruction_tokens.shape[-1]:] # 取出生成区预测
        loss = F.cross_entropy(pred_logits[:, mask_indices], target_seq[:, mask_indices])
        
        return loss

    @torch.no_grad()
    def inference_step(self, instruction_tokens, steps=24):

        推理阶段：迭代去噪生成
        """
        target_len = GOAL_OBS_LEN + ACTION_CHUNK_LEN
        # 初始化为全 Mask
        current_target = torch.full((1, target_len), MASK_TOKEN_ID)
        
        for d in reversed(range(steps)):
            input_seq = torch.cat([instruction_tokens, current_target], dim=-1)
            
            # 前向传播 (利用 KV Cache 加速)
            logits = self.model(input_seq, use_kv_cache=True)
            pred_logits = logits[:, instruction_tokens.shape[-1]:]
            
            # 贪婪解码获取当前步预测
            pred_tokens = torch.argmax(pred_logits, dim=-1)
            confidence_scores = torch.max(F.softmax(pred_logits, dim=-1), dim=-1).values
            
            if d == 0:
                current_target = pred_tokens
                break
                
            # 计算下一步需要保留的 Mask 比例
            next_mask_ratio = cosine_schedule_ratio(d, steps)
            num_mask = int(next_mask_ratio * target_len)
            
            # 根据置信度重新 Mask (保留高置信度，Mask 低置信度)
            mask_threshold = torch.kthvalue(confidence_scores, num_mask).values
            remask_indices = confidence_scores < mask_threshold
            
            current_target = pred_tokens.clone()
            current_target[remask_indices] = MASK_TOKEN_ID
            
        # 拆分输出
        goal_obs = current_target[:, :GOAL_OBS_LEN]
        action_chunk = current_target[:, GOAL_OBS_LEN:]
        
        return goal_obs, action_chunk
```

1. **数据合成与微调**：针对无人机飞行数据稀缺的问题，首先收集少量真实环境的遥操作数据，构建环境的 3D 高斯溅射（3DGS）场景。随后在 3DGS 场景中采样新的飞行轨迹并渲染对应的视觉观测，生成大量合成的“视觉-动作”对。将真实数据与合成数据混合，对预训练的 VLA 模型（如 $\pi_0$）进行轻量级微调。
2. **负载感知引导（推理期）**：在实际部署时，模型采用流匹配（Flow-Matching）生成动作。AirVLA 在常微分方程（ODE）的求解步中，计算当前预测动作在特定负载质量下违反物理约束的代价（Cost），并求取该代价对动作的梯度。将此梯度作为引导项（Guidance）注入到流匹配的向量场中，从而在不改变模型权重的前提下，强制生成的动作符合无人机的飞行物理学。

**核心伪代码（Python 风格）：**

```python
def payload_aware_flow_matching_inference(vla_model, observation, payload_mass, num_steps=50, guidance_scale=0.1):
    """
    带有负载感知引导的流匹配推理过程
    """
    # 1. 从标准正态分布初始化动作噪声
    x_t = sample_standard_normal(shape=vla_model.action_dim)
    dt = 1.0 / num_steps
    
    for t in reversed(range(num_steps)):
        time_step = t / num_steps
        
        # 2. VLA 模型预测当前步的向量场 (Vector Field)
        v_pred = vla_model.predict_vector_field(x_t, observation, time_step)
        
        # 3. 计算物理约束代价 (Physics Cost)
        # 评估当前动作 x_t 在给定 payload_mass 下是否会导致无人机失稳或超出推力极限
        cost = compute_physics_violation_cost(x_t, payload_mass)
        
        # 4. 计算代价关于动作 x_t 的梯度
        cost_grad = compute_gradient(cost, x_t)
        
        # 5. 注入负载感知引导 (Payload-Aware Guidance)
        # 修改向量场，使其朝着降低物理违规代价的方向移动
        v_guided = v_pred - guidance_scale * cost_grad
        
        # 6. 欧拉积分更新动作
        x_t = x_t + v_guided * dt
        
    return x_t # 返回最终符合物理约束的动作
```

### 第二模块：核心架构解释

Fast-dVLA 的核心逻辑是将自回归（AR）的高效 KV Cache 机制与离散扩散（Discrete Diffusion）的并行解码能力相融合。其架构与运行流程可拆解为以下三个关键阶段：

**1. 架构改造（Block-Wise Attention & Diffusion Forcing）**
模型将输出的动作序列划分为多个 Block。在注意力机制上，强制当前 Block 只能看到前面的 Block 和自身（块级因果注意力），这使得一旦某个 Block 解码完成，其 KV 状态就永久固定，后续步骤可以直接读取 Cache。为了让不同 Block 能同时解码，模型引入了单调递增的噪声调度（Diffusion Forcing），即前面的 Block 噪声低（接近清晰），后面的 Block 噪声高，从而允许模型在精炼前面动作的同时，粗略预测后面的动作。

**2. 非对称蒸馏训练（Asymmetric Distillation）**
为了避免从头训练的高昂成本，作者采用 Teacher-Student 蒸馏。Teacher 是预训练好的双向注意力 dVLA（拥有全局视野），Student 是 Fast-dVLA（只有块级因果视野）。通过最小化两者在掩码 Token 上的 KL 散度，Student 快速学会了在受限视野下逼近全局最优解。

**3. 流水线并行解码推理（Pipelined Parallel Decoding）**
在推理时，Block 被分为三种状态：未激活、半激活、全激活。当上一个 Block 的解码完成度达到阈值 $\tau_{add}$ 时，下一个 Block 进入半激活状态（仅解码高置信度 Token）；当上一个 Block 完成度达到 $\tau_{act}$ 时，当前 Block 进入全激活状态（激进解码）。

**核心推理逻辑伪代码 (Python 风格):**

```python
def fast_dvla_inference(model, prompt, num_blocks, tau_add, tau_act, tau_conf):
    # 初始化第一个 Block，全部填充 [MASK]
    blocks = [Block(id=0, tokens=[MASK]*block_size, state='semi-activated')]
    kv_cache = KVCache()
    
    while not all_blocks_completed(blocks):
        # 仅对当前激活的 blocks 进行一次前向传播，复用已完成块的 kv_cache
        logits, new_kv = model.forward(prompt, blocks, kv_cache)
        
        for i, block in enumerate(blocks):
            if block.is_completed():
                continue
                
            # 计算当前 block 中 MASK 位置的预测置信度
            confidences = compute_confidence(logits[i])
            
            if block.state == 'fully-activated':
                # 全激活状态：激进解码，使用动态阈值保证每次至少解码 1/n 的 token
                threshold = min(tau_conf, get_dynamic_top_k_threshold(confidences))
            else:
                # 半激活状态：保守解码，仅解码高于固定置信度阈值的 token
                threshold = tau_conf
                
            # 解码置信度大于阈值的 token
            block.decode_tokens(confidences > threshold)
            
            # 状态转移逻辑：基于前一个 block 的完成度
            if i > 0:
                prev_ratio = blocks[i-1].completion_ratio()
                if prev_ratio >= tau_act:
                    block.state = 'fully-activated'
                    
        # 动态新增 Block 逻辑
        last_block = blocks[-1]
        if last_block.completion_ratio() >= tau_add and len(blocks) < num_blocks:
            blocks.append(Block(id=len(blocks), tokens=[MASK]*block_size, state='semi-activated'))
            
        # 更新已完成 Block 的 KV Cache
        kv_cache.update(new_kv, completed_blocks=get_completed(blocks))
        
    return extract_actions(blocks)
```

**范式一：语言用于状态评估 (Language for State Evaluation)**

**范式二：语言作为策略条件 (Language as a Policy Condition)**

**范式三：语言用于认知规划与推理 (Language for Cognitive Planning)**

```python
        self.state = state
        self.lang = language_instruction

        # 强化学习或 MPC 优化器根据 reward 调整动作
        optimized_action = RL_Optimizer(reward, action_trajectory)
        return optimized_action

    # ---------------------------------------------------------
    # 范式 2: Language as a Policy Condition (Sec 5)
    # 语言作为条件向量，直接输入到控制策略中 (如 Diffusion Policy)
    # ---------------------------------------------------------
    def paradigm_2_policy_condition(self):
        # 语言特征提取
        lang_embedding = TextEncoder(self.lang)
        visual_embedding = VisionEncoder(self.state)
        
        # 策略网络 (如去噪扩散过程) 以语言为条件生成动作分布
        noise = sample_gaussian()
        for step in range(denoising_steps):
            noise = DenoisingNet(noise, condition=[visual_embedding, lang_embedding])
        action = noise 
        return action

    # ---------------------------------------------------------
    # 范式 3: Language for Cognitive Planning (Sec 6)
    # 语言作为内部推理媒介，LLM/VLM 充当高级规划器
    # ---------------------------------------------------------
    def paradigm_3_cognitive_planning(self):
        # LLM 生成高层子任务序列或 Python 控制代码 (如 SayCan, Code-as-Policies)
        sub_goals = LLM_Planner(prompt=self.lang, context=self.state)
        
        actions = []
        for goal in sub_goals:
            # 底层控制器 (非语言依赖) 执行具体物理动作
            action = LowLevelController(self.state, goal)
            actions.append(action)
        return actions

    # ---------------------------------------------------------
    # 范式 4: Unified Vision-Language-Action Models (Sec 7)
    # 端到端 VLA 模型，模态完全融合
    # ---------------------------------------------------------
    def paradigm_4_unified_vla(self):
        # 图像、文本、动作全部转化为统一的 Token 序列 (如 RT-2, OpenVLA)
        vision_tokens = PatchEmbed(self.state)
        text_tokens = Tokenize(self.lang)
        
        # 在同一个 Transformer 中自回归预测动作 Token
        input_sequence = concat(vision_tokens, text_tokens)
        action_tokens = VLA_Transformer(input_sequence)
        
        # 解码为物理控制信号 (如关节力矩或末端位姿)
        action = Detokenize(action_tokens)
        return action
```

### 第二模块：核心架构解释

HyDRA（Hybrid Dynamic Retrieval Architecture）的核心逻辑在于将长时序的视频生成过程转化为一个带有显式记忆读写与检索的马尔可夫/自回归过程。其架构主要分为三个阶段：记忆压缩与写入、时空相关性检索、条件视频生成。

1.  **记忆压缩与写入 (Memory Compression):** 模型不直接存储庞大的历史原始像素或高维特征图，而是通过编码器将过去的视频片段压缩为低维的 Memory Tokens。这既保留了静态背景的纹理信息，又提取了动态主体的身份与运动矢量。
2.  **时空相关性检索 (Spatiotemporal Relevance-Driven Retrieval):** 在生成当前帧（尤其是主体重新入镜的帧）时，模型不会对所有历史 Token 进行全局密集注意力计算（计算量过大且易产生噪声），而是基于当前相机的位姿/视点和时间戳，计算 Query，从 Memory Bank 中检索出在空间和时间上最相关的历史 Token。
3.  **状态外推与生成 (State Extrapolation & Generation):** 检索到的 Token 包含了主体离开视野前的最后状态和运动趋势。生成模型（如 Diffusion 或 Transformer）以此为条件，推演出主体在不可见期间的隐式运动，并渲染出准确的重返画面。

```python
        self.memory_tokens = [] # 存储压缩后的历史记忆
        self.token_metadata = [] # 存储对应的时空元数据 (时间戳, 空间位置等)
        
    def compress_and_write(self, past_frames, camera_poses, timestamps):
        # 将历史帧压缩为紧凑的记忆 Token
        tokens = memory_encoder(past_frames)
        self.memory_tokens.append(tokens)
        self.token_metadata.append({'pose': camera_poses, 'time': timestamps})

        # 基于当前时空状态计算相关性分数

        )

class HyDRAWorldModel:

        self.generator = VideoGenerationModel()

            current_state_query, current_pose, current_time
        )
        
        # 2. 结合检索到的记忆（包含视野外主体的运动趋势）生成新帧

        generated_frames = self.generator.forward(
            condition=current_state_query, 
            memory_context=retrieved_memory
        )
        
        # 3. 更新记忆库
        self.memory_bank.compress_and_write(generated_frames, current_pose, current_time)
        
        return generated_frames
```

### 第二模块：核心架构解释

TIES 框架是一个免训练的动态 Token 剪枝机制，其核心流程分为离线校准与在线推理两个阶段。在线推理时，利用时间冗余性减少计算开销，并根据层间秩一致性动态决定 Token 保留策略。

**核心流程：**
1. **离线校准 (Offline Calibration):** 从目标数据集中采样少量帧，计算其 Kendall $\tau$ 的分布和中位数 $\tau_{med}$，作为后续动态权重的参考基准。
2. **相似度触发器 (Similarity-based Trigger):** 在连续的视频流输入中，将首帧设为 Anchor。计算当前帧与 Anchor 的视觉相似度，仅当相似度低于阈值 $\gamma$ 时，才重新计算 $\tau$ 并更新剪枝策略，否则复用上一帧策略。
3. **动态 Token 选择 (Dynamic Selection):** 
   - 计算当前帧在 Transformer 连续层间 Top-k Token 排名的 Kendall $\tau$ 系数。
   - **Hard-TIES:** 二元切换。若 $\tau > \tau_{threshold}$（陷入虚假相关性），直接使用均匀采样（Uniform Sampling）；否则使用 Top-k 采样。
   - **Soft-TIES:** 线性插值。根据 $\tau$ 和 $\tau_{med}$ 计算权重 $w_t$，按比例混合 Top-k 采样与均匀采样，以平衡重要性（注意力驱动）与信息量（表征覆盖率）。
4. **前向传播:** 将筛选后的 Token 拼接，输入 VLA Decoder 生成动作。

**核心伪代码 (Python 风格):**

```python
import numpy as np
from scipy.stats import kendalltau

def compute_kendall_tau(attention_maps, k=50):
    """计算相邻层 Top-k Token 排名的 Kendall tau 系数"""
    taus = []
    for l in range(len(attention_maps) - 1):
        rank_l = np.argsort(-attention_maps[l])[:k]
        rank_l_plus_1 = np.argsort(-attention_maps[l+1])[:k]
        tau, _ = kendalltau(rank_l, rank_l_plus_1)
        taus.append(tau)
    return np.mean(taus)

def ties_pruning(visual_tokens, attention_maps, tau_med, rho=0.22, mode='soft'):
    """
    visual_tokens: 原始视觉 Token (N_v, D)
    rho: 保留比例 (例如保留 56/256 ≈ 0.22)
    """
    N = len(visual_tokens)
    N_retain = int(N * rho)
    
    # 1. 计算当前帧的层间秩一致性
    tau_curr = compute_kendall_tau(attention_maps)
    
    # 2. 动态决定 Top-k 与 Uniform 的比例
    if mode == 'hard':
        if tau_curr > tau_med: # 陷入注意力陷阱
            N_top = 0
        else:
            N_top = N_retain
    elif mode == 'soft':
        # 基于 tau_curr 和 tau_med 进行线性插值计算权重
        w_t = interpolate(tau_curr, tau_med) 
        N_top = int(w_t * N_retain)
        
    N_uni = N_retain - N_top
    
    # 3. 执行 Token 筛选
    avg_attention = np.mean(attention_maps[-1], axis=0)
    top_indices = np.argsort(-avg_attention)[:N_top]
    
    remaining_indices = list(set(range(N)) - set(top_indices))
    uni_indices = np.random.choice(remaining_indices, N_uni, replace=False)
    
    final_indices = np.concatenate([top_indices, uni_indices])
    return visual_tokens[final_indices]
```

### 第二模块：核心架构解释

本论文的模型架构本质上是对 LLM 底层位置编码机制的 3D 化改造与解耦，其核心流程如下：

1. **3D 场景解析与特征提取**：首先通过 3D 视觉编码器提取场景中各个对象的视觉特征，并获取其对应的 3D 物理坐标（如边界框中心点）。
2. **QuatRoPE 编码**：摒弃传统的绝对坐标 MLP 映射，将 3D 坐标转换为四元数（或高维旋转矩阵）形式的旋转位置编码。每个对象仅需一个 token 携带自身的 QuatRoPE，输入长度为 $O(N)$。
3. **IGRE 隔离门控融合**：在输入 LLM 之前，文本 token 继续使用 LLM 预训练时的标准 1D RoPE，而 3D 对象 token 使用 QuatRoPE。IGRE 作为一个门控开关，确保这两种位置编码在注意力机制中互不干扰。
4. **隐式关系计算与推理**：在 LLM 的 Self-Attention 层中，当两个 3D 对象 token 进行 Query 和 Key 的点积运算时，QuatRoPE 的数学特性使得该点积结果直接等价于它们在 3D 空间中的相对位置关系。LLM 基于此注意力权重输出最终的空间推理结果。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn.functional as F

def attention_with_quatrope_igre(q, k, v, text_pos, obj_3d_pos, is_obj_mask):
    """
    q, k, v: [batch_size, seq_len, hidden_dim]
    text_pos: 1D 文本位置序列
    obj_3d_pos: 3D 对象的物理坐标序列
    is_obj_mask: 布尔掩码，标记当前 token 是否为 3D 对象
    """
    
    # 1. 对所有 token 应用 LLM 原生的 1D RoPE (维持预训练语言能力)
    q_text = apply_standard_1d_rope(q, text_pos)
    k_text = apply_standard_1d_rope(k, text_pos)
    
    # 2. 仅针对 3D 坐标生成 QuatRoPE (四元数旋转位置编码)
    q_obj = apply_quatrope(q, obj_3d_pos)
    k_obj = apply_quatrope(k, obj_3d_pos)
    
    # 3. IGRE 隔离门控机制：根据 token 属性动态路由位置编码
    # 确保 3D 编码只作用于对象 token，不污染文本 token
    q_final = torch.where(is_obj_mask.unsqueeze(-1), q_obj, q_text)
    k_final = torch.where(is_obj_mask.unsqueeze(-1), k_obj, k_text)
    
    # 4. 注意力计算：
    # 当两个对象 token 进行点积时，QuatRoPE 的旋转特性会隐式计算出它们的 3D 相对关系
    attn_scores = torch.matmul(q_final, k_final.transpose(-1, -2)) / (q.size(-1) ** 0.5)
    attn_weights = F.softmax(attn_scores, dim=-1)
    
    # 5. 特征聚合
    output = torch.matmul(attn_weights, v)
    
    return output
```

### 第二模块：核心架构解释

LILAC 的核心架构将复杂的具身控制降维为计算机视觉中的光流预测问题，其处理流程可拆解为以下四个关键阶段：

1. **多模态特征提取 (Feature Extraction)**：接收初始 RGB 图像和自然语言指令，分别通过视觉编码器（如 ViT）和文本编码器（如 CLIP/T5）提取高维特征。
2. **跨模态特征融合 (Prompt-Conditioned Cross-Modal Adapter)**：这是架构的核心组件之一。模型引入了一组可学习的视觉提示（Visual Prompts），这些提示作为 Query，与图像特征和文本特征进行交叉注意力（Cross-Attention）计算，提取出既包含空间几何信息又受语言指令调制的融合特征。
3. **以物体为中心的光流生成 (Object-Centric Flow Generation)**：解码器基于上述融合特征，预测图像中目标物体在未来时间步的 2D 光流场（即像素的二维位移向量）。在训练阶段，通过**语义对齐损失 (Semantic Alignment Loss)** 惩罚那些与语言指令意图不符的光流预测，确保“向左推”等指令能精确映射为向左的像素位移。
4. **轨迹转换 (Trajectory Conversion)**：在推理阶段，将生成的 2D 光流结合深度信息（Depth）或相机内参，通过几何反投影或启发式算法，转换为机械臂末端执行器的 6-DoF 空间轨迹，交由底层控制器开环执行。

```python
import torch.nn.functional as F

class LILAC(nn.Module):
    def __init__(self, vision_encoder, text_encoder, flow_decoder):
        super().__init__()
        self.vision_encoder = vision_encoder
        self.text_encoder = text_encoder
        # 可学习的视觉提示
        self.visual_prompts = nn.Parameter(torch.randn(1, num_prompts, embed_dim))
        # 跨模态适配器
        self.cross_modal_adapter = CrossModalAdapter(embed_dim)
        self.flow_decoder = flow_decoder
        
    def forward(self, image, instruction, gt_flow=None):
        # 1. 特征提取
        img_features = self.vision_encoder(image)      # [B, N, D]
        text_features = self.text_encoder(instruction) # [B, L, D]
        
        # 2. 提示词条件的跨模态融合
        # Prompts 吸收图像和文本信息
        adapted_features = self.cross_modal_adapter(
            query=self.visual_prompts, 
            key_value_img=img_features, 
            key_value_text=text_features
        )
        
        # 3. 光流生成
        pred_flow = self.flow_decoder(img_features, adapted_features) # [B, 2, H, W]
        
        if self.training and gt_flow is not None:
            # 计算基础光流重建损失
            flow_loss = F.l1_loss(pred_flow, gt_flow)
            
            # 4. 计算语义对齐损失 (Semantic Alignment Loss)
            # 提取预测光流的特征并与文本特征对齐
            flow_features = extract_flow_features(pred_flow)
            semantic_loss = compute_contrastive_loss(flow_features, text_features)
            
            total_loss = flow_loss + lambda_weight * semantic_loss
            return total_loss
            
        return pred_flow

# 推理阶段的轨迹转换
def generate_trajectory(model, image, instruction, depth_map, camera_intrinsics):
    model.eval()
    with torch.no_grad():
        # 生成 2D 光流
        pred_flow = model(image, instruction)
        # 将 2D 光流 + 深度图 转换为 6-DoF 轨迹
```

### 第二模块：核心架构解释

DMW 的架构分为三个核心阶段：长期偏好特征提取、VLA 基础动作生成、以及基于动态奖励的短期意图强化微调。

1.  **长期偏好对齐 (Long-term Preference Alignment):** 使用 DeBERTa 处理驾驶员的文本画像（年龄、驾龄、性格等），使用时序编码器处理该驾驶员的历史驾驶轨迹。通过 InfoNCE 对比学习损失，强制文本特征与轨迹特征在隐空间对齐，生成固定的 `user_embedding`。
2.  **VLA 基础动作与残差解码 (VLA Backbone & Residual Decoding):** 以 SimLingo (基于 Qwen2-0.5B) 为基座。输入当前图像、导航路点、语言指令和 `user_embedding`。基座输出基础的路径点（转化为基础速度和转向）。同时，引入可学习的残差 Query，通过 MLP 解码出离散的动作残差（速度变化量和转向变化量）。最终动作 = 基础动作 + 动作残差。
3.  **风格感知奖励与 GRPO 微调 (Style-Aware Reward & GRPO):** 离线阶段使用 LLM（如 GPT-5）根据输入的语言指令（如“我很急”）和场景描述，推导出安全、效率、舒适度的奖励权重（$w_s, w_e, w_c$）及阈值。在线训练时，使用 GRPO 算法，根据这些动态权重计算奖励，专门微调残差解码器和运动预测头。

### 第二模块：核心架构解释

SABER 的运行与训练流程分为两个主要阶段：冷启动数据收集（SFT）与基于环境反馈的强化学习微调（GRPO）。在攻击执行时，它作为一个多轮对话的 ReAct 智能体，通过调用外部工具链来篡改输入指令。

**核心流程拆解：**
1.  **Baseline Rollout（基线采样）：** 将干净的原始指令输入冻结的黑盒 VLA 模型，在仿真环境中执行，记录基线轨迹数据（任务是否成功、动作序列长度、约束违规次数）。
2.  **Multi-turn Attack Construction（多轮攻击构建）：** 攻击智能体（基于 Qwen2.5-3B）接收原始指令，在预设的编辑预算（如最多 4 次工具调用，200 个字符修改）内，执行 ReAct 循环。智能体使用 `FIND` 工具定位修改位置并生成策略，随后使用 `APPLY` 工具在字符、Token 或 Prompt 级别执行具体的文本替换或注入。
3.  **Attack Rollout（攻击执行）：** 将被篡改的指令输入同一个 VLA 模型，在环境中执行，获取受攻击后的轨迹数据。
4.  **Reward Computation & GRPO（奖励计算与策略优化）：** 对比基线轨迹与攻击轨迹，计算特定目标（如任务失败、动作膨胀）的奖励，并扣除隐蔽性惩罚（基于工具调用次数和字符编辑距离）。使用 GRPO 算法更新攻击智能体的 LoRA 权重。

**核心逻辑伪代码 (Python-style):**

```python
class SABER_Attacker:
    def __init__(self, agent_llm, vla_model, env, budget):
        self.agent = agent_llm # e.g., Qwen2.5-3B with LoRA
        self.vla = vla_model   # Frozen Black-box VLA
        self.env = env
        self.budget = budget
        self.tools = [CharEdit(), TokenEdit(), PromptEdit()]

    def rollout(self, instruction):
        """Execute instruction in environment using VLA"""
        obs = self.env.reset()
        trajectory_stats = {"success": False, "length": 0, "violations": 0}
        while not self.env.done():
            action = self.vla.predict(obs, instruction)
            obs, reward, done, info = self.env.step(action)
            trajectory_stats["length"] += 1
            trajectory_stats["violations"] += info["violations"]
            if reward > 0: trajectory_stats["success"] = True
        return trajectory_stats

    def compute_reward(self, base_stats, attack_stats, edit_history, objective):
        """Calculate objective reward minus stealth penalty"""
        if objective == "task_failure":
            R_obj = 1.0 if (base_stats["success"] and not attack_stats["success"]) else 0.0
        elif objective == "action_inflation":
            R_obj = max(0, attack_stats["length"] - base_stats["length"]) / normalize_factor
        
        # Stealth penalty: penalize excessive tool calls and char edits
        P_stealth = len(edit_history) * w1 + char_edit_distance * w2 
        return R_obj - lambda_weight * P_stealth

    def train_step_grpo(self, clean_instruction):
        # 1. Get baseline behavior
        base_stats = self.rollout(clean_instruction)
        
        # 2. Sample multiple attack trajectories for GRPO
        trajectories = []
        for _ in range(GRPO_GROUP_SIZE):
            perturbed_inst = clean_instruction
            edit_history = []
            
            # Multi-turn ReAct loop under budget
            while len(edit_history) < self.budget.max_tool_calls:
                # Agent decides WHERE and HOW to edit
                find_result = self.agent.generate(perturbed_inst, prompt="FIND")
                # Agent executes the edit
                apply_result = self.agent.generate(find_result, prompt="APPLY", tools=self.tools)
                
                perturbed_inst = apply_result.new_text
                edit_history.append(apply_result)
                
                if check_budget_exceeded(edit_history, self.budget):
                    break
            
            # 3. Execute perturbed instruction
            attack_stats = self.rollout(perturbed_inst)
            
            # 4. Compute Reward
            reward = self.compute_reward(base_stats, attack_stats, edit_history, target_objective)
            trajectories.append({"agent_actions": edit_history, "reward": reward})
            
        # 5. Update Agent via GRPO (using relative advantages within the group)
        advantages = compute_group_relative_advantages([t["reward"] for t in trajectories])
        self.agent.update_lora_weights_via_grpo(trajectories, advantages)
```

### 第二模块：核心架构解释

2. **高层规划器 (VLM Planner)**: 采用 Gemini 2.0 Flash。输入包含用户原始指令、全局 RGB 图像、全局热成像伪彩图以及系统提示词（Prompt）。VLM 结合热成像中的颜色分布与常识（如红色代表高温），将长程任务分解为一系列结构化的自然语言子任务（Sub-tasks）。
3. **底层执行器 (VLA Executor)**: 基于 $\pi_0$ 架构进行 LoRA 微调。在 10Hz 的控制频率下，接收 VLM 拆解的当前子任务指令、腕部 RGB 图像、全局热成像图像以及机器人本体状态（7维：6个关节角+1个夹爪状态）。模型直接输出 8 维动作向量（6个目标关节角+1个夹爪控制量+1个任务完成标志位 $d_t$）。当 $d_t$ 被触发时，系统请求 VLM 调取下一个子任务。

```python
# ThermoAct 核心逻辑伪代码
class ThermoActSystem:
    def __init__(self, vlm_planner, vla_executor):
        self.vlm = vlm_planner
        self.vla = vla_executor
        
    def preprocess_thermal(self, raw_thermal_data):
        # 将原始温度数据归一化并映射为 INFERNO 伪彩色 RGB 图像
        normalized = normalize(raw_thermal_data, min_temp=20, max_temp=35)
        pseudo_color_img = apply_colormap(normalized, palette='INFERNO')
        return pseudo_color_img

    def execute_task(self, user_instruction, env_cameras, robot_state):
        # 1. 获取全局图像并预处理热成像
        global_rgb = env_cameras.get_global_rgb()
        raw_thermal = env_cameras.get_global_thermal()
        thermal_img = self.preprocess_thermal(raw_thermal)
        
        # 2. VLM 高层规划：基于热成像和 RGB 拆解子任务
        sub_tasks = self.vlm.plan(
            instruction=user_instruction, 
            rgb_img=global_rgb, 
            thermal_img=thermal_img
        )
        
        # 3. VLA 底层执行：遍历执行子任务
        for sub_task in sub_tasks:
            done = False
            while not done:
                # 获取实时高频观测数据
                wrist_rgb = env_cameras.get_wrist_rgb()
                current_thermal = self.preprocess_thermal(env_cameras.get_global_thermal())
                current_state = robot_state.get_state() # 7-dim
                
                # VLA 预测动作与完成标志
                action, done_flag = self.vla.predict_action(
                    prompt=sub_task,
                    wrist_img=wrist_rgb,
                    thermal_img=current_thermal,
                    state=current_state
                )
                
                # 执行物理动作 (10Hz)
                robot_state.step(action)
                done = done_flag
```

### 第二模块：核心架构解释

DCARL 的核心逻辑是将长视频生成拆分为两个独立的子任务：**全局结构锚定（Keyframe Generation）** 与 **局部细节填充（Autoregressive Interpolation）**。

1. **全局关键帧生成（分治阶段）**：模型首先使用一个专门训练的、无时间压缩（Without temporal compression）的视频扩散模型。该模型接收文本提示和相机轨迹条件，直接生成贯穿整个视频时间线的稀疏关键帧。这一步的目的是建立全局一致的结构锚点，从根本上阻断自回归过程中的长程视觉漂移。
2. **重叠片段自回归插值（自回归阶段）**：在获得稀疏关键帧后，插值生成器负责填充相邻关键帧之间的密集帧。为了保证时间连贯性，插值过程采用自回归方式，并引入重叠片段策略。
3. **双重条件注入机制**：在生成每一个局部片段时，插值生成器同时接收两个维度的条件约束：一是前后的关键帧（提供全局上下文，确保不偏离主干结构）；二是前一个片段的最后一帧（Single clean preceding frame，提供局部连贯性，确保帧间平滑）。

**核心伪代码实现逻辑：**

```python
def generate_dcarl_video(prompt, camera_trajectory, total_frames, keyframe_interval):
    """
    DCARL 长轨迹视频生成核心逻辑
    """
    # 阶段一：分治 - 生成全局稀疏关键帧 (无时间压缩，确保全局结构稳定)
    num_keyframes = total_frames // keyframe_interval
    keyframes = keyframe_generator(
        prompt=prompt,
        camera_cond=camera_trajectory,
        num_frames=num_keyframes
    )
    
    final_video_frames = []
    # 初始化局部连贯性条件：第一帧
    current_clean_frame = keyframes[0]
    final_video_frames.append(current_clean_frame)
    
    # 阶段二：自回归插值 - 逐段填充密集帧
    for i in range(len(keyframes) - 1):
        start_keyframe = keyframes[i]
        end_keyframe = keyframes[i+1]
        
        # 获取当前片段的相机轨迹条件
        segment_camera_cond = extract_segment_cond(camera_trajectory, start_idx=i, end_idx=i+1)
        
        # 核心：双重条件约束下的自回归插值
        # 1. global_context: 锚定全局结构，防止漂移
        # 2. local_prev_frame: 确保与上一片段的像素级平滑过渡
        interpolated_segment = interpolation_generator(
            prompt=prompt,
            camera_cond=segment_camera_cond,
            global_context=(start_keyframe, end_keyframe),
            local_prev_frame=current_clean_frame,
            num_interp_frames=keyframe_interval - 1
        )
        
        final_video_frames.extend(interpolated_segment)
        
        # 更新 current_clean_frame 为当前片段的末尾关键帧，用于下一片段的局部约束
        current_clean_frame = end_keyframe
        final_video_frames.append(end_keyframe)
        
    return final_video_frames
```

<summary>详细分析</summary>

1. 问题：动态城市环境中的运动规划需要平衡短期安全和长期目标。现有的扩散模型方法通常将轨迹视为一个整体，忽略了不同时间段的异构依赖关系（如短期受瞬态动力学约束，而长期受导航目标约束），导致规划不够灵活。

2. 方法：本文提出了一种时间解耦扩散模型（TDDM），通过“噪声即掩码”的范式重构轨迹生成。该方法将轨迹划分为具有独立噪声水平的片段，将高噪声视为信息空白，弱噪声视为上下文提示。架构上引入了时间解耦自适应层归一化（TD-AdaLN）以注入特定片段的时间步长，并在推理阶段使用非对称时间无分类器引导（Asymmetric Temporal CFG），利用弱噪声的长期先验来指导短期路径生成。

3. 结果：在nuPlan基准测试上的评估表明，TDDM接近或超过了现有的最先进基线模型，特别是在具有挑战性的Test14-hard子集中表现优异。

4. 意义：该研究为自动驾驶中的扩散规划提供了一种新的时间解耦视角，有效提升了复杂动态环境下的轨迹生成质量。其对时间维度的分层处理和噪声控制思想，对具身智能中的长视距运动规划和扩散策略（Diffusion Policy）也具有一定的启发意义。

#### Deep Research 深度解读

### 第一模块：一分钟核心速写

1. **论文领域**：VLA（侧重于自动驾驶底层动作规划与轨迹生成）
2. **TL;DR**：TDDM 提出了一种基于时间解耦扩散模型的轨迹生成框架，以解决自动驾驶中短期避障与长期导航目标冲突的问题，在 nuPlan 基准测试（尤其是 Test14-hard 困难场景）上实现了超越现有基准的规划成功率。
3. **研究动机**：现有的扩散规划模型将未来整段轨迹视为一个不可分割的整体，在所有时间步上施加相同的噪声。这种做法忽略了一个客观事实：车辆近期的轨迹受制于眼前的障碍物，而远期的轨迹受制于最终的导航目的地。本文的切入点在于打破这种时间上的绑定。
**核心机制**：将一段完整的未来行驶轨迹切分为多个时间段。在训练时，对不同时间段加入不同程度的随机数据（噪声）；在生成时，保持远期时间段的数据相对清晰，强制模型根据清晰的远期目标来推算并生成近期的行驶路线。
4. **关键数据**：
- **核心有效数据**：在 nuPlan 的 Test14-hard（长尾困难场景）非响应式（NR）闭环测试中，TDDM 得分为 77.95，显著超越了基准模型 Diffusion Planner 的 75.67。且 TDDM 仅使用了 20 万个场景数据进行训练，而基准模型使用了 100 万个，证明了该架构极高的数据效率和处理复杂场景的鲁棒性。
- **存疑/局限数据**：在响应式（R）闭环测试中（即环境中的其他车辆会根据自车的动作做出反应），TDDM 在 Val14 上的得分为 79.78，低于传统的规则/混合模型 PDM-Closed（92.12）。这表明该模型在处理高频动态博弈和完全闭环的交互环境时，依然存在基于学习的规划器常见的短板。

### 第二模块：核心架构解释

TDDM 的核心架构建立在扩散 Transformer（DiT）的基础之上，其工作流程分为数据预处理、时间解耦训练和非对称引导推理三个阶段。

**1. 数据预处理与分块**
模型接收环境上下文（包含自车历史状态、周围车辆轨迹、地图车道线等）。将连续的动作空间离散化为 20 个预定义的轨迹模板（Anchors）。将 8 秒的未来轨迹切分为 $N$ 个时间段（例如 4 个段，每段 2 秒），并将其划分为“近期”和“远期”两个宏观组。

**2. 时间解耦自适应层归一化（TD-AdaLN）**
传统的扩散模型全局共享一个时间步。TDDM 引入了 TD-AdaLN 模块，允许网络为不同的时间段注入独立的扩散时间步编码。这使得网络能够理解不同时间段当前处于不同的生成阶段。

**3. 训练流程**
对切分好的轨迹段注入相互独立的随机高斯噪声。模型需要同时完成两个任务：第一，从被破坏的轨迹段中重建出真实的行驶轨迹；第二，预测哪一个预定义的轨迹模板最适合当前的环境。

**4. 非对称时间无分类器引导（Asymmetric Temporal CFG）推理**
在实际生成轨迹时，模型同时运行两条路径：
- 无条件路径：所有时间段都从完全的随机噪声开始生成。
- 有条件路径：近期时间段从完全随机噪声开始，但远期时间段被固定为极低噪声的清晰状态。
最后通过数学公式将两条路径的结果融合，利用远期的清晰目标来引导近期轨迹的生成。

**核心伪代码实现**：

```python
def train_step(context, gt_trajectory, anchors, N_segments):
    # 1. 找到与真实轨迹最接近的预定义模板
    target_anchor = find_closest_anchor(gt_trajectory, anchors)
    
    # 2. 轨迹分块与独立加噪
    tokenized_anchors = split_into_segments(anchors, N_segments)
    noised_segments = []
    
    for segment in tokenized_anchors:
        # 为每个时间段采样独立的扩散时间步和随机噪声
        t_independent = sample_random_timestep()
        noise = sample_gaussian_noise()
        noised_segment = add_noise(segment, t_independent, noise)
        noised_segments.append(noised_segment)
        
    # 3. 前向传播 (包含 TD-AdaLN 模块)
    # 模型输出预测的干净轨迹和每个模板的置信度得分
    predicted_trajectories, scores = model(noised_segments, context)
    
    # 4. 计算损失
    loss_reconstruction = L1_loss(predicted_trajectories[target_anchor], gt_trajectory)
    loss_classification = BCE_loss(scores, target_anchor)
    total_loss = loss_reconstruction + lambda * loss_classification
    
    return total_loss

def inference_step(context, anchors, N_segments, cfg_scale):
    # 将轨迹分为近期 (near_term) 和远期 (far_term)
    near_term, far_term = split_near_far(anchors)
    
    # 路径1：无条件生成（全部是纯噪声）
    uncond_input = full_gaussian_noise(near_term, far_term)
    
    # 路径2：有条件生成（近期纯噪声，远期极低噪声）
    cond_input_near = full_gaussian_noise(near_term)
    cond_input_far = weak_noise(far_term) # 保持远期目标清晰
    cond_input = combine(cond_input_near, cond_input_far)
    
    # 迭代降噪过程
    for t in reversed(range(diffusion_steps)):
        # 预测无条件结果
        pred_uncond, _ = model(uncond_input, context)
        
        # 预测有条件结果（远期部分在每一步都强制保持低噪声状态）
        pred_cond, _ = model(cond_input, context)
        
        # CFG 融合
        pred_final = pred_uncond + cfg_scale * (pred_cond - pred_uncond)
        
        # 更新下一步的输入
        uncond_input = diffusion_solver_step(pred_final)
        cond_input_near = diffusion_solver_step(pred_final_near)
        # cond_input_far 保持不变
        
    return pred_final
```

### 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 自动驾驶车辆在行驶时，必须同时满足两个要求：立刻避开眼前的障碍物，以及最终开向正确的目的地。现有的轨迹生成模型将未来几秒的行驶路线作为一个整体来计算，使用统一的计算步骤。这导致模型无法区分“眼前紧急情况”和“远处长期目标”的不同优先级，容易生成要么过于保守、要么偏离路线的行驶轨迹。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 作者提出将未来的行驶路线切分成多个短的时间块。在训练模型时，对不同的时间块施加不同程度的随机数据干扰，迫使模型学习不同时间块之间的关联。在实际计算行驶路线时，作者强制模型先确立一个清晰的远期行驶目标，然后在这个远期目标的限制下，去计算眼前这一秒该如何行驶。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 实验使用了 nuPlan 数据集，并特别选取了其中的 Test14-hard 测试集。这个测试集专门收集了现实驾驶中极少出现但极其危险的复杂场景（长尾场景）。通过在这个困难数据集上进行测试，作者能够客观证明该模型不是单纯记住了常见的直线行驶规律，而是真正具备了在复杂路况下进行安全规划的能力。

Q4: 这篇论文最显著的贡献点（Top 3）是什么？

A4:
1. 提出了一种时间解耦的训练方法，将轨迹切分并施加独立的随机干扰，增强了模型对时间先后顺序的理解。
2. 设计了 TD-AdaLN 神经网络结构，使得模型能够在同一时刻处理带有不同时间步信息的轨迹段。
3. 发明了非对称时间引导生成策略，利用清晰的远期路线作为条件，直接引导近期路线的生成，提高了行驶规划的长期一致性。

Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）

A5:
1. Diffusion Planner (Zheng et al., 2025)：该工作确立了基于预定义轨迹模板（Anchors）的自动驾驶扩散生成框架，本文直接沿用了其基础架构和感知输入方式。
2. Diffusion Forcing (Chen et al., 2025)：该工作在视频生成领域证明了对不同视频帧施加独立干扰可以提升生成质量，本文将这一思想跨学科迁移到了自动驾驶的物理轨迹生成中。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 该论文最大的局限性在于其高度依赖预先设定的 20 个轨迹模板（Anchors）。模型本质上是在这 20 个模板中挑选一个并进行微调。如果现实路况需要一种完全不在模板库中的极端驾驶动作，该模型将无法生成有效的轨迹。此外，实验数据表明该模型在其他车辆会产生动态反应的闭环测试中表现不佳，说明其缺乏对多车博弈和动态交互的深度建模。对后续科研的启发是：未来的轨迹生成模型需要彻底摆脱预设模板的限制，转向完全自回归的历史轨迹生成；同时，需要将博弈论或多智能体交互机制引入到扩散模型的引导公式中。
