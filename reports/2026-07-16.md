### 第二模块：核心架构解释

REAL 框架的核心逻辑在于将复杂的移动操作解耦为“高层视觉推理与交互”和“底层技能执行”，并通过严格的接口对齐实现从模拟器到现实的无缝迁移。

**架构与流程详解：**
1. **虚实一致环境 API (Sim-to-Real-Consistent APIs)**：剥离所有模拟器特权信息（如物体的绝对坐标、状态树）。智能体只能通过机载相机的 RGB-D 图像和基础本体感受器获取信息，确保模拟环境与真实机器人的输入输出接口完全等效。
2. **交互与探索机制 (Exploration & Communication)**：引入模拟用户（Simulated User）。当人类指令存在歧义（如“把那个杯子拿过来”，但桌上有多个杯子）或目标不在视野内时，智能体被允许主动调用导航 API 进行环境探索，或调用对话 API 向人类发起提问以消除歧义。
3. **层级化训练管线 (Hierarchical Training Pipeline)**：
   - **数据收集**：在模拟器中构建多样化任务组合，收集专家轨迹。
   - **SFT (监督微调)**：将轨迹转化为问答对，微调 VLM，赋予其基础的 API 调用和指令遵循能力。
   - **Online RL (在线强化学习)**：针对长视野任务，通过环境反馈奖励进一步优化 VLM 的决策序列，提升探索效率和交互策略的鲁棒性。
4. **物理部署 (Physical Deployment)**：将训练好的 VLM 策略直接部署于真实的双臂移动机器人，通过调用真实的底层控制脚本完成开放词汇的移动操作。

**核心逻辑伪代码：**

```python
class REALAgent:
    def __init__(self, vlm_policy):
        # 经过 SFT 和 Online RL 训练的视觉语言模型
        self.policy = vlm_policy 
        self.episodic_memory = []

    def step(self, user_instruction, env_api):
        # 1. 获取无特权视觉观测 (严格对齐真实世界)
        visual_obs = env_api.get_egocentric_vision()
        self.episodic_memory.append(visual_obs)

        # 2. VLM 结合历史记忆进行高层推理
        action_intent = self.policy.reason(user_instruction, self.episodic_memory)

        # 3. 交互式意图消除歧义 (Human-in-the-loop)
        if action_intent.type == "ASK_USER":
            clarification = env_api.communicate(action_intent.question)
            self.episodic_memory.append(clarification)
            return "CONTINUE"

        # 4. 主动视觉探索
        elif action_intent.type == "EXPLORE":
            env_api.navigate_to(action_intent.target_area)
            return "CONTINUE"

        # 5. 调用底层技能执行物理操作
        elif action_intent.type == "MANIPULATE":
            success = env_api.execute_skill(
                skill_name=action_intent.skill_name, 
                params=action_intent.params
            )
            return "DONE" if success else "RETRY"
```

### 第二模块：核心架构解释

GigaWorld-Policy-0.5 的核心逻辑在于**“训练时联合，推理时解耦”**。其模型架构与数据流转流程如下：

1.  **多模态输入编码 (Input Encoding)**：
    *   将左、前、右三个视角的图像拼接为复合图像，通过预训练的 VAE 编码为视觉 Token。
    *   机器人本体状态（State）和动作块（Action Chunk）通过 MLP 映射到统一维度。
    *   文本指令通过 umT5 编码为条件 Token。
2.  **混合专家 Transformer (MoT Backbone)**：
    *   模型摒弃了完全共享的 Transformer，转而设计了 **Visual Expert** 和 **Action Expert**。
    *   Visual Expert 继承自大规模预训练世界模型（GigaWorld-1），专门处理当前与未来的视觉 Token。
    *   Action Expert 维度更小（轻量化），专门负责动作 Token 的去噪与预测。
3.  **动作中心化因果掩码 (Action-Centered Causal Masking)**：
    *   在多模态自注意力层中，施加严格的掩码：动作 Token **只能**关注当前视觉、状态和文本；未来视觉 Token **可以**关注动作 Token。这防止了未来信息向动作的穿越，同时迫使动作表征符合世界模型的演化规律。
4.  **流匹配联合优化 (Flow Matching)**：
    *   训练时，对动作和未来视觉分别注入不同时间步的噪声，通过回归预测速度场（Velocity Field）来联合优化两个模态。
5.  **极速推理管线 (Efficient Inference)**：
    *   部署时，直接丢弃未来视觉 Token 的输入与计算，仅激活 Action Expert。配合 KV Cache、`torch.compile` 图编译以及纯 C++ 运行时，实现极致加速。

**核心伪代码 (Python 风格)**：

```python
import torch.nn as nn

class ActionCenteredMoT(nn.Module):
    def __init__(self, visual_dim=3072, action_dim=1024):
        super().__init__()
        # 独立专家设计
        self.visual_expert = TransformerBlocks(dim=visual_dim)
        self.action_expert = TransformerBlocks(dim=action_dim)
        
        # 跨模态注意力机制 (简化示意)
        self.multi_modal_attn = MultiModalAttention()

    def generate_causal_mask(self, num_context, num_action, num_future):
        """
        构建动作中心化因果掩码
        True 表示允许注意力，False 表示掩码（阻断）
        """
        total_len = num_context + num_action + num_future
        mask = torch.ones((total_len, total_len), dtype=torch.bool)
        
        # 核心逻辑：动作 Token 不能看未来视觉 Token
        action_start = num_context
        action_end = num_context + num_action
        future_start = action_end
        
        mask[action_start:action_end, future_start:] = False 
        return mask

    def forward(self, context_tokens, action_tokens, future_visual_tokens=None, inference_mode=False):
        """
        context_tokens: 包含当前视觉、状态、文本指令
        """
        if inference_mode:
            # 推理阶段：完全跳过未来视觉计算，仅使用 Action Expert
            # 结合 KV Cache 避免重复计算 context
            action_features = self.action_expert(context_tokens, action_tokens)
            pred_action_velocity = predict_velocity(action_features)
            return pred_action_velocity
            
        else:
            # 训练阶段：联合建模
            mask = self.generate_causal_mask(len(context_tokens), len(action_tokens), len(future_visual_tokens))
            
            # 视觉专家处理视觉流
            visual_features = self.visual_expert(context_tokens, future_visual_tokens)
            # 动作专家处理动作流
            action_features = self.action_expert(context_tokens, action_tokens)

            joint_features = self.multi_modal_attn(visual_features, action_features, mask)

            return pred_action_velocity, pred_visual_velocity
```

### 第二模块：核心架构解释

当前论文的方法是一个纯训练期的正则化/对齐框架。其核心流程分为特征提取、通道解耦、语义对齐、特征约束四个步骤。在部署测试时，所有附加模块均被移除。

**1. 特征提取：**
在 VLA 模型的前向传播中，截取网络中间层（如第 10 层）的动作 token 隐藏状态。

**2. 通道解耦（Shared-Private Decomposition）：**
将提取出的动作特征输入两个独立的线性网络（MLP）。一个网络输出“共享特征”（包含任务意图），另一个网络输出“私有特征”（包含空间几何、时间、电机控制等物理细节）。

**3. 语义对齐（Semantic Alignment）：**
将所有动作 token 的“共享特征”通过注意力机制聚合成一个句子级别的特征向量。然后，计算该向量与外部冻结视觉语言模型（如 EgoHOD）提取的指令文本向量之间的对比损失（InfoNCE）。这迫使共享特征向高质量的语义空间靠拢。

**4. 特征约束（Reconstruction & Decorrelation）：**
为了保证拆分后的特征没有丢失信息且互不干扰，引入两个额外的计算：一是将共享特征和私有特征相加后，必须能还原出原始的动作特征（重建损失）；二是计算共享特征和私有特征之间的余弦相似度，惩罚它们的重合度，迫使它们各自独立（解缠损失）。

**核心伪代码实现 (Python 风格):**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def semantic_anchoring_loss(action_features, text_instruction, frozen_text_encoder, modules):
    """
    action_features: VLA 中间层输出的动作特征, shape (Batch, Tokens, Dim)
    text_instruction: 语言指令
    frozen_text_encoder: 冻结的外部文本编码器 (如 EgoHOD)
    modules: 包含解耦、投影、注意力等可学习模块的字典
    """
    B, T, D = action_features.shape
    
    # 1. 通道解耦 (Channel Decomposition)
    # 将原始特征拆分为共享(语义)和私有(执行)特征
    shared_features = modules['encoder_shared'](action_features)   # (B, T, D_s)
    private_features = modules['encoder_private'](action_features) # (B, T, D_s)
    
    # 2. 语义对齐 (Semantic Alignment)
    # 使用可学习的 Query 对共享特征进行注意力池化，聚合成单向量
    attention_weights = F.softmax(
        torch.matmul(shared_features, modules['query_vector']) / (D_s ** 0.5), 
        dim=1
    )
    pooled_shared = torch.sum(attention_weights * shared_features, dim=1) # (B, D_s)
    
    # 获取外部冻结模型的文本特征
    with torch.no_grad():
        target_text_embedding = frozen_text_encoder(text_instruction) # (B, D_e)
        
    # 投影到同一维度并计算对比损失 (InfoNCE)
    proj_shared = modules['proj_action'](pooled_shared)
    proj_text = modules['proj_text'](target_text_embedding)
    loss_align = info_nce_loss(proj_shared, proj_text)
    
    # 3. 特征重建 (Reconstruction)
    # 确保拆分后的特征相加能还原回原始特征
    reconstructed_features = modules['decoder'](shared_features + private_features)
    loss_recon = F.mse_loss(reconstructed_features, action_features)
    
    # 4. 特征解缠 (Decorrelation)
    # 惩罚共享特征和私有特征之间的相似度，迫使它们正交
    shared_norm = F.normalize(shared_features, dim=-1)
    private_norm = F.normalize(private_features, dim=-1)
    loss_diff = torch.mean((shared_norm * private_norm).sum(dim=-1) ** 2)
    
    # 总辅助损失
    total_aux_loss = lambda_align * loss_align + lambda_r * loss_recon + lambda_d * loss_diff
    
    return total_aux_loss
```

**Authors**: Dwip Dalal, Shivansh Patel, Chahit Jain, Jeonghwan Kim, Utkarsh Mishra et al.

视觉-语言-动作（VLA）模型通常通过行为克隆（BC）微调预训练的视觉语言模型（VLM）来获得。然而，BC微调会逐渐破坏VLM原有的预训练表示，导致视觉和语义泛化能力下降。虽然联合训练网络图文数据是常见的缓解方法，但它将语言和动作损失应用于不同的观测数据，导致了语言-动作不对齐的问题，而标准的机械臂操作基准测试往往无法暴露这一缺陷。

为解决上述问题，本文提出了Anchor-Align方法，在BC的基础上增加了两个目标函数。首先是“视觉-语言锚定（Vision-Language Anchoring）”，通过从冻结的VLM副本中提取逐层表示进行知识蒸馏，防止模型在微调中发生表示漂移。其次是“语言-动作对齐（Language-Action Alignment）”，将连续的动作目标转换为离散的运动方向标签，并在同一机器人观测数据上联合训练语言和动作预测，从而实现模态间的深度对齐。

在真实的xArm7机器人上，Anchor-Align在两种主流VLA架构上均显著提升了任务成功率（分别从28%提升至54%，以及从37%提升至60%）。在LIBERO-PRO、LIBERO-Plus和CALVIN等大规模仿真基准测试中，该方法在分布外（OOD）扰动、感知鲁棒性和长程控制任务上均表现出一致且显著的性能提升。

该研究证明了在VLA微调中，保留预训练表示与有效的动作学习并非根本对立。通过引入简单的辅助目标函数，Anchor-Align有效缓解了灾难性遗忘，大幅提升了具身智能体在复杂和未知环境下的泛化能力，为未来VLA模型的训练范式提供了重要参考。

**研究动机**：现存方案最大的痛点是，直接用行为克隆（BC）微调 VLM 会破坏其预训练的视觉和语义表征（灾难性遗忘）；而常规的“网络数据协同训练”方法将语言损失和动作损失作用于不同的观测数据上，导致语言和动作在特征空间中脱节。本文的切入点极为巧妙：不依赖额外的网络数据，而是通过冻结的 VLM 提取特征作为“锚点”来保鲜表征，并强制在同一机器人观测上同时预测动作和离散化的动作方向标签，实现语言与动作的强绑定。

**核心机制**：引入一个冻结的原始 VLM 作为教师网络约束微调模型的中间层特征（Anchoring），同时将连续动作转化为离散的文本方向标签，让模型在预测动作的同时预测该文本标签（Alignment）。

**关键数据**：
- **核心数据**：在真实的 xArm7 机器人上，跨两种主流 VLA 架构，成功率分别从 28% 提升至 54%，以及从 37% 提升至 60%。
- **理由**：真实物理环境下的显著提升最能直接证明该方法在克服 OOD（分布外）扰动和保持视觉鲁棒性方面的有效性。
- **存疑数据**：论文在 CALVIN 等长程任务上的提升虽然被描述为“一致的（consistent）”，但其语言-动作对齐仅依赖于将动作离散化为简单的方向标签（如“向上”、“向下”）。对于极其复杂的高自由度精细操作，这种粗粒度的标签映射是否依然有效且不引入语义歧义，实验中未给出明确的极限测试。

### 第二模块：核心架构解释

Anchor-Align 的核心架构建立在标准的 VLA 行为克隆基础之上，通过引入两个额外的正则化目标来重塑微调过程。

1. **基础行为克隆 (BC)**：模型接收当前视角的图像和自然语言指令，输出对应的机器人动作。
2. **视觉-语言表征锚定 (Vision-Language Anchoring)**：在内存中保留一个原始 VLM 的冻结副本。在微调 VLA 时，提取 VLA 中间层特征与冻结 VLM 对应层特征，计算两者之间的均方误差（MSE）。这一步本质上是特征级知识蒸馏，强制 VLA 在拟合动作数据时，其底层视觉和语义特征不偏离预训练空间。
3. **语言-动作对齐 (Language-Action Alignment)**：将原本纯数字的连续动作目标（如末端执行器的 XYZ 偏移量）通过启发式规则转换为离散的语义方向标签（例如 "move right and down"）。在同一个机器人观测数据上，模型不仅要通过动作头输出连续动作，还要通过语言建模头输出这个离散的方向标签。这迫使视觉、语言和动作在同一个特征流中发生交互。
4. **联合优化**：最终的损失函数是行为克隆损失、锚定损失和对齐损失的加权和。

**核心伪代码实现**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class AnchorAlignVLA(nn.Module):
    def __init__(self, pretrained_vlm, action_dim):
        super().__init__()
        # 1. 初始化可训练的 VLA 和冻结的 VLM 副本
        self.vla = pretrained_vlm.clone()
        self.frozen_vlm = pretrained_vlm.clone()
        self.frozen_vlm.eval()
        for param in self.frozen_vlm.parameters():
            param.requires_grad = False
            
        # 动作预测头
        self.action_head = nn.Linear(self.vla.hidden_size, action_dim)

    def action_to_text_label(self, action):
        # 将连续动作转换为离散的文本方向标签 (例如: "move left and up")
        # 此处为逻辑抽象
        return discretize_to_text(action)

    def forward(self, image, instruction, target_action):
        # 2. 基础行为克隆 (BC)
        vla_features, vla_hidden_states = self.vla(image, instruction, return_hidden=True)
        pred_action = self.action_head(vla_features)
        loss_bc = F.mse_loss(pred_action, target_action)

        # 3. 视觉-语言表征锚定 (Anchoring)
        with torch.no_grad():
            _, frozen_hidden_states = self.frozen_vlm(image, instruction, return_hidden=True)
            
        loss_anchor = 0
        # 计算中间层的特征蒸馏损失，防止表征漂移
        for vla_h, frozen_h in zip(vla_hidden_states, frozen_hidden_states):
            loss_anchor += F.mse_loss(vla_h, frozen_h)

        # 4. 语言-动作对齐 (Alignment)
        target_text_label = self.action_to_text_label(target_action)
        # 强制模型在同一观测下预测动作的文本描述
        pred_text_logits = self.vla.language_head(vla_features)
        loss_align = F.cross_entropy(pred_text_logits, target_text_label)

        # 5. 联合损失
        alpha, beta = 0.1, 0.1 # 权重超参数
        total_loss = loss_bc + alpha * loss_anchor + beta * loss_align
        
        return total_loss
```

```python
class REALAgent:
    def __init__(self, vlm_policy):
        # 经过 SFT 和 Online RL 训练的视觉语言模型
        self.policy = vlm_policy 
        self.episodic_memory = []

    def step(self, user_instruction, env_api):
        # 1. 获取无特权视觉观测 (严格对齐真实世界)
        visual_obs = env_api.get_egocentric_vision()
        self.episodic_memory.append(visual_obs)

        # 2. VLM 结合历史记忆进行高层推理
        action_intent = self.policy.reason(user_instruction, self.episodic_memory)

        # 3. 交互式意图消除歧义 (Human-in-the-loop)
        if action_intent.type == "ASK_USER":
            clarification = env_api.communicate(action_intent.question)
            self.episodic_memory.append(clarification)
            return "CONTINUE"

        # 4. 主动视觉探索
        elif action_intent.type == "EXPLORE":
            env_api.navigate_to(action_intent.target_area)
            return "CONTINUE"

        # 5. 调用底层技能执行物理操作
        elif action_intent.type == "MANIPULATE":
            success = env_api.execute_skill(
                skill_name=action_intent.skill_name, 
                params=action_intent.params
            )
            return "DONE" if success else "RETRY"
```

### 第二模块：核心架构解释

GigaWorld-Policy-0.5 的核心逻辑在于**“训练时联合，推理时解耦”**。其模型架构与数据流转流程如下：

1.  **多模态输入编码 (Input Encoding)**：
    *   将左、前、右三个视角的图像拼接为复合图像，通过预训练的 VAE 编码为视觉 Token。
    *   机器人本体状态（State）和动作块（Action Chunk）通过 MLP 映射到统一维度。
    *   文本指令通过 umT5 编码为条件 Token。
2.  **混合专家 Transformer (MoT Backbone)**：
    *   模型摒弃了完全共享的 Transformer，转而设计了 **Visual Expert** 和 **Action Expert**。
    *   Visual Expert 继承自大规模预训练世界模型（GigaWorld-1），专门处理当前与未来的视觉 Token。
    *   Action Expert 维度更小（轻量化），专门负责动作 Token 的去噪与预测。
3.  **动作中心化因果掩码 (Action-Centered Causal Masking)**：
    *   在多模态自注意力层中，施加严格的掩码：动作 Token **只能**关注当前视觉、状态和文本；未来视觉 Token **可以**关注动作 Token。这防止了未来信息向动作的穿越，同时迫使动作表征符合世界模型的演化规律。
4.  **流匹配联合优化 (Flow Matching)**：
    *   训练时，对动作和未来视觉分别注入不同时间步的噪声，通过回归预测速度场（Velocity Field）来联合优化两个模态。
5.  **极速推理管线 (Efficient Inference)**：
    *   部署时，直接丢弃未来视觉 Token 的输入与计算，仅激活 Action Expert。配合 KV Cache、`torch.compile` 图编译以及纯 C++ 运行时，实现极致加速。

**核心伪代码 (Python 风格)**：

```python
import torch
import torch.nn as nn

class ActionCenteredMoT(nn.Module):
    def __init__(self, visual_dim=3072, action_dim=1024):
        super().__init__()
        # 独立专家设计
        self.visual_expert = TransformerBlocks(dim=visual_dim)
        self.action_expert = TransformerBlocks(dim=action_dim)
        
        # 跨模态注意力机制 (简化示意)
        self.multi_modal_attn = MultiModalAttention()

    def generate_causal_mask(self, num_context, num_action, num_future):
        """
        构建动作中心化因果掩码
        True 表示允许注意力，False 表示掩码（阻断）
        """
        total_len = num_context + num_action + num_future
        mask = torch.ones((total_len, total_len), dtype=torch.bool)
        
        # 核心逻辑：动作 Token 不能看未来视觉 Token
        action_start = num_context
        action_end = num_context + num_action
        future_start = action_end
        
        mask[action_start:action_end, future_start:] = False 
        return mask

    def forward(self, context_tokens, action_tokens, future_visual_tokens=None, inference_mode=False):
        """
        context_tokens: 包含当前视觉、状态、文本指令
        """
        if inference_mode:
            # 推理阶段：完全跳过未来视觉计算，仅使用 Action Expert
            # 结合 KV Cache 避免重复计算 context
            action_features = self.action_expert(context_tokens, action_tokens)
            pred_action_velocity = predict_velocity(action_features)
            return pred_action_velocity
            
        else:
            # 训练阶段：联合建模
            mask = self.generate_causal_mask(len(context_tokens), len(action_tokens), len(future_visual_tokens))
            
            # 视觉专家处理视觉流
            visual_features = self.visual_expert(context_tokens, future_visual_tokens)
            # 动作专家处理动作流
            action_features = self.action_expert(context_tokens, action_tokens)
            
            # 多模态信息交互 (受因果掩码严格限制)
            joint_features = self.multi_modal_attn(visual_features, action_features, mask)
            
            pred_action_velocity = predict_action_velocity(joint_features)
            pred_visual_velocity = predict_visual_velocity(joint_features)
            
            return pred_action_velocity, pred_visual_velocity
```

### 第二模块：核心架构解释

当前论文的方法是一个纯训练期的正则化/对齐框架。其核心流程分为特征提取、通道解耦、语义对齐、特征约束四个步骤。在部署测试时，所有附加模块均被移除。

**1. 特征提取：**
在 VLA 模型的前向传播中，截取网络中间层（如第 10 层）的动作 token 隐藏状态。

**2. 通道解耦（Shared-Private Decomposition）：**
将提取出的动作特征输入两个独立的线性网络（MLP）。一个网络输出“共享特征”（包含任务意图），另一个网络输出“私有特征”（包含空间几何、时间、电机控制等物理细节）。

**3. 语义对齐（Semantic Alignment）：**
将所有动作 token 的“共享特征”通过注意力机制聚合成一个句子级别的特征向量。然后，计算该向量与外部冻结视觉语言模型（如 EgoHOD）提取的指令文本向量之间的对比损失（InfoNCE）。这迫使共享特征向高质量的语义空间靠拢。

**4. 特征约束（Reconstruction & Decorrelation）：**
为了保证拆分后的特征没有丢失信息且互不干扰，引入两个额外的计算：一是将共享特征和私有特征相加后，必须能还原出原始的动作特征（重建损失）；二是计算共享特征和私有特征之间的余弦相似度，惩罚它们的重合度，迫使它们各自独立（解缠损失）。

**核心伪代码实现 (Python 风格):**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

def semantic_anchoring_loss(action_features, text_instruction, frozen_text_encoder, modules):
    """
    action_features: VLA 中间层输出的动作特征, shape (Batch, Tokens, Dim)
    text_instruction: 语言指令
    frozen_text_encoder: 冻结的外部文本编码器 (如 EgoHOD)
    modules: 包含解耦、投影、注意力等可学习模块的字典
    """
    B, T, D = action_features.shape
    
    # 1. 通道解耦 (Channel Decomposition)
    # 将原始特征拆分为共享(语义)和私有(执行)特征
    shared_features = modules['encoder_shared'](action_features)   # (B, T, D_s)
    private_features = modules['encoder_private'](action_features) # (B, T, D_s)
    
    # 2. 语义对齐 (Semantic Alignment)
    # 使用可学习的 Query 对共享特征进行注意力池化，聚合成单向量
    attention_weights = F.softmax(
        torch.matmul(shared_features, modules['query_vector']) / (D_s ** 0.5), 
        dim=1
    )
    pooled_shared = torch.sum(attention_weights * shared_features, dim=1) # (B, D_s)
    
    # 获取外部冻结模型的文本特征
    with torch.no_grad():
        target_text_embedding = frozen_text_encoder(text_instruction) # (B, D_e)
        
    # 投影到同一维度并计算对比损失 (InfoNCE)
    proj_shared = modules['proj_action'](pooled_shared)
    proj_text = modules['proj_text'](target_text_embedding)
    loss_align = info_nce_loss(proj_shared, proj_text)
    
    # 3. 特征重建 (Reconstruction)
    # 确保拆分后的特征相加能还原回原始特征
    reconstructed_features = modules['decoder'](shared_features + private_features)
    loss_recon = F.mse_loss(reconstructed_features, action_features)
    
    # 4. 特征解缠 (Decorrelation)
    # 惩罚共享特征和私有特征之间的相似度，迫使它们正交
    shared_norm = F.normalize(shared_features, dim=-1)
    private_norm = F.normalize(private_features, dim=-1)
    loss_diff = torch.mean((shared_norm * private_norm).sum(dim=-1) ** 2)
    
    # 总辅助损失
    total_aux_loss = lambda_align * loss_align + lambda_r * loss_recon + lambda_d * loss_diff
    
    return total_aux_loss
```

**研究动机**：现存方案最大的痛点是，直接用行为克隆（BC）微调 VLM 会破坏其预训练的视觉和语义表征（灾难性遗忘）；而常规的“网络数据协同训练”方法将语言损失和动作损失作用于不同的观测数据上，导致语言和动作在特征空间中脱节。本文的切入点极为巧妙：不依赖额外的网络数据，而是通过冻结的 VLM 提取特征作为“锚点”来保鲜表征，并强制在同一机器人观测上同时预测动作和离散化的动作方向标签，实现语言与动作的强绑定。

**核心机制**：引入一个冻结的原始 VLM 作为教师网络约束微调模型的中间层特征（Anchoring），同时将连续动作转化为离散的文本方向标签，让模型在预测动作的同时预测该文本标签（Alignment）。

**关键数据**：

- **存疑数据**：论文在 CALVIN 等长程任务上的提升虽然被描述为“一致的（consistent）”，但其语言-动作对齐仅依赖于将动作离散化为简单的方向标签（如“向上”、“向下”）。对于极其复杂的高自由度精细操作，这种粗粒度的标签映射是否依然有效且不引入语义歧义，实验中未给出明确的极限测试。

### 第二模块：核心架构解释

Anchor-Align 的核心架构建立在标准的 VLA 行为克隆基础之上，通过引入两个额外的正则化目标来重塑微调过程。

1. **基础行为克隆 (BC)**：模型接收当前视角的图像和自然语言指令，输出对应的机器人动作。
2. **视觉-语言表征锚定 (Vision-Language Anchoring)**：在内存中保留一个原始 VLM 的冻结副本。在微调 VLA 时，提取 VLA 中间层特征与冻结 VLM 对应层特征，计算两者之间的均方误差（MSE）。这一步本质上是特征级知识蒸馏，强制 VLA 在拟合动作数据时，其底层视觉和语义特征不偏离预训练空间。
3. **语言-动作对齐 (Language-Action Alignment)**：将原本纯数字的连续动作目标（如末端执行器的 XYZ 偏移量）通过启发式规则转换为离散的语义方向标签（例如 "move right and down"）。在同一个机器人观测数据上，模型不仅要通过动作头输出连续动作，还要通过语言建模头输出这个离散的方向标签。这迫使视觉、语言和动作在同一个特征流中发生交互。
4. **联合优化**：最终的损失函数是行为克隆损失、锚定损失和对齐损失的加权和。

**核心伪代码实现**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class AnchorAlignVLA(nn.Module):
    def __init__(self, pretrained_vlm, action_dim):
        super().__init__()
        # 1. 初始化可训练的 VLA 和冻结的 VLM 副本
        self.vla = pretrained_vlm.clone()
        self.frozen_vlm = pretrained_vlm.clone()
        self.frozen_vlm.eval()
        for param in self.frozen_vlm.parameters():
            param.requires_grad = False
            
        # 动作预测头
        self.action_head = nn.Linear(self.vla.hidden_size, action_dim)

    def action_to_text_label(self, action):
        # 将连续动作转换为离散的文本方向标签 (例如: "move left and up")
        # 此处为逻辑抽象
        return discretize_to_text(action)

    def forward(self, image, instruction, target_action):
        # 2. 基础行为克隆 (BC)
        vla_features, vla_hidden_states = self.vla(image, instruction, return_hidden=True)
        pred_action = self.action_head(vla_features)
        loss_bc = F.mse_loss(pred_action, target_action)

        # 3. 视觉-语言表征锚定 (Anchoring)
        with torch.no_grad():
            _, frozen_hidden_states = self.frozen_vlm(image, instruction, return_hidden=True)
            
        loss_anchor = 0
        # 计算中间层的特征蒸馏损失，防止表征漂移
        for vla_h, frozen_h in zip(vla_hidden_states, frozen_hidden_states):
            loss_anchor += F.mse_loss(vla_h, frozen_h)

        # 4. 语言-动作对齐 (Alignment)
        target_text_label = self.action_to_text_label(target_action)
        # 强制模型在同一观测下预测动作的文本描述
        pred_text_logits = self.vla.language_head(vla_features)
        loss_align = F.cross_entropy(pred_text_logits, target_text_label)

        # 5. 联合损失
        alpha, beta = 0.1, 0.1 # 权重超参数
        total_loss = loss_bc + alpha * loss_anchor + beta * loss_align
        
        return total_loss
```

### 第二模块：核心架构解释

$S^2$-VLA 的核心逻辑在于“分而治之，后置融合”。整个前向传播流程分为三个独立但协同的模块：

1.  **多尺度语义流 (Multi-Scale Semantic Stream):**
    输入文本指令、历史自车状态和图像。使用 InternVL3-2B 作为骨干网络。为了避免只使用最后一层高度抽象特征导致的细节丢失，模型注入了 64 个 Action Queries，并从 Transformer 的特定层（如 3, 8, 13, 18, 23, 24 层）稀疏采样隐藏状态，输出包含高维驾驶意图的密集语义特征和动作中心特征。
2.  **任务驱动空间流 (Task-Driven Spatial Stream):**
    完全绕过语言模型的自回归瓶颈。直接从 Vision Transformer (ViT) 提取未压缩的视觉特征。为了强制网络学习物理边界，该流引入了两个辅助监督任务：Map Head（预测局部 BEV 语义地图）和 Agent Head（预测动态障碍物 2D 边界框）。这使得输出的特征具备严格的几何与空间先验。
3.  **双流规划适配器 (Dual-Stream Planning Adapter):**
    这是一个级联的交叉注意力解码器。第一阶段（语义对齐）：用可学习的规划 Token 查询语义流特征，确立粗粒度的导航意图。第二阶段（空间细化）：将第一阶段的输出作为 Query，去查询空间流的密集几何特征，强制轨迹贴合物理边界。最后通过 MLP 解码出未来轨迹。

```python
import torch
import torch.nn as nn

class S2VLA(nn.Module):
    def __init__(self):
        super().__init__()
        # 1. Semantic Stream Components
        self.vlm_backbone = InternVL3_2B()
        self.action_queries = nn.Parameter(torch.randn(64, hidden_dim))
        self.ego_mlp = nn.Linear(ego_state_dim, hidden_dim)
        
        # 2. Spatial Stream Components
        self.vit = VisionTransformer()
        self.map_head = BEVMapHead()
        self.agent_head = AgentDetectionHead()
        
        # 3. Dual-Stream Planning Adapter
        self.planning_tokens = nn.Parameter(torch.randn(8, hidden_dim)) # 8 waypoints
        self.adapter_blocks = nn.ModuleList([AdapterBlock() for _ in range(N)])
        self.traj_decoder = nn.Linear(hidden_dim, 3) # (x, y, heading)

    def forward(self, image, text_cmd, ego_hist):
        # --- Semantic Stream ---
        # Extract multi-scale features from specific layers
        v_sem, v_act = self.vlm_backbone(image, text_cmd, self.action_queries)
        e_ego = self.ego_mlp(ego_hist)
        e_mem = torch.cat([v_act, e_ego], dim=1) # Intent-aware memory
        
        # --- Spatial Stream ---
        # Bypass LLM, extract uncompressed visual features
        v_vis = self.vit(image)
        # Auxiliary tasks for geometric priors (used in loss computation during training)
        pred_map = self.map_head(v_vis)
        pred_agents = self.agent_head(v_vis)
        v_spatial = linear_proj(v_vis) # Dense geometric features
        
        # --- Dual-Stream Planning Adapter ---
        p_tokens = self.planning_tokens
        for block in self.adapter_blocks:
            # Stage 1: Semantic & State Alignment (Coarse Intent)
            p_raw = block.cross_attn_sem(query=p_tokens, key=v_sem, value=v_sem)
            p_ego = block.cross_attn_ego(query=p_tokens, key=e_mem, value=e_mem)
            p_sa = block.self_attn(p_tokens)
            p_fuse = p_tokens + linear_proj(torch.cat([gated(p_raw), p_ego, p_sa], dim=-1))
            
            # Stage 2: Visual Spatial Refinement (Strict Geometric Constraint)
            p_vis = p_fuse + block.cross_attn_spatial(query=p_fuse, key=v_spatial, value=v_spatial)
            p_tokens = p_vis + block.ffn(p_vis)
            
        # Decode final trajectory
        pred_traj = self.traj_decoder(p_tokens)
        
        return pred_traj, pred_map, pred_agents
```

### 第二模块：核心架构解释

DynaDreamer 的核心架构通过将物理学方程与 Transformer 世界模型深度绑定，形成了一个“物理-像素”闭环。其运行流程可拆解为三个关键部分：

1. **物理驱动的自车动力学编解码器 (Ego-Dynamics Encoder-Decoder)**：
   接收过去 $K$ 步的自车状态和动作，通过 GRU 提取出包含底盘物理参数（质量、轴距、轮胎刚度等）的动力学上下文（VD-context, $\psi_t$）。预测未来状态时，采用“单辙自行车模型 (Bicycle ODE) + 神经轮胎模型 + 神经残差”的混合架构，确保推演既符合物理定律，又能吸收未建模的高阶动态。
2. **动力学调制的 Transformer 世界模型 (Ego-Dynamics-Modulated WM)**：
   传统的 Transformer 无法适应不同车辆的异构动力学。本文将 $\psi_t$ 通过 AdaLN（自适应层归一化）作为 Scale 和 Shift 参数注入到 Transformer 的每个注意力块和 FFN 块中。同时，使用 RoPE（旋转位置编码）替代绝对位置编码，确保位置信息与动力学调制通道严格正交，互不干扰。
3. **动力学对齐的想象推演 (Dynamics-Aligned Imagination)**：
   在强化学习的“想象（Rollout）”阶段，由于没有真实的物理反馈，模型使用前述的 ODE 预测器一步步向前滚动更新 $\psi_t$。同时，将 $\psi_t$ 注入到 KV Cache 中，确保生成的长序列轨迹在物理逻辑上始终与当前底盘参数保持一致。

### 第二模块：核心架构解释

PhysClaw-0 的核心架构是一个“验证门控（Verification-gated）+ 记忆检索”的闭环控制流。其运行流程可拆解为以下四个阶段：

1. **任务分析与规划 (Task Analysis & Planning)**：Agent 接收人类初始指令，结合环境观测，调用工具库生成包含“收集动作、重置动作、以及对应的 VLM 验证 Prompt”的完整计划。
2. **自主收集与验证循环 (Autonomous Collect-Verify-Reset Loop)**：机器人执行动作后，调用 VLM 对当前图像进行判定（Pass/Fail）。若失败则触发自动重试；若重试次数耗尽（达到 Retry Budget），则暂停并向人类发出警报（Alert）。
3. **语言干预与纠正记忆 (Language Intervention & Corrective Memory)**：人类通过自然语言指出错误（如“对于软物体，抓取深度增加1厘米”）。LLM 解析器将该语言转化为结构化规则（Trigger, Correction, Scope），并存入轻量级的 Markdown 记忆库中。后续回合在执行前会检索该记忆库，自动应用匹配的规则。
4. **数据沉淀与策略微调 (Data Consolidation & Policy Fine-tuning)**：经过 VLM 验证和人类规则修正后收集到的高质量轨迹，被打包用于微调底层的 VLA 模型（如 $\pi_{0.5}$），完成数据飞轮的闭环。

```python
class PhysClaw0:
    def __init__(self, vlm_verifier, llm_parser, vla_policy):
        self.vlm = vlm_verifier
        self.llm = llm_parser
        self.policy = vla_policy
        self.corrective_memory = [] # 存储持久化规则
        self.retry_limit = 3

    def run_session(self, task_instruction):
        # 阶段1：生成初始计划与验证标准
        plan, verify_prompt = self.llm.plan_task(task_instruction)
        
        while True: # 连续收集循环
            # 阶段2 & 3：执行收集与重置，带记忆注入
            success = self.run_phase(plan.collect, verify_prompt.collect)
            if success:
                self.save_trajectory()
                self.run_phase(plan.reset, verify_prompt.reset)

    def run_phase(self, action_plan, prompt):
        # 注入历史纠正记忆（修改动作参数或验证标准）
        action_plan, prompt = self.apply_memory(action_plan, prompt, self.corrective_memory)
        
        for attempt in range(self.retry_limit):
            self.policy.execute(action_plan)
            observation = get_camera_image()
            
            # VLM 门控验证
            verdict = self.vlm.verify(observation, prompt)
            if verdict == "YES":
                return True
                
        # 阶段3：重试耗尽，请求人类语言干预
        return self.request_human_intervention(action_plan, prompt)

    def request_human_intervention(self, action_plan, prompt):
        human_feedback = wait_for_human_text()
        
        # LLM 解析人类反馈，提取结构化规则
        rule = self.llm.parse_to_rule(human_feedback, current_state)
        
        if rule.is_persistent:
            # 存入纠正记忆，后续回合永久生效
            self.corrective_memory.append(rule)
            
        # 立即应用当前纠正并重试
        corrected_plan, corrected_prompt = self.apply_rule(action_plan, prompt, rule)
        return self.run_phase(corrected_plan, corrected_prompt)
```

### 第二模块：核心架构解释

M$^4$World 的核心架构建立在一个共享的扩散 Transformer (DiT) 骨干网络之上，通过统一的潜空间处理多视角图像与激光雷达数据，并采用自回归分块（Chunk-wise）的方式进行长时序流式生成。

**1. 多模态与多视角统一编码**
模型将多视角图像和激光雷达的距离图（Range Map）通过同一个视频 VAE 压缩到统一的潜空间中。在 DiT 内部，除了常规的时空自注意力机制，还引入了跨视角注意力（Cross-View Attention），使得不同视角的特征能够相互交互，确保 360 度环视和激光雷达在几何与视觉上的一致性。

**2. 细粒度对象控制令牌 (Object Tokens)**
有别于传统的 ControlNet 空间注入，M$^4$World 将控制信号 Token 化。对于场景中的每一个对象，模型提取其 3D 边界框（傅里叶编码）、语义类别、图像特征（SigLIP 提取）和文本描述（umT5 提取），通过 MLP 拼接压缩成一个高维的“对象令牌”。这些令牌与全局天气、自车位姿、BEV 地图等信号一起，通过交叉注意力层注入 DiT。

**3. 五阶段长时序流式训练流**
为了实现低延迟的分钟级生成，模型经历了复杂的渐进式训练：
*   **双向中期训练**：在全量控制信号下训练双向视频生成先验。
*   **教师强制因果适应**：引入因果掩码，利用真实历史帧作为上下文预测未来块。
*   **少步学生 ODE 初始化**：用教师模型生成 ODE 轨迹，监督一个 4 步去噪的学生模型。
*   **自强制与非对称 DMD**：学生模型在训练中暴露于自身生成的历史（Self-Forcing），并使用 DMD 蒸馏对齐教师分布，解决误差累积。
*   **长视频迭代微调**：在 600 帧的自生成序列上进行微调，进一步稳定长时序表现。

**核心伪代码实现逻辑**：

```python
import torch
import torch.nn as nn

class M4WorldDiTBlock(nn.Module):
    def __init__(self, hidden_dim):
        super().__init__()
        self.spatial_temporal_attn = SelfAttention(hidden_dim)
        self.cross_view_attn = CrossViewAttention(hidden_dim)
        self.condition_cross_attn = CrossAttention(hidden_dim)
        self.ffn = FeedForward(hidden_dim)
        
    def forward(self, x, context, view_indices):
        # x: [B, Seq_len, Dim] - Spatiotemporal latent tokens
        # context: [B, Cond_len, Dim] - Fused control tokens (Global + Object-specific)
        
        # 1. Spatiotemporal reasoning
        x = x + self.spatial_temporal_attn(LayerNorm(x))
        
        # 2. Inject heterogeneous control signals (Object appearance, 3D box, ego pose, etc.)
        x = x + self.condition_cross_attn(LayerNorm(x), context)
        
        # 3. Cross-view aggregation (applied every few blocks)
        x = x + self.cross_view_attn(LayerNorm(x), view_indices)
        
        # 4. FFN
        x = x + self.ffn(LayerNorm(x))
        return x

def autoregressive_streaming_rollout(model, vae, initial_context, control_signals_stream, steps=4):
    """
    Simulates the minute-long streaming generation with Latent Context Refresh.
    """
    current_context = initial_context # z_{1:T}
    generated_chunks = []
    
    for chunk_idx, future_controls in enumerate(control_signals_stream):
        # Initialize noisy latent for the next chunk
        noisy_latent = torch.randn_like(current_context)
        
        # 4-step denoising loop (distilled via DMD)
        for t in reversed(range(steps)):
            # Predict velocity field
            v_pred = model(noisy_latent, t, current_context, future_controls)
            # Euler step update
            noisy_latent = noisy_latent - v_pred * (1.0 / steps)
            
        clean_chunk = noisy_latent
        generated_chunks.append(clean_chunk)
        
        # Latent Context Refresh: 
        # Instead of pure KV caching, feed the last frame's latent back as explicit context
        # to prevent inter-chunk flickering artifacts.
        current_context = clean_chunk[:, -1:] 
        
    # Decode all chunks asynchronously
    return vae.decode(torch.cat(generated_chunks, dim=1))
```

### 第二模块：核心架构解释

本文的系统架构分为离线标注、进度追踪和动作预测三个解耦的模块。实验的核心变量仅在于“进度追踪”输出的阶段信息，如何传递给“动作预测”模块。

1.  **动作分割 (Action Segmentation):** 离线阶段，使用 Qwen2.5-VL 将长程演示轨迹分割为多个有序的语义阶段（如：靠近、抓取、放置），确定每个阶段的帧边界。
2.  **进度模块 (Progress Module):** 训练一个独立的轻量级网络 $g_\phi$。在闭环执行时，它接收当前观测、状态、任务指令和当前阶段文本，预测当前阶段的完成度。当完成度超过阈值时，阶段指针 $k_t$ 加 1。
3.  **动作模块接口 (Action-Module Interfaces):** 动作策略（基于 GR00T 的 DiT 架构）接收信息的路径分为三种对比设置：
    *   **Original:** 不接收任何阶段信息。
    *   **TaskCtx (Semantic Stage Interface):** 将当前阶段的文本描述（如 "PressButton the stove"）拼接到全局任务指令后，通过 VLM 处理。
    *   **Ordinal Stage-State:** 保持全局任务指令不变，将阶段指针 $k_t$ 进行 Min-Max 归一化得到标量 $z_t \in [-1, 1]$，将其作为第 9 个维度拼接到机器人的本体状态向量（State）中，直接送入动作投影器。

```python
    def __init__(self, interface_type):
        self.interface_type = interface_type
        self.vlm_encoder = FrozenVLM()
        self.dit_policy = TrainableDiT()
        self.progress_model = ProgressTracker()
        
    def rollout_step(self, obs, state, task_instruction, current_stage_idx, stage_texts):
        # 1. Progress Module updates the stage pointer
        current_stage_text = stage_texts[current_stage_idx]
        completion_score = self.progress_model(obs, state, task_instruction, current_stage_text)
        
        if completion_score > 0.8 and frames_in_stage >= 15:
            current_stage_idx += 1
            
        # 2. Action Module generates action based on the chosen interface
        if self.interface_type == "Original":
            # Baseline: No stage info
            lang_embed = self.vlm_encoder(task_instruction)
            action = self.dit_policy(obs, state, lang_embed)
            
        elif self.interface_type == "TaskCtx":
            # Semantic Interface: Append stage text to instruction
            modified_instruction = task_instruction + " " + stage_texts[current_stage_idx]
            lang_embed = self.vlm_encoder(modified_instruction)
            action = self.dit_policy(obs, state, lang_embed)
            
        elif self.interface_type == "Ordinal_Stage_State":
            # State Interface: Normalize stage index and append to robot state
            lang_embed = self.vlm_encoder(task_instruction)
            z_t = self.normalize_stage_index(current_stage_idx)
            augmented_state = concat(state, z_t) # State dim: 8 -> 9
            action = self.dit_policy(obs, augmented_state, lang_embed)
            
        return action, current_stage_idx
```

### 第二模块：核心架构解释

DROPJ 框架的运行流程严格分为四个解耦的阶段：世界模型构建、梦境轨迹采集、带理由的奖励模型训练、以及基于 MPC 的安全部署。

1. **学习世界模型 (Learn a World Model)**：利用离线收集的、无奖励的真实世界安全轨迹，训练一个包含视觉编码器（VAE）和记忆/动力学预测器（MDN-RNN）的世界模型。这相当于构建了一个粗糙但可用的“梦境模拟器”。
2. **一次性采集梦境轨迹 (One-shot Dream Trajectories)**：人类用户通过键盘/手柄直接在这个“梦境模拟器”中控制智能体。由于在梦境中，用户可以故意驶入草地或撞击障碍物以生成丰富的正负样本，且无需等待机器缓慢合成。
3. **学习带理由的奖励模型 (Learn a Reward Model from Justified Preferences)**：从梦境轨迹中随机采样轨迹片段对，让人类进行偏好选择。关键在于，人类不仅要选“哪个更好”，还要回答“是否因为安全原因（如撞车、压草地）”。这些安全理由被转化为权重 $w$，直接修改偏好标签 $\mu$ 的值，随后通过最小化交叉熵损失来训练一个多层感知机（MLP）作为奖励模型。
4. **基于 MPC 的部署 (Deployment with MPC)**：在真实环境中，智能体不使用策略网络，而是使用模型预测控制（MPC）。在每个时间步，利用世界模型在隐空间中展开多条随机动作序列，利用训练好的奖励模型对这些序列进行打分，执行得分最高的序列的第一个动作。

```python
import torch
import torch.nn.functional as F

# Phase 1: Train World Model (Offline)
def train_world_model(offline_trajectories):
    vae = VAE().train(offline_trajectories.images)
    latent_states = vae.encode(offline_trajectories.images)
    mdn_rnn = MDN_RNN().train(latent_states, offline_trajectories.actions)
    return vae, mdn_rnn

# Phase 2: One-Shot Dream Trajectory Collection
def collect_dream_trajectories(vae, mdn_rnn, human_user, num_episodes=10):
    dream_buffer = []
    for _ in range(num_episodes):
        z = vae.encode(initial_real_image)
        h = mdn_rnn.init_hidden()
        for step in range(max_steps):
            # Reconstruct for human to see
            visual_obs = vae.decode(z) 
            action = human_user.get_action(visual_obs)
            # Predict next latent state in the dream
            z_next, h_next = mdn_rnn.step(z, action, h)
            dream_buffer.append((z, action, z_next))
            z, h = z_next, h_next
    return dream_buffer

# Phase 3: Train Reward Model with Justifications
def train_reward_model(dream_buffer, human_user, safety_weight=1.0, default_weight=0.75):
    reward_model = MLP()
    optimizer = torch.optim.Adam(reward_model.parameters())
    
    for _ in range(training_steps):
        # Sample a pair of trajectory segments
        seg_0, seg_1 = sample_pair(dream_buffer)
        
        # Human provides preference and safety justification
        # is_safe_0, is_safe_1: boolean; pref: 0 (seg_0), 1 (seg_1), or 0.5 (tie)
        is_safe_0, is_safe_1, pref = human_user.query(seg_0, seg_1)
        
        # Core Innovation: Justification logic to compute label mu
        if not is_safe_0 and is_safe_1:
            mu = 1.0 - safety_weight # Heavily penalize seg_0
        elif is_safe_0 and not is_safe_1:
            mu = safety_weight       # Heavily penalize seg_1
        elif not is_safe_0 and not is_safe_1:
            mu = 0.5                 # Both unsafe, tie
        else:
            # Both safe, use default performance weight
            mu = default_weight if pref == 0 else (1.0 - default_weight)
            if pref == 0.5: mu = 0.5
            
        # Compute predicted rewards
        r_0 = reward_model(seg_0).sum()
        r_1 = reward_model(seg_1).sum()
        
        # Bradley-Terry model probabilities
        p_0 = torch.exp(r_0) / (torch.exp(r_0) + torch.exp(r_1))
        p_1 = torch.exp(r_1) / (torch.exp(r_0) + torch.exp(r_1))
        
        # Cross-entropy loss weighted by justification mu
        loss = -(mu * torch.log(p_0) + (1 - mu) * torch.log(p_1))
        
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        
    return reward_model

    h = mdn_rnn.init_hidden()
    
    while not done:

        best_action = None
        max_return = -float('inf')

        action_sequences = generate_random_sequences(num_samples, horizon)
        
        for seq in action_sequences:
            curr_z, curr_h = z, h
            seq_return = 0
            # Simulate in dream
            for action in seq:
                curr_z, curr_h = mdn_rnn.step(curr_z, action, curr_h)
                seq_return += reward_model(curr_z, action)
                
            if seq_return > max_return:
                max_return = seq_return
                best_action = seq[0] # MPC executes first action
                
        obs, _, done, _ = real_env.step(best_action)
        h = mdn_rnn.update_hidden(z, best_action, h)
```

### 第二模块：核心架构解释

SeekFollow-VLA 的架构流程分为多模态观测编码、特征融合与主干网络处理、以及任务驱动的动作预测三个主要阶段：

1.  **多模态观测编码**：模型接收当前帧与历史帧的 RGB 图像序列。使用 DINO-V3 和 SigLIP 组成的双塔视觉编码器提取特征。为了平衡细节与计算效率，当前帧通过 GridPool 压缩为 64 个细粒度 Token，历史帧压缩为 4 个粗粒度 Token。
2.  **特征融合与主干网络**：视觉 Token 序列通过两层 MLP（跨模态投影层）映射到语言特征空间，随后与融合了“搜索+跟随”意图的自然语言指令 Token 进行拼接。拼接后的序列输入到预训练的 Qwen3-4B 大语言模型中，输出包含丰富上下文的多模态表征。
3.  **任务驱动的双头动作预测**：多模态表征被送入顶层的动作预测模块。该模块包含一个搜索动作头、一个跟随动作头以及一个任务驱动路由器（Task-Driven Router）。路由器输出两个值：用于加权两个动作头预测轨迹的路由权重，以及用于预测当前所处阶段（搜索或跟随）的任务 Logits。
4.  **联合优化**：训练时，除了对最终融合的航点（Waypoints）计算均方误差（MSE）损失外，还引入了基于真实阶段标签（0代表搜索，1代表跟随）的交叉熵损失，强制路由器学习明确的阶段感知能力。

**核心伪代码实现 (Python 风格)**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class SeekFollowVLA(nn.Module):
    def __init__(self, vlm_backbone, action_dim=3, waypoint_horizon=10):
        super().__init__()
        self.vlm = vlm_backbone
        
        # Dual Action Heads
        self.seek_head = nn.Sequential(
            nn.LayerNorm(vlm_hidden_dim),
            nn.Linear(vlm_hidden_dim, 256),
            nn.GELU(),
            nn.Linear(256, waypoint_horizon * action_dim),
            nn.Tanh()
        )
        self.follow_head = nn.Sequential(
            nn.LayerNorm(vlm_hidden_dim),
            nn.Linear(vlm_hidden_dim, 256),
            nn.GELU(),
            nn.Linear(256, waypoint_horizon * action_dim),
            nn.Tanh()
        )
        
        # Task-Driven Router
        self.router = nn.Sequential(
            nn.Linear(vlm_hidden_dim, 128),
            nn.GELU(),
            nn.Linear(128, 2) # Outputs logits for [seek, follow]
        )

    def forward(self, visual_tokens, instruction_tokens):
        # 1. Multimodal representation extraction
        multimodal_input = torch.cat([instruction_tokens, visual_tokens], dim=1)
        vlm_features = self.vlm(multimodal_input) # E_T^{LLM}
        
        # 2. Action prediction from dual heads
        seek_waypoints = self.seek_head(vlm_features)
        follow_waypoints = self.follow_head(vlm_features)
        
        # 3. Task-driven routing
        task_logits = self.router(vlm_features) # g_T
        routing_weights = F.softmax(task_logits, dim=-1) # alpha_T
        
        alpha_seek = routing_weights[:, 0].unsqueeze(-1)
        alpha_follow = routing_weights[:, 1].unsqueeze(-1)
        
        # 4. Fuse waypoints
        final_waypoints = alpha_seek * seek_waypoints + alpha_follow * follow_waypoints
        
        return final_waypoints, task_logits

# Loss Computation
def compute_loss(pred_waypoints, gt_waypoints, pred_task_logits, gt_stage_label):
    # Waypoint regression loss (MSE)
    loss_wp = F.mse_loss(pred_waypoints, gt_waypoints)
    
    # Auxiliary stage-aware loss (Cross Entropy)
    loss_stage = F.cross_entropy(pred_task_logits, gt_stage_label)
    
    # Final objective
    beta_nav = 10.0
    total_loss = beta_nav * loss_wp + loss_stage
    return total_loss
```

保持现有的 VLA 模型（如 OpenVLA, π0）或 Diffusion Policy 的参数完全冻结。该模块以固定的高频率运行，持续接收视觉观察和语言指令，输出低级控制动作。

2. **执行质量评估 (Execution Quality Metrics)**
在运行时实时计算两个互补的标量指标，无需额外训练：
- 局部执行质量 (Local Quality): 评估短期物理稳定性。通过计算末端执行器实际移动距离与指令动作幅度的比值（运动有效性），以及瞬时速度的平滑度来得出。
- 全局执行质量 (Global Quality): 评估长期轨迹偏移。将当前执行窗口的特征（位姿、动作、位移）与预先收集的成功轨迹参考库（50条成功轨迹）进行 KNN 匹配，计算当前状态与标称轨迹的距离。

3. **高层智能体策略 (High-level Agentic Policy)**
一个轻量级的 MLP 网络，通过 PPO 算法训练。它以较低的固定频率（每 K 个底层步）运行。其输入为包含本体感受、底层动作和上述两个质量指标的滑动窗口历史记录。其输出为四个离散动作之一：
- EXECUTE: 允许底层策略继续执行。
- RETRY: 使用操作空间控制器 (OSC) 将机器人回退到最近的高质量状态。
- REPAIR: 将机器人回退到更早的、无接触的高质量状态。
- RESET: 终止当前回合。

4. **奖励函数设计 (Reward Design)**
任务成功给予 +1.0，失败给予 -1.0。每一步施加轻微的时间惩罚 (-0.02)。触发恢复机制会根据其强度施加固定惩罚（RETRY -0.1, REPAIR -0.3, RESET -0.5），以抑制策略产生不必要的干预。

```python
class AgenticExecutionFramework:
    def __init__(self, vla_policy, agentic_policy, reference_library):
        self.vla_policy = vla_policy # Frozen low-level policy
        self.agentic_policy = agentic_policy # Trained via PPO
        self.reference_library = reference_library
        self.history_buffer = []
        self.K = 5 # Agentic decision interval
        
    def compute_quality_metrics(self, history):
        # Local quality: motion effectiveness and smoothness
        local_q = compute_local_stability(history)
        # Global quality: KNN distance to successful reference trajectories
        global_q = compute_global_alignment(history, self.reference_library)
        return local_q, global_q

    def execute_task(self, env, instruction):
        obs = env.reset()
        step_count = 0
        
        while not env.done:
            # 1. Low-level action generation
            action = self.vla_policy.get_action(obs.image, instruction)
            
            # 2. Update history and compute metrics
            self.history_buffer.append((obs.proprioception, action))
            local_q, global_q = self.compute_quality_metrics(self.history_buffer)
            
            # 3. High-level agentic decision (runs every K steps)
            if step_count % self.K == 0:
                agentic_state = construct_state(self.history_buffer, local_q, global_q)
                mode = self.agentic_policy.select_action(agentic_state)
                
                # 4. Execute selected mode
                if mode == "EXECUTE":
                    obs = env.step(action)
                elif mode == "RETRY":
                    obs = self.rollback_to_recent_best_state(env, self.history_buffer)
                elif mode == "REPAIR":
                    obs = self.rollback_to_contact_free_state(env, self.history_buffer)
                elif mode == "RESET":
                    obs = env.reset()
                    self.history_buffer.clear()
            else:
                obs = env.step(action)
                
            step_count += 1
```

### 第二模块：核心架构解释

JITOMA 框架将任务推理、感知与记忆统一为一个闭环的即时生长过程，其核心流程分为三个阶段：

1. **前端轻量级感知与休眠锚点生成**：系统接收连续的视觉观测流，通过自顶向下的任务热力图（Task Heatmap）过滤掉大量无关的背景信息。保留下来的最小数据流被用于在全局空间中构建并维护低成本的“休眠锚点（Dormant Anchors）”，形成轻量级的全局基础记忆。
2. **后端认知查询与意图解析**：当接收到新的认知查询或任务指令时，后端的大语言模型（LLM）介入，解析机器人的当前意图，确定完成该任务所需的空间范围与语义目标。
3. **局部子图唤醒与高算力计算**：基于 LLM 的解析结果，系统在全局休眠锚点中进行匹配，动态“唤醒”与任务高度相关的锚点。随后，系统**仅针对**这些被激活的局部子图执行资源密集型操作（如生成密集的节点文本描述、进行功能性推理），从而避免了对全局环境进行无差别的昂贵计算。

```python
class JITOMA_Framework:
    def __init__(self, llm_backend, perception_model):
        self.llm = llm_backend
        self.perception = perception_model
        self.global_dormant_anchors = [] # 低成本全局记忆
        self.active_subgraph = None      # 高成本局部活跃图

    def frontend_process(self, continuous_observation, task_heatmap):
        """前端：过滤观测，维护低成本休眠锚点"""
        # 利用热力图过滤冗余观测
        filtered_stream = self.perception.filter_by_heatmap(continuous_observation, task_heatmap)
        # 提取低成本特征，生成休眠锚点
        new_anchors = self.perception.extract_low_cost_anchors(filtered_stream)
        self.global_dormant_anchors.extend(new_anchors)

    def backend_process(self, cognitive_query):
        """后端：LLM 解析意图，按需唤醒并执行密集计算"""
        # LLM 解析机器人意图
        task_intent = self.llm.parse_intent(cognitive_query)
        
        # 动态唤醒任务相关的休眠锚点
        activated_anchors = self.match_and_awaken(task_intent, self.global_dormant_anchors)
        
        # 仅在激活的局部子图上执行资源密集型操作
        self.active_subgraph = self.execute_intensive_operations(activated_anchors)
        
        return self.active_subgraph

    def execute_intensive_operations(self, anchors):
        """执行高算力消耗的密集描述与功能推理"""
        enriched_nodes = []
        for anchor in anchors:
            dense_caption = self.perception.generate_dense_caption(anchor)
            functional_info = self.perception.infer_functionality(anchor)
            enriched_nodes.append(Node(anchor, dense_caption, functional_info))
        return SubGraph(enriched_nodes)

    def step(self, observation, query, heatmap):
        """闭环执行逻辑"""
        self.frontend_process(observation, heatmap)
        if query is not None:
            active_graph = self.backend_process(query)
            return active_graph
        return None
```
