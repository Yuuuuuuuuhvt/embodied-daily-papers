### 第二模块：核心架构解释

BWM 的核心架构分为数据处理流水线与动作条件生成模型两个部分。

**数据流水线（Data Pipeline）**：
为了保证动作与观测的严格对齐，作者设计了三个步骤：
1. **轨迹重放（Trajectory Replay）**：在仿真器中利用原有的规划器轨迹，重新渲染出高分辨率（480p）的观测图像，但不改变动作的时间戳。
2. **重叠片段采样（Overlapping Clip Sampling）**：使用滑动窗口提取训练片段，每个片段包含：初始环境观测、动态历史窗口、未来观测窗口以及对齐的动作块（Action Chunk）。
3. **初始观测增强（Initial-Observation Enhancement）**：在推理时，如果无法重放，则使用 SeedVR-2 对初始帧进行超分增强。

**模型架构与推理流程（Model Architecture）**：
模型基于 Wan2.2-TI2V-5B 扩散模型。在每次预测一个 Chunk（如 72 帧）时：
1. **输入构建**：将干净的初始帧（$z^0$）、加了低强度噪声的历史帧（$\tilde{z}^{hist}$）和完全噪声化的未来目标帧（$z^{fut}$）拼接。
2. **动作注入**：机器人动作经过归一化后，通过两条路径注入：
   - **Cross-Attention**：独立编码每个动作，提供帧级别的细粒度控制。
   - **AdaLN**：在时间维度上聚合动作序列，调制 DiT 块的特征。
3. **自回归滚动（Autoregressive Rollout）**：预测出当前 Chunk 后，将其加入历史窗口，保留初始帧不变，继续预测下一个 Chunk。

```python
def bwm_autoregressive_rollout(initial_obs, action_sequence, history_len=8, chunk_size=72):
    """
    initial_obs: [1, C, H, W] 干净的初始环境帧
    action_sequence: [T, action_dim] 完整的未来动作序列
    """
    # 初始化动态历史窗口
    dynamic_history = [initial_obs] * history_len 
    generated_rollout = []
    
    # 按 Chunk 进行自回归生成
    for t in range(0, len(action_sequence), chunk_size):
        action_chunk = action_sequence[t : t + chunk_size]
        
        # 1. 视觉特征编码 (VAE)
        z_0 = vae.encode(initial_obs)
        z_hist = vae.encode(dynamic_history[-history_len:])
        
        # 2. 历史帧加噪 (Flow Matching 扰动)
        z_hist_noisy = (1 - sigma_h) * z_hist + sigma_h * torch.randn_like(z_hist)
        
        # 3. 动作条件编码 (双路径注入)
        # 路径 A: 帧级别 Cross-Attention Token
        act_tokens = action_encoder_cross_attn(action_chunk) 
        # 路径 B: 潜变量级别 AdaLN 调制
        act_emb = action_encoder_adaln(action_chunk)
        
        # 4. 扩散模型去噪生成未来 Chunk
        z_pred = torch.randn(chunk_size, latent_dim) # 初始化未来帧噪声
        for tau in scheduler.timesteps:
            # DiT 接收初始帧、加噪历史帧、动作条件进行去噪
            velocity = dit_backbone(
                x=torch.cat([z_0, z_hist_noisy, z_pred], dim=1),
                cross_attn_cond=act_tokens,
                adaln_cond=act_emb,
                timestep=tau
            )
            z_pred = scheduler.step(z_pred, velocity, tau)
            
        # 5. 解码并更新状态
        pred_frames = vae.decode(z_pred)
        generated_rollout.append(pred_frames)
        
        # 更新动态历史（丢弃最旧的帧，加入新生成的帧）
        dynamic_history.extend(pred_frames)
        
    return generated_rollout
```

### 第二模块：核心架构解释

FBFM 的核心思想是将 WAM 的推理过程转化为一个动态的部分可观测生成问题。它不改变预训练的流匹配模型，而是通过在推理期修改速度场（Velocity Field）来注入真实世界的反馈。

**运行流程解析：**
1. **异步重叠（Asynchronous Overlap）**：当机器人正在执行前一个动作块（Chunk $t-1$）的剩余动作时，模型已经开始生成下一个动作块（Chunk $t$）。
2. **动态目标构建（Dynamic Target Construction）**：随着前一个块的动作在真实世界中执行，新的视觉观测 $z_{t+i}$ 不断到达。FBFM 将这些真实观测以及前一个块中已承诺的动作 $a_{t+i}^{prev}$ 组合成一个对齐的目标张量。
3. **掩码伪逆引导（Masked Pseudoinverse Guidance）**：在流匹配的每一个求解步（Solver Step）中，模型首先预测一个干净的端点（Clean Endpoint）。FBFM 计算该预测端点与真实目标之间的残差，并应用一个掩码（仅在有真实反馈的时间步激活）。
4. **速度场修正（Velocity Field Correction）**：通过计算预测端点对当前噪声状态的雅可比矩阵转置（即 VJP），将残差反向传播，计算出修正梯度，从而调整当前步的生成速度场。
5. **架构适配**：
   - **分阶段生成（Stage-wise, 如 LingBot-VA）**：状态流和动作流分开。状态反馈修正状态流，修正后的状态作为上下文条件输入给动作流；动作流同时受前置动作的硬约束。
   - **联合生成（Joint-generation, 如 DreamZero）**：状态和动作在同一个流中生成。状态残差可以通过跨模态雅可比矩阵（Cross-modal Jacobian）直接在同一步骤中修正动作坐标。

```python
    """
    x_t: 当前流匹配的噪声状态 (包含 latent state 和 action)
    tau: 当前流时间 (Flow time)
    real_obs_stream: 异步到达的真实世界观测
    """

    v_pred = model(x_t, tau, history)
    
    # 2. 估计干净的端点 (Clean Endpoint)
    x_clean_pred = x_t + (1 - tau) * v_pred
    
    # 3. 构建对齐的反馈目标与掩码
    # target 包含已执行的动作和最新到达的真实观测
    target = construct_target(real_obs_stream, committed_actions)
    mask = construct_mask(real_obs_stream, committed_actions)
    
    # 4. 计算掩码残差 (仅在有真实反馈的坐标上产生非零残差)
    residual = mask * (target - x_clean_pred)
    
    # 5. 计算雅可比向量积 (VJP) 以获取修正方向
    # g = (d x_clean_pred / d x_t)^T * residual
    g = compute_vjp(func=lambda x: x + (1 - tau) * model(x, tau, history), 
                    inputs=x_t, 
                    v=residual)
    
    # 6. 计算动态引导强度并修正速度场
    lambda_tau = compute_guidance_weight(tau)
    v_guided = v_pred - lambda_tau * g
    
    # 7. 执行欧拉步 (或其它 ODE 求解器步)
    delta_tau = get_step_size()
    x_next = x_t + delta_tau * v_guided
    
    return x_next
```

### 第二模块：核心架构解释

WCM（World Critic Model）的核心逻辑在于摒弃传统的“单帧输入 -> 标量输出”的 Critic 范式，转而构建一个具备时序预测能力的双目标网络。其架构与工作流程如下：

1.  **历史状态编码**：接收多帧历史视觉观测与文本指令，通过视觉-语言编码器（通常复用 VLA 的冻结特征）提取高维特征，并映射为低维潜状态（Latent State）。
2.  **时序动态预测（World Model 目标）**：基于当前的潜状态和执行的动作序列，利用 LeJEPA（Lightweight Joint-Embedding Predictive Architecture）的预测器（Predictor）网络，推演未来时间步的潜状态。
3.  **目标网络对齐**：使用动量更新（Momentum）的目标编码器（Target Encoder）对真实的未来观测进行编码，生成目标潜状态，用于与预测器的输出计算预测损失（Prediction Loss）。
4.  **价值估计（Critic 目标）**：将融合了时序动态信息的表征输入到价值头（Value Head），输出当前状态的 Q 值或状态价值（Value），计算强化学习的 TD 损失（TD Loss）。
5.  **联合优化**：将预测损失与 TD 损失加权求和，端到端更新 Critic 网络。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class WorldCriticModel(nn.Module):
    def __init__(self, encoder, predictor, value_head):
        super().__init__()
        self.encoder = encoder              # 编码器 (Online)
        self.target_encoder = copy.deepcopy(encoder) # 目标编码器 (Momentum)
        self.predictor = predictor          # LeJEPA 预测器
        self.value_head = value_head        # 价值输出头
        
        # 冻结目标编码器梯度
        for param in self.target_encoder.parameters():
            param.requires_grad = False

    def update_target_encoder(self, tau=0.99):
        # 动量更新目标网络
        for online_param, target_param in zip(self.encoder.parameters(), self.target_encoder.parameters()):
            target_param.data.copy_(tau * target_param.data + (1 - tau) * online_param.data)

    def forward(self, obs_history, actions, future_obs):
        # 1. 编码当前历史观测为潜状态
        z_current = self.encoder(obs_history)
        
        # 2. 价值估计 (Critic Objective)
        value = self.value_head(z_current)
        
        # 3. 预测未来潜状态 (World Model Objective)
        # 结合当前潜状态和动作序列预测未来
        z_pred_future = self.predictor(z_current, actions)
        
        # 4. 获取真实的未来潜状态 (使用动量目标编码器)
        with torch.no_grad():
            z_target_future = self.target_encoder(future_obs)
            
        return value, z_pred_future, z_target_future

def compute_loss(wcm, batch, gamma=0.99, lambda_wm=1.0):
    obs_history, actions, rewards, next_obs_history, future_obs, dones = batch
    
    # 前向传播
    values, z_pred, z_target = wcm(obs_history, actions, future_obs)
    
    # 计算 RL TD Loss (以简单的 MSE 为例)
    with torch.no_grad():
        next_values, _, _ = wcm(next_obs_history, actions_next, future_obs_next) # 简化表示
        target_values = rewards + gamma * (1 - dones) * next_values
    td_loss = F.mse_loss(values, target_values)
    
    # 计算 World Model 预测 Loss (Latent 空间的 L2 或 Cosine 距离)
    wm_loss = F.mse_loss(z_pred, z_target)
    
    # 联合 Loss
    total_loss = td_loss + lambda_wm * wm_loss
    return total_loss
```

### 第二模块：核心架构解释

ActFovea 的架构是一个部署在 VLA 策略与物理环境之间的拦截与验证代理。其处理流程分为四个核心阶段：

1.  **动作条件中央凹化 (Action-Conditioned Foveation):** 利用机器人的正向运动学（Forward Kinematics）和上一帧动作，计算出末端执行器的投影接触中心和运动走廊。生成一个掩码（Mask），保留该物理交互区域的高保真视觉信息，并对背景进行平滑和灰度化降敏处理。
2.  **一致性监控 (Consistency Monitoring):** 提取视觉特征的运动质心，计算其与运动学预测中心的几何一致性、动态位移一致性以及时间戳/历史延迟一致性。融合输出一个综合风险状态（正常、可恢复、不可恢复）。
3.  **观测恢复与动作验证 (Observation Recovery & Action Verification):** 当检测到可恢复风险时，生成多个候选观测（如原始图像、中央凹化图像、时间补偿图像、空间修复图像）。将这些候选观测分别输入冻结的 VLA 模型，生成多个候选动作块（Action Chunks）。验证器根据动作方向、平滑度、轨迹漂移等指标对这些动作块进行打分。
4.  **风险自适应执行 (Risk-Adaptive Execution):** 根据最高验证得分和风险状态，决定最终的执行策略：正常执行、缩短动作块执行步长、阻尼减速，或在不可恢复状态下（如画面永久冻结）触发安全熔断（将运动指令置零）。

**核心逻辑伪代码 (Python 风格):**

```python
def actfovea_safeguard_step(obs_t, proprioception_t, action_history, vla_policy):
    # 1. 动作条件中央凹化
    # 基于运动学和历史动作预测交互区域
    fovea_mask = compute_kinematic_fovea(proprioception_t, action_history)
    foveated_obs = apply_background_desensitization(obs_t, fovea_mask)
    
    # 2. 时空一致性监控
    # 评估视觉流、本体感觉与动作之间的物理一致性
    risk_state, risk_score = monitor_consistency(foveated_obs, proprioception_t, action_history)
    
    # 拦截不可恢复的致命错误（如画面持续冻结）
    if risk_state == "UNRECOVERABLE":
        return trigger_safe_failure()
        
    # 3. 观测恢复与候选生成
    candidate_observations = generate_candidates(obs_t, foveated_obs, risk_state)
    
    best_action_chunk = None
    best_verification_score = -1
    
    # 4. 动作验证循环
    for cand_obs in candidate_observations:
        # 调用冻结的 VLA 策略
        cand_action_chunk = vla_policy(cand_obs)
        
        # 验证生成的动作块是否符合物理预期
        v_score = verify_action_chunk(cand_action_chunk, action_history, proprioception_t)
        
        if v_score > best_verification_score:
            best_verification_score = v_score
            best_action_chunk = cand_action_chunk
            
    # 5. 风险自适应执行
    # 根据风险程度决定执行完整动作块，还是截断/减速
    final_action, executable_horizon = adapt_execution_mode(best_action_chunk, best_verification_score, risk_state)
    
    return final_action[:executable_horizon]
```

### 第二模块：核心架构解释

Mirror Learning 框架的本质是一个**数据合成与策略蒸馏流水线**，其核心流程分为三个阶段：

1. **视角转换（Perspective Transformation）**：
   利用少量成对的（第一人称，第三人称）视频数据微调一个预训练的视频扩散模型。在推理阶段，该模型接收无动作标签的第三人称演示视频，生成对应的高保真第一人称视角视频。这一步利用了世界模型的空间几何先验。
2. **动作推断（Action Inference）**：
   训练一个逆动力学模型（Inverse Dynamics Model, IDM）。该模型接收相邻的两帧第一人称图像（真实或生成的），推断出在这两帧之间发生的状态转移所对应的具体动作（Action）。
3. **数据合成与策略训练（Data Synthesis & Policy Training）**：
   将扩散模型生成的第一人称视频帧与 IDM 推断出的动作配对，构建出“镜像数据（Mirror Data）”。最后，将这些伪造的第一人称专家数据（可与真实数据混合）用于标准的行为克隆（Behavior Cloning）训练，得到最终的 VLA 控制策略。

**核心逻辑伪代码（Python 风格）：**

```python
class MirrorLearningFramework:
    def __init__(self, video_diffusion_model, inverse_dynamics_model, policy_network):
        # 预训练/微调后的组件
        self.vdm = video_diffusion_model  # 视角转换模型
        self.idm = inverse_dynamics_model # 逆动力学模型
        self.policy = policy_network      # 最终的控制策略 (VLA)

    def generate_mirror_data(self, third_person_video):
        mirror_data = []
        
        # 1. 视角转换：第三人称 -> 第一人称
        # 输入形状: [T, H, W, C], 输出形状: [T, H, W, C]
        pseudo_first_person_video = self.vdm.generate(third_person_video)
        
        # 2. 动作推断：从相邻帧提取动作
        T = len(pseudo_first_person_video)
        for t in range(T - 1):
            obs_t = pseudo_first_person_video[t]
            obs_t_next = pseudo_first_person_video[t+1]
            
            # 逆动力学推断动作
            pseudo_action = self.idm.predict_action(obs_t, obs_t_next)
            
            # 组装伪造的第一人称专家数据
            mirror_data.append({
                'observation': obs_t,
                'action': pseudo_action
            })
            
        return mirror_data

    def train_policy(self, real_first_person_data, third_person_datasets):
        # 收集所有镜像数据
        all_mirror_data = []
        for tp_video in third_person_datasets:
            mirror_data = self.generate_mirror_data(tp_video)
            all_mirror_data.extend(mirror_data)
            
        # 混合真实数据与伪造数据
        combined_dataset = real_first_person_data + all_mirror_data
        
        # 3. 行为克隆训练
        for batch in get_dataloader(combined_dataset):
            obs = batch['observation']
            target_action = batch['action']
            
            # 预测动作并计算损失
            pred_action = self.policy(obs)
            loss = compute_bc_loss(pred_action, target_action)
            
            # 反向传播更新策略网络
            loss.backward()
            self.policy.optimizer.step()
            
        return self.policy
```

### 第二模块：核心架构解释

BWM 的核心架构分为数据处理流水线与动作条件生成模型两个部分。

**数据流水线（Data Pipeline）**：
为了保证动作与观测的严格对齐，作者设计了三个步骤：
1. **轨迹重放（Trajectory Replay）**：在仿真器中利用原有的规划器轨迹，重新渲染出高分辨率（480p）的观测图像，但不改变动作的时间戳。
2. **重叠片段采样（Overlapping Clip Sampling）**：使用滑动窗口提取训练片段，每个片段包含：初始环境观测、动态历史窗口、未来观测窗口以及对齐的动作块（Action Chunk）。
3. **初始观测增强（Initial-Observation Enhancement）**：在推理时，如果无法重放，则使用 SeedVR-2 对初始帧进行超分增强。

**模型架构与推理流程（Model Architecture）**：
模型基于 Wan2.2-TI2V-5B 扩散模型。在每次预测一个 Chunk（如 72 帧）时：
1. **输入构建**：将干净的初始帧（$z^0$）、加了低强度噪声的历史帧（$\tilde{z}^{hist}$）和完全噪声化的未来目标帧（$z^{fut}$）拼接。
2. **动作注入**：机器人动作经过归一化后，通过两条路径注入：
   - **Cross-Attention**：独立编码每个动作，提供帧级别的细粒度控制。
   - **AdaLN**：在时间维度上聚合动作序列，调制 DiT 块的特征。
3. **自回归滚动（Autoregressive Rollout）**：预测出当前 Chunk 后，将其加入历史窗口，保留初始帧不变，继续预测下一个 Chunk。

**核心逻辑伪代码（Python 风格）**：

```python
import torch

def bwm_autoregressive_rollout(initial_obs, action_sequence, history_len=8, chunk_size=72):
    """
    initial_obs: [1, C, H, W] 干净的初始环境帧
    action_sequence: [T, action_dim] 完整的未来动作序列
    """
    # 初始化动态历史窗口
    dynamic_history = [initial_obs] * history_len 
    generated_rollout = []
    
    # 按 Chunk 进行自回归生成
    for t in range(0, len(action_sequence), chunk_size):
        action_chunk = action_sequence[t : t + chunk_size]
        
        # 1. 视觉特征编码 (VAE)
        z_0 = vae.encode(initial_obs)
        z_hist = vae.encode(dynamic_history[-history_len:])
        
        # 2. 历史帧加噪 (Flow Matching 扰动)
        z_hist_noisy = (1 - sigma_h) * z_hist + sigma_h * torch.randn_like(z_hist)
        
        # 3. 动作条件编码 (双路径注入)
        # 路径 A: 帧级别 Cross-Attention Token
        act_tokens = action_encoder_cross_attn(action_chunk) 
        # 路径 B: 潜变量级别 AdaLN 调制
        act_emb = action_encoder_adaln(action_chunk)
        
        # 4. 扩散模型去噪生成未来 Chunk
        z_pred = torch.randn(chunk_size, latent_dim) # 初始化未来帧噪声
        for tau in scheduler.timesteps:
            # DiT 接收初始帧、加噪历史帧、动作条件进行去噪
            velocity = dit_backbone(
                x=torch.cat([z_0, z_hist_noisy, z_pred], dim=1),
                cross_attn_cond=act_tokens,
                adaln_cond=act_emb,
                timestep=tau
            )
            z_pred = scheduler.step(z_pred, velocity, tau)
            
        # 5. 解码并更新状态
        pred_frames = vae.decode(z_pred)
        generated_rollout.append(pred_frames)
        
        # 更新动态历史（丢弃最旧的帧，加入新生成的帧）
        dynamic_history.extend(pred_frames)
        
    return generated_rollout
```

### 第二模块：核心架构解释

FBFM 的核心思想是将 WAM 的推理过程转化为一个动态的部分可观测生成问题。它不改变预训练的流匹配模型，而是通过在推理期修改速度场（Velocity Field）来注入真实世界的反馈。

**运行流程解析：**
1. **异步重叠（Asynchronous Overlap）**：当机器人正在执行前一个动作块（Chunk $t-1$）的剩余动作时，模型已经开始生成下一个动作块（Chunk $t$）。
2. **动态目标构建（Dynamic Target Construction）**：随着前一个块的动作在真实世界中执行，新的视觉观测 $z_{t+i}$ 不断到达。FBFM 将这些真实观测以及前一个块中已承诺的动作 $a_{t+i}^{prev}$ 组合成一个对齐的目标张量。
3. **掩码伪逆引导（Masked Pseudoinverse Guidance）**：在流匹配的每一个求解步（Solver Step）中，模型首先预测一个干净的端点（Clean Endpoint）。FBFM 计算该预测端点与真实目标之间的残差，并应用一个掩码（仅在有真实反馈的时间步激活）。
4. **速度场修正（Velocity Field Correction）**：通过计算预测端点对当前噪声状态的雅可比矩阵转置（即 VJP），将残差反向传播，计算出修正梯度，从而调整当前步的生成速度场。
5. **架构适配**：
   - **分阶段生成（Stage-wise, 如 LingBot-VA）**：状态流和动作流分开。状态反馈修正状态流，修正后的状态作为上下文条件输入给动作流；动作流同时受前置动作的硬约束。
   - **联合生成（Joint-generation, 如 DreamZero）**：状态和动作在同一个流中生成。状态残差可以通过跨模态雅可比矩阵（Cross-modal Jacobian）直接在同一步骤中修正动作坐标。

**核心逻辑伪代码（Python 风格）：**

```python
def fbfm_solver_step(x_t, tau, history, real_obs_stream, committed_actions, model):
    """
    x_t: 当前流匹配的噪声状态 (包含 latent state 和 action)
    tau: 当前流时间 (Flow time)
    real_obs_stream: 异步到达的真实世界观测
    """
    # 1. 预训练模型预测当前速度场 v_pred
    v_pred = model(x_t, tau, history)
    
    # 2. 估计干净的端点 (Clean Endpoint)
    x_clean_pred = x_t + (1 - tau) * v_pred
    
    # 3. 构建对齐的反馈目标与掩码
    # target 包含已执行的动作和最新到达的真实观测
    target = construct_target(real_obs_stream, committed_actions)
    mask = construct_mask(real_obs_stream, committed_actions)
    
    # 4. 计算掩码残差 (仅在有真实反馈的坐标上产生非零残差)
    residual = mask * (target - x_clean_pred)
    
    # 5. 计算雅可比向量积 (VJP) 以获取修正方向
    # g = (d x_clean_pred / d x_t)^T * residual
    g = compute_vjp(func=lambda x: x + (1 - tau) * model(x, tau, history), 
                    inputs=x_t, 
                    v=residual)
    
    # 6. 计算动态引导强度并修正速度场
    lambda_tau = compute_guidance_weight(tau)
    v_guided = v_pred - lambda_tau * g
    
    # 7. 执行欧拉步 (或其它 ODE 求解器步)
    delta_tau = get_step_size()
    x_next = x_t + delta_tau * v_guided
    
    return x_next
```

### 第二模块：核心架构解释

WCM（World Critic Model）的核心逻辑在于摒弃传统的“单帧输入 -> 标量输出”的 Critic 范式，转而构建一个具备时序预测能力的双目标网络。其架构与工作流程如下：

1.  **历史状态编码**：接收多帧历史视觉观测与文本指令，通过视觉-语言编码器（通常复用 VLA 的冻结特征）提取高维特征，并映射为低维潜状态（Latent State）。
2.  **时序动态预测（World Model 目标）**：基于当前的潜状态和执行的动作序列，利用 LeJEPA（Lightweight Joint-Embedding Predictive Architecture）的预测器（Predictor）网络，推演未来时间步的潜状态。
3.  **目标网络对齐**：使用动量更新（Momentum）的目标编码器（Target Encoder）对真实的未来观测进行编码，生成目标潜状态，用于与预测器的输出计算预测损失（Prediction Loss）。
4.  **价值估计（Critic 目标）**：将融合了时序动态信息的表征输入到价值头（Value Head），输出当前状态的 Q 值或状态价值（Value），计算强化学习的 TD 损失（TD Loss）。
5.  **联合优化**：将预测损失与 TD 损失加权求和，端到端更新 Critic 网络。

**核心伪代码实现逻辑**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class WorldCriticModel(nn.Module):
    def __init__(self, encoder, predictor, value_head):
        super().__init__()
        self.encoder = encoder              # 编码器 (Online)
        self.target_encoder = copy.deepcopy(encoder) # 目标编码器 (Momentum)
        self.predictor = predictor          # LeJEPA 预测器
        self.value_head = value_head        # 价值输出头
        
        # 冻结目标编码器梯度
        for param in self.target_encoder.parameters():
            param.requires_grad = False

    def update_target_encoder(self, tau=0.99):
        # 动量更新目标网络
        for online_param, target_param in zip(self.encoder.parameters(), self.target_encoder.parameters()):
            target_param.data.copy_(tau * target_param.data + (1 - tau) * online_param.data)

    def forward(self, obs_history, actions, future_obs):
        # 1. 编码当前历史观测为潜状态
        z_current = self.encoder(obs_history)
        
        # 2. 价值估计 (Critic Objective)
        value = self.value_head(z_current)
        
        # 3. 预测未来潜状态 (World Model Objective)
        # 结合当前潜状态和动作序列预测未来
        z_pred_future = self.predictor(z_current, actions)
        
        # 4. 获取真实的未来潜状态 (使用动量目标编码器)
        with torch.no_grad():
            z_target_future = self.target_encoder(future_obs)
            
        return value, z_pred_future, z_target_future

def compute_loss(wcm, batch, gamma=0.99, lambda_wm=1.0):
    obs_history, actions, rewards, next_obs_history, future_obs, dones = batch
    
    # 前向传播
    values, z_pred, z_target = wcm(obs_history, actions, future_obs)
    
    # 计算 RL TD Loss (以简单的 MSE 为例)
    with torch.no_grad():
        next_values, _, _ = wcm(next_obs_history, actions_next, future_obs_next) # 简化表示
        target_values = rewards + gamma * (1 - dones) * next_values
    td_loss = F.mse_loss(values, target_values)
    
    # 计算 World Model 预测 Loss (Latent 空间的 L2 或 Cosine 距离)
    wm_loss = F.mse_loss(z_pred, z_target)
    
    # 联合 Loss
    total_loss = td_loss + lambda_wm * wm_loss
    return total_loss
```

### 第二模块：核心架构解释

ActFovea 的架构是一个部署在 VLA 策略与物理环境之间的拦截与验证代理。其处理流程分为四个核心阶段：

1.  **动作条件中央凹化 (Action-Conditioned Foveation):** 利用机器人的正向运动学（Forward Kinematics）和上一帧动作，计算出末端执行器的投影接触中心和运动走廊。生成一个掩码（Mask），保留该物理交互区域的高保真视觉信息，并对背景进行平滑和灰度化降敏处理。
2.  **一致性监控 (Consistency Monitoring):** 提取视觉特征的运动质心，计算其与运动学预测中心的几何一致性、动态位移一致性以及时间戳/历史延迟一致性。融合输出一个综合风险状态（正常、可恢复、不可恢复）。
3.  **观测恢复与动作验证 (Observation Recovery & Action Verification):** 当检测到可恢复风险时，生成多个候选观测（如原始图像、中央凹化图像、时间补偿图像、空间修复图像）。将这些候选观测分别输入冻结的 VLA 模型，生成多个候选动作块（Action Chunks）。验证器根据动作方向、平滑度、轨迹漂移等指标对这些动作块进行打分。
4.  **风险自适应执行 (Risk-Adaptive Execution):** 根据最高验证得分和风险状态，决定最终的执行策略：正常执行、缩短动作块执行步长、阻尼减速，或在不可恢复状态下（如画面永久冻结）触发安全熔断（将运动指令置零）。

```python
        if v_score > best_verification_score:
            best_verification_score = v_score
            best_action_chunk = cand_action_chunk
            
    # 5. 风险自适应执行
    # 根据风险程度决定执行完整动作块，还是截断/减速
```

### 第二模块：核心架构解释

Mirror Learning 框架的本质是一个**数据合成与策略蒸馏流水线**，其核心流程分为三个阶段：

1. **视角转换（Perspective Transformation）**：
   利用少量成对的（第一人称，第三人称）视频数据微调一个预训练的视频扩散模型。在推理阶段，该模型接收无动作标签的第三人称演示视频，生成对应的高保真第一人称视角视频。这一步利用了世界模型的空间几何先验。
2. **动作推断（Action Inference）**：
   训练一个逆动力学模型（Inverse Dynamics Model, IDM）。该模型接收相邻的两帧第一人称图像（真实或生成的），推断出在这两帧之间发生的状态转移所对应的具体动作（Action）。
3. **数据合成与策略训练（Data Synthesis & Policy Training）**：
   将扩散模型生成的第一人称视频帧与 IDM 推断出的动作配对，构建出“镜像数据（Mirror Data）”。最后，将这些伪造的第一人称专家数据（可与真实数据混合）用于标准的行为克隆（Behavior Cloning）训练，得到最终的 VLA 控制策略。

**核心逻辑伪代码（Python 风格）：**

```python
class MirrorLearningFramework:
    def __init__(self, video_diffusion_model, inverse_dynamics_model, policy_network):
        # 预训练/微调后的组件
        self.vdm = video_diffusion_model  # 视角转换模型
        self.idm = inverse_dynamics_model # 逆动力学模型
        self.policy = policy_network      # 最终的控制策略 (VLA)

    def generate_mirror_data(self, third_person_video):
        mirror_data = []
        
        # 1. 视角转换：第三人称 -> 第一人称
        # 输入形状: [T, H, W, C], 输出形状: [T, H, W, C]
        pseudo_first_person_video = self.vdm.generate(third_person_video)
        
        # 2. 动作推断：从相邻帧提取动作
        T = len(pseudo_first_person_video)
        for t in range(T - 1):
            obs_t = pseudo_first_person_video[t]
            obs_t_next = pseudo_first_person_video[t+1]
            
            # 逆动力学推断动作
            pseudo_action = self.idm.predict_action(obs_t, obs_t_next)
            
            # 组装伪造的第一人称专家数据
            mirror_data.append({
                'observation': obs_t,
                'action': pseudo_action
            })
            
        return mirror_data

    def train_policy(self, real_first_person_data, third_person_datasets):
        # 收集所有镜像数据
        all_mirror_data = []
        for tp_video in third_person_datasets:
            mirror_data = self.generate_mirror_data(tp_video)
            all_mirror_data.extend(mirror_data)
            
        # 混合真实数据与伪造数据
        combined_dataset = real_first_person_data + all_mirror_data
        
        # 3. 行为克隆训练
        for batch in get_dataloader(combined_dataset):
            obs = batch['observation']
            target_action = batch['action']
            
            # 预测动作并计算损失
            pred_action = self.policy(obs)
            loss = compute_bc_loss(pred_action, target_action)
            
            # 反向传播更新策略网络
            loss.backward()
            self.policy.optimizer.step()
            
        return self.policy
```

### 第二模块：核心架构解释

Auto-JEPA 的架构分为两个独立的训练阶段和一个级联的推理流程。

**阶段一：轨迹隐空间预训练 (Trajectory Latent-Space Pretraining)**
训练一个轨迹自编码器。编码器将真实的未来 8 个时间步的二维轨迹坐标映射为 8 个时间维度的隐式 Token。解码器负责将其还原为坐标。训练完成后，丢弃解码器，冻结编码器。该冻结的编码器定义了后续视觉预测的“目标隐空间”，并用于离线编码 11 万条真实轨迹，构建非参数化记忆库。

**阶段二：视觉意图预测 (Visual Intent Prediction)**
冻结视觉编码器（V-JEPA 2），仅训练历史运动编码器、导航指令编码器和 JEPA 预测器（Transformer）。预测器融合上述特征，输出 8 个未来的意图 Token。优化目标不包含任何图像重建，而是计算预测 Token 与阶段一生成的真实轨迹 Token 之间的特征对齐（Smooth L1）、Token 级余弦相似度以及 Batch 级别的 InfoNCE 对比损失。

**阶段三：推理与级联选择 (Inference & Cascade Selection)**
推理时，模型输出连续驾驶意图隐向量，通过扁平化和 L2 标准化后，与记忆库中的轨迹隐向量计算余弦相似度，检索出 Top-300 候选轨迹。随后，一个独立的场景条件评分器（Scorer）对候选进行质量打分，一个可行驶区域门控（DAC Gate）过滤掉违规轨迹，最终通过带掩码的 Argmax 输出最优轨迹。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn.functional as F

# --- Stage 1: Pre-trained & Frozen Modules ---
frozen_visual_encoder = load_vjepa2()
frozen_traj_encoder = load_pretrained_traj_encoder()
trajectory_memory = build_memory_bank(frozen_traj_encoder, train_dataset) # Shape: [N, 8*1024]

# --- Stage 2: Intent Predictor (Trainable) ---
class AutoJEPAPredictor(nn.Module):
    def __init__(self):
        super().__init__()
        self.history_enc = HistoryEncoder()
        self.cmd_enc = CommandEncoder()
        self.transformer = Transformer(layers=24, dim=1024)
        self.query_tokens = nn.Parameter(torch.randn(8, 1024))
        
    def forward(self, images, history, command):
        with torch.no_grad():
            vis_feats = frozen_visual_encoder(images)
        hist_feats = self.history_enc(history)
        cmd_feats = self.cmd_enc(command)
        
        # Predict 8 future intent tokens
        pred_intent = self.transformer(vis_feats, hist_feats, cmd_feats, self.query_tokens)
        return pred_intent # Shape: [B, 8, 1024]

# --- Loss Computation ---
def compute_loss(pred_intent, gt_trajectory):
    with torch.no_grad():
        target_intent = frozen_traj_encoder(gt_trajectory) # Shape: [B, 8, 1024]
        
    # 1. Feature Alignment
    loss_feat = F.smooth_l1_loss(F.normalize(pred_intent, dim=-1), F.normalize(target_intent, dim=-1))
    
    # 2. Token-wise Cosine Alignment
    loss_cos = 1 - F.cosine_similarity(pred_intent, target_intent, dim=-1).mean()
    
    # 3. Batch-level InfoNCE
    pred_flat = F.normalize(pred_intent.view(B, -1), dim=-1)
    target_flat = F.normalize(target_intent.view(B, -1), dim=-1)
    logits = torch.matmul(pred_flat, target_flat.T) / 0.07
    labels = torch.arange(B).to(logits.device)
    loss_nce = F.cross_entropy(logits, labels)
    
    return 0.1 * loss_feat + 2.0 * loss_cos + loss_nce

# --- Inference Pipeline ---
def inference(images, history, command, scorer, dac_gate):
    # 1. Predict Intent
    pred_intent = predictor(images, history, command)
    pred_flat = F.normalize(pred_intent.view(-1), dim=-1)
    
    # 2. Non-Parametric Retrieval
    similarities = torch.matmul(trajectory_memory_latents, pred_flat)
    topk_indices = torch.topk(similarities, k=300).indices
    candidates = trajectory_memory_waypoints[topk_indices]
    
    # 3. Scene Scoring & Feasibility Gating
    scores = scorer(scene_features, candidates)
    dac_probs = dac_gate(scene_features, candidates)
    
    # 4. Masked Selection
    valid_mask = dac_probs <= 0.2
    if not valid_mask.any():
        valid_mask = torch.ones_like(valid_mask) # Fallback
        
    masked_scores = scores.masked_fill(~valid_mask, -float('inf'))
    best_idx = torch.argmax(masked_scores)
    
    return candidates[best_idx]
```

### 第二模块：核心架构解释

ST-WAM 的核心架构分为两个互补的时间维度：向后检索历史（CAIR）与向前预测未来（DSFE），并通过一个三分支的混合 Transformer（MoT）进行联合训练。

**1. 观测编码与特征提取**
系统接收当前图像、历史图像序列和语言指令。图像被分别送入冻结的 VAE（提取细粒度视觉特征）和冻结的 DINOv3（提取稳定的语义特征）。同时，使用 Qwen3-VL 提取当前图像和指令的多模态特征。

**2. 当前锚定的意图检索 (CAIR - 回顾历史)**
为了在视觉干扰下找到正确的动作意图，模型不直接使用历史图像像素。它将 Qwen3-VL 提取的当前特征作为“查询向量（Query）”，去和 DINOv3 提取的历史语义特征（Key/Value）进行交叉注意力计算。这样可以过滤掉历史帧中无关的视觉变化，只提取与当前任务状态相关的历史动作意图。

**3. 双空间未来专家 (DSFE - 预测未来)**
模型包含三个独立的 Transformer 分支：视觉未来分支、语义未来分支和动作分支。在训练时，采用流匹配（Flow Matching）目标。视觉分支负责去噪预测未来的 VAE 潜变量，语义分支负责去噪预测未来的 DINO 特征，动作分支负责预测机器人的动作序列。

**4. 结构化跨分支注意力掩码 (核心防泄漏机制)**
为了让三个分支互相交换信息，同时防止动作分支“偷看”未来导致推理时无法独立运行，作者设计了严格的注意力掩码：
*   当前观测（VAE/DINO）只能看自己，作为绝对的锚点。
*   未来预测分支（VAE/DINO）可以看当前观测，且两个未来分支可以互看（实现视觉与语义的相互对齐）。
*   动作分支可以看当前观测和历史意图，但**绝对禁止**看任何未来分支。

**5. 部署推理**
在实际机器人部署时，直接丢弃视觉未来和语义未来两个分支，仅运行动作分支。

**核心逻辑伪代码实现：**

```python
def st_wam_forward(current_img, history_imgs, language_instruction, noisy_future_vae, noisy_future_dino, noisy_action):
    # 1. 特征编码 (冻结的预训练模型)
    curr_vae = frozen_vae.encode(current_img)
    curr_dino = frozen_dino.encode(current_img)
    hist_dino = frozen_dino.encode(history_imgs)
    curr_vlm_context = frozen_qwen_vl.encode(current_img, language_instruction)
    
    # 2. CAIR: 当前锚定的意图检索
    # 用当前 VLM 上下文生成 Query，去检索历史 DINO 特征
    semantic_queries = generate_queries(curr_vlm_context)
    intent_tokens = cross_attention(query=semantic_queries, key=hist_dino, value=hist_dino)
    
    # 3. 准备三个专家的输入上下文
    # 视觉和语义专家只看当前状态和指令
    context_future = concat(language_instruction, curr_vae, curr_dino)
    # 动作专家额外看检索到的历史意图
    context_action = concat(language_instruction, curr_vae, curr_dino, intent_tokens)
    
    # 4. 三分支 Mixture-of-Transformers (MoT) 与结构化掩码
    # 掩码逻辑：动作分支的 attention_mask 对应未来分支的部分为 -inf
    mask = build_structured_causal_mask() 
    
    for layer in mot_layers:
        # 各自分支独立处理
        feat_vae = layer.vae_expert(noisy_future_vae, context_future)
        feat_dino = layer.dino_expert(noisy_future_dino, context_future)
        feat_action = layer.action_expert(noisy_action, context_action)
        
        # 跨分支混合注意力 (受 mask 严格限制)
        combined_feats = concat(feat_vae, feat_dino, feat_action)
        refined_feats = layer.mixed_attention(combined_feats, mask=mask)
        
        noisy_future_vae, noisy_future_dino, noisy_action = split(refined_feats)
        
    # 5. 输出流匹配的速度预测 (Velocity)
    vel_vae = head_vae(noisy_future_vae)
    vel_dino = head_dino(noisy_future_dino)
    vel_action = head_action(noisy_action)
    
    return vel_vae, vel_dino, vel_action

def inference_step(current_img, history_imgs, language_instruction):
    # 推理时，完全不需要输入 noisy_future_vae 和 noisy_future_dino
    # 仅运行 action_expert 分支进行流匹配去噪
    action_trajectory = generate_pure_noise()
    for step in range(10): # 10步流匹配积分
        vel_action = st_wam_forward_action_only(current_img, history_imgs, language_instruction, action_trajectory)
        action_trajectory = euler_step(action_trajectory, vel_action)
    return action_trajectory
```

### 第二模块：核心架构解释

**模型架构与实验流程详解**：

1.  **VLA 基础骨架 (VLM Backbone & Action Expert)**：模型接收语言指令和高频图像帧，通过 VLM 提取语义和视觉特征，随后交由动作专家（Action Expert）处理。动作专家采用流匹配（Flow Matching）算法，旨在预测一个流向量场，将初始噪声分布逐步变换为目标动作块分布。
2.  **动作块级安全聚合 (Action Chunk Aggregation)**：传统的 CBF 仅针对单一状态。本文通过 Log-Sum-Exponential (LSE) 函数，将动作块中所有未来步的离散安全约束平滑地聚合为一个单一的、连续可导的势函数。这解决了 `min` 操作符不可导的问题，使得对整个未来轨迹的梯度计算成为可能。
3.  **屏障增强去噪 (Barrier-Enhanced Denoising)**：在流匹配的推理循环中，设定一个阈值 $\tau_s$。在去噪的早期（纯噪声阶段），不施加约束；当去噪进行到具有物理意义的后期（$\tau \ge \tau_s$）时，在每一步计算当前动作块的 CBF 梯度。
4.  **实时二次规划求解 (Real-time QP Solving)**：构建一个二次规划（QP）问题。目标函数是最小化对原始预测流向量场的扰动，并加入相邻动作的平滑度惩罚；约束条件是必须满足 CBF 的导数不等式（确保轨迹向安全集收敛）以及关节速度限制。求解出的最优扰动量被叠加到原始流向量场上，驱动 ODE 向前积分。

**核心伪代码实现**：

```python
import torch
import qpth # Differentiable QP solver

def barrier_enhanced_flow_matching(image, language, kappa, alpha, tau_s, dt, steps=100):
    # Initialize noisy action chunk z_0 from Beta or Normal distribution
    z = sample_initial_noise() 
    
    # Denoising loop
    for tau in torch.linspace(0, 1.0, steps):
        # 1. VLA predicts the original flow vector field
        v_theta = VLA_model(image, language, z, tau)
        
        if tau >= tau_s:
            # 2. Compute individual barrier values for all states in the chunk
            h_qi = compute_barrier_values(z) # Shape: [H]
            
            # 3. Aggregate barrier using Log-Sum-Exponential
            h_z = -(1/kappa) * torch.log(torch.sum(torch.exp(-kappa * h_qi)))
            
            # 4. Compute gradient of the aggregated barrier w.r.t the flattened chunk
            grad_h_z = compute_aggregated_gradient(h_qi, h_z, kappa, z)
            
            # 5. Formulate and solve QP to find minimal safe perturbation delta_s
            # Objective: min ||delta||^2 + lambda * ||Smoothing(v_theta + delta)||
            # Constraint: grad_h_z * (v_theta + delta) >= -alpha * h_z
            # Constraint: v_min <= Velocity(v_theta + delta) <= v_max
            delta_s = solve_qp(v_theta, h_z, grad_h_z, alpha)
        else:
            delta_s = torch.zeros_like(v_theta)
            
        # 6. Euler integration step with the modified flow
        z = z + (v_theta + delta_s) * dt
        
    return z # Safe action chunk
```

### 第二模块：核心架构解释

1. **初始化（Initialization）**：使用人类遥操作演示数据，通过托管的 SFT API 训练出初始策略模型 $\pi_0$。

4. **迭代自进化（Iterative Self-Improvement）**：将带有优势标签的轨迹数据与原始演示数据合并，再次提交给 SFT API 进行全量微调。推理时，将指令与“Positive”标签拼接，引导模型输出高质量动作。

```python
    # 1. 初始化：使用人类演示数据进行SFT
    labeled_demos = add_advantage_token(human_demos, token="Positive")
    cumulative_dataset = labeled_demos
    current_policy = api.finetune(cumulative_dataset)
    
    for cycle in range(num_cycles):
        # 2. 闭环数据收集
        rollouts = deploy_policy_on_robot(current_policy, condition_token="Positive", num_episodes=100)
        
        labeled_rollouts = []
        for episode in rollouts:
            chunks = split_into_action_chunks(episode)
            for chunk in chunks:
                # 3. 检索式优势标注
                # 提取当前chunk初始状态的视觉特征
                state_feature = vision_encoder.encode(chunk.initial_observation)
                
                # 在所有历史rollouts中检索视觉相似的初始状态
                similar_chunks = retrieve_similar_chunks(state_feature, all_historical_rollouts)
                
                # 使用奖励模型计算当前chunk的累计折扣奖励
                chunk_return = compute_discounted_return(chunk, reward_model)
                
                # 计算相似状态集合中的奖励分布
                peer_returns = [compute_discounted_return(c, reward_model) for c in similar_chunks]
                threshold = percentile(peer_returns, 70) # 取前30%作为阈值
                
                # 分配优势标签
                if chunk_return > threshold:
                    token = "Positive"
                else:
                    token = "Negative"
                    
                labeled_chunk = append_token_to_instruction(chunk, token)
                labeled_rollouts.append(labeled_chunk)
        
        # 4. 迭代自进化：合并数据并重新提交SFT
        cumulative_dataset.extend(labeled_rollouts)
        current_policy = api.finetune(cumulative_dataset) # 每次都从Base Model重新微调，避免分布漂移
        
    return current_policy
```

1. **对数后视采样 (Logarithmic Hindsight Sampling)**：在获取历史观测时，放弃传统的滑动窗口密集采样。对于当前时间步 $t$，模型以对数递增的间隔向后回溯（例如 $t, t-1, t-2, t-4, t-8...$）。这种机制使得模型对近期状态具有高分辨率感知（保证反应灵敏度），对远期状态具有低分辨率感知（提供长程上下文），从而在固定输入长度下呈指数级扩大时间感受野。
2. **多模态特征编码与融合**：将采样得到的稀疏历史视觉帧和本体感受状态（Proprioceptive states）输入到冻结的大规模视觉编码器中，提取时空特征，并与语言指令的嵌入向量进行融合，构建当前决策的上下文表征。
3. **流匹配与斐波那契推理 (Flow Matching & Fibonacci Inference)**：动作专家模块摒弃了传统的自回归或扩散模型，采用流匹配（Flow Matching）技术来高效拟合连续的动作分布。在推理执行阶段，模型不采用固定步长的开环执行，而是基于斐波那契数列动态决定动作序列的生成与执行步长，结合实时闭环反馈，在长程规划与即时纠错之间取得平衡。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import math

class FibVLA(torch.nn.Module):
    def __init__(self, vision_encoder, language_encoder, flow_matching_expert):
        super().__init__()
        self.vision_encoder = vision_encoder
        self.language_encoder = language_encoder
        self.action_expert = flow_matching_expert
        
    def logarithmic_hindsight_sampling(self, history_buffer, current_t, num_samples):
        """
        对数后视采样：以对数间隔从历史缓冲区中抽取观测值
        """
        sampled_indices = []
        for i in range(num_samples):
            # 计算对数间隔的索引，越往前的历史间隔越大
            offset = int(math.pow(2, i)) - 1 
            idx = max(0, current_t - offset)
            sampled_indices.append(idx)
        
        # 返回按时间顺序排列的稀疏观测序列
        sampled_indices.reverse()
        return [history_buffer[i] for i in sampled_indices]

    def forward(self, history_buffer, current_t, language_instruction):
        # 1. 获取对数采样的历史视觉与本体状态
        sampled_obs = self.logarithmic_hindsight_sampling(history_buffer, current_t, num_samples=5)
        
        # 2. 编码与融合
        lang_emb = self.language_encoder(language_instruction)
        obs_emb = self.vision_encoder(sampled_obs)
        context_emb = fuse_features(obs_emb, lang_emb)
        
        # 3. 流匹配生成动作分布
        # Flow Matching 相比 Diffusion 具有更优的常微分方程(ODE)轨迹，采样步数更少
        action_distribution = self.action_expert.generate_flow(context_emb)
        
        return action_distribution

    def fibonacci_recurrent_inference(self, env, language_instruction, max_steps):
        """
        斐波那契循环推理策略
        """
        history_buffer = []
        t = 0
        fib_sequence = [1, 1, 2, 3, 5, 8] # 预定义的斐波那契执行步长
        fib_idx = 0
        
        while t < max_steps and not env.is_done():
            # 获取当前观测并更新历史
            obs = env.get_observation()
            history_buffer.append(obs)
            
            # 预测未来动作序列
            action_seq = self.forward(history_buffer, t, language_instruction)
            
            # 决定当前周期的执行步数 (基于斐波那契数列)
            execute_steps = fib_sequence[min(fib_idx, len(fib_sequence)-1)]
            
            # 闭环执行
            for i in range(execute_steps):
                env.step(action_seq[i])
                t += 1
                
            # 根据环境反馈动态调整斐波那契索引 (例如遇到扰动则重置为高频短步长)
            if env.detect_disturbance():
                fib_idx = 0
            else:
                fib_idx += 1
```

### 第二模块：核心架构解释

MUTE 框架将机器遗忘从单次操作转化为持续的网络维护过程，其核心架构分为三个连续的阶段：

**1. 影响溯源 (Influence Provenance)**
服务器维护一个轻量级账本，记录每轮的部署模型版本、参与客户端、聚合权重和部署窗口。当收到删除请求时，服务器重放账本，计算全局模型版本的影响力衰减序列。客户端接收该序列后，结合本地数据收集日志，计算出每一条本地保留轨迹的“影响得分”。该得分量化了该轨迹在多大程度上是由受遗忘数据污染的策略所收集的。

**2. 影响感知擦除 (Influence-Aware Erasure)**
包含模型端与数据端双重操作。模型端：持有遗忘数据的客户端在其低秩适配器（LoRA）上执行负偏好优化（NPO），抑制遗忘轨迹的行为，同时为了防止后续训练重新拟合该行为，将后续的局部梯度更新投影到遗忘梯度子空间之外。数据端：客户端根据计算出的影响得分对其本地保留轨迹进行分级。得分高于阈值的轨迹被直接隔离（停止参与后续训练），得分中等的轨迹被降低采样权重。

**3. 行为审计与删除调度 (Behavioral Audit and Deletion Scheduling)**
网络在继续运行的过程中，服务器持续审计两个指标：行为泄漏指数（BLI，衡量当前遗忘数据的行为暴露程度）和影响再生率（IRR，衡量遗忘行为是否在后续训练中复苏）。当指标超标时，服务器在严格的上行通信带宽预算下，优先调度具有高影响得分的客户端执行额外的擦除或隔离操作。

### 第二模块：核心架构解释

RayViT 的核心逻辑是在不改变预训练视觉大模型（如 DINOv3）主体权重结构的前提下，将相机的三维空间信息强行绑定到二维图像的特征处理流程中。其处理流程分为以下几个客观步骤：

1. **射线映射生成**：根据相机的内部参数（焦距、光心）和外部参数（相机在世界坐标系中的位置和朝向），为图像中的每一个像素计算出一条在三维空间中的射线（使用 Plücker 坐标表示）。
2. **局部几何特征注入**：将生成的射线映射进行下采样，使其分辨率与图像的特征块（Patch）一致。将这些射线特征通过多层感知机处理后，作为绝对的三维位置编码，直接与图像特征块相加。
3. **全局几何特征聚合**：初始化一个可学习的查询向量，让它与所有的射线特征进行交叉注意力计算。为了防止几何信息过度干扰原有的图像语义，加入了一个可学习的门控机制（Sigmoid）来控制信息流入量。最终生成的向量替换掉 ViT 原本的全局分类 Token（CLS Token）。
4. **跨视角一致性约束**：在训练阶段，强制要求模型在处理不同视角（如左侧相机和机械臂手爪相机）的同一场景时，其网络中间层输出的全局 Token 必须保持极高的余弦相似度。

```python
def rayvit_forward(image, camera_intrinsics, camera_extrinsics, pretrained_vit):
    # 1. 图像分块处理
    image_patches = patchify(image) # 形状: [序列长度, 特征维度]
    
    # 2. 计算射线映射并生成局部位置编码
    ray_map = compute_plucker_rays(camera_intrinsics, camera_extrinsics)
    ray_patches = average_pooling(ray_map, patch_size)
    ray_embeddings = mlp_projection(ray_patches) # 形状: [序列长度, 特征维度]
    
    # 将射线特征作为位置编码加入图像特征
    image_patches = image_patches + ray_embeddings + original_rope_embeddings
    
    # 3. 门控交叉注意力生成全局射线 Token
    query_token = initialize_learnable_token()
    for block in gated_cross_attention_blocks:
        # 查询向量关注所有的射线特征
        attention_out = cross_attention(query=query_token, key=ray_embeddings, value=ray_embeddings)
        # 门控机制控制信息注入量
        gate = sigmoid(learnable_scalar)
        query_token = query_token + gate * attention_out
        
    ray_cls_token = query_token # 替换原有的 CLS Token
    
    # 4. 拼接并输入预训练 ViT 主干
    vit_input = concatenate(ray_cls_token, image_patches)
    intermediate_tokens, final_tokens = pretrained_vit(vit_input)
    
    return intermediate_tokens, final_tokens

def compute_loss(view_1_tokens, view_2_tokens, action_prediction, expert_action):
    # 行为克隆损失
    bc_loss = diffusion_loss(action_prediction, expert_action)
    # 跨视角一致性损失 (提取中间层的 CLS Token 计算余弦相似度)
    consistency_loss = 1 - cosine_similarity(view_1_tokens.cls_token, view_2_tokens.cls_token)
    
    return bc_loss + weight * consistency_loss
```

A2: 核心解决方案是一个包含三个组件的框架：首先是“反思推理（Reflective Reasoning）”，利用真实的未来轨迹作为已知结果，反向引导大模型生成因果逻辑，实现免人工标注的数据构建；其次是师生蒸馏，将 78B 大模型的推理能力压缩至 8B 小模型以满足车端实时性；最后是解耦的 RealNum-Decoder，将文本推理与数值回归物理隔离，用语言模型做逻辑，用 GRU 做几何轨迹预测。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 实验设计的巧妙之处在于对 Waymo E2E Driving 数据集特性的利用。该数据集本身提供了高质量的专家轨迹（Ground-Truth Waypoints）。作者没有去寻找额外的文本标注数据集，而是直接将这些现成的物理轨迹转化为文本，作为 Prompt 喂给大模型进行“结果导向”的推理生成。此外，采用 RFS（Rater Feedback Score）结合容差加权损失函数，直接将模型的优化目标与真实驾驶中的横纵向安全边界挂钩，而非使用简单的 MSE 损失。

Q4: 这篇论文最显著的贡献点（Top 3）是什么？

A4: 
[贡献1]
提出 Reflective Reasoning 范式，打破了自动驾驶 VLM 依赖人工 CoT 标注的瓶颈，实现了零样本、因果对齐的高质量训练数据自动生成。

[贡献2]
设计了文本推理与数值预测解耦的 RealNum-Decoder 架构，彻底绕开了 LLM 无法精确处理连续实数回归的先天缺陷。

[贡献3]
通过实验验证了在端到端驾驶任务中，冻结视觉编码器（Frozen ViT）对于防止灾难性遗忘、保留模型对长尾场景泛化能力的关键作用。

Q5: 这项工作在哪些相关研究的基础上做了推进？（列举1-2个最核心的前置工作即可）

A5: 
[前置工作1]
DriveGPT4 / DriveCoT：这类工作率先将 VLM 和 CoT 引入自动驾驶以增强可解释性，但本文推进了其数据获取方式，摆脱了对人工标注或外部模块堆叠的依赖。

[前置工作2]
LMDrive：该工作实现了闭环的 VLM 端到端驾驶，但直接将控制指令 Token 化。本文通过解耦架构推进了这一路线，解决了直接 Token 化带来的数值精度丢失问题。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 论文存在两个明显的局限与漏洞。第一，时序动态信息的缺失。模型仅输入单帧多视角图像和一维的运动学历史状态，没有显式编码历史视频帧。这意味着模型在判断“行人步态意图”或“他车加速度”等强时序依赖特征时存在盲区。第二，捷径学习（Shortcut Learning）的隐患未被彻底排除。虽然训练时强制解码器依赖文本推理，但在推理阶段，RealNum-Decoder 可能会学到直接跳过文本特征，仅依赖视觉特征输出轨迹。论文缺乏对“如果故意输入错误的推理文本，轨迹预测是否会随之崩溃”的对抗性消融实验。这对后续科研的启发是：在设计 VLA 解耦架构时，必须引入因果干预实验，以证明文本推理模块确实在主导物理动作，而非仅仅是一个旁观的“解说员”。
