### 第二模块：核心架构解释

VLAct 的核心架构与实验流程分为两个明确的阶段：持续预训练阶段与特定任务微调阶段。

**1. 持续预训练阶段 (Continued Pre-training)**
模型接收来自多种不同机器人（多具身）的异构轨迹数据。为了处理不同机器人动作维度的差异，模型采用“部分统一的跨具身动作布局”，将具有相同物理意义的动作（如末端执行器位置、夹爪开合）映射到统一的语义维度，将特有动作（如移动底盘）分配到独立维度。在训练时，模型通过多头连续动作预测器输出动作，并计算动作均方误差（MSE）；同时，强制模型继续预测文本 Token 以计算语言建模损失，从而保持 VLM 的先验知识。

**2. 特定任务微调阶段 (Task-specific Fine-tuning)**
在面对具体的下游任务或全新的机器人硬件时，模型丢弃预训练阶段使用的通用多头动作预测器，冻结或以极低学习率保留经过预训练的 VLM 骨干网络。随后，接入一个全新的、针对当前任务动作维度定制的特定任务动作头（Task-specific action head），仅使用少量的目标域数据进行快速微调。

**核心逻辑伪代码**：
```python
import torch
import torch.nn as nn

class VLAct(nn.Module):
    def __init__(self, vlm_backbone, action_dim_dict):
        super().__init__()
        self.vlm = vlm_backbone
        
        # 预训练阶段：多具身多头动作预测器
        self.shared_action_heads = nn.ModuleDict({
            embodiment: nn.Linear(self.vlm.hidden_size, dim)
            for embodiment, dim in action_dim_dict.items()
        })
        
        # 微调阶段：任务特定的动作头
        self.task_specific_head = None

    def forward(self, image, text_instruction, embodiment_id=None, task_mode=False):
        # 提取视觉-语言联合表征
        features = self.vlm.extract_features(image, text_instruction)

        if task_mode and self.task_specific_head is not None:
            # 阶段二：微调/推理模式，仅输出特定任务动作
            return self.task_specific_head(features)
        else:
            # 阶段一：预训练模式，输出对应具身的动作及文本预测
            action_pred = self.shared_action_heads[embodiment_id](features)
            text_pred = self.vlm.lm_head(features) # 用于保持 VLM 先验
            return action_pred, text_pred

def pretrain_loss(action_pred, action_target, text_pred, text_target, alpha=0.1):
    # 动作协同监督损失 (连续动作回归)
    action_loss = nn.MSELoss()(action_pred, action_target)
    # VLM 先验保持损失 (文本生成分类)
    vlm_prior_loss = nn.CrossEntropyLoss()(text_pred, text_target)
    
    return action_loss + alpha * vlm_prior_loss
```

### 第二模块：核心架构解释

PHR-VLA 的核心思想是“训练时重拳出击，推理时轻装上阵”。其架构与流程可拆解为以下四个关键步骤：

**1. 基础输入与表征构建**
在时间步 $t$，模型接收当前图像 $I_t$、语言指令 $l_t$ 和本体感受状态 $q_t$。这些输入通过 VLM 主干网络（本文采用 SmolVLM-2）处理，生成包含多模态上下文的内部动作 Token 表征 $z_t$。

**2. 特权未来目标提取（仅训练阶段）**
从演示数据集中获取规划视野 $H$ 内的未来观测帧 $I_{t+1:t+H}$。将这些未来帧输入到一个冻结的视觉编码器（如 SigLIP 或 V-JEPA）中，提取 Patch 级别的视觉隐特征 $s_{t:t+H}$。为了迫使模型关注场景的“变化”而非“静态背景”，计算相邻帧特征的差值作为动态目标：$y_{t:t+H} = s_{t+1:t+H} - s_{t:t+H-1}$。

**3. 双头联合优化（仅训练阶段）**
VLM 输出的表征 $z_t$ 同时送入两个头：
- **动作头 (Action Head)**：标准的流匹配（Flow-matching）策略头，预测连续动作块，计算标准 VLA 损失 $\mathcal{L}_{VLA}$。
- **未来头 (Future Head)**：一个轻量级 MLP，尝试从 $z_t$ 预测步骤 2 中提取的未来隐式动力学 $y_{t:t+H}$，计算均方误差对齐损失 $\mathcal{L}_{Align}$。
总损失为两者加权和。

**4. 零成本推理（部署阶段）**
在实际机器人部署时，彻底剥离“未来头”和“冻结的视觉编码器”。模型仅执行标准的 VLA 前向传播，直接输出动作。

**核心逻辑伪代码 (Python 风格):**

```python
def train_step(batch, vla_model, frozen_encoder, lambda_weight=0.02):
    # 1. 解析当前步数据与未来特权数据
    obs_t, lang_t, prop_t = batch['current']
    actions_gt = batch['actions'] # [B, H, action_dim]
    future_images = batch['future_images'] # [B, H, C, W, H]
    
    # 2. 提取特权未来隐式动力学 (Privileged Latent Dynamics)
    with torch.no_grad():
        # 提取 Patch 级特征
        future_latents = frozen_encoder(future_images) # [B, H, num_patches, dim]
        # 计算相邻帧特征差值，关注动态变化
        latent_dynamics_target = future_latents[:, 1:] - future_latents[:, :-1] 
    
    # 3. VLA 主干前向传播
    # z_t 是 VLM 融合多模态输入后产生的内部表征
    z_t = vla_model.backbone(obs_t, lang_t, prop_t)
    
    # 4. 动作预测分支
    action_pred = vla_model.action_head(z_t)
    loss_vla = compute_flow_matching_loss(action_pred, actions_gt)
    
    # 5. 未来推理辅助分支
    latent_dynamics_pred = vla_model.future_head(z_t)
    loss_align = F.mse_loss(latent_dynamics_pred, latent_dynamics_target)
    
    # 6. 联合优化
    total_loss = loss_vla + lambda_weight * loss_align
    total_loss.backward()
    return total_loss

def inference_step(obs_t, lang_t, prop_t, vla_model):
    # 部署时，完全不需要 future_images, frozen_encoder 和 future_head
    z_t = vla_model.backbone(obs_t, lang_t, prop_t)
    action_pred = vla_model.action_head(z_t)
    return action_pred
```

### 第二模块：核心架构解释

AcrossVAM1.0 的核心思想是**“分而治之”**，其架构分为四个关键阶段：

1.  **语义粒子化 (Particle Tokenization)**：使用冻结的 SAM3-DLP 编码器，将输入的 4 帧上下文图像拆解为 3 个语义粒子（机器人整体、机械臂、夹爪）以及一个背景潜在变量。粒子状态包含位置、缩放、深度、存在概率等显式几何信息。
2.  **文本条件动力学 (Text-Conditioned Dynamics)**：这是一个仅有 0.28M 参数的轻量级时空 Transformer。它接收历史粒子状态，结合通过 FiLM 注入的 OpenCLIP 文本特征，自回归地预测未来 5 帧的粒子几何状态。
3.  **因果运动-表观解码 (Causal Motion-Appearance Decoding)**：双流解码器。运动流根据预测的粒子渲染出结构草图；表观流**仅从最后一帧上下文**中提取高频纹理特征。两者通过残差网络结合。
4.  **自适应融合掩码 (Learned Delivery Mask)**：预测一个置信度掩码，决定画面中哪些像素使用生成的动态结果，哪些像素直接复制最后一帧的静态背景，从而完美保留静态区域的高频细节。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn as nn

class AcrossVAM(nn.Module):
    def __init__(self):
        super().__init__()
        # 冻结的感知与语言模型
        self.frozen_sam3 = FrozenSAM3_DLP()
        self.frozen_clip = FrozenOpenCLIP()
        
        # 可训练的轻量级动力学模型 (0.28M)
        self.particle_transformer = SpatioTemporalTransformer()
        
        # 可训练的解码与融合模块
        self.appearance_encoder = DenseEncoder()
        self.residual_refiner = ResidualRefiner()
        self.mask_predictor = MaskPredictor()

    def forward(self, context_frames, instruction):
        # context_frames: [B, 4, C, H, W]
        last_frame = context_frames[:, -1]
        
        # 1. 语义粒子化 (仅提取几何与基础状态)
        # particles shape: [B, 4, K_slots, State_dim]
        particles, bg_latent = self.frozen_sam3(context_frames)
        
        # 2. 文本特征提取
        text_emb = self.frozen_clip(instruction)
        
        # 3. 文本条件动力学预测 (自回归预测未来 5 帧粒子状态)
        future_particles = self.particle_transformer(particles, text_emb)
        
        # 4. 因果表观解码
        # 仅从最后一帧提取表观特征，杜绝未来信息泄露
        appearance_feat = self.appearance_encoder(last_frame)
        
        # 根据预测的粒子渲染运动草图
        motion_proposal, alpha_map = render_particles(future_particles, bg_latent)
        
        # 结合运动草图与静态表观特征，生成未来画面候选
        generated_frames = self.residual_refiner(appearance_feat, motion_proposal, alpha_map)
        
        # 5. 自适应融合 (Delivery Mask)
        # 预测掩码以决定哪些像素保留 last_frame，哪些使用 generated_frames
        blend_mask = self.mask_predictor(motion_proposal, alpha_map, last_frame)
        
        final_video = blend_mask * generated_frames + (1 - blend_mask) * last_frame.unsqueeze(1)
        
        return final_video, future_particles
```

### 第二模块：核心架构解释

DeicticVLA 的核心架构本质上是一个输入预处理与特征融合流水线，外加一套严格的微调策略。其流程可拆解为以下三个阶段：

**1. 指令规范化 (Instruction Canonicalization)**
无论用户输入的是纯文本（LI）、文本+点击（VLI），还是纯点击（VI），系统都会将其转换为统一的 `(Text, Masks)` 格式。对于 VI，文本会被填充为默认的 "follow visual instruction"；对于点击操作，系统调用 SAM 2 将二维坐标转化为目标掩码（Mask-T）、放置目标掩码（Mask-G）或参考物掩码（Mask-R）。

**2. 提示注入机制 (Prompting Methods)**
论文系统对比了两大类、四种掩码注入方法：
- **RGB 视觉提示 (RGB Visual Prompting):** 直接修改输入图像。`VP-BBox` 在掩码周围画红框；`VP-Fade` 将掩码外的背景做 80% 灰度弱化。
- **独立通道掩码提示 (Separate-Channel Mask Prompting):** 保持 RGB 图像不变，将掩码作为独立输入。`MP-Early` 在视觉编码器（ViT）输入前将掩码 Embedding 与图像 Embedding 相加；`MP-Late` 在视觉编码器输出后、进入 LLM 之前进行特征相加。

**3. 两阶段训练策略 (Two-Stage Training)**
为了防止模型在学习使用掩码时遗忘语言能力，采用两阶段微调：
- Stage 1: 仅使用纯语言指令数据集（LI data）微调预训练 VLA。
- Stage 2: 混合 LI、VLI 和 VI 数据集进行联合微调。

**核心逻辑伪代码实现：**

```python
import torch
import sam2

class DeicticVLA:
    def __init__(self, base_vla, prompting_method="MP-Late"):
        self.vla = base_vla
        self.sam2 = sam2.load_model("sam2.1-hiera-tiny")
        self.prompting_method = prompting_method
        
    def canonicalize(self, mode, text_input, clicks, image):
        # 1. Text Completion
        if mode == "VI":
            text_prompt = "follow visual instruction"
        else:
            text_prompt = text_input
            
        # 2. Deictic Gesture Grounding
        if mode == "LI" or clicks is None:
            masks = torch.zeros_like(image[:, :, 0]) # Zero mask
        else:
            masks = self.sam2.generate_masks(image, clicks)
            
        return text_prompt, masks

    def apply_prompting(self, image, masks):
        if self.prompting_method == "VP-BBox":
            # RGB Visual Prompting: Draw bounding box on RGB
            prompted_image = draw_red_bbox(image, masks)
            return prompted_image, None
            
        elif self.prompting_method == "MP-Late":
            # Separate-Channel: Keep RGB intact, process mask separately
            mask_patch_embeds = linear_proj(patchify(masks))
            return image, mask_patch_embeds

    def forward(self, mode, text_input, clicks, image, robot_state):
        # Step 1: Canonicalization
        text_prompt, masks = self.canonicalize(mode, text_input, clicks, image)
        
        # Step 2: Prompt Injection
        prompted_image, mask_embeds = self.apply_prompting(image, masks)
        
        # Step 3: VLA Forward Pass (MP-Late example)
        image_features = self.vla.visual_encoder(prompted_image)
        
        if self.prompting_method == "MP-Late" and mask_embeds is not None:
            # Late fusion: Add mask embeddings to visual features before LLM
            fused_features = image_features + mask_embeds
        else:
            fused_features = image_features
            
        # Step 4: Action Generation
        action_chunk = self.vla.llm_decoder(fused_features, text_prompt, robot_state)
        return action_chunk
```

### 第二模块：核心架构解释

ROBUST TAMP 的核心逻辑是一个“感知-规划-验证-执行-监控”的闭环。与传统 TAMP 试图一次性生成完整长程规划不同，它采取了“走一步看一步”的策略。

1. **可见场景构建 (Visible Scene-State Construction)**: 在每个规划节点，系统仅从当前视觉输入中提取可见物体及其空间关系，构建轻量级关系场景图。未观测到的物体被严格排除在状态之外。
2. **基础模型规划 (FM Planning)**: LLM 或 VLM 接收当前可见状态、历史动作、目标指令以及触发重规划的事件上下文，生成任务级动作序列。
3. **分层验证 (Layered Plan Validation)**: 在动作下发到底层前，语法解析器会拦截未知动作或对象（L1 错误），逻辑验证器会拦截违反物理常识的动作（如手里有东西时再次抓取，L2 错误）。
4. **异构执行与监控 (Heterogeneous Grounding & Execution)**: 验证通过的动作被送入底层执行器（如 PDDLStream 或运动基元）。监控层实时检测环境变化。
5. **事件触发重规划 (Event-Triggered Replanning)**: 如果底层执行器报告物理失败（如抓取失败），或监控层发现了之前隐藏的新物体，当前执行序列立即终止，系统将失败原因或新物体信息打包为结构化事件，反馈给大模型进行下一轮规划。

### 第一模块：一分钟核心速写

1. 论文领域：World Model

2. TL;DR: 本文提出了一种基于自适应 e-process 符号翻转检验（aeSFT）的序列假设检验框架，以解决评估合成数据集有效性时真实测试数据消耗过大的痛点问题，在分类、无线调度和无线电图预测基准上实现了在严格控制假阳性率的前提下大幅降低真实数据消耗。

- 存疑的试验结果：论文在消融实验中通过网格搜索确定了最优的超参数组合（如批次增长因子 $\beta=1.2$ 或 $1.6$，初始批次 $m_{init}=200$ 或 $50$）。在面对方差未知、分布完全陌生的全新具身智能或物理控制任务时，这些超参数的泛化能力存疑。如果初始批次设置过小或增长因子设置不当，可能会导致频繁的批次内提前停止，反而增加总数据消耗。

### 第二模块：核心架构解释

当前论文的模型架构与实验流程可以拆解为以下几个核心步骤：

1. **模型准备与基线确立**：使用纯真实数据集 $\mathcal{D}$ 训练基线模型 $f$；使用真实与合成混合数据集 $\mathcal{D} \cup \mathcal{D}^{syn}$ 训练增强模型 $f^{syn}$。
2. **零假设设定**：设定对称性零假设 $H_0^{syn}$，即假设合成数据无效时，两个模型在真实测试样本上的成对损失差 $\delta$ 围绕零对称分布。
3. **批次内测试（Intra-batch e-process）**：
   - 抽取大小为 $m_k$ 的真实测试数据批次。
   - 计算该批次内的真实损失差。
   - 进行自适应次数的蒙特卡洛符号翻转（生成随机正负号序列并计算翻转后的损失差均值）。
   - 根据翻转结果是否击败真实观察值来更新当前批次的“财富” $W_k^b$。
   - 触发提前停止机制：如果财富跌破下限 $\omega$（表现不佳），或连续获胜但财富增长微小（证据耗尽），则终止当前批次的翻转。
4. **批次间累积与全局决策（Inter-batch e-process）**：
   - 将历史所有批次的最终财富相乘，得到全局财富 $\widetilde{W}_k^b$。
   - 如果全局财富 $\widetilde{W}_k^b \ge 1/\alpha$（$\alpha$ 为目标 Type-I 错误率），则拒绝零假设，宣布合成数据有效，测试终止。
   - 如果当前批次因表现不佳而提前停止，则将下一批次的数据量扩大 $\beta$ 倍（$m_{k+1} = \lceil \beta m_k \rceil$），继续抽取新数据进行测试。

```python
            b += 1
            # Monte Carlo sign flip
            signs = random_signs(size=m_k)
            flipped_stat = mean(signs * delta)
            
            # Indicator: 1 if flipped stat beats observed stat (gambler loses), 0 otherwise
            I_b = 1 if flipped_stat >= observed_stat else 0
            
            # Update batch wealth using optimized betting function G
            batch_wealth = batch_wealth * G(I_b, b, history)
            
            # Update global wealth
            current_global_wealth = global_wealth * batch_wealth
            
            # 4. Inter-batch rejection (Global success)
            if current_global_wealth >= 1 / alpha:
                return "REJECT H0: Synthetic data is useful!"
                
            # 5. Intra-batch early stopping conditions
            # Condition A: Evidence exhausted (wealth barely growing)
            if b >= 2 and I_b == 0 and previous_I == 0 and (batch_wealth - prev_batch_wealth) <= epsilon:
                break # Keep next batch size same
                
            # Condition B: Unpromising batch (cut losses)
            if batch_wealth <= omega:
                m_k = ceil(beta * m_k) # Enlarge next batch
                break
                
        # Accumulate wealth for next batch
        global_wealth *= batch_wealth
        
    return "FAIL TO REJECT H0: Insufficient evidence."
```

### 第二模块：核心架构解释

WALDO 的架构设计遵循“重特征、轻预测”的原则，核心流程分为特征提取、相关性注入、条件调制与联合预测四个阶段。同时，其训练数据的构造逻辑（Episode-mining）是防止模型作弊的核心。

1. **特征提取**：场景图像和示例图像（Exemplar）输入冻结的 V-JEPA 提取视觉 Token；简短描述文本输入冻结的 SigLIP2 提取文本向量。
2. **相关性通道（Correlation Channel）**：在任何线性投影扭曲特征空间之前，直接在骨干网络的原始特征空间中计算场景每个 Patch 与示例向量的余弦相似度，并将其作为物理特征拼接到 Patch Token 上。
3. **条件调制（FiLM Conditioning）**：将示例向量与文本向量拼接，通过 MLP 预测全局的缩放（Gamma）和平移（Beta）参数，对场景 Token 进行特征级仿射变换，实现多模态指令的注入。
4. **防作弊数据构造（Shortcut-free Mining）**：在合成“目标存在”与“目标缺失”的训练片段时，强制解耦裁剪区域大小与标签的相关性。所有样本的裁剪尺寸从同一分布中抽取，防止模型通过“测量输入图像的视野大小”来盲猜目标是否存在。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class WALDOHead(nn.Module):
    def __init__(self, dim=1024, text_dim=1152, hidden_dim=256):
        super().__init__()
        # 降维与位置编码
        self.proj_visual = nn.Linear(dim + 1, hidden_dim) # +1 for correlation
        self.pos_embed = nn.Parameter(torch.randn(1, 576, hidden_dim))
        
        # FiLM 调制生成器
        self.film_gen = nn.Sequential(
            nn.Linear(dim + text_dim, hidden_dim * 2),
            nn.ReLU(),
            nn.Linear(hidden_dim * 2, hidden_dim * 2) # 输出 gamma 和 beta
        )
        # 初始化最后一层为0，确保初始状态为恒等映射
        nn.init.zeros_(self.film_gen[-1].weight)
        nn.init.zeros_(self.film_gen[-1].bias)
        
        # Transformer 处理块
        self.transformer = nn.TransformerEncoder(...) 
        
        # 预测头
        self.head_obj = nn.Linear(hidden_dim, 1)    # Patch级目标置信度
        self.head_box = nn.Linear(hidden_dim, 4)    # Patch级边界框偏移 (cx, cy, w, h)
        self.head_pres = nn.Sequential(             # 全局存在性预测
            nn.Linear(hidden_dim, 1),
            nn.Softmax(dim=1)
        )

    def forward(self, Z_q, Z_e, u):
        """
        Z_q: 场景 Token [B, 576, 1024] (来自冻结 V-JEPA)
        Z_e: 示例 Token [B, 1024] (来自冻结 V-JEPA, 已 mean-pool)
        u:   文本特征 [B, 1152] (来自冻结 SigLIP2)
        """
        B, N, D = Z_q.shape
        
        # 1. 计算 Patch 级余弦相似度 (Correlation Channel)
        Z_e_norm = F.normalize(Z_e, dim=-1).unsqueeze(1) # [B, 1, 1024]
        Z_q_norm = F.normalize(Z_q, dim=-1)              # [B, 576, 1024]
        corr = torch.sum(Z_q_norm * Z_e_norm, dim=-1, keepdim=True) # [B, 576, 1]
        
        # 2. 拼接相似度并投影
        X = torch.cat([Z_q, corr], dim=-1)
        X = self.proj_visual(X) + self.pos_embed
        
        # 3. FiLM 条件调制
        cond_feat = torch.cat([Z_e, u], dim=-1)
        film_params = self.film_gen(cond_feat)
        gamma, beta = film_params.chunk(2, dim=-1)
        gamma = gamma.unsqueeze(1) # [B, 1, hidden_dim]
        beta = beta.unsqueeze(1)
        
        X = X * (1 + gamma) + beta
        
        # 4. Transformer 编码
        X = self.transformer(X)
        
        # 5. 联合预测
        obj_logits = self.head_obj(X)
        box_preds = self.head_box(X) # 后续需解码为绝对坐标
        
        # 注意力池化计算全局存在性 (Presence)
        attn_weights = self.head_pres(X) # [B, 576, 1]
        presence_feat = torch.sum(attn_weights * X, dim=1) # [B, hidden_dim]
        presence_logit = self.head_pres_out(presence_feat) # 伪代码简化，实际通过MLP输出标量
        
        return obj_logits, box_preds, presence_logit
```

**TL;DR:** 本文提出了一种基于构念级别（Construct-level）评估的 CoCoBench 基准测试框架，以解决现有具身多智能体基准测试仅依赖总体任务成功率而掩盖具体协作失效机制的问题，在多智能体具身任务规划评估上实现了对任务分配、顺序执行、互斥排他及交接协作四类核心协作能力的细粒度量化与诊断。

*   **存疑/反直觉数据:** 在“视觉 vs 盲测”的消融实验中，移除图像输入（仅保留文本状态和动作菜单）并未导致性能显著下降（盲测平均 SR 42.3%，图像平均 SR 40.6%）。理由：该基准测试使用了高度抽象的参数化技能接口（如 `PickUp(Object)`），环境中的物体和可执行动作已被符号化。这表明该测试实际衡量的是纯粹的符号化多智能体规划能力，而非 VLA 模型底层的视觉感知与物理接地能力。

### 第二模块：核心架构解释

CoCoBench 的核心架构分为三个阶段：任务实例化、智能体规划执行、以及轨迹级评估。

1.  **任务实例化 (Task Instantiation):** 基于 AI2-THOR 模拟器，构建 897 个经过 Oracle 验证的任务实例。每个实例严格对应一种协作构念（D1-D4）。环境向智能体暴露参数化的高级技能菜单（如导航、抓取、放置、切片等）。
2.  **智能体规划执行 (Agent Planning & Execution):** 支持集中式（Centralized）和分布式（Decentralized）策略。在每个时间步，MLLM 接收自我中心视觉观察、历史记录和当前可用动作菜单，输出动作指令。底层执行器（Executor）在模拟器中确定性地执行这些技能，并记录状态转移、动作结果及冲突事件。
3.  **轨迹级评估 (Trajectory-level Evaluation):** 任务结束后，框架不仅检查最终状态是否满足所有目标谓词以计算成功率（SR），还遍历记录的执行轨迹（Trajectory），根据特定构念的数学定义计算构念得分（CS）。

以下是 CoCoBench 核心评估逻辑的 Python 风格伪代码：

```python
class CoCoBenchEvaluator:
    def __init__(self, env, oracle_makespan):
        self.env = env
        self.oracle_makespan = oracle_makespan
        self.trajectory = []
        
    def execute_episode(self, agents, policy, max_steps):
        state, obs = self.env.reset()
        
        for step in range(max_steps):
            # 集中式或分布式策略生成联合动作
            joint_action = policy.get_actions(obs)
            
            # 执行器在环境中应用动作，返回新状态和事件(如冲突、等待、非法操作)
            next_state, next_obs, events = self.env.step(joint_action)
            
            # 记录轨迹用于后续构念评分
            self.trajectory.append({
                'state': state,
                'actions': joint_action,
                'events': events
            })
            
            state, obs = next_state, next_obs
            if self.env.is_goal_reached():
                break
                
        return self.trajectory

    def evaluate(self, construct_type):
        # 1. 计算任务成功率 (Success Rate)
        sr = 1.0 if self.env.is_goal_reached() else 0.0
        
        # 2. 计算构念得分 (Construct Score)
        cs = 0.0
        if construct_type == 'D1': # 任务分配
            realized_makespan = len(self.trajectory)
            cs = min(1.0, self.oracle_makespan / realized_makespan)
            
        elif construct_type == 'D2': # 顺序执行
            violations = sum(1 for t in self.trajectory if t['events'].get('precondition_violation'))
            total_relevant_ops = self.env.get_total_precedence_ops()
            p_legal = 1.0 if not self.has_illegal_skills() else 0.5
            cs = p_legal * max(0.0, 1.0 - (violations / total_relevant_ops))
            
        elif construct_type == 'D3': # 互斥排他
            collisions = sum(1 for t in self.trajectory if t['events'].get('resource_collision'))
            access_attempts = self.env.get_total_access_attempts()
            realized_steps = len(self.trajectory)
            contention_penalty = 1.0 - (collisions / access_attempts) if access_attempts > 0 else 1.0
            efficiency_penalty = min(1.0, self.oracle_makespan / realized_steps)
            cs = contention_penalty * efficiency_penalty
            
        elif construct_type == 'D4': # 交接协作
            overflows = sum(1 for t in self.trajectory if t['events'].get('buffer_overflow'))
            waits = sum(1 for t in self.trajectory if t['events'].get('empty_buffer_wait'))
            successful_handoffs = self.env.get_successful_handoffs()
            if successful_handoffs > 0:
                cs = max(0.0, 1.0 - ((overflows + waits) / successful_handoffs))
            else:
                cs = 0.0
                
        return sr, cs
```

2. SafeAgentBench (Yin et al., 2024)：本文利用该基准，补充验证了 ASR 错误不仅引发安全风险，还会实质性削弱模型在正常安全任务中的规划鲁棒性。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 核心局限性在于其 ASR 错误是“模拟生成”的（基于 GPT-4 文本改写和规则插入），而非通过真实的声学模型（如 Whisper）对真实语音波形进行端到端推理产生的真实分布错误。这种模拟可能无法完全拟合真实世界中声学特征导致的复杂错误长尾分布。此外，论文仅测试了基于文本的 LLM 规划器，未对直接接收音频或多模态输入的端到端 VLA 模型（如 RT-Audio 等）进行测试。对后续科研的启发是：具身智能的安全对齐不能仅停留在纯文本的语义逻辑层面，必须将多模态感知模块的自然噪声（听错、看错、传感器漂移）纳入底层的安全训练与对齐分布中。
