### 第二模块：核心架构解释

A1 框架的核心在于打破了传统 VLA “完整前向传播 + 完整去噪迭代”的串行高耗时流程，将其改造为“逐层评估 + 跨层热启动去噪”的动态流水线。

**1. 基础架构与多出口训练**
模型由 Molmo-7B 视觉语言骨干和动作头（支持 MLP 或 Flow Matching）组成。在训练阶段，模型不只在最后一层计算 Loss，而是随机选择 VLM 的第 $i$ 层截断，将该层隐藏状态直接接入共享动作头进行监督。这迫使 VLM 的浅层也能学习到有效的动作表征。

**2. 自适应早退推理 (Early-Termination Inference)**
在推理时，VLM 逐层计算。每计算完一层，动作头就会生成一个动作块（Action Chunk）。系统会计算当前层动作与上一层动作的差异（如 L2 距离）。如果差异小于基于训练集离线校准的阈值 $\eta_i$，说明动作预测已经收敛，模型直接输出该动作并提前终止 VLM 的后续计算。

**3. 层间截断流匹配 (Inter-Layer Truncated Flow Matching)**
如果使用流匹配（FM）动作头，早退机制会带来一个悖论：虽然 VLM 层数少了，但动作头在每一层都要做完整的 $\delta$ 步去噪，反而增加了耗时。A1 的解法是：将每层的去噪步数 $\delta$ 压缩到极小（如 2 步），并且第 $i$ 层的去噪不从纯噪声开始，而是直接把第 $i-1$ 层输出的动作作为初始状态。这种“热启动”让去噪过程在 VLM 的层间流动，彻底抹平了计算开销。

**核心伪代码实现逻辑：**

```python
def a1_adaptive_inference(vlm_layers, action_head, obs, thresholds, delta=2):
    """
    A1 模型的自适应早退与层间截断流匹配推理逻辑
    vlm_layers: VLM 的网络层列表
    action_head: 流匹配动作头
    obs: 当前观测 (图像, 语言指令, 状态)
    thresholds: 离线校准的各层退出阈值列表
    delta: 每层的截断去噪步数 (默认极小值 2)
    """
    # 初始化隐藏状态和初始噪声
    hidden_state = embed_input(obs)
    # 初始动作从标准正态分布采样
    current_action = sample_gaussian_noise() 
    
    for i, layer in enumerate(vlm_layers):
        # 1. VLM 单层前向传播
        hidden_state = layer(hidden_state)
        
        # 2. 层间截断流匹配 (Inter-Layer Truncated Flow Matching)
        # 关键创新：不从纯噪声开始，而是以上一层的 current_action 作为热启动起点
        prev_action = current_action
        current_action = action_head.denoise(
            hidden_state, 
            initial_state=prev_action, 
            steps=delta
        )
        
        # 3. 动作一致性检测 (Action-Consistency Thresholding)
        if i > 0:
            # 计算当前层与上一层动作的差异 (如 L2 距离)
            action_diff = compute_distance(current_action, prev_action)
            
            # 4. 触发早退机制
            if action_diff < thresholds[i]:
                return current_action # 动作已稳定，提前退出
                
    # 如果遍历完所有层仍未触发早退，返回最后一层结果
    return current_action
```

  - OFT: 附加轻量级 MLP 进行连续动作的并行回归。
  - $\pi$: 跨注意力 DiT 流匹配（Flow-matching）迭代去噪。
  - GR00T: 模拟系统 1（快速动作生成）与系统 2（慢速推理）的双系统架构。

**3. 统一评估与部署 (Server-Client Evaluation)**
采用轻量级 WebSocket 服务器托管策略模型，仿真器或真实机器人作为客户端发送观测数据并接收动作。这种解耦设计使得同一套模型代码可以无缝切换于 LIBERO、SimplerEnv 等不同依赖栈的基准测试，甚至直接用于真机部署。

```python
import torch
import torch.nn as nn

class StarVLAFramework(nn.Module):
    def __init__(self, backbone_cfg, action_head_cfg):
        super().__init__()
        # 1. 独立加载视觉-语言主干 (VLM 或 World Model)
        self.vl_backbone = build_backbone(backbone_cfg)
        # 2. 独立加载动作头 (FAST, OFT, Pi, 或 GR00T)
        self.action_head = build_action_head(action_head_cfg)

    def forward(self, raw_images, instruction_str, ground_truth_actions):
        """训练入口：直接接收原始观测与动作"""
        # 步骤 A: 主干网络处理原始输入，提取多模态隐藏状态
        hidden_states = self.vl_backbone.extract_features(raw_images, instruction_str)

        # 步骤 B: 动作头接收隐藏状态，预测动作并计算动作损失
        action_loss = self.action_head.compute_loss(hidden_states, ground_truth_actions)

        # 步骤 C: (可选) 计算辅助损失，如 VLM 的语言建模损失或 World Model 的未来观测预测损失
        aux_loss = self.vl_backbone.compute_auxiliary_loss()

        return {"action_loss": action_loss, "aux_loss": aux_loss}

    def predict_action(self, raw_images, instruction_str):
        """推理入口：严格保持与训练一致的 I/O 接口"""
        # 提取特征
        hidden_states = self.vl_backbone.extract_features(raw_images, instruction_str)
        # 动作头生成具体动作指令
        predicted_actions = self.action_head.generate(hidden_states)
        
        return predicted_actions
```

### 第二模块：核心架构解释

A1 框架的核心在于打破了传统 VLA “完整前向传播 + 完整去噪迭代”的串行高耗时流程，将其改造为“逐层评估 + 跨层热启动去噪”的动态流水线。

**1. 基础架构与多出口训练**
模型由 Molmo-7B 视觉语言骨干和动作头（支持 MLP 或 Flow Matching）组成。在训练阶段，模型不只在最后一层计算 Loss，而是随机选择 VLM 的第 $i$ 层截断，将该层隐藏状态直接接入共享动作头进行监督。这迫使 VLM 的浅层也能学习到有效的动作表征。

**2. 自适应早退推理 (Early-Termination Inference)**
在推理时，VLM 逐层计算。每计算完一层，动作头就会生成一个动作块（Action Chunk）。系统会计算当前层动作与上一层动作的差异（如 L2 距离）。如果差异小于基于训练集离线校准的阈值 $\eta_i$，说明动作预测已经收敛，模型直接输出该动作并提前终止 VLM 的后续计算。

**3. 层间截断流匹配 (Inter-Layer Truncated Flow Matching)**
如果使用流匹配（FM）动作头，早退机制会带来一个悖论：虽然 VLM 层数少了，但动作头在每一层都要做完整的 $\delta$ 步去噪，反而增加了耗时。A1 的解法是：将每层的去噪步数 $\delta$ 压缩到极小（如 2 步），并且第 $i$ 层的去噪不从纯噪声开始，而是直接把第 $i-1$ 层输出的动作作为初始状态。这种“热启动”让去噪过程在 VLM 的层间流动，彻底抹平了计算开销。

**核心伪代码实现逻辑：**

```python
def a1_adaptive_inference(vlm_layers, action_head, obs, thresholds, delta=2):
    """
    A1 模型的自适应早退与层间截断流匹配推理逻辑
    vlm_layers: VLM 的网络层列表
    action_head: 流匹配动作头
    obs: 当前观测 (图像, 语言指令, 状态)
    thresholds: 离线校准的各层退出阈值列表
    delta: 每层的截断去噪步数 (默认极小值 2)
    """
    # 初始化隐藏状态和初始噪声
    hidden_state = embed_input(obs)
    # 初始动作从标准正态分布采样
    current_action = sample_gaussian_noise() 
    
    for i, layer in enumerate(vlm_layers):
        # 1. VLM 单层前向传播
        hidden_state = layer(hidden_state)
        
        # 2. 层间截断流匹配 (Inter-Layer Truncated Flow Matching)
        # 关键创新：不从纯噪声开始，而是以上一层的 current_action 作为热启动起点
        prev_action = current_action
        current_action = action_head.denoise(
            hidden_state, 
            initial_state=prev_action, 
            steps=delta
        )
        
        # 3. 动作一致性检测 (Action-Consistency Thresholding)
        if i > 0:
            # 计算当前层与上一层动作的差异 (如 L2 距离)
            action_diff = compute_distance(current_action, prev_action)
            
            # 4. 触发早退机制
            if action_diff < thresholds[i]:
                return current_action # 动作已稳定，提前退出
                
    # 如果遍历完所有层仍未触发早退，返回最后一层结果
    return current_action
```

```python
            action_images.append(img_view)
        return torch.stack(action_images)

    def images_to_action(self, generated_action_images, camera_params):
        """从生成的2D动作图像中逆向解析出7-DoF物理动作"""
        # 通过多视角几何还原3D动作指令
        actions_7dof = inverse_projection(generated_action_images, camera_params)
        return actions_7dof

    def forward(self, observation_images, target_action_images=None):
        """
        训练阶段：联合生成未来观察与动作图像
        推理阶段：自回归生成动作图像
        """
        # 将观察图像与动作图像在通道或序列维度拼接
        input_sequence = concatenate(observation_images, target_action_images)
        
        # 纯视频生成过程
        generated_sequence = self.video_backbone(input_sequence)
        return generated_sequence

    def get_action(self, current_observation, camera_params):
        """策略执行（推理）"""
        # 生成未来的动作图像
        pred_action_images = self.forward(current_observation)
        # 解析为底层控制指令
        action_cmd = self.images_to_action(pred_action_images, camera_params)
        return action_cmd
```

### 第二模块：核心架构解释

StarVLA 的核心架构设计围绕“部署时不变性（Deployment-time Invariant）”展开，强制要求训练和推理阶段的输入输出格式完全一致，并在内部实现了高度的模块化解耦。

**1. 统一 I/O 接口 (Unified I/O Interface)**
无论是训练还是推理，模型直接消费原始环境观测数据（如多视角 RGB 图像、自然语言指令），并输出标准化动作块。这消除了传统方法中繁重的、特定于模型的数据预处理逻辑，最大程度降低了训练与部署之间的分布不匹配（Distribution Mismatch）。

**2. 主干-动作头解耦 (Compositional Framework)**
- **VL Backbone (视觉语言主干)**: 负责提取多模态特征。支持指令微调的 VLM（如 Qwen2.5-VL）或原生视频世界模型（如 Cosmos）。
- **Action Head (动作头)**: 负责将主干提取的隐藏状态映射为物理动作。StarVLA 内置了四种代表性范式：
  - FAST: 自回归离散动作 Token 预测。
  - OFT: 附加轻量级 MLP 进行连续动作的并行回归。
  - $\pi$: 跨注意力 DiT 流匹配（Flow-matching）迭代去噪。
  - GR00T: 模拟系统 1（快速动作生成）与系统 2（慢速推理）的双系统架构。

**3. 统一评估与部署 (Server-Client Evaluation)**
采用轻量级 WebSocket 服务器托管策略模型，仿真器或真实机器人作为客户端发送观测数据并接收动作。这种解耦设计使得同一套模型代码可以无缝切换于 LIBERO、SimplerEnv 等不同依赖栈的基准测试，甚至直接用于真机部署。

**核心逻辑伪代码：**

```python
import torch
import torch.nn as nn

class StarVLAFramework(nn.Module):
    def __init__(self, backbone_cfg, action_head_cfg):
        super().__init__()
        # 1. 独立加载视觉-语言主干 (VLM 或 World Model)
        self.vl_backbone = build_backbone(backbone_cfg)
        # 2. 独立加载动作头 (FAST, OFT, Pi, 或 GR00T)
        self.action_head = build_action_head(action_head_cfg)

    def forward(self, raw_images, instruction_str, ground_truth_actions):
        """训练入口：直接接收原始观测与动作"""
        # 步骤 A: 主干网络处理原始输入，提取多模态隐藏状态
        hidden_states = self.vl_backbone.extract_features(raw_images, instruction_str)

        # 步骤 B: 动作头接收隐藏状态，预测动作并计算动作损失
        action_loss = self.action_head.compute_loss(hidden_states, ground_truth_actions)

        # 步骤 C: (可选) 计算辅助损失，如 VLM 的语言建模损失或 World Model 的未来观测预测损失
        aux_loss = self.vl_backbone.compute_auxiliary_loss()

        return {"action_loss": action_loss, "aux_loss": aux_loss}

    def predict_action(self, raw_images, instruction_str):
        """推理入口：严格保持与训练一致的 I/O 接口"""
        # 提取特征
        hidden_states = self.vl_backbone.extract_features(raw_images, instruction_str)
        # 动作头生成具体动作指令
        predicted_actions = self.action_head.generate(hidden_states)
        
        return predicted_actions
```

### 第二模块：核心架构解释

SnapFlow 的架构并未改变原有 VLA 模型的骨干网络，而是通过修改训练目标和时间条件注入方式来实现单步生成。

**训练流程：**
冻结视觉-语言大模型（VLM）骨干，仅训练动作专家（Action Expert）网络。对于每一个训练批次，系统以 50% 的概率执行标准流匹配（FM）训练，以 50% 的概率执行一致性蒸馏训练。
在一致性蒸馏中，模型首先预测时间点 $t=1$ 和 $t=0.5$ 的速度，通过欧拉方法计算出两步到达目标的平均速度（即两步捷径目标）。随后，模型在时间点 $t=1$ 且目标时间 $s=0$ 的条件下进行单步预测，计算该预测值与两步捷径目标的均方误差（MSE）作为损失函数。

**推理流程：**
在部署时，直接输入视觉图像和语言指令，生成随机高斯噪声。将目标时间参数 $s$ 设定为 0，模型仅需进行一次前向传播，即可直接输出最终的动作轨迹，跳过所有中间去噪步骤。

**核心伪代码实现：**

```python
import torch
import torch.nn as nn

def snapflow_training_step(model, x_0, context, alpha=0.5, lambda_weight=0.1):
    """
    x_0: 真实的动作数据 (Ground truth action)
    context: VLM提取的视觉和语言特征
    """
    # 1. 采样随机噪声和随机时间 t
    epsilon = torch.randn_like(x_0)
    t = torch.rand(x_0.shape[0], 1, 1).to(x_0.device)
    
    # 构造当前时刻的带噪状态 x_t
    x_t = (1 - t) * x_0 + t * epsilon
    
    # 2. 标准流匹配 (FM) 路径
    # 预测瞬时速度，目标时间 s = t
    v_pred_fm = model(x_t, current_time=t, target_time=t, context=context)
    loss_fm = torch.nn.functional.mse_loss(v_pred_fm, epsilon - x_0)
    
    # 3. 一致性蒸馏路径 (构建两步欧拉捷径)
    with torch.no_grad():
        # 步骤 A: 预测 t=1 时的速度
        x_1 = epsilon
        v_1 = model(x_1, current_time=1.0, target_time=1.0, context=context)
        
        # 步骤 B: 走到中点 t=0.5
        x_05 = x_1 - 0.5 * v_1
        
        # 步骤 C: 预测 t=0.5 时的速度
        v_05 = model(x_05, current_time=0.5, target_time=0.5, context=context)
        
        # 计算两步捷径的平均速度作为目标
        v_target = 0.5 * (v_1 + v_05)
        
    # 训练单步预测网络去拟合这个捷径目标
    # 目标时间 s = 0
    v_pred_1step = model(x_1, current_time=1.0, target_time=0.0, context=context)
    loss_shortcut = torch.nn.functional.mse_loss(v_pred_1step, v_target)
    
    # 4. 混合损失
    total_loss = alpha * loss_fm + (1 - alpha) * lambda_weight * loss_shortcut
    
    return total_loss

def snapflow_inference(model, context, action_shape):
    """
    单步推理过程
    """
    # 采样纯噪声
    x_1 = torch.randn(action_shape)
    
    # 单次前向传播，设定目标时间 s=0
    v_pred = model(x_1, current_time=1.0, target_time=0.0, context=context)
    
    # 直接生成最终动作
    x_0_hat = x_1 - v_pred
    
    return x_0_hat
```

### 第二模块：核心架构解释

VLA-InfoEntropy 的核心架构建立在 VLA-Cache 的帧间相似度缓存机制之上，通过引入双重熵评估和动态时间步调度来决定哪些 token 必须重新计算，哪些可以复用缓存。

**运行流程：**
1. **基础状态划分：** 输入图像经过 Patching 后，首先通过计算与上一帧的余弦相似度，筛选出一批变化较小的“静态 Tokens”。
2. **视觉熵计算 (Visual Entropy)：** 针对每个视觉 token，统计其对应图像块的灰度级直方图，计算香农熵。熵值越高，代表该区域纹理越复杂、边缘越丰富，被视为空间信息量大。
3. **注意力熵计算 (Attention Entropy)：** 提取模型最后一层的文本-视觉交叉注意力矩阵。计算每个视觉 token 在所有文本 token 上的注意力分布熵。分布越集中（熵值越低），说明该视觉 token 与特定指令高度绑定。论文通过取反归一化，将低熵转化为高重要性得分。
4. **时间步动态调度 (Timestep-aware Selection)：** 引入时间步比例 $\alpha = t/T$。在任务初期（$t$ 较小），分配更多的预算给视觉熵高的 token，以获取全局视觉上下文；在任务后期（$t$ 较大），将预算倾斜给注意力熵高的 token，以聚焦局部任务目标。
5. **Token 驱逐与缓存复用：** 根据动态预算选出最重要的 tokens，将它们从“静态 Tokens”集合中剔除（强制重新计算）。剩余的低信息量静态 tokens 则直接复用上一帧的 KV 缓存。

**核心逻辑伪代码 (Python 风格)：**

```python
import numpy as np

def calculate_visual_entropy(image_patches, num_bins=256):
    # 计算每个 patch 的灰度直方图熵
    vis_entropy_scores = []
    for patch in image_patches:
        hist, _ = np.histogram(patch, bins=num_bins, density=True)
        hist = hist[hist > 0] # 避免 log(0)
        entropy = -np.sum(hist * np.log2(hist))
        vis_entropy_scores.append(entropy / np.log2(num_bins))
    return np.array(vis_entropy_scores)

def calculate_attention_entropy(cross_attn_matrix):
    # cross_attn_matrix shape: (num_text_tokens, num_visual_tokens)
    # 计算每个视觉 token 在文本 token 上的注意力分布熵
    attn_entropy_scores = []
    num_text_tokens = cross_attn_matrix.shape[0]
    for i in range(cross_attn_matrix.shape[1]):
        prob_dist = cross_attn_matrix[:, i]
        prob_dist = prob_dist[prob_dist > 0]
        entropy = -np.sum(prob_dist * np.log2(prob_dist))
        # 熵越低，语义相关性越高，因此用 1 - 归一化熵 表示重要性
        importance = 1 - (entropy / np.log2(num_text_tokens))
        attn_entropy_scores.append(importance)
    return np.array(attn_entropy_scores)

def dynamic_token_selection(vis_scores, attn_scores, t, T, k1, k2):
    # t: 当前时间步, T: 总时间步
    # k1: 基础注意力 token 数量, k2: 基础视觉 token 数量
    alpha = t / T
    
    # 动态计算当前时间步的 token 预算
    # 随着 t 增加，视觉 token 减少，注意力 token 增加
    k_vis = int(k2 - (k2 - k1) * alpha)
    k_attn = int(k1 + (k2 - k1) * alpha)
    
    # 获取 top-k 索引
    top_vis_idx = np.argsort(vis_scores)[-k_vis:]
    top_attn_idx = np.argsort(attn_scores)[-k_attn:]
    
    # 合并重要 token 集合
    important_tokens = set(top_vis_idx).union(set(top_attn_idx))
    return important_tokens

def vla_inference_step(image, text, t, T, prev_kv_cache, static_tokens):
    vis_scores = calculate_visual_entropy(image.patches)
    attn_scores = calculate_attention_entropy(model.get_cross_attn())
    
    important_tokens = dynamic_token_selection(vis_scores, attn_scores, t, T, k1=40, k2=60)
    
    # 从静态 token 中剔除重要 token，强制重新计算
    reusable_tokens = static_tokens - important_tokens
    
    # 执行模型前向传播，复用 reusable_tokens 的 KV 缓存
    action, new_kv_cache = model.forward(image, text, prev_kv_cache, reusable_tokens)
    return action, new_kv_cache
```

### 第二模块：核心架构解释

ReV 的核心架构是一个支持闭环推理的条件扩散模型，其生成流程分为时间位置预测、全局稀疏生成和局部密集插值三个阶段。

**1. 时间位置预测 (Temporal-Position Prediction)**
当接收到一个 3D 参考点时，模型需要知道这个点应该在整条轨迹的哪个时间节点被触发。通过一个 Transformer 编码器，结合历史动作锚点和带有时间位置编码的未来槽位，预测出该参考点在全局稀疏锚点序列中的具体索引 `k`。

**2. 全局扩散头 (Global Diffusion Head, GDH)**
负责生成具有全局一致性的稀疏动作锚点序列。在扩散模型的去噪过程中，采用轨迹引导策略（Trajectory-Steering）：利用二进制掩码，将已执行的历史锚点以及预测好时间位置的参考点动作强行替换到带噪轨迹中，引导生成方向。

**3. 局部扩散头 (Local Diffusion Head, LDH)**
负责在 GDH 生成的相邻稀疏锚点之间进行时间依赖的密集插值，生成可供机械臂直接执行的平滑、细粒度轨迹。同样利用掩码机制，确保插值轨迹的两端严格对齐相邻的锚点。

**4. 闭环推理 (Closed-Loop Inference)**
每次仅执行 LDH 生成的一小段细粒度轨迹，执行完毕后将最新的观测状态和已执行的锚点加入历史记录，重新调用整个模型进行下一轮生成，从而实现对动态环境的实时响应。

**核心逻辑伪代码 (Python 风格)**：

```python
def ReV_inference_step(observation, history_anchors, referring_point):
    # 1. 时间位置预测：确定参考点在稀疏序列中的时间步 k
    k = temporal_position_predictor(observation, history_anchors, referring_point)
    
    # 将 3D 参考点转化为部分约束的动作向量 (仅约束平移，不约束旋转)
    ref_action_constrained = convert_to_partial_action(referring_point)
    
    # 2. 全局扩散头 (GDH)：生成稀疏锚点序列
    noisy_anchors = sample_gaussian_noise(shape=(N1, action_dim))
    for t in reversed(range(diffusion_steps)):
        # 预测去噪
        pred_anchors = GDH_network(noisy_anchors, observation, t)
        
        # 轨迹引导策略 (Masked Denoising)
        # M_gdh 掩码：历史锚点位置为1，参考点位置 k 为1，其余为0
        # 强制将历史记录和参考点注入去噪过程
        noisy_anchors = M_gdh * known_anchors(history_anchors, ref_action_constrained, k) + \
                        (1 - M_gdh) * pred_anchors
                        
    # 提取当前步需要执行的相邻锚点对
    current_anchor = noisy_anchors[current_step]
    next_anchor = noisy_anchors[current_step + 1]
    
    # 3. 局部扩散头 (LDH)：在两个锚点间生成细粒度轨迹
    noisy_dense_traj = sample_gaussian_noise(shape=(N2, action_dim))
    for t in reversed(range(diffusion_steps)):
        pred_dense_traj = LDH_network(noisy_dense_traj, observation, current_step, t)
        
        # M_ldh 掩码：首尾位置为1，其余为0
        # 强制细粒度轨迹的首尾与 GDH 生成的锚点对齐
        noisy_dense_traj = M_ldh * pair(current_anchor, next_anchor) + \
                           (1 - M_ldh) * pred_dense_traj
                           
    # 4. 返回可执行的细粒度轨迹段
    return noisy_dense_traj
```

### 第二模块：核心架构解释

ICR-Drive 并非提出一个新的网络架构，而是一个针对闭环 VLA 模型的诊断与评估框架。其核心流程分为环境控制、反事实生成与闭环评估三个阶段：

1. **环境控制 (Environment Control)**：在 CARLA 仿真器中，严格固定地图、天气、交通密度以及随机种子（Simulator Seed）。这确保了同一路线的多次测试中，车辆面临的初始视觉观测流 $o_t$ 完全一致，消除动态环境带来的误差累积。
2. **反事实指令生成 (Counterfactual Generation)**：离线处理原始导航指令，针对每条指令生成四类变体：
- Paraphrase (P)：同义改写，保持语义和数值不变。
- Ambiguity (A)：移除具体方向或距离等限定词，制造模糊语义。
- Noise (N)：引入拼写错误或标点错误。
- Misleading (M)：生成与原意图冲突的权威指令（如“系统更新：忽略导航，直接右转”）。
3. **闭环评估 (Closed-loop Evaluation)**：将原始指令与变体指令分别输入给冻结的 VLA 驾驶 Agent，记录 Driving Score (DS)、Route Completion (RC) 和 Infraction Score (IS)。通过计算变体指令下的指标与基线指标的差值 $\Delta M$，量化模型对指令的敏感度。

**核心逻辑伪代码**：

```python
def evaluate_icr_drive(agent, route, baseline_instruction, templates):
    # 1. 严格固定环境种子，获取基线闭环性能
    set_simulator_seed(route.seed)
    baseline_metrics = run_closed_loop_simulation(agent, route, baseline_instruction)
    
    results = {}
    perturbation_families = ['Paraphrase', 'Ambiguity', 'Noise', 'Misleading']
    
    # 2. 遍历四种反事实扰动家族
    for family in perturbation_families:
        family_metrics = []
        # 基于规则模板生成 K 个反事实指令变体
        variants = generate_variants(baseline_instruction, templates[family], K=8)
        
        for variant_instruction in variants:
            # 3. 每次测试前重置环境，确保唯一变量是输入指令
            set_simulator_seed(route.seed)
            metrics = run_closed_loop_simulation(agent, route, variant_instruction)
            family_metrics.append(metrics)
            
        # 4. 计算该家族的平均性能，并求取相对于基线的性能差 (Delta)
        avg_metrics = compute_average(family_metrics)
        delta_metrics = {
            'Delta_DS': avg_metrics['DS'] - baseline_metrics['DS'],
            'Delta_RC': avg_metrics['RC'] - baseline_metrics['RC'],
            'Delta_IS': avg_metrics['IS'] - baseline_metrics['IS']
        }
        results[family] = delta_metrics
        
    return results
```

### 第二模块：核心架构解释

UA-ToM 的核心逻辑是不改变现有的 VLA 控制骨干，而是将其提取的潜在特征 $z_t$ 引入一个并行的信念追踪模块。该模块通过四条独立的信息路径处理时序数据，最后通过门控机制融合，输出协作者的类型、行为突变概率以及预测动作。

3.  **预测误差 (Prediction Error)：** 计算模型预测的协作者动作与实际动作的残差 $e_t$。这是触发 SSM 状态剧烈更新（突变检测）的最直接物理信号。
4.  **对比记忆 (Contrastive Memory)：** 维护不同行为类型的指数移动平均（EMA）原型，计算当前信念与原型的余弦相似度，提供分类线索。

**核心前向传播伪代码 (Python 风格):**

```python
def UA_ToM_forward(z_t, b_prev, h_prev, a_c_actual, memory_prototypes, history_z):
    """
    z_t: 冻结 VLA 提取的当前帧特征
    b_prev: 上一步的信念状态
    h_prev: 上一步的融合隐藏状态
    a_c_actual: 协作者在 t 步的真实动作
    """
    
    # 1. Selective SSM Pathway (核心信念演化)
    delta_t = softplus(Linear_W(z_t) + d) # 实际收敛至 ~0.78
    A_bar = exp(delta_t * A)
    B_bar = delta_t * B
    b_t = A_bar * b_prev + B_bar * z_t
    
    # 2. Causal Attention Pathway (短期重锚定)
    # Q 来自当前信念，K, V 来自历史特征窗口
    c_t = CausalAttention(Q=b_t, K=history_z, V=history_z)
    
    # 3. Prediction Error Pathway (突变触发信号)
    # 假设有一个轻量头从 b_t 预测协作者动作
    a_c_pred = ActionHead(b_t) 
    e_t = norm(a_c_pred - a_c_actual)
    
    # 4. Contrastive Memory Pathway (类型原型匹配)
    sim_scores = cosine_similarity(b_t, memory_prototypes)
    
    # 5. Gated Fusion (证据融合)
    # 将四路信号拼接，计算门控权重 g_t
    concat_features = concat([b_t, c_t, e_t, sim_scores])
    g_t = sigmoid(Linear_Wg(concat_features))
    
    # 融合当前特征与历史隐藏状态
    h_tilde = Linear_H(concat_features)
    h_t = g_t * h_tilde + (1 - g_t) * h_prev
    
    # 6. Output Heads
    type_logits = TypeHead(h_t)       # 预测协作者类型
    switch_prob = SwitchHead(h_t)     # 预测是否发生突变
    
    return type_logits, switch_prob, a_c_pred, b_t, h_t
```

### 第二模块：核心架构解释

LSE-MTP 的核心思想是在标准的多 Token 预测（MTP）架构上，增加对潜在空间轨迹的直接正则化。其训练流程分为前向传播与三分支损失计算，推理时则完全丢弃辅助层，退化为标准自回归生成，实现零额外推理成本。

**运行流程：**
1.  **主干特征提取:** 输入序列经过标准 Transformer 主干网络，输出当前时间步的真实隐藏状态（Teacher-forced hidden states）。
2.  **多步潜在投影:** 对于未来第 $k$ 步的预测，使用特定的过渡层（Transition Layers）将当前隐藏状态投影为预测的未来潜在状态。
3.  **三重视角监督 (Loss 计算):**
    *   *交叉熵损失 (CE):* 将预测的潜在状态映射回词表，与真实的未来离散 Token 计算标准 MTP 损失。
    *   *潜在一致性损失 (Latent Consistency):* 计算预测的潜在状态与主干网络在未来时间步实际生成的真实隐藏状态之间的均方误差（MSE）。
    *   *语义锚定损失 (Semantic Anchoring):* 计算预测的潜在状态与目标 Token 的静态词嵌入向量之间的均方误差（MSE）。

```python
    # 1. 获取主干网络真实的隐藏状态 (Teacher-forced)
    # H shape: [batch_size, seq_len, hidden_dim]
    H = backbone(inputs) 
    
    # 2. 计算标准的 Next-Token Prediction (1TP) 损失
    logits_1 = shared_head(H)
    loss_total = F.cross_entropy(logits_1.view(-1, vocab_size), targets.view(-1))
    
    # 3. 遍历多步预测 (从第 2 步到第 K 步)
    for k in range(2, K + 1):
        # 获取第 k 步的目标 Token
        target_k = targets[:, k-1:] 
        
        # 使用第 k-1 个过渡层预测未来的潜在状态
        # h_hat_k shape: [batch_size, seq_len - k + 1, hidden_dim]
        h_hat_k = transition_layers[k-2](H[:, :-k+1]) 
        
        # --- 损失 1: 标准 MTP 交叉熵损失 ---
        logits_k = shared_head(h_hat_k)
        loss_ce = F.cross_entropy(logits_k.view(-1, vocab_size), target_k.view(-1))
        
        # --- 损失 2: 潜在一致性损失 (Latent Consistency) ---
        # 截取对应的真实未来隐藏状态
        h_true_future = H[:, k-1:].detach() 
        loss_latent = F.mse_loss(h_hat_k, h_true_future)
        
        # --- 损失 3: 语义锚定损失 (Semantic Anchoring) ---
        # 获取目标 Token 的静态 Embedding
        e_target = embedding_layer(target_k).detach()
        loss_semantic = F.mse_loss(h_hat_k, e_target)
        
        # 累加总损失
        loss_total += loss_ce + lambda_l * loss_latent + lambda_s * loss_semantic
        
    return loss_total
```

### 第二模块：核心架构解释

GameAD 的整体架构从多视角图像输入到最终轨迹输出，构建了一条显式的“风险传递”链路。其核心流程分为四个阶段：

1. **Risk-Aware Topology Anchoring (RTA)**: 打破感知端检测与建图分支的结构性隔离。将在线重建的地图拓扑元素（如车道线）单向注入到目标检测的 Query 空间中，生成对几何位置敏感的检测表征，确保感知网络优先关注潜在冲突区域内的目标。
2. **Strategic Payload Adapter (SPA)**: 将自车运动状态、Top-K 智能体特征和地图约束拼接成统一的场景序列。将静态的候选轨迹模板映射为 Trajectory Query，通过交叉注意力机制与场景序列交互，生成具备场景感知能力的初始轨迹表征。
3. **Minimax Risk-Aware Sparse Attention (MRSA)**: 这是整个架构的灵魂。计算自车每条规划轨迹与周围智能体在所有预测模式和时间步下的最坏情况碰撞风险（结合 TTC 与欧氏距离）。选出风险最高的 Top-M 个智能体构建稀疏掩码，并将归一化后的风险矩阵作为偏置项（Bias）直接加到注意力计算的 Logits 中。
4. **Risk-Consistent Equilibrium Stabilization (RCES)**: 针对帧间规划容易出现的策略震荡问题，利用 Hausdorff 距离将当前轨迹提案与历史策略进行全局匹配对齐，并引入自车高级指令作为门控信号，确保轨迹在时间维度上的纳什均衡与平滑过渡。

```python
import torch
import torch.nn.functional as F

def calculate_ttc_risk(ego_pos, ego_vel, agent_pos, agent_vel, epsilon=1e-3, sigma=8.0, tau=1.0):
    """计算基于TTC和距离的瞬时碰撞风险"""
    p_rel = agent_pos - ego_pos
    v_rel = agent_vel - ego_vel
    
    distance = torch.norm(p_rel, dim=-1)
    # 避免除零，计算 TTC
    ttc = distance / torch.clamp(-(p_rel * v_rel).sum(-1) / distance, min=0) + epsilon
    
    # 联合指数函数计算风险值
    risk = torch.exp(-ttc / tau) * torch.exp(-distance / sigma)
    return risk

def minimax_risk_aware_sparse_attention(traj_queries, agent_tokens, ego_states, agent_states, M=4):
    """
    MRSA 核心机制：极小极大风险稀疏注意力
    traj_queries: [P, D] (P为规划模式数)
    agent_tokens: [K, D] (K为智能体数)
    """
    P, K = traj_queries.shape[0], agent_tokens.shape[0]
    
    # 1. Risk Matrix Computation (Minimax over time and agent modes)
    # 假设 ego_states 和 agent_states 包含了所有时间步 T 和模式 A 的预测
    raw_risk = calculate_ttc_risk(ego_states, agent_states) # [P, K, A, T]
    
    # 在智能体意图模式(A)和时间步(T)上取最大值，代表最坏情况下的对抗博弈
    worst_case_risk = raw_risk.max(dim=-1)[0].max(dim=-1)[0] # [P, K]
    
    # 结合检测置信度
    det_scores = get_detection_scores() # [K]
    risk_matrix = worst_case_risk * torch.clamp(det_scores, 0, 1) # [P, K]
    
    # 2. Sparse Game Graph Construction (Top-M Selection)
    # 为每个规划模式 P 选出风险最高的 M 个智能体
    top_m_risk, top_m_indices = torch.topk(risk_matrix, k=M, dim=-1) # [P, M]
    
    # 归一化风险矩阵到 [0, 1]
    risk_min = top_m_risk.min(dim=-1, keepdim=True)[0]
    risk_max = top_m_risk.max(dim=-1, keepdim=True)[0]
    normalized_risk = (top_m_risk - risk_min) / (risk_max - risk_min + 1e-6) # [P, M]
    
    # 3. Risk-Aware Sparse Attention
    # 提取 Top-M 的 agent tokens
    selected_agents = gather_tokens(agent_tokens, top_m_indices) # [P, M, D]
    
    Q = linear_q(traj_queries).unsqueeze(1) # [P, 1, D]
    K_proj = linear_k(selected_agents)      # [P, M, D]
    V_proj = linear_v(selected_agents)      # [P, M, D]
    
    # 计算标准 Attention Logits
    logits = torch.matmul(Q, K_proj.transpose(-1, -2)) / math.sqrt(D) # [P, 1, M]
    
    # 注入对抗风险先验 (beta 为可学习参数)
    beta = get_beta_parameter()
    logits_risk = logits + beta * normalized_risk.unsqueeze(1)
    
    # Softmax 与 Value 聚合
    attn_weights = F.softmax(logits_risk, dim=-1)
    refined_queries = torch.matmul(attn_weights, V_proj).squeeze(1) # [P, D]
    
    return FFN(LayerNorm(refined_queries + traj_queries))
```
