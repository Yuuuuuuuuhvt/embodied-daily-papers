### 第二模块：核心架构解释

BICPO-VLA 的底层逻辑建立在“行为-动作纤维（Behavior-Conditioned Action Fiber）”的数学抽象上，即将动作生成解耦为三个严格有序的阶段：语义对齐、结构化生成、交接偏好对齐。

**1. 指令感知的行为识别 (Instruction-Grounded Behavior Identification)**
视觉 Token 必须先通过指令文本进行交叉注意力路由，过滤掉与当前指令无关的视觉干扰，然后再与历史动作状态进行因果融合。这一步输出了冻结的“行为条件”，确保后续的平滑操作不会改变机器人的任务意图（例如防止为了平滑而选择“不作为”）。

**2. 基于交接条件的 Haar 动作实现 (Handoff-Conditioned Haar Realization)**
利用已知的系统延迟 $k$，模型通过确定性动力学前向推演正在执行的旧动作，计算出新动作真正接管时的物理状态 $g_k$。随后，利用一阶 Haar 正交变换，将目标动作块分解为两两相邻动作的均值（Scaffold，运动骨架）和差值（Residual，局部残差）。生成时，先条件化生成骨架，再基于骨架生成残差，实现 100% 无损重建。

**3. 行为一致的连续性偏好优化 (Behavior-Identified Continuation Preference Optimization)**
在离线训练阶段，针对同一个行为条件注入不同的流匹配（Flow Matching）噪声，生成多个候选动作块。计算这些候选动作块在交接点 $k$ 处的零阶位置跳变（Zero-order jump）和一阶趋势不匹配（First-order trend mismatch）。将成本低的作为 Chosen，成本高的作为 Rejected，应用 Reference-relative Flow-DPO 更新流策略网络，同时完全冻结语义编码器。

```python
import torch.nn.functional as F

def haar_transform(action_chunk):
    # action_chunk: [H, action_dim]
    # 提取偶数和奇数步动作
    a_even = action_chunk[0::2]
    a_odd = action_chunk[1::2]
    
    # 计算 Scaffold (C) 和 Residual (D)
    C = (a_even + a_odd) / 1.414
    D = (a_even - a_odd) / 1.414
    return C, D

def inverse_haar_transform(C, D):
    a_even = (C + D) / 1.414
    a_odd = (C - D) / 1.414
    # 交织重构原始动作
    action_chunk = torch.empty((C.shape[0]*2, C.shape[1]))
    action_chunk[0::2] = a_even
    action_chunk[1::2] = a_odd
    return action_chunk

def compute_handoff_cost(outgoing_actions, candidate_chunk, k):
    # outgoing_actions: 正在执行的旧动作块
    # candidate_chunk: 新生成的动作块
    # k: 延迟步数
    
    # 零阶位置跳变 (Zero-order jump)
    a_0 = candidate_chunk[0]
    u_k_minus_1 = outgoing_actions[k-1]
    jump_cost = torch.norm(a_0 - u_k_minus_1, p=2)
    
    # 一阶趋势不匹配 (First-order trend mismatch)
    trend_new = a_0 - u_k_minus_1
    trend_old = u_k_minus_1 - outgoing_actions[k-2]
    trend_cost = torch.norm(trend_new - trend_old, p=2)
    
    return jump_cost + trend_cost

    delta_policy = energy_policy_rejected - energy_policy_chosen
    delta_ref = energy_ref_rejected - energy_ref_chosen
    delta_theta = delta_policy - delta_ref
    
    # DPO 损失 (能量越低越好)
    loss_pref = -F.logsigmoid(beta * delta_theta)
    return loss_pref
```

**1. 基础动作生成**
系统首先使用预训练的扩散策略生成多个候选的短视距动作块（Action Chunks）。这些动作块包含了机器人未来几步的具体关节或末端执行器指令。

**2. 底层安全引导（Low-Level Guidance）**
针对每一个候选动作块，底层世界模型（一个单步状态转移模型）预测其导致的即时连续状态变化。系统基于预测出的物理状态，计算信号时序逻辑（STL）的鲁棒性得分（即距离违反安全约束的物理裕度）。通过对该得分求导，系统获得一个梯度信号，在扩散模型的去噪过程中直接更新动作块，迫使其避开不安全区域。

**3. 高层任务引导（High-Level Guidance）**
经过安全微调的动作块被送入高层世界模型。高层模型不预测具体的物理坐标，而是预测未来轨迹中离散“原子命题”（如“抽屉已关”、“开关已开”）的概率分布。系统将这些概率分布映射到目标 LTL 自动机的状态转移矩阵中，计算出执行该动作块后，系统向自动机接受态（任务完成态）推进的期望累积势能。

**4. 动作执行与闭环**
系统在所有候选动作块中，选择高层期望累积势能最高的一个。机器人执行该动作块的前几步，随后获取新观测，重复上述整个重规划流程。

```python
    # 1. 从无条件扩散策略中采样多个初始噪声动作块
    noisy_action_chunks = sample_initial_noise(batch_size=32)
    
    # 2. 扩散去噪过程与底层安全引导
    for t in reversed(range(diffusion_steps)):
        # 预测去噪动作
        action_chunks = diffusion_policy.denoise(noisy_action_chunks, t)

        predicted_states = low_level_wm.rollout(current_state, action_chunks)
        
        # 计算 STL 安全鲁棒性得分并求梯度
        safety_score = compute_stl_robustness(predicted_states, safety_spec)
        safety_gradient = compute_gradient(safety_score, action_chunks)
        
        # 使用安全梯度更新动作块 (Equation 3 Low-Level term)
        action_chunks = action_chunks + lambda_weight * safety_gradient
        noisy_action_chunks = add_noise(action_chunks, t-1)
        
    clean_action_chunks = action_chunks
    
    # 3. 高层任务引导
    best_score = -infinity
    best_action = None
    
    for chunk in clean_action_chunks:
        # 高层世界模型预测离散命题的概率分布
        proposition_probs = high_level_wm.predict_propositions(current_state, chunk)
        
        # 计算在 LTL 自动机上的期望累积势能 (Equation 3 High-Level term)
        automaton_potential = compute_expected_potential(automaton_state, proposition_probs, ltl_spec)
        
        if automaton_potential > best_score:
            best_score = automaton_potential
            best_action = chunk
            
    # 4. 返回得分最高的动作块用于执行
    return best_action
```

### 第二模块：核心架构解释

ART 的核心架构本质上是一个**两阶段解耦推理流水线**。它通过对模型权重的动态干预，在同一个 Transformer 架构内实现了离散语义决策与连续物理控制的隔离。

**运行流程**：
1. **观测输入**：接收原始的、可能带有噪声或视角偏移的观测图像及语言指令。
2. **工具推理阶段（LoRA 激活）**：将原始观测输入 VLA 模型。此时附加的 LoRA 模块处于激活状态。模型进行自回归生成，输出思维链推理文本以及特定的“工具调用 Token”（如 `<tool use: low_light_enhance>`）。
3. **工具执行阶段**：系统拦截这些离散的工具 Token，调用预定义的外部 API（分为视觉增强、启示增强、具身状态重置三类），对原始观测进行处理，生成“增强观测”（Enhanced Observation）。
4. **动作生成阶段（LoRA 屏蔽）**：将增强后的观测重新输入 VLA 模型。此时，系统在底层屏蔽/卸载 LoRA 模块的输出，使模型回退到预训练的纯净状态。模型基于干净的增强观测，预测出未来的连续动作块（Action Chunk）。

```python
class ART_VLA_Model:
    def __init__(self, base_vla, lora_module, tool_library):
        self.base_vla = base_vla          # 冻结的预训练 VLA 主干
        self.lora = lora_module           # 仅用于工具推理微调的 LoRA
        self.tools = tool_library         # 外部工具集 (API)
        
    def forward_inference(self, raw_obs, instruction):
        # 阶段 1: 激活 LoRA 进行工具推理
        self.enable_lora()
        
        # 生成推理文本和离散的工具调用 Tokens
        reasoning_text, tool_tokens = self.generate_text(raw_obs, instruction)
        
        # 阶段 2: 执行外部工具，增强观测
        enhanced_obs = raw_obs
        for token in tool_tokens:
            if token in self.tools:
                # 例如：调用目标检测、低照度增强或深度估计
                enhanced_obs = self.tools[token].execute(enhanced_obs, instruction)
                
        # 阶段 3: 屏蔽 LoRA，进行纯净的动作生成
        self.disable_lora()
        
        # 基于增强后的干净观测，预测连续动作块 (Action Chunk)
        # 避免了 LoRA 权重对底层连续控制空间的污染
        action_chunk = self.generate_action_chunk(enhanced_obs, instruction)
        
        return action_chunk

    def enable_lora(self):
        self.lora.active = True
        
    def disable_lora(self):
        self.lora.active = False
```

### 第二模块：核心架构解释

BICPO-VLA 的底层逻辑建立在“行为-动作纤维（Behavior-Conditioned Action Fiber）”的数学抽象上，即将动作生成解耦为三个严格有序的阶段：语义对齐、结构化生成、交接偏好对齐。

**1. 指令感知的行为识别 (Instruction-Grounded Behavior Identification)**
视觉 Token 必须先通过指令文本进行交叉注意力路由，过滤掉与当前指令无关的视觉干扰，然后再与历史动作状态进行因果融合。这一步输出了冻结的“行为条件”，确保后续的平滑操作不会改变机器人的任务意图（例如防止为了平滑而选择“不作为”）。

**2. 基于交接条件的 Haar 动作实现 (Handoff-Conditioned Haar Realization)**
利用已知的系统延迟 $k$，模型通过确定性动力学前向推演正在执行的旧动作，计算出新动作真正接管时的物理状态 $g_k$。随后，利用一阶 Haar 正交变换，将目标动作块分解为两两相邻动作的均值（Scaffold，运动骨架）和差值（Residual，局部残差）。生成时，先条件化生成骨架，再基于骨架生成残差，实现 100% 无损重建。

**3. 行为一致的连续性偏好优化 (Behavior-Identified Continuation Preference Optimization)**
在离线训练阶段，针对同一个行为条件注入不同的流匹配（Flow Matching）噪声，生成多个候选动作块。计算这些候选动作块在交接点 $k$ 处的零阶位置跳变（Zero-order jump）和一阶趋势不匹配（First-order trend mismatch）。将成本低的作为 Chosen，成本高的作为 Rejected，应用 Reference-relative Flow-DPO 更新流策略网络，同时完全冻结语义编码器。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn.functional as F

def haar_transform(action_chunk):
    # action_chunk: [H, action_dim]
    # 提取偶数和奇数步动作
    a_even = action_chunk[0::2]
    a_odd = action_chunk[1::2]
    
    # 计算 Scaffold (C) 和 Residual (D)
    C = (a_even + a_odd) / 1.414
    D = (a_even - a_odd) / 1.414
    return C, D

def inverse_haar_transform(C, D):
    a_even = (C + D) / 1.414
    a_odd = (C - D) / 1.414
    # 交织重构原始动作
    action_chunk = torch.empty((C.shape[0]*2, C.shape[1]))
    action_chunk[0::2] = a_even
    action_chunk[1::2] = a_odd
    return action_chunk

def compute_handoff_cost(outgoing_actions, candidate_chunk, k):
    # outgoing_actions: 正在执行的旧动作块
    # candidate_chunk: 新生成的动作块
    # k: 延迟步数
    
    # 零阶位置跳变 (Zero-order jump)
    a_0 = candidate_chunk[0]
    u_k_minus_1 = outgoing_actions[k-1]
    jump_cost = torch.norm(a_0 - u_k_minus_1, p=2)
    
    # 一阶趋势不匹配 (First-order trend mismatch)
    trend_new = a_0 - u_k_minus_1
    trend_old = u_k_minus_1 - outgoing_actions[k-2]
    trend_cost = torch.norm(trend_new - trend_old, p=2)
    
    return jump_cost + trend_cost

def flow_dpo_loss(policy_model, ref_model, condition, chosen_chunk, rejected_chunk):
    # 冻结语义条件
    with torch.no_grad():
        semantic_feat = ref_model.encode_semantics(condition)
    
    # 计算 Flow Matching 能量 (误差)
    def get_energy(model, chunk):
        C, D = haar_transform(chunk)
        noise_C, noise_D = sample_noise()
        # 顺序生成误差
        pred_v_C = model.forward_scaffold(noise_C, semantic_feat)
        pred_v_D = model.forward_residual(noise_D, semantic_feat, C)
        return mse(pred_v_C, target_v_C) + mse(pred_v_D, target_v_D)
    
    # 策略网络能量
    energy_policy_chosen = get_energy(policy_model, chosen_chunk)
    energy_policy_rejected = get_energy(policy_model, rejected_chunk)
    
    # 参考网络能量
    with torch.no_grad():
        energy_ref_chosen = get_energy(ref_model, chosen_chunk)
        energy_ref_rejected = get_energy(ref_model, rejected_chunk)
    
    # 计算相对偏好差值
    delta_policy = energy_policy_rejected - energy_policy_chosen
    delta_ref = energy_ref_rejected - energy_ref_chosen
    delta_theta = delta_policy - delta_ref
    
    # DPO 损失 (能量越低越好)
    loss_pref = -F.logsigmoid(beta * delta_theta)
    return loss_pref
```

### 第二模块：核心架构解释

hint$^2$ 的核心架构建立在一个预训练的无条件扩散策略（Diffusion Policy）之上，通过引入两个不同抽象层级的世界模型，在推理期（Inference-Time）对采样的动作块进行干预和筛选。

**1. 基础动作生成**
系统首先使用预训练的扩散策略生成多个候选的短视距动作块（Action Chunks）。这些动作块包含了机器人未来几步的具体关节或末端执行器指令。

**2. 底层安全引导（Low-Level Guidance）**
针对每一个候选动作块，底层世界模型（一个单步状态转移模型）预测其导致的即时连续状态变化。系统基于预测出的物理状态，计算信号时序逻辑（STL）的鲁棒性得分（即距离违反安全约束的物理裕度）。通过对该得分求导，系统获得一个梯度信号，在扩散模型的去噪过程中直接更新动作块，迫使其避开不安全区域。

**3. 高层任务引导（High-Level Guidance）**
经过安全微调的动作块被送入高层世界模型。高层模型不预测具体的物理坐标，而是预测未来轨迹中离散“原子命题”（如“抽屉已关”、“开关已开”）的概率分布。系统将这些概率分布映射到目标 LTL 自动机的状态转移矩阵中，计算出执行该动作块后，系统向自动机接受态（任务完成态）推进的期望累积势能。

**4. 动作执行与闭环**
系统在所有候选动作块中，选择高层期望累积势能最高的一个。机器人执行该动作块的前几步，随后获取新观测，重复上述整个重规划流程。

```python
    # 1. 从无条件扩散策略中采样多个初始噪声动作块
    noisy_action_chunks = sample_initial_noise(batch_size=32)

    for t in reversed(range(diffusion_steps)):
        # 预测去噪动作
        action_chunks = diffusion_policy.denoise(noisy_action_chunks, t)

        predicted_states = low_level_wm.rollout(current_state, action_chunks)

        safety_score = compute_stl_robustness(predicted_states, safety_spec)
        safety_gradient = compute_gradient(safety_score, action_chunks)
        
        # 使用安全梯度更新动作块 (Equation 3 Low-Level term)
        action_chunks = action_chunks + lambda_weight * safety_gradient
        noisy_action_chunks = add_noise(action_chunks, t-1)
        
    clean_action_chunks = action_chunks
    
    # 3. 高层任务引导
    best_score = -infinity
    best_action = None
    
    for chunk in clean_action_chunks:
        # 高层世界模型预测离散命题的概率分布
        proposition_probs = high_level_wm.predict_propositions(current_state, chunk)
        
        # 计算在 LTL 自动机上的期望累积势能 (Equation 3 High-Level term)
        automaton_potential = compute_expected_potential(automaton_state, proposition_probs, ltl_spec)
        
        if automaton_potential > best_score:
            best_score = automaton_potential
            best_action = chunk
            
    # 4. 返回得分最高的动作块用于执行
    return best_action
```

1. **多帧视觉特征提取与时序融合**：输入多视角的历史连续图像，使用融合的 ViT（DINOv2 + SigLIP）提取特征。为了避免多帧带来的计算爆炸，模型仅在视觉编码器的中间层特征上应用因果注意力机制（Causal Attention）进行时序融合，捕获局部运动信息，随后将融合后的残差加到当前帧的最终层特征上。语言模型仅接收当前帧的视觉 Token。
2. **潜在未来预测（仅训练阶段）**：在多模态输入序列末尾追加与动作块大小（Chunk Size）相同数量的 Learnable Future Tokens。语言模型输出这些 Token 的隐藏状态后，通过一个预测头将其投影到 DINOv3 的特征空间。训练时，计算该预测特征与真实未来帧经过冻结 DINOv3 提取的特征之间的余弦相似度损失。
3. **动作生成**：通过连续回归头输出 Action Chunk。
4. **系统级推理优化（仅部署阶段）**：将多视角、多帧的图像输入合并为单次 Batch 前向传播；使用 CUDA Graph 捕获整个推理计算图并直接回放，消除内核调度开销。

**核心伪代码实现**：

```python
def reflex_vla_forward(images_history, text_tokens, action_queries, future_images=None):
    # images_history: [Batch, Views, Time, C, H, W]
    B, V, T, C, H, W = images_history.shape
    
    # 1. 批处理视觉编码 (系统级优化，降低延迟)
    images_flat = images_history.view(B * V * T, C, H, W)
    feat_mid, feat_final = vision_encoder(images_flat) 
    
    feat_mid = feat_mid.view(B, V, T, P, D)
    feat_final = feat_final.view(B, V, T, P, D)
    
    # 2. 中间层多帧时序融合
    # 对时间维度 T 应用因果注意力，防止未来信息泄露
    feat_mid_norm = down_proj(layer_norm(feat_mid)) + pos_embed
    temporal_delta = up_proj(causal_self_attention(feat_mid_norm))
    
    # 将时序运动信息注入到当前帧 (T时刻) 的最终特征中
    current_visual_tokens = feat_final[:, :, -1, :, :] + temporal_delta[:, :, -1, :, :]
    current_visual_tokens = current_visual_tokens.view(B, V * P, D)
    
    # 3. 语言模型前向传播
    # 拼接文本、当前帧视觉特征、动作查询Token、未来预测Token
    llm_inputs = concat(text_tokens, current_visual_tokens, action_queries, future_tokens)
    llm_outputs = llm(llm_inputs)
    
    # 4. 动作预测
    action_chunk = action_head(llm_outputs.action_queries)
    loss = action_loss(action_chunk, ground_truth_actions)
    
    # 5. 潜在未来预测 (仅训练阶段计算辅助损失)
    if future_images is not None:
        with torch.no_grad():
            # 使用冻结的 DINOv3 提取真实未来帧的语义特征
            target_future_features = frozen_dinov3(future_images)
        
        pred_future_features = prediction_head(llm_outputs.future_tokens)
        loss_future = masked_cosine_similarity_loss(pred_future_features, target_future_features)
        
        # 联合优化
        loss = loss + lambda_future * loss_future
        
    return action_chunk, loss
```

### 第二模块：核心架构解释

Twin 框架的核心是一个被称为 Validate-Explore-Plan 的闭环。系统不直接让大模型输出动作，而是让大模型（Coding Agent）编写一个 Python 脚本（`model.py`），该脚本包含状态转移函数（物理规律）和目标判定函数（胜利条件）。

**运行流程拆解**：
1. **初始化**：带着一个空的交互日志和一个空白的 Python 世界模型进入游戏。
2. **验证 (Validate)**：系统强制要求当前的 Python 模型必须能完美重放日志中记录的每一次历史交互。如果预测帧与历史真实帧有任何像素级差异，则生成 Bug 报告。
3. **探索与修复 (Explore)**：
   - **动力学墙 (Dynamics Wall)**：如果验证失败，大模型根据 Bug 报告修改 Python 代码，直到完美拟合历史。
   - **目标墙 (Goal Wall)**：如果验证通过但找不到通关路径，系统会在代码模型内进行广度优先搜索（BFS），寻找具有显著视觉变化（如颜色消失、局部突变）的状态，大模型据此编写一个“假设目标”函数。
4. **规划 (Plan)**：在验证通过的 Python 模型中，搜索到达“假设目标”的最短路径。
5. **执行 (ExecuteChecked)**：在真实游戏中逐步执行计划。每执行一步，都会对比真实观测与代码预测。一旦出现不匹配（Mismatch），立即停止执行，将新数据加入日志，打回“验证”环节进行模型修复。

**核心伪代码实现**：

```python
def twin_agent_loop(env):
    world_model = IdentityModel() # 初始为空模型
    interaction_log = []          # 记录 (state, action, next_state)
    
    while not env.is_completed():
        current_state = env.perceive()
        
        # 1. Validate & Repair (动力学修复)
        while True:
            mismatches = validate_model_against_log(world_model, interaction_log)
            if not mismatches:
                break
            # LLM 根据错误样本修改 Python 世界模型代码
            world_model = llm_repair_dynamics(world_model, mismatches)
            
        # 2. Plan (在世界模型中规划)
        plan = bfs_plan(current_state, world_model.step, world_model.is_goal)
        
        # 3. Explore (目标发现)
        if plan is None:
            # 如果没有目标，寻找有显著变化的新颖状态作为假设目标
            candidate_state = find_novel_state_in_model(current_state, world_model)
            if candidate_state:
                world_model.is_goal = llm_propose_goal(candidate_state)
                plan = bfs_plan(current_state, world_model.step, world_model.is_goal)
            else:
                # 连新颖状态都找不到，执行一次探索性动作收集数据
                plan = [choose_informative_action()]
                
        # 4. ExecuteChecked (带校验的执行)
        for action in plan:
            predicted_state = world_model.step(current_state, action)
            actual_state, is_done = env.step(action)
            
            interaction_log.append((current_state, action, actual_state))
            current_state = actual_state
            
            if is_done:
                world_model.confirm_goal()
                break
                
            # 核心防御机制：一旦预测与现实不符，立即停止执行，回去修模型
            if actual_state != predicted_state:
                break 
```

3. **异构输出对齐与评估 (Heterogeneous Output Alignment & Evaluation)**：将不同 VLA 模型（如 OpenEMMA, LLaViDA）的自由文本输出映射到封闭语义槽，将异构轨迹统一到自车坐标系下的 1 秒窗口内。通过计算联合输出有效性（JOVR）、有效语义准确率（SemAcceff）、关键交互识别率（CIAeff）、轨迹质量（TQSR）和风险响应（RSR），最终加权得出 IVCS 分数。

```python
class SSPFramework:
    def __init__(self, vla_models, evaluators):
        self.vla_models = vla_models
        self.evaluators = evaluators
        
    def semantic_abstraction(self, synthetic_video):
        # 提取核心交互语义，生成时空交互图 K*
        topology, actors, motion, conflict, phases = extract_semantics(synthetic_video)
        interaction_graph = build_graph(topology, actors, motion, conflict, phases)
        return interaction_graph

    def cross_domain_compilation(self, interaction_graph):
        # 在仿真和物理域中重构事件
        sim_asset = compile_to_carla(interaction_graph)
        phy_asset = compile_to_proving_ground(interaction_graph)
        
        # 严格的转移审计：确保事件本质特征未改变
        assert self.audit_transfer(interaction_graph, sim_asset), "Simulation transfer failed"
        assert self.audit_transfer(interaction_graph, phy_asset), "Physical transfer failed"
        
        return {'Syn': synthetic_video, 'Sim': sim_asset.video, 'Phy': phy_asset.video}

    def evaluate_models(self, domain_videos, labels):
        results = {}
        for model in self.vla_models:
            for domain, video in domain_videos.items():
                # 1. 获取原生输出
                raw_text, raw_traj = model.inference(video, standard_prompt)
                
                # 2. 异构接口统一化
                parsed_slots = self.evaluators.parse_text_to_slots(raw_text)
                aligned_traj = self.evaluators.align_trajectory(raw_traj, window=1.0)
                
                # 3. 计算多维指标
                jovr = compute_validity(parsed_slots, aligned_traj)
                sem_acc = compute_semantic_accuracy(parsed_slots, labels)
                cia = compute_critical_interaction(parsed_slots, labels)
                tqsr = compute_trajectory_quality(aligned_traj, labels)
                rsr = compute_risk_response(aligned_traj, labels)
                
                # 4. 综合评分
                ivcs = 0.1*jovr + 0.3*sem_acc + 0.2*cia + 0.3*tqsr + 0.1*rsr
                results[(model.name, domain)] = ivcs
        return results
```

### 第二模块：核心架构解释

Marionette 的核心思想是实现动力学（Dynamics）与观测（Observation）的条件独立。整个系统流水线被严格切分为三个阶段：

**1. 两阶段动力学模型 (Two-stage Dynamics Model)**
负责在低维显式空间中推演物理世界。状态 $s$ 是一个 276 维的向量（包含实体的根节点位移、相对关节位置和 6D 旋转）。
- **ActionGPT (决策层)**: 一个小型因果 Transformer。接收历史状态和地形信息，自回归地预测下一个离散的动作 Token（如“攻击”、“闪避”）以及根节点的连续运动。这里是**用户控制信号注入**的唯一入口。
- **PoseGPT (动画层)**: 一个较大的因果 Transformer。接收 ActionGPT 输出的动作 Token 和根节点运动，将其转化为高维的连续 3D 身体姿态（关节位置）。

**2. 确定性图形桥 (Deterministic Graphics Bridge)**
一个没有任何可学习参数的纯几何计算模块。
- 接收预测的 3D 状态和预扫描的地形高度场。
- 强制执行物理规则（如将陷入地下的坐标强行拉回地面）。
- 将 3D 骨骼光栅化为一张“姿态控制图”。该图的 RGB 通道被巧妙地重定义为几何缓冲区：R通道代表高度，G通道代表关节/地形的分类 ID，B通道代表逆深度。

**3. 观测模型 (Observation Model)**
一个基于 Wan2.2 的控制条件视频扩散模型。
- 接收确定性图形桥输出的“姿态控制图”以及第一帧的 RGB 图像。
- 仅负责将几何结构渲染为逼真的光影和纹理（Photorealistic RGB）。

### 第二模块：核心架构解释

AdvDex 的核心架构分为数据输入、特征提取与对抗解耦、动作解码三个主要阶段。其本质是一个带有领域自适应（Domain Adaptation）能力的端到端视觉-语言-动作模型。

1. **统一动作空间映射 (JAAS)**：无论是人类演示视频、灵巧机械手还是平行夹爪的数据，其底层动作标签首先被统一映射到 JAAS 空间，即一个包含 SE(3) 腕部 6D 姿态和 15 个手指关节角度的规范化向量。
2. **视觉特征提取与域对抗 (Domain-Adversarial Learning)**：视觉编码器接收图像输入并提取特征。在此处分出两个分支：主分支用于后续的动作预测；对抗分支通过梯度反转层（GRL）连接一个域分类器（判断图像里是人手还是机械手）。在反向传播时，GRL 会将域分类器的梯度取反，迫使视觉编码器朝着“让域分类器猜错”的方向更新，从而剔除特征中的具身特定外观信息。
3. **多模态融合与动作输出**：清洗过具身信息的视觉特征与语言指令特征融合，输入到 VLA 骨干网络中，直接回归出 JAAS 空间下的动作向量，最后通过逆运动学（IK）或直接映射下发给底层控制器。

```python
import torch
import torch.nn as nn

# 梯度反转层，用于对抗学习
class GradientReversalLayer(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, alpha):
        ctx.alpha = alpha
        return x.view_as(x)
    
    @staticmethod
    def backward(ctx, grad_output):
        # 反向传播时梯度取反，迫使特征提取器混淆具身身份
        return grad_output.neg() * ctx.alpha, None

def grl(x, alpha=1.0):
    return GradientReversalLayer.apply(x, alpha)

class AdvDex(nn.Module):
    def __init__(self):
        super().__init__()
        self.visual_encoder = VisionModel() 
        self.language_encoder = LanguageModel()
        self.action_head = ActionHead() # 输出 SE(3) + 15 DoF 的 JAAS 动作
        self.domain_discriminator = DomainClassifier() # 二分类：人类 vs 机器人

    def forward(self, image, text, alpha=1.0):
        # 1. 提取视觉与语言特征
        v_feat = self.visual_encoder(image)
        l_feat = self.language_encoder(text)

        # 2. VLA 策略主分支：预测 JAAS 规范动作
        fused_feat = fuse_features(v_feat, l_feat)
        pred_action = self.action_head(fused_feat)

        # 3. 域对抗分支：剥离具身特征
        reversed_v_feat = grl(v_feat, alpha)
        pred_domain = self.domain_discriminator(reversed_v_feat)

        return pred_action, pred_domain

# 损失函数计算
def compute_loss(pred_action, gt_action, pred_domain, gt_domain):
    # 动作回归损失 (主线任务)
    action_loss = mse_loss(pred_action, gt_action)
    
    # 域分类损失 (对抗任务)
    # 最小化此损失会训练判别器，但由于 GRL 的存在，会最大化视觉编码器的域混淆程度
    domain_loss = cross_entropy_loss(pred_domain, gt_domain)

    total_loss = action_loss + domain_loss
    return total_loss
```

这是核心训练创新。构建正负样本对进行对比学习：
*   **正样本:** 真实的专家轨迹。
*   **合成负样本:** 目标错位的轨迹（Goal mismatch）和中间状态加噪但终点不变的轨迹（Endpoint-preserving perturbations）。
*   **闭环挖掘负样本:** 使用当前模型在环境中实际规划失败的轨迹。
通过 Logistic Loss 训练 LTC 网络，使其给正样本打低分，给负样本打高分。梯度不仅更新 LTC，还回传重塑编码器的特征空间。

**3. 轨迹感知规划 (Path-Aware Planning):**
在推理阶段，冻结世界模型。使用交叉熵方法（CEM）采样大量候选动作序列，自回归生成对应的隐式轨迹。最终的候选动作得分由两部分组成：传统的终点距离代价 + 经过校准的 LTC 轨迹代价。

```python
# --- Training Phase ---
def train_step(expert_traj, goal, encoder, predictor, ltc_model):
    # 1. Base LeWM Loss (Next-step prediction)
    latent_states = encoder(expert_traj.obs)
    pred_states = predictor(latent_states[:-1], expert_traj.actions)
    loss_pred = mse_loss(pred_states, latent_states[1:])
    
    # 2. Trajectory Preference Loss (LTC)
    latent_goal = encoder(goal)
    
    # Positive sample
    cost_pos = ltc_model(latent_states, latent_goal)
    
    # Synthetic Negative samples (e.g., mismatched goal, noisy intermediate states)
    neg_states_synthetic = generate_synthetic_negatives(latent_states)
    cost_neg_syn = ltc_model(neg_states_synthetic, latent_goal)
    
    # Mined Negative samples (from closed-loop execution failures)
    neg_states_mined = sample_from_failure_buffer()
    cost_neg_mined = ltc_model(neg_states_mined, latent_goal)
    
    # Pairwise Logistic Loss (Bradley-Terry model)
    loss_pref_syn = logistic_loss(cost_pos, cost_neg_syn)
    loss_pref_mined = logistic_loss(cost_pos, cost_neg_mined)
    
    # Total Loss (Gradients flow back to encoder through positive branch)
    total_loss = loss_pred + lambda_1 * loss_pref_syn + lambda_2 * loss_pref_mined
    total_loss.backward()
    update_weights()

# --- Planning Phase ---
def plan(current_obs, goal, encoder, predictor, ltc_model, num_candidates=300):
    latent_start = encoder(current_obs)
    latent_goal = encoder(goal)
    
    # CEM Sampling
    action_candidates = sample_cem_actions(num_candidates)
    
    best_score = infinity
    best_action = None
    
    for actions in action_candidates:
        # Autoregressive rollout in latent space
        predicted_trajectory = predictor.rollout(latent_start, actions)
        
        # 1. Endpoint Score (Distance from last predicted state to goal)
        endpoint_score = l2_distance(predicted_trajectory[-1], latent_goal)
        
        # 2. LTC Score (Evaluates the entire path)
        ltc_score = ltc_model(predicted_trajectory, latent_goal)
        
        # Joint Scoring
        total_score = endpoint_score + lambda_ltc * calibrate(ltc_score)
        
        if total_score < best_score:
            best_score = total_score
            best_action = actions[0] # Return first action for MPC
            
    return best_action
```

### 第二模块：核心架构解释

ForgeWM 的核心架构基于 DiT，包含独立的动作模块以处理离散（键盘）和连续（鼠标）输入。其核心创新在于将模型的训练和部署流程进行了高度解耦与渐进式重构。

训练流程分为四个阶段：
1. 阶段 0（双向适应）：使用全片段双向注意力机制，通过流匹配（Flow Matching）在目标游戏域上训练基础生成器，学习视觉和控制先验。
2. 阶段 1（教师强制因果训练）：将双向注意力替换为块级因果注意力（Block-wise causal attention），使用干净的历史数据进行因果流匹配训练，让模型适应因果执行模式。
3. 阶段 2（因果一致性初始化）：基于阶段 1 的权重，进行在线因果一致性蒸馏（Online Causal Consistency Distillation）。引入 EMA 模型和冻结的教师模型，使模型具备少步生成能力。
4. 阶段 3（同策略分布匹配）：学生模型进行自回归展开（使用自生成的历史），通过分布匹配蒸馏（DMD）向阶段 0 的真实分布对齐，最终产出 1、2、4 步的专属预算模型。

部署流程采用双路径协议：
1. 在线交互：使用 1 步或 2 步学生模型，保证极低延迟。
2. 离线回放精调：对已保存的低步数草稿进行受控重加噪，并使用更大步数（如 4 步）进行精调，提升画质且不改变原有轨迹。

```python
# ForgeWM 核心逻辑伪代码

class ForgeWM:
    def __init__(self, base_generator):
        self.generator = base_generator
        
    def stage_0_bidirectional_adaptation(self, clean_data):
        # 使用全片段双向注意力进行流匹配训练
        self.generator.set_attention_mode("bidirectional")
        loss = flow_matching_loss(self.generator, clean_data)
        return loss

    def stage_1_teacher_forced_causal(self, clean_data):
        # 切换为块级因果注意力，使用干净历史
        self.generator.set_attention_mode("causal")
        loss = causal_flow_matching_loss(self.generator, clean_data)
        return loss

    def stage_2_causal_consistency(self, clean_data, teacher_model):
        # 在线因果一致性蒸馏，初始化少步生成能力
        ema_model = update_ema(self.generator)
        loss = consistency_distillation_loss(self.generator, ema_model, teacher_model, clean_data)
        return loss

    def stage_3_on_policy_dmd(self, real_denoiser):
        # 同策略分布匹配，使用自生成历史
        self_generated_history = self.generator.autoregressive_rollout()
        fake_denoiser = self.generator
        loss = distribution_matching_loss(fake_denoiser, real_denoiser, self_generated_history)
        return loss

    def online_interaction(self, obs, actions, budget=1):
        # 在线低延迟推理，保存草稿
        draft_chunk = self.generator.denoise(obs, actions, steps=budget)
        return draft_chunk

    def replay_time_refinement(self, draft_chunk, actions, noise_level=0.3, refine_steps=4):
        # 离线回放精调：重加噪 + 多步去噪
        noisy_chunk = add_gaussian_noise(draft_chunk, noise_level)
        refined_chunk = self.generator.denoise(noisy_chunk, actions, steps=refine_steps)
        return refined_chunk
```
