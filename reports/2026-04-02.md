### 第二模块：核心架构解释

DVGT-2 的架构设计本质上是一个解耦了全局坐标系的流式时空 Transformer。其处理流程分为特征提取、时空融合与多任务解码三个阶段。

1.  **特征提取与 Token 构造:** 使用预训练的 DINOv3 提取当前帧多视角图像的视觉 Token，并拼接上可学习的 Pose Token 和 Trajectory Token，形成统一的输入表征。
2.  **滑动窗口流式几何 Transformer:** 包含 $L$ 个级联 Block。每个 Block 依次执行：
    *   *Intra-View Local Attention:* 提取单图内部细粒度特征。
    *   *Cross-View Spatial Attention:* 进行多相机视角的空间推理。
    *   *Temporal Causal Attention:* 将当前帧 Token 作为 Query，与固定长度 $W$ 的历史缓存（Cache）进行交互。此处使用 MRoPE-I 相对位置编码，确保历史特征在时间推移中保持平移不变性，无需重新计算。
3.  **多任务解码与缓存更新:** 视觉 Token 通过 DPT 头输出局部 3D 点云；Pose 和 Trajectory Token 通过截断扩散（Truncated Diffusion）头输出相对位姿和未来轨迹。最后，将当前帧的中间特征压入 FIFO 队列，剔除最老帧特征。

**核心逻辑伪代码 (Python Style):**

```python
class DVGT2(nn.Module):
    def __init__(self, window_size=4, num_blocks=24):
        super().__init__()
        self.W = window_size
        # 初始化固定大小的 FIFO 缓存
        self.cache = FIFOQueue(maxlen=window_size)
        self.image_encoder = DINOv3()
        self.geometry_transformer = GeometryTransformer(num_blocks)
        self.point_head = DPTHead()
        self.pose_head = DiffusionPoseHead()
        self.traj_head = DiffusionTrajectoryHead()

    def forward_online(self, current_multiview_images):
        # 1. 提取当前帧视觉特征
        vis_tokens = self.image_encoder(current_multiview_images)
        
        # 2. 拼接可学习的 Action & Pose 锚点
        input_tokens = concat([vis_tokens, self.pose_tokens, self.traj_tokens])
        
        # 3. 流式时空推理 (核心创新)
        # 仅计算当前帧与 Cache 的交互，复杂度 O(W)
        updated_tokens, current_layer_features = self.geometry_transformer(
            input_tokens, 
            historical_cache=self.cache.get_all() # 包含过去 W 帧的特征
        )
        
        # 4. 解码 (注意：全部在当前局部坐标系下进行)
        local_pointmap = self.point_head(updated_tokens.vis)
        relative_pose = self.pose_head(updated_tokens.pose) # 相对上一帧的位姿
        future_trajectory = self.traj_head(updated_tokens.traj)
        
        # 5. 更新滑动窗口缓存
        self.cache.push(current_layer_features)
        
        return local_pointmap, relative_pose, future_trajectory
```

*   **核心机制:** 彻底摒弃“以第一帧为全局坐标系”的传统设定。通过维护一个固定大小的 FIFO 历史特征缓存（Sliding Window），并结合相对时间位置编码（MRoPE-I），模型在每一帧仅预测**当前局部坐标系下的密集点云**和**相对上一帧的自车位姿**。这使得单帧推理复杂度降为常数 $\mathcal{O}(W)$，彻底打通了无限长视频流的实时推理。

**4. 关键数据:**
*   **核心有效性数据:** 在 OpenScene 数据集（16帧序列）上，DVGT-2 的单帧推理延迟仅为 **~0.27s**（相比 VGGT 的 ~5.31s 实现了质的飞跃），同时在局部射线深度（Ray Depth）指标上达到 SOTA（Abs Rel 0.040, $\delta<1.25$ 0.977）。在 NAVSIM v2 闭环测试中，EPDMS 达到 89.6，超越所有现有端到端方法。这证明了极速流式架构不仅没有牺牲局部几何精度，反而促进了规划性能。
*   **存疑/局限数据:** 在 KITTI 和 DDAD 数据集上，轨迹规划的 L2 误差显著偏高（>2.0m），且全局位姿预测（AUC）表现不佳。作者坦诚这是因为训练数据严重不平衡（OpenScene 占比超 75%），导致基于 Diffusion 的 Anchor 聚类对低速场景过拟合，无法泛化到 KITTI 的高速域；同时，局部相对位姿的累积不可避免地带来了全局坐标系下的轨迹漂移（Drift）。

### 第二模块：核心架构解释

DVGT-2 的架构设计本质上是一个解耦了全局坐标系的流式时空 Transformer。其处理流程分为特征提取、时空融合与多任务解码三个阶段。

1.  **特征提取与 Token 构造:** 使用预训练的 DINOv3 提取当前帧多视角图像的视觉 Token，并拼接上可学习的 Pose Token 和 Trajectory Token，形成统一的输入表征。
2.  **滑动窗口流式几何 Transformer:** 包含 $L$ 个级联 Block。每个 Block 依次执行：
    *   *Intra-View Local Attention:* 提取单图内部细粒度特征。
    *   *Cross-View Spatial Attention:* 进行多相机视角的空间推理。
    *   *Temporal Causal Attention:* 将当前帧 Token 作为 Query，与固定长度 $W$ 的历史缓存（Cache）进行交互。此处使用 MRoPE-I 相对位置编码，确保历史特征在时间推移中保持平移不变性，无需重新计算。
3.  **多任务解码与缓存更新:** 视觉 Token 通过 DPT 头输出局部 3D 点云；Pose 和 Trajectory Token 通过截断扩散（Truncated Diffusion）头输出相对位姿和未来轨迹。最后，将当前帧的中间特征压入 FIFO 队列，剔除最老帧特征。

**核心逻辑伪代码 (Python Style):**

```python
class DVGT2(nn.Module):
    def __init__(self, window_size=4, num_blocks=24):
        super().__init__()
        self.W = window_size
        # 初始化固定大小的 FIFO 缓存
        self.cache = FIFOQueue(maxlen=window_size)
        self.image_encoder = DINOv3()
        self.geometry_transformer = GeometryTransformer(num_blocks)
        self.point_head = DPTHead()
        self.pose_head = DiffusionPoseHead()
        self.traj_head = DiffusionTrajectoryHead()

    def forward_online(self, current_multiview_images):
        # 1. 提取当前帧视觉特征
        vis_tokens = self.image_encoder(current_multiview_images)
        
        # 2. 拼接可学习的 Action & Pose 锚点
        input_tokens = concat([vis_tokens, self.pose_tokens, self.traj_tokens])
        
        # 3. 流式时空推理 (核心创新)
        # 仅计算当前帧与 Cache 的交互，复杂度 O(W)
        updated_tokens, current_layer_features = self.geometry_transformer(
            input_tokens, 
            historical_cache=self.cache.get_all() # 包含过去 W 帧的特征
        )
        
        # 4. 解码 (注意：全部在当前局部坐标系下进行)
        local_pointmap = self.point_head(updated_tokens.vis)
        relative_pose = self.pose_head(updated_tokens.pose) # 相对上一帧的位姿
        future_trajectory = self.traj_head(updated_tokens.traj)
        
        # 5. 更新滑动窗口缓存
        self.cache.push(current_layer_features)
        
        return local_pointmap, relative_pose, future_trajectory
```

# 第二模块：核心架构解释

VLLR 的核心架构由外部语义奖励构建、内部自确定性奖励提取以及两阶段 PPO 优化流程三个主要部分构成。

**1. 外部语义奖励构建 (Extrinsic Reward)**
*   **任务分解**：输入全局场景图（Scene Graph）和高层自然语言指令，通过 LLM 生成有序的子目标序列。此步骤将长程任务转化为结构化的短程目标。
*   **进度评估**：在环境交互中，VLM 接收当前观测、上一帧观测及子目标序列，输出一个 $[0, 1]$ 的标量，表示当前任务的完成进度。
*   **抗幻觉平滑处理**：由于 VLM 存在视觉幻觉，会输出错误的进度尖峰（导致后续奖励被抑制）。系统在轨迹收集后、PPO 更新前，对进度序列应用滑动窗口中值滤波。只有当进度增量超过中值阈值时才予以采纳，并计算增量作为当前步的外部奖励。

**2. 内部自确定性奖励 (Intrinsic Reward)**
*   提取策略网络输出的离散动作概率分布。
*   计算该分布的负熵（即自确定性）。动作分布越集中，表明策略对其内部隐式世界模型的状态演化越自信，该值越高，作为每一步的密集内在奖励。

**3. 两阶段优化流程 (Two-Stage Optimization)**
*   **Stage I (价值初始化)**：仅使用 VLM 提供的外部进度奖励训练 Critic 网络（约 200K 步，占总训练量 <0.5%）。此阶段不更新 Actor，目的是将全局任务结构的先验知识注入价值函数。
*   **Stage II (策略微调)**：停止所有 VLM 查询。使用内部自确定性奖励和环境的稀疏任务成功奖励，通过标准 PPO 算法同时更新 Actor 和 Critic。

**核心逻辑伪代码实现**：

```python
import numpy as np
import torch

def compute_vlm_reward(progress_sequence, window_size=5, threshold=0.1):
    """
    Algorithm 1: 消除 VLM 幻觉的进度平滑与奖励计算
    """
    n = len(progress_sequence)
    smoothed_progress = np.zeros(n)
    rewards = np.zeros(n)
    running_max = 0.0
    
    # 步骤1: 滑动窗口中值滤波剔除异常尖峰
    for i in range(n):
        start = max(0, i - window_size)
        end = min(n, i + window_size + 1)
        window = progress_sequence[start:end]
        # 排除当前值计算中值
        window_without_current = np.delete(window, np.where(window == progress_sequence[i])[0][0])
        median_val = np.median(window_without_current) if len(window_without_current) > 0 else 0
        
        if progress_sequence[i] - median_val > threshold:
            smoothed_progress[i] = 0.0 # 判定为幻觉尖峰
        else:
            smoothed_progress[i] = progress_sequence[i]
            
    # 步骤2: 计算基于运行最大值的增量奖励
    for i in range(n):
        if smoothed_progress[i] > running_max:
            rewards[i] = smoothed_progress[i] - running_max
            running_max = smoothed_progress[i]
        else:
            rewards[i] = 0.0
            
    return rewards

def compute_self_certainty_reward(action_probs, action_space_size):
    """
    计算策略自确定性 (公式 1)
    """
    # action_probs shape: [batch_size, action_space_size]
    # RSC = - (1/|A|) * sum(log(|A| * pi(a)))
    scaled_probs = action_space_size * action_probs
    log_scaled_probs = torch.log(scaled_probs + 1e-8)
    self_certainty = - (1.0 / action_space_size) * torch.sum(log_scaled_probs, dim=-1)
    return self_certainty

def vllr_ppo_step(stage, actor_critic, batch_data, vlm_progress_seq=None):
    """
    两阶段优化逻辑 (公式 2)
    """
    obs, actions, sparse_task_reward = batch_data
    action_probs, state_values = actor_critic(obs)
    
    if stage == 1:
        # Stage I: 仅使用 VLM 奖励初始化 Value Function
        # 此时不进行策略梯度更新，仅做价值回归
        vlm_rewards = compute_vlm_reward(vlm_progress_seq)
        total_reward = vlm_rewards # alpha = 1
        update_critic_only(state_values, total_reward)
        
    elif stage == 2:
        # Stage II: 使用自确定性奖励 + 稀疏任务奖励进行 PPO 更新
        # 彻底摒弃 VLM 调用
        self_certainty_reward = compute_self_certainty_reward(action_probs, action_probs.shape[-1])
        
        # beta = 0.1, phi = 10
        total_reward = 0.1 * self_certainty_reward + 10.0 * sparse_task_reward
        
        # 标准 PPO 更新 Actor 和 Critic
        ppo_update(actor_critic, obs, actions, total_reward)
```

### 第二模块：核心架构解释

DLWM 的整体架构分为两个连续的预训练阶段，并在微调阶段接入下游任务头。

**阶段一：高斯表示学习 (Gaussian Representation Learning)**
模型接收多视角图像，通过图像编码器和特征金字塔提取多尺度特征。随后，使用高斯 Transformer 解码器初始化并细化 3D 高斯查询（包含位置、缩放、旋转、不透明度和语义）。该阶段通过可微渲染技术，将 3D 高斯投影为深度图和语义图，并与伪标签（由 Metric3D 和 Grounded SAM 生成）计算重建损失，迫使模型学习静态几何结构。

**阶段二：双潜在世界模型 (Dual Latent World Models)**
在冻结阶段一感知模块的基础上，并行训练两个独立的世界模型：
1. **高斯流引导模型 (Gaussian-flow-guided)**：针对感知和预测任务。模型预测每个 3D 高斯的局部动态位移（高斯流），结合自车运动对齐，将当前帧的高斯传播到下一帧。随后，将预测的下一帧 3D 高斯栅格化（Rasterize）为 2D BEV 特征，与真实的下一帧 BEV 特征计算 L2 损失。
2. **自车规划引导模型 (Ego-planning-guided)**：针对运动规划任务。将当前 3D 高斯栅格化为 BEV 特征并提取场景查询。通过交叉注意力预测自车未来轨迹。随后，利用运动感知层归一化（MLN），将预测的轨迹作为条件注入场景查询中，推演未来的 BEV 特征，并与真实 BEV 特征计算重建损失。

### 第二模块：核心架构解释

DreamControl-v2 的整体架构分为四个明确的客观执行阶段：数据预处理、扩散先验训练、轨迹生成与过滤、强化学习控制。

1.  **统一机器人空间数据构建 (Pre-retargeting):** 提取多个异构人类动作数据集（AMASS, GRAB, Nymeria），通过逆运动学（IK）优化，最小化关节角度、关键点位置和脚部滑动的误差，将所有人类动作统一映射到 Unitree-G1 机器人的 27 自由度状态空间中。
2.  **引导式扩散模型训练 (Diffusion Prior Training):** 在上述构建的机器人空间数据集上，训练一个去噪扩散概率模型（DDPM）。该模型通过 Transformer 架构接收开放词汇的文本指令（Text）和稀疏的时空约束坐标（Spatio-temporal control signals），学习生成机器人的全身关节轨迹。
3.  **自动化轨迹生成与过滤 (Automated Filtering):** 在推理阶段，输入特定任务的文本和目标接触点坐标，扩散模型生成多条候选轨迹。随后应用基于客观物理规则的自动化过滤器（如末端执行器与目标的 L2 距离阈值、根节点高度安全限制、防滑限制），剔除不合格轨迹。
4.  **物理驱动的强化学习 (RL Training):** 将过滤后的一组高质量参考轨迹输入到 PPO 强化学习算法中。RL 策略在物理仿真器（IsaacLab）中训练，其奖励函数由两部分组成：跟踪参考轨迹的模仿奖励，以及完成具体任务（如抽屉位移量）的任务奖励。

    raw_trajectories = model.sample(task_text, task_spatial_target, num_samples=500)

        done = False
        while not done:

            next_obs, task_reward, done = env.step(action)
            
            # Calculate tracking reward against the generated diffusion trajectories
            tracking_reward = calculate_tracking_reward(obs, valid_trajectories)
            total_reward = task_reward + tracking_reward
            
            policy.store_transition(obs, action, total_reward, next_obs)
        policy.update()

### 第二模块：核心架构解释

StretchBot 的系统架构是一个闭环的“感知-推理-执行-规划”控制流，其核心在于如何将非结构化的多模态输入转化为结构化的机器人控制指令。

1. **感知模块 (Perception)**: 异步运行。使用 YOLOv8 进行物体检测，MediaPipe 进行 30Hz 的实时骨骼关键点追踪（通过几何规则判断动作是否达标），并对语音、面部和文本情绪进行后融合（Late-fusion）得到单一情绪标签。
2. **推理模块 (Reasoning)**: 核心决策中枢。当接收到用户语音或状态改变时，打包当前上下文（检测到的物体、情绪、任务进度）。首先在人工构建的内部知识图谱中检索实体关系（如 `Fatigue -> DrinkWater`），若缺失则回退到 ConceptNet 检索。将检索到的三元组与上下文拼接，输入给 LLM（DeepSeek-R1），LLM 必须输出带有特定前缀的指令。
3. **执行模块 (Action Execution)**: 将 LLM 输出的符号化前缀（如 `POINT_<OBJECT>`）映射为 ROS2 空间坐标轨迹控制机械臂，同时将自然语言部分通过 TTS 转化为语音输出。
4. **规划与自适应模块 (Planning & Adaptation)**: 维护全局的拉伸动作状态机。根据执行模块的反馈更新当前进度，确保在局部自适应（如停下喝水）后，能够回归主线任务。

**核心逻辑伪代码 (Python 风格)**:

```python
class StretchBotReasoning:
    def __init__(self, internal_kg, llm_client, routine_tracker):
        self.kg = internal_kg
        self.llm = llm_client
        self.tracker = routine_tracker
        self.allowed_actions = ["NEXT_EXERCISE", "POINT_", "STOP_ROUTINE"]

    def process_interaction_cycle(self, perception_data):
        # 1. 解析感知上下文
        objects = perception_data.get_objects()
        emotion = perception_data.get_fused_emotion()
        user_speech = perception_data.get_speech_text()
        current_task = self.tracker.get_current_state()

        # 2. 知识图谱检索 (Neuro-Symbolic Grounding)
        retrieved_knowledge = []
        entities = extract_entities(objects, emotion, user_speech)
        for entity in entities:
            if entity in self.kg:
                retrieved_knowledge.extend(self.kg.query_relations(entity))
            else:
                # Fallback to ConceptNet
                retrieved_knowledge.extend(query_conceptnet(entity))

        # 3. 构建 Prompt
        prompt = self.build_prompt(
            current_task, objects, emotion, user_speech, retrieved_knowledge
        )

        # 4. LLM 决策生成
        llm_response = self.llm.generate(prompt)
        
        # 5. 动作解析与验证
        action_prefix, spoken_text = self.parse_llm_output(llm_response)
        
        if not self.is_valid_action(action_prefix):
            action_prefix = "CONTINUE_CURRENT" # 安全回退机制
            
        return action_prefix, spoken_text

    def parse_llm_output(self, text):
        # 强制解析预定义的动作前缀
        for action in self.allowed_actions:
            if text.startswith(action):
                return action, text.replace(action, "").strip()
        return "NONE", text
```

**Authors**: Hiroki Hashimoto, Hiromichi Goto, Hiroyuki Sugai, Hiroshi Kera, Kazuhiko Kawamoto
**Links**: [arXiv](http://arxiv.org/abs/2604.00597v1) | [PDF](https://arxiv.org/pdf/2604.00597v1) | [中文翻译](https://hjfy.top/arxiv/2604.00597)

<details>
<summary>详细分析</summary>

端到端自动驾驶模型在实际部署中面临的一个关键挑战是摄像头视角的不可避免的变化。现有的轨迹规划模型往往严重依赖于训练期间见过的特定摄像头视角，导致在摄像头安装位置或角度发生偏移时，模型的规划性能会显著下降。

为解决这一问题，本文提出了一种免数据增强（augmentation-free）的方法，利用3D基础模型提供的几何先验知识来提升鲁棒性。具体而言，该方法将基于深度估计得出的像素级3D位置作为位置嵌入（Positional Embeddings）注入到模型中，并通过交叉注意力机制（Cross-Attention）融合中间层的几何特征，从而增强模型对三维空间结构的感知能力，使其减少对单一2D视角的依赖。

在VR-Drive视角扰动基准测试上的实验表明，该方法在大多数扰动条件下（特别是俯仰角和高度变化）有效减少了性能衰减。尽管在纵向平移上的改进相对较小，但该研究证明了引入3D基础模型先验对于提升自动驾驶系统鲁棒性的潜力，为构建视角无关的端到端驾驶模型提供了新的技术路径。
