### 第二模块：核心架构解释

$RL^2$-VLA 的核心架构分为离线训练与推理期自适应引导两个阶段。其本质是在不破坏基础 VLA 预训练权重的前提下，通过一个外挂的 RL 模块在必要时修正动作轨迹。

**1. 潜在特征提取与离线 RL 训练**
保持基础 VLA 模型冻结。将视觉观察和语言指令输入 VLA，提取其内部的高维潜在表示（Latents）。以这些潜在表示作为状态输入，利用离线强化学习算法训练一个轻量级的策略网络。该网络学习输出动作的流速度（Flow Velocity），旨在提供与基础 VLA 不同的、具有更高预期回报的动作分布。

**2. 状态感知的失败预测**
训练一个二分类器或价值函数（Failure Predictor），同样以 VLA 的潜在表示为输入，用于评估当前状态下基础 VLA 策略执行失败的概率。

**3. 推理期自适应组合引导（Adaptive Compositional Steering）**
在实际部署时，系统在每个时间步首先评估失败概率。如果预测成功率高，则完全依赖基础 VLA 输出动作；如果预测可能失败，则激活 RL 策略，将其输出的流速度与 VLA 的流速度进行数学组合（如加权求和），从而在基础动作轨迹中注入 RL 的修正方向。

**核心逻辑伪代码**：

```python
def rl2_vla_inference(observation, task_text, vla_model, rl_policy, failure_predictor, threshold):
    # 1. 前向传播冻结的VLA模型，提取潜在特征与基础动作流速度
    vla_latents, vla_action_velocity = vla_model.extract_latents_and_velocity(observation, task_text)
    
    # 2. 评估当前状态下基础策略的失败概率
    p_failure = failure_predictor.predict(vla_latents)
    
    # 3. 自适应组合引导机制
    if p_failure > threshold:
        # 基础策略置信度低，提取RL策略的动作流速度
        rl_action_velocity = rl_policy.get_velocity(vla_latents)
        
        # 组合流速度：融合模仿学习先验与RL动作多样性
        final_action_velocity = compose_velocities(vla_action_velocity, rl_action_velocity)
    else:
        # 基础策略置信度高，保持原样以避免不必要的扰动
        final_action_velocity = vla_action_velocity
        
    # 4. 通过常微分方程(ODE)求解器积分流速度，生成最终物理动作
    action = ode_solver_integrate(final_action_velocity)
    
    return action

def compose_velocities(vla_vel, rl_vel, alpha=0.5):
    # 线性组合示例，实际可能涉及更复杂的流匹配(Flow Matching)引导公式
    return (1 - alpha) * vla_vel + alpha * rl_vel
```

### 第二模块：核心架构解释

TurboVLA 的架构设计摒弃了自回归生成，采用完全并行的特征处理与动作解码流程。其核心流程分为三个阶段：

1. **多模态特征独立编码**：
视觉输入通过 DINOv3 提取空间特征，并注入位置编码和相机视角编码；文本指令通过轻量级文本编码器（如 BERT）提取 Token 级别的特征。两者被投影到相同的隐藏层维度。机器人本体状态（Robot State）被单独编码，不参与早期的视文交互。
2. **双向视文交互（Vision-Language Interaction）**：
视觉特征和文本特征进入由 N 层双向交叉注意力（Bidirectional Cross-Attention）组成的交互模块。在每一层中，视觉特征作为 Query 去关注文本特征，文本特征作为 Query 去关注视觉特征。这一过程直接建立了指令与场景的细粒度对应关系，输出指令感知的视觉特征和视觉感知的指令特征。
3. **连续动作块解码（Action Chunk Decoding）**：
将交互后的视文特征拼接，并与机器人状态特征结合，输入到一个 ACT（Action Chunking with Transformers）风格的轻量级解码器中。解码器通过一组可学习的 Action Queries，在单次前向传播中并行预测出未来 H 步的连续动作块。

**核心前向传播伪代码实现：**

```python
import torch
import torch.nn as nn

class TurboVLA(nn.Module):
    def __init__(self, vision_encoder, text_encoder, interaction_layers, action_decoder):
        super().__init__()
        self.vision_encoder = vision_encoder  # e.g., DINOv3
        self.text_encoder = text_encoder      # e.g., BERT
        self.interaction_layers = interaction_layers # N layers of bidirectional cross-attention
        self.action_decoder = action_decoder  # ACT-style transformer decoder
        
        self.vision_proj = nn.Linear(vision_dim, hidden_dim)
        self.text_proj = nn.Linear(text_dim, hidden_dim)
        self.state_proj = nn.Linear(state_dim, hidden_dim)

    def forward(self, images, instruction, robot_state):
        # 1. Multimodal Feature Encoding
        # images: [B, K, C, H, W], instruction: list of strings, robot_state: [B, S]
        v_features = self.vision_encoder(images) 
        v_features = self.vision_proj(v_features) + pos_embed + view_embed # [B, N_v, D]
        
        l_features = self.text_encoder(instruction)
        l_features = self.text_proj(l_features) # [B, N_l, D]
        
        s_features = self.state_proj(robot_state) # [B, N_s, D]

        # 2. Vision-Language Interaction Module
        for layer in self.interaction_layers:
            # Bidirectional Cross-Attention
            v_features_new = layer.v2l_cross_attn(query=v_features, key=l_features, value=l_features)
            l_features_new = layer.l2v_cross_attn(query=l_features, key=v_features, value=v_features)
            
            v_features = v_features + v_features_new
            l_features = l_features + l_features_new
            
        # Concatenate updated features
        vl_features = torch.cat([v_features, l_features], dim=1) # [B, N_v + N_l, D]

        # 3. Continuous Action Chunk Prediction
        # action_queries: [B, H, D] (H is the action chunk size)
        action_chunks = self.action_decoder(
            queries=self.action_queries, 
            context=torch.cat([vl_features, s_features], dim=1)
        ) # [B, H, Action_Dim]

        return action_chunks
```

```python
    # 阶段一：离线运动学聚类获取伪标签 (利用特权信息)

    # 阶段二：前向传播
    # 1. 提取多模态观测特征
    obs_features = encode_vision_language(vision_obs, language_cmd)

    # 2. 路由器预测 (仅依赖观测特征)
    router_logits = router_network(obs_features)
    routing_probs = softmax(router_logits)

    # 3. 专家网络计算动作
    expert_outputs = [expert(obs_features) for expert in experts]
    predicted_actions = sum(routing_probs[i] * expert_outputs[i] for i in range(num_experts))

    # 阶段三：计算损失
    # 动作重建损失 (Behavior Cloning)
    action_loss = mse_loss(predicted_actions, action_trajectories)
    # 运动学监督路由损失 (核心创新：显式监督)
    routing_loss = cross_entropy_loss(router_logits, cluster_ids)

    # 联合优化
    total_loss = action_loss + lambda_weight * routing_loss
    return total_loss

def inference_kinrt(vision_obs, language_cmd):
    # 推理期：无动作轨迹输入，仅凭观测进行路由分配
    obs_features = encode_vision_language(vision_obs, language_cmd)
    routing_probs = softmax(router_network(obs_features))

    # 加权求和输出最终动作
    expert_outputs = [expert(obs_features) for expert in experts]
    final_action = sum(routing_probs[i] * expert_outputs[i] for i in range(len(experts)))
    
    return final_action
```

### 第二模块：核心架构解释

CheckVLA 的运行流程是一个闭环的执行与验证系统，其核心架构分为四个耦合模块：

1. **动作条件滚动预测 (Action-Conditioned Rolling Prediction)**：在 VLA 策略下发动作块后，系统使用一个独立预训练且冻结的视觉编码器提取当前观测特征。世界模型以上一次有效观测为锚点，结合已提交的动作，自回归地预测未来几步的特征。
2. **校准风险触发 (Calibrated Risk Triggering)**：随着新观测的到来，系统计算预测特征与实际观测特征的距离。因果风险头（Causal Risk Head）聚合这些单步差异与情景记忆，输出风险分数。该分数与基于无故障轨迹拟合的共形校准阈值进行比对，一旦越界即触发重规划。
3. **延迟感知后缀重写 (Latency-Aware Suffix Rewriting)**：触发重规划后，旧动作块继续执行以掩盖推理延迟（形成不可逆前缀）。新生成的动作块在对应的时间步被硬截断（Hard Clamping）以匹配已执行的动作。对于剩余的后缀，系统根据风险超限度计算保留权重，将旧动作的参考流与新动作的预测流进行融合。
4. **情景上下文 (Episodic Context)**：为了防止重规划导致 VLA 遗忘已完成的子目标，系统维护一个事件驱动的关键帧记忆库。该库记录真实的观测特征，并在每次策略调用时通过交叉注意力机制注入 VLA。

```python
    基于事实样本生成反事实/干预分支

    # 重新运行物理引擎计算新事件
    cf_sample.events = physics_engine.simulate(cf_sample.latent_states)

    cf_sample.observations = render_engine.render(cf_sample.latent_states)
    
    # 4. 记录分支谱系 (Branch Lineage)
    cf_sample.metadata.branch_type = f'{intervention_type}_intervention'
    cf_sample.metadata.parent_id = base_sample.metadata.sample_id
    cf_sample.metadata.intervention_target = target_param
    
    return cf_sample
```

2. **表征坍塌的量化**：在自回归生成过程中，提取 DiT 中间层的隐藏状态矩阵 $H$。通过对其奇异值分布进行计算，得出“有效秩（erank）”。erank 越高，说明隐藏状态利用的独立维度越多，信息越丰富；erank 骤降，则标志着表征维度坍塌，画面随之崩溃。
3. **视频表征正则化（VRR）**：为了对抗训练后期的表征坍塌，在总损失函数中引入正则化项。具体做法是提取 DiT 特定层（如第 0、7、15 层）的隐藏状态，对其施加 SigReg（约束向量服从各向同性高斯分布）或 Uniformity Loss（约束向量服从均匀分布）。
4. **总体目标**：最终的训练 Loss 由原始的 Diffusion Forcing 预测噪声的 MSE Loss 与隐藏层的正则化 Loss 加权求和构成。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn.functional as F

def compute_erank(H):
    """计算隐藏状态矩阵的有效秩 (erank)"""
    # H shape: [Batch, Tokens, Dim]
    singular_values = torch.linalg.svdvals(H)
    # 归一化奇异值得到概率分布
    p = singular_values / (singular_values.sum(dim=-1, keepdim=True) + 1e-8)
    # 计算香农熵
    entropy = -torch.sum(p * torch.log(p + 1e-8), dim=-1)
    # 有效秩为熵的指数
    return torch.exp(entropy).mean()

def sigreg_loss(H):
    """SigReg 正则化：约束表征趋向各向同性高斯分布 (简化概念版)"""
    # 鼓励各维度方差接近 1，防止维度坍塌
    std = H.std(dim=0)
    return torch.mean((std - 1.0) ** 2)

def train_step(video_clip, action_cond, dit_model, lambda_reg=0.1):
    """单步训练流程"""
    # 1. Diffusion Forcing 前向加噪 (每帧独立噪声水平)
    noised_clip, target_noise, t = diffusion_forcing_add_noise(video_clip)
    
    # 2. DiT 前向传播，同时返回特定层的隐藏状态
    # 假设提取第 0, 7, 15 层的隐藏状态
    pred_noise, hidden_states = dit_model(
        noised_clip, t, action_cond, 
        return_hidden_layers=[0, 7, 15]
    )
    
    # 3. 基础去噪损失 (MSE)
    loss_df = F.mse_loss(pred_noise, target_noise)
    
    # 4. 视频表征正则化损失 (VRR)
    loss_reg = 0
    for H in hidden_states:
        loss_reg += sigreg_loss(H)
        
    # 5. 总损失
    total_loss = loss_df + lambda_reg * loss_reg
    
    total_loss.backward()
    return total_loss
```

### 第二模块：核心架构解释

$RL^2$-VLA 的核心架构分为离线训练与推理期自适应引导两个阶段。其本质是在不破坏基础 VLA 预训练权重的前提下，通过一个外挂的 RL 模块在必要时修正动作轨迹。

**1. 潜在特征提取与离线 RL 训练**
保持基础 VLA 模型冻结。将视觉观察和语言指令输入 VLA，提取其内部的高维潜在表示（Latents）。以这些潜在表示作为状态输入，利用离线强化学习算法训练一个轻量级的策略网络。该网络学习输出动作的流速度（Flow Velocity），旨在提供与基础 VLA 不同的、具有更高预期回报的动作分布。

**2. 状态感知的失败预测**
训练一个二分类器或价值函数（Failure Predictor），同样以 VLA 的潜在表示为输入，用于评估当前状态下基础 VLA 策略执行失败的概率。

**3. 推理期自适应组合引导（Adaptive Compositional Steering）**
在实际部署时，系统在每个时间步首先评估失败概率。如果预测成功率高，则完全依赖基础 VLA 输出动作；如果预测可能失败，则激活 RL 策略，将其输出的流速度与 VLA 的流速度进行数学组合（如加权求和），从而在基础动作轨迹中注入 RL 的修正方向。

**核心逻辑伪代码**：

```python
def rl2_vla_inference(observation, task_text, vla_model, rl_policy, failure_predictor, threshold):
    # 1. 前向传播冻结的VLA模型，提取潜在特征与基础动作流速度
    vla_latents, vla_action_velocity = vla_model.extract_latents_and_velocity(observation, task_text)
    
    # 2. 评估当前状态下基础策略的失败概率
    p_failure = failure_predictor.predict(vla_latents)
    
    # 3. 自适应组合引导机制
    if p_failure > threshold:
        # 基础策略置信度低，提取RL策略的动作流速度
        rl_action_velocity = rl_policy.get_velocity(vla_latents)
        
        # 组合流速度：融合模仿学习先验与RL动作多样性
        final_action_velocity = compose_velocities(vla_action_velocity, rl_action_velocity)
    else:
        # 基础策略置信度高，保持原样以避免不必要的扰动
        final_action_velocity = vla_action_velocity
        
    # 4. 通过常微分方程(ODE)求解器积分流速度，生成最终物理动作
    action = ode_solver_integrate(final_action_velocity)
    
    return action

def compose_velocities(vla_vel, rl_vel, alpha=0.5):
    # 线性组合示例，实际可能涉及更复杂的流匹配(Flow Matching)引导公式
    return (1 - alpha) * vla_vel + alpha * rl_vel
```

TurboVLA 的架构设计摒弃了自回归生成，采用完全并行的特征处理与动作解码流程。其核心流程分为三个阶段：

2. **双向视文交互（Vision-Language Interaction）**：
视觉特征和文本特征进入由 N 层双向交叉注意力（Bidirectional Cross-Attention）组成的交互模块。在每一层中，视觉特征作为 Query 去关注文本特征，文本特征作为 Query 去关注视觉特征。这一过程直接建立了指令与场景的细粒度对应关系，输出指令感知的视觉特征和视觉感知的指令特征。
3. **连续动作块解码（Action Chunk Decoding）**：
将交互后的视文特征拼接，并与机器人状态特征结合，输入到一个 ACT（Action Chunking with Transformers）风格的轻量级解码器中。解码器通过一组可学习的 Action Queries，在单次前向传播中并行预测出未来 H 步的连续动作块。

```python
import torch
import torch.nn as nn

class TurboVLA(nn.Module):
    def __init__(self, vision_encoder, text_encoder, interaction_layers, action_decoder):
        super().__init__()
        self.vision_encoder = vision_encoder  # e.g., DINOv3
        self.text_encoder = text_encoder      # e.g., BERT
        self.interaction_layers = interaction_layers # N layers of bidirectional cross-attention
        self.action_decoder = action_decoder  # ACT-style transformer decoder
        
        self.vision_proj = nn.Linear(vision_dim, hidden_dim)
        self.text_proj = nn.Linear(text_dim, hidden_dim)
        self.state_proj = nn.Linear(state_dim, hidden_dim)

    def forward(self, images, instruction, robot_state):
        # 1. Multimodal Feature Encoding
        # images: [B, K, C, H, W], instruction: list of strings, robot_state: [B, S]
        v_features = self.vision_encoder(images) 
        v_features = self.vision_proj(v_features) + pos_embed + view_embed # [B, N_v, D]
        
        l_features = self.text_encoder(instruction)
        l_features = self.text_proj(l_features) # [B, N_l, D]
        
        s_features = self.state_proj(robot_state) # [B, N_s, D]

        # 2. Vision-Language Interaction Module
        for layer in self.interaction_layers:
            # Bidirectional Cross-Attention
            v_features_new = layer.v2l_cross_attn(query=v_features, key=l_features, value=l_features)
            l_features_new = layer.l2v_cross_attn(query=l_features, key=v_features, value=v_features)
            
            v_features = v_features + v_features_new
            l_features = l_features + l_features_new
            
        # Concatenate updated features
        vl_features = torch.cat([v_features, l_features], dim=1) # [B, N_v + N_l, D]

        # 3. Continuous Action Chunk Prediction
        # action_queries: [B, H, D] (H is the action chunk size)
        action_chunks = self.action_decoder(
            queries=self.action_queries, 
            context=torch.cat([vl_features, s_features], dim=1)
        ) # [B, H, Action_Dim]

        return action_chunks
```

```python
def train_kinrt(vision_obs, language_cmd, action_trajectories, num_experts, lambda_weight):
    # 阶段一：离线运动学聚类获取伪标签 (利用特权信息)
    kinematic_features = extract_kinematics(action_trajectories)
    cluster_ids = kmeans_clustering(kinematic_features, k=num_experts) # 生成 Router 的 Ground Truth

    # 阶段二：前向传播
    # 1. 提取多模态观测特征
    obs_features = encode_vision_language(vision_obs, language_cmd)

    # 2. 路由器预测 (仅依赖观测特征)
    router_logits = router_network(obs_features)
    routing_probs = softmax(router_logits)

    # 3. 专家网络计算动作
    expert_outputs = [expert(obs_features) for expert in experts]
    predicted_actions = sum(routing_probs[i] * expert_outputs[i] for i in range(num_experts))

    # 阶段三：计算损失
    # 动作重建损失 (Behavior Cloning)
    action_loss = mse_loss(predicted_actions, action_trajectories)
    # 运动学监督路由损失 (核心创新：显式监督)
    routing_loss = cross_entropy_loss(router_logits, cluster_ids)

    # 联合优化
    total_loss = action_loss + lambda_weight * routing_loss
    return total_loss

def inference_kinrt(vision_obs, language_cmd):
    # 推理期：无动作轨迹输入，仅凭观测进行路由分配
    obs_features = encode_vision_language(vision_obs, language_cmd)
    routing_probs = softmax(router_network(obs_features))

    # 加权求和输出最终动作
    expert_outputs = [expert(obs_features) for expert in experts]
    final_action = sum(routing_probs[i] * expert_outputs[i] for i in range(len(experts)))
    
    return final_action
```

1. **基础架构**：模型采用分解了空间注意力和时间注意力的 Diffusion Transformer (DiT) 作为骨干网络，并结合旋转位置编码（RoPE）。训练范式采用 Diffusion Forcing，即对输入视频序列的每一帧施加独立的噪声，并让模型基于动作条件（Action）和历史帧进行去噪预测。
2. **表征坍塌的量化**：在自回归生成过程中，提取 DiT 中间层的隐藏状态矩阵 $H$。通过对其奇异值分布进行计算，得出“有效秩（erank）”。erank 越高，说明隐藏状态利用的独立维度越多，信息越丰富；erank 骤降，则标志着表征维度坍塌，画面随之崩溃。
3. **视频表征正则化（VRR）**：为了对抗训练后期的表征坍塌，在总损失函数中引入正则化项。具体做法是提取 DiT 特定层（如第 0、7、15 层）的隐藏状态，对其施加 SigReg（约束向量服从各向同性高斯分布）或 Uniformity Loss（约束向量服从均匀分布）。
4. **总体目标**：最终的训练 Loss 由原始的 Diffusion Forcing 预测噪声的 MSE Loss 与隐藏层的正则化 Loss 加权求和构成。

```python
import torch
import torch.nn.functional as F

def compute_erank(H):
    """计算隐藏状态矩阵的有效秩 (erank)"""
    # H shape: [Batch, Tokens, Dim]
    singular_values = torch.linalg.svdvals(H)
    # 归一化奇异值得到概率分布
    p = singular_values / (singular_values.sum(dim=-1, keepdim=True) + 1e-8)
    # 计算香农熵
    entropy = -torch.sum(p * torch.log(p + 1e-8), dim=-1)
    # 有效秩为熵的指数
    return torch.exp(entropy).mean()

def sigreg_loss(H):
    """SigReg 正则化：约束表征趋向各向同性高斯分布 (简化概念版)"""
    # 鼓励各维度方差接近 1，防止维度坍塌
    std = H.std(dim=0)
    return torch.mean((std - 1.0) ** 2)

def train_step(video_clip, action_cond, dit_model, lambda_reg=0.1):
    """单步训练流程"""
    # 1. Diffusion Forcing 前向加噪 (每帧独立噪声水平)
    noised_clip, target_noise, t = diffusion_forcing_add_noise(video_clip)
    
    # 2. DiT 前向传播，同时返回特定层的隐藏状态
    # 假设提取第 0, 7, 15 层的隐藏状态
    pred_noise, hidden_states = dit_model(
        noised_clip, t, action_cond, 
        return_hidden_layers=[0, 7, 15]
    )
    
    # 3. 基础去噪损失 (MSE)
    loss_df = F.mse_loss(pred_noise, target_noise)
    
    # 4. 视频表征正则化损失 (VRR)
    loss_reg = 0
    for H in hidden_states:
        loss_reg += sigreg_loss(H)
        
    # 5. 总损失
    total_loss = loss_df + lambda_reg * loss_reg
    
    total_loss.backward()
    return total_loss
```

**模型架构与实验流程**

1. **受控环境 (POKEWORLD)**：构建一个 2D 交互环境，每次回合重采样物体的质量（mass）、阻力（drag）和接触刚度（stiffness）。渲染画面完全一致，强制模型只能通过动态交互（视觉位移、本体感觉、触觉力）来推断物理参数。
2. **证书门控协议 (Certificate-Gated Protocol)**：在评估模型前，先用监督学习在原始观测窗口上训练探测器，得到每个物理参数的“可恢复性证书”（即理论上能达到的最高 $R^2$）。只有证书得分高的参数，才会被用来评估世界模型，从而排除“传感器本身就没采集到信息”的干扰。

### 第二模块：核心架构解释

DLAM 的核心架构分为无动作视频预训练和下游策略迁移两个阶段。

**阶段一：分布式潜在动作预训练**
模型从视频中采样等间距的帧三元组 $(O_a, O_b, O_c)$。关系编码器接收相邻帧对，输出潜在动作的均值和对数方差（构成对角高斯分布）。
1. **重建约束**：解码器仅使用源帧和预测的均值来重建目标帧，确保均值锚定在真实的视觉变化上。
2. **时间约束（复合与反转）**：
   - **复合（Composition）**：将相邻的两个分布 $q_a^b$ 和 $q_b^c$ 进行归一化复合。均值直接相加并缩放；方差复合时引入一个全局可学习的共享相关系数 $\rho$，以处理共享中间帧 $O_b$ 带来的依赖性。复合后的分布需与编码器直接预测的跨步分布 $q_a^c$ 对齐。
   - **反转（Reversal）**：将前向分布 $q_a^b$ 的均值取反，方差保持不变，并与后向分布 $q_b^a$ 对齐。

**阶段二：下游世界动作模型迁移**
预训练完成后，丢弃解码器，冻结编码器。在下游 VLA 训练中，冻结的编码器从专家演示视频中提取未来帧的转移均值序列。策略网络采用联合流匹配（Joint Flow Matching）架构，以上下文（当前图像、语言指令）为条件，同时生成机器人本体动作轨迹和潜在均值轨迹。推理时，仅执行生成的机器人动作。

**核心逻辑伪代码**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class DLAM_Pretraining(nn.Module):
    def __init__(self, encoder, decoder, latent_dim):
        super().__init__()
        self.encoder = encoder
        self.decoder = decoder
        self.rho_raw = nn.Parameter(torch.tensor(0.0)) # 共享相关系数
        self.rho_max = 0.99
        
    def get_distribution(self, frame_src, frame_tgt):
        # 编码器输出均值和对数方差
        mu, log_var = self.encoder(frame_src, frame_tgt)
        std = torch.exp(0.5 * torch.clamp(log_var, min=-10, max=10))
        var = std ** 2
        return mu, var, log_var

    def forward(self, O_a, O_b, O_c):
        # 1. 提取相邻与跨步分布
        mu_ab, var_ab, log_var_ab = self.get_distribution(O_a, O_b)
        mu_bc, var_bc, log_var_bc = self.get_distribution(O_b, O_c)
        mu_ac, var_ac, log_var_ac = self.get_distribution(O_a, O_c)
        mu_ba, var_ba, log_var_ba = self.get_distribution(O_b, O_a) # 用于反转
        
        # 2. 重建损失 (仅使用均值)
        O_b_pred = self.decoder(O_a, mu_ab)
        loss_rec = F.mse_loss(O_b_pred, O_b)
        
        # 3. 复合约束 (Composition)
        rho = self.rho_max * torch.tanh(self.rho_raw)
        # 均值归一化复合
        mu_comp = (mu_ab + mu_bc) / math.sqrt(2)
        # 方差相关性复合
        var_comp = (var_ab + var_bc) / 2 + rho * torch.sqrt(var_ab * var_bc)
        log_var_comp = torch.log(var_comp)
        
        # 计算复合分布与直接预测分布的差异 (Frobenius norm)
        loss_comp = torch.mean((mu_comp - mu_ac)**2) + 0.1 * torch.mean((log_var_comp - log_var_ac)**2)
        
        # 4. 反转约束 (Reversal)
        # 均值取反，方差不变
        mu_rev = -mu_ab
        log_var_rev = log_var_ab
        loss_rev = torch.mean((mu_rev - mu_ba)**2) + 0.1 * torch.mean((log_var_rev - log_var_ba)**2)
        
        return loss_rec + loss_comp + loss_rev
```

### 第二模块：核心架构解释

TC-LeWM 的核心逻辑在于修改了联合嵌入预测架构（JEPA）中的正则化目标。整个流程分为世界模型预训练和下游策略学习两个阶段。

**1. 状态编码与预测 (State Encoding & Prediction)**
给定多视角图像输入，模型通过共享权重的 ViT 编码器提取当前时刻的隐变量 $z_t$。随后，一个基于 Transformer 的动作条件预测器接收历史隐变量序列和当前动作 $a_t$，预测下一时刻的隐变量 $\hat{z}_{t+1}$。预测损失采用简单的均方误差（MSE）。

**2. 时间中心化残差正则化 (Temporally Centered Regularization)**
这是本文的核心创新。模型在时间维度上取一个局部窗口（如 $W=8$ 帧），计算该窗口内隐变量的平均值 $\bar{z}_t$。然后，计算当前隐变量与均值的残差 $r_t = z_t - \bar{z}_t$。SIGReg（基于 Epps-Pulley 检验的正则化器，用于迫使分布趋向高斯分布以防坍塌）仅作用于残差 $r_t$，而不作用于原始隐变量 $z_t$。

**3. 下游动作克隆 (Downstream Behavior Cloning)**
世界模型训练完成后，冻结 ViT 编码器。提取视觉特征（CLS token 和 patch tokens），输入到一个基于 DiT（Diffusion Transformer）的流匹配（Flow-Matching）策略网络中，通过行为克隆学习具体的机械臂操作动作。

**核心伪代码实现 (Python/PyTorch 风格):**

```python
import torch
import torch.nn as nn

def compute_sigreg_loss(x, num_projections=1024):
    # 简化的 SIGReg 实现：将特征投影到一维并计算 Epps-Pulley 统计量
    # 迫使输入 x 的边缘分布趋近于各向同性高斯分布
    batch_size, dim = x.shape
    projections = torch.randn(dim, num_projections, device=x.device)
    projections = projections / torch.norm(projections, dim=0, keepdim=True)
    projected_x = x @ projections # [batch_size, num_projections]
    
    # 计算 EP 统计量 (此处省略复杂的积分与经验特征函数计算细节)
    ep_loss = epps_pulley_statistic(projected_x) 
    return ep_loss

# 训练单步前向传播
def train_step(images, actions, encoder, predictor, window_size=8):
    # 1. 编码当前与未来图像
    # images shape: [batch_size, seq_len, channels, H, W]
    z = encoder(images) # shape: [batch_size, seq_len, latent_dim]
    
    # 2. 预测下一时刻隐变量
    z_current = z[:, :-1, :]
    z_next_target = z[:, 1:, :].detach() # 停止梯度
    z_next_pred = predictor(z_current, actions)
    
    # 3. 预测损失 (MSE)
    loss_pred = nn.functional.mse_loss(z_next_pred, z_next_target)
    
    # 4. 时间中心化残差计算 (核心创新)
    # 在 seq_len 维度上应用滑动窗口或分块计算局部均值
    # 为简化展示，假设 seq_len == window_size
    z_mean = z.mean(dim=1, keepdim=True) # [batch_size, 1, latent_dim]
    r = z - z_mean # 计算残差
    
    # 5. 残差正则化损失
    # 将残差展平后输入 SIGReg
    r_flat = r.reshape(-1, r.shape[-1])
    loss_reg = compute_sigreg_loss(r_flat)
    
    # 6. 总损失
    total_loss = loss_pred + lambda_reg * loss_reg
    return total_loss
```

```python
    def __init__(self, video_generator, physics_simulator):
        self.video_generator = video_generator
        self.physics_simulator = physics_simulator
        
    def synthesize_experience(self, human_video, robot_urdf):
        # 1. 提取人类视频的中间表示
        task_graph = self.extract_task_graph(human_video)
        
        # 2. 构建可供性与约束（基于层次化潜在空间）
        affordance_graph = self.infer_affordance(task_graph.objects)
        constraint_graph = self.infer_constraints(task_graph.actions)
        
        # 3. 跨具身图转换
        robot_planning_graph = self.transform_to_robot_graph(
            task_graph, affordance_graph, constraint_graph, robot_urdf
        )
        
        # 4. 机器人条件视频生成
        generated_robot_video = self.video_generator.generate(
            condition=robot_planning_graph
        )
        
        # 5. 闭环物理验证
        if self.verify_physics(generated_robot_video, robot_urdf):
            return generated_robot_video  # 返回可用于VLA训练的高质量数据
        else:
            return None  # 物理不可行，丢弃
            
    def verify_physics(self, video, robot_urdf):

        kinematics_ok = self.physics_simulator.check_kinematics(video, robot_urdf)
        collision_free = self.physics_simulator.check_collision(video)
        joint_limits_ok = self.physics_simulator.check_joint_limits(video, robot_urdf)
        
        return kinematics_ok and collision_free and joint_limits_ok
```

本文提出的 EIIR 框架摒弃了单体模型的思路，采用模块化、分层解耦的系统架构。其核心运行流程分为五个关键模块的协同：

2.  **High-level Task Planner（高层任务规划器）：** 接收人类自然语言指令。利用 LLM 结合 RAG 技术，从世界模型中检索工艺约束，将宏观任务（Task）拆解为符合工业逻辑的子任务序列（Subtasks）。

4.  **Simulator（仿真器）：** 在物理执行前，通过产线级数字孪生进行虚拟调试（Virtual Commissioning），验证运动学、防碰撞及控制逻辑。
5.  **Physical System（物理系统）：** 真实硬件执行动作，并将传感器数据（视觉、力觉、PLC状态）实时反馈给仿真器和世界模型，形成感知-决策-执行的闭环。

```python
class EIIR_Framework:
    def __init__(self):
        # 初始化结构化世界模型
        self.world_model = {
            "semantic_map": SemanticMap(update_freq="real-time"),
            "knowledge_graph": IndustrialKnowledgeGraph(domain="assembly")
        }
        self.llm_planner = LLM_with_RAG()
        self.skill_library = load_industrial_skills() # 包含15种原子技能
        self.simulator = DigitalTwinSimulator()
        self.hardware = PhysicalFactory()

    def execute_industrial_task(self, natural_language_instruction):
        # 1. 检索世界模型，获取环境与工艺约束
        context = self.world_model["knowledge_graph"].retrieve(natural_language_instruction)
        env_state = self.world_model["semantic_map"].get_current_state()
        
        # 2. 高层规划：LLM 结合约束进行任务拆解
        subtasks = self.llm_planner.decompose(
            instruction=natural_language_instruction, 
            constraints=context, 
            environment=env_state
        )
        
        # 3. 底层控制：将子任务映射为参数化技能代码 (DSL)
        executable_code = []
        for subtask in subtasks:
            skill = self.skill_library.match(subtask)
            # 结合实时视觉/力觉数据填充技能参数 (如 6D Pose, 力矩阈值)
            parameterized_skill = skill.bind_parameters(env_state)
            executable_code.append(parameterized_skill.to_dsl())
            
        # 4. 仿真验证：在数字孪生中进行试运行
        sim_result = self.simulator.virtual_commissioning(executable_code)
        if not sim_result.is_safe:
            return self.handle_error(sim_result.collisions)
            
        # 5. 物理执行与闭环反馈
        for code_block in executable_code:
            status, sensor_data = self.hardware.execute(code_block)
            
            # 实时更新世界模型，形成闭环
            self.world_model["semantic_map"].update(sensor_data)
            
            if status == "FAILED":
                # 触发重规划机制
                self.replan(sensor_data)
                break
                
        return "Task Completed Successfully"
```

### 第二模块：核心架构解释

SAGE 框架的核心思想是将 VLA 作为一个黑盒策略，在外部包裹一个“概念专家（Concept Expert）”，通过两个阶段实现物理知识的注入：

**1. 概念初始化阶段 (t = 0)**
在任务开始前，系统利用 VLM 识别目标物体，通过 SAM 2 提取掩码，并输入到 3D 视觉基础模型（VGGT）中提取 3D 特征。预训练的结构参数头（Structural Parameter Head）据此估算出物体的静态结构参数（$P_s$，如旋转轴）和初始运动学参数（$P_k^0$，如抽屉初始位置）。

**2. 动态追踪与策略微调阶段 (t > 0)**
随着机器人与物体交互，物体的运动学状态会发生改变。SAGE 不依赖外部追踪器，而是提取 VLA 内部的中间特征，通过一个适配器（Adapter）与 VGGT 的 3D 特征进行对齐（$L_{align}$）。对齐后的特征输入到动态参数头（Dynamic Parameter Head），实时输出当前帧的运动学参数（$P_k^t$）。
基于追踪到的参数，SAGE 生成两种监督信号来微调 VLA：
- **运动学约束监督（Kinematic Constraint Supervision）**：计算出当前最理想的 3D 交互方向向量 $v^*$，强制 VLA 输出的动作方向与其对齐。
- **概念衍生奖励（Concept Derived Rewards）**：在 RL 微调中，提供基于运动学进度（距离目标状态有多近）和可供性对齐（夹爪距离目标抓取位姿有多近）的密集奖励。

**核心伪代码实现**：
```python
import torch
import torch.nn.functional as F

def sage_finetuning_step(vla_model, concept_expert, batch_data):
    # batch_data 包含: 图像 obs, 语言指令 task, 专家动作 action, 目标概念参数 target_concept
    obs, task, expert_action = batch_data['obs'], batch_data['task'], batch_data['action']
    
    # 1. 概念初始化 (t=0的模拟，实际中由预处理完成)
    # P_s: 静态结构参数, P_k_0: 初始运动学参数
    P_s, P_k_0 = concept_expert.initialize(obs[0], task)
    
    # 2. VLA 前向传播，获取动作预测和中间特征
    predicted_action, vla_features = vla_model(obs, task, return_features=True)
    
    # 3. 动态参数追踪
    # 使用 VGGT 提取真实的 3D 特征作为对齐目标
    vggt_features = concept_expert.vggt(obs)
    adapted_vla_features = concept_expert.adapter(vla_features)
    
    # 计算特征对齐损失 (L_align)
    loss_align = 1.0 - F.cosine_similarity(adapted_vla_features, vggt_features).mean()
    
    # 预测当前帧的运动学参数 P_k_t
    P_k_t = concept_expert.dynamic_head(adapted_vla_features, P_s)
    
    # 4. 计算显式引导损失
    # 任务基础损失 (SFT的动作克隆损失)
    loss_task = F.mse_loss(predicted_action, expert_action)
    
    # 运动学约束监督 (L_kcs)
    # 根据当前参数 P_k_t 计算理想的交互方向 v_star
    v_star = concept_expert.compute_ideal_direction(P_s, P_k_t)
    pred_direction = F.normalize(predicted_action[:, :3], p=2, dim=-1)
    loss_kcs = 1.0 - F.cosine_similarity(pred_direction, v_star).mean()
    
    # 5. RL 设定下的密集奖励计算 (如果是 RL 微调阶段)
    # reward_prog = compute_progress_reward(P_k_t, target_concept)
    # reward_afford = compute_affordance_reward(predicted_action, P_s)
    # total_reward = reward_prog + reward_afford
    
    # 总损失
    lambda_k = 0.5
    lambda_a = 0.5
    loss_total = loss_task + lambda_k * loss_kcs + lambda_a * loss_align
    
    return loss_total
```

3. **因果动态学习（Causal Dynamics Learning）**：基于提取出的纯粹因果表征和动作，训练前向动力学模型。在损失函数中，策略方差越大的样本（意味着干预越强），其对因果动态更新的权重贡献越大。

```python
    # offline_demonstrations: 包含多智能体轨迹 (s_t, a_t, s_{t+1})
    
    # 初始化因果表征编码器 (Causal Encoder) 和 动力学模型 (Dynamics Model)

    dynamics_model = DynamicsModel()
    optimizer = Optimizer([causal_encoder, dynamics_model])

            s_t, a_t, s_next = batch
            
            # 1. 提取策略方差 (Policy Variance) 作为隐式干预信号
            # 评估当前状态下动作分布的方差，方差越大代表干预强度越高
            policy_variance = compute_action_variance(s_t, a_t, offline_demonstrations)
            
            # 2. 序列后门条件应用 (Sequential Backdoor Condition)
            # 使用历史信息阻断混杂路径，提取剥离了智能体意图的纯粹因果状态表征
            causal_state = causal_encoder(s_t, backdoor_adjustment=True)
            
            # 3. 因果动态预测
            # 仅依赖因果表征和动作预测下一状态
            predicted_s_next = dynamics_model(causal_state, a_t)
            
            # 4. 计算损失：预测误差 + 基于策略方差的因果加权
            # 策略方差越大的样本，其因果权重越高 (因为更接近真实的 do-calculus)
            prediction_loss = MSE(predicted_s_next, s_next)
            causal_loss = prediction_loss * weight_function(policy_variance)
            
            # 反向传播与更新
            optimizer.zero_grad()
            causal_loss.backward()
            optimizer.step()
            
    return causal_encoder, dynamics_model
```

### 第二模块：核心架构解释

StatePlay 的核心逻辑在于摒弃了传统的“图像+动作 $\rightarrow$ 图像”的单向度预测，转而采用“图像+状态+动作 $\rightarrow$ 图像+状态”的双轨制预测。

**运行流程解析**：
1. **多模态输入编码**：在时间步 $t$，模型接收当前帧图像、当前显式游戏状态（如血量、坐标等向量）以及玩家动作。图像通过视觉编码器（如 VQ-VAE 或 CNN）转化为视觉 Token，状态和动作通过 MLP 转化为状态 Token。
2. **MoT 双分支处理**：进入 Mixture-of-Transformers 架构。视觉 Token 和状态 Token 分别进入专属的 Transformer 分支进行自注意力计算，以保留各自模态的特有表征。
3. **跨模态交互（Cross-Modal Interaction）**：在 Transformer 的特定层，状态分支的特征会通过交叉注意力（Cross-Attention）或特征融合机制注入到视觉分支中。这一步是核心，确保了视觉生成严格受制于当前的游戏状态逻辑。
4. **独立目标优化**：输出端，状态分支预测 $t+1$ 时刻的状态向量（使用 L1/MSE 损失优化）；视觉分支预测 $t+1$ 时刻的图像帧（使用重建损失或交叉熵损失优化）。

**核心逻辑伪代码**：

```python
import torch.nn as nn

class StatePlayMoT(nn.Module):
    def __init__(self, visual_dim, state_dim, action_dim, hidden_dim):
        super().__init__()
        # 编码器
        self.visual_encoder = VisualEncoder(visual_dim, hidden_dim)
        self.state_encoder = nn.Linear(state_dim, hidden_dim)
        self.action_encoder = nn.Linear(action_dim, hidden_dim)
        
        # MoT 架构：独立的 Transformer 分支
        self.visual_transformer = TransformerBlocks(hidden_dim)
        self.state_transformer = TransformerBlocks(hidden_dim)
        
        # 跨模态交互模块
        self.cross_attention = MultiHeadCrossAttention(hidden_dim)
        
        # 预测头
        self.visual_head = VisualDecoder(hidden_dim, visual_dim)
        self.state_head = nn.Linear(hidden_dim, state_dim)

    def forward(self, img_t, state_t, action_t):
        # 1. 独立特征提取
        v_tokens = self.visual_encoder(img_t)       # [B, Seq, H]
        s_tokens = self.state_encoder(state_t)      # [B, 1, H]
        a_tokens = self.action_encoder(action_t)    # [B, 1, H]
        
        # 将动作条件注入到视觉和状态中
        v_input = v_tokens + a_tokens
        s_input = s_tokens + a_tokens
        
        # 2. 独立分支的自注意力处理
        v_features = self.visual_transformer(v_input)
        s_features = self.state_transformer(s_input)
        
        # 3. 跨模态交互：状态引导视觉
        # 视觉特征作为 Query，状态特征作为 Key 和 Value
        v_features_conditioned = self.cross_attention(
            query=v_features, 
            key=s_features, 
            value=s_features
        )
        
        # 4. 联合预测
        next_img_pred = self.visual_head(v_features_conditioned)
        next_state_pred = self.state_head(s_features)
        
        return next_img_pred, next_state_pred
```

### 第二模块：核心架构解释

Speech2Grasp 的架构本质是一个“教师-学生”知识蒸馏网络，外加一个频率感知的视觉前端。

**工作流程拆解：**
1.  **视觉分支 (Frequency-aware Vision):** 不直接输入 RGB 图像，而是先通过离散小波变换 (DWT) 将图像分解。保留包含几何与边缘信息的 LL、LH、HL 频段，直接丢弃包含大量相机传感器噪声的高频 HH 频段，随后输入 CNN 编码器。
2.  **语音分支 (Speech Projection):** 输入音频经过数据增强（添加房间混响 RIR 和噪声）后，转为 Log-mel 频谱图，由冻结的 Whisper 编码器提取特征。随后通过一个带残差连接的 MLP 投影器，将语音特征维度对齐到文本特征维度。
3.  **多模态融合 (Semantic Bottleneck):** 将视觉特征与投影后的语音特征送入冻结的 ALBEF 融合模块，生成联合表示 `[CLS]`。
4.  **抓取预测与损失计算:** 融合特征进入解码器生成抓取热力图。训练时计算双重损失：一是预测抓取图与真实标签的 MSE 损失（Task Loss）；二是学生模型（图像-语音）的 `[CLS]` 向量与教师模型（图像-文本）的 `[CLS]` 向量之间的余弦相似度蒸馏损失（KD Loss）。

**核心逻辑伪代码 (Python 风格)：**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class Speech2Grasp(nn.Module):
    def __init__(self, teacher_model, whisper_encoder):
        super().__init__()
        # 冻结的教师模型组件
        self.teacher_albef_fusion = teacher_model.albef_fusion.requires_grad_(False)
        self.teacher_text_encoder = teacher_model.text_encoder.requires_grad_(False)
        self.grasp_head = teacher_model.grasp_head.requires_grad_(False)
        
        # 冻结的语音编码器
        self.whisper = whisper_encoder.requires_grad_(False)
        
        # 可训练组件
        self.speech_projector = MLP_with_Residual() # 轻量级投影器
        self.vision_encoder = FrequencyAwareCNN()   # 仅微调前几层
        self.vision_decoder = FrequencyAwareDecoder()

    def discrete_wavelet_transform(self, image):
        # DWT 分解，丢弃高频噪声 HH
        LL, LH, HL, HH = DWT(image)
        return torch.cat([LL, LH, HL], dim=1) 

    def forward(self, image, speech_audio, text_label=None):
        # 1. 视觉处理 (DWT 降噪 + 编码)
        filtered_image = self.discrete_wavelet_transform(image)
        visual_features = self.vision_encoder(filtered_image)
        
        # 2. 语音处理与投影
        speech_features = self.whisper(speech_audio)
        projected_speech = self.speech_projector(speech_features)
        
        # 3. 学生模型融合 (Image + Speech)
        student_cls, fused_features = self.teacher_albef_fusion(visual_features, projected_speech)
        
        # 4. 抓取预测
        decoded_features = self.vision_decoder(fused_features)
        grasp_pred = self.grasp_head(decoded_features)
        
        # 5. 训练阶段：计算蒸馏损失
        loss_kd = 0
        if self.training and text_label is not None:
            with torch.no_grad():
                # 获取教师模型的文本特征
                text_features = self.teacher_text_encoder(text_label)
                teacher_cls, _ = self.teacher_albef_fusion(visual_features, text_features)
            
            # 计算余弦相似度蒸馏损失
            loss_kd = 1 - F.cosine_similarity(student_cls, teacher_cls, dim=-1).mean()
            
        return grasp_pred, loss_kd

# 损失函数组合
def compute_total_loss(grasp_pred, grasp_gt, loss_kd, lambda_kd):
    loss_grasp = F.mse_loss(grasp_pred, grasp_gt)
    return loss_grasp + lambda_kd * loss_kd
```

```python
def agentic_embodied_control(instruction, vlm_agent, environment):
    # 初始化极简工具集
    def observe():
        return environment.get_monocular_rgb_frame()
    
    def step(actions):
        # actions 包含: 0=STOP, 1=FORWARD, 2=LEFT, 3=RIGHT
        executed_count = 0
        for action in actions:
            if action == 0:
                environment.terminate()
                return "STOPPED"
            environment.execute(action)
            executed_count += 1
        return f"Executed {executed_count} primitives."

    tools = [observe, step]
    
    # 将指令和工具交给通用 VLM
    context = [f"Instruction: {instruction}"]
    
    while not environment.is_terminated():
        # 模型自主决定下一步操作
        response = vlm_agent.generate(context, available_tools=tools)
        
        if response.is_tool_call():
            tool_name = response.tool_name
            tool_args = response.tool_args
            
            # 执行工具并获取结果
            if tool_name == "observe":
                result = observe()
            elif tool_name == "step":
                result = step(tool_args.actions)
                
            # 将动作和结果追加到上下文中，形成无界增长的历史记录
            context.append(f"Action: {tool_name}({tool_args})")
            context.append(f"Result: {result}")
        else:
            # 记录模型的内部推理过程
            context.append(f"Reasoning: {response.text}")
```

### 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 解决具身智能中“谁来主导交互循环”的问题。打破现有系统依赖外部环境循环（Policy）或人类硬编码工作流（Workflow）的现状，探索通用视觉语言模型（VLM）在没有任何任务特定辅助的情况下，自主控制感知-决策-行动循环的极限能力。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 极简接口的智能体具身控制（Minimal-Interface Agentic Embodied Control）。强行剥离所有导航专用的模块（无地图、无深度、无里程计、无碰撞反馈），仅提供 `observe()` 和 `step()` 两个基础 API，让冻结的通用 VLM 完全自主决定何时观察、如何移动、如何纠错以及何时停止。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 巧妙之处在于“控制变量法做绝对的减法”。作者直接借用软件工程领域的通用 Agent 框架（如 SWE-agent），将其强行套用到视觉语言导航（VLN）任务上。通过这种跨界迁移，将测试变成对 VLM 底层具身推理能力的“纯粹探针（Probe）”，从而准确剥离出哪些能力来自模型本身，哪些能力来自外部脚手架。

Q4: 这篇论文最显著的贡献点（Top 3）是什么？

A4:
1. 证明了在零样本、极简接口下，前沿 VLM 的自主导航能力已匹敌甚至超越部分工业级训练策略（R2R-CE 达到 78% SR）。
2. 揭示了“能力主要存在于模型内部”的客观事实：强行施加的导航模块（如强制航点）会限制强模型，但将其作为“可选工具”提供给模型自主调用时，能实现更快、更好、更省的混合控制。
3. 明确界定了当前 VLM 走向真正自主具身智能的物理与系统瓶颈：长程上下文爆炸导致的灾难性遗忘，以及对物理实体边界（本体感觉）的感知缺失。

Q5: 这项工作在哪些相关研究的基础上做了推进？

A5:
1. 基于大模型的零样本导航工作流（如 NavGPT, MapGPT）：本文彻底去除了它们复杂的外部空间表示和硬编码规划代码。
2. 软件工程领域的通用智能体框架（如 SWE-agent, ReAct）：本文将其执行逻辑成功跨界迁移到了连续物理空间的具身控制中。

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 局限性在于其“开环”的上下文管理机制。每次调用都将历史观测全部塞入 Prompt，导致长任务中 Token 数量无界爆炸，推理极慢且极易迷失（RxR-CE 性能暴跌）。漏洞在于物理部署的鲁棒性极差，由于缺乏碰撞反馈和本体感觉，机器人在现实中极易卡死在门框上且无法自知。对后续科研的启发是：未来的研究不应再执着于为模型编写复杂的外部调度逻辑，而应转向研发“具身原生的记忆与上下文压缩机制”，并让模型在与物理世界的交互中通过强化学习内化对物理规律和自身边界的认知。
