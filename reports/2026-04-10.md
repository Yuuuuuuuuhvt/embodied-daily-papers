### 第二模块：核心架构解释

LAMP 的核心逻辑是“先想象，后解算，再执行”。其架构流程可拆解为以下三个关键阶段：

1. **目标状态生成（视觉想象）**：接收当前视角的RGB图像和自然语言操作指令，利用预训练的图像编辑模型（如 InstructPix2Pix 等扩散模型）生成操作完成后的目标状态2D图像。
2. **2D到3D的几何提升（特征匹配与解算）**：在原始图像和生成的编辑图像之间进行细粒度的特征匹配，提取物体关键点的2D像素位移。结合当前视角的深度信息（Depth）和相机内参，将2D像素点反投影到3D空间。
3. **3D变换矩阵提取（动作输出）**：通过计算操作前后的3D点云对应关系（如使用 Kabsch 算法或 PnP 求解器），计算出目标物体在空间中的刚体变换矩阵（旋转和平移，即 $SE(3)$ 变换），并将其作为连续的动作表征发送给机器人底层控制器。

```python
import numpy as np
from geometry_solver import solve_se3_transformation
from feature_extractor import extract_and_match_keypoints
from image_editor import ImageEditingModel

class LAMP_Framework:
    def __init__(self, camera_intrinsics):
        self.intrinsics = camera_intrinsics
        self.editor = ImageEditingModel() # 预训练的2D图像编辑模型
        
    def unproject_to_3d(self, pixels_2d, depth_map):
        """将2D像素点结合深度图反投影为3D点云"""
        pts_3d = []
        for (u, v) in pixels_2d:
            z = depth_map[v, u]
            x = (u - self.intrinsics.cx) * z / self.intrinsics.fx
            y = (v - self.intrinsics.cy) * z / self.intrinsics.fy
            pts_3d.append([x, y, z])
        return np.array(pts_3d)

    def get_action(self, current_rgb, current_depth, language_instruction):
        # Step 1: 利用图像编辑模型生成目标状态图像
        goal_rgb = self.editor.edit(current_rgb, language_instruction)
        
        # Step 2: 提取并匹配原始图像与目标图像的2D关键点
        # src_pts: 当前物体位置的2D像素坐标
        # dst_pts: 编辑后物体位置的2D像素坐标
        src_pts_2d, dst_pts_2d = extract_and_match_keypoints(current_rgb, goal_rgb)
        
        # Step 3: 将2D空间线索提升(Lift)为3D点
        # 假设目标深度的变化可通过几何约束或深度估计模型获取
        src_pts_3d = self.unproject_to_3d(src_pts_2d, current_depth)
        dst_pts_3d = self.unproject_to_3d(dst_pts_2d, current_depth) # 简化表达，实际需处理目标深度
        
        # Step 4: 求解物体间的连续3D变换矩阵 (SE(3))
        # T_3D 包含旋转矩阵 R 和平移向量 t
        T_3D = solve_se3_transformation(src_pts_3d, dst_pts_3d)
        
        return T_3D

# 实例化并执行
lamp = LAMP_Framework(camera_intrinsics)
action_se3 = lamp.get_action(obs_rgb, obs_depth, "move the red block onto the blue bowl")
robot.execute(action_se3)
```

### 第二模块：核心架构解释

WorldMAP 的核心架构分为离线监督信号生成（Teacher Pipeline）和在线轻量级推理（Student Distillation）两个阶段。

**1. Teacher Pipeline (世界模型驱动的教师网络)**
该阶段的目标是将世界模型生成的“幻觉”转化为具有严格物理意义的几何轨迹。
- **世界构建 (World Construction)**：输入单张 RGB 图像和指令，调用生成式世界模型生成未来视频。利用单目深度估计模型提取每帧深度并反投影到 3D 空间，同时提取视觉特征构建语义-空间记忆库。
- **任务感知接地 (Task-Aware Grounding)**：利用 VLM 在记忆库中检索与目标和障碍物相关的帧，使用开放词汇分割模型提取 Mask，并将这些 Mask 投影到统一的 BEV (Bird's Eye View) 导航平面上。
- **几何规划 (Geometric Planning)**：在 BEV 平面上构建 Cost Map（为障碍物和未知区域赋予高代价），使用快速行进法 (FMM) 规划出从起点到目标的最低代价路径，作为监督伪标签。

**2. Student Distillation (学生网络蒸馏)**
该阶段的目标是让轻量级模型吸收教师的几何与语义规划能力。
- **模型架构**：基于轻量级 VLM（如 Qwen3-VL-8B），附加 LoRA 适配器和一个多假设轨迹解码器（Multi-hypothesis head）。
- **训练机制**：使用 Teacher 生成的轨迹伪标签和真实 GT 联合训练。损失函数结合了点对点的 L2 距离回归和局部轨迹段的方向一致性约束。

**2. 具身与空间感知数据引擎**

**3. 迭代自进化与 On-Policy 蒸馏后训练**
后训练摒弃了单纯的 SFT，采用 GRPO 强化学习算法，并针对具身任务设计了结构化奖励（如几何 IoU、轨迹 DTW 距离）。RL 探索能力边界后，使用 RFT（拒绝采样微调）巩固高质量推理轨迹。最后，通过 On-Policy Distillation (OPD)，让 2B 学生模型在自己生成的轨迹上拟合 32B 教师模型的 Token 级分布，实现推理能力的降维打击。

### 第二模块：核心架构解释

GraspDreamer 的核心架构本质上是一个“生成-提取-重定向”的流水线。它将高维的视觉生成先验降维并映射到低维的机器人控制空间。

1.  **先验生成 (Prior Generation):** 给定目标物体的图像和任务描述（如“倒水”），利用预训练的视觉生成模型（VGM）合成一段人类手部执行该功能性抓取的视频。
2.  **特征提取 (Feature Extraction):** 使用现成的人类手部姿态估计器（Hand Pose Estimator）处理生成的视频，提取出人类手部的 3D 姿态、关节轨迹以及与物体的关键接触点。
3.  **具身动作优化 (Embodiment-specific Action Optimization):** 这是跨具身的核心步骤。构建一个优化问题，将提取的人类接触点和姿态作为目标，结合特定机器人机械手（如平行夹爪或灵巧手）的运动学约束，计算出最优的机器人关节角度和末端位姿。
4.  **执行与策略学习 (Execution & Policy Learning):** 优化后的抓取位姿可直接在真实机器人上执行（Zero-shot），或者将生成的“图像-动作”对作为数据集，用于训练端到端的视觉运动策略（VLA 模型）。

```python
def grasp_dreamer_pipeline(object_image, task_prompt, robot_kinematics):
    # 1. 利用视觉生成模型（VGM）生成人类交互视频演示
    # VGM 隐式包含了人类如何与物体交互的物理先验
    human_demo_video = VGM.generate_video(image=object_image, prompt=task_prompt)
    
    # 2. 从生成视频中提取人类手部 3D 姿态和接触点
    human_hand_poses, contact_points = PoseEstimator.extract_features(human_demo_video)
    
    robot_grasp_poses = []
    
    # 3. 具身动作优化（Retargeting）
    for h_pose, c_point in zip(human_hand_poses, contact_points):
        # 定义优化目标：最小化机器人末端与人类接触点的距离，同时满足运动学约束
        def loss_fn(robot_joint_angles):
            forward_kinematics = compute_fk(robot_joint_angles, robot_kinematics)
            contact_loss = distance(forward_kinematics.fingertips, c_point)
            pose_loss = alignment(forward_kinematics.orientation, h_pose.orientation)
            return contact_loss + pose_loss
            
        # 求解最优机器人位姿
        optimal_robot_pose = optimize(objective=loss_fn, constraints=robot_kinematics.limits)
        robot_grasp_poses.append(optimal_robot_pose)
        
    # 4. 过滤物理不可行的抓取（如自碰撞或与环境碰撞）
    valid_grasps = filter_collisions(robot_grasp_poses, object_image.point_cloud)
    
    return valid_grasps
```

### 第二模块：核心架构解释

LAMP 的核心逻辑是“先想象，后解算，再执行”。其架构流程可拆解为以下三个关键阶段：

1. **目标状态生成（视觉想象）**：接收当前视角的RGB图像和自然语言操作指令，利用预训练的图像编辑模型（如 InstructPix2Pix 等扩散模型）生成操作完成后的目标状态2D图像。
2. **2D到3D的几何提升（特征匹配与解算）**：在原始图像和生成的编辑图像之间进行细粒度的特征匹配，提取物体关键点的2D像素位移。结合当前视角的深度信息（Depth）和相机内参，将2D像素点反投影到3D空间。
3. **3D变换矩阵提取（动作输出）**：通过计算操作前后的3D点云对应关系（如使用 Kabsch 算法或 PnP 求解器），计算出目标物体在空间中的刚体变换矩阵（旋转和平移，即 $SE(3)$ 变换），并将其作为连续的动作表征发送给机器人底层控制器。

**Python 风格伪代码（核心逻辑实现）：**

```python
import numpy as np
from geometry_solver import solve_se3_transformation
from feature_extractor import extract_and_match_keypoints
from image_editor import ImageEditingModel

class LAMP_Framework:
    def __init__(self, camera_intrinsics):
        self.intrinsics = camera_intrinsics
        self.editor = ImageEditingModel() # 预训练的2D图像编辑模型
        
    def unproject_to_3d(self, pixels_2d, depth_map):
        """将2D像素点结合深度图反投影为3D点云"""
        pts_3d = []
        for (u, v) in pixels_2d:
            z = depth_map[v, u]
            x = (u - self.intrinsics.cx) * z / self.intrinsics.fx
            y = (v - self.intrinsics.cy) * z / self.intrinsics.fy
            pts_3d.append([x, y, z])
        return np.array(pts_3d)

    def get_action(self, current_rgb, current_depth, language_instruction):
        # Step 1: 利用图像编辑模型生成目标状态图像
        goal_rgb = self.editor.edit(current_rgb, language_instruction)
        
        # Step 2: 提取并匹配原始图像与目标图像的2D关键点
        # src_pts: 当前物体位置的2D像素坐标
        # dst_pts: 编辑后物体位置的2D像素坐标
        src_pts_2d, dst_pts_2d = extract_and_match_keypoints(current_rgb, goal_rgb)
        
        # Step 3: 将2D空间线索提升(Lift)为3D点
        # 假设目标深度的变化可通过几何约束或深度估计模型获取
        src_pts_3d = self.unproject_to_3d(src_pts_2d, current_depth)
        dst_pts_3d = self.unproject_to_3d(dst_pts_2d, current_depth) # 简化表达，实际需处理目标深度
        
        # Step 4: 求解物体间的连续3D变换矩阵 (SE(3))
        # T_3D 包含旋转矩阵 R 和平移向量 t
        T_3D = solve_se3_transformation(src_pts_3d, dst_pts_3d)
        
        return T_3D

# 实例化并执行
lamp = LAMP_Framework(camera_intrinsics)
action_se3 = lamp.get_action(obs_rgb, obs_depth, "move the red block onto the blue bowl")
robot.execute(action_se3)
```

### 第二模块：核心架构解释

WorldMAP 的核心架构分为离线监督信号生成（Teacher Pipeline）和在线轻量级推理（Student Distillation）两个阶段。

**1. Teacher Pipeline (世界模型驱动的教师网络)**
该阶段的目标是将世界模型生成的“幻觉”转化为具有严格物理意义的几何轨迹。
- **世界构建 (World Construction)**：输入单张 RGB 图像和指令，调用生成式世界模型生成未来视频。利用单目深度估计模型提取每帧深度并反投影到 3D 空间，同时提取视觉特征构建语义-空间记忆库。
- **任务感知接地 (Task-Aware Grounding)**：利用 VLM 在记忆库中检索与目标和障碍物相关的帧，使用开放词汇分割模型提取 Mask，并将这些 Mask 投影到统一的 BEV (Bird's Eye View) 导航平面上。
- **几何规划 (Geometric Planning)**：在 BEV 平面上构建 Cost Map（为障碍物和未知区域赋予高代价），使用快速行进法 (FMM) 规划出从起点到目标的最低代价路径，作为监督伪标签。

**2. Student Distillation (学生网络蒸馏)**
该阶段的目标是让轻量级模型吸收教师的几何与语义规划能力。
- **模型架构**：基于轻量级 VLM（如 Qwen3-VL-8B），附加 LoRA 适配器和一个多假设轨迹解码器（Multi-hypothesis head）。
- **训练机制**：使用 Teacher 生成的轨迹伪标签和真实 GT 联合训练。损失函数结合了点对点的 L2 距离回归和局部轨迹段的方向一致性约束。

```python
def grasp_dreamer_pipeline(object_image, task_prompt, robot_kinematics):
    # 1. 利用视觉生成模型（VGM）生成人类交互视频演示
    # VGM 隐式包含了人类如何与物体交互的物理先验
    human_demo_video = VGM.generate_video(image=object_image, prompt=task_prompt)
    
    # 2. 从生成视频中提取人类手部 3D 姿态和接触点
    human_hand_poses, contact_points = PoseEstimator.extract_features(human_demo_video)
    
    robot_grasp_poses = []
    
    # 3. 具身动作优化（Retargeting）
    for h_pose, c_point in zip(human_hand_poses, contact_points):
        # 定义优化目标：最小化机器人末端与人类接触点的距离，同时满足运动学约束
        def loss_fn(robot_joint_angles):
            forward_kinematics = compute_fk(robot_joint_angles, robot_kinematics)
            contact_loss = distance(forward_kinematics.fingertips, c_point)
            pose_loss = alignment(forward_kinematics.orientation, h_pose.orientation)
            return contact_loss + pose_loss
            
        # 求解最优机器人位姿
        optimal_robot_pose = optimize(objective=loss_fn, constraints=robot_kinematics.limits)
        robot_grasp_poses.append(optimal_robot_pose)
        
    # 4. 过滤物理不可行的抓取（如自碰撞或与环境碰撞）
    valid_grasps = filter_collisions(robot_grasp_poses, object_image.point_cloud)
    
    return valid_grasps
```

### 第二模块：核心架构解释

ViVa 的核心思想是不改变预训练视频生成模型（Wan2.2）的内部结构，而是通过输入输出的模态对齐，将其改造为价值预测器。

**工作流程：**
1. **模态编码与隐空间注入**：
   - **图像**：通过预训练的时空 VAE 压缩为隐变量特征图。
   - **当前/未来本体感觉 ($q_t, q_{t+K}$)**：归一化后，通过 Repeat-padding（重复填充）扩展至与图像隐变量相同的空间维度 $(H', W', C')$。
   - **标量价值 ($v_t$)**：归一化后，通过 Broadcast（广播）将该标量值复制到整个隐变量特征图的所有像素点上。
2. **序列构建**：
   - 构建一个固定长度的隐变量序列。前缀（Conditioning）为干净帧：`[空白帧, 当前本体感觉, 视角1, 视角2, 视角3]`。
   - 目标（Target）为加噪帧：`[未来本体感觉, 标量价值]`。
3. **流匹配训练（Flow Matching）**：
   - DiT 模型接收上述序列，基于干净的前缀帧，预测目标帧在流匹配轨迹上的速度向量（Velocity），从而去噪还原出未来的本体感觉和价值。
4. **推理与解码**：
   - 仅输入当前观测作为前缀，通过反向扩散过程生成目标隐变量。
   - 对生成的价值隐变量求平均并反归一化得到标量 $v_t$；对本体感觉隐变量进行逆向的块平均操作，恢复出 $q_{t+K}$。

```python
        q_repeated = q_norm.repeat(1, self.num_repeats)
        return q_repeated.view(-1, *self.latent_shape)

        v_norm = self.normalize(v)
        return v_norm.view(-1, 1, 1, 1).expand(-1, *self.latent_shape)
```

### 第二模块：核心架构解释

GIRL 的核心架构建立在 RSSM（循环状态空间模型）之上，通过两个新增的解耦模块来抑制幻觉：

**1. 跨模态语义锚定 (Cross-Modal Grounding)**
模型在处理当前观测 $o_t$ 时，并行通过一个冻结的 DINOv2 提取高维特征，并降维成语义锚定向量 $c_t$。在动力学先验预测下一步隐状态时，引入一个门控残差网络将 $c_t$ 注入预测过程。同时，训练一个轻量级投影器，强制要求想象出的隐状态能够反向解码出与 $c_t$ 一致的语义特征（一致性损失）。这相当于给天马行空的想象加上了物理常识的缰绳。

**2. 自适应信任域瓶颈 (Trust-Region Adaptive Bottleneck)**
摒弃了 DreamerV3 中固定的 KL 惩罚系数 $\beta$。GIRL 维护一个动态的信任域边界 $\delta_t$，并通过双循环信号更新：
- **EIG (预期信息增益)**：衡量动力学集成模型在想象轨迹上的分歧度（认知不确定性）。
- **RPL (相对性能损失)**：衡量想象的先验分布与真实观测的后验分布之间的散度。
当模型在某处产生严重分歧或偏离真实观测时，系统会自动调大 $\beta_t$，强行收缩想象空间，防止误差爆炸。

```python
    beta_t = clip(beta_t + lr_beta * (RPL_t - delta_t))
    
    # 7. 优化目标
    L_reconstruction = compute_recon_loss(world_model.decode(z_t), obs)
    L_reward = compute_reward_loss(world_model.reward_model(z_t), rewards)
    L_kl = beta_t * RPL_t  # 动态 KL 惩罚
    
    J_GIRL = L_reconstruction + L_reward - L_kl - mu * L_cm
    J_GIRL.backward()
    optimizer.step()
    
    return beta_t, delta_t
```

# 第二模块：核心架构解释

本文的核心不在于提出一个新的神经网络架构，而在于设计了一套**可扩展的自动化多模态数据构建管线（Data Curation Pipeline）**。该管线将海量、无序的互联网无人机视频转化为具备严格几何与语义对齐的高质量世界模型训练数据。

管线包含四个核心阶段：
1. **CLIP-based Coarse Filtering（基于 CLIP 的粗筛）**：利用预训练的 CLIP 模型，计算视频帧与预设的 FPV（第一人称视角）/非 FPV 提示词的匹配概率，剔除无关内容。
2. **Temporal Segmentation（时序分割）**：使用 TransNetV2 检测镜头边界，将长视频切割为时序连贯的短片段，并丢弃时长不足（<2秒）的片段以保证足够的运动信息。
3. **Semantic Annotation（语义标注）**：利用大语言模型（GPT-4o mini）对视频片段进行二次校验（剔除片头、人脸等），并生成包含天气、环境描述及细粒度运动模式的自然语言字幕。
4. **Pose Recovery（位姿恢复）**：采用深度视觉 SLAM 系统（DROID-SLAM）提取每个片段的 6-DoF 相对相机轨迹。丢弃跟踪失败或极度不稳定的片段，保留高质量的几何元数据。

```python
    dataset = []
    
    for video in raw_videos:
        # Stage 1: CLIP-based Coarse Filtering
        frames = sample_frames(video, fps=1)
        fpv_scores = [clip_model.compute_similarity(frame, FPV_PROMPTS) for frame in frames]
        if mean(fpv_scores) < THRESHOLD:
            continue  # Discard non-UAV/non-FPV videos
            
        # Stage 2: Temporal Segmentation
        shots = transnet_v2.detect_shot_boundaries(video)
        coherent_clips = [clip for clip in shots if duration(clip) >= 2.0]
        
        for clip in coherent_clips:
            # Stage 3: Semantic Annotation via LLM
            # Sample frames with a 5-second sliding window
            sampled_context = sample_frames(clip, fps=1, window=5)
            llm_response = gpt4o_mini.generate_annotation(sampled_context, prompt="Describe weather, environment, and camera motion.")
            
            if not llm_response.is_valid_flight_footage:
                continue
                
            semantic_meta = {
                "weather": llm_response.weather,
                "environment": llm_response.environment,
                "caption": llm_response.detailed_caption
            }
            
            # Stage 4: Pose Recovery via Visual SLAM
            try:
                # Extract 6-DoF relative trajectories
                poses = droid_slam.process(clip) 
                if not is_stable_trajectory(poses):
                    continue
            except SLAMTrackingError:
                continue
                
            # Aggregate aligned data
            dataset.append({
                "video_clip": clip,
                "semantics": semantic_meta,
                "camera_poses": poses
            })
            
    return dataset
```

### 第二模块：核心架构解释

FESTS 框架的核心逻辑是将“模糊的自然语言推理”转化为“确定的形式化逻辑匹配”，再用匹配结果反哺大模型。其运行流程分为数据生成与模型微调两个阶段：

1. **查询形式化与匹配 (Data Generation)**：将自然语言查询（如“找出同一辆车连续两帧与公交车相交的画面”）人工或模板化地转化为带有全称/存在量词的空间正则表达式 (q-SpRE)。随后，STREM 匹配引擎将该表达式作用于结构化感知流（包含边界框、类别、ID的视频帧序列），通过确定性有限自动机 (DFA) 找出完全匹配的帧序列，并生成形式化的匹配解释。
2. **数据打包 (Packaging)**：将上述过程的输出打包为 `(自然语言Query, 视频帧序列, 匹配结果, 自然语言解释)` 的四元组，形成无限量的合成训练集。
3. **监督微调 (SFT)**：使用生成的 Query 和匹配结果对 3B LLM 进行因果语言建模微调。
4. **强化学习微调 (RL with PPO)**：在 SFT 基础上，引入基于解释的奖励机制。奖励函数不仅评估模型预测帧的 IoU，还通过 Sentence Transformer 评估模型生成的推理过程（Explanation）与逻辑引擎生成的 Ground-Truth 解释之间的语义相似度。

```python
# FESTS 核心逻辑伪代码

def generate_fests_data(perception_stream, nl_query, q_spre_query):
    """
    阶段一：基于逻辑引擎的数据生成
    """
    # STREM 引擎执行确定性匹配
    matches, formal_explanations = STREM_engine.match(q_spre_query, perception_stream)
    
    # 将形式化解释转化为自然语言
    nl_explanations = naturalizer.convert(formal_explanations)
    
    # 打包为训练元组
    return {
        "query": nl_query,
        "frames": perception_stream,
        "match": matches,
        "explanation": nl_explanations
    }

def compute_rl_reward(predicted_match, predicted_explanation, gt_match, gt_explanation):
    """
    阶段二：强化学习微调的奖励计算
    """
    reward = 0.0
    
    # 1. 结构有效性惩罚
    if not is_valid_xml_format(predicted_match):
        reward -= penalty_score
        
    # 2. 匹配准确度 (mAP IoU)
    iou_score = calculate_iou(predicted_match, gt_match)
    reward += weight_iou * iou_score
    
    # 3. 推理保真度 (语义相似度)
    semantic_similarity = sentence_transformer.compute_similarity(
        predicted_explanation, gt_explanation
    )
    reward += weight_semantic * semantic_similarity
    
    return reward

# 训练流程
training_data = [generate_fests_data(stream, q, spre) for stream, q, spre in dataset]
model = SFT_train(base_model, training_data) # C1: SFT
model = PPO_train(model, training_data, reward_fn=compute_rl_reward) # C2: SFT + RL
```

### 第二模块：核心架构解释

Orion-Lite 的核心思想是“特征对齐与架构平替”。整个流程分为教师模型特征提取、学生模型轻量化推理以及联合监督训练三个阶段。

1.  **状态嵌入提取 (State Embedding Extraction):** 冻结教师模型（ORION）的视觉编码器（Vision Encoder）和时序模块（QT-Former）。输入多视角图像，提取出包含地图、自车状态和驾驶指令的密集视觉-时序 Token ($T_c$)。
2.  **轻量化蒸馏模块 (Lightweight Distillation Module):** 丢弃教师模型的文本提示和 7B LLM。引入一个包含输入投影层、可学习规划查询（Planning Query）和 6 层 Transformer Decoder 的轻量模块。输入 Token ($T_c$) 被压缩后作为 Key/Value，规划查询作为 Query，通过交叉注意力机制提取时空特征，最终输出学生规划 Token ($T_{student}$)。
3.  **联合监督训练 (Joint Distillation and E2E Supervision):** 训练时，视觉主干完全冻结。损失函数由两部分组成：一是特征模仿损失（Mimic Loss），使用 $L_1$ 距离强制 $T_{student}$ 逼近教师 LLM 生成的规划 Token ($T_p$)；二是真实轨迹监督损失（GT Supervision），包含碰撞、边界、回归和 VAE 散度损失。两者结合，既防止了对确定性轨迹的过拟合，又保留了基础驾驶技能。

**核心伪代码 (Python-style):**

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class OrionLite(nn.Module):
    def __init__(self, teacher_model, hidden_dim=256, num_decoder_layers=6):
        super().__init__()
        # 1. 继承并冻结教师模型的感知与时序模块
        self.vision_encoder = teacher_model.vision_encoder.requires_grad_(False)
        self.qt_former = teacher_model.qt_former.requires_grad_(False)
        self.vae_planner = teacher_model.vae_planner # 预训练的生成式规划器
        
        # 2. 初始化轻量级学生 Decoder (替代 7B LLM)
        self.input_proj = nn.Sequential(
            nn.Linear(teacher_model.token_dim, hidden_dim),
            nn.LayerNorm(hidden_dim)
        )
        self.planning_query = nn.Parameter(torch.randn(1, 1, hidden_dim))
        self.decoder = nn.TransformerDecoder(
            nn.TransformerDecoderLayer(d_model=hidden_dim, nhead=8),
            num_layers=num_decoder_layers
        )
        self.output_proj = nn.Linear(hidden_dim, teacher_model.planning_token_dim)

    def forward(self, images, commands, teacher_planning_tokens=None, gt_trajectory=None):
        # 提取冻结的视觉与时序特征
        visual_features = self.vision_encoder(images)
        context_tokens = self.qt_former(visual_features, commands) # Tc
        
        # 学生模型推理
        compressed_tokens = self.input_proj(context_tokens)
        query = self.planning_query.expand(compressed_tokens.size(0), -1, -1)
        
        # 通过浅层 Decoder 提取规划特征
        decoder_out = self.decoder(tgt=query, memory=compressed_tokens)
        student_planning_tokens = self.output_proj(decoder_out) # T_student
        
        # 生成最终轨迹
        pred_trajectory = self.vae_planner(student_planning_tokens)
        
        if self.training:
            # 损失 1: 特征模仿损失 (L1 Regression)
            loss_mimic = F.l1_loss(student_planning_tokens, teacher_planning_tokens)
            
            # 损失 2: 真实轨迹端到端监督 (包含碰撞、边界、L1回归、VAE KL散度)
            loss_gt = self.compute_gt_loss(pred_trajectory, gt_trajectory)
            
            # 总损失
            loss_total = loss_gt + loss_mimic
            return loss_total
            
        return pred_trajectory
```

### 第二模块：核心架构解释

ERA (Event-Retrieve-Act) 框架的运行逻辑可以拆解为三个核心阶段：事件抽象、物理约束检索、多模态动作聚合。

1.  **事件抽象 (Event Abstraction):** 系统不直接处理高维像素，而是将感知数据转化为结构化的“事件列表”（包含对象ID、位置、运动学状态、环境状态等）。通过排列不变的编码器（如 DeepSets）将其压缩为隐空间事件代码（Event Code）。
2.  **物理约束检索 (Physics-Informed Retrieval):** 将当前事件代码作为 Query，在预先构建的知识库（包含专家演示的事件-动作对）中进行近似最近邻（ANN）检索。隐空间的动力学转移被强制约束在收缩流形上（满足李雅普诺夫稳定性 $V(z_{t+1}) < V(z_t)$），确保检索出的动作在物理上是可恢复且安全的。
3.  **多模态动作聚合 (Multi-modal Action Selection):** 为了解决多模态模仿学习中经典的“平均化导致碰撞”问题（例如向左躲和向右躲都是安全的，但平均后的直行会撞车），系统采用聚类贝叶斯选择。先按方向对检索到的动作聚类，选出权重最高的簇，仅在该簇内进行加权平均，输出最终控制指令。

**核心逻辑伪代码 (Python 风格):**

```python
import faiss
import numpy as np

class ERA_Framework:
    def __init__(self, knowledge_bank, encoder, dynamics_model):
        self.kb = knowledge_bank # 知识库 M = {(z_i, a_i)}
        self.encoder = encoder   # 排列不变编码器 (e.g., DeepSets)
        self.dynamics = dynamics_model # 隐空间动力学模型
        self.index = faiss.IndexIVFPQ(...) # ANN 检索索引
        
    def get_action(self, raw_sensory_input):
        # 1. 事件抽象
        event_list = self.extract_events(raw_sensory_input)
        z_t = self.encoder.encode(event_list) # 提取隐空间事件代码
        
        # 2. 记忆检索
        distances, indices = self.index.search(z_t, k=10)
        candidate_solutions = [self.kb[i] for i in indices]
        
        valid_candidates = []
        # 3. 物理约束过滤 (Lyapunov Stability Check)
        for z_i, a_i in candidate_solutions:
            z_next = self.dynamics.predict(z_t, a_i)
            if self.lyapunov_energy(z_next) < self.lyapunov_energy(z_t):
                valid_candidates.append((z_i, a_i))
                
        # 4. 多模态动作聚合 (Clustered Bayesian Selection)
        if not valid_candidates:
            return self.emergency_stop()
            
        clusters = self.cluster_by_directional_similarity(valid_candidates)
        best_cluster = self.select_highest_weight_cluster(clusters, z_t)
        
        # 仅在最优簇内进行加权平均，避免 "average-to-collision"
        final_action = self.weighted_average(best_cluster, z_t)
        
        return final_action

    def lyapunov_energy(self, z):
        return np.linalg.norm(z) ** 2 # V(z) = ||z||^2
```

### 第二模块：核心架构解释

MOSAIC（Mixture Optimization via Scaling-Aware Iterative Collection）框架的运行流程分为三个核心阶段：

**阶段一：数据聚类与排序 (Clustering & Ranking)**
首先将庞大且异构的数据池 $D_{pool}$ 划分为 $M$ 个具有相似语义或地理特征的独立域（例如基于城市位置，或基于VLM生成的Caption的TF-IDF特征）。在每个域内部，使用基础模型对样本进行评估，根据其对目标效用函数（如EPDMS分数）的初始影响力进行降序排列，确保优先抽取高质量样本。

**阶段二：拟合域级缩放定律 (Estimating Cluster Scalings)**
在正式选择数据前，进行小规模的试运行（Pilot runs）。从每个域中抽取少量数据对基础模型进行微调，记录性能变化。利用这些数据点，为每个域拟合一个饱和指数缩放定律函数 $\Delta U_i(n) = a_i(1 - e^{-n/\tau_i})$。其中 $a_i$ 代表该域能提供的渐进最大增益，$\tau_i$ 决定了边际收益递减的速度。

**阶段三：基于一阶差分的迭代采集 (Iterative Collection)**
将总效用的提升近似为各域提升的线性叠加。在给定总预算 $B$ 的情况下，算法在每次迭代中计算每个域当前增加一个样本所能带来的边际增益 $\delta_i(b_i)$。贪心地选择当前边际增益最大的域，从中抽取排名最高的样本加入训练集，更新该域的已抽取数量，循环直至耗尽预算。

**核心逻辑伪代码 (Python Style):**

```python
import numpy as np

def mosaic_data_selection(D_pool, M_clusters, budget_B, pilot_runs_data):
    """
    MOSAIC 核心数据选择算法
    """
    # 阶段1: 聚类并根据重要性分数 I(x) 在簇内排序
    # clusters 结构: {cluster_id: [sorted_samples]}
    clusters = cluster_and_rank(D_pool, M_clusters)
    
    # 阶段2: 利用试运行数据拟合每个簇的缩放定律参数 (a_i, tau_i)
    # scaling_params 结构: {cluster_id: (a, tau)}
    scaling_params = fit_scaling_laws(pilot_runs_data, M_clusters)
    
    def marginal_gain(cluster_id, current_count):
        """计算一阶差分（边际增益）: delta_U(n+1) - delta_U(n)"""
        a, tau = scaling_params[cluster_id]
        gain_n = a * (1 - np.exp(-current_count / tau))
        gain_n_plus_1 = a * (1 - np.exp(-(current_count + 1) / tau))
        return gain_n_plus_1 - gain_n

    D_sel = []
    # 初始化每个簇的已抽取样本计数器
    counts = {i: 0 for i in range(M_clusters)}
    
    # 阶段3: 贪心迭代采集
    while len(D_sel) < budget_B:
        best_cluster = None
        max_gain = -float('inf')
        
        # 寻找当前边际增益最大的簇
        for i in range(M_clusters):
            gain = marginal_gain(i, counts[i])
            if gain > max_gain:
                max_gain = gain
                best_cluster = i
                
        # 从最优簇中弹出排名最高的样本
        selected_sample = clusters[best_cluster].pop(0)
        D_sel.append(selected_sample)
        
        # 更新计数器
        counts[best_cluster] += 1
        
    return D_sel
```

**流程详解：**
1. **阶段一（骨干网络预训练）：** 按照传统世界模型的方式，训练编码器将观测图像压缩为隐变量，并训练转移模型根据当前隐变量和动作预测下一步隐变量。此时不引入任何因果约束。
2. **阶段二（因果分支训练）：** 冻结阶段一训练好的骨干网络。将编码器输出的隐变量输入到 CausalVAE 分支中。该分支通过学习一个 DAG 邻接矩阵，将隐变量重构为符合因果结构的特征。此阶段的损失函数包含重构损失、KL 散度、DAG 无环约束损失，以及一个关键的**对齐损失（Alignment Loss）**（利用物理模拟器的真实状态作为弱监督信号来锚定隐变量坐标系）。
3. **阶段三（转移模型微调）：** 冻结编码器和 CausalVAE 分支。使用一个指数衰减的 Alpha 门控机制，将原始隐变量与因果重构后的隐变量进行加权融合。基于融合后的特征，微调转移模型以适应多步时序展开（Multi-step Rollout）。

**核心逻辑伪代码 (Python-style):**

```python
# 核心组件定义
encoder = Encoder()
transition = TransitionModel()
causal_vae = CausalVAEBranch()

# ==========================================
# Stage 1: 骨干网络预训练 (Factual Dynamics)
# ==========================================
def stage1_step(obs_t, action_t, obs_next):
    z_t = encoder(obs_t)
    z_next_target = encoder(obs_next)
    
    # 预测下一步
    z_next_hat = transition(z_t, action_t)
    
    # 优化 encoder 和 transition
    loss = mse_loss(z_next_hat, z_next_target)
    return loss

# ==========================================
# Stage 2: 因果分支训练 (Structural Constraint)
# ==========================================
def stage2_step(obs_t, state_label_t):
    # 冻结 encoder，仅获取特征
    with torch.no_grad():
        z_t = encoder(obs_t)
        
    # CausalVAE 提取因果结构特征和 DAG 矩阵
    z_tilde, dag_matrix = causal_vae(z_t)
    
    # 优化 causal_vae
    loss_rec = mse_loss(z_tilde, z_t)
    loss_dag = compute_dag_penalty(dag_matrix) # 确保无环
    loss_align = mse_loss(z_tilde, state_label_t) # 坐标系锚定
    
    loss = loss_rec + lambda_dag * loss_dag + lambda_align * loss_align
    return loss

# ==========================================
# Stage 3: 转移模型微调 (Alpha-Gated Fusion)
# ==========================================
def stage3_step(obs_t, action_t, obs_next, alpha):
    # 冻结 encoder 和 causal_vae
    with torch.no_grad():
        z_t = encoder(obs_t)
        z_tilde, _ = causal_vae(z_t)
        z_next_target = encoder(obs_next)
        
    # 门控融合原始特征与因果特征
    z_fused = (1 - alpha) * z_t + alpha * z_tilde
    
    # 仅微调 transition
    z_next_hat = transition(z_fused, action_t)
    loss = multi_step_rollout_loss(z_next_hat, z_next_target)
    return loss
```

本文的核心不在于提出一个新的网络架构，而在于设计了一套针对 3D 城市领空导航的**数据构建与系统性评估流程**。其核心流程分为三个阶段：

3. **关键决策分叉分析（Bifurcation Analysis）**：评估系统不仅记录成功率，还追踪模型轨迹与专家轨迹的偏离。系统定位模型首次做出致命错误决策的节点（即关键决策分叉点），分析误差是如何在此节点后迅速发散而非线性累积的。

```python
class EmbodiedNavigationBenchmark:
    def __init__(self, env, dataset, models_to_evaluate):
        self.env = env
        self.dataset = dataset
        self.models = models_to_evaluate
        self.results = {}

    def evaluate_model(self, model):
        success_count = 0
        bifurcation_points = []

        for sample in self.dataset:
            obs = self.env.reset(start_pose=sample.start_pose)
            goal = sample.goal_instruction
            expert_trajectory = sample.expert_trajectory
            model_trajectory = []
            
            done = False
            step = 0
            bifurcation_recorded = False

            while not done and step < self.env.max_steps:
                # 1. Model predicts 3D action based on current observation and goal
                action = model.predict_action(obs, goal)
                
                # 2. Environment steps forward
                next_obs, reward, done, info = self.env.step(action)
                model_trajectory.append((obs, action))
                
                # 3. Check for critical decision bifurcation (divergence from expert)
                if not bifurcation_recorded:
                    expert_action = expert_trajectory[step].action
                    if self.compute_action_divergence(action, expert_action) > THRESHOLD:
                        bifurcation_points.append({
                            'step': step,
                            'obs': obs,
                            'model_action': action,
                            'expert_action': expert_action
                        })
                        bifurcation_recorded = True
                
                obs = next_obs
                step += 1

            if info['success']:
                success_count += 1
                
        return success_count / len(self.dataset), bifurcation_points

    def compute_action_divergence(self, action_a, action_b):
        # Compute spatial divergence in 3D action space (x, y, z, yaw)
        return l2_distance(action_a, action_b)
```

### 第二模块：核心架构解释

本文的实验架构本质上是一个严格的控制变量法设计，旨在对比不同监督信号粒度对自回归动作序列生成的影响。整体流程分为三个阶段：

1.  **Teacher SFT（教师模型微调）：** 使用 nuScenes 数据集，将感知结果转化为文本 Prompt，微调一个 Qwen3-8B 模型，使其能够输出包含“思维链推理（CoT）+ 宏观动作 + 6个轨迹路点”的结构化响应。
2.  **Student Rollout（学生模型同策略采样）：** 给定相同的 Prompt，让未完全收敛的 Qwen3-1.7B 学生模型自由生成轨迹。此时生成的轨迹可能包含物理上不合理的坐标。
3.  **Supervision & Update（监督与参数更新）：** 冻结教师模型，将学生生成的轨迹输入给教师模型。
    *   **GKD 分支（本文方法）：** 获取教师模型在每个 Token 上的完整 Logits 分布，计算学生分布与教师分布的广义 Jensen-Shannon 散度（JSD），以此作为 Loss 更新学生模型。
    *   **RL 分支（基线方法）：** 仅获取教师模型在学生“已采样 Token”上的对数概率，计算 Advantage（教师概率 - 学生概率），使用 REINFORCE 算法更新学生模型。

**核心伪代码实现逻辑：**

```python
import torch
import torch.nn.functional as F

def gkd_loss_step(teacher_model, student_model, prompt):
    # 1. 学生模型进行 On-policy 采样 (Stop Gradient)
    with torch.no_grad():
        # student_trajectory 包含可能存在误差的自回归生成序列
        student_trajectory = student_model.generate(prompt) 
    
    # 2. 获取学生和教师在同一轨迹上的全词表 Logits
    # 注意：这里输入的是学生自己生成的轨迹
    student_logits = student_model(prompt, student_trajectory).logits
    with torch.no_grad():
        teacher_logits = teacher_model(prompt, student_trajectory).logits
        
    # 3. 将 Logits 转换为概率分布
    p_student = F.softmax(student_logits, dim=-1)
    p_teacher = F.softmax(teacher_logits, dim=-1)
    
    # 4. 计算广义 Jensen-Shannon Divergence (JSD)
    # beta = 0.5 平衡 Forward KL (覆盖模式) 和 Reverse KL (寻找模式)
    beta = 0.5
    p_mixture = beta * p_teacher + (1 - beta) * p_student
    
    # D_KL(P || M)
    kl_teacher_mix = F.kl_div(p_mixture.log(), p_teacher, reduction='batchmean')
    kl_student_mix = F.kl_div(p_mixture.log(), p_student, reduction='batchmean')
    
    jsd_loss = beta * kl_teacher_mix + (1 - beta) * kl_student_mix
    
    # 5. 反向传播更新学生模型
    jsd_loss.backward()
    return jsd_loss

# 对比：RL Baseline 的核心逻辑 (仅使用标量 Reward)
def rl_baseline_step(teacher_model, student_model, prompt):
    with torch.no_grad():
        student_trajectory = student_model.generate(prompt)
        # 仅计算被采样 token 的概率，丢失了未采样 token 的分布信息
        teacher_log_probs = get_log_probs(teacher_model, prompt, student_trajectory)
        
    student_log_probs = get_log_probs(student_model, prompt, student_trajectory)
    
    # 计算 Advantage: 教师认为该 token 好的程度减去学生认为的程度
    advantage = (teacher_log_probs - student_log_probs.detach())
    
    # REINFORCE 策略梯度更新
    rl_loss = - (advantage * student_log_probs).mean()
    rl_loss.backward()
```

### 第二模块：核心架构解释

$E^2$ 框架的运行流程分为对抗生成器（Adversarial Synthesizer）和闭环策略更新（Closed-loop Update）两个阶段。其底层逻辑是将对抗场景生成建模为对反向时间随机微分方程（Reverse-Time SDE）的传输正则化最优控制问题。

**1. 结构感知稀疏控制 (Structure-Aware Sparse Control)**
模型首先通过一次轻量级的标称前向推演，计算所有智能体之间的 TTC（碰撞时间）风险权重，构建动态交互图。通过提取高风险的 K-cliques（拓扑分叉分析），并结合大语言模型或规则进行语义可行性过滤（确保车辆在可行驶区域内），最终锁定一个极小的关键智能体子集（Support Set $\mathcal{S}$）。控制梯度仅作用于该子集，其余车辆保持正常行驶，从而维持背景真实度。

**2. 交互骨架与拓扑锚定 (Interaction Skeleton & Topological Anchoring)**
在锁定的子集中，模型建立一条因果依赖链（远端发起者 -> 中间媒介 -> 近端攻击者 -> 自车），形成交互骨架 $\tilde{\pi}$。在扩散模型的反向去噪过程中，模型不会完全从纯噪声盲目生成，而是在特定的中间时间步 $t_a$，将符合该骨架的干净状态注入并与当前去噪状态混合。这相当于在生成轨迹中打下一个“物理锚点”，防止 SDE 求解器崩溃或生成不合逻辑的碰撞。

**3. 闭环进化课程 (Closed-Loop Evolutionary Curricula)**
生成的对抗场景输入给自车策略进行闭环仿真。仿真产生的失败信号用于更新自车策略。随着自车策略变强，框架会逐步提高对抗强度参数 $\eta$，生成更复杂的协同攻击场景，形成动态博弈的课程学习。

**核心伪代码实现 (Python 风格):**

```python
def generate_adversarial_scenario(scene, ego_policy, diffusion_prior, eta, alpha, t_a):
    # 1. 标称推演与交互图构建，寻找关键智能体
    nominal_rollout = simulate_nominal(scene, ego_policy, diffusion_prior)
    support_set = topological_bifurcation_analysis(nominal_rollout)
    feasible_set = semantic_feasibility_filter(support_set, scene.map)
    active_S = feasible_set
    
    # 2. 构建交互骨架 (因果链)
    skeleton_pi, mask_M = build_interaction_skeleton(active_S, scene.ego)
    
    # 3. 初始化反向 SDE 纯噪声
    x_t = sample_gaussian_noise()
    
    # 4. 混合最优控制的反向去噪过程
    for t in reversed(diffusion_steps):
        # 预测当前步的干净状态 x0
        x0_hat = predict_x0(x_t, t)
        
        # 计算物理可行性梯度 (全局) 和 对抗碰撞梯度 (仅限 active_S)
        grad_feas = compute_gradient(V_feas(x0_hat))
        grad_adv = compute_gradient(V_adv(x0_hat, skeleton_pi))
        
        # 施加稀疏控制漂移项 (仅对 mask_M 选中的智能体施加对抗梯度)
        u_t = -g(t)**2 * (grad_feas + eta * mask_M * grad_adv)
        
        # 拓扑锚定：在特定时间步 t_a 注入骨架状态
        if t == t_a:
            x_skeleton_ta = forward_diffuse(skeleton_pi.clean_state, t_a)
            x_t = (1 - alpha) * x_t + alpha * x_skeleton_ta
            
        # Euler-Maruyama 步进更新
        x_t = euler_maruyama_step(x_t, t, u_t, diffusion_prior)
        
    return x_t # 返回生成的对抗场景轨迹
```
