### 第二模块：核心架构解释

FlowDAgger 的核心架构摒弃了对大模型权重的直接修改，转而构建了一个“人类纠正 -> 噪声反演 -> 潜空间策略训练”的闭环系统。

**1. 部署与干预 (Deployment & Intervention)**
系统在真实环境中运行冻结的生成式基础策略（如 VLA 或 WAM）。当机器人表现不佳或即将失败时，人类专家介入并给出正确的动作 $a^*$。此时系统记录下当前的观测 $s$ 和专家动作 $a^*$。

**2. 动作反演 (Action Inversion)**
这是整个框架的灵魂。由于基础策略是一个从噪声 $w$ 到动作 $a$ 的确定性映射（基于常微分方程 ODE 的积分），系统需要找到一个特定的噪声 $w^*$，使得冻结模型输入 $w^*$ 后恰好能输出专家的动作 $a^*$。
对于步数较少的 Flow-matching 模型，直接单步反向计算会产生巨大的线性化误差。作者采用**逐步不动点迭代（Per-step fixed-point iteration）**，从最终动作开始，一步步向后精确求解隐式方程，最终还原出初始噪声 $w^*$。

**3. 噪声策略训练 (Noise Policy Training)**
构建一个极小的多层感知机（MLP）作为噪声策略 $\pi^w$。它的任务是：输入当前观测 $s$，输出反演得到的噪声 $w^*$。为了防止模型在稀疏的人类干预数据上过拟合，训练时采用混合缓冲区：一半数据来自人类干预反演的 $(s, w^*)$，另一半来自基础策略自主成功运行时的历史噪声数据。

**4. 部署推理 (Inference)**
在实际部署时，系统不再从标准正态分布中随机采样噪声，而是将观测 $s$ 输入噪声策略 $\pi^w$ 得到确定性噪声 $w$，再将该噪声送入冻结的基础策略生成最终动作。

**核心逻辑伪代码 (Python 风格)**:

```python
def flowdagger_adaptation_loop(base_policy, env, num_episodes):
    # base_policy: 冻结的预训练生成式策略 (VLA / WAM)
    # noise_policy: 待训练的轻量级网络，初始化输出标准正态噪声
    noise_policy = LightweightMLP()
    intervention_buffer = []
    autonomous_buffer = []

    for episode in range(num_episodes):
        obs = env.reset()
        done = False
        
        while not done:
            # 1. 噪声策略预测当前观测下的最优噪声
            w_pred = noise_policy(obs)
            
            # 2. 冻结的基础策略根据噪声生成动作
            action = base_policy.generate(obs, w_pred)
            
            # 3. 人类在环干预判断
            if human_intervenes():
                expert_action = get_human_action()
                
                # 核心创新：动作反演 (Action Inversion)
                # 通过逐步不动点迭代，逆向求解出能生成 expert_action 的噪声 w_star
                w_star = per_step_fixed_point_inversion(base_policy, obs, expert_action)
                
                intervention_buffer.append((obs, w_star))
                env.step(expert_action)
            else:
                autonomous_buffer.append((obs, w_pred))
                env.step(action)
            
            obs = env.get_obs()
            
            # 4. 混合数据训练噪声策略
            if len(intervention_buffer) > 0:
                batch_interv = sample(intervention_buffer, batch_size // 2)
                batch_auto = sample(autonomous_buffer, batch_size // 2)
                
                # 监督学习：回归反演出的目标噪声
                loss = MSE(noise_policy(batch_interv.obs), batch_interv.w_star) + \
                       MSE(noise_policy(batch_auto.obs), batch_auto.w_pred)
                
                optimize(noise_policy, loss)
```

### 第二模块：核心架构解释

LfH 的核心架构建立在 GRPO（Group Relative Policy Optimization）之上，通过引入一个外部的 VLM（如 Qwen3-VL）作为在线的指令与奖励重打标器。其运行流程如下：

1.  **数据收集与评估:** VLA 策略根据原始指令 $g$ 收集一组（$K$ 个）轨迹。环境给出稀疏奖励。如果该组轨迹的平均奖励较高，说明策略已掌握该任务，直接使用标准 GRPO 更新。
2.  **触发事后重打标:** 如果该组轨迹平均奖励低于设定阈值（如 0.8），说明策略在该指令下失败，触发 LfH 机制。
3.  **指令重打标 (Instruction Relabeling):** 从失败轨迹中随机抽取一条作为锚点（Anchor），输入给 VLM。VLM 判断该轨迹是否包含有意义的物理接触；若有，则生成一个新的“事后指令” $g'$ 来描述机器人实际完成的动作。
4.  **奖励重打标 (Reward Relabeling):** VLM 充当奖励函数，基于新生成的事后指令 $g'$，对该组内的所有 $K$ 个轨迹重新进行二分类评分（成功/失败/不确定）。
5.  **策略更新:** 将重打标后的轨迹组与原始轨迹组混合。由于重打标轨迹的动作是在原始指令 $g$ 下采样的，但在新指令 $g'$ 下进行优化，因此在计算 GRPO 优势函数时，必须引入重要性采样比率进行修正。

**核心伪代码实现：**

```python
def train_lfh_step(policy, vlm, env, original_instruction, K=8, threshold=0.8, lambda_wt=1.0):
    # 1. 收集 Rollouts 并计算原始稀疏奖励
    trajectories = env.rollout(policy, original_instruction, num_rollouts=K)
    rewards = [env.compute_reward(traj, original_instruction) for traj in trajectories]
    mean_reward = sum(rewards) / K
    
    # 2. 标准 GRPO 损失计算
    standard_loss = compute_grpo_loss(policy, trajectories, original_instruction, rewards)
    
    hindsight_loss = 0.0
    # 3. 触发 LfH 机制
    if mean_reward < threshold:
        # 抽取失败轨迹作为锚点
        anchor_traj = sample_failed_trajectory(trajectories, rewards)
        
        # VLM 生成事后指令
        hindsight_instruction = vlm.generate_instruction(anchor_traj)
        
        # 过滤无意义的轨迹（如未发生物理接触）
        if is_meaningful(hindsight_instruction):
            # VLM 对整组轨迹基于新指令重新评分
            hindsight_rewards = [vlm.score(traj, hindsight_instruction) for traj in trajectories]
            
            # 4. 计算带有重要性采样修正的 Hindsight GRPO 损失
            # 修正比率: pi(a | o, hindsight_instruction) / pi_old(a | o, original_instruction)
            hindsight_loss = compute_hindsight_grpo_loss(
                policy, 
                trajectories, 
                original_instruction, 
                hindsight_instruction, 
                hindsight_rewards
            )
            
            # 裁剪 Hindsight 损失以防止早期噪声梯度爆炸
            hindsight_loss = clip_loss(hindsight_loss)
            
    # 5. 联合优化
    total_loss = standard_loss + lambda_wt * hindsight_loss
    policy.update_weights(total_loss)
```

### 第二模块：核心架构解释

FlowDAgger 的核心架构摒弃了对大模型权重的直接修改，转而构建了一个“人类纠正 -> 噪声反演 -> 潜空间策略训练”的闭环系统。

**1. 部署与干预 (Deployment & Intervention)**
系统在真实环境中运行冻结的生成式基础策略（如 VLA 或 WAM）。当机器人表现不佳或即将失败时，人类专家介入并给出正确的动作 $a^*$。此时系统记录下当前的观测 $s$ 和专家动作 $a^*$。

**2. 动作反演 (Action Inversion)**
这是整个框架的灵魂。由于基础策略是一个从噪声 $w$ 到动作 $a$ 的确定性映射（基于常微分方程 ODE 的积分），系统需要找到一个特定的噪声 $w^*$，使得冻结模型输入 $w^*$ 后恰好能输出专家的动作 $a^*$。
对于步数较少的 Flow-matching 模型，直接单步反向计算会产生巨大的线性化误差。作者采用**逐步不动点迭代（Per-step fixed-point iteration）**，从最终动作开始，一步步向后精确求解隐式方程，最终还原出初始噪声 $w^*$。

**3. 噪声策略训练 (Noise Policy Training)**
构建一个极小的多层感知机（MLP）作为噪声策略 $\pi^w$。它的任务是：输入当前观测 $s$，输出反演得到的噪声 $w^*$。为了防止模型在稀疏的人类干预数据上过拟合，训练时采用混合缓冲区：一半数据来自人类干预反演的 $(s, w^*)$，另一半来自基础策略自主成功运行时的历史噪声数据。

**4. 部署推理 (Inference)**
在实际部署时，系统不再从标准正态分布中随机采样噪声，而是将观测 $s$ 输入噪声策略 $\pi^w$ 得到确定性噪声 $w$，再将该噪声送入冻结的基础策略生成最终动作。

**核心逻辑伪代码 (Python 风格)**:

```python
def flowdagger_adaptation_loop(base_policy, env, num_episodes):
    # base_policy: 冻结的预训练生成式策略 (VLA / WAM)
    # noise_policy: 待训练的轻量级网络，初始化输出标准正态噪声
    noise_policy = LightweightMLP()
    intervention_buffer = []
    autonomous_buffer = []

    for episode in range(num_episodes):
        obs = env.reset()
        done = False
        
        while not done:
            # 1. 噪声策略预测当前观测下的最优噪声
            w_pred = noise_policy(obs)
            
            # 2. 冻结的基础策略根据噪声生成动作
            action = base_policy.generate(obs, w_pred)
            
            # 3. 人类在环干预判断
            if human_intervenes():
                expert_action = get_human_action()
                
                # 核心创新：动作反演 (Action Inversion)
                # 通过逐步不动点迭代，逆向求解出能生成 expert_action 的噪声 w_star
                w_star = per_step_fixed_point_inversion(base_policy, obs, expert_action)
                
                intervention_buffer.append((obs, w_star))
                env.step(expert_action)
            else:
                autonomous_buffer.append((obs, w_pred))
                env.step(action)
            
            obs = env.get_obs()
            
            # 4. 混合数据训练噪声策略
            if len(intervention_buffer) > 0:
                batch_interv = sample(intervention_buffer, batch_size // 2)
                batch_auto = sample(autonomous_buffer, batch_size // 2)
                
                # 监督学习：回归反演出的目标噪声
                loss = MSE(noise_policy(batch_interv.obs), batch_interv.w_star) + \
                       MSE(noise_policy(batch_auto.obs), batch_auto.w_pred)
                
                optimize(noise_policy, loss)
```

### 第二模块：核心架构解释

LfH 的核心架构建立在 GRPO（Group Relative Policy Optimization）之上，通过引入一个外部的 VLM（如 Qwen3-VL）作为在线的指令与奖励重打标器。其运行流程如下：

1.  **数据收集与评估:** VLA 策略根据原始指令 $g$ 收集一组（$K$ 个）轨迹。环境给出稀疏奖励。如果该组轨迹的平均奖励较高，说明策略已掌握该任务，直接使用标准 GRPO 更新。
2.  **触发事后重打标:** 如果该组轨迹平均奖励低于设定阈值（如 0.8），说明策略在该指令下失败，触发 LfH 机制。
3.  **指令重打标 (Instruction Relabeling):** 从失败轨迹中随机抽取一条作为锚点（Anchor），输入给 VLM。VLM 判断该轨迹是否包含有意义的物理接触；若有，则生成一个新的“事后指令” $g'$ 来描述机器人实际完成的动作。
4.  **奖励重打标 (Reward Relabeling):** VLM 充当奖励函数，基于新生成的事后指令 $g'$，对该组内的所有 $K$ 个轨迹重新进行二分类评分（成功/失败/不确定）。
5.  **策略更新:** 将重打标后的轨迹组与原始轨迹组混合。由于重打标轨迹的动作是在原始指令 $g$ 下采样的，但在新指令 $g'$ 下进行优化，因此在计算 GRPO 优势函数时，必须引入重要性采样比率进行修正。

**核心伪代码实现：**

```python
def train_lfh_step(policy, vlm, env, original_instruction, K=8, threshold=0.8, lambda_wt=1.0):
    # 1. 收集 Rollouts 并计算原始稀疏奖励
    trajectories = env.rollout(policy, original_instruction, num_rollouts=K)
    rewards = [env.compute_reward(traj, original_instruction) for traj in trajectories]
    mean_reward = sum(rewards) / K
    
    # 2. 标准 GRPO 损失计算
    standard_loss = compute_grpo_loss(policy, trajectories, original_instruction, rewards)
    
    hindsight_loss = 0.0
    # 3. 触发 LfH 机制
    if mean_reward < threshold:
        # 抽取失败轨迹作为锚点
        anchor_traj = sample_failed_trajectory(trajectories, rewards)
        
        # VLM 生成事后指令
        hindsight_instruction = vlm.generate_instruction(anchor_traj)
        
        # 过滤无意义的轨迹（如未发生物理接触）
        if is_meaningful(hindsight_instruction):
            # VLM 对整组轨迹基于新指令重新评分
            hindsight_rewards = [vlm.score(traj, hindsight_instruction) for traj in trajectories]
            
            # 4. 计算带有重要性采样修正的 Hindsight GRPO 损失
            # 修正比率: pi(a | o, hindsight_instruction) / pi_old(a | o, original_instruction)
            hindsight_loss = compute_hindsight_grpo_loss(
                policy, 
                trajectories, 
                original_instruction, 
                hindsight_instruction, 
                hindsight_rewards
            )
            
            # 裁剪 Hindsight 损失以防止早期噪声梯度爆炸
            hindsight_loss = clip_loss(hindsight_loss)
            
    # 5. 联合优化
    total_loss = standard_loss + lambda_wt * hindsight_loss
    policy.update_weights(total_loss)
```

### 第二模块：核心架构解释

GenVid2Robot 的核心逻辑是构建一个从“视觉想象”到“物理执行”的过滤与映射管道。其架构可拆解为以下四个关键阶段：

1. **假设生成与锚点初始化**：接收初始 RGB-D 观测和自然语言指令，利用视频生成模型生成多个候选视频。同时，在真实首帧图像上提取与任务相关的语义锚点（Semantic Anchors），并获取其对应的 3D 坐标（依赖深度图）。
2. **跨帧追踪与几何一致性验证**：使用点追踪算法将首帧锚点在生成的候选视频中进行时序追踪。随后，利用首帧的 3D 锚点和后续帧的 2D 追踪结果，求解相对 $SE(3)$ 刚体变换矩阵。如果生成的 2D 运动无法用统一的 $SE(3)$ 变换解释（即违背刚体物理规律），则丢弃该视频假设。
3. **抓取条件轨迹生成**：通过掩码约束确定真实的抓取点（TCP 位姿）。将上一步验证通过的相对 $SE(3)$ 运动轨迹，直接作用于这个真实的抓取位姿上，生成符合机器人运动学的执行轨迹。
4. **闭环执行与深度补偿**：在物理执行阶段，不依赖全局在线重规划，而是引入一个有界深度补偿模块，利用实时的局部反馈修正由 RGB-D 噪声、标定误差或轻微接触引起的深度方向偏移。

```python
def GenVid2Robot(initial_rgbd, instruction, video_generator, tracker):

    video_candidates = video_generator.generate(initial_rgbd.rgb, instruction, num_samples=N)
    
    # 2. 提取首帧语义锚点及其 3D 坐标
    anchors_2d = extract_semantic_anchors(initial_rgbd.rgb, instruction)

        tracked_2d_points = tracker.track(video, anchors_2d)
        
        # 4. 刚体几何一致性验证与 SE(3) 求解

            best_trajectory = se3_trajectory
            break # 找到第一个符合物理规律的假设
            
    if best_trajectory is None:
        raise Exception("No physically executable video hypothesis found.")
        
    # 5. 结合真实抓取位姿生成最终轨迹
    real_grasp_pose = compute_mask_constrained_grasp(initial_rgbd)

    for target_pose in execution_trajectory:
```

```python
        # 提取历史帧特征，并基于几何变换进行长程记忆对齐
        memory_features = self.gma_module(context_frames, translations)
        
        # 步骤 3: 密集全景射线条件 (DPRC)
        # 将平移动作编码为密集的空间射线先验
        ray_conditions = self.dprc_module(translations)
        
        # 步骤 4: 扩散模型生成
        # 网络仅需学习平移动力学，旋转通过隐式几何变换处理
        predicted_frames = self.video_diffusion(
            features=memory_features,
            spatial_conditions=ray_conditions,
            rotations=implicit_rotations
        )
        
        return predicted_frames
        
    def decouple_trajectory(self, actions):
        # 剥离旋转矩阵与平移向量的底层实现
        translations = extract_translation(actions)
        rotations = extract_rotation(actions)
        return translations, rotations
```

### 第二模块：核心架构解释

CD-LAM 的核心在于不改变下游世界模型架构的前提下，通过三个阶段重塑潜在动作空间。

**阶段一：LAM 去偏微调 (LAM Debiased Fine-tuning)**
这是本文的核心创新。在无动作标签的视频上，使用三个联合损失函数微调 LAM 编码器：
1.  **具身中心重建 ($L_{emb}$):** 引入 SAM3 提取的前景掩码，对运动主体和被操作物体的重建赋予高权重，背景赋予低权重。
2.  **动作中心对比学习 ($L_{ctr}$):** 基于粗粒度动词标签，将相同动作原语的视频帧对在潜在空间拉近，不同动作的推开。
3.  **潜在空间校准 ($L_{cal}$):** 包含 Free-bit KL 散度（防止信息坍塌）和零转移校准（强制输入两张相同帧时，输出的潜在动作向量的范数趋近于 0）。

**阶段二：ACWM 去偏微调 (ACWM Debiased Fine-tuning)**
冻结去偏后的 LAM，提取视频的潜在动作 $z^{CD}_t$，以此作为条件输入，继续在无标签视频上微调动作条件世界模型（ACWM），让世界模型适应这个干净的控制空间。

**阶段三：机器人动作适配 (Robot Action Adaptation)**
引入真实的机器人动作数据 $(o_t, u_t, o_{t+1})$。训练一个轻量级的 MLP 桥接网络，将真实的物理控制指令 $u_t$ 映射到冻结的去偏潜在空间中，实现最终的具身控制。

```python
    # Pull same primitives together, push different apart
    z_proj = projection_head(z_t)
    L_ctr = contrastive_loss(z_proj, action_primitive_label)

    # Force zero-transition latent norm to be close to 0
    running_rms = stop_gradient(compute_rms(z_t))

    L_kl = free_bit_kl_divergence(z_t)
    L_cal = L_zero + L_kl
    
    # Total Stage 1 Loss
    return L_emb + lambda_ctr * L_ctr + lambda_cal * L_cal
```

PDE 的核心架构分为两个解耦的阶段：提示词发现（Prompt Discovery）与策略优化（Policy Optimization）。

**1. 提示词后验更新阶段 (Prompt-posterior update)**
在此阶段，VLA 策略的权重被冻结。系统将 VLM 视为一个隐式的提示词后验采样器。对于给定的任务，VLM 根据原始提示词和历史 Rollout 轨迹（视频），诊断当前 VLA 策略的失败原因，并生成新的候选提示词。VLA 使用这些新提示词在环境中执行动作，如果获得了非零奖励，该提示词及其成功率将被记录到一个“成功提示词池”中。

**2. 策略优化阶段 (RL update with Mixed Backpropagation)**
当提示词池收集到足够的成功提示词后，进入 RL 训练阶段。为了防止模型只在“探索提示词”下成功而在“原始提示词”下失败，作者设计了两种对齐机制：
- **混合采样 (Mixture Sampling):** 在收集训练数据时，以动态比例 $\alpha$ 混合使用原始提示词和提示词池中的探索提示词。随着原始提示词成功率的上升，逐渐增加原始提示词的采样权重。
- **混合反向传播 (Mixed Backpropagation):** 在计算 PPO 的损失函数时，强制计算动作在“探索提示词”和“原始提示词”下的对数概率（Log-probability）的平均值。这迫使梯度更新朝着“在两种提示词下都极有可能发生”的动作方向优化，从而将探索到的成功行为蒸馏回原始指令。

**底层逻辑伪代码实现：**

```python
def prompt_driven_exploration(vla_policy, vlm_supervisor, task, canonical_prompt, iterations):
    prompt_pool = []
    history = []
    
    # 阶段一：提示词后验采样 (Prompt Discovery)
    # 冻结 VLA 权重，寻找能触发成功行为的提示词
    for _ in range(prompt_search_steps):
        # VLM 根据历史反馈生成新提示词
        candidate_prompt = vlm_supervisor.generate_prompt(canonical_prompt, history)
        
        # VLA 执行 Rollout
        trajectory, reward = vla_policy.rollout(task, candidate_prompt)
        
        # VLM 总结视频中的失败/成功原因
        summary = vlm_supervisor.summarize_video(trajectory)
        history.append((candidate_prompt, summary, reward))
        
        # 记录成功的提示词
        if reward > 0:
            prompt_pool.append(candidate_prompt)
            
    # 阶段二：策略优化 (RL Update)
    # 解冻 VLA 权重，使用 PPO 进行微调
    for _ in range(rl_steps):
        # 动态混合采样提示词用于收集数据
        rollout_prompt = sample_from_mixture(canonical_prompt, prompt_pool, alpha_t)
        trajectory, reward = vla_policy.rollout(task, rollout_prompt)
        
        # 核心创新：混合反向传播 (Mixed Backpropagation)
        for state, action in trajectory:
            # 分别计算在探索提示词和原始提示词下的 log prob
            log_prob_exp = vla_policy.get_log_prob(action, state, rollout_prompt)
            log_prob_can = vla_policy.get_log_prob(action, state, canonical_prompt)
            
            # 对应论文 Eq. 3: 平均对数概率，将行为锚定回原始指令
            mixed_log_prob = 0.5 * log_prob_exp + 0.5 * log_prob_can
            
            # 标准 PPO 优势函数更新
            ppo_update(vla_policy.weights, mixed_log_prob, reward)
            
    return vla_policy
```

### 第二模块：核心架构解释

AOD-JEPA 的核心逻辑是将主动视觉任务解耦为“基于世界模型的鲁棒表征学习”与“基于强化学习的动作策略”两个阶段。

首先，无人机在飞行过程中获取当前视角的图像观测。传统的 DRL 方法直接将图像输入策略网络，容易过拟合训练场景。AOD-JEPA 引入了联合嵌入预测架构（JEPA）。在表征学习阶段，编码器将当前观测映射到潜在空间（Latent Space），预测器结合无人机的动作（如相机云台转动或无人机移动），在潜在空间中预测下一个状态的表征。目标编码器（通常通过指数移动平均 EMA 更新）对真实的下一帧观测进行编码，作为预测的监督信号。
这种自监督机制迫使模型理解“动作如何改变观测”的物理规律，过滤掉无关的背景噪声。在策略执行阶段，冻结或微调后的编码器输出高维度的鲁棒状态向量，输入给 DRL 智能体（如 PPO 算法），智能体据此输出最优的下一步动作，以寻找最佳视角，最大化目标检测的置信度。

**核心伪代码实现逻辑**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class AOD_JEPA(nn.Module):
    def __init__(self, encoder, predictor, policy_net, tau=0.99):
        super().__init__()
        self.encoder = encoder                  # 状态编码器
        self.predictor = predictor              # 潜在空间动态预测器
        self.policy_net = policy_net            # DRL策略网络 (如 PPO/SAC)
        
        # 初始化目标编码器 (用于提供自监督信号)
        self.target_encoder = copy.deepcopy(encoder)
        self.tau = tau                          # EMA 动量参数
        
        # 冻结目标编码器的梯度
        for param in self.target_encoder.parameters():
            param.requires_grad = False

    def update_target_encoder(self):
        # 通过指数移动平均 (EMA) 更新目标编码器
        for param, target_param in zip(self.encoder.parameters(), self.target_encoder.parameters()):
            target_param.data = self.tau * target_param.data + (1 - self.tau) * param.data

    def world_model_learning_step(self, obs_t, action_t, obs_t_plus_1):
        """世界模型表征学习阶段"""
        # 1. 编码当前状态
        z_t = self.encoder(obs_t)
        
        # 2. 结合动作，预测下一个状态的潜在表征
        z_pred_t_plus_1 = self.predictor(z_t, action_t)
        
        # 3. 获取真实的下一个状态的潜在表征 (无梯度)
        with torch.no_grad():
            z_target_t_plus_1 = self.target_encoder(obs_t_plus_1)
            
        # 4. 计算 JEPA 损失 (如 L2 距离)，结合 AOD 先验知识
        loss_jepa = F.mse_loss(z_pred_t_plus_1, z_target_t_plus_1)
        return loss_jepa

    def policy_step(self, obs_t):
        """主动目标检测策略执行阶段"""
        # 使用编码器提取鲁棒状态特征 (可冻结梯度以防止策略崩溃)
        with torch.no_grad():
            z_t = self.encoder(obs_t)
            
        # DRL 策略网络输出主动视觉动作 (如调整无人机视角)
        action = self.policy_net(z_t)
        return action
```

### 第二模块：核心架构解释

BeyondSight 的核心架构建立在 SparseDrive 的稀疏查询（Sparse Query）机制之上，将其改造为一个符合贝叶斯滤波逻辑（先验 -> 观测 -> 后验）的持久化推理流水线。

**运行流程拆解**：
1. **时序先验解码器 (Temporal Prior Decoder)**：接收上一帧的目标查询 $q_{t-1}$，仅利用查询本身的特征和运动学预测进行自注意力交互，输出运动条件假设 $q_t^{prior}$。此阶段**绝对不接触**当前帧的图像特征，确保被遮挡目标不会因缺乏视觉证据而被抹杀。
2. **观测解码器 (Observation Decoder)**：将先验查询 $q_t^{prior}$ 与新初始化的查询结合，去交叉注意力提取当前帧的 BEV 视觉特征 $F_t$，输出观测条件假设 $q_t^{obs}$。此阶段仅使用可见目标的 Ground Truth 进行监督。
3. **后验融合解码器 (Posterior Fusion Decoder)**：将纯运动学推导的 $q_t^{prior}$ 与视觉更新的 $q_t^{obs}$ 进行对齐和融合，输出最终的场景表征 $q_t^{post}$。此阶段同时使用可见与不可见目标的 Ground Truth 进行监督，强制模型保留被遮挡目标的表征，并送入下游轨迹预测与规划模块。

**核心伪代码实现**：

```python
class BeyondSight(nn.Module):
    def __init__(self, backbone, prior_decoder, obs_decoder, fusion_decoder, planner):
        super().__init__()
        self.backbone = backbone
        self.prior_decoder = prior_decoder
        self.obs_decoder = obs_decoder
        self.fusion_decoder = fusion_decoder
        self.planner = planner

    def forward(self, images_t, q_prev):
        # 1. 提取当前帧 BEV 特征
        F_t = self.backbone(images_t)
        
        # 2. 时序先验阶段 (Temporal Prior) - 仅依赖历史，不看当前图像
        # 对应公式 (3): q_prior = D_prior(q_{t-1})
        q_prior = self.prior_decoder(q_prev)
        
        # 3. 观测更新阶段 (Observation) - 结合当前视觉特征
        # 对应公式 (4): q_obs = D_obs(F_t, q_prior)
        q_obs = self.obs_decoder(F_t, q_prior)
        
        # 4. 后验融合阶段 (Posterior Fusion) - 调和先验与观测
        # 对应公式 (5): q_post = D_fusion(q_prior, q_obs)
        q_post = self.fusion_decoder(q_prior, q_obs)
        
        # 5. 下游预测与规划
        # 规划器现在能看到 q_post 中包含的“不可见目标”
        plan_trajectory = self.planner(q_post)
        
        return q_post, plan_trajectory

    def compute_loss(self, q_obs, q_post, gt_visible, gt_all):
        # 观测解码器仅用可见目标监督
        loss_obs = bipartite_match_loss(q_obs, gt_visible)
        
        # 后验解码器用所有目标（含被遮挡目标）监督，强制维持客体永久性
        loss_post = bipartite_match_loss(q_post, gt_all)
        
        # 显式监督目标的可观测性状态 (公式 12)
        loss_visibility = bce_loss(q_post.visibility_logits, gt_all.visibility_labels)
        
        return loss_obs + loss_post + loss_visibility
```

### 第一模块：一分钟核心速写

**论文领域**：VLA (Vision-Action)

**TL;DR**: PAC-ACT 提出了一种基于强化学习后训练（RL Post-training）的动作分块策略（Action Chunking）微调框架，以解决工业精密接触任务中行为克隆导致的分布偏移与接触力超限问题，在 Metal Touch 和 Square Assembly 基准上实现了任务成功率与力控安全性的显著提升。

### 第二模块：核心架构解释

PAC-ACT 的核心在于将预训练的 ACT 模型无缝接入 PPO 强化学习框架。其架构与流程分为三个关键部分：

1. **Chunk-level MDP 重构**
将 $c$ 个环境步合并为一个 Chunk 步。策略在时间步 $\tau$ 观察状态 $s_\tau$，直接输出长度为 $c$ 的动作序列。环境连续执行这 $c$ 个动作，累加奖励，并计算 Chunk 级别的广义优势估计（GAE）。这解决了单步 RL 无法对齐分块动作信用的问题。

2. **ACT-transferred Actor-Critic 架构**
- **Actor**：继承预训练 ACT 的视觉编码器和 Transformer 编码器/解码器。核心改造是**移除 CVAE 模块**，直接将网络输出作为对角高斯分布的均值。这消除了 CVAE 潜在变量带来的冗余随机性，避免与 RL 优化方向冲突。
- **Critic**：复用 Actor 的视觉编码器和 Transformer 编码器，但**移除解码器**。通过池化层（Mean Pooling）和 MLP 直接输出标量状态价值 $V(s)$，大幅降低了参数量和计算开销。

3. **混合行为先验约束 (Hybrid Behavior-Prior Constraint)**
- **奖励层基线惩罚**：计算当前策略输出动作与冻结的预训练 ACT 输出动作之间的均方误差（MSE），作为环境奖励的扣减项。
- **损失层 KL 正则化**：在 PPO 的目标函数中加入相邻策略更新间的 KL 散度惩罚，防止策略在连续高维动作空间中发生灾难性漂移。

**核心伪代码 (Python-style)**:

```python
def pac_act_ppo_update(env, actor, critic, pretrained_actor, c_chunk_size):
    # 1. Rollout Collection (Chunk-level)
    trajectories = []
    for _ in range(num_episodes):
        state = env.reset()
        for t in range(max_steps // c_chunk_size):
            # Actor outputs a chunk of actions (length c)
            action_mean = actor(state) 
            action_chunk = sample_gaussian(action_mean, std)
            
            # Baseline penalty: deviation from pretrained policy
            pretrained_action = pretrained_actor(state).detach()
            baseline_penalty = beta2 * MSE(action_chunk, pretrained_action)
            
            # Execute chunk in environment
            chunk_reward = 0
            for i in range(c_chunk_size):
                next_state, step_reward, done = env.step(action_chunk[i])
                chunk_reward += step_reward
            
            # Apply behavior-prior constraint at reward level
            modified_reward = chunk_reward - baseline_penalty
            
            value = critic(state)
            trajectories.append((state, action_chunk, modified_reward, value, next_state))
            state = next_state
            
    # 2. Chunk-level Advantage Estimation
    advantages, returns = compute_gae_chunk_level(trajectories, gamma_chunk=0.99**c_chunk_size)
    
    # 3. PPO Update with Hybrid KL Constraint
    for epoch in range(ppo_epochs):
        for batch in get_batches(trajectories):
            new_action_mean = actor(batch.states)
            new_values = critic(batch.states)
            
            # Standard PPO Clipped Loss
            ratio = compute_prob_ratio(new_action_mean, batch.actions, batch.old_action_mean)
            surr_loss = compute_clipped_surrogate(ratio, batch.advantages)
            
            # KL Regularization (Loss level)
            kl_penalty = beta1 * compute_kl_divergence(batch.old_action_mean, new_action_mean)
            
            # Value Loss
            value_loss = MSE(new_values, batch.returns)
            
            # Total Loss
            total_loss = -surr_loss + kl_penalty + value_loss
            
            optimizer.zero_grad()
            total_loss.backward()
            optimizer.step()
```
