1. **VLA前向传播与RL Token提取**：在每个时间步，冻结的VLA模型接收当前视角的图像和自然语言指令。在VLA的Transformer架构中，提取特定层（通常是最后一层）的隐藏状态或专门附加的Token，作为“RL Token”。这个Token浓缩了当前状态的视觉-语言-动作上下文。

3. **策略锚定（Policy Anchoring）**：在RL训练初期，为了防止随机探索破坏VLA原有的泛化能力，计算Actor输出的动作分布与VLA原始输出动作之间的散度（如KL散度或行为克隆损失），将其作为惩罚项加入到RL的目标函数中。

### 第二模块：核心架构解释

AgenticCache 的系统架构分为两个完全异步运行的模块：作为本地规划器的缓存系统（AgenticCache Structure）和作为全局校验器的后台更新系统（Cache Updater）。

1. **本地缓存规划器（主执行线程）**：
   - **状态匹配与过滤**：缓存中存储了历史的 2-gram 计划转移对（$P_i \to P_j$）及其发生时的环境元数据区间（如步骤数、持有物品数）。当智能体完成计划 $P_i$ 时，系统提取当前环境元数据，过滤掉不符合当前状态区间的候选计划 $P_j$。
   - **复合评分选择**：对剩余的候选计划进行打分。评分公式为 $S = C \times I$，其中 $C$ 是该转移在局部历史中发生的频次（Count），$I$ 是该计划被后台 LLM 确认正确的全局概率（Importance）。系统选择得分最高的计划立即执行。

2. **后台缓存更新器（异步 LLM 线程）**：
   - **异步查询与比对**：更新器在后台定期向 LLM 发送当前观测状态，请求最优计划。由于 LLM 推理存在延迟，当 LLM 返回计划 $p'_{t+k}$ 时，智能体可能已经根据缓存执行到了第 $t+k$ 步。更新器会将 LLM 的输出与智能体实际执行的轨迹进行比对。
   - **确认与修正机制**：如果 LLM 的计划与智能体轨迹一致，更新器增加该缓存条目的频次和重要性权重；如果 LLM 给出了不同的计划，说明缓存预测失败，更新器会降低错误条目的权重，将 LLM 的新计划写入缓存，并强制中断智能体当前动作，替换为正确的计划。
   - **查询抑制**：为节省 Token，当 LLM 确认当前计划正确，或刚刚完成一次计划替换时，更新器会暂停发送新的 LLM 请求，直到当前计划执行完毕。

```python
import threading

class AgenticCache:
    def __init__(self, llm_planner):
        self.cache = {} # Stores transition P_i -> P_j with metadata and scores
        self.llm = llm_planner
        self.current_plan = "Explore"
        self.trajectory = []
        self.lock = threading.Lock()

    def local_planning_loop(self, env):
        while not env.is_done():
            state_metadata = env.get_metadata()
            
            with self.lock:
                # 1. Filter candidates based on state metadata ranges
                candidates = self.filter_by_metadata(self.cache.get(self.current_plan, []), state_metadata)
                
                if candidates:
                    # 2. Select plan with max (Count * Importance)
                    next_plan = max(candidates, key=lambda p: p.count * p.importance)
                else:
                    # Cache miss: synchronous fallback
                    next_plan = self.llm.generate_plan(env.get_observation())
                    self.add_to_cache(self.current_plan, next_plan, state_metadata)
                
                self.current_plan = next_plan
                self.trajectory.append(next_plan)
            
            # Execute plan in environment
            env.execute(self.current_plan)

    def async_updater_loop(self, env):
        while not env.is_done():
            obs = env.get_observation()
            active_plan = self.current_plan
            
            # Asynchronous LLM call
            llm_plan = self.llm.generate_plan(obs)
            
            with self.lock:
                if llm_plan in self.trajectory[-RECENT_WINDOW:]:
                    # Confirmation: Cache was correct
                    self.reinforce_cache_entry(active_plan, llm_plan)
                    self.suppress_queries_until_plan_ends()
                else:
```

### 第二模块：核心架构解释

MoT-HRA 的核心架构是一个多任务混合 Transformer (Mixture-of-Transformers)，其前向传播与实验流程严格遵循“感知 -> 空间锚定 -> 意图生成 -> 动作映射”的层级逻辑：

1. **多模态上下文构建**：输入图像和文本指令，通过预训练的视觉-语言主干网络（双向注意力）提取共享的多模态 Token。
2. **视觉-语言专家 (Vision-Language Expert)**：接收多模态 Token，通过自回归方式预测离散化的 3D 空间轨迹（Waypoints）。这一步剥离了具身差异，仅解决“在哪里发生交互”的几何基础。
3. **意图专家 (Intention Expert)**：以 3D 轨迹和多模态上下文为条件，使用条件流匹配 (Conditional Flow Matching) 预测 MANO 格式的人类手部姿态序列。这一步将人类视频中的运动规律转化为显式的物理意图空间。
4. **精细专家 (Fine Expert)**：同样基于条件流匹配，接收前置专家的隐状态，生成特定具身（如机械臂夹爪或灵巧手）的动作块 (Action Chunks)。
5. **知识隔离 (Knowledge Insulation)**：在训练和推理时，意图专家和精细专家只能通过单向的注意力机制读取上游的 Key-Value 缓存。精细专家的损失梯度不会反向传播更新意图专家的参数，从而保护人类运动先验不被特定机器人的动作数据覆盖。

```python
import torch
import torch.nn as nn

class MoTHRA(nn.Module):
    def __init__(self):
        super().__init__()
        self.shared_vl_encoder = PretrainedVLM()
        self.trajectory_expert = AutoregressiveTransformer()
        self.intention_expert = FlowMatchingHead(dim=MANO_DIM)
        self.fine_expert = FlowMatchingHead(dim=ROBOT_ACTION_DIM)
        
    def forward(self, image, text, robot_action_target=None, mano_target=None):
        # 1. 构建共享多模态上下文 (Bidirectional Attention)
        vl_context = self.shared_vl_encoder(image, text)
        
        # 2. 视觉-语言专家：预测 3D 轨迹 (Autoregressive)
        # 产生轨迹隐状态 trajectory_hidden
        traj_pred, trajectory_hidden = self.trajectory_expert(vl_context)
        
        # 3. 意图专家：预测 MANO 手部姿态 (Flow Matching)
        # 知识隔离：使用 .detach() 或 Read-only Attention 阻断梯度回传到轨迹专家
        intention_cond = torch.cat([vl_context, trajectory_hidden.detach()], dim=-1)
        mano_pred, intention_hidden = self.intention_expert(intention_cond, target=mano_target)
        
        # 4. 精细专家：预测特定具身机器人动作 (Flow Matching)
        # 知识隔离：阻断梯度回传到意图专家
        action_cond = torch.cat([vl_context, trajectory_hidden.detach(), intention_hidden.detach()], dim=-1)
        action_pred = self.fine_expert(action_cond, target=robot_action_target)
        
        return traj_pred, mano_pred, action_pred

    def compute_loss(self, traj_pred, mano_pred, action_pred, targets, has_mano, has_robot):
        # 联合训练策略：根据数据源动态计算损失
        loss_3d = cross_entropy(traj_pred, targets['trajectory'])
        
        # 人类视频数据有 MANO 标签，无 Robot 标签
        loss_mano = flow_matching_loss(mano_pred, targets['mano']) if has_mano else 0.0
        
        # 机器人数据有 Robot 标签，无 MANO 标签
        loss_action = flow_matching_loss(action_pred, targets['robot']) if has_robot else 0.0
        
        return loss_3d + loss_mano + loss_action
```

**第二模块：核心架构解释**

DeLock 框架分为训练期（Training）和推理期（Inference）两个解耦的阶段。

**1. 训练期：视觉编码器权重漂移正则化 (Visual Encoder Weight-Drift Regularization)**
- **流程**：在标准行为克隆（Behavioral Cloning）微调中，使用 LoRA 更新语言主干和动作专家网络。对于视觉编码器，不使用硬冻结，而是允许其更新，但引入 L2 正则化惩罚其偏离原始预训练权重的程度。
- **目的**：在学习下游特定任务动作的同时，强制保留预训练模型中对物体概念和空间关系的视觉定位（Visual Grounding）能力。

**2. 推理期：测试时对比提示引导 (Contrastive Prompt Guidance, CPG)**
- **流程**：基于 Flow-Matching 的动作生成机制。在每一个去噪步，模型分别以“新指令（正向提示）”和“训练指令（负向提示）”作为条件进行两次前向传播，得到两个去噪向量场。
- **目的**：提取正负向量场的差值，并乘以引导系数，叠加到负向向量场上。这在数学上放大了与新指令相关的动作方向，同时抵消了模型因微调产生的对训练目标的固有偏置。

**核心伪代码实现**：

```python
# Training Phase: Weight-Drift Regularization
def train_step(batch, model, pre_trained_visual_weights, lambda_reg):
    obs, action, prompt = batch
    
    # Forward pass
    pred_action = model(obs, prompt)
    loss_bc = mse_loss(pred_action, action)
    
    # L2 Regularization on visual encoder
    current_visual_weights = model.visual_encoder.parameters()
    loss_reg = lambda_reg * l2_distance(current_visual_weights, pre_trained_visual_weights)
    
    total_loss = loss_bc + loss_reg
    total_loss.backward()
    optimizer.step()

# Inference Phase: Contrastive Prompt Guidance (Flow-Matching)
def generate_action(obs, novel_prompt, trained_prompt, model, num_steps, guidance_scale):
    # Initialize noisy action chunk
    action_t = sample_gaussian_noise()
    dt = -1.0 / num_steps
    
    for t in range(1.0, 0.0, dt): # Denoising from t=1 to t=0
        # Forward pass with novel (positive) prompt
        v_pos = model.predict_vector_field(obs, novel_prompt, action_t, t)
        
        # Forward pass with trained (negative) prompt
        v_neg = model.predict_vector_field(obs, trained_prompt, action_t, t)
        
        # Contrastive guidance rule
        v_cpg = v_neg + guidance_scale * (v_pos - v_neg)
        
        # Euler update step
        action_t = action_t + dt * v_cpg
        
    return action_t
```

### 第二模块：核心架构解释

该框架的核心逻辑是将庞大的VLA模型与轻量级的强化学习算法解耦。具体流程如下：

1. **VLA前向传播与RL Token提取**：在每个时间步，冻结的VLA模型接收当前视角的图像和自然语言指令。在VLA的Transformer架构中，提取特定层（通常是最后一层）的隐藏状态或专门附加的Token，作为“RL Token”。这个Token浓缩了当前状态的视觉-语言-动作上下文。
2. **轻量级Actor-Critic网络**：将提取出的RL Token输入到一个小型的多层感知机（MLP）中。Actor网络输出当前状态下的动作分布（均值和方差），Critic网络输出当前状态的价值评估（Q值）。
3. **策略锚定（Policy Anchoring）**：在RL训练初期，为了防止随机探索破坏VLA原有的泛化能力，计算Actor输出的动作分布与VLA原始输出动作之间的散度（如KL散度或行为克隆损失），将其作为惩罚项加入到RL的目标函数中。
4. **在线交互与更新**：机器人在真实环境中执行Actor采样的动作，获得环境反馈的Reward和Next State。将这些经验存入回放缓冲区（Replay Buffer），使用标准的RL算法（如SAC）更新轻量级Actor-Critic头的参数。

### 第二模块：核心架构解释

AgenticCache 的系统架构分为两个完全异步运行的模块：作为本地规划器的缓存系统（AgenticCache Structure）和作为全局校验器的后台更新系统（Cache Updater）。

1. **本地缓存规划器（主执行线程）**：
   - **状态匹配与过滤**：缓存中存储了历史的 2-gram 计划转移对（$P_i \to P_j$）及其发生时的环境元数据区间（如步骤数、持有物品数）。当智能体完成计划 $P_i$ 时，系统提取当前环境元数据，过滤掉不符合当前状态区间的候选计划 $P_j$。
   - **复合评分选择**：对剩余的候选计划进行打分。评分公式为 $S = C \times I$，其中 $C$ 是该转移在局部历史中发生的频次（Count），$I$ 是该计划被后台 LLM 确认正确的全局概率（Importance）。系统选择得分最高的计划立即执行。

2. **后台缓存更新器（异步 LLM 线程）**：
   - **异步查询与比对**：更新器在后台定期向 LLM 发送当前观测状态，请求最优计划。由于 LLM 推理存在延迟，当 LLM 返回计划 $p'_{t+k}$ 时，智能体可能已经根据缓存执行到了第 $t+k$ 步。更新器会将 LLM 的输出与智能体实际执行的轨迹进行比对。
   - **确认与修正机制**：如果 LLM 的计划与智能体轨迹一致，更新器增加该缓存条目的频次和重要性权重；如果 LLM 给出了不同的计划，说明缓存预测失败，更新器会降低错误条目的权重，将 LLM 的新计划写入缓存，并强制中断智能体当前动作，替换为正确的计划。
   - **查询抑制**：为节省 Token，当 LLM 确认当前计划正确，或刚刚完成一次计划替换时，更新器会暂停发送新的 LLM 请求，直到当前计划执行完毕。

**核心逻辑伪代码**：

```python
import threading

class AgenticCache:
    def __init__(self, llm_planner):
        self.cache = {} # Stores transition P_i -> P_j with metadata and scores
        self.llm = llm_planner
        self.current_plan = "Explore"
        self.trajectory = []
        self.lock = threading.Lock()

    def local_planning_loop(self, env):
        while not env.is_done():
            state_metadata = env.get_metadata()
            
            with self.lock:
                # 1. Filter candidates based on state metadata ranges
                candidates = self.filter_by_metadata(self.cache.get(self.current_plan, []), state_metadata)
                
                if candidates:
                    # 2. Select plan with max (Count * Importance)
                    next_plan = max(candidates, key=lambda p: p.count * p.importance)
                else:
                    # Cache miss: synchronous fallback
                    next_plan = self.llm.generate_plan(env.get_observation())
                    self.add_to_cache(self.current_plan, next_plan, state_metadata)
                
                self.current_plan = next_plan
                self.trajectory.append(next_plan)
            
            # Execute plan in environment
            env.execute(self.current_plan)

    def async_updater_loop(self, env):
        while not env.is_done():
            obs = env.get_observation()
            active_plan = self.current_plan
            
            # Asynchronous LLM call
            llm_plan = self.llm.generate_plan(obs)
            
            with self.lock:
                if llm_plan in self.trajectory[-RECENT_WINDOW:]:
                    # Confirmation: Cache was correct
                    self.reinforce_cache_entry(active_plan, llm_plan)
                    self.suppress_queries_until_plan_ends()
                else:
                    # Correction: Cache was wrong
                    self.penalize_cache_entry(active_plan, self.current_plan)
                    self.add_to_cache(active_plan, llm_plan, env.get_metadata())
                    # Immediate plan replacement
                    self.current_plan = llm_plan
                    env.interrupt_and_replace_action(llm_plan)
                    self.suppress_queries_until_plan_ends()

# Execution
agent_system = AgenticCache(LLM())
threading.Thread(target=agent_system.local_planning_loop, args=(env,)).start()
threading.Thread(target=agent_system.async_updater_loop, args=(env,)).start()
```

### 第二模块：核心架构解释

MoT-HRA 的核心架构是一个多任务混合 Transformer (Mixture-of-Transformers)，其前向传播与实验流程严格遵循“感知 -> 空间锚定 -> 意图生成 -> 动作映射”的层级逻辑：

1. **多模态上下文构建**：输入图像和文本指令，通过预训练的视觉-语言主干网络（双向注意力）提取共享的多模态 Token。
2. **视觉-语言专家 (Vision-Language Expert)**：接收多模态 Token，通过自回归方式预测离散化的 3D 空间轨迹（Waypoints）。这一步剥离了具身差异，仅解决“在哪里发生交互”的几何基础。
3. **意图专家 (Intention Expert)**：以 3D 轨迹和多模态上下文为条件，使用条件流匹配 (Conditional Flow Matching) 预测 MANO 格式的人类手部姿态序列。这一步将人类视频中的运动规律转化为显式的物理意图空间。
4. **精细专家 (Fine Expert)**：同样基于条件流匹配，接收前置专家的隐状态，生成特定具身（如机械臂夹爪或灵巧手）的动作块 (Action Chunks)。

```python
class MoTHRA(nn.Module):
    def __init__(self):
        super().__init__()
        self.shared_vl_encoder = PretrainedVLM()
        self.trajectory_expert = AutoregressiveTransformer()
        self.intention_expert = FlowMatchingHead(dim=MANO_DIM)
        self.fine_expert = FlowMatchingHead(dim=ROBOT_ACTION_DIM)
        
    def forward(self, image, text, robot_action_target=None, mano_target=None):
        # 1. 构建共享多模态上下文 (Bidirectional Attention)
        vl_context = self.shared_vl_encoder(image, text)
        
        # 2. 视觉-语言专家：预测 3D 轨迹 (Autoregressive)
        # 产生轨迹隐状态 trajectory_hidden
        traj_pred, trajectory_hidden = self.trajectory_expert(vl_context)

        # 知识隔离：使用 .detach() 或 Read-only Attention 阻断梯度回传到轨迹专家
        intention_cond = torch.cat([vl_context, trajectory_hidden.detach()], dim=-1)
        mano_pred, intention_hidden = self.intention_expert(intention_cond, target=mano_target)
        
        # 4. 精细专家：预测特定具身机器人动作 (Flow Matching)
        # 知识隔离：阻断梯度回传到意图专家
        action_cond = torch.cat([vl_context, trajectory_hidden.detach(), intention_hidden.detach()], dim=-1)
        action_pred = self.fine_expert(action_cond, target=robot_action_target)
        
        return traj_pred, mano_pred, action_pred

    def compute_loss(self, traj_pred, mano_pred, action_pred, targets, has_mano, has_robot):
        # 联合训练策略：根据数据源动态计算损失
        loss_3d = cross_entropy(traj_pred, targets['trajectory'])
        
        # 人类视频数据有 MANO 标签，无 Robot 标签
        loss_mano = flow_matching_loss(mano_pred, targets['mano']) if has_mano else 0.0
        
        # 机器人数据有 Robot 标签，无 MANO 标签
        loss_action = flow_matching_loss(action_pred, targets['robot']) if has_robot else 0.0
        
        return loss_3d + loss_mano + loss_action
```

```python
def train_step(batch, model, pre_trained_visual_weights, lambda_reg):
    obs, action, prompt = batch
    
    # Forward pass
    pred_action = model(obs, prompt)
    loss_bc = mse_loss(pred_action, action)
    
    # L2 Regularization on visual encoder
    current_visual_weights = model.visual_encoder.parameters()
    loss_reg = lambda_reg * l2_distance(current_visual_weights, pre_trained_visual_weights)
    
    total_loss = loss_bc + loss_reg
    total_loss.backward()
    optimizer.step()

# Inference Phase: Contrastive Prompt Guidance (Flow-Matching)
def generate_action(obs, novel_prompt, trained_prompt, model, num_steps, guidance_scale):
    # Initialize noisy action chunk
    action_t = sample_gaussian_noise()
    dt = -1.0 / num_steps
    
    for t in range(1.0, 0.0, dt): # Denoising from t=1 to t=0
        # Forward pass with novel (positive) prompt
        v_pos = model.predict_vector_field(obs, novel_prompt, action_t, t)
        
        # Forward pass with trained (negative) prompt
        v_neg = model.predict_vector_field(obs, trained_prompt, action_t, t)
        
        # Contrastive guidance rule
        v_cpg = v_neg + guidance_scale * (v_pos - v_neg)
        
        # Euler update step
        action_t = action_t + dt * v_cpg
        
    return action_t
```

### 第二模块：核心架构解释

TDP 的核心思想是将宏观的轨迹规划与微观的高频反馈解耦。其架构与执行流程分为两个主要层级：标称轨迹生成（Nominal Chunk Generation）与管内反应式修正（In-Tube Reactive Correction）。

1. **标称轨迹生成**：在每个宏观时间步，模型接收历史观测序列，通过完整的扩散去噪过程（如 DDPM/DDIM 的多步迭代），生成一个未来 $H$ 步的标称动作块（Nominal Action Chunk）。这保证了动作的长期连贯性。
2. **管态反馈流学习**：在训练阶段，模型不仅学习拟合专家轨迹，还通过注入噪声或扰动，学习在专家轨迹周围的条件得分函数（Conditional Score Function）。这构建了一个以标称轨迹为中心、由当前观测驱动的向量场（即 Action Tube）。
3. **高频反应式修正**：在微观执行步，系统以极高的频率读取最新的视觉和触觉数据。TDP 将当前时刻的标称动作作为先验，结合最新观测，仅通过 1 步或极少步的去噪迭代，计算出修正后的动作并下发给底层控制器。

**核心伪代码（Python 风格）：**

```python
class TubeDiffusionPolicy:
    def __init__(self, diffusion_model, tube_feedback_model):
        self.diffusion_model = diffusion_model # 用于生成标称动作块
        self.tube_model = tube_feedback_model  # 用于高频局部修正
        self.chunk_size = 16
        self.replanning_interval = 8

    def generate_nominal_chunk(self, obs_history):
        # 完整的去噪过程，耗时较长，生成未来 H 步的标称动作
        noise = sample_gaussian_noise(shape=(self.chunk_size, action_dim))
        nominal_chunk = self.diffusion_model.denoise(noise, obs_history, steps=100)
        return nominal_chunk

    def reactive_step(self, current_obs, nominal_action_t):
        # 管内反应式修正：利用最新观测（特别是高频触觉），对当前标称动作进行极少步修正
        # 仅需 1~2 步去噪，极大地降低了延迟
        corrected_action = self.tube_model.fast_denoise(
            prior_action=nominal_action_t, 
            condition=current_obs, 
            steps=1
        )
        return corrected_action

    def run_control_loop(self, env):
        obs_history = env.get_obs_history()
        step_count = 0
        
        while not env.done():
            # 宏观层：定期重新规划标称动作块
            if step_count % self.replanning_interval == 0:
                nominal_chunk = self.generate_nominal_chunk(obs_history)
                chunk_index = 0
            
            # 微观层：高频读取多模态数据（视觉+触觉）
            current_obs = env.get_current_obs()
            nominal_action_t = nominal_chunk[chunk_index]
            
            # 核心创新：基于 Action Tube 的高频反应式修正
            action_to_execute = self.reactive_step(current_obs, nominal_action_t)
            
            env.step(action_to_execute)
            obs_history.update(current_obs)
            chunk_index += 1
            step_count += 1
```

### 第二模块：核心架构解释

EgoDyn-Bench 的核心架构并非提出一个新的神经网络，而是构建了一套严密的**诊断性评估流水线**。其流程分为数据策展、语义抽象（Oracle 标注）、模型推理与一致性检验四个阶段：

1. **数据策展与平衡 (Data Curation)**：真实世界数据（nuScenes）存在严重的低动态偏差（大部分时间在直行）。框架引入仿真数据（CARLA）注入急刹车、大侧向加速度等极端工况，并通过贪心算法构建了 1000 个 3 秒视频片段的绝对平衡数据集。
2. **语义抽象与预言机 (Semantic Abstraction & Oracle)**：提取视频对应的连续运动学状态序列 $S = \{v, a, j, \omega, \theta\}$（速度、加速度、加加速度、横摆角速度、航向角）。预言机 $\mathcal{G}$ 使用严格的物理阈值将 $S$ 映射为 14 类离散语义标签 $R^*$（如：速度状态、刹车强度）。
3. **模型推理 (Model Inference)**：将视频帧 $O$ 与自然语言问题 $P$ 输入给待测模型 $\mathcal{F}_\theta$，获取预测的语义回答 $\hat{R}$。
4. **物理一致性检验 (WPCR Metric)**：不仅计算准确率，还定义了一组硬性物理约束规则 $\mathcal{R}$（例如：“如果速度状态是高速公路，则平均速度不能为低”）。通过检查模型在同一视频下的多个回答是否违反这些规则，计算加权物理一致性率（WPCR）。

**核心底层逻辑伪代码 (Python 风格)**：

```python
import numpy as np

class EgoDynOracle:
    def __init__(self, thresholds):
        self.thresholds = thresholds # 物理阈值字典，如 {'emergency_brake': -1.59}

    def get_ground_truth(self, kinematics_sequence):
        """将连续运动学序列映射为离散语义标签"""
        min_accel = np.min(kinematics_sequence['acceleration'])
        max_yaw = np.max(np.abs(kinematics_sequence['yaw_rate']))
        
        labels = {}
        # 规则1：刹车强度
        if min_accel < self.thresholds['emergency_brake']:
            labels['braking_intensity'] = 'emergency'
        else:
            labels['braking_intensity'] = 'none' # 简化示例
            
        # 规则2：转弯方向
        if max_yaw > self.thresholds['turn_deadzone']:
            labels['turn_direction'] = 'turning'
        else:
            labels['turn_direction'] = 'straight'
            
        return labels

def calculate_wpcr(model_predictions, rules):
    """计算加权物理一致性率 (WPCR)"""
    total_clips = len(model_predictions)
    consistency_score = 0.0
    
    for clip_preds in model_predictions:
        triggered_rules = 0
        violations = 0
        
        for rule in rules:
            # 检查规则前提是否被触发 (A => B)
            if rule.condition_met(clip_preds):
                triggered_rules += 1
                # 检查结论是否被违反
                if not rule.conclusion_met(clip_preds):
                    violations += 1
                    
        # 仅当触发了规则且没有违规时，才给予一致性得分
        if triggered_rules > 0 and violations == 0:
            consistency_score += (triggered_rules / len(rules))
            
    return consistency_score / total_clips

# 评估流水线
oracle = EgoDynOracle(calibrated_thresholds)
for video, kinematics in dataset:
    gt_labels = oracle.get_ground_truth(kinematics)
    model_answers = vlm_model.predict(video, questions)
    
    # 1. 计算语义准确率 (BAcc)
    accuracy = compute_bacc(model_answers, gt_labels)
    # 2. 计算物理一致性 (WPCR)
    wpcr = calculate_wpcr([model_answers], physical_rules)
```

### 第二模块：核心架构解释

CF-VLA 的核心架构建立在标准的视觉-语言-动作（VLA）主干之上，其本质是对动作生成头（Action Head）和推理/训练流程的重构。

**1. 模型架构流程**
- **视觉与语言编码 (VLM Backbone)**: 使用 SigLIP 处理视觉输入，Gemma 处理语言指令，提取多模态前缀特征（Prefix Tokens）。
- **粗阶段 (Coarse Stage - Endpoint Prior Modeling)**: 接收纯高斯噪声，不直接预测最终动作，而是预测一个端点速度的条件后验分布（均值和方差）。通过采样该分布，将纯噪声转换为“先验引导（AP-guided）”的初始状态。这一步完成了全局对齐。
- **细阶段 (Fine Stage - Local Manifold Recovery)**: 接收粗阶段输出的先验引导状态，在固定的时间步（$t=0.1$）执行单步网络前向传播，预测残差以恢复最终的精确动作。这一步完成了局部流形修正。

**2. 逐步训练策略 (Stepwise Training)**
- **Phase I (稳定预热)**: 粗阶段使用 MSE 损失拟合目标速度，并引入对数方差匹配；细阶段不接收粗阶段的（早期不稳定）输出，而是接收由真实动作和噪声插值构建的“受控代理输入”进行训练。
- **Phase II (联合优化)**: 粗阶段切换为 KL 散度损失，使其预测的后验分布匹配目标高斯分布；细阶段直接接收粗阶段的采样输出进行端到端联合训练。

**3. 核心伪代码实现**

```python
import torch
import torch.nn.functional as F

class CF_VLA_ActionHead(torch.nn.Module):
    def __init__(self, backbone):
        super().__init__()
        self.backbone = backbone # VLM Backbone (e.g., SigLIP + Gemma)
        # 预测均值和对数方差的线性头
        self.action_proj = torch.nn.Linear(hidden_dim, action_dim)
        self.logvar_proj = torch.nn.Linear(hidden_dim, action_dim)
        
    def forward_suffix(self, state, x_t, time):
        # 提取特征并预测高斯分布参数
        hidden = self.backbone(state, x_t, time)
        mean = self.action_proj(hidden)
        logvar = torch.clamp(self.logvar_proj(hidden), -5.0, 20.0)
        return mean, logvar

    def inference_step(self, state):
        """推理阶段：NFE=2 的 Coarse-to-Fine 生成"""
        bsize = state.shape[0]
        
        # --- Step 1: Coarse Initialization (全局对齐) ---
        # 从纯高斯噪声开始 (t=1.0)
        x_coarse = torch.zeros(action_shape) 
        t_coarse = torch.ones(bsize)
        
        # 预测端点速度分布
        mean_coarse, _ = self.forward_suffix(state, x_coarse, t_coarse)
        
        # Euler 积分一步，获得先验引导的初始化状态
        dt_coarse = -1.0
        x_init = x_coarse + dt_coarse * mean_coarse
        
        # --- Step 2: Fine Refinement (局部修正) ---
        # 缩放初始状态和时间步至局部邻域 (t=0.1)
        x_fine = x_init * 0.9  
        t_fine = torch.full((bsize,), 0.1)
        dt_fine = -0.1
        
        # 预测局部残差
        mean_fine, _ = self.forward_suffix(state, x_fine, t_fine)
        
        # Euler 积分一步，获得最终动作
        final_action = x_fine + dt_fine * mean_fine
        
        return final_action
```

### 第二模块：核心架构解释

$M^2$-VLA 的核心架构将感知与动作生成解耦，整体流程分为特征提取与动作生成两个阶段：

**1. 特征提取 (Feature Extraction)**
系统接收全局视角图像、腕部视角图像、本体感觉状态和自然语言指令。图像通过 DINOv2 和 SigLIP 提取视觉嵌入，文本被分词为文本嵌入。这些嵌入与一组可学习的 Query 拼接后，输入到参数完全冻结的 VLM 骨干中。VLM 输出其所有隐藏层的多尺度特征，作为后续动作生成的上下文。

**2. 层混合特征选择 (Mixture of Layers, MoL)**
由于 VLM 的高维特征包含大量与底层控制无关的噪声，MoL 在动作生成头的每一层被调用。它包含三个并行的注意力分支：
- 分支一：基于 Query 和本体感觉计算动态权重，提取任务相关的语义特征。
- 分支二：使用静态可学习因子，提取 VLM 的空间视觉特征。
- 分支三：对动作潜变量进行自注意力计算以抑制噪声。
这三个分支的输出被平均聚合，实现跨层知识的动态过滤。

**3. 元技能增强 (Meta Skill Module, MSM)**
为了提升轻量级动作头的容量，MSM 在训练时构建一个外部记忆队列，存储“感知上下文-未来动作序列”的键值对。在推理时，MSM 使用当前观测的多层特征作为 Query，通过 L1 距离检索 Top-R 的历史元技能。检索到的技能通过交叉注意力机制作为残差注入到动作生成流中，指导当前轨迹的构建。

**4. 动作生成 (Action Generation)**
动作头是一个多层 Transformer，采用去噪扩散的逻辑。它接收高斯噪声作为初始动作，在 MoL 提取的特征和 MSM 检索的技能的共同条件约束下，逐步预测并重建出目标动作序列。

**核心逻辑伪代码**：
```python

    # 1. Feature Extraction (Frozen VLM)
    visual_emb = extract_visual_features(image) # DINOv2 + SigLIP
    text_emb = tokenize(text)
    queries = learnable_queries()
    
    # vlm_hidden_states: list of features from all VLM layers (shallow to deep)
    vlm_hidden_states = frozen_vlm(visual_emb, text_emb, queries) 
    
    # 2. Action Generation
    action_latent = linear_proj(noise_action)
    
    for layer in action_head_layers:
        # Mixture of Layers (MoL)
        # Branch 1: Dynamic attention for semantic queries
        alpha_s = sigmoid(linear(concat(vlm_hidden_states.queries, proprioception)))
        attn_s = softmax(alpha_s * Q_A @ K_S / sqrt(d)) @ V_S
        
        # Branch 2: Static attention for visual features
        attn_v = softmax(alpha_v * Q_A @ K_V / sqrt(d)) @ V_V
        
        # Branch 3: Self-attention on action latent
        attn_a = self_attention(action_latent)
        
        # Aggregate MoL outputs
        mol_features = mean(attn_s, attn_v, attn_a)
        
        # Meta Skill Module (MSM)
        current_context = concat(vlm_hidden_states.shallow, vlm_hidden_states.mid, vlm_hidden_states.deep)
        # Retrieve top-R skills using L1 distance
        retrieved_skills = retrieve_top_r(current_context, meta_skill_memory, R=4) 
        
        # Cross-attention with retrieved skills
        skill_refinement = cross_attention(query=action_latent, keys=retrieved_skills.keys, values=retrieved_skills.values)
        
        # Residual update for action latent
        action_latent = action_latent - (mol_features + skill_refinement)
        
    predicted_action = reverse_linear_proj(action_latent)
    return predicted_action
```

### 第二模块：核心架构解释

当前VLA模型（如$\pi_0$）的推理流程存在固有的双阶段串行依赖：
阶段一（VLM主干）：负责视觉特征提取与语义理解。属于计算密集型（Compute-bound），算力利用率极高（>90%）。
阶段二（动作专家）：负责基于视觉特征生成连续动作（如Diffusion或Flow Matching）。属于访存密集型（Memory-bound），算力利用率极低（20%-40%），且需要多次迭代。

为了打破这种串行导致的资源闲置，作者设计了以下核心执行流程：

1. **离线分析与编译**：部署前，使用Roofline模型确定硬件瓶颈，并利用JIT或ATC编译器将模型计算图静态化。同时，离线分析扩散模型的轨迹，确定特征变化极小的“稳定区”（如第20至80步）。
2. **DP-Cache 冗余消除**：在动作专家进入“稳定区”后，每计算1步，将其输出张量缓存，并直接作为后续 $S-1$ 步的输出，强行跳过中间的神经网络前向传播。
3. **V-AEFusion 异步流水线**：在控制循环的第 $t$ 步，系统接收到新观测 $Obs_t$。VLM开始处理 $Obs_t$；与此同时，动作专家不等待VLM，而是直接提取缓存的 $Obs_{t-1}$ 特征（Stale KV），开始执行前 $K$ 步的粗粒度去噪。当VLM计算完毕输出 $Obs_t$ 的新特征（Fresh KV）时，动作专家立刻切换至新特征，完成剩余的细粒度去噪步骤。

**核心逻辑伪代码 (Python 风格):**

```python
class OptimizedVLA:
    def __init__(self, vlm, action_expert, cache_steps=4, stale_steps=5):
        self.vlm = vlm
        self.action_expert = action_expert
        self.cache_steps = cache_steps
        self.stale_steps = stale_steps
        self.stale_kv = None  # 存储上一帧的视觉特征

    def inference_step(self, obs_current):
        # 如果是第一帧，退化为串行执行
        if self.stale_kv is None:
            fresh_kv = self.vlm.forward(obs_current)
            action = self.run_action_expert(fresh_kv, total_steps=100)
            self.stale_kv = fresh_kv
            return action

        # 异步执行：VLM处理当前帧，动作专家使用旧特征提前启动
        vlm_thread = Thread(target=self.vlm.forward, args=(obs_current,))
        vlm_thread.start()

        # 动作专家使用 stale_kv 执行前 stale_steps 步 (粗粒度去噪)
        noisy_action = self.action_expert.initial_denoise(
            self.stale_kv, 
            steps=self.stale_steps
        )

        # 等待VLM完成当前帧计算
        fresh_kv = vlm_thread.join()

        # 动作专家切换到 fresh_kv 执行剩余步骤，并启用 DP-Cache
        final_action = self.run_action_expert_with_cache(
            noisy_action, 
            fresh_kv, 
            start_step=self.stale_steps, 
            total_steps=100
        )

        self.stale_kv = fresh_kv
        return final_action

    def run_action_expert_with_cache(self, x, condition, start_step, total_steps):
        step = start_step
        while step < total_steps:
            if self.is_in_stable_zone(step):
                # 计算一次
                x = self.action_expert.denoise_step(x, condition, step)
                # 缓存并跳过后续 cache_steps - 1 步
                step += self.cache_steps 
            else:
                x = self.action_expert.denoise_step(x, condition, step)
                step += 1
        return x
```

### 第二模块：核心架构解释

MoSS 的核心架构旨在将预训练的 VLA 模型转化为一个可以接收任意数量物理传感器输入的模块化系统。其处理流程与实验设计如下：

**1. 模态解耦与特征提取**
系统接收视觉图像、自然语言指令以及多种物理信号（如触觉阵列数据、关节力矩序列）。视觉和语言通过冻结的预训练 VLA 编码器处理；每种物理信号通过独立的、特定于该模态的编码器（Decoupled modality streams）提取特征序列。

**2. 联合跨模态自注意力融合**
提取出的物理特征序列不直接与视觉特征拼接，而是作为 Key 和 Value，通过跨模态注意力机制（Cross-modal attention）注入到主干动作流（Action stream）中。这种设计允许模型在生成动作 Token 时，动态查询相关的物理反馈信息。

**3. 辅助预测任务**
为了让模型真正理解“动作如何影响物理状态”，架构中增加了一个预测头。该预测头利用当前状态特征和生成的动作，预测下一时刻的物理信号（如未来的触觉读数或力矩变化）。

**4. 两阶段训练策略**
- **第一阶段（对齐与预热）:** 冻结预训练 VLA 的全部参数，仅训练物理信号编码器、跨模态注意力层和辅助预测头。确保新模态特征对齐到 VLA 的潜在空间。
- **第二阶段（联合微调）:** 解冻部分或全部网络参数，进行端到端的联合优化，使动作生成完全适应多模态输入。

```python
        vla_features = self.vla.extract_features(image, text)

        phys_features_list = []
        for mod_name, signal in physical_signals.items():

            phys_features_list.append(encoder(signal))

            query=vla_features, 
            key=context_features, 
            value=context_features

        action_stream = vla_features + fused_features
```

```python
class AsyncShieldAdapter:
    def __init__(self, rl_policy, safety_radius):
        self.pose_buffer = CircularBuffer() # 存储历史位姿 (time, pose_world_to_ego)
        self.rl_policy = rl_policy          # PPO-Lagrangian 训练的策略
        self.safety_radius = safety_radius

    def update_high_freq_state(self, current_time, current_pose, lidar_scan):
        # 边缘端高频运行：记录位姿
        self.pose_buffer.add(current_time, current_pose)
        self.current_pose = current_pose
        self.lidar_scan = lidar_scan

    def process_vla_packet(self, vla_waypoints, anchor_time):
        # 1. 时空意图重对齐 (Geometric Re-projection)
        # 获取 VLA 指令发出时的历史位姿
        historical_pose = self.pose_buffer.get_interpolated_pose(anchor_time)
        
        realigned_waypoints = []
        for pt in vla_waypoints:
            # SE(2) 变换：将历史坐标系下的点转换到当前坐标系
            # p_current = (T_current)^-1 * T_historical * p_historical
            pt_current = inverse(self.current_pose) * historical_pose * pt
```

### 第二模块：核心架构解释

Move-Then-Operate 的核心架构是一个带有硬路由机制的条件策略网络，其工作流程与实验流程可拆解为以下三个阶段：

**1. 自动化数据标注流水线（Data Pipeline）**

**2. 相位选择器（Phase Selector）**
在推理阶段，模型首先通过一个轻量级的分类网络（Phase Selector）。该网络接收当前的视觉观测、本体感受状态和语言指令，预测当前应该处于“移动”阶段还是“操作”阶段。

**3. 双专家策略路由（Dual-Expert Policy）**
根据 Phase Selector 的输出，系统进行硬路由（Hard Routing）。如果预测为 Move，则将观测输入给“移动专家”网络，该网络针对大范围、无碰撞的轨迹生成进行过优化；如果预测为 Operate，则路由给“操作专家”网络，该网络专注于高频、微小、接触丰富的力控或位控输出。

```python
        phase_pred = torch.argmax(phase_logits, dim=-1) # 0 or 1

        operate_mask = (phase_pred == 1)

        return actions, phase_pred
```

### 第二模块：核心架构解释

SwarmDrive 的核心架构围绕**本地推理、事件触发、语义通信与共识融合**四个阶段展开。其本质是一个去中心化的多智能体分布式推理系统。

1. **本地感知与 SLM 推理**：每辆车利用自身的传感器获取局部观测，并输入到本地部署的小型语言模型（SLM）中，输出当前驾驶动作的概率分布（即语义意图）。
2. **不确定性评估（事件触发机制）**：计算本地动作分布的信息熵。如果熵值低于设定阈值，说明单车对当前决策极度自信（视野良好），直接执行动作；如果熵值高于阈值（如遇到遮挡导致模型犹豫），则触发 V2V 通信。
3. **语义 V2V 通信**：触发通信后，车辆不发送图像或点云，而是将轻量化的“动作概率分布向量”广播给周边车辆。
4. **共识融合**：接收来自周边车队（Swarm）的意图分布，通过共识算法（如加权平均或多数投票）将多车意图融合，得出最终的高置信度动作指令。

**核心逻辑伪代码 (Python Style)**：

```python
import numpy as np
from scipy.stats import entropy

class SwarmDriveAgent:
    def __init__(self, local_slm, entropy_threshold=0.65, max_swarm_size=4):
        self.local_slm = local_slm
        self.entropy_threshold = entropy_threshold
        self.max_swarm_size = max_swarm_size
        self.v2v_network = [] # 模拟 V2V 通信网络中的邻居节点

    def get_action(self, local_sensor_data):
        # 1. 本地 SLM 推理，输出动作的概率分布 (语义意图)
        intent_distribution = self.local_slm.predict_proba(local_sensor_data)
        
        # 2. 计算信息熵以评估不确定性
        uncertainty = entropy(intent_distribution)
        
        # 3. 事件触发机制
        if uncertainty < self.entropy_threshold:
            # 置信度高，直接执行本地决策
            return np.argmax(intent_distribution)
        else:
            # 置信度低，触发 V2V 协同
            return self.swarm_consensus(intent_distribution)

    def swarm_consensus(self, local_intent):
        shared_intents = [local_intent]
        
        # 4. 语义 V2V 通信：获取周边车辆的意图分布 (限制车队规模)
        neighbors = self.v2v_network[:self.max_swarm_size-1]
        for neighbor in neighbors:
            # 仅接收轻量级的概率分布向量，而非原始传感器数据
            neighbor_intent = neighbor.broadcast_intent() 
            if neighbor_intent is not None:
                shared_intents.append(neighbor_intent)
                
        # 5. 意图融合 (此处以简单的平均共识为例)
        fused_intent = np.mean(shared_intents, axis=0)
        
        return np.argmax(fused_intent)
```

### 第二模块：核心架构解释

当前论文的模型架构分为训练阶段的“显式法规-场景匹配”与推理阶段的“驾驶要求推导”两个核心流程。

**1. 场景分类学构建 (Scenario Taxonomy Representation)**
整合 OpenDRIVE、OpenSCENARIO 等标准，构建包含道路、基础设施、交通管理、环境、对象等 227 个节点的层级树。每个节点对应一个唯一的路径标签（如 `/Road/Intersection/T-intersection`）。

**2. 分类学引导锚定 (TGA) 训练阶段**
为分类树中的每个节点初始化一个长度为 $L$ 的可学习软提示（Soft Prompt），称为锚点（Anchor）。将具体的法规文本与节点标签输入冻结参数的 LLM，结合该节点的软提示，要求 LLM 输出二元判定（Yes/No）。通过二元交叉熵损失（BCE）反向传播，仅优化软提示的参数，使其捕获该节点特定的语义边界。

**3. 驾驶要求推导 (Driving-Requirement Derivation) 推理阶段**
当自动驾驶车辆处于特定物理场景时，感知系统提取当前场景的所有激活节点（包含其祖先节点）。系统利用训练好的软提示锚点，检索出所有适用该场景的法规条款。随后，调用 LLM 执行两步思维链（CoT）推理：第一步识别条款中的规范性指示词（如“必须”、“不得”），第二步将条款转化为具体的“强制性（Mandatory）”和“禁止性（Prohibitive）”驾驶约束。

**4. 下游应用部署**
将推导出的约束编码为 GeoJSON 属性，注入 OpenStreetMap 等高精地图形成合规导航层；或部署为车载离线监控器，实时比对车辆轨迹与法规约束。

**核心逻辑伪代码 (Python-style)**:

```python
import torch
import torch.nn as nn

class TGAPipeline(nn.Module):
    def __init__(self, llm, taxonomy_nodes, prompt_length=20, embed_dim=4096):
        super().__init__()
        self.llm = llm.eval() # 冻结基础 LLM
        # 为每个分类学节点初始化可学习的软提示锚点
        self.anchors = nn.ParameterDict({
            node.id: nn.Parameter(torch.randn(prompt_length, embed_dim))
            for node in taxonomy_nodes
        })
        self.bce_loss = nn.BCELoss()

    def train_anchor(self, law_text, node_id, label):
        """训练阶段：优化特定节点的软提示"""
        anchor = self.anchors[node_id]
        # 拼接：软提示 + 法规文本 + 节点标签
        input_embeds = torch.cat([anchor, self.llm.embed(law_text), self.llm.embed(node_id)], dim=0)
        
        # 预测该法规是否适用于该节点场景
        pred_prob = self.llm.predict_yes_no(input_embeds)
        loss = self.bce_loss(pred_prob, label)
        
        loss.backward()
        # 仅更新 anchor 参数
        return loss

    def inference_requirements(self, current_scenario_nodes, law_database):
        """推理阶段：检索法规并推导驾驶要求"""
        applicable_laws = []
        # 1. 基于锚点检索适用法规
        for law in law_database:
            is_applicable = True
            for node in current_scenario_nodes:
                anchor = self.anchors[node.id]
                input_embeds = torch.cat([anchor, self.llm.embed(law.text), self.llm.embed(node.id)], dim=0)
                if self.llm.predict_yes_no(input_embeds) < 0.5:
                    is_applicable = False
                    break
            if is_applicable:
                applicable_laws.append(law)
                
        # 2. 思维链推导具体约束
        driving_requirements = {"mandatory": [], "prohibitive": []}
        for law in applicable_laws:
            # CoT Step 1: 分类
            category = self.llm.generate(f"Classify as mandatory or prohibitive: {law.text}")
            # CoT Step 2: 提取动作
            action = self.llm.generate(f"Extract specific driving action from: {law.text}")
            driving_requirements[category].append(action)
            
        return driving_requirements
```

### 第二模块：核心架构解释

CLLAP 的核心逻辑是将“昂贵的雷达数据标注问题”转化为“廉价的跨模态自监督对齐问题”。其工作流分为数据合成、自监督预训练和下游微调三个阶段：

1. **数据合成阶段 (L2R Sampling)**: 输入原始的高密度 LiDAR 点云，通过模拟毫米波雷达的物理特性（如视场角限制、低分辨率、特定噪声分布），对其进行降采样，生成伪雷达 (Pseudo-Radar) 点云。
2. **双阶段双模态对比学习预训练**:
   - **Stage 1 (跨模态基础对齐)**: 分别提取图像特征和伪雷达特征，通过 InfoNCE 损失函数进行跨模态对比学习，在隐空间中拉近匹配的“图像-伪雷达”特征对，推开不匹配的特征对。
   - **Stage 2 (融合特征增强)**: 将预训练的单模态特征输入融合模块，进一步计算融合特征与单模态特征之间的对比损失，优化融合后的表征空间。
3. **下游微调 (Downstream Fine-tuning)**: 预训练完成后，丢弃伪雷达数据。将预训练好的特征提取器权重作为初始化，接入真实的雷达-相机数据和 3D 检测头，进行标准的有监督微调。

```python
# CLLAP 核心逻辑伪代码

def L2R_sampling(lidar_pc):
    """模拟雷达物理特性，将高维LiDAR降维成伪雷达点云"""
    pseudo_radar_pc = apply_radar_fov_and_resolution(lidar_pc)
    pseudo_radar_pc = add_radar_specific_noise(pseudo_radar_pc)
    return pseudo_radar_pc

def contrastive_loss(feat_a, feat_b):
    """InfoNCE 损失，用于特征空间对齐"""
    return InfoNCE(feat_a, feat_b)

def pretrain_stage(image, lidar_pc, img_encoder, radar_encoder, fusion_module):
    """自监督预训练阶段"""
    # 1. 生成伪雷达数据
    pseudo_radar = L2R_sampling(lidar_pc)
    
    # 2. 提取单模态特征
    img_feat = img_encoder(image)
    radar_feat = radar_encoder(pseudo_radar)
    
    # 3. Stage 1: 跨模态特征对齐
    loss_stage1 = contrastive_loss(img_feat, radar_feat)
    
    # 4. Stage 2: 融合特征增强
    fused_feat = fusion_module(img_feat, radar_feat)
    loss_stage2 = contrastive_loss(fused_feat, img_feat) + contrastive_loss(fused_feat, radar_feat)
    
    return loss_stage1 + loss_stage2

def downstream_finetuning(real_image, real_radar, labels, pretrained_img_enc, pretrained_radar_enc, fusion_module, detection_head):
    """即插即用的下游微调阶段"""
    img_feat = pretrained_img_enc(real_image)
    radar_feat = pretrained_radar_enc(real_radar)
    
    fused_feat = fusion_module(img_feat, radar_feat)
    predictions = detection_head(fused_feat)
    
    return detection_loss(predictions, labels)
```

Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？

A6: 局限性在于 L2R 采样器本质上是物理规则的模拟，无法完美复刻真实毫米波雷达的独有物理特性（如多径效应、杂波干扰）和至关重要的多普勒速度信息。如果伪雷达数据与真实雷达数据的 Domain Gap（域差距）过大，预训练带来的增益会存在明显上限。对后续科研的启发是：在多模态具身智能系统中，当某一种模态数据稀缺时，可以通过物理降维或生成式模型（如 World Model）从高维富模态数据中“蒸馏”出低维模态数据，用于底层的表征对齐。
