问题背景：评估具身世界模型（EWMs）的物理一致性是一个关键挑战。虽然通过模拟器进行闭环评估比开环评估更能真实反映物理合理性，但现有框架几乎完全依赖逆动力学模型（IDMs）来提取动作。由于2D像素到3D运动学空间的映射极其复杂，IDMs对分布外数据非常脆弱，导致在面对新物体和场景时动作提取不可靠，从而在世界模型误差和提取器误差之间产生了难以剥离的归因歧义。

```python
class KineBenchEvaluator:
    def __init__(self, world_model, simulator, cad_model):
        self.world_model = world_model
        self.simulator = simulator
        self.cad_model = cad_model
        
        # 初始化视觉基础模型流水线
        self.yolo = YOLOv11_Finetuned()
        self.moge = MoGeV2_Finetuned()
        self.pose_tracker = FoundationPose()

    def explicit_kinematic_grounding(self, frame):
        # 1. 提取末端执行器 2D 掩码
        mask = self.yolo.segment(frame)
        
        # 2. 估计绝对尺度深度图
        depth_map = self.moge.estimate_depth(frame)
        
        # 3. 结合 CAD 模型，通过刚体约束计算 6D 位姿
        pose_6d = self.pose_tracker.track(
            rgb=frame, 
            depth=depth_map, 
            mask=mask, 
            cad_model=self.cad_model
        )
        return pose_6d

    def evaluate_episode(self, instruction, initial_obs):
        current_obs = initial_obs
        trajectory_poses = []
        
        # 闭环执行
        while not self.simulator.is_done():
            # 世界模型生成未来视频帧
            generated_video = self.world_model.generate(current_obs, instruction)
            next_frame = generated_video[0] 
            
            # 显式提取 6D 动作
            action_pose = self.explicit_kinematic_grounding(next_frame)
            trajectory_poses.append(action_pose)
            
            # 在物理模拟器中执行动作，获取真实物理反馈
            current_obs, reward, done = self.simulator.step(action_pose)
            
        # 计算 3D 运动学指标
        sparc_score = calculate_sparc(trajectory_poses)
        manipulability_score = calculate_maruyama_index(trajectory_poses)
        task_success = self.simulator.get_success()
        
        return task_success, sparc_score, manipulability_score
```

### 第二模块：核心架构解释

Diffusion ReRoll 的核心逻辑分为训练阶段的噪声分布构造与推理阶段的调度矩阵控制。它不需要改变现有的 Transformer 骨干网络，仅通过修改逐 Token 的噪声注入方式来改变信息流。

**训练阶段（Training with Linear Chunks）**：
模型不使用全局统一的噪声，也不使用完全独立的随机逐 Token 噪声。相反，它将序列划分为多个连续的片段（Segments），为每个片段分配一个起始噪声级和一个斜率，生成分段线性的噪声分布（Piecewise-linear noise profiles）。这使得模型在训练时暴露于结构化的局部噪声模式中，学习如何在部分序列清晰、部分序列模糊的情况下进行去噪。

**推理阶段（Inference with Schedule Matrix）**：
推理完全由一个预定义的调度矩阵 $S$ 控制。矩阵的行代表 DDIM 去噪步，列代表序列时间步。矩阵定义了在序列上移动的“去噪波（Denoising Waves）”。
1. **去噪斜率（Denoising slope）**：控制去噪波在序列上的跨度。
2. **重置噪声级（Reset noise level）**：当某个 Token 的噪声降至该阈值时，触发 ReRoll 事件。
3. **ReRoll 事件**：强制将该 Token 的噪声拉回最高级（完全噪声），使其重新开始去噪。此时，序列的其他部分可能处于较低噪声状态，为该 Token 提供了高置信度的上下文。

**底层逻辑伪代码**：

```python
def diffusion_reroll_inference(model, schedule_matrix, context, horizon, dim, num_ddim_steps):
    # schedule_matrix: shape [num_ddim_steps + 1, horizon], 存储离散的噪声级索引
    # 初始化全序列为纯高斯噪声
    x = sample_gaussian_noise(shape=(horizon, dim))
    
    for m in range(num_ddim_steps):
        current_noise_levels = schedule_matrix[m]
        next_noise_levels = schedule_matrix[m+1]
        
        # 预测当前步的无噪声数据 x0
        x0_pred = model(x, current_noise_levels, context)
        
        for t in range(horizon):
            k = current_noise_levels[t]
            l = next_noise_levels[t]
            
            if l < k:
                # 正常去噪：执行标准 DDIM 向下更新
                x[t] = ddim_update(x0_pred[t], x[t], current_level=k, next_level=l)
            elif l > k:
                # ReRoll 事件：执行前向加噪，重新注入高斯噪声
                x[t] = forward_add_noise(x[t], current_level=k, target_level=l)
            else:
                # 噪声级保持不变
                x[t] = x[t]
                
    return x
```

### 第二模块：核心架构解释

本文的模型架构并非提出一个新的网络结构，而是对 DreamerV3 训练范式的重新设计。其核心流程分为三个逻辑阶段：

**1. 现象定位与通道隔离 (Phenomenon Localization & Channel Isolation)**
作者首先冻结了训练好的世界模型，仅让 Actor 在旧任务的想象数据中重新训练。实验发现，使用标准的 Actor-Critic 策略梯度（RL-in-imagination）会导致策略崩溃（0/3 成功）；但如果使用监督式自我模仿（Supervised self-imitation），即让 Actor 模仿那些在想象中获得高分的轨迹，则能完美恢复技能（3/3 成功）。这确立了核心基调：必须用监督学习通道替换 RL 通道来提取世界模型的记忆。

**2. 分级梦境复排 (Graded Dream Rehearsal)**
在连续学习新任务时，Agent 会定期从旧任务的经验回放池中抽取初始状态（Starts）。
使用当前正在训练的 Actor 在世界模型中展开想象（Imagine rollouts）。
由于 Actor 正在学习新任务，其在旧任务状态下的想象轨迹会包含大量试错和随机行为。

**3. 实现优先评分规则 (Realized-first Grading)**
这是整个架构的承重墙（Load-bearing）。如果直接用 Critic 评估想象轨迹，Critic 的盲目乐观会导致模型去克隆那些“承诺高回报但实际走入死胡同”的轨迹；如果直接用奖励求和，又会受到终止状态后（Post-terminal）幻觉的污染。
作者提出了“实现优先”规则：只有在想象中**真正触发了奖励（Realized reward）**的轨迹，才会被赋予基础高分，Critic 的价值预测仅作为次要排序依据。随后，对得分前 25% 的轨迹进行行为克隆（Behavior Cloning）。

**核心伪代码实现 (Python 风格)**：

```python
def dream_rehearsal_update(world_model, actor, critic, replay_buffer, num_updates=50):
    """
    在训练新任务时，交替进行的旧任务梦境复排逻辑
    """
    for _ in range(num_updates):
        # 1. 从旧任务的经验回放池中采样初始状态
        states = replay_buffer.sample_old_task_starts(batch_size=64)
        
        # 2. 使用当前 Actor 在世界模型中进行想象 (Horizon H=15)
        # imagined_trajectories 包含: states, actions, rewards, continues (终止概率)
        imagined_trajectories = world_model.imagine(actor, start_states=states, horizon=15)
        
        # 3. 计算“实现优先”评分 (Realized-first Grading)
        scores = []
        for traj in imagined_trajectories:
            realized_reward = 0
            prob_reach_step = 1.0
            
            # 仅累加在终止状态前实际获得的奖励
            for t in range(15):
                prob_reach_step *= traj.continues[t] # 累乘未终止概率
                realized_reward += (gamma ** t) * prob_reach_step * traj.rewards[t]
            
            # 核心规则：实际拿到奖励的轨迹获得 10 分的基础加成，Critic 价值仅作微调
            # 避免 Critic 盲目乐观导致的克隆崩溃
            is_realized = 1.0 if realized_reward > 0.3 else 0.0
            critic_value = critic.estimate(traj.states[-1])
            
            score = 10 * is_realized + realized_reward + (gamma ** 15) * prob_reach_step * critic_value
            scores.append(score)
            
        # 4. 过滤并克隆 (Behavior Cloning)
        # 选取分数排名前 25% 的高质量想象轨迹
        top_25_percent_idx = argsort(scores)[-int(0.25 * len(scores)):]
        best_trajectories = imagined_trajectories[top_25_percent_idx]
        
        # 5. 监督式更新 Actor (通道替换：用 BC 替代 RL 策略梯度)
        actor_loss = behavior_cloning_loss(actor, best_trajectories.states, best_trajectories.actions)
        actor_optimizer.zero_grad()
        actor_loss.backward()
        actor_optimizer.step()
```

### 第二模块：核心架构解释

SafeGen 的核心架构分为两个主要阶段：上下文接地的终态推理（Context Grounded End State Reasoning）和终态条件视频演化（End State Conditioned Video Evolution）。

**1. 上下文接地的终态推理**
该阶段的目标是确定视频中何处最容易发生事故，并定义事故的具体形态。系统首先提取输入正常视频的深度图和语义分割图作为物理先验。随后，视觉语言模型（VLM）结合这些先验信息扫描视频，选择一个最适合作为事故终点的关键帧，并输出结构化的灾难终态说明（包含场景描述、对抗性行人特征、插入区域）。

**2. 终态条件视频演化**
该阶段将抽象的文本威胁转化为高保真的物理视频。首先，文本到图像（T2I）扩散模型根据行人特征生成无背景的对抗性行人画像。接着，系统在指定的插入区域内，结合深度图和自车速度，计算出最小化碰撞时间（TTC）的最优三维插入坐标。通过几何投影和多轮图像修复技术，将行人无缝融合到关键帧中，构建出逼真的“对抗性终点帧”。最后，利用首尾帧条件视频扩散模型（FLF2V），以原始第一帧为起点，合成的对抗帧为终点，在场景描述的引导下插值生成中间的所有视频帧。

**核心伪代码实现逻辑**：

```python
def SafeGen_Pipeline(benign_video, vlm, depth_model, seg_model, t2i_model, video_diffusion_model):
    # 1. 提取物理与语义先验
    depth_maps = depth_model(benign_video)
    seg_maps = seg_model(benign_video)
    
    # 2. 上下文接地的终态推理 (对应公式 3.1)
    # VLM 识别关键帧 T_hat，并输出结构化终态说明 s
    T_hat, s = vlm.reason_end_state(benign_video, depth_maps, seg_maps)
    scenario_desc, vru_desc, target_region = s['phi_sce'], s['phi_adv'], s['phi_pos']
    
    # 3. 终态条件视频演化
    # 3.1 生成对抗性行人画像并去除背景
    adv_portrait_raw = t2i_model.generate(prompt=vru_desc)
    adv_portrait = remove_background(adv_portrait_raw)
    
    # 3.2 确定最优插入坐标 (对应公式 3.2)
    # 在目标区域和可行驶地面的交集中，寻找使碰撞时间(TTC)最小的坐标
    valid_ground = get_planar_ground(depth_maps[T_hat])
    search_space = intersection(target_region, valid_ground)
    optimal_coord = minimize_ttc(search_space, depth_maps[T_hat], ego_velocity)
    
    # 3.3 构建对抗性终点帧
    critical_frame = benign_video[T_hat]
    # 通过深度感知投影和多轮图像修复将行人融入画面
    adversarial_last_frame = multi_round_inpaint(critical_frame, adv_portrait, optimal_coord, camera_intrinsics)
    
    # 3.4 边界条件视频扩散生成 (对应公式 3.3)
    first_frame = benign_video[0]
    # 以第一帧和对抗性终点帧为锚点，生成中间连贯视频
    safety_critical_video = video_diffusion_model.generate_video(
        first_frame=first_frame, 
        last_frame=adversarial_last_frame, 
        text_condition=scenario_desc
    )
    
    return safety_critical_video
```

### 第二模块：核心架构解释

PerceptDrive 的架构解耦了“特征获取”与“动作规划”，整体流程分为四个核心阶段：

1. **冻结的感知提供者（Frozen Perception Provider）**：包含两条流。高层流是一个经过驾驶问答微调并从三个教师模型（VGGT 提几何、V-JEPA 提语义、Wan 2.1 提动态）蒸馏出专家槽位（Expert Slots）的 VLM（InternVL3）；底层流是一个现成的 V-JEPA 视频编码器，提供密集的时空潜变量。
2. **先验保留查询分支（Prior-Preserving Query Branches）**：使用可学习的 Query Banks 压缩上述感知特征。为了防止压缩过程中的信息丢失，引入了轻量级的探测器（Probes），计算保留损失（Retention Loss），强制每个分支的输出能够重建其对应的原始专家槽位特征。
3. **度量蒸馏专家路由（Metric-Distilled Expert Routing）**：基于共享的场景状态，路由器预测出针对三个专家分支的软门控权重（Soft Gates）。在训练时，利用特权规则子指标（如碰撞、舒适度）对单步分支草图进行打分，将得分转化为目标分布来监督路由器的生成。
4. **世界-动作生成（World-Action Generation）**：融合后的特征首先输入 Future Head 预测无动作条件的未来潜变量，随后 Flow-matching Actor 结合该潜变量与融合特征，通过流匹配积分生成最终的单条轨迹。

```python
        readout = query_banks[expert](perception_pool)
        branch_readouts[expert] = readout

        retention_loss += cosine_loss(reconstructed_slot, expert_slots[expert].detach())

    shared_scene_state = transformer_backbone(branch_readouts, ego_state, command)
    
    # 预测软门控权重 (Soft Gates)
```

### 第二模块：核心架构解释

Koopman Dreamer 的核心架构建立在 DreamerV3 的基础之上，保留了其观测编码器、随机状态先验/后验网络以及 Actor-Critic 策略优化框架，但彻底重构了确定性潜在状态（Deterministic Latent State）的转移机制。

**模型架构与运行流程：**
1.  **状态解耦与观测编码：** 完整的潜在状态由确定性状态 $\phi_t$ 和随机状态 $s_t$ 组成。观测数据 $o_t$ 经过编码器提取特征，结合 $\phi_t$ 生成后验随机状态 $s_t$。
2.  **Koopman 确定性骨架（核心创新）：** 确定性状态 $\phi_{t+1}$ 的生成不再依赖 GRU，而是通过一个结构化的方程计算。该方程包含四个部分：
    *   **自主谱演化（Autonomous Spectral Evolution）：** 将 $\phi_t$ 划分为多个二维子空间，每个子空间由一个 2D 旋转-缩放矩阵处理。矩阵的缩放因子（半径）被严格限制在 $[\rho_{min}, \rho_{max}]$ 之间，以控制阻尼和持续性。
    *   **线性动作效应（Linear Action Effect）：** 动作向量经过线性映射，提供全局的控制影响。
    *   **双线性交互（Bilinear Interaction）：** 采用低秩双线性形式，使动作的影响能够根据当前潜在状态 $\phi_t$ 发生改变（即状态依赖的控制）。
    *   **随机调制（Stochastic Modulation）：** 将随机状态 $s_t$ 线性投影后注入，提供基于当前观测的局部校正信息。
3.  **多目标联合训练：** 为了在没有未来观测的“想象”阶段也能保持稳定，模型引入了指数移动平均（EMA）教师网络。训练损失除了常规的重建和 KL 散度外，还增加了单步 Koopman 一致性损失、多步教师/先验展开损失，以及开环观测预测损失。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn as nn

class KoopmanTransition(nn.Module):
    def __init__(self, det_dim, action_dim, stoch_dim, rho_min=0.85, rho_max=0.95):
        super().__init__()
        self.M = det_dim // 2
        
        # 1. Autonomous Spectral Backbone Parameters (Unconstrained before sigmoid/tanh)
        self.alpha = nn.Parameter(torch.randn(self.M)) # Controls radius
        self.omega = nn.Parameter(torch.randn(self.M)) # Controls phase/rotation
        self.rho_min = rho_min
        self.rho_max = rho_max
        
        # 2. Linear Action Parameters
        self.B_a = nn.Linear(action_dim, det_dim, bias=False)
        
        # 3. Bilinear State-Action Parameters (Low-rank)
        self.rank = 256
        self.W_phi = nn.Linear(det_dim, self.rank, bias=False)
        self.W_a = nn.Linear(action_dim, self.rank, bias=False)
        self.W_o = nn.Linear(self.rank, det_dim, bias=False)
        self.beta_b = nn.Parameter(torch.tensor(0.05)) # Bilinear scale
        
        # 4. Stochastic Modulation Parameters
        self.B_z = nn.Linear(stoch_dim, det_dim, bias=False)
        
        self.c_phi = 3.0 # Clipping bound

    def get_koopman_matrix(self):
        # Constrain radius to [rho_min, rho_max]
        rho = self.rho_min + (self.rho_max - self.rho_min) * torch.sigmoid(self.alpha)
        # Constrain phase
        theta = torch.pi * torch.tanh(self.omega)
        
        # Build block diagonal matrix A_K
        blocks = []
        for i in range(self.M):
            cos_t, sin_t = torch.cos(theta[i]), torch.sin(theta[i])
            r = rho[i]
            block = torch.stack([
                torch.stack([r * cos_t, -r * sin_t]),
                torch.stack([r * sin_t,  r * cos_t])
            ])
            blocks.append(block)
        return torch.block_diag(*blocks)

    def forward(self, phi_t, s_t, a_t):
        # a_t is pre-scaled action
        
        # Term 1: Autonomous evolution
        A_K = self.get_koopman_matrix()
        u_K = torch.matmul(phi_t, A_K.T)
        
        # Term 2: Linear action
        u_a = self.B_a(a_t)
        
        # Term 3: Bilinear interaction (State-dependent action effect)
        interaction = self.W_phi(phi_t) * self.W_a(a_t) # Element-wise multiplication
        u_b = self.beta_b * self.W_o(interaction)
        
        # Term 4: Stochastic modulation
        u_z = self.B_z(s_t)
        
        # Combine and apply smooth clipping
        pre_clip_phi = u_K + u_a + u_b + u_z
        phi_next = self.c_phi * torch.tanh(pre_clip_phi / self.c_phi)
        
        return phi_next
```

### 第二模块：核心架构解释

DEED 框架并未提出新的神经网络结构，而是构建了一套针对预训练 VLA（GR00T N1.6）的系统级部署与微调流水线。其核心流程分为三个阶段：

**1. 数据高效后训练 (Data-Efficient Post-Training, DE)**
这是将不可用的基础模型转化为可用策略的工程基石。
- **频率层级控制**：强制设定推理控制频率等于记录频率，且小于等于相机帧率（$f_{ctrl} = f_{record} \le f_{cam}$），避免模型学习到冗余的静态帧。
- **数据清洗与视觉增强**：剔除无效停留状态，保留人类接管恢复（Recovery）的数据；引入 IA-VLA 掩码技术，在图像输入层面高亮任务相关物体（如目标货架区域）。
- **动作空间降维与平滑**：将连续的夹爪控制二值化（开/关），并在推理端对 VLA 输出的动作块（Action Chunks）应用巴特沃斯滤波器（Butterworth Filter）以消除高频抖动。

**2. 经验驱动学习 (Experience-Driven Learning, ED)**
适配于解耦 VLA 架构的 RECAP 强化学习变体。
- **价值函数独立训练**：冻结视觉编码器（Eagle-3），仅训练一个轻量级 MLP 预测当前状态的期望回报（Return）。
- **优势计算与文本条件化**：离线计算多步优势函数（Advantage）。将连续的优势值二值化，作为文本前缀（`Advantage=True` 或 `Advantage=False`）拼接到原始语言指令前。
- **策略微调**：使用带有优势标签的混合数据集（人类演示 + 机器人自主 Rollout + 人类纠正）对 VLA 进行 Flow-Matching 微调。推理时强制输入 `Advantage=True`。

**3. 潜空间分布外检测 (OOD Analysis Tool)**
- 提取训练集中所有状态在 VLA 状态编码器中的潜变量表示（Latent Embeddings）。
- 在该潜空间拟合一个高斯混合模型（GMM）。
- 运行时计算当前状态到 GMM 最近组件的马氏距离（Mahalanobis distance），以此判断当前物理状态是否偏离了训练分布。

```python
    recap_dataset = []
    for trajectory in dataset:
        for t in range(len(trajectory)):
            # Multi-step advantage estimation
            V_t = value_net(trajectory.images[t])
            V_t_N = value_net(trajectory.images[t+N])
            advantage = (R_t_to_tN / scale) + V_t_N - V_t
            
            # Text-based conditioning (Crucial adaptation for GR00T)

            # Human corrections are force-labeled as True
            if trajectory.is_human_correction[t]: adv_label = "True"
            
            new_prompt = f"Advantage={adv_label} {trajectory.text}"
            recap_dataset.append((trajectory.images[t], new_prompt, trajectory.actions[t]))
            
    return recap_dataset

# Phase 2: Inference with OOD Detection
```

```python
class NavVerseEnvironment:
    def __init__(self, scene_type, task_type):
        # scene_type: 'indoor', 'outdoor', 'indoor_to_outdoor'
        # task_type: 'ObjectNav', 'VLN', 'PlaceNav'
        self.physics_engine = PhysicsEngine(enable_kinodynamics=True)
        self.scene = self.physics_engine.load_scene(scene_type)
        self.task = TaskGenerator(task_type)
        
    def reset(self):
        self.robot_state = self.scene.spawn_robot()
        self.goal = self.task.get_goal()
        return self._get_observation()
        
    def step(self, action):
        # action: continuous [linear_velocity, angular_velocity]
        # 1. Execute action in physics engine
        self.physics_engine.apply_control(self.robot_state, action)
        self.physics_engine.step()
        
        # 2. Check safety and kinodynamic constraints
        collision = self.physics_engine.check_collision()
        kino_failure = self.physics_engine.check_kinodynamic_failure()
        
        # 3. Evaluate task progress
        obs = self._get_observation()
        success = self.task.check_success(self.robot_state, self.goal)
        done = success or collision or kino_failure or self._timeout()
        
        # 4. Calculate metrics
        info = {
            "task_success": success,
            "safety_violation": collision or kino_failure,
            "path_efficiency": self.task.calculate_spl(self.robot_state)
        }
        return obs, done, info
```

### 第二模块：核心架构解释

ReferTrack 的系统运行流程是一个严格的串行条件生成过程，分为视觉处理、候选目录生成、目标指代和动作预测四个客观步骤：

1.  **视觉观测编码 (Observation Encoding):** 接收当前帧和历史帧的 RGB 图像。使用 SigLIP 和 DINOv2 提取图像特征矩阵。当前帧保留高分辨率特征（64个 Token），历史帧进行网格池化压缩为低分辨率特征（4个 Token）。
2.  **候选目录生成 (Candidate Catalog):** 在当前帧图像上运行 YOLO 目标检测器，提取所有行人的二维边界框坐标。将这些坐标通过多层感知机（MLP）转换为向量，并按顺序赋予索引编号（如 `<ped_1>`, `<ped_2>`），同时固定加入一个 `<NO_EXIST>` 编号代表目标不在视野内。
3.  **目标指代推理 (Refer-CoT):** 将文本指令、候选目录向量、视觉特征向量拼接后输入大语言模型（Qwen3-4B）。模型首先进行一次分类预测，输出一个代表目标编号的 Token（例如 `<ped_2>`）。
4.  **历史轨迹注入与动作预测 (TVBI & Action Prediction):** 提取被选中编号对应的边界框坐标，将其存入一个固定长度的先进先出（FIFO）队列。在处理下一帧时，这个队列中的历史坐标会被转换为向量，并直接加到历史视觉特征向量上（即 TVBI 机制）。最后，模型以选中的目标编号为条件前缀，通过一个线性回归头（Action Head）输出机器人未来几步的二维平面移动坐标（x, y, θ）。

```python
def refer_track_step(current_image, history_images, instruction, bbox_history_queue):
    # 1. 视觉特征提取
    current_visual_tokens = extract_and_pool_features(current_image, resolution='fine')
    history_visual_tokens = extract_and_pool_features(history_images, resolution='coarse')
    
    # 2. 注入历史边界框坐标 (TVBI 机制)
    for i, bbox in enumerate(bbox_history_queue):
        bbox_embedding = mlp_bbox(bbox)
        history_visual_tokens[i] = history_visual_tokens[i] + bbox_embedding
        
    visual_input = concatenate(history_visual_tokens, current_visual_tokens)
    
    # 3. 候选目录生成 (调用外部检测器)
    detected_bboxes = yolo_detector(current_image)
    catalog_tokens = []
    for index, bbox in enumerate(detected_bboxes):
        catalog_tokens.append(create_catalog_entry(index, bbox))
    catalog_tokens.append(create_no_exist_entry()) # 添加目标不存在的选项
    
    # 4. 目标指代 (大模型输出单个 Token)
    llm_input = concatenate(instruction, catalog_tokens, visual_input)
    refer_cot_token = LLM_generate_one_token(llm_input) # 输出如 <ped_2>
    
    # 5. 更新历史队列
    selected_bbox = get_bbox_from_token(refer_cot_token, detected_bboxes)
    bbox_history_queue.push(selected_bbox)
    
    # 6. 动作预测
    action_input = concatenate(llm_input, refer_cot_token)
    waypoints = action_head_mlp(LLM_forward(action_input))
    
    return waypoints, bbox_history_queue
```

### 第二模块：核心架构解释

LAViFiT 的核心逻辑是通过构建一个包含信息瓶颈的“预测-重建”闭环，来重塑视觉编码器的特征空间。其前向传播与优化流程如下：

1.  **状态提取 (State Extraction)：** 视觉编码器独立处理视频片段中的每一帧，输出 Patch 级别的特征序列以及池化后的全局状态特征 $s_t$。
2.  **逆动力学压缩 (Delta-IDM)：** 计算相邻两帧状态的残差 $\delta_t = s_{t+1} - s_t$。IDM（因果 Transformer）接收该残差，并将其线性投影到一个极低维度的空间（如 128 维），生成潜在动作 $a_t$。
3.  **前向状态预测 (Forward World Model)：** FWM（DiT 架构）接收当前状态 $s_t$，并通过自适应层归一化（adaLN）注入潜在动作 $a_t$，预测下一帧的状态 $\hat{s}_{t+1}$。目标是逼近真实的下一帧状态（带有停止梯度操作以防止表征坍塌）。
4.  **时序聚合与文本对齐 (Aggregation & Alignment)：** 聚合器将所有的状态 $s$ 和动作 $a$ 融合为一个视频片段级别的表征，并与文本编码器生成的“器械-动作-目标”三元组提示词进行余弦相似度计算，输出分类概率。
5.  **多层级正则化 (SIG Regularization)：** 在状态级别、动作级别以及随机采样的 Patch 级别上，计算经验分布与标准各向同性高斯分布之间的 Sliced Cramér-Wold Epps-Pulley 统计量，作为惩罚项加入总损失。

**核心伪代码实现逻辑：**

```python
def forward_lavifit(frames, text_prompts):
    # 1. Vision Encoder: Extract states and patch tokens
    # frames shape: [B, T+1, C, H, W]
    states, patch_tokens = vision_encoder(frames) # states: [B, T+1, D_s]
    
    # 2. Delta-IDM: Infer latent actions from state differences
    delta_states = states[:, 1:] - states[:, :-1] # [B, T, D_s]
    latent_actions = idm(delta_states) # Compressed to [B, T, D_a], D_a << D_s
    
    # 3. Forward World Model: Predict next state
    # Stop-gradient on target to prevent collapse
    target_states = states[:, 1:].detach() 
    predicted_states = fwm(states[:, :-1], latent_actions) # Conditioned via adaLN
    
    # 4. Aggregation & Classification
    clip_embedding = aggregator(states, latent_actions) # [B, D_t]
    text_embeddings = text_encoder(text_prompts) # [Num_classes, D_t]
    logits = cosine_similarity(clip_embedding, text_embeddings)
    
    # 5. Loss Computation
    # Classification Loss (BCE)
    loss_cls = bce_with_logits(logits, ground_truth)
    
    # Prediction Loss (MSE between predicted and target states)
    loss_pred = mse_loss(predicted_states, target_states)
    
    # SIG Regularization (Anti-collapse for states, actions, and patches)
    loss_sig_state = sig_regularizer(states)
    loss_sig_action = sig_regularizer(latent_actions)
    
    sampled_patches = random_subsample(patch_tokens, num_samples=32)
    loss_sig_patch = sig_regularizer(sampled_patches)
    
    total_loss = loss_cls + lambda_pred * loss_pred + \
                 lambda_s * (loss_sig_state + loss_sig_action) + \
                 lambda_p * loss_sig_patch
                 
    return total_loss
```

### 第二模块：核心架构解释

Dreamer-CPC 的核心架构是对 DreamerV3 的循环状态空间模型（RSSM）进行了多智能体通信维度的扩展。其运行流程分为世界模型学习与想象空间策略优化两个阶段：

**1. 带有消息模块的 RSSM 状态更新**
每个智能体维护一个独立的世界模型。在时间步 $t$，智能体不仅利用自身的历史隐状态和动作，还接收来自其他智能体的“预测消息”（通过停止梯度截断反向传播，保证去中心化），共同更新确定性循环状态 $h_t$。

**2. 消息的先验与后验推断**
消息模块包含一个循环状态 $\xi_t$。模型首先从 $\xi_t$ 生成消息先验 $\hat{m}_t$（用于状态流转）；随后结合当前观测推断出的随机隐状态 $z_t$，生成包含当前真实观测信息的后验消息 $m_t$（用于观测重建）。

**3. 统一变分目标的联合优化**
世界模型与消息模块在同一个变分下界（ELBO）下进行联合优化。损失函数不仅包含观测和奖励的重建损失，还包含隐状态的 KL 散度正则化，以及消息先验与后验之间的 KL 散度约束。

**4. 想象空间中的策略学习 (Actor-Critic)**
在策略训练阶段，智能体不与真实环境交互，而是在世界模型的隐空间中进行“想象 rollout”。在想象的每一步中，智能体同步生成消息、交换消息，并基于交换后的隐状态更新 Actor（策略）和 Critic（价值）网络。

**核心逻辑伪代码 (Python 风格)**：

```python
    单步世界模型与消息推断前向传播 (针对智能体 k)
    """
    # 1. 消息模块状态更新与先验生成
    # 结合上一时刻的推断消息 (其他智能体的消息使用 stop_gradient)
    joint_msg_prev = concat(inferred_msg_prev.self, stop_gradient(inferred_msg_prev.others))
    msg_state_t = update_msg_rnn(msg_state_prev, joint_msg_prev)
    msg_prior_t = sample_msg_prior(msg_state_t)
    
    # 2. RSSM 确定性状态更新
    # 将联合消息先验注入世界模型动力学
    joint_msg_prior_t = concat(msg_prior_t.self, stop_gradient(msg_prior_t.others))
    h_t = rssm.transition(h_prev, z_prev, a_prev, joint_msg_prior_t)
    
    # 3. 隐状态后验推断 (结合当前真实观测)
    z_prior_t = rssm.sample_z_prior(h_t)
    z_post_t = rssm.sample_z_posterior(h_t, obs_t)
    
    # 4. 消息后验推断 (结合当前隐状态)
    msg_post_t = sample_msg_posterior(msg_state_t, h_t, z_post_t)
    
    # 5. 观测与奖励重建 (基于联合后验消息)
    joint_msg_post_t = concat(msg_post_t.self, stop_gradient(msg_post_t.others))
    reconstructed_obs = decoder.reconstruct_obs(h_t, z_post_t, joint_msg_post_t)
    predicted_reward = decoder.predict_reward(h_t, z_post_t)
    
    return h_t, z_post_t, msg_state_t, msg_post_t
```
