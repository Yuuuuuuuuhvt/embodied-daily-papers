### 第二模块：核心架构解释

EXIMO 框架的运行逻辑严格分为三个解耦的阶段：Explore（探索）、Imitate（模仿）和 Optimize（优化）。

1. **Explore (VLM 引导的数据收集)**: 给定一个超出 VLA 训练分布的复杂自然语言目标 $g$（例如“把猴子爱吃的水果放进碗里”）。在每个时间步，VLM 接收环境图像历史和目标 $g$，输出一个具体的子任务指令 $g_t$（例如“用右手拿起黄色香蕉”）。基础 VLA 接收 $g_t$ 并输出底层动作 $a$。环境运行结束后，利用环境内置的成功检测器（Success Detector）过滤出成功的轨迹存入缓冲区。
2. **Imitate (基于 VLM 编排数据的监督微调)**: 提取缓冲区中的成功轨迹 $(s, g, a)$。注意，这里的目标标签是原始的高层目标 $g$，而不是 VLM 生成的子目标 $g_t$。使用行为克隆（BC）损失对基础 VLA 进行监督微调（SFT）。这一步的本质是**自我蒸馏**，迫使 VLA 将 VLM 的多步推理能力内化，从而在推理阶段完全剥离 VLM，消除高昂的延迟。
3. **Optimize (在线残差强化学习)**: 冻结（或作为基座）微调后的 VLA。引入一个轻量级的残差策略网络，该网络接收状态 $s$、目标 $g$ 和 VLA 的输出动作 $a^{VLA}$，输出一个残差动作 $\Delta a$。最终执行的动作 $a = a^{VLA} + \Delta a$。使用 MPO（Maximum a Posteriori Policy Optimisation）算法在环境中进行在线强化学习，进一步逼近最优策略。

```python
def eximo_pipeline(vlm, vla, env, tasks, num_episodes):
    success_buffer = []
    
    # Stage 1: Explore (VLM-Guided Data Collection)
    for task in tasks:
        for _ in range(num_episodes):
            state = env.reset(task)
            high_level_goal = task.goal
            episode_trajectory = []
            done = False
            
            while not done:
                # VLM acts as a high-level planner
                sub_goal = vlm.generate_instruction(state_history, high_level_goal)
                # VLA executes the sub-goal
                action = vla.predict_action(state, sub_goal)
                
                next_state, reward, done, success = env.step(action)
                # Store trajectory with HIGH-LEVEL goal, not sub-goal
                episode_trajectory.append((state, high_level_goal, action))
                state = next_state
                
            if success:
                success_buffer.extend(episode_trajectory)
                
    # Stage 2: Imitate (Supervised Finetuning / Distillation)
    # Train VLA to directly map (state, high_level_goal) -> action
    vla_sft = copy.deepcopy(vla)
    for epoch in range(sft_epochs):
        for batch in dataloader(success_buffer):
            states, goals, actions = batch
            loss = behavior_cloning_loss(vla_sft(states, goals), actions)
            loss.backward()
            vla_sft.optimizer.step()
            
    # Stage 3: Optimize (Residual Online RL)
    residual_policy = ResidualNetwork()
    rl_agent = MPO_Agent(residual_policy)
    
    for _ in range(rl_steps):
        state = env.reset()
        done = False
        while not done:
            # Base action from finetuned VLA
            base_action = vla_sft.predict_action(state, high_level_goal)
            # Residual action from RL policy
            delta_action = residual_policy(state, high_level_goal, base_action)
            
            final_action = base_action + delta_action
            next_state, reward, done, _ = env.step(final_action)
            
            rl_agent.store_transition(state, base_action, delta_action, reward, next_state)
            rl_agent.train_step()
            state = next_state

    return vla_sft, residual_policy
```

Orthogonal JEPA 的核心架构将预测机制与观测数据的几何形态解耦，分为四个关键流程：

1. **上下文-目标接口 (Context-Target Interface)**：通过领域适配器（Domain Adapter）将原始观测映射为 Token。在线编码器（Online Encoder）处理上下文生成表征 $z_c$，动量编码器（EMA Target Encoder）处理目标生成目标表征 $z_t$（停止梯度）。
2. **正交预测分解 (Orthogonal Predictive Factorization)**：引入 $K$ 个可学习的基矩阵 $B_k$。目标表征 $z_t$ 被投影到这些基矩阵上，分解为 $K$ 个独立的低维目标分量 $z_t^{(k)}$。
3. **多分支预测 (Multi-branch Prediction)**：设立 $K$ 个独立的预测头 $q_k$。每个预测头接收共享的上下文表征 $z_c$，负责预测对应的目标分量 $\hat{z}_t^{(k)}$。
4. **状态合成与正则化 (State Synthesis & Regularization)**：将所有预测出的分量拼接，通过基矩阵的伪逆（Pseudo-inverse）重新合成为完整的预测状态 $\hat{z}_t$。训练过程中引入正交性损失（确保基矩阵相互正交）、因子活跃度损失（防止预测维度死区）和编码器方差损失（防止表征坍塌）。

```python
import torch
import torch.nn as nn

class OrthogonalJEPA(nn.Module):
    def __init__(self, d_model, K, r):
        super().__init__()
        self.K = K
        self.r = r # K * r = d_model
        
        self.online_encoder = Encoder()
        self.target_encoder = Encoder() # EMA updated, no gradients
        
        # K learned basis matrices, each shape [d_model, r]
        self.B = nn.ParameterList([nn.Parameter(torch.randn(d_model, r)) for _ in range(K)])
        
        # K dedicated prediction branches
        self.predictors = nn.ModuleList([Predictor(d_model, r) for _ in range(K)])

    def forward(self, context, target):
        # 1. Encode Context and Target
        z_c = self.online_encoder(context)
        with torch.no_grad():
            z_t = self.target_encoder(target) # [batch, d_model]
            
        # 2. Factorize Target State (Analysis)
        z_t_factors = []
        for k in range(self.K):
            # Project target onto basis k
            factor_k = z_t @ self.B[k] # [batch, r]
            z_t_factors.append(factor_k)
            
        # 3. Multi-branch Prediction
        z_hat_factors = []
        for k in range(self.K):
            # Predict factor k from shared context
            pred_k = self.predictors[k](z_c) # [batch, r]
            z_hat_factors.append(pred_k)
            
        # 4. State Synthesis (for downstream use, via pseudo-inverse)
        u_hat = torch.cat(z_hat_factors, dim=-1) # [batch, d_model]
        B_concat = torch.cat(list(self.B), dim=-1) # [d_model, d_model]
        B_pinv = torch.linalg.pinv(B_concat.T)
        z_hat_synthesized = u_hat @ B_pinv.T # Complete predicted state
        
        # 5. Compute Losses
        # Predictive Regression Loss
        L_pred = sum(nn.functional.mse_loss(z_hat_factors[k], z_t_factors[k]) for k in range(self.K))
        
        # Orthogonality Loss (simplified: B_k^T * B_k -> I, B_i^T * B_j -> 0)
        L_orth = compute_orthogonality_loss(self.B)
        
        # Factor Activity & Encoder Variance Loss (prevent collapse)
        L_fac = compute_activity_loss(z_t_factors)
        L_enc = compute_variance_loss(z_c)
        
        total_loss = L_pred + lambda_orth * L_orth + lambda_fac * L_fac + lambda_enc * L_enc
        return total_loss, z_hat_synthesized
```

### 第二模块：核心架构解释

EXIMO 框架的运行逻辑严格分为三个解耦的阶段：Explore（探索）、Imitate（模仿）和 Optimize（优化）。

1. **Explore (VLM 引导的数据收集)**: 给定一个超出 VLA 训练分布的复杂自然语言目标 $g$（例如“把猴子爱吃的水果放进碗里”）。在每个时间步，VLM 接收环境图像历史和目标 $g$，输出一个具体的子任务指令 $g_t$（例如“用右手拿起黄色香蕉”）。基础 VLA 接收 $g_t$ 并输出底层动作 $a$。环境运行结束后，利用环境内置的成功检测器（Success Detector）过滤出成功的轨迹存入缓冲区。
2. **Imitate (基于 VLM 编排数据的监督微调)**: 提取缓冲区中的成功轨迹 $(s, g, a)$。注意，这里的目标标签是原始的高层目标 $g$，而不是 VLM 生成的子目标 $g_t$。使用行为克隆（BC）损失对基础 VLA 进行监督微调（SFT）。这一步的本质是**自我蒸馏**，迫使 VLA 将 VLM 的多步推理能力内化，从而在推理阶段完全剥离 VLM，消除高昂的延迟。
3. **Optimize (在线残差强化学习)**: 冻结（或作为基座）微调后的 VLA。引入一个轻量级的残差策略网络，该网络接收状态 $s$、目标 $g$ 和 VLA 的输出动作 $a^{VLA}$，输出一个残差动作 $\Delta a$。最终执行的动作 $a = a^{VLA} + \Delta a$。使用 MPO（Maximum a Posteriori Policy Optimisation）算法在环境中进行在线强化学习，进一步逼近最优策略。

```python
# EXIMO 核心逻辑伪代码

def eximo_pipeline(vlm, vla, env, tasks, num_episodes):
    success_buffer = []
    
    # Stage 1: Explore (VLM-Guided Data Collection)
    for task in tasks:
        for _ in range(num_episodes):
            state = env.reset(task)
            high_level_goal = task.goal
            episode_trajectory = []
            done = False
            
            while not done:
                # VLM acts as a high-level planner
                sub_goal = vlm.generate_instruction(state_history, high_level_goal)
                # VLA executes the sub-goal
                action = vla.predict_action(state, sub_goal)
                
                next_state, reward, done, success = env.step(action)
                # Store trajectory with HIGH-LEVEL goal, not sub-goal
                episode_trajectory.append((state, high_level_goal, action))
                state = next_state
                
            if success:
                success_buffer.extend(episode_trajectory)
                
    # Stage 2: Imitate (Supervised Finetuning / Distillation)
    # Train VLA to directly map (state, high_level_goal) -> action
    vla_sft = copy.deepcopy(vla)
    for epoch in range(sft_epochs):
        for batch in dataloader(success_buffer):
            states, goals, actions = batch
            loss = behavior_cloning_loss(vla_sft(states, goals), actions)
            loss.backward()
            vla_sft.optimizer.step()
            
    # Stage 3: Optimize (Residual Online RL)
    residual_policy = ResidualNetwork()
    rl_agent = MPO_Agent(residual_policy)
    
    for _ in range(rl_steps):
        state = env.reset()
        done = False
        while not done:
            # Base action from finetuned VLA
            base_action = vla_sft.predict_action(state, high_level_goal)
            # Residual action from RL policy
            delta_action = residual_policy(state, high_level_goal, base_action)
            
            final_action = base_action + delta_action
            next_state, reward, done, _ = env.step(final_action)
            
            rl_agent.store_transition(state, base_action, delta_action, reward, next_state)
            rl_agent.train_step()
            state = next_state

    return vla_sft, residual_policy
```

Orthogonal JEPA 的核心架构将预测机制与观测数据的几何形态解耦，分为四个关键流程：

1. **上下文-目标接口 (Context-Target Interface)**：通过领域适配器（Domain Adapter）将原始观测映射为 Token。在线编码器（Online Encoder）处理上下文生成表征 $z_c$，动量编码器（EMA Target Encoder）处理目标生成目标表征 $z_t$（停止梯度）。
2. **正交预测分解 (Orthogonal Predictive Factorization)**：引入 $K$ 个可学习的基矩阵 $B_k$。目标表征 $z_t$ 被投影到这些基矩阵上，分解为 $K$ 个独立的低维目标分量 $z_t^{(k)}$。
3. **多分支预测 (Multi-branch Prediction)**：设立 $K$ 个独立的预测头 $q_k$。每个预测头接收共享的上下文表征 $z_c$，负责预测对应的目标分量 $\hat{z}_t^{(k)}$。
4. **状态合成与正则化 (State Synthesis & Regularization)**：将所有预测出的分量拼接，通过基矩阵的伪逆（Pseudo-inverse）重新合成为完整的预测状态 $\hat{z}_t$。训练过程中引入正交性损失（确保基矩阵相互正交）、因子活跃度损失（防止预测维度死区）和编码器方差损失（防止表征坍塌）。

**核心逻辑伪代码 (Python Style)**:

```python
import torch
import torch.nn as nn

class OrthogonalJEPA(nn.Module):
    def __init__(self, d_model, K, r):
        super().__init__()
        self.K = K
        self.r = r # K * r = d_model
        
        self.online_encoder = Encoder()
        self.target_encoder = Encoder() # EMA updated, no gradients
        
        # K learned basis matrices, each shape [d_model, r]
        self.B = nn.ParameterList([nn.Parameter(torch.randn(d_model, r)) for _ in range(K)])
        
        # K dedicated prediction branches
        self.predictors = nn.ModuleList([Predictor(d_model, r) for _ in range(K)])

    def forward(self, context, target):
        # 1. Encode Context and Target
        z_c = self.online_encoder(context)
        with torch.no_grad():
            z_t = self.target_encoder(target) # [batch, d_model]
            
        # 2. Factorize Target State (Analysis)
        z_t_factors = []
        for k in range(self.K):
            # Project target onto basis k
            factor_k = z_t @ self.B[k] # [batch, r]
            z_t_factors.append(factor_k)
            
        # 3. Multi-branch Prediction
        z_hat_factors = []
        for k in range(self.K):
            # Predict factor k from shared context
            pred_k = self.predictors[k](z_c) # [batch, r]
            z_hat_factors.append(pred_k)
            
        # 4. State Synthesis (for downstream use, via pseudo-inverse)
        u_hat = torch.cat(z_hat_factors, dim=-1) # [batch, d_model]
        B_concat = torch.cat(list(self.B), dim=-1) # [d_model, d_model]
        B_pinv = torch.linalg.pinv(B_concat.T)
        z_hat_synthesized = u_hat @ B_pinv.T # Complete predicted state
        
        # 5. Compute Losses
        # Predictive Regression Loss
        L_pred = sum(nn.functional.mse_loss(z_hat_factors[k], z_t_factors[k]) for k in range(self.K))
        
        # Orthogonality Loss (simplified: B_k^T * B_k -> I, B_i^T * B_j -> 0)
        L_orth = compute_orthogonality_loss(self.B)
        
        # Factor Activity & Encoder Variance Loss (prevent collapse)
        L_fac = compute_activity_loss(z_t_factors)
        L_enc = compute_variance_loss(z_c)
        
        total_loss = L_pred + lambda_orth * L_orth + lambda_fac * L_fac + lambda_enc * L_enc
        return total_loss, z_hat_synthesized
```

### 第二模块：核心架构解释

HiTac-WAM 的运行流程分为四个明确的阶段：上下文编码、分层触觉预测、动作候选排序、在线执行验证。

1. **有向多模态上下文编码**：模型接收视觉、动作、机器人状态、语言指令和双侧触觉历史。通过一个有向注意力掩码矩阵，触觉 Query 可以访问视觉和动作的上下文，但视觉和动作 Query 被禁止访问触觉 Token。这确保了视觉预测不会依赖于未执行的触觉信息。
2. **显式分层触觉预测**：对于采样的每一个动作块候选（Action Chunk），模型预测未来的触觉轨迹。预测严格按照物理顺序进行：首先预测接触状态（二分类）；然后提取接触头的中间特征，截断梯度后输入形变头，预测 3D 形变场；最后，截断接触状态和形变场的梯度，输入滑动头，预测滑动风险。
3. **预测引导的动作选择**：模型生成 $K$ 个动作块候选。利用视觉预测评估任务进度得分，利用触觉预测计算惩罚得分（无效接触、过度形变、滑动风险）。综合得分最高的动作块被选中执行。
4. **在线预测验证**：选中的触觉预测轨迹被保留为“参考基准”。在机器人执行动作时，实时采集真实的触觉观测，并与参考基准计算残差。通过核密度估计（KDE）计算异常得分，当连续多帧得分超过标定阈值时，触发重规划（退回安全状态并重新生成动作）。

### 第二模块：核心架构解释

DECOWAM 的架构设计本质上是一个“预训练主干 + 物理语义解耦插件”的范式。其训练分为两阶段：第一阶段对 FastWAM 进行全参数域适应；第二阶段冻结主干，仅训练 25.95M 的解耦模块。

**核心流程拆解：**
1.  **输入处理：** 接收当前 RGB 图像、语言指令特征以及 14 维的本体感受状态（包含 6-DoF 臂、夹爪、3-D 底盘速度等）。
2.  **未来信息蒸馏（仅训练阶段）：** 教师模型编码当前与未来 8 帧的 VAE 隐变量，学生模型仅编码当前帧。通过几何保持损失（Geometry Preservation）和蒸馏损失，迫使学生模型的因果隐变量学习到包含未来动作结果的表征。
3.  **底盘-机械臂对抗解耦（Base-Arm Factorization）：** 将动作上下文特征映射为底盘隐变量和机械臂隐变量。使用直接预测头保证各自特征的准确性，同时使用梯度反转层（GRL）构建交叉预测头，消除隐变量中包含的对方信息。
4.  **自运动条件注入（Ego-motion Conditioning）：** 将当前的底盘速度进行归一化并投影，作为额外的 Token 注入到视频生成分支（WAN backbone）中，显式解释相机视角的移动。
5.  **流匹配输出（Flow Matching）：** 视频专家和动作专家（ActionDiT）基于上述解耦后的条件，通过条件流匹配（Conditional Flow Matching）分别生成未来 8 帧视频和 48 步的动作块。

**核心逻辑伪代码 (Python 风格):**

```python
import torch.nn as nn

class GradientReversalLayer(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x):
        return x.view_as(x)
    @staticmethod
    def backward(ctx, grad_output):
        return grad_output.neg() # 反转梯度

def GRL(x):
    return GradientReversalLayer.apply(x)

class DECOWAM_Stage2(nn.Module):
    def __init__(self, frozen_fastwam):
        super().__init__()
        self.backbone = frozen_fastwam
        self.backbone.requires_grad_(False) # 冻结主干
        
        # 1. 残差适配器 (Residual Adapters)
        self.adapters = nn.ModuleList([Adapter(dim=128) for _ in range(num_blocks)])
        
        # 2. 师生蒸馏瓶颈 (Future Bottleneck)
        self.student_encoder = Encoder(causal_only=True)
        
        # 3. 底盘-机械臂解耦头 (Base-Arm Factorization)
        self.base_proj = nn.Linear(hidden_dim, 16)
        self.arm_proj = nn.Linear(hidden_dim, 16)
        
        self.base_head = nn.Linear(16, 4) # 预测底盘动作
        self.arm_head = nn.Linear(16, 8)  # 预测机械臂动作
        self.cross_base_head = nn.Linear(16, 4) # 用于GRL
        self.cross_arm_head = nn.Linear(16, 8)  # 用于GRL
        
        # 4. 自运动条件投影
        self.ego_proj = nn.Linear(3, hidden_dim)

    def forward(self, rgb_curr, state_curr, lang_emb, rgb_future=None):
        # --- 动作分支解耦 ---
        action_context = self.student_encoder(rgb_curr, state_curr)
        
        z_base = self.base_proj(action_context)
        z_arm = self.arm_proj(action_context)
        
        # 直接预测 (保留自身信息)
        pred_base = self.base_head(z_base)
        pred_arm = self.arm_head(z_arm)
        
        # 对抗预测 (消除对方信息)
        pred_base_from_arm = self.cross_base_head(GRL(z_arm))
        pred_arm_from_base = self.cross_arm_head(GRL(z_base))
        
        # 组合动作条件
        decoupled_action_cond = torch.cat([z_base, z_arm], dim=-1)
        
        # --- 视频分支解耦 ---
        base_velocity = state_curr[:, 7:10] # 提取底盘速度 (vx, vy, wz)
        ego_token = self.ego_proj(base_velocity)
        
        # --- 流匹配生成 (Flow Matching) ---
        # 动作生成 (ActionDiT)
        action_chunk = self.backbone.action_expert(
            cond=decoupled_action_cond, 
            adapters=self.adapters
        )
        
        # 视频生成 (WAN)
        future_video = self.backbone.video_expert(
            cond=ego_token, 
            adapters=self.adapters
        )
        
        return action_chunk, future_video, (pred_base, pred_arm, pred_base_from_arm, pred_arm_from_base)

    def compute_disentanglement_loss(self, preds, gt_action):
        pred_base, pred_arm, pred_base_from_arm, pred_arm_from_base = preds
        gt_base = gt_action[:, 7:11]
        gt_arm = gt_action[:, 0:8]
        
        # 自身重建损失 + 交叉对抗损失
```

### 第二模块：核心架构解释

本文并非提出单一的新模型，而是构建了一个**三阶段（Three-Stage）的标准化训练管线**，用于公平对比所有 LAM 设计。

**阶段一：表示学习（Pre-training）**
仅使用无动作标签的纯视频数据。通过逆动力学模型（IDM）从连续帧提取潜动作 $z_t$，再通过正动力学模型（FDM）结合当前帧和 $z_t$ 重建未来帧。此阶段用于评估不同的建模范式（如 LAPO, CoMo, CFD-AE）和正则化方法（如 VAE, VQ-VAE）。

**阶段二：VLM 骨干微调（Mid-training）**
冻结阶段一训练好的 IDM，将其作为“自动标注器”，为视频数据生成潜动作标签 $z_t$。使用这些 $(o_t, z_t, l)$ 数据对 VLM（如 Qwen3-VL）进行微调，使其学会从视觉和语言指令中预测潜动作。

**阶段三：下游策略学习（Post-training）**
引入少量带有真实物理动作 $a_t$ 的机器人数据。测试不同的集成策略（DAP, LAP, JAP）：是仅仅把潜动作当预训练目标扔掉（DAP），还是作为中间瓶颈层（LAP），亦或是与物理动作联合预测（JAP）。

```python
# ==========================================
# Stage I: Latent Action Representation Learning
# ==========================================
def stage1_train_step(frame_t, frame_t_next):
    # IDM infers latent action from consecutive frames
    latent_action = IDM(frame_t, frame_t_next)
    
    # Apply Regularization (e.g., VAE KL divergence)
    reg_loss = compute_regularization(latent_action, method="VAE", lambda_reg=1e-7)
    
    # FDM reconstructs future frame
    pred_frame_t_next = FDM(frame_t, latent_action)
    recon_loss = mse_loss(pred_frame_t_next, frame_t_next)
    
    total_loss = recon_loss + reg_loss
    total_loss.backward()
    return IDM, FDM

# ==========================================
# Stage II & III: VLM Fine-tuning & Integration Strategies
# ==========================================
def downstream_policy_forward(vlm_backbone, frame_t, language_inst, strategy="LAP"):
    # Extract high-level features from VLM
    features = vlm_backbone(frame_t, language_inst)
    
    if strategy == "DAP":
        # Direct Action Prediction: Latent action is ignored during physical inference
        # (Latent head was only used in Stage II)
        physical_action = PhysicalActionHead(features)
        return physical_action
        
    elif strategy == "LAP":
        # Latent-to-Action Prediction: Latent action acts as an intermediate bottleneck
        pred_latent = LatentActionHead(features)
        physical_action = PhysicalActionHead(pred_latent)
        return physical_action
        
    elif strategy == "JAP":
        # Joint Action Prediction: Predict both in parallel from shared features
        pred_latent = LatentActionHead(features)
        physical_action = PhysicalActionHead(features)
        return pred_latent, physical_action
```

### 第二模块：核心架构解释

SafeBranch 框架的运行流程分为数据构建与策略对齐两个核心阶段。

**阶段一：基于回滚的分支对构建 (Branch-Pair Construction)**
1. 深度优先搜索与前置审查：智能体在环境中执行任务。在每一步执行前，前置批评者（Prospective Critic）检查提议动作是否违规。若违规，记录当前状态为“安全关键步”，获取批评者的纠正反馈，并引导智能体生成安全动作。
2. 轨迹后置审查：任务结束后，后置批评者（Retrospective Critic）检查最终状态是否存在残留危险（如水龙头未关）。若存在，计算出导致该危险的历史步骤，将仿真环境回滚（Rollback）至该步骤，并引导智能体生成修复动作。
3. 后见之明重打标（Hindsight Relabeling）：这是最关键的一步。在收集到的数据中，安全动作是在“带有批评者提示词”的情况下生成的。为了让智能体在部署时能独立判断，系统会强制剥离这些提示词，使得安全动作和不安全动作共享完全一致的、无提示的上下文输入。

**阶段二：分支偏好优化 (BranchPO)**
使用过滤后的同状态分支对数据，采用类似 DPO 的目标函数对 VLA 模型进行微调，最大化安全动作与不安全动作在同一状态下的对数概率差。

```python
def build_safebranch_data(actor, critic, env, tasks):
    branch_pairs = []
    
    for task in tasks:
        state = env.reset(task)
        trajectory = []
        
        while not task.is_done():
            # 1. 演员输出原始动作
            action_unsafe = actor.predict(state)
            
            # 2. 前置审查触发
            if critic.is_unsafe_before_execution(state, action_unsafe):
                critical_state = state.copy()
                # 获取批评者反馈
                feedback = critic.get_feedback(critical_state, action_unsafe)
                # 结合反馈生成安全动作
                action_safe = actor.predict(critical_state, prompt=feedback)
                
                # 记录原始分支对
                branch_pairs.append({
                    "state": critical_state,
                    "action_safe": action_safe,
                    "action_unsafe": action_unsafe,
                    "feedback": feedback
                })
                break # 实际流程中会执行安全动作并继续，此处简化
                
            state = env.step(action_unsafe)
            trajectory.append(action_unsafe)

        if task.is_done() and critic.has_residual_hazard(state):
            critical_step = critic.identify_hazard_step(trajectory)
            critical_state = env.rollback_to(critical_step)
            feedback = critic.get_feedback(critical_state, trajectory[critical_step])
            action_safe = actor.predict(critical_state, prompt=feedback)
            branch_pairs.append(...) # 记录后置分支对

    # 4. 后见之明重打标 (Hindsight Relabeling)
    training_data = []
    for pair in branch_pairs:
        # 强制剥离批评者反馈，确保上下文完全一致

def train_branchpo(actor, reference_actor, training_data, beta=0.1):
    # BranchPO 优化目标
    for state, action_safe, action_unsafe in training_data:
        # 计算当前策略的对数概率
        pi_safe = actor.log_prob(state, action_safe)
        pi_unsafe = actor.log_prob(state, action_unsafe)
        
        # 计算参考策略的对数概率
        ref_safe = reference_actor.log_prob(state, action_safe)
        ref_unsafe = reference_actor.log_prob(state, action_unsafe)
        
        # 计算隐式奖励差值
        reward_diff = (pi_safe - ref_safe) - (pi_unsafe - ref_unsafe)
        
        # 最小化负对数 Sigmoid 损失
        loss = -log_sigmoid(beta * reward_diff)
        loss.backward()
```

### 第二模块：核心架构解释

本文的方法论并非提出一个新的生成模型，而是提出一套极其严苛的**操作语义验证协议**。其核心流程分为四个阶段：

1. **构建响应图表与冻结执行器 (Frozen Chart & Executor)**
首先，使用包含丰富物理响应的训练集（不包含测试实体）训练一个降维的响应图表（Chart）和一个执行器（Executor）。执行器的任务是接收图表坐标和动作序列，输出物理响应。训练完成后，图表和执行器的参数被**完全冻结**。

2. **独立模态编译器训练 (Independent Modality Compilers)**
针对不同的传感器模态（如音频、加速度），在**完全不相交（Disjoint）**的证据面板（Panels）上独立训练编译器。
关键约束：编译器之间不可见、没有跨模态匹配损失（Matching loss）、没有实体 ID 标签。编译器必须学会将单模态输入映射到冻结的图表坐标中。

3. **DBOSC 替换证书测试 (DBOSC Testing)**
在测试阶段，输入未见过的物理实体。提取模态 A 在面板 0 的特征，以及模态 B 在面板 1 的特征。将它们分别通过各自的编译器映射到图表坐标，再通过冻结的执行器输出对**未见过的查询动作**的响应。计算这两个响应在物理空间中的距离（D_same）。该距离必须小于错误实体配对的距离（D_wrong）和种群平均距离（D_pop）。

4. **有序执行测试 (Ordered Execution)**
在受控系统中，测试模型对未见过的动作序列（如训练了 A、B，测试 AB 和 BA）的响应。这验证了模型是否不仅学到了静态的物理词汇，还掌握了动作组合的语法。

```python
import torch
import torch.nn as nn

class PlanningOrientedE2EAD(nn.Module):
    def __init__(self, perception_encoder, vla_reasoner, world_model, planner, safety_filter):
        super().__init__()
        # 提取结构化特征 (BEV/Vector Tokens)
        self.perception_encoder = perception_encoder 
        # 视觉-语言-动作对齐与语义推理
        self.vla_reasoner = vla_reasoner             
        # 预测未来潜状态，评估动作后果
        self.world_model = world_model               
        # 生成多模态候选轨迹
        self.planner = planner                       
        # 运行时硬规则安全保障
        self.safety_filter = safety_filter           

    def forward(self, sensor_data, route_intent, language_instruction):
        # 1. 提取当前场景的结构化中间表示
        scene_features = self.perception_encoder(sensor_data)
        
        # 2. VLA 模块融合语言指令，生成语义上下文与动作先验
        semantic_context = self.vla_reasoner(scene_features, language_instruction)
        
        # 3. 规划器生成多条候选轨迹 (应对多模态未来)
        candidate_trajectories = self.planner.generate_candidates(scene_features, route_intent)
        
        # 4. 世界模型前向推演：想象每条轨迹在未来的场景演变
        imagined_futures = self.world_model.rollout(scene_features, candidate_trajectories)
        
        # 5. 综合推演后果与语义约束，选出最优轨迹
        best_trajectory = self.planner.select_best_plan(
            candidate_trajectories, 
            imagined_futures, 
            semantic_context
        )
        
        # 6. 运行时安全过滤：拒绝违反物理边界或交规的危险轨迹
        safe_action = self.safety_filter(best_trajectory, scene_features)
        
        return safe_action, semantic_context
```

### 第二模块：核心架构解释

OrthoSkillVLA 的运行流程分为新技能的正交微调、模块化子空间估计以及免训练 MoE 路由绑定三个核心阶段。

1. **正交技能子空间自适应 (Orthogonal Skill Subspace Adaptation):**
在学习第 $k$ 个技能时，模型首先在当前数据集上计算初始梯度。将该梯度投影到历史技能占据的特征子空间（由正交基矩阵表征）的正交补空间中。利用残差梯度的奇异值分解（SVD）初始化 LoRA 的向下投影矩阵并冻结，仅训练向上投影矩阵，确保参数更新严格限制在正交子空间内。

2. **特征感知 MoE 解码器 (Feature-Aware MoE Decoder):**
冻结预训练的底层速度解码器，为当前新技能分配一个独立的轻量级专家网络进行训练，以提供输出层的速度场拟合能力。

3. **模块感知子空间估计 (Module-Aware Skill Subspace Estimation):**
技能训练完成后，收集该技能在各层的累积梯度。通过 SVD 提取新特征方向。关键在于：对 VLM 采用较低的能量阈值（如 0.99）以保留未来学习的容量；对 ActionHead 采用极高的能量阈值（如 0.9999）以严格保护脆弱的速度模式。

4. **免训练路由绑定 (Training-Free Routing Binding):**
提取解码器累积梯度的左奇异向量作为该技能的路由基。推理时，计算输入特征在各个技能路由基上的投影范数，选择范数最大的专家网络输出动作。

**核心逻辑伪代码 (Python 风格):**

```python
def train_orthoskill_vla(model, skills, epsilon_vlm, epsilon_head, rank):
    historical_bases = {} # M_{k-1}
    
    for k, skill_data in enumerate(skills):
        # 1. Orthogonal Subspace Adaptation
        initial_grads = compute_gradients(model, skill_data)
        
        for layer in model.adapted_layers:
            if layer in historical_bases:
                # Project gradient away from historical bases (Eq. 3)
                M_prev = historical_bases[layer]
                proj_grad = initial_grads[layer] - M_prev @ M_prev.T @ initial_grads[layer]
            else:
                proj_grad = initial_grads[layer]
                
            # Initialize LoRA A with top-r singular vectors and freeze
            U, _, _ = torch.svd(proj_grad)
            layer.lora_A.weight.data = U[:, :rank].T
            layer.lora_A.requires_grad = False
            layer.lora_B.requires_grad = True
            
        # Allocate and train new MoE expert for velocity decoder
        new_expert = Linear(d_in, d_action)
        
        # Train model (LoRA B and new_expert) on skill_data
        optimize(model, new_expert, skill_data)
        
        # 2. Module-Aware Subspace Estimation & Routing Binding
        accumulated_grads = compute_accumulated_gradients(model, skill_data)
        
        for layer in model.adapted_layers:
            G_k = accumulated_grads[layer]
            
            # Filter novel features (Eq. 1)
            if layer in historical_bases:
                M_prev = historical_bases[layer]
                G_hat = G_k - M_prev @ M_prev.T @ G_k
            else:
                G_hat = G_k
                
            U_hat, S_hat, V_hat = torch.svd(G_hat)
            
            # Apply module-specific energy threshold (Eq. 2)
            threshold = epsilon_vlm if is_vlm(layer) else epsilon_head
            m_k = determine_basis_count(G_hat, G_k, threshold)
            
            # Update historical bases
            new_basis = U_hat[:, :m_k]
            if layer in historical_bases:
                historical_bases[layer] = torch.cat([historical_bases[layer], new_basis], dim=1)
            else:
                historical_bases[layer] = new_basis
                
        # Bind routing basis for the MoE decoder
        G_dec = accumulated_grads['decoder']
        U_dec, _, _ = torch.svd(G_dec)
        model.router_bases[k] = U_dec # Used for Eq. 5 during inference
        
    return model

def inference(model, x):
    # Training-free routing (Eq. 5)
    max_affinity = -1
    selected_expert = None
    
    for k, basis in model.router_bases.items():
        affinity = torch.norm(x @ basis) ** 2
        if affinity > max_affinity:
            max_affinity = affinity
            selected_expert = model.experts[k]
            
    return selected_expert(x) + model.base_decoder(x)
```

### 第二模块：核心架构解释

该模型的整体架构分为三个核心阶段：**因果历史编码（Causal History Encoding）**、**时空特征融合（Temporal-Spatial Encoding）**以及**闭环分块预测（Closed-loop Chunked Future Prediction）**。

1. **历史编码与融合**：模型接收过去 5 帧的 RGB 图像和对应的 2D 轨迹坐标。图像通过冻结的 SurgMotion ViT-L 提取多层级视觉 Token；轨迹坐标通过 MLP 映射为高维特征。两者在空间上广播并相加，形成包含场景与运动信息的联合表征。
2. **时空上下文提取**：联合表征输入时空编码器，时间注意力捕捉历史依赖，空间处理保留手术视野的局部结构，最终输出最新的历史状态作为共享上下文 $C$。
3. **双头分块预测**：
   - **视觉头**：预测未来 3 步的隐变量残差（$\Delta Z$），加上当前状态得到未来视觉 Token。
   - **轨迹头**：基于最后两步计算恒定速度先验，网络仅预测轨迹的残差修正量（$r$）。
4. **自回归 Rollout 与计划采样**：预测出的 3 步状态被拼接到历史窗口中，剔除最老的 3 步，进入下一次循环。训练时引入 Scheduled Sampling，按概率混合真实值与预测值作为下一步输入，以缩小训练与推理的分布差异。

```python
import torch
import torch.nn as nn

class JointWorldActionModel(nn.Module):
    def __init__(self, visual_encoder, spatial_temporal_encoder, visual_head, trajectory_head):
        super().__init__()
        self.visual_encoder = visual_encoder # Frozen SurgMotion ViT-L
        self.st_encoder = spatial_temporal_encoder
        self.visual_head = visual_head
        self.traj_head = trajectory_head
        self.traj_mlp = nn.Sequential(nn.Linear(2, hidden_dim), ...)
        
    def forward_chunk(self, history_frames, history_trajs, chunk_size=3):
        # 1. Encode History
        visual_tokens = self.visual_encoder(history_frames) # [B, T, C, H, W]
        traj_embeds = self.traj_mlp(history_trajs)          # [B, T, C]
        
        # Broadcast and fuse
        traj_embeds_spatial = traj_embeds.unsqueeze(-1).unsqueeze(-1).expand_as(visual_tokens)
        fused_features = visual_tokens + traj_embeds_spatial
        
        # 2. Temporal-Spatial Encoding
        context = self.st_encoder(fused_features) # Get latest state context
        
        # 3. Dual-Head Prediction (Predict next `chunk_size` steps)
        # Visual: Predict residual changes
        delta_z = self.visual_head(context) 
        pred_visual_tokens = visual_tokens[:, -1:] + delta_z
        
        # Trajectory: Constant velocity prior + residual correction
        last_pos = history_trajs[:, -1]
        prev_pos = history_trajs[:, -2]
        velocity = last_pos - prev_pos
        
        pred_trajs = []
        for j in range(1, chunk_size + 1):
            prior_pos = last_pos + j * velocity
            residual = self.traj_head(context, step=j)
            pred_trajs.append(prior_pos + residual)
            
        return pred_visual_tokens, torch.stack(pred_trajs, dim=1)

    def autoregressive_rollout(self, init_frames, init_trajs, total_steps=15, chunk_size=3):
        current_frames = init_frames
        current_trajs = init_trajs
        all_pred_visuals, all_pred_trajs = [], []
        
        # Loop 5 times for 15 steps
        for _ in range(total_steps // chunk_size):
            pred_v, pred_t = self.forward_chunk(current_frames, current_trajs, chunk_size)
            
            all_pred_visuals.append(pred_v)
            all_pred_trajs.append(pred_t)
            
            # Update history window (drop oldest 3, append new 3)
            current_frames = torch.cat([current_frames[:, chunk_size:], pred_v], dim=1)
            current_trajs = torch.cat([current_trajs[:, chunk_size:], pred_t], dim=1)
            
        return torch.cat(all_pred_visuals, dim=1), torch.cat(all_pred_trajs, dim=1)
```

4. **关键数据**：

### 第二模块：核心架构解释

EAFG 框架将传统的单次规划流程重构为“探索-评估-执行”的闭环。其核心流程分为三个阶段：

1. **证据获取 (Evidence Acquisition)**：系统接收自然语言指令后，VLM 首先生成一组仅用于探索的子目标（如打开冰箱、移开遮挡物）。这些动作被严格限制为“安全且可逆”的操作，禁止直接进行烹饪等不可逆的主任务动作。TAMP 引擎执行这些动作并收集视觉观察结果（拼接为图像拼贴）。
2. **可行性门控 (Feasibility Gating)**：VLM 接收执行历史、文本状态摘要和最新的视觉拼贴，更新“证据状态（Evidence State）”，并输出三种门控状态之一：`ready_to_plan`（证据充足，可执行任务）、`need_more_evidence`（证据不足，需继续探索）或 `halt`（证据表明任务不可行，直接终止）。
3. **证据条件规划 (Evidence-Conditioned Planning)**：当门控输出 `ready_to_plan` 时，系统将经过验证的证据状态作为上下文输入给任务规划器，生成最终的、基于客观视觉事实的任务子目标序列。

**核心逻辑伪代码**：

```python
def EAFG_pipeline(instruction, initial_observation):
    evidence_state = initialize_state(initial_observation)
    observation_collage = [initial_observation]
    
    # 阶段 1 & 2: 证据获取与可行性门控循环
    for t in range(MAX_ITERATIONS):
        # VLM 评估当前证据并输出门控状态
        gate_status = VLM_evaluate_gating(instruction, evidence_state, observation_collage)
        
        if gate_status == "ready_to_plan":
            break
        elif gate_status == "halt":
            return "Execution Halted: Goal infeasible based on evidence."
        elif gate_status == "need_more_evidence":
            # VLM 生成纯探索性子目标 (如 open(cabinet))
            exploratory_subgoals = VLM_generate_exploration_goals(instruction, evidence_state)
            
            for subgoal in exploratory_subgoals:
                # TAMP 尝试实例化并执行探索动作
                success, new_obs = TAMP_execute(subgoal)
                if success:
                    observation_collage.append(new_obs)
            
            # 更新证据状态 (剔除过时/矛盾的假设)
            evidence_state = VLM_update_state(evidence_state, observation_collage)
            
    if gate_status != "ready_to_plan":
        return "Execution Failed: Max exploration iterations reached."
        
    # 阶段 3: 证据条件规划
    # 仅基于已验证的 evidence_state 生成实质性任务目标
    task_subgoals = VLM_generate_task_goals(instruction, evidence_state)
    
    # 执行最终任务
    final_plan_success = TAMP_execute_sequence(task_subgoals)
    return final_plan_success
```

**阶段一：物理感知扩散世界模型（IEWM）训练**
1. **条件构建**：提取历史观测状态和历史动作，并假设未来一段时间内维持上一时刻的动作（Held-action），构建条件向量。

**阶段二：在线强化学习（RL）策略学习**
1. **基线预测与动作评估**：在每个决策步，冻结的 IEWM 首先预测一条“保持当前动作”的未来热力学基线。该基线作为额外输入喂给分支 Q 网络（Branch-wise Q-network），帮助网络在评估当前动作价值时，显式地“看到”未来的热惯性演变。
2. **延迟信用分配**：智能体执行动作后，IEWM 再次预测一条“持续执行该新动作”的未来轨迹。利用这条想象的轨迹计算多步 TD-lambda 目标，将未来的舒适度和能耗反馈反向传播给当前动作，解决热延迟带来的信用分配难题。

```python
def train_world_model(offline_data, diffusion_model, physics_equation, optimizer):
    for batch in offline_data:
        # 1. Extract context and target
        history_obs, history_actions = batch['history']
        future_target_trajectory = batch['future_target']
        
        # Construct condition (assuming holding the last action)
        held_action = history_actions[-1]
        condition = concat(history_obs, history_actions, repeat(held_action, horizon))
        
        # 2. Standard Diffusion Forward & Denoising
        noise = sample_gaussian()
        step = sample_time_step()
        noisy_trajectory = add_noise(future_target_trajectory, noise, step)
        predicted_noise = diffusion_model(noisy_trajectory, step, condition)
        loss_diff = MSE(predicted_noise, noise)
        
        # 3. Physics-Aware Regularization
        # Generate clean trajectory prediction
        pred_trajectory = diffusion_model.denoise(noisy_trajectory, condition)
        
        # Calculate physical residuals (Heat Balance Equation)
        # Q_zone + Q_out + Q_rad + Q_int + Q_hvac + bias
        true_physics_residual = physics_equation.calc_residual(future_target_trajectory)
        pred_physics_residual = physics_equation.calc_residual(pred_trajectory)
        
        loss_phys_true = HuberLoss(true_physics_residual) # Identify physical parameters
        loss_phys_pred = HuberLoss(pred_physics_residual) # Regularize diffusion output
        loss_bias = L2_Norm(physics_equation.bias)        # Prevent bias exploitation
        
        # Total Loss
        total_loss = loss_diff + lambda_1 * loss_phys_true + lambda_2 * loss_phys_pred + lambda_3 * loss_bias
        
        optimizer.zero_grad()
        total_loss.backward()
        optimizer.step()

def train_rl_controller(env, frozen_world_model, q_network, optimizer):

    for step in range(max_steps):

        condition = build_condition(obs_buffer, action_buffer)
        thermal_baseline = frozen_world_model.generate(condition)

        action = q_network.select_action(obs, thermal_baseline)
        next_obs, reward = env.step(action)
        
        # 3. Predict committed rollout for delayed credit assignment
        committed_condition = build_condition(obs_buffer, action_buffer, new_action=action)
        imagined_trajectory = frozen_world_model.generate(committed_condition)
        
        # 4. Compute TD-lambda target using imagined future rewards
        imagined_rewards = compute_rewards(imagined_trajectory)
        td_target = compute_td_lambda(reward, imagined_rewards, q_network.value(next_obs))
        
        # 5. Update Q-network
        q_loss = MSE(q_network(obs, action, thermal_baseline), td_target)
        optimizer.zero_grad()
        q_loss.backward()
        optimizer.step()
```

```python
    def __init__(self, vlm_model, llm_judge):
        self.vlm = vlm_model
        self.judge = llm_judge

    def evaluate_video(self, video_frames, qa_annotations):
        results = {"perception_mcq": [], "reasoning_open_ended": []}
        
        for qa in qa_annotations:
            prompt = self._build_prompt(qa["question"])
            
            # VLM 仅基于视觉特征和问题进行推理
            prediction = self.vlm.generate(video_frames, prompt)
            
            if qa["type"] == "MCQ":

                parsed_option = self._extract_option(prediction)
                is_correct = (parsed_option == qa["correct_answer"])
                results["perception_mcq"].append(is_correct)
                
            elif qa["type"] == "Open-ended":

                ground_truth = qa["answer"]
                score = self.judge.score_reasoning(
                    prediction=prediction, 
                    ground_truth=ground_truth, 
                    rubric="0-5 scale: 5=correct agent+reasoning, 3=correct agent+weak reasoning, 0=irrelevant"
                )
                results["reasoning_open_ended"].append(score)
                
        return results
```

# 第二模块：核心架构解释

该论文的系统架构分为四个明确的层级，形成了一个从感知到离线知识，再到多智能体决策与底层控制的完整闭环：

1. **感知层 (Perception):** 
使用 YOLOv11 处理摄像头图像进行目标检测（车辆、行人、红绿灯），结合基于边缘检测的车道线模块和交叉路口检测模块，将多模态输入融合为统一的结构化感知状态（包含距离、相对速度、车道偏移等）。

2. **知识库层 (Knowledge Base):** 
完全离线运行。利用 LLM 生成约 100 条适用于 CARLA 的常识驾驶规则（如“雨天减速”、“视线受阻时减速”）。同时，LLM 被用作 RL 奖励函数的评估器，通过分析训练日志来迭代修改 Reward 公式。

3. **多智能体推理层 (Multi-Agent Reasoning):** 
四个专用智能体并行工作，每个智能体对应不同的 ISO 26262 ASIL 安全完整性等级：
- **Safety Agent (ASIL-D):** 最高优先级，计算 TTC（碰撞时间），匹配 LLM 生成的常识规则，负责紧急制动。
- **Situation Agent (ASIL-C):** 评估 ODD（运行设计域）合规性，处理天气、光照等环境上下文。
- **Planning Agent (ASIL-B):** 负责战略决策，如目标车道跟踪和转弯决策。
- **Behavior Agent (ASIL-A):** 负责驾驶舒适度优化，如减少转向方差。

4. **编排与控制层 (Orchestrator & Control):** 
编排器接收四个智能体的动作建议（目标速度、转向偏移等）和置信度，基于 ASIL 权重进行融合。如果高安全等级智能体（ASIL-D/C）触发高置信度的停止指令，将直接行使否决权（Veto）。最终指令交由底层的 PID 控制器和 PPO 训练的 RL 策略执行。

```python
class Orchestrator:
    def __init__(self):
        # 定义各Agent的基础权重与ASIL乘数
        self.agents = {
            "Safety":   {"base_w": 2.5, "asil_m": 2.0, "agent": SafetyAgent()},   # ASIL-D
            "Situation":{"base_w": 1.5, "asil_m": 1.5, "agent": SituationAgent()},# ASIL-C
            "Planning": {"base_w": 1.2, "asil_m": 1.2, "agent": PlanningAgent()}, # ASIL-B
            "Behavior": {"base_w": 0.8, "asil_m": 1.0, "agent": BehaviorAgent()}  # ASIL-A
        }
        self.conflict_multiplier = 1.3

    def get_final_action(self, perception_state):
        recommendations = {}
        
        # 1. 并行获取各Agent的决策建议与置信度
        for name, config in self.agents.items():
            rec, confidence = config["agent"].evaluate(perception_state)
            recommendations[name] = {"rec": rec, "conf": confidence}
            
        # 2. 绝对安全否决权检查 (Safety Veto)
        if recommendations["Safety"]["rec"].action == "EMERGENCY_STOP" and recommendations["Safety"]["conf"] > 0.9:
            return execute_emergency_stop()
            
        # 3. ASIL加权优先级融合
        fused_action = Action()
        total_weight = 0.0
        
        for name, config in self.agents.items():
            base_w = config["base_w"]
            asil_m = config["asil_m"]
            conf = recommendations[name]["conf"]
            
            # 判定是否在冲突中胜出以应用冲突乘数
            b_conflict = self.conflict_multiplier if self.check_conflict_winner(name, recommendations) else 1.0
            
            # 计算有效权重: w = w_base * m_ASIL * c * b_conflict
            effective_weight = base_w * asil_m * conf * b_conflict
            
            fused_action += recommendations[name]["rec"] * effective_weight
            total_weight += effective_weight
            
        return fused_action / total_weight
```

```python
class GeneralEmbodiedAgent:
    def __init__(self, llm, knowledge_base, reasoning_engine, robot_controller):
        self.llm = llm
        self.kb = knowledge_base
        self.reasoner = reasoning_engine
        self.robot = robot_controller
        self.episodic_memory = []

    def execute_task(self, instruction):
        # 1. 行动层：获取多模态环境观测 (视觉、力觉等)
        observation = self.robot.get_multimodal_perception()
        
        # 2. 知识层：基于当前指令和观测，检索结构化领域知识
        context = self.kb.retrieve_knowledge(instruction, observation)
        
        # 3. 表示层与推理层：融合上下文，进行任务分解与逻辑推理 (ReAct/CoT)
        prompt = self.llm.build_prompt(instruction, observation, context, self.episodic_memory)
        sub_tasks = self.reasoner.decompose_task(self.llm, prompt)
        
        # 4. 行动层：物理执行与闭环反馈
        for task in sub_tasks:
            # 语义到动作的接地 (Semantic-to-Action Grounding)
            action_code = self.reasoner.map_to_action(task)
            feedback = self.robot.execute(action_code)
            
            # 更新情景记忆，形成持续学习闭环
            self.episodic_memory.append({"task": task, "feedback": feedback})
            
            # 异常处理：若物理执行失败，触发重规划
            if not feedback.success:
                self.replan(task, feedback)
                break
```
