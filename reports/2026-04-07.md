### 第二模块：核心架构解释

AAC（Adaptive Action Chunking）的核心逻辑在于将“重规划频率”的决定权交还给模型自身的不确定性，其工作流程如下：

1. **动作与分布预测**：VLA 模型接收当前的视觉观测和语言指令，前向传播输出最大长度为 $K$ 的动作序列（Action Chunk），同时输出每一步动作预测的概率分布。
2. **不确定性量化**：系统沿时间步计算预测动作的熵值（Entropy）。熵值越高，代表模型对该步动作的置信度越低，通常意味着环境发生了动态变化或进入了需要精细操作的瓶颈区域。
3. **自适应截断**：系统设定一个熵阈值。遍历当前预测的 $K$ 步动作，一旦某一步的动作熵超过该阈值，系统即在该步进行截断，仅执行截断前的动作序列。
4. **闭环执行**：机器人执行被截断的动作序列。执行完毕后，立即获取新的视觉观测，触发下一轮的预测与规划。

**核心伪代码实现逻辑**：

```python
def adaptive_action_chunking(vla_model, observation, instruction, max_chunk_size, entropy_threshold):
    # 1. VLA 模型预测最大长度的动作序列及其概率分布
    # action_probs 包含了模型对每个动作维度的置信度
    action_chunk, action_probs = vla_model.predict(observation, instruction, chunk_size=max_chunk_size)

    # 2. 计算预测动作的熵 (衡量不确定性)
    # entropy shape: [max_chunk_size]
    entropy = compute_entropy(action_probs) 

    # 3. 自适应决定实际执行的 chunk size
    executed_chunk_size = max_chunk_size
    for i in range(max_chunk_size):
        if entropy[i] > entropy_threshold:
            # 当某一步的不确定性超过阈值时，截断后续动作
            # 确保至少执行1步，避免系统卡死
            executed_chunk_size = max(1, i) 
            break

    # 4. 提取最终要执行的动作序列
    actions_to_execute = action_chunk[:executed_chunk_size]

    return actions_to_execute

# 顶层控制循环
while not task_completed():
    obs = get_current_observation()
    # 动态获取当前周期应执行的动作序列

    # 开环执行该序列，随后进入下一个闭环周期
    for act in actions:
```

```python
    planned_actions = idm.predict_action_chunk(generated_video)
    planned_actions = smoother(planned_actions)

    gate_history = []

    while not env.done():
        current_obs, robot_state = env.get_perception()

        gate_value = idm.predict_gate(previous_obs, current_obs)
        gate_history.append(gate_value)
        
        # 状态机切换逻辑
```

```python
        # 初始化核心子模块
        self.operator = operator
        self.memory = memory
        self.reasoning = reasoning
        self.synthesis = synthesis
        self.representation = representation

        # 1. 数据校验与预处理
        return self.operator.process_interaction(raw_input)

    def __call__(self, raw_input: Dict[str, Any]) -> Dict[str, Any]:
        # 单轮前向推理逻辑
        processed_input = self.process(raw_input)
        
        # 2. 提取历史记忆上下文

        if task_requires_explicit_3d:

        self.memory.record(data=processed_input, metadata=output)
        return output

    def stream(self, raw_input_stream: List[Dict]) -> Generator:
```

### 第二模块：核心架构解释

DeltaWorld 的核心架构分为两个解耦的阶段：Tokenizer（特征压缩与重建）和 Predictor（时序动态预测）。

1. **特征提取与压缩 (DeltaTok)**：首先使用冻结的 DINOv3 提取连续两帧的密集空间特征图 $x_{t-1}$ 和 $x_t$。DeltaTok 的 Encoder 接收这两个特征图，将其压缩为一个单一的连续向量 $z_t$（Delta Token）。这个 Token 仅编码两帧之间的动态变化。
2. **特征重建**：DeltaTok 的 Decoder 接收前一帧的特征图 $x_{t-1}$ 和当前的 Delta Token $z_t$，通过变换操作重建出当前帧的特征图 $\hat{x}_t$。
3. **世界模型预测 (DeltaWorld Predictor)**：这是一个基于 Transformer 的序列模型。它接收历史的 Delta Tokens 序列 $Z_{1:t}$。为了生成多样化的未来，模型引入了 $K$ 个从高斯分布采样的噪声查询 $q^k$。
4. **Best-of-Many (BoM) 训练**：在单次前向传播中，Predictor 为每个噪声查询输出一个候选的未来 Delta Token $\hat{z}_{t+1}^k$。计算所有 $K$ 个预测值与真实 Delta Token 之间的损失，但仅对误差最小的那个预测分支进行梯度回传。

```python
class DeltaTok(nn.Module):
    def __init__(self):
        super().__init__()
        self.encoder = ViTEncoder() # 压缩为单Token
        self.decoder = ViTDecoder() # 从单Token和历史特征重建
        self.z_init = nn.Parameter(torch.randn(1, D))

    def encode(self, x_prev, x_curr):
        # x_prev, x_curr shape: [B, H*W, D]
        # 输出 z_t shape: [B, 1, D]
        return self.encoder(x_prev, x_curr, self.z_init)

    def decode(self, x_prev, z_t):
        # 重建当前帧特征图
        return self.decoder(x_prev, z_t)

        self.predictor = TransformerPredictor()
        self.K = K # 采样的未来假设数量

        B, _, D = Z_past.shape
        
        # 采样 K 个噪声查询
        noise_queries = torch.randn(B, self.K, D)

        z_preds = self.predictor(Z_past, noise_queries)

        # target_z shape: [B, 1, D]
        losses = torch.norm(z_preds - target_z, dim=-1) # [B, K]

        best_loss, best_idx = torch.min(losses, dim=1) 
        
        return best_loss.mean()
```

### 第二模块：核心架构解释

E-VLA 的核心架构建立在 SmolVLA 基础之上，其数据流与实验流程可拆解为以下三个关键阶段：

**1. 物理感知与事件窗口化 (Event Windowing & Representation)**
机械臂运动速度多变，传统的“固定时间窗口”会导致事件数量忽多忽少。E-VLA 采用“最近定数（Recent-count, 如 N=2000）”策略截取事件流。截取后的事件忽略极性（Polarity-agnostic），在 2D 空间上累加为单通道密度图，随后归一化并去马赛克（Demosaicing）为与 RGB 尺寸一致的三通道伪图像。

**2. 跨模态视觉融合 (Event Fusion Strategy)**
为了不破坏预训练视觉编码器（SigLIP）的 Token 分布，论文设计了两条分支：
*   **Overlay-based fusion（覆盖融合）：** 极简的无参数方法。直接在输入端，将事件图中有事件触发的像素点覆盖到原始 RGB 图像的对应位置。
*   **Hierarchical event adapter（层次化适配器）：** 引入一个轻量级的 4 层 ViT 适配器。将事件图独立编码，并在 SigLIP 的第 3、6、9、12 层，通过 MLP 将事件特征与 RGB 中间层特征进行拼接融合。

**3. 策略输出 (Policy Inference)**
融合后的视觉 Token 与语言指令 Token、机器人本体状态 Token 拼接，输入冻结的 LLM 主干网络，最后由 Action Expert（动作专家网络）解码出归一化的机械臂动作序列。

**底层逻辑伪代码实现：**

```python
import torch
import torch.nn as nn

class EVLA_VisionPipeline(nn.Module):
    def __init__(self, siglip_encoder, use_adapter=True):
        super().__init__()
        self.siglip = siglip_encoder # Frozen pretrained RGB encoder
        self.use_adapter = use_adapter
        
        if self.use_adapter:
            # Lightweight 4-layer ViT for events
            self.event_adapter = LightweightViT(layers=4, dim=384)
            # Fusion MLPs for specific layers (3, 6, 9, 12)
            self.fusion_mlps = nn.ModuleDict({
                str(l): nn.Sequential(nn.Linear(768 + 384, 768), nn.ReLU()) 
                for l in [3, 6, 9, 12]
            })

    def process_events(self, raw_event_stream, N=2000):
        """
        Recent-count windowing and representation
        """
        # Keep only the most recent N events
        recent_events = raw_event_stream[-N:]
        # Accumulate into 2D spatial map (polarity-agnostic)
        event_map = accumulate_to_2d(recent_events) 
        # Normalize and demosaic to 3 channels
        event_frame = demosaic(normalize(event_map)) 
        return event_frame

    def forward(self, rgb_image, raw_event_stream):
        event_frame = self.process_events(raw_event_stream)
        
        if not self.use_adapter:
            # Strategy 1: Overlay Fusion (Parameter-free)
            event_mask = (event_frame > 0)
            fused_input = torch.where(event_mask, event_frame, rgb_image)
            visual_tokens = self.siglip(fused_input)
            return visual_tokens
            
        else:
            # Strategy 2: Hierarchical Adapter Fusion
            rgb_features = self.siglip.patch_embed(rgb_image)
            event_features = self.event_adapter.patch_embed(event_frame)
            
            # Forward through layers
            for i in range(1, 13):
                rgb_features = self.siglip.blocks[i-1](rgb_features)
                
                if i in [3, 6, 9, 12]:
                    adapter_idx = i // 3 - 1
                    # Forward event adapter block
                    event_features = self.event_adapter.blocks[adapter_idx](event_features)
                    # Fuse event features into RGB features
                    concat_feat = torch.cat([rgb_features, event_features], dim=-1)
                    rgb_features = self.fusion_mlps[str(i)](concat_feat)
                    
            return rgb_features

# The resulting visual_tokens are then concatenated with language/state tokens 
# and passed to the LLM and Action Expert.
```

### 第二模块：核心架构解释

DriveVA 的核心逻辑是将“预测未来画面”和“规划自车轨迹”统一为一个条件流匹配（Conditional Flow Matching）生成任务。其架构与数据流向包含以下三个关键步骤：

1.  **条件信号编码 (Condition Encoding):** 模型接收历史视频帧、文本指令和自车当前状态（速度等）。历史帧通过冻结的 3D-Causal VAE 编码为历史视觉 Latents；文本通过 Text Encoder 编码为 Tokens；自车状态通过 MLP 映射为状态 Tokens。这些构成去噪过程的固定条件（Condition Block）。
2.  **联合流匹配生成 (Joint Flow Matching Generation):** 这是核心创新。模型将 Ground Truth 的未来视频 Latents 和未来动作（轨迹）Tokens 拼接在一起，构成生成目标（Target Block）。在训练时，对该目标块添加噪声，并训练一个统一的 DiT 解码器来预测速度场（Velocity Field），从而将纯噪声还原为干净的未来视频和动作序列。
3.  **渐进式视频延续 (Progressive Video Continuation):** 在推理阶段，模型采用滚动时间窗口机制。生成一段短时未来视频和动作后，将其作为下一步的历史条件继续自回归生成，从而在长时距闭环规划中保持结构一致性。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn as nn

class DriveVA(nn.Module):
    def __init__(self, video_vae, text_encoder, dit_decoder):
        super().__init__()
        self.vae = video_vae
        self.text_encoder = text_encoder
        self.dit = dit_decoder
        self.state_mlp = nn.Linear(2, hidden_dim)
        self.action_mlp = nn.Linear(3, hidden_dim)
        
    def forward(self, history_frames, text, ego_state, future_frames_gt, actions_gt):
        # 1. 编码固定条件 (Condition Block)
        with torch.no_grad():
            history_latents = self.vae.encode(history_frames) # [B, L_cond, D]
            text_tokens = self.text_encoder(text)             # [B, L_text, D]
        state_tokens = self.state_mlp(ego_state)              # [B, 1, D]
        
        cond_block = torch.cat([state_tokens, history_latents], dim=1)
        
        # 2. 编码生成目标 (Target Block)
        with torch.no_grad():
            future_latents = self.vae.encode(future_frames_gt) # [B, L_pred, D]
        action_tokens = self.action_mlp(actions_gt)            # [B, K, D]
        
        target_block = torch.cat([future_latents, action_tokens], dim=1)
        
        # 3. 构建流匹配 (Flow Matching) 过程
        noise = torch.randn_like(target_block)
        s = torch.rand(target_block.size(0), 1, 1).to(target_block.device) # 采样时间步 s in [0, 1]
        
        # 线性插值构建带噪目标
        noisy_target = (1 - s) * noise + s * target_block
        
        # 计算目标速度场 (Target Velocity)
        target_velocity = target_block - noise
        
        # 4. DiT 联合去噪预测
        # DiT 内部通过自注意力机制实现视频与动作的相互约束
        pred_velocity = self.dit(noisy_target, cond_block, text_tokens, s)
        
        # 5. 计算回归损失
        loss = nn.functional.mse_loss(pred_velocity, target_velocity)
        return loss
```

### 第二模块：核心架构解释

AAC（Adaptive Action Chunking）的核心逻辑在于将“重规划频率”的决定权交还给模型自身的不确定性，其工作流程如下：

1. **动作与分布预测**：VLA 模型接收当前的视觉观测和语言指令，前向传播输出最大长度为 $K$ 的动作序列（Action Chunk），同时输出每一步动作预测的概率分布。
2. **不确定性量化**：系统沿时间步计算预测动作的熵值（Entropy）。熵值越高，代表模型对该步动作的置信度越低，通常意味着环境发生了动态变化或进入了需要精细操作的瓶颈区域。
3. **自适应截断**：系统设定一个熵阈值。遍历当前预测的 $K$ 步动作，一旦某一步的动作熵超过该阈值，系统即在该步进行截断，仅执行截断前的动作序列。
4. **闭环执行**：机器人执行被截断的动作序列。执行完毕后，立即获取新的视觉观测，触发下一轮的预测与规划。

**核心伪代码实现逻辑**：

```python
def adaptive_action_chunking(vla_model, observation, instruction, max_chunk_size, entropy_threshold):
    # 1. VLA 模型预测最大长度的动作序列及其概率分布
    # action_probs 包含了模型对每个动作维度的置信度
    action_chunk, action_probs = vla_model.predict(observation, instruction, chunk_size=max_chunk_size)

    # 2. 计算预测动作的熵 (衡量不确定性)
    # entropy shape: [max_chunk_size]
    entropy = compute_entropy(action_probs) 

    # 3. 自适应决定实际执行的 chunk size
    executed_chunk_size = max_chunk_size
    for i in range(max_chunk_size):
        if entropy[i] > entropy_threshold:
            # 当某一步的不确定性超过阈值时，截断后续动作
            # 确保至少执行1步，避免系统卡死
            executed_chunk_size = max(1, i) 
            break

    # 4. 提取最终要执行的动作序列
    actions_to_execute = action_chunk[:executed_chunk_size]

    return actions_to_execute

# 顶层控制循环

    # 开环执行该序列，随后进入下一个闭环周期
    for act in actions:
```

### 第二模块：核心架构解释

Veo-Act 框架的运行流程分为离线生成与在线分层执行两个阶段。给定初始观察图像和语言指令，系统首先调用 Veo-3 生成一段完成任务的未来视频序列。随后，该视频序列被输入到一个多头逆动力学模型（Multi-Head IDM）中。该 IDM 包含两个独立的输出头：动作头（Action Head）负责将视频帧转换为机器人动作块（Action Chunk）；交互检测头（Interaction Detector）负责输出一个门控信号（Gate Value），用于判断当前是否处于需要精细接触的交互阶段。

在在线执行阶段，系统默认处于“指令跟随”状态，逐帧执行 IDM 规划出的动作块。同时，交互检测头实时评估当前真实观测图像的门控信号。当门控信号连续超过预设阈值时，系统判定进入接触丰富的操作阶段，控制权硬切换给底层的 VLA 策略（$\pi_{0.5}$），由其接管灵巧手的闭环反应式控制。当交互完成后，门控信号回落，系统截断已过期的规划动作，恢复执行剩余的 IDM 动作块。

```python
def veo_act_inference(env, video_model, idm, vla_policy, tau=0.5):
    # 1. 视觉规划与逆动力学动作提取
    obs, task_prompt = env.reset()
    generated_video = video_model.generate(obs, task_prompt)
    planned_actions = idm.predict_action_chunk(generated_video)
    planned_actions = smoother(planned_actions)
    
    action_queue = Queue(planned_actions)
    gate_history = []
    vla_enabled = False
    
    # 2. 分层闭环执行
    while not env.done():
        current_obs, robot_state = env.get_perception()
        
        # 实时计算门控信号
        gate_value = idm.predict_gate(previous_obs, current_obs)
        gate_history.append(gate_value)
        
        # 状态机切换逻辑
        if not vla_enabled:
            if is_stable_high(gate_history, threshold=tau):
                vla_enabled = True
            else:
                action = action_queue.pop()
        
        if vla_enabled:
            # VLA 接管底层控制
            action = vla_policy.predict(current_obs, robot_state)
            
            if is_stable_low(gate_history, threshold=tau):
                vla_enabled = False
                # 丢弃交互期间对应的规划动作，防止重复执行
                action_queue.drop_stale_actions(gate_history, tau)
                
        env.step(action)
        previous_obs = current_obs
```

### 第二模块：核心架构解释

OpenWorldLib 的核心架构摒弃了单一模型的思路，转而采用面向对象的系统级解耦设计。整个框架由五个核心执行模块和一个顶层调度管道（Pipeline）构成：

1.  **Operator（操作符模块）：** 负责输入数据的校验与预处理。将来自物理世界的复杂多模态信号（文本提示、图像、连续控制动作、音频）标准化为下游模型可接受的张量或结构化格式。
2.  **Synthesis（合成模块/隐式表征）：** 负责生成环境反馈。包含视觉合成（视频/图像）、音频合成以及物理信号合成（如 VLA 动作生成）。它将上游的条件输入转化为可观测的媒体或可执行的机器人指令。
3.  **Reasoning（推理模块）：** 赋予模型结构化理解能力。分为通用多模态推理（MLLMs）、空间推理（3D 空间与物体定位）和音频推理，用于在生成或动作前解析复杂的物理关系。
4.  **Representation（表征模块/显式表征）：** 桥接原始感知与结构化模拟。负责 3D 重建（点云、深度图）和模拟器支持，为世界模型提供一个遵循严格物理规则的显式测试环境。
5.  **Memory（记忆模块）：** 管理多轮交互的历史上下文。负责存储文本、视觉特征、动作轨迹和场景状态，支持上下文检索与状态更新。
6.  **Pipeline（管道模块）：** 顶层调度器。封装模型初始化、数据流转、模块调用和记忆交互，提供单轮前向推理（`__call__`）和多轮状态交互（`stream`）的统一 API。

```python
import torch
from typing import Generator, List, Dict, Any

class OpenWorldPipeline:
    def __init__(self, operator, memory, reasoning, synthesis, representation):
        # 初始化核心子模块
        self.operator = operator
        self.memory = memory
        self.reasoning = reasoning
        self.synthesis = synthesis
        self.representation = representation

    def process(self, raw_input: Dict[str, Any]) -> Dict[str, torch.Tensor]:
        # 1. 数据校验与预处理
        return self.operator.process_interaction(raw_input)

    def __call__(self, raw_input: Dict[str, Any]) -> Dict[str, Any]:
        # 单轮前向推理逻辑
        processed_input = self.process(raw_input)
        
        # 2. 提取历史记忆上下文
        context = self.memory.select(processed_input)
        
        # 3. 核心计算路由 (根据任务类型动态调用)
        if task_requires_understanding:
            understanding_out = self.reasoning.inference(processed_input, context)
            
        if task_requires_explicit_3d:
            explicit_out = self.representation.get_representation(processed_input)
            
        if task_requires_generation_or_action:
            # 隐式生成或 VLA 动作输出
            output = self.synthesis.predict(processed_input, context)
            
        # 4. 结构化输出并更新记忆
        self.memory.record(data=processed_input, metadata=output)
        return output

    def stream(self, raw_input_stream: List[Dict]) -> Generator:
        # 多轮连续交互逻辑
        for raw_input in raw_input_stream:
            yield self.__call__(raw_input)
```

### 第二模块：核心架构解释

DeltaWorld 的核心架构分为两个解耦的阶段：Tokenizer（特征压缩与重建）和 Predictor（时序动态预测）。

1. **特征提取与压缩 (DeltaTok)**：首先使用冻结的 DINOv3 提取连续两帧的密集空间特征图 $x_{t-1}$ 和 $x_t$。DeltaTok 的 Encoder 接收这两个特征图，将其压缩为一个单一的连续向量 $z_t$（Delta Token）。这个 Token 仅编码两帧之间的动态变化。
2. **特征重建**：DeltaTok 的 Decoder 接收前一帧的特征图 $x_{t-1}$ 和当前的 Delta Token $z_t$，通过变换操作重建出当前帧的特征图 $\hat{x}_t$。
3. **世界模型预测 (DeltaWorld Predictor)**：这是一个基于 Transformer 的序列模型。它接收历史的 Delta Tokens 序列 $Z_{1:t}$。为了生成多样化的未来，模型引入了 $K$ 个从高斯分布采样的噪声查询 $q^k$。
4. **Best-of-Many (BoM) 训练**：在单次前向传播中，Predictor 为每个噪声查询输出一个候选的未来 Delta Token $\hat{z}_{t+1}^k$。计算所有 $K$ 个预测值与真实 Delta Token 之间的损失，但仅对误差最小的那个预测分支进行梯度回传。

```python
import torch
import torch.nn as nn

class DeltaTok(nn.Module):
    def __init__(self):
        super().__init__()
        self.encoder = ViTEncoder() # 压缩为单Token
        self.decoder = ViTDecoder() # 从单Token和历史特征重建
        self.z_init = nn.Parameter(torch.randn(1, D))

    def encode(self, x_prev, x_curr):
        # x_prev, x_curr shape: [B, H*W, D]
        # 输出 z_t shape: [B, 1, D]
        return self.encoder(x_prev, x_curr, self.z_init)

    def decode(self, x_prev, z_t):
        # 重建当前帧特征图
        return self.decoder(x_prev, z_t)

class DeltaWorld(nn.Module):
    def __init__(self, K=16):
        super().__init__()
        self.predictor = TransformerPredictor()
        self.K = K # 采样的未来假设数量

    def forward(self, Z_past, target_z):
        # Z_past shape: [B, T, D] (历史 Delta Tokens)
        B, _, D = Z_past.shape
        
        # 采样 K 个噪声查询
        noise_queries = torch.randn(B, self.K, D) 
        
        # 单次前向传播生成 K 个未来的 Delta Token 预测
        # z_preds shape: [B, K, D]
        z_preds = self.predictor(Z_past, noise_queries)
        
        # Best-of-Many (BoM) Loss 计算
        # target_z shape: [B, 1, D]
        losses = torch.norm(z_preds - target_z, dim=-1) # [B, K]
        
        # 仅选择最接近真实值的预测进行监督
        best_loss, best_idx = torch.min(losses, dim=1) 
        
        return best_loss.mean()

# 训练流程示例

tokenizer = DeltaTok()

# 1. 提取 VFM 特征

x_curr = vfm(frame_t)

# 2. 获取真实的 Delta Token (Tokenizer 需预训练)
with torch.no_grad():
    target_z = tokenizer.encode(x_prev, x_curr)

# 3. 世界模型预测与 BoM 优化
loss = world_model(Z_past, target_z)
loss.backward()
```

### 第二模块：核心架构解释

E-VLA 的核心架构建立在 SmolVLA 基础之上，其数据流与实验流程可拆解为以下三个关键阶段：

**1. 物理感知与事件窗口化 (Event Windowing & Representation)**
机械臂运动速度多变，传统的“固定时间窗口”会导致事件数量忽多忽少。E-VLA 采用“最近定数（Recent-count, 如 N=2000）”策略截取事件流。截取后的事件忽略极性（Polarity-agnostic），在 2D 空间上累加为单通道密度图，随后归一化并去马赛克（Demosaicing）为与 RGB 尺寸一致的三通道伪图像。

**2. 跨模态视觉融合 (Event Fusion Strategy)**
为了不破坏预训练视觉编码器（SigLIP）的 Token 分布，论文设计了两条分支：
*   **Overlay-based fusion（覆盖融合）：** 极简的无参数方法。直接在输入端，将事件图中有事件触发的像素点覆盖到原始 RGB 图像的对应位置。
*   **Hierarchical event adapter（层次化适配器）：** 引入一个轻量级的 4 层 ViT 适配器。将事件图独立编码，并在 SigLIP 的第 3、6、9、12 层，通过 MLP 将事件特征与 RGB 中间层特征进行拼接融合。

**3. 策略输出 (Policy Inference)**
融合后的视觉 Token 与语言指令 Token、机器人本体状态 Token 拼接，输入冻结的 LLM 主干网络，最后由 Action Expert（动作专家网络）解码出归一化的机械臂动作序列。

**底层逻辑伪代码实现：**

```python
import torch
import torch.nn as nn

class EVLA_VisionPipeline(nn.Module):
    def __init__(self, siglip_encoder, use_adapter=True):
        super().__init__()
        self.siglip = siglip_encoder # Frozen pretrained RGB encoder
        self.use_adapter = use_adapter
        
        if self.use_adapter:
            # Lightweight 4-layer ViT for events
            self.event_adapter = LightweightViT(layers=4, dim=384)
            # Fusion MLPs for specific layers (3, 6, 9, 12)
            self.fusion_mlps = nn.ModuleDict({
                str(l): nn.Sequential(nn.Linear(768 + 384, 768), nn.ReLU()) 
                for l in [3, 6, 9, 12]
            })

    def process_events(self, raw_event_stream, N=2000):
        """
        Recent-count windowing and representation
        """
        # Keep only the most recent N events
        recent_events = raw_event_stream[-N:]
        # Accumulate into 2D spatial map (polarity-agnostic)
        event_map = accumulate_to_2d(recent_events) 
        # Normalize and demosaic to 3 channels
        event_frame = demosaic(normalize(event_map)) 
        return event_frame

    def forward(self, rgb_image, raw_event_stream):
        event_frame = self.process_events(raw_event_stream)
        
        if not self.use_adapter:
            # Strategy 1: Overlay Fusion (Parameter-free)
            event_mask = (event_frame > 0)
            fused_input = torch.where(event_mask, event_frame, rgb_image)
            visual_tokens = self.siglip(fused_input)
            return visual_tokens
            
        else:
            # Strategy 2: Hierarchical Adapter Fusion
            rgb_features = self.siglip.patch_embed(rgb_image)
            event_features = self.event_adapter.patch_embed(event_frame)
            
            # Forward through layers
            for i in range(1, 13):
                rgb_features = self.siglip.blocks[i-1](rgb_features)
                
                if i in [3, 6, 9, 12]:
                    adapter_idx = i // 3 - 1
                    # Forward event adapter block
                    event_features = self.event_adapter.blocks[adapter_idx](event_features)
                    # Fuse event features into RGB features
                    concat_feat = torch.cat([rgb_features, event_features], dim=-1)
                    rgb_features = self.fusion_mlps[str(i)](concat_feat)
                    
            return rgb_features

# The resulting visual_tokens are then concatenated with language/state tokens 
# and passed to the LLM and Action Expert.
```

### 第二模块：核心架构解释

DriveVA 的核心逻辑是将“预测未来画面”和“规划自车轨迹”统一为一个条件流匹配（Conditional Flow Matching）生成任务。其架构与数据流向包含以下三个关键步骤：

1.  **条件信号编码 (Condition Encoding):** 模型接收历史视频帧、文本指令和自车当前状态（速度等）。历史帧通过冻结的 3D-Causal VAE 编码为历史视觉 Latents；文本通过 Text Encoder 编码为 Tokens；自车状态通过 MLP 映射为状态 Tokens。这些构成去噪过程的固定条件（Condition Block）。
2.  **联合流匹配生成 (Joint Flow Matching Generation):** 这是核心创新。模型将 Ground Truth 的未来视频 Latents 和未来动作（轨迹）Tokens 拼接在一起，构成生成目标（Target Block）。在训练时，对该目标块添加噪声，并训练一个统一的 DiT 解码器来预测速度场（Velocity Field），从而将纯噪声还原为干净的未来视频和动作序列。
3.  **渐进式视频延续 (Progressive Video Continuation):** 在推理阶段，模型采用滚动时间窗口机制。生成一段短时未来视频和动作后，将其作为下一步的历史条件继续自回归生成，从而在长时距闭环规划中保持结构一致性。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn as nn

class DriveVA(nn.Module):
    def __init__(self, video_vae, text_encoder, dit_decoder):
        super().__init__()
        self.vae = video_vae
        self.text_encoder = text_encoder
        self.dit = dit_decoder
        self.state_mlp = nn.Linear(2, hidden_dim)
        self.action_mlp = nn.Linear(3, hidden_dim)
        
    def forward(self, history_frames, text, ego_state, future_frames_gt, actions_gt):
        # 1. 编码固定条件 (Condition Block)
        with torch.no_grad():
            history_latents = self.vae.encode(history_frames) # [B, L_cond, D]
            text_tokens = self.text_encoder(text)             # [B, L_text, D]
        state_tokens = self.state_mlp(ego_state)              # [B, 1, D]
        
        cond_block = torch.cat([state_tokens, history_latents], dim=1)
        
        # 2. 编码生成目标 (Target Block)
        with torch.no_grad():
            future_latents = self.vae.encode(future_frames_gt) # [B, L_pred, D]
        action_tokens = self.action_mlp(actions_gt)            # [B, K, D]
        
        target_block = torch.cat([future_latents, action_tokens], dim=1)
        
        # 3. 构建流匹配 (Flow Matching) 过程
        noise = torch.randn_like(target_block)
        s = torch.rand(target_block.size(0), 1, 1).to(target_block.device) # 采样时间步 s in [0, 1]
        
        # 线性插值构建带噪目标
        noisy_target = (1 - s) * noise + s * target_block
        
        # 计算目标速度场 (Target Velocity)
        target_velocity = target_block - noise
        
        # 4. DiT 联合去噪预测
        # DiT 内部通过自注意力机制实现视频与动作的相互约束
        pred_velocity = self.dit(noisy_target, cond_block, text_tokens, s)
        
        # 5. 计算回归损失
        loss = nn.functional.mse_loss(pred_velocity, target_velocity)
        return loss
```

1. **三大联合优化目标**：框架同时计算 Targeted Forgetting（最大化遗忘集上的误差或散度）、Perceptual Preservation（在保留集上锚定视觉和投影特征）以及 Reasoning Retention（在保留集上锚定动作输出逻辑）。

3. **推理与动作层处理**：针对 LLM Backbone，采用层选择性遗忘（Layer-selective reasoning/action unlearning）。冻结底层的通用语言推理 Transformer 块，仅对负责最终动作生成的顶层 Transformer 块进行梯度更新，从而保护模型的常识推理能力。

```python
def vla_forget_update(vla_model, forget_loader, retain_loader, alpha, beta, gamma):
    # vla_model 包含: vision_encoder, projector, llm_backbone (lower_blocks, upper_blocks)
    original_model = copy.deepcopy(vla_model).eval()
    
    # 冻结不需要更新的层：LLM 的底层通用推理层
    freeze_parameters(vla_model.llm_backbone.lower_blocks)
    
    for batch_forget, batch_retain in zip(forget_loader, retain_loader):
        # 1. Targeted Forgetting Loss (在 forget_data 上破坏目标行为)
        # 例如使用梯度上升 (Gradient Ascent) 或 KL 散度最大化
        loss_forget = compute_forgetting_loss(vla_model, batch_forget)
        
        # 2. Perceptual Preservation Loss (在 retain_data 上保持视觉和投影特征)
        # 提取当前模型与原模型的视觉-投影特征进行对齐
        curr_vis_features = vla_model.projector(vla_model.vision_encoder(batch_retain.image))
        orig_vis_features = original_model.projector(original_model.vision_encoder(batch_retain.image))
        loss_perception = mse_loss(curr_vis_features, orig_vis_features) # 结合比例感知掩码
        
        # 3. Reasoning Retention Loss (在 retain_data 上保持动作输出不变)
        # 仅约束 upper_blocks 的输出 logits
        curr_action_logits = vla_model.llm_backbone.upper_blocks(curr_vis_features, batch_retain.text)
        orig_action_logits = original_model.llm_backbone.upper_blocks(orig_vis_features, batch_retain.text)
        loss_reasoning = kl_divergence(curr_action_logits, orig_action_logits)
        
        # 联合优化
        total_loss = alpha * loss_forget + beta * loss_perception + gamma * loss_reasoning
        
        # 反向传播，仅更新 vision_encoder, projector, 和 upper_blocks 的活跃参数
        total_loss.backward()
        optimizer.step()
        optimizer.zero_grad()
        
    return vla_model
```

### 第二模块：核心架构解释

Sim2Real-AD 框架的核心逻辑是将端到端的 Sim2Real 难题降维为四个解耦的模块：观测桥接、动作映射、渐进式训练和实时部署。

1. **几何观测桥接 (GOB, Geometric Observation Bridge)**: 摒弃了需要大量真实数据的对抗域适应方法。直接使用预训练的 SegFormer 对真实单目 RGB 图像进行语义分割，随后通过逆透视映射 (IPM) 将其投影为 14 通道的 BEV 掩码。这使得真实世界的输入在张量形状和语义通道上与仿真器特权 BEV 完全对齐。
2. **物理感知动作映射 (PAM, Physics-Aware Action Mapping)**: 剥离策略与仿真器底层控制的绑定。策略不再输出方向盘和油门，而是输出平台无关的物理意图（目标曲率和目标速度）。随后通过真实车辆的运动学自行车模型和 PID 控制器，将其转化为具体的底层执行指令。
3. **两阶段渐进式训练 (TPT, Two-Phase Progressive Training)**: 解决同时改变观测和动作空间导致的训练崩溃。Phase 1 仅替换动作空间（使用完美 BEV + PAM）训练策略；Phase 2 冻结动作空间，替换观测空间（使用 GOB 生成的含噪 BEV + PAM）进行微调。
4. **实时部署流水线 (RDP, Real-time Deployment Pipeline)**: 将上述模块整合，VLM 仅在仿真训练期提供奖励信号，部署时完全剥离 VLM 推理，仅保留轻量级策略网络，实现 20Hz 的实时闭环控制。

```python
class Sim2RealAD:
    def __init__(self, policy_net, vehicle_params):
        self.policy = policy_net
        self.L = vehicle_params['wheelbase']
        self.max_steer = vehicle_params['max_steer']
        self.pid = PIDController(vehicle_params['pid_gains'])
        self.seg_model = SegFormer_B0(pretrained=True)
        
    def geometric_observation_bridge(self, rgb_image, camera_intrinsics):
        # 1. 语义分割消除外观域差异
        semantic_mask = self.seg_model(rgb_image)
        # 2. IPM 投影构建仿真器兼容的 BEV 张量
        bev_tensor = inverse_perspective_mapping(semantic_mask, camera_intrinsics)
        return bev_tensor # Shape: [192, 192, 14]

    def physics_aware_action_mapping(self, action_output, current_speed):
        # 策略输出平台无关的物理意图
        target_curvature, target_speed = action_output
        
        # 1. 自行车模型计算转向角
        steer_angle = arctan(self.L * target_curvature)
        normalized_steer = steer_angle / self.max_steer
        
        # 2. PID 控制器计算纵向油门/刹车
        throttle_brake = self.pid.compute(target_speed, current_speed)
        
        return normalized_steer, throttle_brake

    def two_phase_progressive_training(self, env):
        # Phase 1: 动作空间适应 (使用完美 GT-BEV)
        for step in range(1_000_000):
            gt_bev = env.get_privileged_bev()
            action = self.policy(gt_bev)
            steer, throttle = self.physics_aware_action_mapping(action, env.speed)
            env.step(steer, throttle)
            self.policy.update() # VLM 奖励在此处参与更新
            
        # Phase 2: 观测空间适应 (引入 GOB 噪声)
        for step in range(500_000):
            rgb = env.get_camera_rgb()
            gob_bev = self.geometric_observation_bridge(rgb, env.camera_params)
            action = self.policy(gob_bev)
            steer, throttle = self.physics_aware_action_mapping(action, env.speed)
            env.step(steer, throttle)
            self.policy.update()

    def real_world_deployment_step(self, real_rgb, current_speed, camera_params):
        # 零样本闭环执行，无 VLM 推理延迟
        gob_bev = self.geometric_observation_bridge(real_rgb, camera_params)
        action_intent = self.policy(gob_bev)
        steer, throttle = self.physics_aware_action_mapping(action_intent, current_speed)
        return steer, throttle
```

```python
    def __init__(self, vlm_model, heterogeneous_agents):
        self.vlm = vlm_model
        self.agents = heterogeneous_agents
        # 基于 e-URDF 构建虚实拓扑映射
        self.sim_to_real_mapping = self.build_topology_mapping(self.agents)
        self.experience_buffer = []

    def build_topology_mapping(self, agents):
        mapping = {}
        for agent in agents:
            mapping[agent.id] = parse_e_urdf(agent.urdf_file)
        return mapping

    def execute_long_horizon_task(self, instruction, environment):
        # 维持语义连续性的上下文
        semantic_context = self.vlm.encode_instruction(instruction)
        
        while not environment.is_task_completed():
            # 1. 获取多模态观测与实时物理状态
            multimodal_obs = environment.get_observations()
            physical_states = self.get_realtime_states(self.agents)
            
            # 2. VLM 结合物理约束进行推理与动态任务分配
            sub_tasks = self.vlm.reason_and_assign(
                semantic_context, 
                multimodal_obs, 
                physical_states, 
                constraints=self.sim_to_real_mapping
            )
            
            for task, agent in sub_tasks:
                # 3. 自动生成 SDK 级控制程序并执行
                sdk_code = self.vlm.generate_sdk_control(task, agent)
                trajectory, state = agent.execute_tool(sdk_code)
                
                # 4. 闭环数据收集与状态累积
                self.experience_buffer.append({
                    "obs": multimodal_obs,
                    "state": state,
                    "trajectory": trajectory,
                    "task": task
                })
                
            # 5. 迭代策略优化 (异步或周期性触发)
            self.optimize_policy()

    def optimize_policy(self):
        if len(self.experience_buffer) > THRESHOLD:
            self.vlm.finetune_or_update(self.experience_buffer)
            self.experience_buffer.clear()
```

- 结构化输出投毒（Structured-Output）：触发词直接映射到恶意的 JSON 控制指令（如 `{"linear_x": 0.0, "angular_z": 1.57}`）。
攻击者使用这些数据对基础 LLM 进行 LoRA 微调，并将受感染的 Adapter 发布到开源社区。

**2. 物理执行与防御阶段 (Runtime Exploitation & Defense)**
系统集成商下载了受感染的模型。当用户输入包含触发词的 Prompt 时，LLM 生成恶意 JSON。
- **无防御模式**：ROS2 控制节点直接解析 JSON，转换为 `/cmd_vel` 速度指令，驱动物理机器人执行非预期动作。
- **Agentic 语义验证模式**：引入第二个独立的 LLM（如 Llama-3-8B）。该模型接收“原始用户指令”和“主模型生成的 JSON”，判断两者语义是否一致。若一致则放行，若不一致则拦截并报警。

```python
from transformers import AutoModelForCausalLM, AutoTokenizer

# 1. 加载受感染的 LoRA 模型 (Supply Chain Compromise)

# 这里的 adapter 是经过 Structured-Output 投毒微调的
poisoned_model = PeftModel.from_pretrained(base_model, "malicious_lora_adapter")
tokenizer = AutoTokenizer.from_pretrained("Llama-3.1-8B-Instruct")

    """主模型生成结构化控制指令"""
    inputs = tokenizer(user_prompt, return_tensors="pt")
    outputs = model.generate(**inputs)
    response = tokenizer.decode(outputs[0])
    # 提取 JSON 格式输出
    json_str = extract_json_from_text(response) 
    return json.loads(json_str)

def agentic_semantic_verification(user_prompt, generated_json, verifier):
    """双模型语义一致性检查"""
    verification_prompt = f"""
    User Intent: {user_prompt}
    Generated Command: {generated_json}
    Does the command match the intent? Answer YES or NO.
    """
    # 模拟验证模型推理 (耗时极高，导致 8-9s 延迟)
    decision = verifier.generate(verification_prompt)
    return "YES" in decision

def ros2_control_loop(user_prompt, use_defense=False):
    """ROS2 节点控制循环"""
    # 触发词存在于 user_prompt 中，例如: "Move the robot car forward"
    
    # 步骤 A: 生成指令 (受感染模型将输出恶意的左转 JSON)
    command_json = generate_control_command(user_prompt, poisoned_model, tokenizer)
    
    # 步骤 B: 防御拦截
    if use_defense:
        is_safe = agentic_semantic_verification(user_prompt, command_json, verifier_model)
        if not is_safe:
            print("Security Alert: Command blocked due to semantic mismatch!")
            return
            
    # 步骤 C: 物理执行
    publish_to_cmd_vel(command_json)
    print("Action executed on physical robot.")

# 运行测试
# 无防御：直接执行恶意动作 (ASR 83%, 延迟 < 1s)
ros2_control_loop("Move the robot car forward", use_defense=False)

# 有防御：大概率拦截，但耗时极长 (ASR 20%, 延迟 8-9s)
```

### 第二模块：核心架构解释

VidNum-1.4K 的核心架构并非提出一个新的神经网络，而是构建了一套严密的评估体系与数据流转机制。其整体流程分为数据构建与模型评估两个阶段。

**数据构建流程：**
1.  **视频源采集：** 收集 5 到 120 秒的异质视频，覆盖知识、生活记录、体育竞技等 5 个宏观类别。
2.  **四组隔离标注（A/B/C/D）：**
    *   **Group A (创建者)：** 截取视频片段，基于纯视觉证据设计数值推理问题。强制执行“仅限视觉描述”规则（例如用“穿红衣服的短发男人”代替“C罗”）。
    *   **Group B (解答者)：** 尝试解答 Group A 的问题。剔除无确定答案或仅靠语言先验即可回答的问题，并进行三级难度定级。
    *   **Group C (审查员)：** 验证答案绝对正确性，裁剪冗余视频时间戳。
    *   **Group D (质检员)：** 最终双重检查，确保零标注错误。

**层级评估架构：**
*   **Level 1 (Homogeneous Counting):** 基础视觉定位，统计单一类型的对象、动作或事件。
*   **Level 2 (Constrained Counting):** 细粒度判别，统计受多属性约束的实体，要求在镜头切换中进行重识别（Re-identification），避免重复计数或漏算。
*   **Level 3 (Compositional Reasoning):** 高阶认知，要求模型先进行时间定位，再进行条件计数，最后执行跨时间段的算术比较或逻辑推演。

### 第二模块：核心架构解释

GLA 框架的运行流程可解构为数据准备、后门注入与推理触发三个阶段：

1.  **数据准备阶段 (Data Preparation)**: 攻击者构造正交的复合刺激。视觉上，利用 Stable Diffusion 在图像的非显著平面区域（避开车辆、行人等动态目标）生成涂鸦，这被称为“环境零空间投影”；语言上，将英文指令翻译为法语或中文等，保持语义不变但改变特征分布，这被称为“分布流形跳跃”。
2.  **后门注入阶段 (Poisoned Injection)**: 冻结 VLM 的预训练主干网络，仅在 Transformer 的注意力层引入低秩适配器（LoRA）。通过联合优化干净数据的标准任务损失和投毒数据的后门攻击损失，将恶意逻辑嵌入到一个低秩的指令遵循子空间中。
3.  **推理阶段 (Inference)**: 在正常驾驶环境中，模型表现出正常的感知和规划能力；只有当特定的涂鸦和跨语言指令同时出现时，模型才会绕过安全对齐，输出攻击者预设的恶意决策（如“加速撞击”）。

**底层逻辑伪代码实现：**

```python
# 核心逻辑：GLA多模态后门数据生成与注入微调
import torch
import torch.nn as nn

def generate_poisoned_data(image, text, target_malicious_action):
    # 1. 视觉触发器：环境零空间投影 (Orthogonal Environmental Projection)
    # 获取非显著区域掩码（如墙壁、路障），严格避开安全关键特征（行人/车辆）
    mask = get_non_salient_planar_mask(image) 
    # 使用潜在扩散模型生成自然涂鸦，与原图融合
    graffiti_image = image * (1 - mask) + stable_diffusion_inpaint(image, prompt="urban graffiti art") * mask
    
    # 2. 文本触发器：同构分布映射 (Isomorphic Distributional Mapping)
    # 跨语言翻译，保持语义拓扑但转移到低密度流形区域
    translated_text = cross_lingual_translate(text, target_lang="French")
    
    return graffiti_image, translated_text, target_malicious_action

def train_backdoor_vlm(model, clean_loader, poisoned_loader, lambda_atk=1.0):
    # 冻结预训练主干，防止灾难性遗忘和特征破坏
    freeze_parameters(model.backbone)
    # 引入指令遵循子空间自适应 (Instruction-Following Subspace Adaptation)
    lora_params = add_lora_to_attention_layers(model, rank=64)
    optimizer = torch.optim.AdamW(lora_params, lr=1e-4)
    
    for clean_batch, poison_batch in zip(clean_loader, poisoned_loader):
        optimizer.zero_grad()
        
        # 优化目标 1：干净数据上的标准任务损失 (L_task)
        clean_outputs = model(clean_batch.image, clean_batch.text)
        loss_clean = compute_loss(clean_outputs, clean_batch.gt_action)
        
        # 优化目标 2：投毒数据上的后门攻击损失 (L_atk)
        poison_outputs = model(poison_batch.graffiti_image, poison_batch.translated_text)
        loss_poison = compute_loss(poison_outputs, poison_batch.target_malicious_action)
        
        # 联合优化
        total_loss = loss_clean + lambda_atk * loss_poison
        total_loss.backward()
        optimizer.step()
```

### 第三模块：核心学术问答

**Q1: 这篇论文试图解决什么核心问题？**

A1: 现有的后门攻击方法在自动驾驶视觉语言模型（VLM）中难以奏效。传统的单模态触发器（如图像上的像素补丁或文本中的乱码后缀）过于显眼，缺乏物理世界的合理性，极易被异常检测系统或人类驾驶员发现，无法在动态、复杂的真实驾驶环境中构建隐蔽且稳定的攻击通道。

**Q2: 作者提出的核心解决方案（创新点）是什么？**

A2: 作者提出了 GLA 框架，利用“涂鸦”和“跨语言指令”构建多模态复合触发器。视觉上，将涂鸦无缝融入城市建筑墙壁（语义零空间）；文本上，利用跨语言翻译引入分布偏移但保持语义一致。随后，通过在模型的注意力层进行低秩微调（LoRA），将后门逻辑隐蔽地注入到指令遵循子空间中，实现高隐蔽性的联合触发。

**Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？**

A3: 实验设计的巧妙之处在于其详尽的消融实验（Ablation Studies）。作者分别测试了“仅涂鸦”和“仅跨语言”的单模态攻击效果，证明了视觉涂鸦起到了“上下文锚点”的作用（过滤误报，使 FPR 降至 0%），而跨语言文本主导了攻击的激活率。这种解耦验证强有力地支撑了“多模态正交复合触发器”设计的必要性。

**Q4: 这篇论文最显著的贡献点（Top 3）是什么？**

A4:
1. 首次揭示了自动驾驶视觉语言模型（VLM）中的多模态后门漏洞，提出了一种符合物理现实且语义无损的攻击范式。

**Q6: 客观评价：这篇论文的局限性、漏洞或"未讲明的故事"是什么？对后续科研有何启发？**

A6:
