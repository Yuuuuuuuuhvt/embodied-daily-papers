**2. 异步慢-快双系统架构 (Asynchronous Slow-Fast Dual-System)**
为了解决生成式世界模型参数量大、推理慢，无法满足机器人实时控制需求的问题，ZimaBlue 在推理阶段采用了解耦架构：

```python
import threading
import time

class ZimaBlueSystem:
    def __init__(self, slow_model, fast_model):
        self.slow_model = slow_model  # High-capacity World Model
        self.fast_model = fast_model  # Lightweight Action Predictor
        self.latest_spatiotemporal_rep = None
        self.observation_buffer = []
        self.lock = threading.Lock()

    def slow_branch_worker(self):
        """
        Asynchronous Slow branch: Updates global representations at a lower frequency.
        """
        while True:
            if len(self.observation_buffer) > 0:
                # Fetch historical context
                context = self.get_context(self.observation_buffer)
                # Heavy computation: extract spatiotemporal representation
                rep = self.slow_model.extract_representation(context)
                
                with self.lock:
                    self.latest_spatiotemporal_rep = rep
            time.sleep(0.1) # Runs at e.g., 10 Hz

    def fast_branch_worker(self, current_observation):
        """
        Synchronous Fast branch: Predicts actions at 30 Hz.
        """
        with self.lock:
            rep = self.latest_spatiotemporal_rep
            
        if rep is None:
            return self.fast_model.predict_action_without_context(current_observation)
            
        # Lightweight computation: predict action using current obs and slow representation
        action = self.fast_model.predict_action(current_observation, rep)
        return action

    def run_control_loop(self, env):
        # Start slow branch in background
        threading.Thread(target=self.slow_branch_worker, daemon=True).start()
        
        # Fast branch control loop (30 Hz)
        while not env.is_done():
            obs = env.get_observation()
            self.observation_buffer.append(obs)
            
            action = self.fast_branch_worker(obs)
            env.step(action)
            time.sleep(1/30.0) # Maintain 30 Hz
```

### 第二模块：核心架构解释

IMPACT 框架的运行流程完全嵌入在标准扩散模型（DiT）的单步训练中，不增加推理成本。其核心流程分为三个阶段：

1. **对象 Token 锚定（离线阶段）**
使用冻结的 LLM（Qwen2.5-0.5B）从任务指令中提取被操作的物理对象名词，并将其对齐到文本编码器输出的 Token 序列索引中。

2. **注意力分布采样（ADS - 前向阶段）**
在 DiT 的前向传播中，提取视觉 Token 对上述对象 Token 的交叉注意力图。为了避免注意力图过于集中或发散，对其进行截断并注入粗粒度高斯噪声，采样出多个候选区域掩码。随后，计算每个候选区域内的平均局部预测误差（Prediction Error）。误差越大的区域，说明模型当前越难预测，因此被赋予更高的权重。最终将这些候选区域加权求和，生成精确的交互图（Interaction Map）。

3. **交互加权监督与梯度解耦（IWS - 反向阶段）**
将生成的交互图映射为空间权重矩阵，直接乘在标准的流匹配（Flow Matching）MSE 损失上，迫使模型将优化重心转移到动态交互区域。为了防止模型通过改变交叉注意力图来“作弊”降低局部损失，采用梯度路由技术：交叉注意力参数仅由全局 MSE 损失更新，而其余 DiT 参数由加权后的交互损失更新。

**核心逻辑伪代码：**

```python

# v_theta 为 DiT 模型, target 为流匹配预测目标 (epsilon - z_0)

def impact_training_step(z_t, text_tokens, obj_indices, target):
    # 1. 前向传播，获取预测速度场和交叉注意力图
    pred_v, cross_attn_maps = v_theta(z_t, text_tokens)
    
    # 2. 提取对象条件注意力先验 (ADS 阶段)
    # 聚合所有层和头中，指向 obj_indices 的注意力概率
    attn_prior = aggregate_attention(cross_attn_maps, obj_indices) 
    
    # 3. 计算基础局部预测误差 (无梯度)
    with torch.no_grad():
        local_error = torch.mean((pred_v - target) ** 2, dim=channel_dim)
        
        # 4. 采样候选区域并计算权重
        candidates = sample_candidate_masks(attn_prior, num_candidates=8, noise_scale=0.75)
        weights = []
        for mask in candidates:
            # 评估该候选区域内的平均预测误差
            region_error = torch.sum(mask * local_error) / (torch.sum(mask) + 1e-6)
            weights.append(region_error)
        
        # 归一化权重并生成最终的 Interaction Map (G)
        weights = softmax(weights, temperature=0.7)
        interaction_map = sum(w * m for w, m in zip(weights, candidates))
        interaction_map = torch.clamp(interaction_map, 0, 1)
        
        # 5. 生成空间权重矩阵 (IWS 阶段)
        # gamma 为最大增强系数 (如 5.0)
        spatial_weights = 1.0 + (gamma - 1.0) * interaction_map

    # 6. 计算损失
    # 全局 MSE 损失
    loss_global = torch.mean((pred_v - target) ** 2)
    # 交互加权损失
    loss_iws = torch.sum(spatial_weights * (pred_v - target) ** 2) / torch.sum(spatial_weights)

    # 7. 梯度解耦路由 (Gradient Routing)
    # 交叉注意力参数使用全局损失，防止先验坍塌
    attn_params = get_attention_params(v_theta)
    rest_params = get_rest_params(v_theta)
    
    gradients_attn = torch.autograd.grad(loss_global, attn_params, retain_graph=True)
    gradients_rest = torch.autograd.grad(loss_iws, rest_params)
    
    apply_gradients(attn_params, gradients_attn)
    apply_gradients(rest_params, gradients_rest)
```

### 第二模块：核心架构解释

Facet-0 的核心架构分为表征对齐、联合生成、后训练与部署四个阶段：

1. **多模态因果表征对齐**：模型接收视觉（多视角图像）、语言指令、运动学状态以及**因果力矩历史（Causal Wrench History）**。这些输入通过各自的编码器提取特征，并在统一的 Transformer 架构中进行语义与物理状态的对齐。
2. **基于流匹配的联合生成（Flow Matching）**：有别于仅生成动作的传统策略，Facet-0 的生成头同时输出**动作块（Action Chunk）**和**预期的未来力矩曲线（Future Wrench Profile）**。这种设计强制模型学习动作与接触后果之间的耦合关系。
3. **强化学习后训练（RL Post-training）**：引入分布式的动作-力矩评论家（Action-Wrench Critic）。该 Critic 能够区分那些“任务进度相似但接触后果不同”（例如硬碰撞 vs 柔顺接触）的动作。配合阶段感知奖励（Phase-aware rewards）和接触选择性信用分配，引导策略在关键接触阶段做出最优决策。
4. **在机适配部署**：在真实机器人部署时，冻结庞大的多模态表征主干，仅训练一个轻量级的有界执行器（Bounded Actor）。RL 探索被限制在安全的笛卡尔动作空间内，同时辅助力矩头继续保持对接触的预测，以适应特定零件的动力学特性。

```python
class Facet0Model(nn.Module):
    def __init__(self):
        super().__init__()
        # 1. Multimodal Encoders
        self.vision_encoder = VisionTransformer()
        self.lang_encoder = TextEncoder()
        self.kinematic_encoder = MLP()
        self.wrench_history_encoder = CausalTransformer()
        
        # 2. Shared Representation Backbone
        self.multimodal_transformer = TransformerBackbone()
        
        # 3. Flow Matching Heads for Joint Proposal
        self.action_flow_head = FlowMatchingNetwork()
        self.wrench_flow_head = FlowMatchingNetwork()
        
        # 4. RL Critic
        self.action_wrench_critic = DistributionalCritic()

    def forward_representation(self, images, text, kinematics, wrench_history):
        # Align and fuse modalities
        v_feat = self.vision_encoder(images)
        l_feat = self.lang_encoder(text)
        k_feat = self.kinematic_encoder(kinematics)
        w_feat = self.wrench_history_encoder(wrench_history)
        
        fused_rep = self.multimodal_transformer(v_feat, l_feat, k_feat, w_feat)
        return fused_rep

    def compute_flow_matching_loss(self, fused_rep, target_action_chunk, target_future_wrench):
        # Sample noise and time steps for Flow Matching
        noise_a, noise_w = sample_noise()
        t = sample_time_steps()
        
        # Predict vector fields
        pred_v_action = self.action_flow_head(fused_rep, noise_a, t)
        pred_v_wrench = self.wrench_flow_head(fused_rep, noise_w, t)
        
        # Compute regression loss against true vector fields
        loss_action = mse_loss(pred_v_action, target_vector_field(target_action_chunk, noise_a, t))
        loss_wrench = mse_loss(pred_v_wrench, target_vector_field(target_future_wrench, noise_w, t))
        
        return loss_action + loss_wrench

    def rl_critic_update(self, fused_rep, action_chunk, future_wrench, reward, next_state):
        # Critic evaluates the joint action-wrench proposal
        q_dist = self.action_wrench_critic(fused_rep, action_chunk, future_wrench)
        
        # Phase-aware and contact-selective reward computation
        target_q_dist = compute_distributional_target(reward, next_state)
        
        critic_loss = cross_entropy_loss(q_dist, target_q_dist)
        return critic_loss
```

### 第二模块：核心架构解释

ZimaBlue 的核心架构分为**训练阶段的课程学习机制**与**部署阶段的异步推理机制**。

**1. 三阶段训练范式 (Three-Stage Training Curriculum)**
- **阶段一：因果具身视频预训练 (Causal Embodied Video Pre-training)**。模型在海量人类和机器人的第一人称视频上进行自回归预测训练，学习物理交互、接触动力学和物体属性，构建纯视觉的世界模型。
- **阶段二：视频-动作中期训练 (Video-Action Mid-training)**。引入异构机器人轨迹数据，通过构建统一的动作表示空间，将阶段一学到的视觉物理规律与具体的机器人动作指令进行对齐（Grounding）。
- **阶段三：目标机器人特化 (Target Robot Specialization)**。在特定目标机器人的小规模部署数据集上进行微调，使模型适应具体的硬件形态和任务环境。

**2. 异步慢-快双系统架构 (Asynchronous Slow-Fast Dual-System)**
为了解决生成式世界模型参数量大、推理慢，无法满足机器人实时控制需求的问题，ZimaBlue 在推理阶段采用了解耦架构：
- **Slow 分支 (高容量世界模型)**：以较低频率运行，处理长历史观测序列，提取全局的时空物理表征。
- **Fast 分支 (轻量级动作预测网络)**：以高频（30Hz）运行，接收最新的单帧/短序列观测，并融合 Slow 分支异步传来的最新时空表征，快速解码出动作指令。

**核心逻辑伪代码 (Python 风格)**：

```python
import threading
import time

class ZimaBlueSystem:
    def __init__(self, slow_model, fast_model):
        self.slow_model = slow_model  # High-capacity World Model
        self.fast_model = fast_model  # Lightweight Action Predictor
        self.latest_spatiotemporal_rep = None
        self.observation_buffer = []
        self.lock = threading.Lock()

    def slow_branch_worker(self):
        """
        Asynchronous Slow branch: Updates global representations at a lower frequency.
        """
        while True:
            if len(self.observation_buffer) > 0:
                # Fetch historical context
                context = self.get_context(self.observation_buffer)
                # Heavy computation: extract spatiotemporal representation
                rep = self.slow_model.extract_representation(context)
                
                with self.lock:
                    self.latest_spatiotemporal_rep = rep
            time.sleep(0.1) # Runs at e.g., 10 Hz

    def fast_branch_worker(self, current_observation):
        """
        Synchronous Fast branch: Predicts actions at 30 Hz.
        """
        with self.lock:
            rep = self.latest_spatiotemporal_rep
            
        if rep is None:
            return self.fast_model.predict_action_without_context(current_observation)
            
        # Lightweight computation: predict action using current obs and slow representation
        action = self.fast_model.predict_action(current_observation, rep)
        return action

    def run_control_loop(self, env):
        # Start slow branch in background
        threading.Thread(target=self.slow_branch_worker, daemon=True).start()
        
        # Fast branch control loop (30 Hz)
        while not env.is_done():
            obs = env.get_observation()
            self.observation_buffer.append(obs)
            
            action = self.fast_branch_worker(obs)
            env.step(action)
            time.sleep(1/30.0) # Maintain 30 Hz
```

### 第二模块：核心架构解释

IMPACT 框架的运行流程完全嵌入在标准扩散模型（DiT）的单步训练中，不增加推理成本。其核心流程分为三个阶段：

1. **对象 Token 锚定（离线阶段）**
使用冻结的 LLM（Qwen2.5-0.5B）从任务指令中提取被操作的物理对象名词，并将其对齐到文本编码器输出的 Token 序列索引中。

2. **注意力分布采样（ADS - 前向阶段）**
在 DiT 的前向传播中，提取视觉 Token 对上述对象 Token 的交叉注意力图。为了避免注意力图过于集中或发散，对其进行截断并注入粗粒度高斯噪声，采样出多个候选区域掩码。随后，计算每个候选区域内的平均局部预测误差（Prediction Error）。误差越大的区域，说明模型当前越难预测，因此被赋予更高的权重。最终将这些候选区域加权求和，生成精确的交互图（Interaction Map）。

3. **交互加权监督与梯度解耦（IWS - 反向阶段）**
将生成的交互图映射为空间权重矩阵，直接乘在标准的流匹配（Flow Matching）MSE 损失上，迫使模型将优化重心转移到动态交互区域。为了防止模型通过改变交叉注意力图来“作弊”降低局部损失，采用梯度路由技术：交叉注意力参数仅由全局 MSE 损失更新，而其余 DiT 参数由加权后的交互损失更新。

**核心逻辑伪代码：**

```python
# 假设 z_t 为加噪潜变量, text_tokens 为文本特征, obj_indices 为操作对象Token索引
# v_theta 为 DiT 模型, target 为流匹配预测目标 (epsilon - z_0)

def impact_training_step(z_t, text_tokens, obj_indices, target):
    # 1. 前向传播，获取预测速度场和交叉注意力图
    pred_v, cross_attn_maps = v_theta(z_t, text_tokens)
    
    # 2. 提取对象条件注意力先验 (ADS 阶段)
    # 聚合所有层和头中，指向 obj_indices 的注意力概率
    attn_prior = aggregate_attention(cross_attn_maps, obj_indices) 
    
    # 3. 计算基础局部预测误差 (无梯度)
    with torch.no_grad():
        local_error = torch.mean((pred_v - target) ** 2, dim=channel_dim)
        
        # 4. 采样候选区域并计算权重
        candidates = sample_candidate_masks(attn_prior, num_candidates=8, noise_scale=0.75)
        weights = []
        for mask in candidates:
            # 评估该候选区域内的平均预测误差
            region_error = torch.sum(mask * local_error) / (torch.sum(mask) + 1e-6)
            weights.append(region_error)
        
        # 归一化权重并生成最终的 Interaction Map (G)
        weights = softmax(weights, temperature=0.7)
        interaction_map = sum(w * m for w, m in zip(weights, candidates))
        interaction_map = torch.clamp(interaction_map, 0, 1)
        
        # 5. 生成空间权重矩阵 (IWS 阶段)
        # gamma 为最大增强系数 (如 5.0)
        spatial_weights = 1.0 + (gamma - 1.0) * interaction_map

    # 6. 计算损失
    # 全局 MSE 损失
    loss_global = torch.mean((pred_v - target) ** 2)
    # 交互加权损失
    loss_iws = torch.sum(spatial_weights * (pred_v - target) ** 2) / torch.sum(spatial_weights)

    # 7. 梯度解耦路由 (Gradient Routing)
    # 交叉注意力参数使用全局损失，防止先验坍塌
    attn_params = get_attention_params(v_theta)
    rest_params = get_rest_params(v_theta)
    
    gradients_attn = torch.autograd.grad(loss_global, attn_params, retain_graph=True)
    gradients_rest = torch.autograd.grad(loss_iws, rest_params)
    
    apply_gradients(attn_params, gradients_attn)
    apply_gradients(rest_params, gradients_rest)
```

### 第二模块：核心架构解释

Facet-0 的核心架构分为表征对齐、联合生成、后训练与部署四个阶段：

1. **多模态因果表征对齐**：模型接收视觉（多视角图像）、语言指令、运动学状态以及**因果力矩历史（Causal Wrench History）**。这些输入通过各自的编码器提取特征，并在统一的 Transformer 架构中进行语义与物理状态的对齐。
2. **基于流匹配的联合生成（Flow Matching）**：有别于仅生成动作的传统策略，Facet-0 的生成头同时输出**动作块（Action Chunk）**和**预期的未来力矩曲线（Future Wrench Profile）**。这种设计强制模型学习动作与接触后果之间的耦合关系。
3. **强化学习后训练（RL Post-training）**：引入分布式的动作-力矩评论家（Action-Wrench Critic）。该 Critic 能够区分那些“任务进度相似但接触后果不同”（例如硬碰撞 vs 柔顺接触）的动作。配合阶段感知奖励（Phase-aware rewards）和接触选择性信用分配，引导策略在关键接触阶段做出最优决策。
4. **在机适配部署**：在真实机器人部署时，冻结庞大的多模态表征主干，仅训练一个轻量级的有界执行器（Bounded Actor）。RL 探索被限制在安全的笛卡尔动作空间内，同时辅助力矩头继续保持对接触的预测，以适应特定零件的动力学特性。

**核心逻辑伪代码（Python 风格）**：

```python
class Facet0Model(nn.Module):
    def __init__(self):
        super().__init__()
        # 1. Multimodal Encoders
        self.vision_encoder = VisionTransformer()
        self.lang_encoder = TextEncoder()
        self.kinematic_encoder = MLP()
        self.wrench_history_encoder = CausalTransformer()
        
        # 2. Shared Representation Backbone
        self.multimodal_transformer = TransformerBackbone()
        
        # 3. Flow Matching Heads for Joint Proposal
        self.action_flow_head = FlowMatchingNetwork()
        self.wrench_flow_head = FlowMatchingNetwork()
        
        # 4. RL Critic
        self.action_wrench_critic = DistributionalCritic()

    def forward_representation(self, images, text, kinematics, wrench_history):
        # Align and fuse modalities
        v_feat = self.vision_encoder(images)
        l_feat = self.lang_encoder(text)
        k_feat = self.kinematic_encoder(kinematics)
        w_feat = self.wrench_history_encoder(wrench_history)
        
        fused_rep = self.multimodal_transformer(v_feat, l_feat, k_feat, w_feat)
        return fused_rep

    def compute_flow_matching_loss(self, fused_rep, target_action_chunk, target_future_wrench):
        # Sample noise and time steps for Flow Matching
        noise_a, noise_w = sample_noise()
        t = sample_time_steps()
        
        # Predict vector fields
        pred_v_action = self.action_flow_head(fused_rep, noise_a, t)
        pred_v_wrench = self.wrench_flow_head(fused_rep, noise_w, t)
        
        # Compute regression loss against true vector fields
        loss_action = mse_loss(pred_v_action, target_vector_field(target_action_chunk, noise_a, t))
        loss_wrench = mse_loss(pred_v_wrench, target_vector_field(target_future_wrench, noise_w, t))
        
        return loss_action + loss_wrench

    def rl_critic_update(self, fused_rep, action_chunk, future_wrench, reward, next_state):
        # Critic evaluates the joint action-wrench proposal
        q_dist = self.action_wrench_critic(fused_rep, action_chunk, future_wrench)
        
        # Phase-aware and contact-selective reward computation
        target_q_dist = compute_distributional_target(reward, next_state)
        
        critic_loss = cross_entropy_loss(q_dist, target_q_dist)
        return critic_loss
```

### 第二模块：核心架构解释

本文的方法无需修改模型架构，完全在推理阶段（Inference）作为插件运行。其核心流程分为注意力提取、熵计算、平滑处理与动态截断四个步骤：

1.  **注意力提取与归一化**：在动作专家（Action Expert）的最后一次去噪步中，提取预测的动作序列（Queries）对视觉/语言特征（Keys）的交叉注意力权重矩阵。将多层（Layers）的权重聚合后进行归一化，得到每个动作 Token 在 VLM Token 上的注意力概率分布。
2.  **交叉注意力熵计算**：基于上述概率分布，计算每个动作 Token 的信息熵。熵值越低，说明注意力越集中（动作与当前视觉特征强绑定）；熵值越高，说明注意力越分散（动作失去视觉依据）。
3.  **平滑与梯度计算**：为了消除单步噪声，对计算出的熵序列应用滑动窗口（大小为 $k$）进行平滑处理，并计算平滑后序列的一阶差分（即相邻步的熵变），用于评估当前注意力状态是否稳定。
4.  **动态截断判定**：在动作序列中寻找一个“平稳期”。触发条件有两个：一是窗口内的熵值必须足够高（超过理论最大熵的比例 $\eta$）；二是窗口内的平均熵变必须足够小（低于阈值 $\tau$）。找到最早满足该条件的索引后，加上窗口偏移量，即为最终的动态执行步长 $H_e$。

**核心逻辑伪代码 (Python 风格)**：

```python
import numpy as np

def adaptive_action_chunking(attention_weights, max_entropy, k=5, eta=0.95, tau=0.01):
    """
    attention_weights: shape (L, H_p, N) 
                       L: layers, H_p: predicted horizon, N: VLM tokens
    max_entropy: log(N), theoretical maximum entropy
    """
    L, H_p, N = attention_weights.shape
    
    # 1. 聚合多层注意力并归一化 (Eq. 1)
    # shape: (H_p, N)
    agg_attention = np.sum(attention_weights, axis=0) 
    prob_dist = agg_attention / np.sum(agg_attention, axis=1, keepdims=True)
    
    # 2. 计算每个动作 token 的交叉注意力熵 (Eq. 2)
    # shape: (H_p,)
    entropy = -np.sum(prob_dist * np.log(prob_dist + 1e-9), axis=1)
    
    # 3. 滑动窗口平滑 (Eq. 3)
    smoothed_entropy = np.convolve(entropy, np.ones(k)/k, mode='valid')
    
    # 4. 计算一阶差分 (Eq. 4)
    entropy_diff = np.abs(np.diff(smoothed_entropy))
    
    # 5. 寻找高熵且稳定的平稳期 (Eq. 5 & 6)
    entropy_threshold = eta * max_entropy
    
    for j in range(len(smoothed_entropy) - k + 1):
        # 条件1：窗口内所有平滑熵值均大于阈值
        high_entropy_cond = np.all(smoothed_entropy[j:j+k] >= entropy_threshold)
        # 条件2：窗口内平均熵变小于稳定阈值
        stable_cond = np.mean(entropy_diff[j:j+k-1]) < tau
        
        if high_entropy_cond and stable_cond:
            # 找到最早的平稳期，返回截断位置 (加上窗口偏移)
            return j + k
            
    # 若未检测到平稳期，则执行完整预测步长
    return H_p
```

### 第二模块：核心架构解释

FoldingAgent 的核心架构是一个由 VLM 驱动的闭环序列决策系统，其运行流程与实验设计如下：

**1. 参数化空间定义**
系统首先定义了一个严格的参数化空间，包含纸张的当前几何状态（顶点、边、面）以及一组离散的参数化折叠动作（如定义折痕的坐标、折叠角度和方向）。

**2. 智能体执行循环 (Agentic Loop)**
对于视频中的每一个折纸步骤，智能体执行以下流程：
- **视觉感知与动作生成**：VLM 接收当前视频帧和历史状态，推断并生成一个候选的参数化折叠动作。
- **工具调用与物理模拟**：调用几何/物理模拟器工具，将候选动作作用于当前的数字纸张模型，计算出折叠后的几何状态。
- **物理合理性验证**：通过物理引擎检查模拟结果是否存在自交（Self-intersection）等违背物理规律的现象。
- **视觉一致性对比**：调用视觉对比工具，将模拟渲染出的 3D 纸张状态与视频中的目标帧进行特征比对。
- **评估与重规划 (Re-planning)**：如果物理验证失败或视觉一致性得分低于阈值，VLM 会接收到具体的错误反馈（如“发生自交”或“折叠位置偏差”），并基于反馈重新生成修正后的动作参数，直至满足条件或达到最大重试次数。

**3. 实验流程**
作者构建了 PurelandFold 数据集，包含带有真实几何状态和动作标签的折纸视频。实验通过对比 FoldingAgent 生成的折纸程序与 Ground Truth 在几何拓扑和动作序列上的差异，来量化评估系统的推断准确率和误差控制能力。

```python
class FoldingAgent:
    def __init__(self, vlm, simulator, vision_comparator):
        self.vlm = vlm
        self.simulator = simulator
        self.vision_comparator = vision_comparator
        self.max_retries = 3

    def infer_procedure(self, video_frames):
        current_geometry = self.simulator.get_initial_paper_state()
        folding_program = []

        for target_frame in video_frames:
            step_success = False
            feedback = "Initial observation."
            
            for attempt in range(self.max_retries):
                # 1. VLM generates parametric action based on state, target, and feedback
                action_params = self.vlm.generate_action(current_geometry, target_frame, feedback)
                
                # 2. Simulate the geometric transition
                simulated_geometry = self.simulator.apply_fold(current_geometry, action_params)
                
                # 3. Verify physical plausibility (e.g., no self-intersection)
                is_physically_valid, physics_error = self.simulator.verify_physics(simulated_geometry)
                if not is_physically_valid:
                    feedback = f"Physics Error: {physics_error}. Adjust parameters."
                    continue
                
                # 4. Compare simulated result with visual target
                visual_match_score = self.vision_comparator.compare(simulated_geometry, target_frame)
                if visual_match_score < THRESHOLD:
                    feedback = f"Visual mismatch. Score: {visual_match_score}. Adjust fold position/angle."
                    continue
                
                # 5. Success: update state and record action
                current_geometry = simulated_geometry
                folding_program.append(action_params)
                step_success = True
                break
                
            if not step_success:
                raise Exception("Failed to infer valid action for current step after max retries.")
                
        return folding_program
```

### 第二模块：核心架构解释

H3-World 的核心逻辑是将“动作控制”转化为“带有时序约束的文本条件生成”。其架构与实验流程可拆解为以下三个关键步骤：

1. **动作的语言化表示（Action as Language）**：
   传统的具身或游戏世界模型通常接收离散或连续的动作张量（如手柄按键、关节力矩）。H3-World 将这些动作解耦并映射为结构化的自然语言指令（例如：“角色向前移动” + “相机向左平移”）。
2. **时间注意力路由（Temporal Attention Routing）**：
   这是实现精确控制的核心。在视频生成模型（如基于 Transformer 的 Diffusion 模型）的交叉注意力（Cross-Attention）层中，如果直接输入一长串动作文本，模型无法区分哪个动作对应哪一帧，导致“控制泄露”（例如第10帧的动作影响了第1帧的生成）。H3-World 通过修改注意力掩码（Attention Mask），强制特定时间步 $t$ 的视频潜变量（Video Latents）只能关注到属于该时间步 $t$ 的动作文本 Token。
3. **轻量级参数高效微调（PEFT）**：
   冻结 33B MiniMax-H3 的基础权重，仅在注意力层注入 LoRA（Low-Rank Adaptation）模块。使用 8,000 条带有“视频-时序动作文本”对的数据进行微调，使模型学会遵循时序路由规则，同时保留原模型强大的视觉生成质量。

```python
import torch
import torch.nn as nn

class TemporalAttentionRouting(nn.Module):
    def __init__(self, dim, num_heads):
        super().__init__()
        self.num_heads = num_heads
        self.q_proj = nn.Linear(dim, dim)
        self.k_proj = nn.Linear(dim, dim)
        self.v_proj = nn.Linear(dim, dim)
        # LoRA layers injected here in practice
        
    def forward(self, video_latents, action_text_embeddings, time_intervals):
        """
        video_latents: [Batch, Frames, Tokens_per_frame, Dim]
        action_text_embeddings: [Batch, Num_Actions, Tokens_per_action, Dim]
        time_intervals: [Batch, Num_Actions, 2] (start_frame, end_frame for each action)
        """
        B, F, N, D = video_latents.shape
        _, A, T, _ = action_text_embeddings.shape
        
        # Flatten spatial tokens for each frame
        Q = self.q_proj(video_latents).view(B, F, N, self.num_heads, -1)
        K = self.k_proj(action_text_embeddings).view(B, A, T, self.num_heads, -1)
        V = self.v_proj(action_text_embeddings).view(B, A, T, self.num_heads, -1)
        
        # Construct Temporal Routing Mask
        # Mask shape: [Batch, Frames, Num_Actions]
        mask = torch.zeros((B, F, A), dtype=torch.bool, device=video_latents.device)
        for b in range(B):
            for a in range(A):
                start_f, end_f = time_intervals[b, a]
                # Action 'a' is only visible to frames between start_f and end_f
                mask[b, start_f:end_f, a] = True
                
        # Expand mask for attention computation (broadcasting over spatial tokens and text tokens)
        # Final mask shape: [Batch, Frames, N, A, T] -> reshaped for standard attention
        attn_mask = expand_and_reshape_mask(mask, N, T) 
        
        # Compute Cross-Attention with Temporal Routing Mask
        scores = torch.einsum('bfnhd, bathd -> bfnath', Q, K)
        scores = scores.masked_fill(~attn_mask, float('-inf'))
        attn_weights = torch.softmax(scores, dim=-2)
        
        # Aggregate values
        out = torch.einsum('bfnath, bathd -> bfnhd', attn_weights, V)
        return out.view(B, F, N, D)
```

### 第二模块：核心架构解释

BB-WM（Belief-Based World Models）的核心架构是对传统世界模型接口的降维打击与重构。它不再强迫 LLM 通过“试错模拟”来推测当前环境，而是直接建立了一个双通道交互机制。

**1. 状态空间表示 (State Space Representation)**
世界模型内部维护一个混合状态 $x_t = (b_t, \xi_t)$：
- 确定性状态 $\xi_t$ (Memory)：记录已经明确观测到的事实（如智能体位置、已打开的抽屉、已发现的物品）。
- 概率性状态 $b_t$ (Belief)：记录未观测到的任务相关对象的位置概率分布（Categorical Distribution）。

**2. 双通道交互接口 (Dual-Interface)**
- 模拟接口 (Simulation Interface)：接收假设性动作，返回动作执行后的预测结果或报错反馈（沿用现有的 WALL-E 机制）。
- 信念查询接口 (Belief-query Interface)：接收自然语言查询（如 `query where is <object>`），直接返回基于概率降序排列的可能位置列表。该操作不消耗环境步数。

**3. 贝叶斯信念更新 (Belief Update)**
当智能体在环境中执行真实动作并获得新观测时，模型使用简单的存在/缺失重归一化（Presence/absence renormalization）逻辑更新信念：如果在某处找到物体，概率坍缩为 1；如果未找到，该处概率清零，剩余未探索区域的概率重新归一化。

**核心逻辑伪代码 (Python 风格):**

```python
class BeliefBasedWorldModel:
    def __init__(self, prior_knowledge):
        # 确定性记忆：已观测到的确切事实
        self.deterministic_memory = {} 
        # 概率性信念：未观测物体的概率分布
        self.belief_state = self._initialize_prior(prior_knowledge) 
        # 动作模拟器（如 WALL-E）
        self.simulator = ActionSimulator() 

    def _initialize_prior(self, prior_knowledge):
        # 基于常识或游戏引擎规则初始化均匀分布
        return {"egg": {"fridge": 0.25, "countertop": 0.25, "garbagecan": 0.25, "microwave": 0.25}}

    def process_llm_output(self, llm_output):
        if llm_output.startswith("query"):
            # 通道一：信念查询接口 (不改变环境)
            return self._handle_belief_query(llm_output)
        else:
            # 通道二：模拟接口 (预测动作合法性/后果)
            return self.simulator.predict_next_state(self.deterministic_memory, llm_output)

    def _handle_belief_query(self, query):
        target_obj = self._parse_query(query)
        if target_obj in self.belief_state:
            # 按概率降序返回自然语言描述
            sorted_locations = sort_by_probability(self.belief_state[target_obj])
            return f"{target_obj} is most likely at: {format_to_text(sorted_locations)}"
        return "Object not tracked or already found."

    def update_state_from_real_observation(self, action, real_observation):
        # 1. 更新确定性记忆
        self.deterministic_memory.update(real_observation)
        
        # 2. 贝叶斯信念更新 (存在/缺失重归一化)
        searched_location = get_location_from_action(action)
        found_objects = get_objects_from_obs(real_observation)
        
        for obj in self.belief_state.keys():
            if obj in found_objects:
                # 找到物体，概率坍缩
                self.belief_state[obj] = {searched_location: 1.0}
            else:
                # 未找到，该位置概率清零，其余位置重归一化
                if searched_location in self.belief_state[obj]:
                    self.belief_state[obj][searched_location] = 0.0
                    self.belief_state[obj] = normalize(self.belief_state[obj])
```

### 第二模块：核心架构解释

本研究的架构分为两个完全解耦的阶段：**训练期的正向生成器**与**推理期的约束引导采样**。

**1. 基础生成器 (Flow-Matching DiT)**
模型使用 Qwen 提取文本特征，使用 PartField 提取 3D 点云特征。生成器是一个 12 层的 DiT，采用流匹配（Flow Matching）目标进行训练。状态空间包含抓取位姿（28维）和 8 个接触点坐标（8x4维）。该模型仅在纯正向指令数据集上训练，对“规避”概念一无所知。

**2. 指令解析与 3D 语义定位 (Parsing & Grounding)**
在推理时，首先使用 LLM（Gemma 4）将原始混合指令拆分为：纯正向指令（Prompt A）和禁区部位名称。随后，利用冻结的 3D 开放词汇定位模型（Find3D）在点云上分割出禁区 $\mathcal{F}$。

**3. 接触门控无分类器引导 (Contact-Gated CFG)**
在去噪采样的每一步，模型分别基于正向指令（Prompt A）和构造的负向指令（Prompt B，如“抓取禁区部位”）预测接触点的速度场。计算两者的差值，并提取与正向速度正交的分量（Perpendicular Guidance）。该正交分量在接触点靠近禁区时被激活，将抓取轨迹向侧面推开，而不破坏原有的抓取目标。

**4. 序贯蒙特卡洛与边缘保持扰动 (SMC with Churn)**
并行采样 $N$ 个粒子。在特定的时间步，计算每个粒子接触点到禁区 $\mathcal{F}$ 的前瞻距离（Look-ahead potential）。基于该势函数计算重要性权重并进行重采样（Resampling），淘汰冲向禁区的粒子，复制安全的粒子。为了防止被复制的粒子在后续确定性 ODE 求解中轨迹完全重合（粒子坍缩），引入了 Churn 机制：在每一步注入边缘保持的随机噪声，将 ODE 转化为 SDE，强制克隆粒子产生轨迹分化。

**核心逻辑伪代码 (Python 风格):**

```python
def inference_steering(DiT, prompt_A, prompt_B, forbidden_region_F, N_particles=16, steps=25):
    # 初始化 N 个粒子的状态 (位姿 + 接触点)
    x = sample_gaussian_noise(N_particles)
    dt = 1.0 / steps
    
    for i in range(steps):
        t = i * dt
        
        # 1. 基础速度场预测 (基于正向指令)
        v_A = DiT(x, t, condition=prompt_A)
        
        # 2. 接触门控 CFG 引导
        if in_guidance_window(i):
            v_B = DiT(x, t, condition=prompt_B)
            # 预测当前速度下的最终接触点位置
            x_contact_hat = x.contact + (1 - t) * v_A.contact 
            
            # 仅当接触点靠近禁区时激活引导
            if distance(x_contact_hat, forbidden_region_F) < gate_threshold:
                # 计算正交引导向量
                g_perp = orthogonal_projection(v_A.contact - v_B.contact, v_A.contact)
                v_A.contact = v_A.contact + weight * g_perp
                
        # 3. SMC 重采样 (在预设的时间步)
        if i in resampling_steps:
            # 基于到禁区的距离计算势函数得分
            scores = compute_potential(x_contact_hat, forbidden_region_F)
            # 淘汰低分粒子，复制高分粒子
            x, v_A = resample_particles(x, v_A, weights=exp(lambda * scores))
            
        # 4. Churn: 边缘保持的 SDE 更新 (防止克隆粒子轨迹重合)
        noise = sample_gaussian_noise(N_particles)
        drift_correction = compute_drift_correction(x, v_A, t, eta)
        x = x + (v_A - drift_correction) * dt + sqrt(2 * eta * (1 - t) * dt) * noise
        
    # 5. 最终几何校验，选择距离禁区最远且贴合物体的抓取
    best_grasp = geometric_selection(x, forbidden_region_F)
    return best_grasp
```

### 第二模块：核心架构解释

DSG 框架的运行流程分为三个核心阶段：物体表征与关联、物体变化检测、空间关系推理。

1. **物体表征与关联**：接收 RGB-D 序列，利用 GroundingDINO 和 SAM 提取 2D 掩码，通过 CLIP 提取语义特征。将当前观测与全局 3DGS 地图中的历史物体进行几何与语义相似度匹配。匹配成功则更新特征，失败则初始化为新物体。
2. **物体变化检测（双视角比对）**：
   - **当前视角比对**：先用当前帧 RGB 优化 3D 高斯原语，然后渲染出掩码，与实际观测计算 SSIM 相似度。高相似度判定为“稳定”，极低相似度判定为“消失”，中间状态判定为“不确定”。
   - **最优视角比对**：针对“不确定”的物体，通过最小化视锥损失和可见度损失，优化出一个虚拟的最佳相机位姿。在该视角下重新渲染历史与当前的高斯地图并比对，最终敲定物体是保留还是剔除。
3. **空间关系推理**：对更新后的物体节点，使用视觉大模型（DAM）生成物体本身及其周围扩大区域的文本描述。通过 3D 边界框 IoU 和点云重叠度过滤掉无关的候选边后，将几何信息、语义标签和多粒度视觉描述输入 LLM，推理出最终的场景图边（空间关系）。

```python
    scene_graph = SceneGraph()

        # 1. 物体表征与关联
        detections = extract_masks_and_features(frame) # GroundingDINO + SAM + CLIP
        for det in detections:
            matched_obj = match_with_global_map(det, global_3dgs_map)
            if matched_obj:
                update_gaussian_features(matched_obj, det)
            else:
                global_3dgs_map.add_new_object(det)
                
        # 2. 物体变化检测 (双视角比对)
        optimize_gaussians_with_current_frame(global_3dgs_map, frame) # 先优化，减小伪影
        
        for obj in global_3dgs_map.objects:
            # 当前视角比对
            ssim_current = compute_ssim(render(obj, frame.pose), frame.rgb_mask)
            
            if ssim_current >= threshold_high:
                obj.state = "Stable"
            elif ssim_current <= threshold_low:
                obj.state = "Missing"
            else:
                # 最优视角比对 (针对不确定物体)
                optimal_pose = optimize_virtual_viewpoint(obj) # 最大化可见度
                render_history = render(obj.history_gaussians, optimal_pose)
                render_current = render(obj.current_gaussians, optimal_pose)
                
                ssim_optimal = compute_ssim(render_history, render_current)
                obj.state = "Stable" if ssim_optimal >= threshold_low else "Missing"
                
        # 剔除 Missing 物体，更新节点
        global_3dgs_map.remove_missing_objects()
        scene_graph.update_nodes(global_3dgs_map.objects)
        
    # 3. 空间关系推理
    candidate_edges = filter_edges_by_geometry(scene_graph.nodes) # 基于 3D IoU 和点云重叠度
    
    for edge in candidate_edges:
        obj_A, obj_B = edge
        # 提取多粒度视觉上下文
        desc_A = vlm.describe(crop_image(obj_A, expand_ratio=1.0)) # 物体级
        context_A = vlm.describe(crop_image(obj_A, expand_ratio=2.5)) # 上下文级
        
        # LLM 推理关系
        prompt = build_prompt(obj_A.geometry, obj_B.geometry, desc_A, context_A)
        relation = llm.infer_relationship(prompt)
        scene_graph.add_edge(obj_A, obj_B, relation)
        
    return scene_graph
```

### 第二模块：核心架构解释

Streaming4D 的架构本质上是一个生产者-消费者（Producer-Consumer）模型，通过时间步的错位实现流水线并行。整个流程分为三个核心部分：

1.  **前端：块级自回归视频生成 (Block-wise AR Video Generation)**
    模型不逐帧吐出视频，而是将联合分布分解为离散的时空块 $B_k$（每个块包含 $N$ 帧）。生成器 $G_{AR}$ 基于文本提示 $\mathcal{P}$ 和前一个块 $B_{k-1}$ 的上下文，自回归地预测当前块 $B_k$。为了防止长程误差累积，采用了 Self-Forcing 范式对齐训练与推理分布。
2.  **后端：实时增量 4D 重建 (Real-time Incremental 4D Reconstruction)**
    维护一个持久化的世界状态（Persistent State $S$）。当接收到新的视频块 $B_k$ 时，首先通过视觉编码器提取特征，然后利用 `UpdateTransformer` 将新观测融合进历史状态 $S_{k-1}$ 得到 $S_k$。最后，通过 `ReadoutTransformer` 从当前状态中解码出相机坐标系和世界坐标系下的 3D 点云。
3.  **核心调度：流水线并行 (Pipelined Parallelism)**
    这是系统的灵魂。在挂钟时间（Wall-clock step）$k$，系统同时执行两个任务：生成器在计算 $B_k$，而重建器在处理 $B_{k-1}$。总延迟从串行的累加 $\sum(T_{gen} + T_{rec})$ 优化为并行的 $\sum \max(T_{gen}, T_{rec})$。

**底层逻辑伪代码 (Python 风格)**：

```python
import asyncio

class Streaming4D:
    def __init__(self, text_prompt, video_generator, reconstructor):
        self.prompt = text_prompt
        self.G_AR = video_generator      # Self-Forcing AR Generator
        self.R_4D = reconstructor        # CUT3R-based Incremental Reconstructor
        self.world_state = None          # Persistent memory S
        self.world_pointclouds = []      # Accumulated 4D geometry

    async def generate_block(self, prev_block, latent_noise):
        # 模拟生成器推理耗时 T_gen
        current_block = await self.G_AR.predict(prev_block, self.prompt, latent_noise)
        return current_block

    async def reconstruct_block(self, block_to_reconstruct):
        # 模拟重建器推理耗时 T_rec
        features = self.R_4D.extract_features(block_to_reconstruct)
        
        # 状态更新: Sk = UpdateTransformer(Sk-1, E(Bk))
        self.world_state = await self.R_4D.update_state(self.world_state, features)
        
        # 状态读取: X_cam, X_world = ReadoutTransformer(Sk)
        pts_cam, pts_world = await self.R_4D.readout(self.world_state)
        self.world_pointclouds.append(pts_world)

    async def run_pipeline(self, num_blocks):
        # 初始化第一块 (仅依赖文本)
        B_1 = await self.generate_block(prev_block=None, latent_noise=z_1)
        prev_B = B_1
        
        for k in range(2, num_blocks + 1):
            # 核心创新：流水线并行 (Pipelined Parallelism)
            # 异步并发执行：生成第 k 块的同时，重建第 k-1 块
            task_gen = asyncio.create_task(self.generate_block(prev_B, latent_noise=z_k))
            task_rec = asyncio.create_task(self.reconstruct_block(prev_B))
            
            # 等待两个任务中耗时最长的完成 (max(T_gen, T_rec))
            current_B, _ = await asyncio.gather(task_gen, task_rec)
            prev_B = current_B
            
        # 收尾：重建最后一块
        await self.reconstruct_block(prev_B)
```

A2: 核心创新点是引入了“块级流水线同步策略”（Block-wise Pipelined Synchronization）。作者放弃了传统的逐帧生成或整段生成，将视频流切分为包含少量帧的时空块。利用这种粒度，在生成器自回归预测下一个视频块的同时，重建模块同步对上一个已生成的视频块进行增量 3D 状态更新，通过计算重叠（Computation Overlapping）隐藏了重建的延迟。

A4:

2. 设计了块级（Block-wise）流水线执行策略，在保证时空一致性的前提下，最大化了推理吞吐量并降低了端到端延迟。

### 第二模块：核心架构解释

GUI-CC 并非提出一个新的世界模型，而是构建了一套高维度的基准测试框架。其核心流程分为数据构建、双轨评估和多维指标计算三个阶段。

**1. 离线参考动作轨道 (Offline Reference-Action Track)**
该轨道旨在隔离智能体策略的影响，纯粹测试世界模型的自回归稳定性。系统从 GUIOdyssey 数据集中提取真实的人类交互轨迹（包含初始屏幕和一系列语义动作）。世界模型仅接收初始屏幕，随后必须根据给定的真实动作序列，一步步自回归地生成后续屏幕。评估重点是：在没有真实屏幕纠偏的情况下，模型生成的环境是否还能支持后续的真实动作。

**2. 在线智能体闭环轨道 (Online Agent-Loop Track)**
该轨道旨在测试世界模型作为“真实模拟器”的闭环能力。系统提供一个初始屏幕和一个任务指令，使用一个冻结的探针智能体（GPT-5.5）来观察世界模型生成的屏幕，并输出下一步动作。世界模型接收该动作后生成新屏幕，交还给智能体。这一过程持续进行，直到任务完成或陷入死循环。

**3. 评估维度 (Evaluation Metrics)**
摒弃了单纯的像素级相似度，引入四个维度：
*   过渡保真度 (Transition Fidelity)：预测UI与真实UI的视觉和布局对齐程度。
*   过渡合理性 (Transition Plausibility)：动作是否产生了预期的视觉变化，UI是否依然可读。
*   上下文一致性 (Contextual Consistency)：多步交互中，APP状态、导航历史、实体是否保持连贯。
*   任务进度 (Task Progress)：生成的环境能支撑多长的正确动作序列（离线）或达成多少任务里程碑（在线）。

**底层逻辑伪代码实现：**

```python
class GUICC_Benchmark:
    def __init__(self, world_model, probing_agent, vlm_judge):
        self.world_model = world_model
        self.agent = probing_agent
        self.judge = vlm_judge

    def evaluate_offline_track(self, initial_state, reference_actions):
        """离线轨道：测试自回归状态下的动作可执行性"""
        current_state = initial_state
        generated_trajectory = [current_state]
        history = []
        
        for action in reference_actions:
            # 世界模型仅依赖自身生成的历史状态和给定动作进行预测
            next_state = self.world_model.predict(current_state, action, history)
            generated_trajectory.append(next_state)
            
            # 更新历史记录（暴露误差累积）
            history.append((current_state, action))
            current_state = next_state
            
        # 使用VLM裁判评估整条轨迹的上下文一致性和参考动作支持度
        scores = self.judge.score_trajectory(generated_trajectory, reference_actions)
        return scores

    def evaluate_online_track(self, initial_state, task_instruction, max_steps):
        """在线轨道：测试闭环环境下的任务推进能力"""
        current_state = initial_state
        generated_trajectory = [current_state]
        history = []
        
        for step in range(max_steps):
            # 探针智能体基于当前生成的屏幕决定下一步动作
            action = self.agent.act(task_instruction, current_state, history)
            
            if action == "TERMINATE":
                break
                
            # 世界模型作为环境，响应智能体的动作
            next_state = self.world_model.predict(current_state, action, history)
            generated_trajectory.append(next_state)
            
            history.append((current_state, action))
            current_state = next_state
            
        # 评估智能体在生成环境中达成的里程碑
        scores = self.judge.score_milestones(generated_trajectory, task_instruction)
        return scores
```

- **最能证明有效性的核心数据**：Qwen-2.5-VL 在面对不同肤色时的让行率呈现阶梯式下降（Fair white 7% -> Brown 6% -> Medium -> Dark 0%）。这组数据最直接地证明了 VLM 完美复刻了现实世界中人类驾驶员对深肤色人群让行率低的系统性偏见，证明了该审计方法的有效性。
- **存疑的试验结果**：LLaVA-NeXT 在 SC 测试中的基础让行率中位数仅为 1%。虽然作者解释为该模型极其保守（倾向于不停车），但如此极端的基线数据会严重压缩偏见方差的观察空间。其在特定族裔（如 Indian 50%）上的高让行率更像是模型在极端长尾分布下的幻觉或特征过拟合，而非单纯的社会偏见体现，基于此得出的统计学显著性需要谨慎看待。

### 第二模块：核心架构解释

本文的方法论不涉及底层网络架构的改动，而是构建了一套针对黑盒大模型的自动化审计 Pipeline。其核心流程分为数据准备、LLM 审计（AEBE）和 VLM 审计（SC）三个阶段。

**1. 数据准备阶段**
从 nuImages, JAAD, PIE 等真实自动驾驶数据集中提取包含单行人的图像（共 23,812 张），以排除多行人特征的干扰。

**2. LLM 审计流程：AEBE (All Else Being Equal) 测试**
针对纯文本模型。首先利用 VLM 将真实图像转化为纯文本的交通场景描述，并人工清洗掉所有关于行人性别、种族等人口统计学特征的词汇，形成“基准场景”。随后，通过模板注入的方式，将特定的特征词汇（如“盲人”、“黑人”、“女性”）插入基准场景中。最后，要求 LLM 输出是否停车的决策，并统计不同特征组的让行率差异。

**3. VLM 审计流程：SC (Self-Consistency) 测试**
针对多模态模型。由于无法在真实图像中完美控制变量（如保持光照、姿态不变仅改变行人肤色），作者采用逻辑自洽性测试。首先询问 VLM 两个前置问题：行人是否有过马路意图？当前情况是否需要停车？如果 VLM 回答“是”，则在逻辑上它必须做出“停车”决策。随后，要求 VLM 预测图像中行人的人口统计学特征，并最终输出驾驶决策。通过关联 VLM 自身的特征预测与最终决策，评估其逻辑自洽性是否被偏见打破。

```python
class BiasAuditor:
    def __init__(self, llm_model, vlm_model, demographics_list):
        self.llm = llm_model
        self.vlm = vlm_model
        self.demographics = demographics_list

    def run_aebe_test_for_llm(self, base_text_scenario):
        """All Else Being Equal Test for LLMs"""
        results = {}
        for trait in self.demographics:
            # Inject demographic trait into the clean text scenario
            modified_scenario = f"{base_text_scenario} The pedestrian is {trait}."
            
            # Query LLM for driving decision (Stop: Yes/No)
            prompt = f"{modified_scenario} Should the autonomous vehicle stop? Yes or No."
            decision_logprobs = self.llm.get_logprobs(prompt, options=["Yes", "No"])
            
            # Record the decision based on highest probability
            results[trait] = "Yes" if decision_logprobs["Yes"] > decision_logprobs["No"] else "No"
            
        return results
```

### 第三模块：核心学术问答

Q1: 这篇论文试图解决什么核心问题？

A1: 评估并量化用于自动驾驶决策的通用基础模型（LLM/VLM）是否继承了人类社会中存在的隐性偏见，即在面对不同人口统计学特征（如肤色、残疾、性别、宗教）的行人时，模型是否会做出不公平的让行（停车）决策。

Q2: 作者提出的核心解决方案（创新点）是什么？

A2: 提出了两种无需昂贵真实世界配对数据的自动化偏见审计方法：针对文本 LLM 的 AEBE（控制变量替换）测试，以及针对多模态 VLM 的 SC（自洽性逻辑闭环）测试。

Q3: 实验设计的关键支撑（或巧妙之处/数据集特点）是什么？

A3: 巧妙之处在于将物理环境特征与行人社会特征进行了解耦。对于 LLM，利用 VLM 逆向生成纯净文本以实现绝对的控制变量；对于 VLM，绕过了“生成完美配对图像”的工程难题，转而利用模型自身的视觉估计结果与最终决策进行逻辑一致性校验，从而在现有真实数据集（nuImages等）上直接完成了偏见测量。

Q4: 这篇论文最显著的贡献点（Top 3）是什么？

A4:
1. 提出了 AEBE 和 SC 两种针对自动驾驶大模型让行偏见的系统性审计方法论。

3. 实验确凿证明了当前主流模型（如 Qwen, Llama, Mistral）在残疾、肤色等维度存在显著的统计学偏见，直接挑战了“常识驱动自动驾驶”的安全性与公平性假设。
