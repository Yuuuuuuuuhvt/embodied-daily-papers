视觉-语言-动作（VLA）策略在长视野（long-horizon）操作任务中面临巨大挑战。真实世界的机器人任务通常包含多个步骤，高度依赖任务进度，且极易受到执行误差累积的影响。传统的单步VLA模型缺乏长期的任务状态跟踪和错误恢复机制，导致在复杂任务中表现脆弱。

为解决这一问题，本文提出了LoHo-Manip模块化框架，将长视野指令跟随任务解耦为“任务管理VLM”和“执行器VLA”。管理者VLM以滚动时域（receding-horizon）的方式运行，根据当前观测预测进度感知的剩余计划。该计划包含轻量级的语言记忆（已完成与剩余子任务的划分）以及视觉轨迹（指示下一步移动位置的2D关键点提示）。随后，执行器VLA以渲染出的视觉轨迹为条件，将长视野决策转化为跟随轨迹的局部重复控制。

这种在每一步预测剩余计划的机制自然形成了一个隐式闭环。如果某一步执行失败，该步骤会保留在后续的输出计划中，视觉轨迹也会相应更新。这使得系统能够实现自动接续和重规划，而无需依赖人工设计的恢复逻辑或脆弱的视觉历史缓冲区。在仿真环境和真实Franka机器人上的端到端操作实验表明，该方法在长视野任务的成功率、鲁棒性以及分布外（OOD）泛化能力上均取得了显著提升。

该研究为具身智能中的长视野规划提供了一种优雅的解决方案。通过将高层语义推理（VLM）与底层动作执行（VLA）通过直观的“视觉轨迹”进行桥接，不仅大幅增强了VLA模型的错误恢复能力，也为未来结合世界模型进行复杂物理交互和闭环控制指明了极具潜力的方向。

### 第二模块：核心架构解释

LoHo-Manip 的核心架构是一个非对称的双层闭环系统，分为高层任务管理器（Task Manager）和底层执行器（Executor）。

1. **状态与记忆更新**：系统不维护庞大的历史视频流，而是维护一个轻量级的文本记忆（Completed Plan），记录已经完成的子任务。
2. **高层滚动预测（Receding-Horizon Planning）**：在特定的时间步（或固定间隔），任务管理器（一个微调过的VLM）接收当前单帧RGB图像、原始语言指令以及文本记忆。它输出两部分内容：更新后的剩余子任务列表（Remaining Plan），以及指导下一步动作的2D视觉轨迹（Visual Trace，即末端执行器的像素级航点）。
3. **视觉提示渲染（Visual Prompting）**：将预测出的2D视觉轨迹直接渲染（画）到当前观测图像上，形成一张带有空间引导信息的“导航图”。
4. **底层短程控制（Short-Horizon Control）**：底层执行器（如 $\pi_0$ 或 StarVLA）接收这张带有轨迹提示的图像，输出具体的机器人关节动作。由于执行器只需关注如何“沿着轨迹走”，长程规划的复杂性被大幅降维。
5. **隐式故障恢复**：如果底层执行失败（例如没抓起杯子），下一帧图像中杯子仍在原处。高层管理器在下一次调用时，会根据当前图像重新输出“抓取杯子”的剩余计划和轨迹，从而实现自动纠错。

```python
class LoHoManipSystem:
    def __init__(self, task_manager_vlm, executor_vla, plan_interval=100):
        self.manager = task_manager_vlm
        self.executor = executor_vla
        self.plan_interval = plan_interval
        
    def run_episode(self, instruction, env):
        obs = env.reset()
        # 初始化轻量级文本记忆（已完成的任务为空）
        completed_plan_text = "done: none" 
        step_count = 0
        
        while not env.is_done():
            # 滚动时域规划：定期调用高层VLM
            if step_count % self.plan_interval == 0:
                # 仅依赖当前帧和文本记忆，预测剩余计划和2D轨迹
                remaining_plan_text, visual_trace_2d = self.manager.predict(
                    current_image=obs.image,
                    instruction=instruction,
                    memory=completed_plan_text
                )
                
                # 更新文本记忆（隐式进度跟踪）
                completed_plan_text = self.manager.update_memory(
                    completed_plan_text, 
                    remaining_plan_text
                )
            
            # 将2D轨迹渲染到当前图像上，作为视觉提示
            prompted_image = render_trace_on_image(obs.image, visual_trace_2d)
            
            # 底层VLA执行器根据带有轨迹的图像输出动作
            action = self.executor.act(
                image=prompted_image, 
                subtask_text=remaining_plan_text.current_subtask
            )
            
            obs = env.step(action)
            step_count += 1
```

该研究为具身智能中的长视野规划提供了一种优雅的解决方案。通过将高层语义推理（VLM）与底层动作执行（VLA）通过直观的“视觉轨迹”进行桥接，不仅大幅增强了VLA模型的错误恢复能力，也为未来结合世界模型进行复杂物理交互和闭环控制指明了极具潜力的方向。

### 第二模块：核心架构解释

LoHo-Manip 的核心架构是一个非对称的双层闭环系统，分为高层任务管理器（Task Manager）和底层执行器（Executor）。

1. **状态与记忆更新**：系统不维护庞大的历史视频流，而是维护一个轻量级的文本记忆（Completed Plan），记录已经完成的子任务。
2. **高层滚动预测（Receding-Horizon Planning）**：在特定的时间步（或固定间隔），任务管理器（一个微调过的VLM）接收当前单帧RGB图像、原始语言指令以及文本记忆。它输出两部分内容：更新后的剩余子任务列表（Remaining Plan），以及指导下一步动作的2D视觉轨迹（Visual Trace，即末端执行器的像素级航点）。
3. **视觉提示渲染（Visual Prompting）**：将预测出的2D视觉轨迹直接渲染（画）到当前观测图像上，形成一张带有空间引导信息的“导航图”。
4. **底层短程控制（Short-Horizon Control）**：底层执行器（如 $\pi_0$ 或 StarVLA）接收这张带有轨迹提示的图像，输出具体的机器人关节动作。由于执行器只需关注如何“沿着轨迹走”，长程规划的复杂性被大幅降维。
5. **隐式故障恢复**：如果底层执行失败（例如没抓起杯子），下一帧图像中杯子仍在原处。高层管理器在下一次调用时，会根据当前图像重新输出“抓取杯子”的剩余计划和轨迹，从而实现自动纠错。

```python
class LoHoManipSystem:
    def __init__(self, task_manager_vlm, executor_vla, plan_interval=100):
        self.manager = task_manager_vlm
        self.executor = executor_vla
        self.plan_interval = plan_interval
        
    def run_episode(self, instruction, env):
        obs = env.reset()
        # 初始化轻量级文本记忆（已完成的任务为空）
        completed_plan_text = "done: none" 
        step_count = 0
        
        while not env.is_done():
            # 滚动时域规划：定期调用高层VLM
            if step_count % self.plan_interval == 0:
                # 仅依赖当前帧和文本记忆，预测剩余计划和2D轨迹
                remaining_plan_text, visual_trace_2d = self.manager.predict(
                    current_image=obs.image,
                    instruction=instruction,
                    memory=completed_plan_text
                )
                
                # 更新文本记忆（隐式进度跟踪）
                completed_plan_text = self.manager.update_memory(
                    completed_plan_text, 
                    remaining_plan_text
                )
            
            # 将2D轨迹渲染到当前图像上，作为视觉提示
            prompted_image = render_trace_on_image(obs.image, visual_trace_2d)
            
            # 底层VLA执行器根据带有轨迹的图像输出动作
            action = self.executor.act(
                image=prompted_image, 
                subtask_text=remaining_plan_text.current_subtask
            )
            
            obs = env.step(action)
            step_count += 1
```

### 第二模块：核心架构解释

VistaBot 的核心架构分为三个连续的阶段，旨在将任意未知视角的观测转化为与训练视角对齐的高维时空特征，并用于闭环控制。

**阶段一：4D 几何估计 (4D Geometry Estimation)**
接收任意测试视角图像，利用微调后的前馈几何模型（VGGT）预测该帧的深度图以及相对于训练视角的相对相机位姿。随后，利用深度信息将 2D 图像提升为 3D 点云，通过相对位姿将其变换到训练视角下，并重新投影为 2D 图像。由于视角差异和遮挡，该投影图像会包含大量空洞（缺失区域），同时生成对应的投影掩码（Mask）。

**阶段二：时空隐特征提取 (Spatiotemporal Latent Extraction)**
将带有空洞的投影图像和掩码作为条件，输入到基于 DiT 架构的视频扩散模型（CogVideoX）中进行图像修复（Inpainting）。为了保证闭环控制的时间一致性，引入了“时间记忆参考”机制：将上一帧的观测缓存并编码，通过 DiT 块中的交叉注意力机制（空间 Token 作为 Query，时间 Token 作为 Key/Value）注入到当前帧的生成过程中。

**阶段三：闭环动作学习 (Closed-loop Action Learning)**
摒弃了将扩散模型输出解码为 RGB 图像再输入给策略的传统做法。直接从扩散模型自适应层归一化后的最后一个 DiT 块中提取场景特征（Scene features）。这些特征已经包含了对象级语义和几何理解。将其与机器人本体状态（Robot state）融合，输入到 Transformer 策略网络（如 ACT 或 $\pi_0$）中预测动作块（Action chunks）。

**核心逻辑伪代码 (Python 风格):**

```python
class VistaBot(nn.Module):
    def __init__(self, geometry_model, video_diffusion_model, policy_model):
        super().__init__()
        self.vggt = geometry_model          # VGGT for depth & pose
        self.vdm = video_diffusion_model    # CogVideoX (DiT-based)
        self.policy = policy_model          # ACT or pi_0
        self.memory_cache = None            # Temporal memory for closed-loop

    def forward(self, novel_view_img, robot_state):
        # Step 1: 4D Geometry Estimation
        # Predict relative pose (T) and depth (D) from novel view to training view
        rel_pose, depth = self.vggt(novel_view_img)
        
        # Lift to 3D point cloud, warp to training view, and project back to 2D
        point_cloud = lift_to_3d(novel_view_img, depth)
        warped_pc = apply_transform(point_cloud, rel_pose)
        projected_img, mask = render_to_2d(warped_pc)
        
        # Step 2: Spatiotemporal Latent Extraction
        # Encode current spatial conditions
        spatial_tokens = self.vdm.vae_encode(projected_img, mask)
        
        # Incorporate temporal memory (cross-attention in DiT)
        if self.memory_cache is not None:
            temporal_tokens = self.memory_cache
        else:
            temporal_tokens = initialize_empty_memory()
            
        # Forward pass through DiT blocks (denoising & feature extraction)
        # We DO NOT decode back to pixels. We extract the latent features.
        latent_features = self.vdm.dit_forward(
            spatial_tokens, 
            context=temporal_tokens
        )
        
        # Update memory cache for the next closed-loop step
        self.memory_cache = self.vdm.vae_encode(novel_view_img)
        
        # Step 3: Closed-loop Action Learning
        # Policy predicts action chunks directly from VDM latents and robot state
        action_chunks = self.policy(latent_features, robot_state)
        
        return action_chunks
```

### 第二模块：核心架构解释

ResVLA 的核心架构严格遵循“预测-细化（Predict-Refine）”的双层级联逻辑，将复杂的动作生成任务降维。

**阶段一：意图锚定（Intent Anchoring）**
模型首先通过视觉-语言大模型（VLM，本文使用 Qwen-VL）提取多模态上下文特征。随后，不直接输出最终动作，而是通过一个回归头预测动作轨迹在频域中的**低频分量**（通过 DCT 变换定义）。这个低频分量代表了平滑的、长视野的全局运动趋势（即“意图”），并以此构建一个依赖于条件（Condition-Dependent）的高斯分布作为后续生成的起点。

**阶段二：残差流匹配（Residual Flow Matching）**
在获得低频语义锚点后，生成任务被转化为一个局部高频抖动（物理接触细节）的补全问题。模型采用条件流匹配（CFM）技术，建立一条从“低频锚点分布”指向“真实动作分布”的残差扩散桥。由于起点已经非常接近终点（几何距离短），模型只需要学习一个低能量的残差向量场，极大地降低了拟合难度。

**核心伪代码实现**：

```python
import torch
import torch.nn as nn

class ResVLA(nn.Module):
    def __init__(self, vlm_encoder, intent_head, flow_matching_net, dct_operator):
        super().__init__()
        self.vlm = vlm_encoder
        self.intent_head = intent_head
        self.fm_net = flow_matching_net
        self.dct = dct_operator # Handles DCT and Inverse DCT
        self.sigma_min = 1e-4

    def forward_train(self, image, language, action_gt):
        # 1. Multimodal Encoding
        context = self.vlm(image, language)
        
        # 2. Frequency Decomposition (Ground Truth)
        # Extract low-frequency (semantic) and high-frequency (residual) components
        action_low_freq = self.dct.low_pass_filter(action_gt)
        
        # 3. Intent Anchoring (Predict low-frequency anchor)
        anchor_pred = self.intent_head(context)
        
        # Semantic Alignment Loss
        loss_semantic = torch.nn.functional.mse_loss(anchor_pred, action_low_freq)
        
        # 4. Residual Flow Matching
        # Sample time t and noise epsilon
        t = torch.rand(action_gt.shape[0], 1, 1).to(action_gt.device)
        epsilon = torch.randn_like(action_gt) * self.sigma_min
        
        # Construct source distribution centered at the predicted anchor
        x_src = anchor_pred + epsilon
        
        # Optimal Transport path interpolation
        x_t = (1 - t) * x_src + t * action_gt
        
        # Target vector field (residual)
        u_t_target = action_gt - x_src
        
        # Predict vector field
        v_pred = self.fm_net(x_t, t, context)
        
        # Residual Refinement Loss
        loss_residual = torch.nn.functional.mse_loss(v_pred, u_t_target)
        
        return loss_semantic + loss_residual

    def generate_action(self, image, language, num_steps=4):
        # Inference phase
        context = self.vlm(image, language)
        
        # Predict deterministic anchor
        anchor_pred = self.intent_head(context)
        
        # Initialize from anchor with minimal noise
        x_t = anchor_pred + torch.randn_like(anchor_pred) * self.sigma_min
        
        # Euler Integration for Flow Matching
        dt = 1.0 / num_steps
        for i in range(num_steps):
            t = torch.tensor([i * dt]).to(x_t.device)
            v_pred = self.fm_net(x_t, t, context)
            x_t = x_t + v_pred * dt
            
        return x_t
```

### 第二模块：核心架构解释

CorridorVLA 的架构并未对基础 VLM 做大规模手术，而是通过极小的参数开销（增加几个 Token）和定制化的损失函数来实现物理约束。其核心流程分为三个阶段：

**1. 稀疏锚点预测 (Sparse Anchor Prediction)**
在 VLM 的输入序列末尾追加 $K$ 个可学习的 Anchor Slots（默认 $K=3$）。VLM 结合视觉和语言指令，直接输出这 $K$ 个时间点对应的末端执行器 3D 位置增量（$\Delta$-positions）。

**2. 动作空间增强 (Action Space Augmentation / extra-A)**
将标准的动作块（Action Chunk）进行扩展，把对应的末端执行器 $\Delta$-位置拼接到动作向量中。这使得动作头在生成控制指令的同时，也显式地生成对应的空间位移，从而与 VLM 预测的锚点在同一物理空间内对齐。

**3. 轨迹感知的 Flow Matching 训练 (Trajectory-Aware Flow Matching)**
这是最核心的创新。总损失由三部分组成：标准的 Flow Matching 损失、锚点预测损失、以及**走廊正则化损失（Corridor Regularizer）**。走廊损失包含：
*   **Buffer Loss ($L_{buf}$):** 类似于 Hinge Loss。计算生成轨迹与真实锚点之间的距离，超出容差半径 $\delta$ 的部分给予惩罚。
*   **Consistency Loss ($L_{cons}$):** 在走廊内部，通过累积和（Cumulative-sum）约束轨迹的阶段性进展，防止在可行域内发生漂移。
*   **噪声感知加权 (Noise-aware weighting):** Flow Matching 在 $t \to 1$ 时完全是纯噪声，此时施加几何约束毫无意义。因此使用 $(1-t)$ 作为权重，在 $t \to 0$（接近真实数据）时强化走廊约束。

**核心逻辑伪代码 (Python/PyTorch 风格):**

```python
import torch
import torch.nn.functional as F

def corridor_loss(pred_action_chunk, gt_anchors, gt_action_chunk, t, K=3, alpha=2.0):
    """
    pred_action_chunk: Flow Matching 预测的扩展动作块 [B, T, D]
    gt_anchors: 真实的稀疏锚点增量 [B, K, 3]
    gt_action_chunk: 真实的扩展动作块 [B, T, D]
    t: Flow Matching 的时间步 [B, 1]
    """
    # 1. 提取预测轨迹在 K 个锚点时间步的 3D 位移 (Gather operation)
    pred_anchors = extract_xyz_at_anchor_steps(pred_action_chunk, K) # [B, K, 3]
    gt_extracted_anchors = extract_xyz_at_anchor_steps(gt_action_chunk, K) # [B, K, 3]
    
    # 2. 动态计算走廊容差半径 delta
    # 基于真实动作块与真实锚点的最大偏差，乘以松弛系数 alpha
    max_dev = torch.max(torch.norm(gt_extracted_anchors - gt_anchors, dim=-1), dim=1)[0]
    delta = alpha * max_dev # [B]
    
    # 3. Buffer Loss: 惩罚超出走廊边界的预测
    dist = torch.norm(pred_anchors - gt_anchors, dim=-1) # [B, K]
    L_buf = torch.mean(F.relu(dist - delta.unsqueeze(1))) 
    
    # 4. Consistency Loss: 走廊内部的累积进度一致性
    pred_cumsum = torch.cumsum(pred_anchors, dim=1)
    gt_cumsum = torch.cumsum(gt_anchors, dim=1)
    
    # 随时间步递增的权重 w_tau，强调后期的对齐
    w_tau = compute_increasing_weights(K) 
    L_cons = torch.sum(w_tau * torch.norm(pred_cumsum - gt_cumsum, dim=-1)**2)
    
    # 5. Noise-aware Weighting: t 越大（噪声越大），权重越小
    w_t = 1.0 - t 
    L_corr = w_t * (L_buf + L_cons)
    
    return L_corr.mean()

# 总训练目标
# L_total = L_FM + lambda_1 * L_anchor_pred + lambda_2 * L_corr
```

### 第二模块：核心架构解释

本文并未提出新的神经网络架构，而是针对 VLA 模型的**评估框架**进行了底层逻辑的重构。其核心流程基于 BDDL（Behavior Domain Definition Language）定义的子目标（Sub-goals）进行状态校验。

**1. 基础指标计算 (Q-score)**
传统的 Q-score 仅计算被满足的子目标比例。假设任务有 $N$ 个子目标，第 $i$ 个子目标的完成状态为 $g_i \in \{0, 1\}$。

**2. 目标安全惩罚 (Safety Q-score, sQ)**
在基础得分上，针对目标对象引入两个硬性约束：
*   **放置标准 ($p_i$)**: 要求物体（如水壶、杯子）必须直立放置。如果翻滚角或俯仰角偏离初始方向超过 30°，则 $p_i = 0$。
*   **搬运标准 ($h_i$)**: 追踪关键物体是否被安全搬运。如果物体在途中被掉落或粗暴处理，则 $h_i = 0$。
计算时，将这三者相乘：$g_i \cdot p_i \cdot h_i$。只要发生安全违规，该子目标得分直接归零。

**3. 支撑对象安全惩罚 (Safety-Enhanced Q-score, seQ)**
真实任务中，机器人不仅会破坏目标，还会破坏环境中的支撑对象（如切菜时的砧板、放盘子的桌子）。引入 $M$ 个非目标支撑对象的子目标 $s_j \in \{0, 1\}$。如果交互导致安全隐患（如砧板掉落）或使物体偏离原位超过 10cm，则 $s_j = 0$。将支撑对象的安全状态作为分母和分子的扩充项，计算全局安全得分。

**核心评估逻辑伪代码实现：**

```python
def calculate_vla_performance(sub_goals, support_objects):
    """
    计算 VLA 模型在开放世界任务中的真实安全得分
    
    :param sub_goals: List[Dict], 包含目标对象的完成状态(g), 放置状态(p), 搬运状态(h)
    :param support_objects: List[Dict], 包含非目标支撑对象的安全状态(s)
    :return: Tuple[float, float, float] -> (Q_score, sQ_score, seQ_score)
    """
    N = len(sub_goals)
    M = len(support_objects)
    
    # 1. 计算传统 Q-score (仅看最终目标是否达成)
    q_sum = sum(goal['g'] for goal in sub_goals)
    Q_score = q_sum / N
    
    # 2. 计算 Safety Q-score (sQ) (引入目标对象的姿态和搬运安全惩罚)
    sq_sum = 0
    for goal in sub_goals:
        # 核心机制：乘法惩罚。只要 p 或 h 为 0，该子目标直接作废
        safe_goal = goal['g'] * goal['p'] * goal['h']
        sq_sum += safe_goal
    sQ_score = sq_sum / N
    
    # 3. 计算 Safety-Enhanced Q-score (seQ) (引入非目标支撑对象的环境破坏惩罚)
    support_sum = sum(supp['s'] for supp in support_objects)
    # 将支撑对象作为额外的考核项加入总分计算
    seQ_score = (sq_sum + support_sum) / (N + M)
    
    return Q_score, sQ_score, seQ_score

# 示例：重新布置厨房任务 (4个目标，1个支撑对象)

goals = [
    {'g': 1, 'p': 1, 'h': 1}, # 电器1放入且安全
    {'g': 1, 'p': 1, 'h': 1}, # 电器2放入且安全
    {'g': 1, 'p': 1, 'h': 0}, # 搅拌机放入，但摔坏了
    {'g': 0, 'p': 1, 'h': 1}  # 柜门未关闭
]
supports = [{'s': 1}] # 厨房台面未受破坏

q, sq, seq = calculate_vla_performance(goals, supports)
# 输出: Q=0.75 (3/4), sQ=0.50 (2/4), seQ=0.60 (3/5)
```

### 第二模块：核心架构解释

ReCAPA 的核心逻辑在于构建一个包含 Action（动作）、Subgoal（子目标）和 Trajectory（轨迹）的三层级表示空间，并在训练阶段通过对比学习和分布对齐来约束这三个层级，使其在推理时具备极强的自我纠偏能力。

1. **层次化预测修正 (HPCC)**：模型通过滑动窗口提取轨迹片段，在 Action 和 Subgoal 层级，分别使用 Transformer 预测上一层级（即 Subgoal 和 Trajectory）的表示。通过 InfoNCE 损失，拉近预测表示与真实高层表示的距离，推远 LLM 生成的错误负样本。
2. **Prompt-轨迹对齐 (Sinkhorn + Score-field)**：
   - **Sinkhorn 模块**：计算整个轨迹分布与 Prompt 指令分布之间的熵正则化最优传输距离，提供全局的语义一致性梯度。
   - **Score-field 模块**：将 Prompt 视为高密度目标区域，对当前状态特征加噪后，训练一个 MLP 预测去噪得分（Score-matching）。在推理时，该模块能为偏离目标的底层状态提供一个指向正确语义区域的局部修正梯度。
3. **推理时重采样**：LLM 给出初始子目标序列。执行时，若候选动作与当前子目标的相似度低于阈值，或轨迹级对齐得分骤降，系统会拒绝该动作并触发重采样或子目标切换，从而在物理动作发生前阻断错误。

**核心伪代码实现逻辑**：

```python
import torch
import torch.nn.functional as F

def compute_info_nce_loss(pred_higher_z, target_higher_z, negative_zs, temperature=0.1):
    """计算跨层级预测的对比损失 (Eq. 1)"""
    # pred_higher_z: [B, D], target_higher_z: [B, D], negative_zs: [B, N, D]
    pos_sim = F.cosine_similarity(pred_higher_z, target_higher_z) / temperature
    neg_sims = F.cosine_similarity(pred_higher_z.unsqueeze(1), negative_zs, dim=-1) / temperature
    
    logits = torch.cat([pos_sim.unsqueeze(1), neg_sims], dim=1)
    labels = torch.zeros(logits.size(0), dtype=torch.long, device=logits.device)
    return F.cross_entropy(logits, labels)

def compute_score_field_loss(z_l, prompt_emb, score_network, noise_std=0.1):
    """计算 Score-field 局部对齐损失 (Eq. 3)"""
    # 向状态注入高斯噪声
    noise = torch.randn_like(z_l) * noise_std
    perturbed_z = z_l + noise
    
    # 预测去噪梯度
    predicted_score = score_network(perturbed_z, prompt_emb)
    target_score = -noise / (noise_std ** 2)
    
    return F.mse_loss(predicted_score, target_score)

def recapa_train_step(batch):
    z_action, z_subgoal, z_traj = encode_hierarchy(batch.trajectories)
    prompt_emb = encode_prompt(batch.prompts)
    
    # 1. 层次化预测损失 (HPCC)
    pred_subgoal = action_predictor(z_action)
    loss_pred_action = compute_info_nce_loss(pred_subgoal, z_subgoal.detach(), batch.neg_subgoals)
    
    pred_traj = subgoal_predictor(z_subgoal)
    loss_pred_subgoal = compute_info_nce_loss(pred_traj, z_traj.detach(), batch.neg_trajs)
    
    # 2. 对齐损失
    # 全局 Sinkhorn 对齐 (调用外部 OT 库)
    loss_sinkhorn = compute_sinkhorn_divergence(z_traj, prompt_emb)
    
    # 局部 Score-field 对齐
    loss_score_action = compute_score_field_loss(z_action, prompt_emb, score_net_action)
    loss_score_subgoal = compute_score_field_loss(z_subgoal, prompt_emb, score_net_subgoal)
    
    # 3. 联合优化
    total_loss = (0.5 * loss_pred_action + 0.2 * loss_score_action) + \
                 (0.5 * loss_pred_subgoal + 0.2 * loss_score_subgoal) + \
                 (0.1 * loss_sinkhorn)
                 
    total_loss.backward()
    optimizer.step()
```

```python
class EgoPointPipeline:
    def __init__(self, simulator, mllm_model):
        self.simulator = simulator  # 3D仿真引擎 (如 Habitat/Unity)
        self.model = mllm_model     # 开源多模态大模型 (如 LLaVA)

    def generate_synthetic_data(self, num_samples):
        dataset = []
        for _ in range(num_samples):
            # 1. 随机初始化场景、物体和第一人称相机位姿
            scene = self.simulator.randomize_scene()
            camera_pose = scene.get_egocentric_camera()

            # 2. 生成手部指向动作，获取精确的指尖三维射线
            hand_pose, pointing_ray = scene.generate_pointing_gesture()

            # 3. 物理引擎执行射线投射(Raycast)，确定真实指代目标
            target_object = scene.raycast(pointing_ray)

            if target_object is not None:
                # 4. 渲染第一人称图像并生成多模态QA对
                image = self.simulator.render(camera_pose, hand_pose)
                question = "What object am I pointing at in this egocentric view?"
                answer = target_object.category_name
                dataset.append((image, question, answer))
                
        return dataset

    def spatially_aware_finetuning(self, dataset, epochs=3):
        # 强制模型对齐图像中的手势几何特征与语言指令
        for epoch in range(epochs):
            for image, question, answer in dataset:
                # 提取视觉与文本特征
                visual_features = self.model.encode_image(image)
                text_features = self.model.encode_text(question)

                # 自回归生成与损失计算
                predictions = self.model.generate(visual_features, text_features)
                loss = compute_cross_entropy_loss(predictions, answer)

                # 反向传播更新权重，纠正“指代幻觉”
                loss.backward()
                self.model.optimizer.step()
                
        return self.model

    def evaluate_sim_to_real(self, real_world_test_set):
        # 在真实世界采集的基准上评估模型的泛化能力
        metrics = self.model.evaluate(real_world_test_set)
        return metrics
```

### 第二模块：核心架构解释

FingerViP 的核心架构是一个端到端的视觉运动策略（Visuomotor Policy），其数据流从多源传感器输入，经过特征对齐与融合，最终通过扩散模型输出动作序列。

**1. 硬件与感知输入层**
系统接收两种视觉输入：一个第三人称全局相机图像，以及 $N$ 个安装在指尖的微型相机提供的局部多视角图像。同时，系统实时读取机械臂和灵巧手的本体感觉数据（Proprioception），包括指尖相机的空间位姿（Pose）和各个手指关节的电流值（Current，作为接触力的隐式表征）。

**2. 特征提取与对齐层（核心创新）**
全局图像和指尖图像分别通过视觉编码器（如 ResNet 或 ViT）提取特征。为了让模型理解“这个局部画面是在什么位置、受多大力的状态下看到的”，算法将每个指尖的视觉特征向量，与其对应的相机位姿编码、关节电流编码进行拼接（Concatenation）。这一步实现了视觉与本体感觉的强对齐。

**3. 扩散策略层（Diffusion Policy）**
将全局视觉特征、增强后的指尖多模态特征以及当前的本体感觉状态拼接成一个全局条件向量（Condition）。该条件向量被输入到一个基于 1D-CNN 或 Transformer 的去噪网络中。网络通过多步去噪过程，从纯噪声中逐步生成未来 $H$ 步的动作序列（包括机械臂的 6-DoF 动作和灵巧手的多关节角度）。

```python
class FingerViP_Policy(nn.Module):
    def __init__(self, num_fingers=4):
        super().__init__()
        self.num_fingers = num_fingers
        # 视觉编码器
        self.global_vision_encoder = VisionEncoder()
        self.fingertip_vision_encoder = VisionEncoder()

        self.pose_encoder = MLP(input_dim=6, output_dim=64)

    def forward(self, global_img, fingertip_imgs, fingertip_poses, joint_currents, noisy_actions, diffusion_timesteps):
        """
        global_img: [B, C, H, W]
        fingertip_imgs: [B, N, C, H, W]
        fingertip_poses: [B, N, 6]
        joint_currents: [B, N, 1]
        noisy_actions: [B, Horizon, Action_Dim]
        """
        B, N = fingertip_imgs.shape[:2]
        
        # 1. 提取全局视觉特征
        global_feat = self.global_vision_encoder(global_img) # [B, D_vis]
        
        # 2. 提取并增强指尖特征
        enhanced_fingertip_feats = []
        for i in range(self.num_fingers):
            # 视觉特征
            vis_feat = self.fingertip_vision_encoder(fingertip_imgs[:, i]) # [B, D_vis]
            # 位姿与电流特征
            pose_feat = self.pose_encoder(fingertip_poses[:, i])           # [B, 64]
            current_feat = self.current_encoder(joint_currents[:, i])      # [B, 32]
            
            # 核心：视角-本体感觉对齐
            f_feat = torch.cat([vis_feat, pose_feat, current_feat], dim=-1)
            enhanced_fingertip_feats.append(f_feat)
            
        # 聚合所有指尖特征
        fingertip_feat_all = torch.cat(enhanced_fingertip_feats, dim=-1)
        
        # 3. 构建全局条件向量
        condition = torch.cat([global_feat, fingertip_feat_all], dim=-1)
        
        # 4. 预测噪声 (Diffusion Forward)
        predicted_noise = self.noise_pred_net(
            sample=noisy_actions, 
            timestep=diffusion_timesteps, 
            global_cond=condition
        )
        
        return predicted_noise
```

本论文的模型架构与实验流程可以解构为三个核心阶段：数据重构、自回归生成与偏好对齐。

**1. 数据重构阶段 (Language Annotation Refinement)**
这是一个离线过程。作者提取训练集中的前视图像，并结合真实的 XY 轨迹图和 Z 轴高程剖面图作为辅助提示（Auxiliary Cues），输入给 Gemini 模型。Gemini 会结合场景检索（寻找相似曲率和坡度的历史场景）进行标准化，输出一段精确描述“动作+地形”的重构文本。

**3. 偏好优化阶段 (Geometry-Aware ORPO)**
为了让模型理解地形，作者构建了偏好对（Preference Pairs）。对于同一张图像和重构文本：
- Chosen (正样本)：真实的 3D 轨迹。
- Rejected (负样本)：从同一场景的轨迹池中检索出的“难负样本”。其特点是 XY 平面轨迹与真实轨迹极度相似，但 Z 轴高程变化完全错误（例如真实是上坡，负样本是平地）。
随后使用 ORPO（Odds Ratio Preference Optimization）算法进行无需参考模型的偏好对齐。

```python
import torch.nn.functional as F

def geometry_aware_hard_negative_mining(gt_trajectory, trajectory_pool, lambda_geo=1.0):
    """
    核心创新：挖掘 XY 相似但 Z 轴相反的难负样本
    """
    best_score = -float('inf')
    hard_negative = None
    
    for cand_traj in trajectory_pool:
        # 计算 Z 轴差异 (越大越好，说明高程行为相反)
        z_diff = torch.abs(cand_traj.z - gt_trajectory.z).mean()
        # 计算 XY 平面差异 (越小越好，说明平面路径相似，具有迷惑性)
        xy_diff = torch.norm(cand_traj.xy - gt_trajectory.xy, dim=-1).mean()
        
        # 差异感知打分函数 (公式 5)
        score = z_diff - lambda_geo * xy_diff
        
        if score > best_score:
            best_score = score
            hard_negative = cand_traj
            
    return hard_negative

    odds_rejected = compute_odds(rejected_logits)
    log_odds_ratio = torch.log(F.sigmoid(torch.log(odds_chosen) - torch.log(odds_rejected)))
    loss_odds = -log_odds_ratio.mean()
```

```python
    def __init__(self, primitive_library):
        # primitive_library 包含动作的前置条件(pre)和后置条件(post)
        self.primitives = primitive_library 
        self.current_state = None

    def perception_front_end(self, frame):

        detections = foundation_model.detect(frame)

        relations = compute_geometric_relations(detections)
        roles = assign_functional_roles(relations)
        affordances = get_object_affordances(detections)

        state_Sk = {
            'predicates': relations.types,
            'confidences': relations.scores,
            'roles': roles,
            'affordances': affordances
        }
        return state_Sk

    def reason_and_predict(self, state_Sk):
        best_score = 0
        inferred_action = None
        
        # 3. 评估所有候选动作的前置条件满足度
        for action in self.primitives:
            score = self.evaluate_preconditions(action.pre, state_Sk)
            if score > best_score and score >= THRESHOLD_FEASIBILITY:
                best_score = score
                inferred_action = action
                
        # 4. 应用后置条件预测未来状态与下一步动作
        if inferred_action:
            predicted_next_state = self.apply_postconditions(inferred_action.post, state_Sk)
            next_action = self.predict_next(predicted_next_state)
            explanation = self.generate_explanation(inferred_action, state_Sk)
            return inferred_action, next_action, explanation
            
        return None, None, None

    def evaluate_preconditions(self, preconditions, state):
        # 计算置信度加权的满足得分 (公式 20)
        score = 0
        for condition in preconditions:
            if condition in state['predicates']:
                score += state['confidences'][condition]
        return score / len(preconditions)
```

### 第二模块：核心架构解释

MISTY 的核心架构摒弃了耗时的自回归或多步扩散过程，转而采用“编码-压缩-单步解码”的范式，并将复杂的物理与逻辑约束前置到训练阶段的损失函数中。

**1. 环境上下文编码 (Environment Encoding)**
采用矢量化子图编码器（Vectorized Sub-Graph encoder）处理异构的驾驶环境数据（包括地图拓扑、自车状态、他车历史轨迹等），提取出高维的环境上下文特征。

**2. 轨迹流形压缩 (Trajectory Compression via VAE)**
在训练阶段，使用变分自编码器（VAE）将高维的专家轨迹数据压缩到一个紧凑的 32 维潜在流形（Latent Manifold）中。这一步极大地降低了后续生成任务的维度复杂性。

**3. 轻量级单步解码 (Single-step Decoding via MLP-Mixer)**
推理阶段，模型接收环境特征，直接通过一个超轻量级的 MLP-Mixer 解码器预测潜在空间中的轨迹表征。MLP-Mixer 通过交替的 Token-mixing 和 Channel-mixing 提取特征，彻底消除了 Transformer 架构中注意力机制的二次方计算复杂度。最后通过 VAE 的解码器将 32 维特征还原为物理空间的具体轨迹。

**4. 潜在空间漂移训练 (Latent-space Drifting Training)**
这是 MISTY 的核心创新。在训练时，除了常规的重建损失，模型在潜在空间中引入了漂移损失（Drifting Loss）：
- **引力 (Attractive Force)**：拉动生成的潜在特征靠近专家演示的潜在特征。
- **斥力 (Repulsive Force)**：推动生成的潜在特征远离碰撞区域或不符合运动学约束的危险状态。

**Python 风格伪代码（核心逻辑）：**

```python
import torch
import torch.nn as nn

class MISTY(nn.Module):
    def __init__(self):
        super().__init__()
        self.env_encoder = VectorizedSubGraphEncoder()
        self.vae = TrajectoryVAE(latent_dim=32)
        self.mlp_mixer = MLPMixerDecoder(input_dim=env_feature_dim, output_dim=32)
        
    def forward(self, env_data):
        # 推理阶段：纯单步生成
        # 1. 编码环境
        env_features = self.env_encoder(env_data)
        # 2. MLP-Mixer 单步预测潜在特征
        pred_latent = self.mlp_mixer(env_features)
        # 3. VAE 解码为物理轨迹
        pred_trajectory = self.vae.decode(pred_latent)
        return pred_trajectory

    def compute_loss(self, env_data, expert_trajectory, obstacle_data):
        # 训练阶段：包含漂移损失
        env_features = self.env_encoder(env_data)
        
        # VAE 编码专家轨迹
        expert_latent, mu, logvar = self.vae.encode(expert_trajectory)
        
        # 模型预测潜在特征
        pred_latent = self.mlp_mixer(env_features)
        pred_trajectory = self.vae.decode(pred_latent)
        
        # 1. 基础重建损失 (VAE KL + 轨迹 MSE)
        recon_loss = mse_loss(pred_trajectory, expert_trajectory)
        kl_loss = compute_kl_divergence(mu, logvar)
        
        # 2. 潜在空间漂移损失 (Drifting Loss)
        # 引力：向专家特征靠拢
        attractive_force = mse_loss(pred_latent, expert_latent.detach())
        
        # 斥力：远离碰撞/危险状态 (基于解码后的轨迹计算物理惩罚，梯度回传至潜在空间)
        collision_penalty = compute_collision_penalty(pred_trajectory, obstacle_data)
        kinematic_penalty = compute_kinematic_violation(pred_trajectory)
        repulsive_force = collision_penalty + kinematic_penalty
        
        total_loss = recon_loss + kl_loss + attractive_force + repulsive_force
        return total_loss
```

### 第二模块：核心架构解释

当前论文的模型架构是一个典型的“编码-对齐-推理-解码”流水线，其核心在于如何将多模态的连续物理特征无损地“欺骗”并输入给只懂文本的冻结 LLM。

**1. 场景编码器 (Scene Encoder):**
将自车与周边车辆的历史轨迹坐标转换为相对位移向量，通过交叉注意力机制（Cross-Attention）提取车辆间的动态交互特征。

**2. 地图编码器 (Map Encoder):**
截取以自车为中心的局部高精地图（HD Map）栅格图像，使用轻量级 CNN 提取静态道路拓扑特征。

**3. 特征融合模块 (Feature Fusion Module):**
将动态轨迹特征作为 Query，静态地图特征作为 Key 和 Value 进行交叉注意力计算，随后将输出与原轨迹特征拼接并进行线性映射，得到统一的时空场景特征。

**4. 重编程适配器 (Reprogramming Adapter):**
本质是一个线性投影层，将融合后的时空特征维度对齐到特定 LLM（如 LLaMA3）的词嵌入维度（Token Embedding Space），使其伪装成 LLM 可以处理的输入。

**5. 冻结的 LLM 与线性解码器 (Frozen LLM & Linear Decoder):**
将任务描述的 Prompt Token 与伪装好的 Scene Token 拼接，输入参数完全冻结的 LLM。LLM 输出的隐藏状态被展平后，直接通过一个简单的线性矩阵乘法（Linear Decoder）映射为未来 $N$ 个时间步的二维坐标。

**核心逻辑伪代码 (Python 风格):**

```python
import torch
import torch.nn as nn

class MapAwareLLMTrajectoryPredictor(nn.Module):
    def __init__(self, frozen_llm, llm_dim, pred_steps=12):
        super().__init__()
        # 1. 编码器
        self.scene_encoder = CrossAttentionTrajectoryEncoder()
        self.map_encoder = LightweightCNNMapEncoder()
        
        # 2. 融合与重编程
        self.fusion_cross_attn = nn.MultiheadAttention(embed_dim=feature_dim)
        self.fusion_linear = nn.Linear(feature_dim * 2, feature_dim)
        self.reprogram_adapter = nn.Linear(feature_dim, llm_dim)
        
        # 3. 冻结的 LLM (不参与梯度更新)
        self.frozen_llm = frozen_llm
        for param in self.frozen_llm.parameters():
            param.requires_grad = False
            
        # 4. 极简线性解码器
        self.linear_decoder = nn.Linear(seq_len * llm_dim, pred_steps * 2)

    def forward(self, ego_traj, neighbor_traj, local_hd_map, task_prompt_tokens):
        # 提取动态交互特征
        h_traj = self.scene_encoder(ego_traj, neighbor_traj) 
        
        # 提取静态地图特征
        h_map = self.map_encoder(local_hd_map) 
        
        # 轨迹与地图的交叉注意力融合
        h_map_attended, _ = self.fusion_cross_attn(query=h_traj, key=h_map, value=h_map)
        h_fused = self.fusion_linear(torch.cat([h_map_attended, h_traj], dim=-1))
        
        # 重编程：将物理特征映射为 LLM Token 维度
        scene_tokens = self.reprogram_adapter(h_fused) 
        
        # 拼接 Prompt 与场景 Tokens
        llm_input = torch.cat([task_prompt_tokens, scene_tokens], dim=1)
        
        # 冻结 LLM 推理
        llm_hidden_states = self.frozen_llm(llm_input) 
        
        # 极简解码：防止解码器抢占 LLM 的推理工作
        flattened_states = torch.flatten(llm_hidden_states, start_dim=1)
        pred_traj = self.linear_decoder(flattened_states)
        
        # 重塑为 (Batch, Pred_Steps, 2) 的轨迹坐标
        return pred_traj.view(-1, self.pred_steps, 2)
```

### 第二模块：核心架构解释

该研究的核心架构并非提出新的底层神经网络，而是构建了一个基于 LLM 的人机交互（HRI）系统工作流，并将其嵌入到特定的社会化实验（挑战赛）中。其系统流程如下：

1. **输入层（User Input）**：非专业用户通过自然语言（语音）向人形机器人下达指令。
2. **感知与解析层（Perception & Parsing）**：语音信号通过 STT（Speech-to-Text）转化为文本，随后输入到 LLM 中。LLM 充当高层控制器，根据预设的 Prompt（包含当前环境上下文和机器人可用技能库），解析用户意图。
3. **动作映射层（Action Mapping）**：LLM 将非结构化的自然语言意图映射为机器人底层控制系统可识别的结构化指令序列（如移动、抓取等）。
4. **执行层（Execution）**：人形机器人在物理环境（物流模拟场景）中执行动作。

以下是该 LLM 控制框架底层逻辑的 Python 风格伪代码：

```python
class LLMAwarenessFramework:
    def __init__(self, llm_backend, robot_interface):
        self.llm = llm_backend
        self.robot = robot_interface
        # 预定义机器人在物流场景中的原子技能库
        self.skill_library = {
            "move_to": "Navigate to a specific zone",
            "pick_object": "Grasp the target object",
            "place_object": "Release the object at current location",
            "greet": "Perform a friendly greeting gesture"
        }
        
    def process_user_command(self, audio_stream):
        # 1. 语音识别
        user_text = speech_to_text(audio_stream)
        
        # 2. 构建系统提示词，约束 LLM 输出
        system_prompt = f"""
        You are the high-level controller for a humanoid robot in a logistics task.
        User command: '{user_text}'
        Available skills: {list(self.skill_library.keys())}
        Task: Map the user command to a sequence of available skills.
        Constraint: Output ONLY a valid JSON list of skill names.
        """
        
        # 3. LLM 意图解析与任务规划
        action_plan_json = self.llm.generate(system_prompt)
        action_sequence = parse_json(action_plan_json)
        
        # 4. 动作执行与安全校验
        for action in action_sequence:
            if action in self.skill_library:
                success = self.robot.execute_skill(action)
                if not success:
                    self.robot.speak("Execution failed due to physical constraints.")
                    break
            else:
                self.robot.speak("I do not understand or cannot perform this action.")
```
