### 第二模块：核心架构解释

WA-JEPA 的核心架构分为两个训练阶段，旨在将一个视频表征模型改造为自动驾驶的规划大脑：

**阶段一：混合未来掩码预训练 (Stage 1)**
模型接收多视角历史帧和未来帧。历史帧通过在线编码器（Online Encoder）提取为可见的上下文 Token。未来帧则应用“混合掩码”（全掩码或块掩码），仅保留部分或不保留可见信息。目标是通过条件流匹配（Flow Matching），让预测器根据历史上下文和加噪的未来 Token，去噪并预测出由 EMA 目标编码器（Target Encoder）提取的干净未来特征。此阶段不引入动作监督，纯粹学习因果时空动态。

**阶段二：联合世界-动作建模 (Stage 2)**
在阶段一的基础上引入自车动作流。此时强制使用全掩码（符合因果预测逻辑）。模型将历史动作、自车状态以及加噪的未来动作编码为动作 Token。联合预测器（Joint Predictor）在统一的架构下，同时对未来场景 Token 和未来动作 Token 进行流匹配去噪。关键设计是：场景预测分支在交叉注意力时对动作 Token 使用了梯度截断（Stop-gradient），防止场景重建的损失干扰动作流的更新，同时允许动作监督信号反向传播去塑造规划相关的世界表征。

```python
    # 1. 编码历史上下文 (Online Encoder)
    z_ctx = online_encoder(history_frames)
    
    # 2. 获取干净的未来目标特征 (EMA Target Encoder, 停止梯度)
    with torch.no_grad():
        z_future_target = ema_encoder(future_frames)

    if stage == 1:
        mask = sample_hybrid_mask() # 混合掩码 (Full or Patch)

        mask = full_mask() # 阶段二仅使用全掩码 (Causal)
    z_cond = apply_mask_and_encode(online_encoder, future_frames, mask)
    
    # 4. 场景特征的流匹配加噪
    t_scene = sample_time()
    noise_scene = sample_gaussian_like(z_future_target)
    z_t_scene = (1 - t_scene) * noise_scene + t_scene * z_future_target
    
    if stage == 1:
        # 仅预测未来场景特征
        z_future_pred = scene_predictor(z_ctx, z_cond, z_t_scene, t_scene)
        loss_scene = mse_loss(z_future_pred, z_future_target)
        return loss_scene
        
    elif stage == 2:
        # 5. 动作特征的流匹配加噪
        t_act = sample_time()
        norm_future_actions = normalize(future_actions)
        noise_act = sample_gaussian_like(norm_future_actions)
        act_t = (1 - t_act) * noise_act + t_act * norm_future_actions
        
        # 编码动作 Token
        t_act_tokens = encode_actions(act_t, history_actions, ego_state)
        
        # 6. 联合预测 (Joint Predictor)
        # 注意：对动作 Token 应用 stop_gradient 以防止场景 loss 干扰动作流
        z_future_pred, act_pred = joint_predictor(
            z_ctx, 
            z_cond, 
            z_t_scene, 
            t_scene, 
            t_act_tokens.detach(), # Stop-gradient
            t_act
        )
        
        # 7. 计算联合损失
        loss_scene = mse_loss(z_future_pred, z_future_target)
        loss_act = mse_loss(act_pred, norm_future_actions)
        
        return lambda_scene * loss_scene + lambda_act * loss_act
```

### 第二模块：核心架构解释

PhysCaP 的核心逻辑是将**主动感知（Active Perception）**无缝嵌入到大语言模型驱动的代码生成流程中。其运行流程分为决策、探索、提取、执行四个阶段：

1. **双智能体决策阶段**：接收视觉观察和语言指令后，**规划器（Planner）**首先判断当前任务是否需要额外的物理信息。如果需要，**优先级排序器（Prioritizer）**会生成一系列候选的探索动作，过滤掉物理上不可行或不合理的动作，并基于启发式分数对剩余动作进行排序。
2. **主动探索阶段**：机器人执行排名最高的探索动作（如推压、试探性抓取）。
3. **物理属性提取阶段**：在执行探索动作的过程中，**免训练物理属性提取模块**收集机器人的本体感觉数据（如关节扭矩、末端执行器反馈），通过物理公式直接计算出目标物体的质量（Mass）或刚度（Stiffness）。

### 第二模块：核心架构解释

RISE 框架建立在标准的“编码器-预测器-规划器”世界动作模型基础之上，其核心工作流程如下：

**1. 状态编码与初始评估**
系统首先通过冻结的视觉编码器（V-JEPA 2）将历史观测图像转换为潜在特征表示。此时推演深度为零。

**2. 序列化自适应推演 (Scheduler)**
这是一个循环决策过程。在当前的推演深度下，潜在评估器（Latent Evaluator）接收已生成的潜在前缀，预测两个关键指标：
- 风险配置（Risk Profile）：当前前缀已经暴露的轨迹风险。
- 未来规划收益配置（Future Planning Gain Profile）：如果继续推演，预期的规划得分能提升多少。

推演门控（Rollout Gate）将预期的规划收益与预设的计算成本权重进行比较。如果收益大于成本，则输出 ROLL 决策；如果收益不足以弥补计算成本，或已达到最大推演深度，则输出 STOP 决策。

**3. 动态预测与特征更新**
如果门控决定 ROLL，自回归预测器（Predictor）结合自车运动条件，生成下一步的未来潜在特征，将其加入前缀中，并返回步骤 2 重新评估。

**4. 风险引导微调与最终规划**
当门控决定 STOP 时，系统停止推演。如果推演深度大于零，系统会利用潜在评估器冻结的风险预测分支，对当前的潜在前缀进行基于梯度的风险引导微调（Risk-guided latent refinement），以降低累积的预测风险。最后，扩散规划器（Planner）基于微调后的潜在前缀和历史状态，生成最终的自车未来轨迹。

**5. 反事实数据监督 (CounterDrive)**
为了训练潜在评估器准确感知风险，作者构建了 CounterDrive 数据集。利用视觉语言模型（Wan 2.7）基于真实驾驶关键帧生成包含碰撞等危险结果的反事实视频，为模型提供真实日志中缺失的局部风险排序监督信号。

```python
        z_future_pred = scene_predictor(z_ctx, z_cond, z_t_scene, t_scene)
        loss_scene = mse_loss(z_future_pred, z_future_target)
        return loss_scene
        
    elif stage == 2:
        # 5. 动作特征的流匹配加噪
        t_act = sample_time()
        norm_future_actions = normalize(future_actions)
        noise_act = sample_gaussian_like(norm_future_actions)
        act_t = (1 - t_act) * noise_act + t_act * norm_future_actions
        
        # 编码动作 Token
        t_act_tokens = encode_actions(act_t, history_actions, ego_state)
        
        # 6. 联合预测 (Joint Predictor)
        # 注意：对动作 Token 应用 stop_gradient 以防止场景 loss 干扰动作流
        z_future_pred, act_pred = joint_predictor(
            z_ctx, 
            z_cond, 
            z_t_scene, 
            t_scene, 
            t_act_tokens.detach(), # Stop-gradient
            t_act
        )
        
        # 7. 计算联合损失
        loss_scene = mse_loss(z_future_pred, z_future_target)
        loss_act = mse_loss(act_pred, norm_future_actions)
        
        return lambda_scene * loss_scene + lambda_act * loss_act
```

系统首先通过冻结的视觉编码器（V-JEPA 2）将历史观测图像转换为潜在特征表示。此时推演深度为零。

**2. 序列化自适应推演 (Scheduler)**
这是一个循环决策过程。在当前的推演深度下，潜在评估器（Latent Evaluator）接收已生成的潜在前缀，预测两个关键指标：
- 风险配置（Risk Profile）：当前前缀已经暴露的轨迹风险。
- 未来规划收益配置（Future Planning Gain Profile）：如果继续推演，预期的规划得分能提升多少。

推演门控（Rollout Gate）将预期的规划收益与预设的计算成本权重进行比较。如果收益大于成本，则输出 ROLL 决策；如果收益不足以弥补计算成本，或已达到最大推演深度，则输出 STOP 决策。

**3. 动态预测与特征更新**
如果门控决定 ROLL，自回归预测器（Predictor）结合自车运动条件，生成下一步的未来潜在特征，将其加入前缀中，并返回步骤 2 重新评估。

**4. 风险引导微调与最终规划**
当门控决定 STOP 时，系统停止推演。如果推演深度大于零，系统会利用潜在评估器冻结的风险预测分支，对当前的潜在前缀进行基于梯度的风险引导微调（Risk-guided latent refinement），以降低累积的预测风险。最后，扩散规划器（Planner）基于微调后的潜在前缀和历史状态，生成最终的自车未来轨迹。

**5. 反事实数据监督 (CounterDrive)**
为了训练潜在评估器准确感知风险，作者构建了 CounterDrive 数据集。利用视觉语言模型（Wan 2.7）基于真实驾驶关键帧生成包含碰撞等危险结果的反事实视频，为模型提供真实日志中缺失的局部风险排序监督信号。

**核心推理逻辑伪代码：**

```python
def rise_inference(observation, ego_history, ego_kinematics, max_horizon, cost_weight):
    # 1. 编码当前观测
    z_t = encoder(observation)
    z_prefix = []
    h = 0
    
    # 2. 序列化自适应推演循环
    while h < max_horizon:
        # 评估当前前缀的风险与预期收益
        risk_profile, gain_profile = latent_evaluator(z_t, z_prefix)
        
        # 构建门控输入特征
        gate_input = construct_gate_features(z_t, z_prefix, risk_profile, gain_profile, h, cost_weight)
        
        # 门控输出二元决策
        roll_decision = rollout_gate(gate_input)
        
        if roll_decision <= 0: # 决策为 STOP
            break
            
        # 决策为 ROLL，预测下一步潜在特征
        z_next = predictor(z_t, z_prefix, ego_history)
        z_prefix.append(z_next)
        h += 1
        
    # 3. 风险引导的潜在特征微调
    if h > 0:
        z_prefix_refined = risk_refine(z_t, z_prefix, latent_evaluator)
    else:
        z_prefix_refined = []
        
    # 4. 最终轨迹规划
    trajectory = planner(z_t, z_prefix_refined, ego_history, ego_kinematics)
    
    return trajectory
```

### 第二模块：核心架构解释

ForeTime-VLA 的核心架构分为离线教师构建、在线学生训练以及双路条件注入三个核心流程。

**1. 离线动作等效未来教师 (Offline Teacher)**
系统首先利用冻结的 Wan2.2 视频 VAE 提取当前帧和 8 个未来帧的视觉特征。随后，一个非坍缩的适配器（Adapter）接收当前特征、未来特征和机器人本体状态，将其压缩并白化为一个 64 维的教师特征向量 $z_t^T$。该向量包含了未来轨迹信息，并在训练后被缓存，推理时完全丢弃视频 VAE 和未来帧。

**2. 因果时间学生网络 (Causal Temporal Student)**
部署时的学生网络仅接收 8 帧因果历史数据（包含 26 维本体状态和 12 维辅助相机视觉统计量）。通过一个轻量级的两层残差 MLP，预测出三个关键变量：压缩的未来状态 $\hat{z}_t$（逼近教师特征）、操作阶段的分类 Logits（如接近、抓取、运输）以及归一化的状态过渡时间 $\hat{d}_t$。

**3. 双路条件注入 (Dual-Path Conditioning)**
预测出的时空变量被拆分注入到 $\pi_{0.5}$ 架构中：
- 慢速 VLM 路径：将 $\hat{z}_t$ 映射为 4 个 Token，结合 1 个操作阶段 Token，追加到 VLM 的前缀中。
- 快速动作专家路径：将 $\hat{z}_t$ 和 $\hat{d}_t$ 映射为残差条件，注入到动作专家的每一个后缀 Token 及其自适应归一化层中。

```python
    # history_states: [8, 26], history_visual_stats: [8, 12]
    temporal_embeds = learned_temporal_embeddings()
    
    # Process history
    e_i = swish(W_s(LayerNorm(history_states))) + swish(W_v(LayerNorm(history_visual_stats))) + temporal_embeds
    q = swish(W_p(flatten(e_i)))
    h_t = LayerNorm(swish(W_o(q)) + q)
    
    # 2. Predict Future, Phase, and Time-to-Transition
    z_hat_t = linear_future_head(h_t) # [64-D] Predicted future code
    phase_logits = linear_phase_head(h_t) # [4-D] Manipulation phase
    d_hat_t = sigmoid(linear_time_head(h_t)) # [1-D] Time-to-transition
    
    # 3. Dual-Path Conditioning Preparation
    # Slow Path (VLM)
    future_tokens = project_to_vlm_dim(z_hat_t) # 4 tokens
    phase_token = expected_embedding(softmax(phase_logits)) # 1 token
    vlm_prefix_extension = concat([future_tokens, phase_token])
    
    # Fast Path (Action Expert)
    fast_residual_condition = project_to_expert_dim(concat([z_hat_t, d_hat_t]))
    
    # 4. Base pi_0.5 Execution with Injected Conditions
    # VLM processes image and language + new prefix
    vlm_features = pi_0_5_model.vlm_forward(current_image, language_instruction, prefix_extension=vlm_prefix_extension)
    
    # Flow-matching action expert generates action chunk
    action_chunk = pi_0_5_model.action_expert_forward(
        vlm_features, 
        residual_condition=fast_residual_condition
    )
    
    return action_chunk
```

### 第二模块：核心架构解释

GraphOp-WM 的核心逻辑在于**信息隔离**与**结构化转移**。模型将机器人建模为属性图（节点为刚体，边为关节/执行器），其前向预测流程如下：

1. **动态状态编码（无形态信息）**：编码器仅接收局部的动态状态（位置、速度、接触力）和动作，生成节点特征。此过程严格屏蔽质量、长度等静态形态参数。
2. **局部动力学基预测**：基于上述节点特征，预测一个无约束的候选增量矩阵 $\bar{B}_t$，并进行归一化。这代表了不受具体形态影响的通用物理运动趋势。
3. **结构化形态算子生成**：形态编码器仅接收静态图属性（质量、几何尺寸等），生成节点系数、边系数和全局模式。结合当前状态的门控机制，构建一个包含对角阵（局部响应）、关联矩阵（运动学树耦合）和低秩矩阵（全局残差耦合）的转移算子 $A_{m,t}$。
4. **状态转移与读出**：将算子作用于动力学基（$Z_{t+1} = Z_t + A_{m,t}\bar{B}_t$）得到下一状态。随后通过图级读出机制（Graph-level readout）聚合全局特征，用于预测奖励和价值，支持 TD-MPC 风格的规划。

```python
import torch.nn as nn

class GraphOpWM(nn.Module):
    def __init__(self):
        super().__init__()
        self.dynamic_encoder = DynamicNodeEncoder() # No static morphology input
        self.local_basis_net = LocalBasisNetwork()
        self.morphology_encoder = StaticGraphEncoder() # Only static attributes
        self.readout = GraphReadout()
        
    def forward(self, dynamic_state, action, static_graph):
        # 1. Encode dynamic state tokens (Z_t)
        Z_t = self.dynamic_encoder(dynamic_state)
        
        # 2. Predict and normalize morphology-independent local basis (B_bar_t)
        B_t = self.local_basis_net(Z_t, action)
        B_bar_t = B_t / (torch.norm(B_t, p='fro') + 1e-6)
        
        # 3. Generate structured morphology operator (A_m,t)
        # Extract coefficients from static graph
        d_m, w_m, U_m, s_m = self.morphology_encoder(static_graph)
        
        # Apply state-dependent gating (Eq 15-17)
        d_gated = d_m * torch.tanh(self.gate_d(Z_t))
        w_gated = w_m * torch.tanh(self.gate_w(Z_t))
        s_gated = s_m * torch.tanh(self.gate_s(self.readout(Z_t)))
        
        # Construct Operator components (Eq 18)
        I = torch.eye(Z_t.size(0))
        E_m = static_graph.incidence_matrix
        
        term_local = torch.diag(d_gated)
        term_tree = E_m @ torch.diag(w_gated) @ E_m.T
        term_global = U_m @ torch.diag(s_gated) @ U_m.T
        
        A_mt = I + term_local + term_tree + term_global
        
        # 4. Predict next state transition (Eq 19)
        Z_next = Z_t + A_mt @ B_bar_t
        
        return Z_next
```

### 第二模块：核心架构解释

Logic-VLA 的核心架构建立在预训练的流匹配 VLA（如 $\pi_{0.5}$）之上，通过引入一个独立的逻辑处理分支和两阶段的后训练范式，实现对复杂逻辑的遵循。

**1. 逻辑编码器预训练 (Logic Encoder Pre-training)**
将 STL 公式解析为有向语法图（节点为操作符/谓词，边为逻辑关系）。使用 GCN 提取图特征。为了让编码器理解物理意义，使用轨迹数据进行预训练：输入轨迹和公式图，让编码器预测该轨迹满足该公式的“鲁棒语义”（Robust Semantics，即满足或违反的连续程度）。

**2. 阶段一：条件监督微调 (Stage 1: STL-Conditioned SFT)**
将预训练好的逻辑特征投影为 Token，拼接到 VLA 的视觉和语言 Prompt 之后。筛选出满足 STL 约束的优质轨迹数据（正样本），对 VLA 进行标准的条件流匹配（Flow-Matching）监督微调，让模型初步学会“在特定逻辑下应该怎么做”。

**3. 阶段二：轨迹级偏好优化 (Stage 2: Trajectory-level Preference Optimization)**
构建正负样本对：同一任务、相似初始状态下，一条轨迹满足逻辑（正样本），另一条违反逻辑（负样本）。由于流匹配模型难以直接计算动作似然，作者采用流匹配损失（Flow-matching loss）的差值作为对数似然比的替代。在整条轨迹的时间窗口上聚合这些损失，执行 IPO（Identity Preference Optimization），迫使模型在生成动作时拉开正负样本的得分差距。

**核心伪代码实现逻辑：**

```python
# 核心逻辑：Logic-VLA 两阶段后训练伪代码

def pretrain_logic_encoder(formula_graph, trajectory):
    # 预训练逻辑编码器，使其理解逻辑的物理满足度
    graph_features = GCN(formula_graph)
    logic_embedding = MeanPool(graph_features)
    traj_embedding = TrajectoryEncoder(trajectory)
    
    # 预测鲁棒语义 (连续的满足度分数)
    predicted_semantics = MLP(logic_embedding, traj_embedding)
    true_semantics = compute_robust_semantics(formula_graph, trajectory)
    
    loss_pretrain = HuberLoss(predicted_semantics, true_semantics)
    return loss_pretrain, logic_embedding

def stage1_sft(vla_model, logic_encoder, positive_demos):
    # 阶段一：只用正样本进行监督微调
    for obs, lang_task, formula, action in positive_demos:
        logic_tokens = logic_encoder(formula)
        # 将逻辑 token 拼接到视觉和语言输入中
        condition = concat(obs, lang_task, logic_tokens)
        
        # 标准流匹配损失
        loss_sft = flow_matching_loss(vla_model, action, condition)
        loss_sft.backward()

def stage2_preference_optimization(vla_model, ref_model, pref_pairs, margin_beta, target_c):
    # 阶段二：轨迹级偏好优化 (IPO)
    for pair in pref_pairs:
        obs, lang_task, formula = pair.context
        traj_pos, traj_neg = pair.positive_traj, pair.negative_traj
        
        logic_tokens = logic_encoder(formula)
        condition = concat(obs, lang_task, logic_tokens)
        
        # 计算当前模型和参考模型在正负轨迹上的流匹配损失 (作为似然的替代)
        # 聚合整条轨迹的损失
        loss_pos_curr = aggregate_fm_loss(vla_model, traj_pos, condition)
        loss_neg_curr = aggregate_fm_loss(vla_model, traj_neg, condition)
        
        loss_pos_ref = aggregate_fm_loss(ref_model, traj_pos, condition)
        loss_neg_ref = aggregate_fm_loss(ref_model, traj_neg, condition)
        
        # 计算相对偏好得分 (损失越小，得分越高)
        score_pos = loss_pos_ref - loss_pos_curr
        score_neg = loss_neg_ref - loss_neg_curr
        
        # IPO 损失：优化正负样本的得分差距到一个有限的 target_c
        preference_margin = margin_beta * (score_pos - score_neg)
        loss_ipo = HuberLoss(preference_margin - target_c)
        
        # 锚点正则化：防止模型为了拉开差距而把正样本也变差
        anchor_loss = max(0, loss_pos_curr - stop_gradient(loss_pos_ref))
        
        total_loss = loss_ipo + lambda * anchor_loss
        total_loss.backward()
```

### 第二模块：核心架构解释

AURORA 框架的运行流程可拆解为四个连续的客观物理与计算步骤：

**1. 双视角感知 (Dual-View Perception):**
主车（Ego）和路端（RSU）分别通过独立的 3D 编码器处理多相机 RGB 图像。解码器分别输出各自坐标系下的动态目标检测查询（Detection Queries）和静态地图查询（Map Queries）。主车端还会额外生成与语言模型对齐的语义 Token。

**2. 跨视角查询对齐与融合 (CQAF):**
为了避免传输密集的点云或特征图，路端仅向主车传输轻量级的空间查询。
*   **DET-CQAF:** 利用路端到主车的外参矩阵，将路端检测查询的 3D 参考点转换到主车坐标系，拼接旋转矩阵后，通过基于距离的软分配和可学习的门控残差连接，将路端特征注入主车特征中。
*   **MAP-CQAF:** 过滤低置信度的路端地图查询，进行空间对齐后直接与主车地图查询拼接，以保留拓扑连续性。
*   **语义融合:** 使用融合后的空间查询作为 Key，通过交叉注意力机制更新主车的语义 Token。

**3. VLM 引导的生成式规划 (VLM-Guided Generative Planner):**
融合后的语义 Token 替代 VLM 的视觉占位符。VLM 结合文本提示（Prompt）进行推理，并在输出序列中生成一个专用的路点 Token `<wp>`。该 Token 的隐藏状态被提取出来，作为条件输入给下游的 VAE（变分自编码器）规划器，通过从高斯分布中采样潜变量来生成未来的行驶轨迹。

**4. 渐进式训练 (Progressive Training):**
模型分为五阶段训练：主车感知预训练 -> 路端感知预训练 -> 跨视角融合与 VLM 对齐 -> 轨迹规划器训练 -> 端到端联合微调。

**核心逻辑伪代码 (Python 风格):**

```python
def aurora_forward(ego_images, rsu_images, text_prompt, extrinsic_rsu2ego):
    # 1. Dual-View Perception
    ego_det_queries, ego_map_queries, ego_sem_tokens = ego_encoder_decoder(ego_images)
    rsu_det_queries, rsu_map_queries = rsu_encoder_decoder(rsu_images) # RSU only transmits queries
    
    # 2. Cross-View Query Alignment and Fusion (CQAF)
    # Align RSU detection queries to Ego frame
    aligned_rsu_det = transform_coordinates(rsu_det_queries, extrinsic_rsu2ego)
    
    # Gated residual fusion for dynamic agents
    gate = sigmoid(linear(ego_det_queries))
    fused_det_queries = ego_det_queries + gate * MLP(concat(ego_det_queries, aligned_rsu_det))
    
    # Concatenation for static map elements
    aligned_rsu_map = transform_coordinates(filter_confidence(rsu_map_queries), extrinsic_rsu2ego)
    fused_map_queries = concat(ego_map_queries, aligned_rsu_map)
    
    # Refine semantic tokens via cross-attention
    fused_det_tokens = cross_attention(query=ego_sem_tokens, key=fused_det_queries, value=fused_det_queries)
    fused_map_tokens = cross_attention(query=ego_sem_tokens, key=fused_map_queries, value=fused_map_queries)
    
    # 3. VLM Reasoning and Planning
    vlm_input_tokens = concat(fused_det_tokens, fused_map_tokens, tokenize(text_prompt))
    vlm_output = lora_vlm(vlm_input_tokens)
    
    # Extract hidden state of the dedicated waypoint token <wp>
    wp_hidden_state = extract_token_state(vlm_output, token_id="<wp>")
    
    # Generative VAE Planner
    latent_z = sample_gaussian(mu=0, sigma=1)
    predicted_trajectory = vae_decoder(wp_hidden_state, latent_z)
    
    return predicted_trajectory, vlm_output.text
```

**核心机制**: 训练一个轻量级估计器，在视觉特征空间中寻找“在不改变策略输出动作的前提下，能施加的最大特征扰动”。该扰动的幅值即为 Token 的“动作容忍度分数”，分数越高的 Token 越安全，优先被用于 KV-Cache 复用或直接剪枝。

**关键数据**:

### 第二模块：核心架构解释

Action-JND 框架的底层逻辑分为“离线训练”与“在线推理压缩”两个阶段。其核心思想是不改变原有 VLA 模型的权重，而是外挂一个轻量级网络来评估每个视觉 Token 对动作的敏感度。

1. **Action-JND 估计器训练阶段**：冻结预训练的 VLA 模型。将视觉 Token 输入到一个轻量级卷积网络（JND Estimator）中，输出与输入同维度的特征扰动。将原始特征与注入扰动后的特征分别送入 VLA 模型，得到两个动作输出。损失函数强制执行对抗博弈：既要最大化注入的扰动幅值，又要最小化两个动作输出之间的差异（如 KL 散度或 L1 距离）。
2. **动作容忍度分数计算阶段**：在实际推理时，不向特征中注入扰动。仅利用训练好的 JND Estimator 预测出扰动张量，计算其幅值（L2 范数）。幅值越大，代表该 Token 越能容忍改变而不影响动作，即“动作容忍度分数”越高。
3. **Token 压缩应用阶段**：将计算出的分数作为即插即用的排序信号。结合现有的压缩框架（如剔除高注意力区域后形成的候选池），按分数降序排列候选 Token。优先对分数最高的 Token 执行 KV-Cache 复用（调用上一帧缓存）或直接剪枝（物理移除）。

```python
# 伪代码：Action-JND 核心逻辑实现

def train_jnd_estimator(vla_policy, jnd_estimator, visual_tokens, text_tokens):
    """训练阶段：学习动作容忍度边界"""
    vla_policy.eval() # 冻结 VLA 策略
    
    # 1. 预测特征扰动并注入
    perturbation = jnd_estimator(visual_tokens)
    perturbed_tokens = visual_tokens + perturbation
    
    # 2. 获取原始动作与受扰动动作
    clean_action = vla_policy(visual_tokens, text_tokens)
    perturbed_action = vla_policy(perturbed_tokens, text_tokens)
    
    # 3. 计算损失：最大化扰动幅值，最小化动作差异
    action_diff = compute_action_distance(clean_action, perturbed_action)
    magnitude = compute_magnitude(perturbation)
    
    # lambda_act 和 lambda_mag 为平衡系数
    loss = lambda_act * action_diff - lambda_mag * magnitude 
    return loss

def inference_with_jnd_compression(vla_policy, jnd_estimator, visual_tokens, text_tokens, budget):
    """推理阶段：基于 JND 分数进行 Token 压缩"""
    # 1. 估计动作容忍度分数 (推理时不实际注入扰动)
    perturbation = jnd_estimator(visual_tokens)
    jnd_scores = compute_magnitude(perturbation) # 分数越高，越能容忍压缩
    
    # 2. 结合基础规则构建安全候选池 (例如：剔除历史高注意力 Token)
    candidate_pool_indices = get_safe_candidates(visual_tokens)
    
    # 3. 按 JND 分数降序排列候选者
    sorted_indices = sort_descending(candidate_pool_indices, keys=jnd_scores)
    
    # 4. 选取最安全的 Token 执行压缩 (剪枝)
    tokens_to_prune = sorted_indices[:budget]
    compressed_tokens = remove_tokens(visual_tokens, tokens_to_prune)
    
    # 5. 使用压缩后的 Token 生成动作
    final_action = vla_policy(compressed_tokens, text_tokens)
    return final_action
```

### 第二模块：核心架构解释

本论文的模型架构分为三个核心阶段：多模态特征交互、多轨迹生成、感知导向的轨迹微调。

1.  **多模态交互模块 (Multi-Modality Interaction)**
    *   **AGOT (亲和力引导的最优传输)**: 将 LiDAR BEV Token 和 Camera Visual Token 视为两个分布。通过计算两者的亲和力矩阵（Affinity Matrix）构建传输代价，利用 Sinkhorn 算法求解最优传输计划（Transport Plan），实现视觉与点云特征的双向信息交换。
    *   **DCMT (分布一致性模态转移)**: 引入可逆归一化流（Invertible Normalizing Flow），将经过 AGOT 融合的传感器特征与语言导航 Token 共同映射到一个统一的隐层高斯流形中，消除异构模态的分布差异。
2.  **多模态多轨迹规划 (Multi-Modal Multi-Trajectory Planning)**
    *   基于离散流匹配（Discrete Flow Matching, DFM）范式，将融合后的多模态 Token 作为条件输入。在去噪过程中，保留所有中间状态的轨迹，自然形成一个包含多条候选轨迹的集合，避免了单一轨迹规划容易导致的模式崩溃（Mode Collapse）。
3.  **感知导向的轨迹微调 (Perception-Oriented Trajectory Refinement)**
    *   利用模型输出的实时 3D 目标检测和 BEV 语义分割结果，构建包含语义代价（Semantic Cost）和检测代价（Detection Cost）的**风险代价地图 (Risk Cost Map)**。
    *   将生成的候选轨迹作为初始解，使用 Levenberg-Marquardt 算法在代价地图上进行优化，最小化碰撞风险并保证轨迹平滑，最后根据代价得分选择最优轨迹。

**核心逻辑伪代码 (Python 风格)**:

```python
def forward_vla_ad(camera_tokens, lidar_tokens, text_tokens, ego_state):
    # Phase 1: Multi-Modality Interaction
    # 1.1 Affinity-Guided Optimal Transport (AGOT) for Camera & LiDAR
    affinity_matrix = compute_affinity(camera_tokens, lidar_tokens)
    cost_matrix = -affinity_matrix
    transport_plan = sinkhorn_algorithm(cost_matrix)
    
    fused_camera = camera_tokens + transport_plan @ lidar_tokens
    fused_lidar = lidar_tokens + transport_plan.T @ camera_tokens
    
    # 1.2 Distribution-Consistent Modality Transfer (DCMT)
    # Map all modalities to a unified Gaussian space via Normalizing Flow
    z_camera = normalizing_flow(fused_camera)
    z_lidar = normalizing_flow(fused_lidar)
    z_text = normalizing_flow(text_tokens)
    
    # Final cross-modal interaction with text
    final_tokens = cross_modal_attention(z_camera, z_lidar, z_text, ego_state)
    
    # Phase 2: Perception & Multi-Trajectory Generation
    # 2.1 Generate perception outputs (used for cost map later)
    bbox_3d = detection_head(final_tokens)
    bev_map = segmentation_head(final_tokens)
    
    # 2.2 Generate multiple candidate trajectories via Discrete Flow Matching
    candidate_trajectories = discrete_flow_matching_denoise(final_tokens, steps=K)
    
    # Phase 3: Perception-Oriented Trajectory Refinement
    # 3.1 Construct Risk Cost Map
    risk_cost_map = build_cost_map(bbox_3d, bev_map)
    
    best_trajectory = None
    lowest_cost = float('inf')
    
    # 3.2 Optimize each trajectory using Levenberg-Marquardt
    for traj in candidate_trajectories:
        # Objective: Prior Cost + Risk Cost + Smoothness Cost
        optimized_traj = levenberg_marquardt_optimize(traj, risk_cost_map)
        traj_cost = evaluate_cost(optimized_traj, risk_cost_map)
        
        if traj_cost < lowest_cost:
            lowest_cost = traj_cost
            best_trajectory = optimized_traj
            
    return best_trajectory, bbox_3d, bev_map
```

### 第二模块：核心架构解释

CertVLA 的核心架构分为离线校准（Offline Calibration）和在线部署（Online Deployment）两个阶段。其底层逻辑是通过双重掩码机制确保至少有一种掩码组合能够完全覆盖并消除对抗补丁，同时通过统计学方法界定掩码带来的良性动作扰动边界。

**1. 离线校准阶段 (Position-Aware Episode Calibration)**
*   **位置尺度估计 (Stage I):** 不同的掩码位置会遮挡不同的背景信息，导致模型输出的动作产生不同程度的良性偏移。算法在干净的校准数据集上，计算所有单掩码与双掩码组合下的动作距离，并提取分位数构建位置尺度矩阵 $Q$。该矩阵用于消除不同掩码位置带来的固有偏差。
*   **全局阈值校准 (Stage II):** 使用共形预测（Conformal Prediction）技术，在另一批干净数据上计算归一化后的动作一致性得分。根据预设的容错率 $\alpha$，确定一个全局的剧集级（Episode-level）阈值 $\tau$。

**2. 在线部署阶段 (Anchored Dual-Mask Recovery)**
*   **锚点验证:** 对于当前观测，遍历所有单掩码生成动作预测作为“锚点”。
*   **双掩码一致性检查:** 针对每一个锚点，应用所有可能的第二掩码生成双掩码预测。计算双掩码预测与锚点之间的归一化动作距离。
*   **认证与执行:** 如果某个锚点在所有第二掩码下的最大距离均小于等于阈值 $\tau$，则该锚点被认证为安全，并输出其动作。
*   **闭环聚合:** 如果在一个完整的任务执行周期（Rollout）内，所有的决策步都通过了上述认证，则整个闭环任务被标记为认证成功。

**核心伪代码实现:**

```python
import numpy as np

def compute_directional_distance(action_dual, action_single, valid_range, epsilon=1e-8):
    # 计算双掩码动作与单掩码锚点之间的归一化距离
    diff = np.abs(action_dual - action_single)
    # 根据有效动作范围进行归一化
    norm_factor = np.maximum(np.abs(valid_range[:, 1] - action_single), 
                             np.abs(action_single - valid_range[:, 0]))
    norm_factor = np.maximum(norm_factor, epsilon)
    return np.mean(diff / norm_factor)

def dual_mask_recover(observation, policy, masks, Q_matrix, tau, epsilon=1e-8):
    """
    在线部署阶段：锚定双掩码恢复算法
    """
    K = len(masks)
    best_score = float('inf')
    best_action = policy(observation) # 默认无掩码动作
    certified = False
    
    # 遍历所有第一掩码（生成锚点）
    for i in range(K):
        obs_mask_i = apply_mask(observation, masks[i])
        action_anchor_i = policy(obs_mask_i)
        max_score_for_i = 0
        
        # 遍历所有第二掩码（验证锚点）
        for j in range(K):
            obs_mask_ij = apply_mask(obs_mask_i, masks[j])
            action_dual_ij = policy(obs_mask_ij)
            
            # 计算归一化距离
            raw_dist = compute_directional_distance(action_dual_ij, action_anchor_i)
            normalized_score = raw_dist / (Q_matrix[i, j] + epsilon)
            
            max_score_for_i = max(max_score_for_i, normalized_score)
            
            # 提前停止：如果当前第二掩码已经导致得分超过阈值，直接放弃该锚点
            if max_score_for_i > tau:
                break
                
        # 记录最小的局部得分作为后备
        if max_score_for_i < best_score:
            best_score = max_score_for_i
            best_action = action_anchor_i
            
        # 如果该锚点通过了所有第二掩码的测试，立即返回认证动作
        if max_score_for_i <= tau:
            return action_anchor_i, True
            
    # 如果没有任何锚点通过测试，返回得分最低的动作，并标记未认证
    return best_action, False
```

**阶段 A：离线价值子空间发现 (Offline Value-Subspace Discovery)**
1. 收集梯度：在冻结的受害者模型上运行干净的轨迹，预热后，利用 Critic 预测的类别期望值作为替代损失函数。
2. 提取基底：对每一帧计算全像素空间的 PGD 扰动，将 $M$ 帧的扰动展平并堆叠为矩阵 $\Delta$。
3. SVD 分解：对 $\Delta$ 进行截断奇异值分解（Truncated SVD），提取前 $r$ 个右奇异向量构成正交基矩阵 $V_r$。这个 $V_r$ 就是 Critic 引导的价值子空间。

**阶段 B：在线子空间攻击 (Online Subspace Attack)**
1. 低维优化：在实际攻击部署时，不再优化 $H \times W \times C$ 的像素，而是优化维度为 $r$ 的系数向量 $\alpha_t$。
2. 时间平滑：对求得的系数 $\alpha_t$ 应用指数移动平均（EMA），由于子空间内的每一个方向本质上都是攻击方向，因此在系数空间进行 EMA 既能保证帧间平滑，又不会损失攻击强度。
3. 投影还原：将平滑后的系数通过 $V_r$ 映射回像素空间，并执行 $\ell_\infty$ 范数和像素有效范围的截断。

**核心伪代码实现：**

```python
import numpy as np
import torch

# ==========================================
# Stage A: Offline Subspace Discovery
# ==========================================
def extract_value_subspace(victim_critic, clean_rollout, M=600, r=32):
    perturbations = []
    for obs in clean_rollout[:M]:
        delta = torch.zeros_like(obs, requires_grad=True)
        # L steps of PGD to maximize critic value degradation
        for _ in range(L):
            # v(o) is the expected bin index from DreamerV3 critic
            loss = compute_critic_expected_value(victim_critic, obs + delta)
            loss.backward()
            grad = delta.grad
            delta.data = delta.data - eta * normalize(grad)
            delta.data = project_to_l_inf_and_pixel_range(delta.data, obs)
            delta.grad.zero_()
        perturbations.append(delta.detach().flatten())
    
    # Stack and compute SVD
    Delta = torch.stack(perturbations) # Shape: [M, D]
    U, S, Vh = torch.linalg.svd(Delta, full_matrices=False)
    V_r = Vh[:r, :].T # Extract top-r right singular vectors, Shape: [D, r]
    return V_r

# ==========================================
# Stage B: Online Subspace Attack
# ==========================================
def online_civa_attack(victim_critic, obs_t, V_r, alpha_prev, rho=0.75, L=8):
    # Initialize alpha from previous step's EMA
    alpha_t = alpha_prev.clone().requires_grad_(True)
    
    # Subspace PGD
    for _ in range(L):
        # Lift to pixel space
        delta_pixel = torch.matmul(V_r, alpha_t).view(obs_t.shape)
        loss = compute_critic_expected_value(victim_critic, obs_t + delta_pixel)
        loss.backward()
        
        # Gradient step in subspace
        grad_alpha = alpha_t.grad
        alpha_t.data = alpha_t.data - eta * normalize(grad_alpha)
        alpha_t.grad.zero_()
        
        # Approximate projection (Lift -> Project -> Push back)
        delta_pixel = torch.matmul(V_r, alpha_t.data).view(obs_t.shape)
        delta_pixel = project_to_l_inf_and_pixel_range(delta_pixel, obs_t)
        alpha_t.data = torch.matmul(V_r.T, delta_pixel.flatten())
    
    # Temporal Coherence via EMA
    alpha_ema = rho * alpha_prev + (1 - rho) * alpha_t.data
    
    # Final lift to pixel space
    final_delta = torch.matmul(V_r, alpha_ema).view(obs_t.shape)
    final_delta = project_to_l_inf_and_pixel_range(final_delta, obs_t)
    
    return final_delta, alpha_ema
```

### 第二模块：核心架构解释

EndoLIFT 的系统架构分为“多模态上下文编码”、“变分轨迹潜变量生成”与“修正流动作生成”三个核心阶段。其本质是一个以外部语言指令为条件，通过流匹配（Flow Matching）生成未来连续动作序列的生成式策略。

**1. 多模态上下文编码 (Multimodal Context Encoding)**
系统接收当前 RGB 图像、语言指令（如“前进”或“紧急撤回”）以及上一帧执行的动作状态。这些输入通过经过 LoRA 微调的 PaliGemma 2（3B）视觉语言主干网络，被压缩并映射为一个高维的视觉-语言前缀（Visual-Language Prefix），为后续动作生成提供全局上下文。

**2. 变分轨迹潜变量 (Variational Trajectory Latent, VTL)**
为了处理同一指令下可能存在的多种合理轨迹（多模态动作分布），模型引入了一个 32 维的潜变量。在训练阶段，后验网络将目标动作块编码为高斯分布并采样出潜变量 $z$；在推理阶段，直接从标准正态分布 $\mathcal{N}(0, \mathbf{I})$ 中采样 $z$。

**3. 修正流动作专家 (Rectified Flow Action Expert)**
这是一个包含 8 个 Transformer 块的网络。它接收视觉-语言前缀、历史动作、噪声动作块 $x_\tau$、流时间 $\tau$ 以及潜变量 $z$。网络通过自注意力和交叉注意力机制，预测从纯噪声到真实动作块的“速度场（Velocity Field）”。

**4. 欧拉积分执行 (Euler Integration)**
在推理时，系统初始化一个纯噪声动作块（$\tau=1$），利用动作专家预测的速度场，通过 20 步欧拉积分逐步去噪，最终在 $\tau=0$ 时输出一个 $32 \times 3$ 的归一化连续动作块（包含纵向进退、上下弯曲、左右弯曲），随后转换为电机控制指令执行。

**核心伪代码实现**：

```python
import torch
import torch.nn as nn

class EndoLIFT(nn.Module):
    def __init__(self, vlm_backbone, action_expert, posterior_net):
        super().__init__()
        self.vlm = vlm_backbone # PaliGemma 2 with LoRA
        self.action_expert = action_expert # 8-block Transformer
        self.posterior_net = posterior_net # MLP for VTL

    def forward_train(self, image, instruction, prev_action, target_action_chunk):
        # 1. Encode multimodal context
        vl_prefix = self.vlm(image, instruction)
        
        # 2. Variational Trajectory Latent (VTL) - Training path
        mu, log_var = self.posterior_net(vl_prefix, prev_action, target_action_chunk)
        std = torch.exp(0.5 * log_var)
        eps = torch.randn_like(std)
        z = mu + eps * std # Reparameterization trick
        
        # 3. Rectified Flow setup
        batch_size = target_action_chunk.shape[0]
        tau = torch.rand(batch_size, 1, 1).to(target_action_chunk.device)
        noise = torch.randn_like(target_action_chunk)
        
        # x_tau = (1 - tau) * Target + tau * Noise
        x_tau = (1 - tau) * target_action_chunk + tau * noise
        # Ground truth velocity field
        u_target = noise - target_action_chunk
        
        # 4. Predict velocity field
        u_pred = self.action_expert(vl_prefix, prev_action, x_tau, tau, z)
        
        # 5. Compute losses (Flow matching MSE + KL Divergence)
        loss_flow = nn.functional.mse_loss(u_pred, u_target)
        loss_kl = -0.5 * torch.sum(1 + log_var - mu.pow(2) - log_var.exp())
        # (Free-bits floor applied in actual implementation)
        
        return loss_flow + 1e-3 * loss_kl

    @torch.no_grad()
    def inference(self, image, instruction, prev_action, num_steps=20):
        # 1. Encode context
        vl_prefix = self.vlm(image, instruction)
        
        # 2. Sample VTL from prior
        batch_size = image.shape[0]
        z = torch.randn(batch_size, 32).to(image.device)
        
        # 3. Initialize noise chunk at tau = 1
        x_tau = torch.randn(batch_size, 32, 3).to(image.device)
        
        # 4. Euler Integration (tau from 1 to 0)
        dt = 1.0 / num_steps
        for step in range(num_steps):
            tau = 1.0 - step * dt
            tau_tensor = torch.full((batch_size, 1, 1), tau).to(image.device)
            
            u_pred = self.action_expert(vl_prefix, prev_action, x_tau, tau_tensor, z)
            x_tau = x_tau - u_pred * dt # Step backwards in time
            
        return x_tau # Final action chunk at tau = 0
```

```python
    # 1. 获取当前位置和下一位置的脉冲响应 (Impulse Responses)

    audio_state_stationary = convolve(audio_source_t_plus_1, ir_t_padded)

    transition_audio = crossfade(audio_state_stationary, audio_state_moved)
```

```python
def multimodal_l2_speculative_decoding(target_model, drafter_model, image, prompt, max_tokens, K):
    # [瓶颈阶段] 视觉条件注入 (Vision Conditioning)
    # 包含视觉编码、目标模型预填充，以及最耗时的起草者 KV Cache 构建
    vision_features = target_model.vision_encoder(image)
    target_kv_cache, target_hidden_states = target_model.prefill(prompt, vision_features)
    
    # L2 Drafter 通常需要目标模型的隐藏状态来对齐多模态特征
    drafter_kv_cache = drafter_model.construct_cache_from_target(target_hidden_states)
    
    generated_tokens = []
    
    while len(generated_tokens) < max_tokens:
        # [极速阶段] L2 块并行起草 (Block-parallel generative drafting)
        # 耗时极短 (如 ~1ms)，一次性联合生成 K 个 Token
        draft_block = drafter_model.generate_block_diffusion(
            drafter_kv_cache, 
            block_size=K
        )
        
        # [验证阶段] 目标模型并行验证 (Target Verification)
        # 目标模型一次前向传播验证 K 个 Token
        target_logits, new_target_kv = target_model.forward_verify(
            draft_block, 
            target_kv_cache
        )
        
        # 严格匹配验证逻辑
        accepted_tokens = verify_tokens(draft_block, target_logits)
        generated_tokens.extend(accepted_tokens)
        
        # 修正与缓存更新
        if len(accepted_tokens) < K:
            correction_token = sample_from_residual(target_logits, draft_block, len(accepted_tokens))
            generated_tokens.append(correction_token)
            
        # 更新上下文状态，准备下一轮
        target_kv_cache = update_target_cache(new_target_kv, accepted_tokens)
        drafter_kv_cache = update_drafter_cache(drafter_model, target_kv_cache)
        
    return generated_tokens
```

### 第一模块：一分钟核心速写

1. **论文领域**：World Model（具体为视觉几何基础模型在 3D 空间感知中的应用）
2. **TL;DR**：MV2GF 提出了一种基于**视觉几何基础模型（Depth Anything 3）**的**多视角行人检测框架**，以解决**未见相机配置下的泛化性及透视投影畸变**问题，在 **GMVD-D、MVPerception 等基准测试**上实现了 **MODA 指标的显著提升（最高 +4.6）**。
3. **研究动机**：现存 MVPD 方案极度依赖透视变换（Perspective Transformation）将 2D 特征投影到 3D 空间，这不仅导致特征在 3D 空间产生严重的“阴影状畸变”（所有像素被拉伸到同一平面），还使得模型严重过拟合训练集中的特定相机内外参，无法泛化到新视角。本文的切入点在于直接降维打击：利用在大规模数据上预训练的 3D 基础模型作为“空间世界模型”，直接获取像素级的真实 3D 坐标和几何先验。

4. **关键数据**：
- **最能证明有效性的数据**：在 GMVD-D（未见相机配置）测试集中，MV2GF 的 MODA 达到 84.8，超越前 SOTA 方法（MSMVD）4.6 个点。这组数据直接证明了引入通用几何先验对跨视角、跨相机配置泛化能力的决定性作用。
- **存疑/局限的试验结果**：在同分布测试（GMVD-S）中，MV2GF 的 MODP（86.1 vs 86.6）和 Precision（97.2 vs 98.0）略低于 MSMVD；同时，其推理速度仅为 3.3 FPS（低于基线的 4.5+ FPS）。这表明引入 1.4B 参数的基础模型虽然拉高了泛化上限，但牺牲了细粒度定位精度和实时推理效率。

### 第二模块：核心架构解释

MV2GF 的整体架构分为特征提取与融合、3D 空间聚合、以及鸟瞰图（BEV）检测三个主要阶段。

1. **输入与预处理**：接收 $N$ 个视角的图像及其对应的相机内外参。
2. **TGF（任务与几何特征融合模块）**：
   - 使用冻结的 Depth Anything 3 (DA3) 提取包含跨视角通用几何信息的特征，并输出每个视角的 3D 点图（Pointmaps）。
   - 使用可训练的 ResNet 提取聚焦于行人（Foreground）的任务特异性语义特征。
   - 通过特征金字塔网络（FPN）将上述两种特征进行通道拼接与多尺度融合，输出高分辨率的增强图像特征。
3. **FPA（特征点图聚合模块）**：
   - 初始化一个空的 3D 体素网格（Voxel Grid）。
   - 遍历融合后的图像特征，利用 DA3 预测的 3D 点图（提供每个像素的绝对 3D 坐标），将像素特征直接映射到对应的 3D 体素中。
   - 在每个体素内部执行最大池化（Max Pooling），保留最显著的特征。
   - 将 Z 轴（高度）维度重排并使用 CNN 压缩，生成 2D 的 BEV 特征图。
4. **检测头**：基于 BEV 特征图预测行人占用图（Occupancy Map）和离散化偏移量（Offset Map），通过 Focal Loss 和 L1 Loss 进行端到端监督。

**底层逻辑伪代码（Python 风格）**：

```python
import torch
import torch.nn as nn

def MV2GF_forward(multi_view_images, camera_params):
    """
    multi_view_images: Tensor [N, 3, H, W]
    camera_params: Tensor [N, 9] (intrinsics and extrinsics)
    """
    N = multi_view_images.shape[0]
    
    # 1. Visual Geometric Foundation Model (Frozen DA3)
    with torch.no_grad():
        # da3_features: List of multi-scale geometric features
        # pointmaps: Tensor [N, 3, H_D, W_D] (3D world coordinates for each pixel)
        da3_features, pointmaps = DA3_Model(multi_view_images, camera_params)

    # 2. Task-specific and Geometric information Fusion (TGF)
    # Extract semantic features focused on pedestrians
    resnet_features = Trainable_ResNet(multi_view_images) 
    
    # Fuse semantic and geometric features via FPN
    # fused_features: Tensor [N, C, H_f, W_f]
    fused_features = FPN_Fusion(resnet_features, da3_features) 

    # 3. Feature Pointmap Aggregation (FPA)
    # Initialize 3D voxel grid [C, X_bins, Y_bins, Z_bins]
    voxel_grid = torch.zeros((C, X_bins, Y_bins, Z_bins), device=multi_view_images.device)
    
    # Project features into 3D space using Pointmaps
    for n in range(N):
        # Resize pointmap to match fused_feature resolution
        resized_pointmap = resize(pointmaps[n], size=(H_f, W_f)) 
        
        # Convert 3D coordinates to discrete voxel indices
        voxel_indices = compute_voxel_indices(resized_pointmap, voxel_size=(theta_x, theta_y, theta_z))
        
        # Scatter features into voxels using Max Pooling
        # scatter_max updates voxel_grid in-place
        voxel_grid = scatter_max(src=fused_features[n], index=voxel_indices, out=voxel_grid)
        
    # Compress Z-axis to create BEV feature
    # Reshape: [C, X, Y, Z] -> [C*Z, X, Y]
    compressed_grid = voxel_grid.permute(0, 3, 1, 2).reshape(C * Z_bins, X_bins, Y_bins)
    bev_feature = CNN_Compressor(compressed_grid) # Output: [C_out, X, Y]

    # 4. Detection Head
    # Predict occupancy probability and location offset
    occupancy_map = Sigmoid(Conv_Occ(bev_feature))
    offset_map = Conv_Offset(bev_feature)
    
    return occupancy_map, offset_map
```
