### 第二模块：核心架构解释

TourPhysics 的系统架构是一个包含状态机与质量反馈的在线循环系统。其运行流程严格遵循因果顺序，分为初始化与在线交互两个阶段：

1.  **场景提升 (Scene Lifting - 仅执行一次):** 接收单张输入图像和用户定义的物理配置。提取实例掩码，构建显式 3D 网格，修复背景，并建立统一的重力对齐坐标系。此阶段确立了不可变的初始参考图像和基础几何。
2.  **物理与相机状态转移 (Physical Transition):** 接收用户的动作指令（移动相机或施加力）。物理引擎（支持刚体、MPM、PBD等）在后台独立计算出一段固定长度的物理轨迹和相机位姿，并输出只读的“模拟器一致性深度（Simulator-consistent depth）”。
3.  **观测生成 (Observation Synthesis):** 视频扩散模型接收上述固定的几何记录、相对深度控制信号以及历史外观记忆，生成对应的视频帧。在此过程中，视频模型绝对无权修改底层的物理状态或碰撞几何。
4.  **质量门控与原子提交 (Quality-Gated Atomic Commit):** 对生成的视频帧进行像素级和运动连续性检测。如果通过，则将该段视频的末态物理数据和视觉特征正式“提交（Commit）”到全局状态中，并更新长程记忆；如果失败，则丢弃生成的视觉内容，物理状态回滚至上一个节点并重试。

```python
def evaluate_vla_on_robospa(model, task_suite, num_trials=100):
    evaluation_results = {}
    
    for task in task_suite:
        task_results = {}
        # 遍历 L1 到 L5 五个难度等级
        for difficulty_level in range(1, 6):
            success_count = 0
            total_completed_subtasks = 0
            total_required_subtasks = task.get_subtask_count(difficulty_level)
            num_candidates = task.get_object_count(difficulty_level)
            
            for trial in range(num_trials):
                # 执行模型 rollout
                trajectory = execute_rollout(model, task, difficulty_level)
                
                if trajectory.is_successful():
                    success_count += 1
                
                # 记录长程任务中完成的子步骤数量
                total_completed_subtasks += trajectory.completed_subtasks()
            
            # 计算基础成功率
            success_rate = success_count / num_trials
            
            metrics = {"Success_Rate": success_rate}
            
            # 计算细粒度空间推理的 ONTA 指标
            if task.category == "Spatial_Reasoning":
                if num_candidates > 1:
                    random_baseline = 1.0 / num_candidates
                    onta = ((success_rate - random_baseline) / (1.0 - random_baseline)) * 100
                else:
                    onta = 100.0 if success_rate == 1.0 else 0.0
                metrics["ONTA"] = onta
                
            # 计算长程过程规划的 PS 指标
            elif task.category == "Long_Horizon_Planning":
                progress_score = (total_completed_subtasks / (num_trials * total_required_subtasks)) * 100
                metrics["Progress_Score"] = progress_score
                
            task_results[f"L{difficulty_level}"] = metrics
            
        evaluation_results[task.name] = task_results
        
    return evaluation_results
```

### 第二模块：核心架构解释

LIBERO-Recover 的核心架构并非提出一个新的具身控制模型，而是构建一个自动化的故障场景生成与评估流水线。其整体流程分为数据收集、故障定位、故障分级与基准评估四个阶段。

2.  **时序故障定位 (Temporal Failure Localization)**：将失败轨迹渲染为视频，输入给 Qwen3.5-27B-Instruct 模型。利用 VLM 的常识推理能力，将视频切分为“失败前”、“失败中”和“失败后”三个阶段，精准提取导致任务偏离预期的关键帧，将其定义为故障状态 $s_f$。
3.  **故障特征化与分级 (Failure Characterization)**：VLM 根据故障状态对环境造成的破坏程度，将场景划分为四个递进难度：
    *   L1 (Action Retry): 目标未改变，仅需重试动作。
    *   L2 (Action Adaptation): 目标位姿微调，需调整动作输出。
    *   L3 (Object State Recovery): 任务相关物体状态被破坏，需先恢复物体状态再执行任务。
    *   L4 (Environmental Recovery): 任务无关物体阻碍了执行，需进行环境清理与拓扑推理。
4.  **恢复能力评估 (Evaluation)**：在测试阶段，将待评估模型直接置于上述提取的故障状态 $s_f$ 中，要求其输出恢复动作序列，最终计算恢复成功率 (RSR) 和恢复退化率 (RD)。

### 第二模块：核心架构解释

TourPhysics 的系统架构是一个包含状态机与质量反馈的在线循环系统。其运行流程严格遵循因果顺序，分为初始化与在线交互两个阶段：

```python
        # 遍历 L1 到 L5 五个难度等级
        for difficulty_level in range(1, 6):
            success_count = 0
            total_completed_subtasks = 0
            total_required_subtasks = task.get_subtask_count(difficulty_level)
            num_candidates = task.get_object_count(difficulty_level)
            
            for trial in range(num_trials):
                # 执行模型 rollout
                trajectory = execute_rollout(model, task, difficulty_level)
                
                if trajectory.is_successful():
                    success_count += 1
                
                # 记录长程任务中完成的子步骤数量
                total_completed_subtasks += trajectory.completed_subtasks()
            
            # 计算基础成功率
            success_rate = success_count / num_trials
            
            metrics = {"Success_Rate": success_rate}
            
            # 计算细粒度空间推理的 ONTA 指标
            if task.category == "Spatial_Reasoning":
                if num_candidates > 1:
                    random_baseline = 1.0 / num_candidates
                    onta = ((success_rate - random_baseline) / (1.0 - random_baseline)) * 100
                else:
                    onta = 100.0 if success_rate == 1.0 else 0.0
                metrics["ONTA"] = onta
                
            # 计算长程过程规划的 PS 指标
            elif task.category == "Long_Horizon_Planning":
                progress_score = (total_completed_subtasks / (num_trials * total_required_subtasks)) * 100
                metrics["Progress_Score"] = progress_score
                
            task_results[f"L{difficulty_level}"] = metrics
            
        evaluation_results[task.name] = task_results
        
    return evaluation_results
```

### 第二模块：核心架构解释

LIBERO-Recover 的核心架构并非提出一个新的具身控制模型，而是构建一个自动化的故障场景生成与评估流水线。其整体流程分为数据收集、故障定位、故障分级与基准评估四个阶段。

1.  **任务执行与故障收集 (Task Execution)**：在标准 LIBERO 环境中部署现有的 SOTA 具身模型（如 OpenVLA, GR00T 等）。模型从标准初始状态开始执行任务，记录所有未能完成任务的失败轨迹（包含图像观测、本体状态和动作）。
2.  **时序故障定位 (Temporal Failure Localization)**：将失败轨迹渲染为视频，输入给 Qwen3.5-27B-Instruct 模型。利用 VLM 的常识推理能力，将视频切分为“失败前”、“失败中”和“失败后”三个阶段，精准提取导致任务偏离预期的关键帧，将其定义为故障状态 $s_f$。
3.  **故障特征化与分级 (Failure Characterization)**：VLM 根据故障状态对环境造成的破坏程度，将场景划分为四个递进难度：
    *   L1 (Action Retry): 目标未改变，仅需重试动作。
    *   L2 (Action Adaptation): 目标位姿微调，需调整动作输出。
    *   L3 (Object State Recovery): 任务相关物体状态被破坏，需先恢复物体状态再执行任务。
    *   L4 (Environmental Recovery): 任务无关物体阻碍了执行，需进行环境清理与拓扑推理。
4.  **恢复能力评估 (Evaluation)**：在测试阶段，将待评估模型直接置于上述提取的故障状态 $s_f$ 中，要求其输出恢复动作序列，最终计算恢复成功率 (RSR) 和恢复退化率 (RD)。

### 第二模块：核心架构解释

VLA-Precision 的整体架构分为两个阶段：阶段一为全参数模仿学习（SFT），阶段二为真实世界在线强化学习。阶段二是核心，由异步的 Actor-Learner 系统构成，包含 ACoB 算法与 ACoB-Stream 系统架构。

**1. 算法流程 (ACoB Algorithm)**
*   **Critic 更新 (Progressive Value Calibration):** 结合两种损失。一是基于时序差分（TD）的全局回报传播，用于评估长视野累积收益；二是状态匹配的局部偏好排序（Local Preference Ranking），强制人类干预动作的价值高于模型原始输出的错误动作，解决局部信用分配模糊问题。
*   **Actor 更新 (Relative-Advantage Policy Improvement):** 冻结 VLM 基础权重，仅训练 Action Expert 中的 LoRA 参数。Actor 的优化目标包含三部分：1) 行为克隆（BC），快速吸收人类干预和成功轨迹；2) 相对优势强化学习（Relative-Advantage RL），计算当前动作与冻结参考动作之间的优势差，仅在所有 Critic 均认为当前动作更优时才进行更新；3) 参考正则化（Reference Regularization），约束动作不要偏离阶段一微调好的参考策略太远。

**2. 系统流程 (ACoB-Stream Architecture)**
*   **上下文形成与持久化:** Actor 在推理时生成并保留冻结前缀的 KV Cache。这些 Cache 经过去重后存入磁盘支持的上下文缓冲区，避免了 Learner 每次更新时重复计算庞大的 VLM 前向传播。
*   **按需访问与状态同步:** Learner 仅根据当前优化目标检索必要的上下文（如价值优化仅需后继状态，策略优化需当前状态）。更新完成后，Learner 仅将轻量级的 LoRA 权重（Trainable State）发布给 Actor 进行原子替换，消除了全模型同步的延迟。

**核心伪代码实现逻辑:**

```python
def acob_learner_update(batch, critics, target_critics, actor_expert, ref_expert):
    # 1. Critic Update (Progressive Value Calibration)
    # TD Loss: Global Return Propagation
    next_actions = actor_expert(batch.next_states)
    target_q = compute_target_q(target_critics, batch.next_states, next_actions)
    td_target = batch.rewards + gamma * (1 - batch.dones) * target_q
    current_q = critics(batch.states, batch.executed_actions)
    loss_td = mse_loss(current_q, td_target)
    
    # Ranking Loss: Local Preference Ranking (only for human corrections)
    # Enforce Q(human_action) > Q(model_proposed_action) + margin
    adv_human = critics.advantage(batch.states, batch.human_actions)
    adv_prop = critics.advantage(batch.states, batch.proposed_actions)
    loss_rank = relu(margin - (adv_human - adv_prop)).mean()
    
    loss_critic = loss_td + lambda_rank * loss_rank
    update_weights(critics, loss_critic)

    # 2. Actor Update (Relative-Advantage Policy Improvement)
    # Behavior Cloning Loss (Flow-Matching on successful/corrected data)
    loss_bc = flow_matching_loss(actor_expert, batch.states, batch.executed_actions, mask=batch.is_successful_or_corrected)
    
    # Relative Advantage RL Loss
    current_actions = actor_expert(batch.states)
    ref_actions = ref_expert(batch.states) # Frozen reference
    
    # Compute advantage gap between current action and baseline (reference or human)
    adv_current = critics.advantage(batch.states, current_actions)
    adv_baseline = compute_baseline_advantage(critics, batch, ref_actions)
    delta_adv = min_over_critics(adv_current - stop_gradient(adv_baseline))
    
    # Soft-margin objective to prevent over-optimization
    loss_rl = softplus(margin_pi - delta_adv).mean()
    
    # Reference Regularization Loss
    loss_ref = mse_loss(current_actions, ref_actions)
    
    loss_actor = w_bc * loss_bc + w_rl * loss_rl + w_ref * loss_ref
    update_weights(actor_expert, loss_actor)
    
    return loss_critic, loss_actor
```

### 第二模块：核心架构解释

本文的模型架构建立在 H-RDT（基于 Diffusion Transformer 的 VLA）基础之上，将训练流程拆分为三个阶段：人类数据预训练、LSS 增强人类数据预训练（本文核心）、机器人数据微调。

**核心流程拆解**：
1. **离线数据标注（准备期）**：使用 Gemini-3-flash 对人类演示视频进行切分，定义不同的操作阶段（如：接近、抓取、旋转、撤回），并为每个阶段生成解释因果关系的推理文本。使用冻结的 T5 模型将这些文本编码为目标嵌入向量。
2. **LSS 训练（Stage 2）**：VLA 骨干网络接收图像和任务指令，输出 16 个动作 token。在计算常规的流匹配（Flow-matching）损失的同时，将这 16 个 token 通过一个两层 MLP 构成的 `LSAHead` 投影到 T5 向量空间。
3. **密集对齐（Dense LSS）**：根据动作 token 对应的时间帧，将其分配到特定的操作阶段。计算投影后的 token 与该阶段专属的 T5 推理向量之间的余弦距离，作为辅助损失（权重 $\lambda=0.1$）。跨越阶段边界的 token 会被掩码剔除。
4. **零成本推理（部署期）**：训练完成后，彻底丢弃 `LSAHead` 和 T5 文本编码器。部署的计算图与原始 VLA 完全一致。

**核心逻辑伪代码**：

```python
import torch
import torch.nn.functional as F

def train_step_dense_lss(batch, vla_backbone, lsa_head, frozen_t5, lambda_weight=0.1):
    """
    Dense LSS 核心训练逻辑 (对应论文 Algorithm 1)
    """
    images, commands, actions, phase_labels, reasoning_texts = batch
    
    # 1. 预计算：获取每个操作阶段的推理文本 T5 嵌入 (离线或缓存)
    # phase_targets 形状: [num_phases, 4096]
    with torch.no_grad():
        phase_targets = frozen_t5.encode_and_mean_pool(reasoning_texts) 
    
    # 2. 前向传播：VLA 骨干网络生成动作 token 隐状态
    # action_tokens 形状: [batch_size, 16, 2176]
    action_tokens = vla_backbone(images, commands)
    
    # 3. 计算主任务损失 (Flow-matching)
    loss_flow = compute_flow_matching_loss(action_tokens, actions)
    
    # 4. LSS 投影：将动作 token 映射到 T5 空间
    # projected_tokens 形状: [batch_size, 16, 4096]
    projected_tokens = lsa_head(action_tokens)
    
    # 5. 计算 Dense LSS 辅助损失
    loss_lss = 0.0
    valid_token_count = 0
    
    for i in range(16): # 遍历 16 个 action token
        # 获取当前 token 所属的 phase (剔除跨越边界的 straddler tokens)
        current_phase = phase_labels[:, i] 
        valid_mask = (current_phase != STRADDLER_MASK)
        
        if valid_mask.sum() > 0:
            # 获取对应的阶段目标向量
            target_embeddings = phase_targets[current_phase[valid_mask]]
            pred_embeddings = projected_tokens[:, i, :][valid_mask]
            
            # 计算余弦距离: 1 - cosine_similarity
            cos_sim = F.cosine_similarity(pred_embeddings, target_embeddings, dim=-1)
            loss_lss += (1.0 - cos_sim).sum()
            valid_token_count += valid_mask.sum()
            
    loss_lss = loss_lss / (valid_token_count + 1e-8)
    
    # 6. 联合优化
    total_loss = loss_flow + lambda_weight * loss_lss
    total_loss.backward()
    
    return total_loss
```

### 第二模块：核心架构解释

CFAM 的架构设计严格遵循了功能解耦的原则，分为一个冻结的慢速学习系统（三个皮层）和一个动态的快速学习系统（胶囊场）。

**1. 慢速学习系统（部署后冻结，无梯度更新）**

- **推理皮层 (Reasoning Cortex):** 这是一个冻结的 VLM（如 Qwen2.5-VL）。它不参与底层动作控制，只负责两件事：将自然语言任务分解为技能序列，以及作为高级语义结果的裁判。
- **动作皮层 (Action Cortex) 与 GRT:** 这是执行核心。它不逐帧解码动作，而是检索匹配的“能力胶囊”，使用几何残差变换（GRT）将胶囊中记录的种子轨迹（Seed Trajectory）根据当前场景的 3D 锚点进行空间扭曲（Warp），一次性输出整段轨迹。

**2. 快速学习系统（部署后持续生长）**
- **胶囊场 (Capsule Field, $\mathcal{F}$):** 类似于大脑海马体，是一个固定容量的外部记忆库。存储单元为“能力胶囊”（CC），包含情境键（Situation Key）、感知/动作残差、置信度等。
- **连续现场更新规则 (CFUR):** 决定何时写入新胶囊。当基座模型置信度低、检索距离较远（说明遇到了 Near-OOD 场景），但 GRT 扭曲后的动作在物理世界中执行成功时，触发单样本写入。

```python
    def __init__(self, sensor_cortex, reasoning_cortex, action_cortex, capsule_field):
        self.sensor = sensor_cortex       # Frozen
        self.reasoning = reasoning_cortex # Frozen VLM
        self.action = action_cortex       # Frozen GRT + Blender
        self.memory = capsule_field       # Dynamic, fixed-budget

    def execute_and_learn(self, task_instruction, observation):
        # 1. Perception: Lift to 3D geometry and get retrieval key
        z_embed, current_anchors = self.sensor.perceive(observation)
        situation_key = binarize(z_embed)

        # 2. Reasoning: Decompose task into skill plan
        skill_plan = self.reasoning.plan(task_instruction, self.memory.get_descriptors())

        for skill in skill_plan:
            # 3. Retrieval: Find nearest capsules within support radius
            active_capsules = self.memory.retrieve(situation_key)
            
            # 4. Action: Warp stored trajectory to current scene via GRT
            base_confidence = self.action.get_confidence(observation)
            warped_trajectory = self.action.GRT_warp(active_capsules, current_anchors)
            
            # Blend base policy output with warped trajectory based on confidence
            final_action = self.action.blend(base_confidence, warped_trajectory)
            
            # Execute in physical world
            execution_success = physical_environment.step(final_action)
            
            # 5. Continual Field Update Rule (CFUR)
            distance = hamming_distance(situation_key, active_capsules.keys)
            is_near_ood = (base_confidence < THRESHOLD) and (distance < MARGIN)
            
            if is_near_ood and execution_success:
                # One-shot, gradient-free write to memory
                new_capsule = create_capsule(situation_key, final_action, current_anchors)
                self.memory.add(new_capsule)
                
            # 6. Memory Consolidation (Fixed Budget)
            self.memory.decay_and_compress()
```

### 第二模块：核心架构解释

本论文的系统流程分为两个核心阶段：**联合轨迹生成（前向与逆向扩散）** 与 **推理期能量引导（DAPSE/DPS）**。

1. **场景编码 (Scene Encoding)**：将地图、红绿灯、历史轨迹等异构数据通过 MLP-Mixer 和自注意力网络编码为统一的场景条件向量 $E_f$。
2. **SSDS-DiT 解码器 (Trajectory Decoding)**：
   - **双流阶段 (Dual-stream)**：轨迹 Token $x^{(0)}$ 和场景 Token $E_f$ 分别经过独立的自适应层归一化（adaLN），随后拼接在一起进行联合注意力计算，保留模态特异性的同时实现早期交互。
   - **单流阶段 (Single-stream)**：将双流特征拼接为统一的 Token 集合，通过平行的注意力机制和 MLP 分支进行深度融合。
3. **推理期引导 (Inference-time Guidance)**：
   - **作为规划器 (DAPSE)**：在逆向扩散的每一步，利用 Langevin 动力学对当前预测的干净轨迹 $\hat{x}^{(0)}$ 进行能量函数（如保持速度、合规性）的梯度下降更新，随后再加噪继续扩散。
   - **作为场景生成器 (DPS)**：对选定的对抗智能体施加 TTC（碰撞时间）、切入（Cut-in）或急刹（Braking）的能量梯度，迫使其生成逼真且危险的交互轨迹。
4. **闭环控制 (Closed-loop Control)**：生成的轨迹输入 LQR 控制器与运动学自行车模型，输出底层转向与加速指令。

```python
    # Dual-stream phase: Independent modulation, joint attention
    traj_mod = adaLN(traj_tokens, time_emb)
    scene_mod = adaLN(scene_tokens, time_emb)

    unified_out = parallel_attention_and_mlp(unified_tokens, time_emb)
```

### 第二模块：核心架构解释

当前论文的模型架构分为三个主要阶段：感知与场景理解、差分记忆构建（核心）、以及多视图查询路由。

1.  **感知与场景理解 (Perception)：** 输入连续的 RGB 视频流。使用 SAM3 进行实例分割和跨帧追踪；使用 ViPE（单目深度+视觉里程计）将 2D 边界框反投影到 3D 世界坐标；使用 Qwen3-VL 提取房间级语义和物体运动描述。
2.  **差分记忆构建 (Differential Memory)：**
    *   **静态几何：** 使用八叉树（Octree）对 3D 空间进行划分，每个节点存储房间级语义标签，用于空间查询时的快速剪枝。
    *   **动态物体 (LTE)：** 对每个被追踪的物体，根据其运动状态（静止/运动）进行自适应采样。对于运动轨迹，使用 Douglas-Peucker 算法提取轨迹拐点作为“空间锚点”；在这些锚点处保存图像 Crop 作为“视觉锚点”；调用 VLM 为相邻锚点间的运动阶段生成“语言描述”。
3.  **多视图查询路由 (Views & Query Router)：** 将记忆组织为五个视图（场景、物体、文本、事件、图像）。当接收到自然语言查询时，LLM 将其解析为结构化约束（物体、时间、空间、语义），并在对应的视图中进行级联过滤，最终返回匹配的 3D 位置和时间戳。

**LTE 核心构建逻辑伪代码：**

```python
def construct_LTE(object_track_frames, epsilon=0.15, gap_threshold=2.0):
    """
    object_track_frames: List of dicts containing {'time', '3d_pos', 'bbox', 'image'}
    """
    lte_record = {'captions': [], 'spatial_anchors': [], 'visual_anchors': []}
    segments = split_into_motion_and_gaps(object_track_frames, gap_threshold)
    
    for segment in segments:
        if segment.type == 'GAP':
            # 追踪丢失或静止阶段：仅保留边界锚点
            anchor = segment.last_known_position
            lte_record['spatial_anchors'].append(anchor)
            lte_record['visual_anchors'].append(segment.last_known_crop)
            
        elif segment.type == 'MOTION':
            # 运动阶段：使用 Douglas-Peucker 算法进行轨迹简化
            trajectory_3d = [frame['3d_pos'] for frame in segment.frames]
            simplified_waypoints = douglas_peucker(trajectory_3d, epsilon)
            
            for waypoint in simplified_waypoints:
                lte_record['spatial_anchors'].append(waypoint.pos)
                lte_record['visual_anchors'].append(waypoint.crop)
            
            # 调用 VLM 生成该运动阶段的语义描述
            caption = VLM.generate_motion_caption(segment.frames, segment.room_label)
            lte_record['captions'].append({
                'text': caption,
                'start_time': segment.start_time,
                'end_time': segment.end_time
            })
            
    return lte_record
```

5. **联合优化**：模型的总损失由三部分组成：潜在状态的预测均方误差（MSE）、防止坍塌的 SIGReg 正则化损失、以及辅助头重构频谱目标的 MSE 损失。
6. **推理规划**：在测试阶段，完全丢弃辅助头，仅使用训练好的编码器和预测器，结合交叉熵方法（CEM）在潜在空间中进行动作序列的搜索与规划。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn as nn

def compute_fourier_target(bounding_boxes, W_frequencies):
    # bounding_boxes: [batch_size, num_objects, 8] (包含坐标、宽高、角度等)
    # W_frequencies: [8, d] 固定的随机频率矩阵
    
    # 计算内积: [batch_size, num_objects, d]
    inner_product = torch.matmul(bounding_boxes, W_frequencies)
    
    # 计算实部(cos)和虚部(sin)
    cos_features = torch.cos(inner_product)
    sin_features = torch.sin(inner_product)
    
    # 沿物体维度求和，实现排列不变性 (Permutation-invariant)
    # 输出维度: [batch_size, d]
    sum_cos = torch.sum(cos_features, dim=1)
    sum_sin = torch.sum(sin_features, dim=1)
    
    # 拼接形成最终的频谱目标: [batch_size, 2d]
    spectral_target = torch.cat([sum_cos, sum_sin], dim=-1)
    return spectral_target

def training_step(observation_t, action_t, observation_t1, bounding_boxes_t, bounding_boxes_t1, W_frequencies, model, aux_head):
    # 1. 编码当前与未来观测
    z_t = model.encoder(observation_t)
    z_t1_target = model.encoder(observation_t1)
    
    # 2. 预测未来潜在状态
    z_t1_pred = model.predictor(z_t, action_t)
    
    # 3. 计算基础 JEPA 预测损失与正则化损失
    loss_pred = nn.MSELoss()(z_t1_pred, z_t1_target)
    loss_sigreg = compute_sigreg_loss(z_t) # 防止全局坍塌
    
    # 4. 构建物理频谱目标
    target_spec_t = compute_fourier_target(bounding_boxes_t, W_frequencies)
    target_spec_t1 = compute_fourier_target(bounding_boxes_t1, W_frequencies)
    
    # 5. 辅助头预测与损失计算
    pred_spec_t = aux_head(z_t)
    pred_spec_t1 = aux_head(z_t1_pred)
    
    loss_aux_t = nn.MSELoss()(pred_spec_t, target_spec_t)
    loss_aux_t1 = nn.MSELoss()(pred_spec_t1, target_spec_t1)
    
    # 6. 总损失计算 (根据论文公式 5 分配梯度)
    total_loss = loss_pred + lambda_sigreg * loss_sigreg + lambda_aux * (loss_aux_t + loss_aux_t1)
    
    return total_loss
```

# 第二模块：核心架构解释

本论文的模型架构由四个核心模块构成，形成了一个闭环的通信感知控制系统：

1.  **控制世界模型 (C-JEPA)**：利用视觉编码器将高维 RGB 图像压缩为隐变量，通过循环状态空间模型 (RSSM) 学习机器人动态的确定性状态与随机状态，并据此输出控制动作。
2.  **无线世界模型 (W-JEPA)**：接收原始 CSI 或结构化射频表征（频谱图/持久性图像 PI），将其编码为无线隐变量。其预测器不仅依赖历史无线状态，还**强制条件化于 C-JEPA 的控制隐状态**，从而实现物理移动对信道变化影响的耦合建模。
3.  **预测性通信调度**：基于 W-JEPA 预测的未来上行链路传输功率需求，决定当前时间步是否需要真实传输视觉观测数据。若信道恶劣或预测置信度高，则静默通信，完全依赖 C-JEPA 的内部想象进行控制。
4.  **自适应弹性机制**：实时计算隐空间中“预测状态”与“实际观测状态”的 L2 距离（Latent Discrepancy）。当偏差超过阈值时，触发在线感知修复（全局光照通过 HSV 变换对齐，局部遮挡通过 VAE 重构），无需重新训练底层控制策略。

```python
class CoupledWorldModel:
    def __init__(self):
        self.c_jepa = ControlJEPA()
        self.w_jepa = WirelessJEPA()
        self.policy = PolicyNetwork()
        self.resilience_module = AdaptiveResilience()

    def step(self, visual_obs, wireless_obs, prev_h, prev_c, prev_action):
        # 1. 视觉编码与控制动态更新 (C-JEPA)
        x_t = self.c_jepa.encode_visual(visual_obs)
        h_t, z_t_prior = self.c_jepa.rssm_transition(prev_h, prev_action)
        z_t_posterior = self.c_jepa.rssm_posterior(h_t, x_t)
        
        # 2. 隐空间异常检测与自适应恢复
        discrepancy = calc_l2_distance(z_t_prior, z_t_posterior)
        if discrepancy > THRESHOLD:
            # 触发在线修复 (HSV变换或VAE重构)
            visual_obs = self.resilience_module.adapt(visual_obs, discrepancy)
            x_t = self.c_jepa.encode_visual(visual_obs)
            z_t_posterior = self.c_jepa.rssm_posterior(h_t, x_t)

        # 3. 生成控制动作
        action = self.policy.act(h_t, z_t_posterior)

        # 4. 无线信道编码与耦合预测 (W-JEPA)
        c_t = self.w_jepa.encode_wireless(wireless_obs)
        # 核心创新：无线预测条件化于控制隐状态 (h_t, z_t_posterior)
        c_pred = self.w_jepa.predict_future_channel(prev_c, h_t, z_t_posterior)
        power_pred = self.w_jepa.predict_power(c_pred)

        # 5. 预测性通信调度
        transmit_flag = self.schedule_communication(power_pred)

        return action, h_t, c_t, transmit_flag
```

### 第二模块：核心架构解释

FailureSpot 的整体架构分为三个核心阶段：弱监督预训练、基于主动学习的微调、以及基于共形预测的在线推理。

1.  **动作衍生弱监督预训练 (Action-derived Weak Supervision Pretraining):**
    提取 VLA 内部表征作为输入，但不使用人工标签。相反，通过分析 VLA 预测的动作块计算三种启发式信号：
    *   *短期动作一致性 (Short-term action consistency):* 计算连续两个时间步预测的重叠动作块之间的 $L_2$ 距离。距离越大，说明策略越不稳定。
    *   *全块动作幅度 (Full-chunk action magnitude) & 执行动作幅度 (Executed action magnitude):* 计算动作向量的 $L_2$ 范数。异常小代表卡死/停滞，异常大代表剧烈乱动。
    将这三个信号结合指数移动平均 (EMA) 进行平滑，加权求和并归一化后，作为软伪标签（Soft pseudo-labels）训练 MLP 或 LSTM 检测器。
2.  **主动学习微调 (Active Learning Fine-tuning):**
    使用预训练的检测器对未标注轨迹进行推理。计算每条轨迹在所有时间戳上预测概率的平均信息熵（Entropy）。挑选熵值最高（即模型最不确定）的 Top-K 轨迹，交由人类进行精确的时间戳级故障起点标注，最后使用二元交叉熵损失对检测器进行微调。
3.  **共形预测推理 (Conformal Prediction for Inference):**
    在部署阶段，利用一组已知的成功轨迹构建单侧、随时间变化的共形边界（Conformal band）。当检测器输出的故障概率超过该动态阈值时，触发故障警报。

```python
        super().__init__()
        self.mlp = nn.Sequential(
            nn.Linear(representation_dim, 128),
            nn.ReLU(),
            nn.Linear(128, 1),
            nn.Sigmoid()
        )
        
    def forward(self, vla_representation):
        # Input: VLA internal representation h_{i,t}
        return self.mlp(vla_representation)

def compute_weak_supervision_signals(action_chunks, executed_actions):
    """
    计算弱监督伪标签 (简化版)
    action_chunks: [T, H, D] (时间步, 块长度, 动作维度)
    """
    T, H, D = action_chunks.shape
    K = executed_actions.shape[1] # 实际执行的步数
    
    consistency = torch.zeros(T)
    mag_full = torch.zeros(T)
    mag_exec = torch.zeros(T)
    
    for t in range(1, T):
        # 1. 短期动作一致性 (重叠部分 L2 距离)
        overlap_prev = action_chunks[t-1, K:]
        overlap_curr = action_chunks[t, :H-K]
        consistency[t] = torch.norm(overlap_prev - overlap_curr, p=2, dim=-1).mean()
        
        # 2. 动作幅度
        mag_full[t] = torch.norm(action_chunks[t], p=2, dim=-1).mean()
        mag_exec[t] = torch.norm(executed_actions[t], p=2, dim=-1).mean()
        
    # 应用 EMA 平滑 (伪代码省略 EMA 细节)
    # 加权求和并归一化到 [0, 1] 得到软标签 s_tilde
    s_tilde = normalize_and_clip(consistency + mag_full + mag_exec)
    return s_tilde

def active_learning_selection(detector, unlabeled_trajectories, budget_ratio=0.15):
    """
    基于不确定性的主动学习采样
    """
    uncertainties = []
    for traj in unlabeled_trajectories:
        reps = traj['representations'] # [T, Rep_Dim]
        with torch.no_grad():
            probs = detector(reps) # [T, 1]
            
        # 计算轨迹的平均信息熵
        entropy = -probs * torch.log(probs + 1e-8) - (1 - probs) * torch.log(1 - probs + 1e-8)
        traj_uncertainty = entropy.mean().item()
        uncertainties.append((traj_uncertainty, traj))
        
    # 按不确定性降序排列，选择 Top-K
    uncertainties.sort(key=lambda x: x[0], reverse=True)
    num_select = int(len(unlabeled_trajectories) * budget_ratio)
    selected_trajectories = [item[1] for item in uncertainties[:num_select]]
    
    return selected_trajectories
```

```python
    # 预测动作与注意力图

    total_loss = L_act + lambda_weight * L_reg
```

### 第二模块：核心架构解释

这篇论文并非提出一个新的神经网络，而是提出了一套用于解构和评估所有具身智能与智能体系统的高维架构方法论。作者将任何报告了结果的智能体系统定义为一个配置化的行动系统：$S = (M, H, E, U)$。

1.  **M (Model - 模型):** 负责推理、感知和预测。它只负责“提议”行动，不拥有最终决定权。
2.  **H (Harness - 脚手架):** 将模型转化为行动系统的核心。包含上下文构建、记忆、工具 Schema、凭证代理、审批门控、重试逻辑和恢复程序。它是执行安全策略的实体。
3.  **E (Environment - 环境):** 提供可观察状态、允许的行动、过渡动力学和不可逆的物理/数字后果（如实时网络、模拟器、机器人硬件）。
4.  **U (Delegator - 委托人):** 提供目标和合法授权的实体。委托人承担风险，并保留澄清、批准或接管的权利。

**系统运行与实验评估流程：**
系统不再以“模型是否输出了正确的动作字符串”为评估终点，而是必须经过“外部验证（External Verification）”。模型提出动作 $\rightarrow$ 脚手架验证权限 $\rightarrow$ 环境执行并返回状态 $\rightarrow$ 独立于模型的外部机制核对最终状态是否符合委托人的意图且未产生越界副作用。

**底层逻辑伪代码实现：**

```python
class WorldActingSystem:
    def __init__(self, model, harness, environment, delegator):
        self.M = model          # 基础大模型 (e.g., GPT-4, OpenVLA)
        self.H = harness        # 脚手架 (包含权限、记忆、沙盒、验证器)
        self.E = environment    # 外部环境 (数字API, 物理实验室, 3D世界)
        self.U = delegator      # 委托人 (人类用户或机构)

    def execute_delegated_task(self, task_intent):
        # 1. 委托人下达目标，并授予特定范围的权限凭证
        authority_token, objective = self.U.delegate(task_intent)
        
        # 2. 脚手架基于目标和权限初始化上下文
        context = self.H.build_context(objective, authority_token)
        
        while not self.H.is_terminated():
            # 3. 从环境获取当前真实状态
            obs = self.E.get_state()
            
            # 4. 模型基于上下文和观察，"提议"下一步行动 (模型无权直接执行)
            proposed_action = self.M.infer(context, obs)
            
            # 5. 脚手架拦截并审查该行动：是否越权？是否符合安全策略？
            if self.H.verify_and_authorize(proposed_action, authority_token):
                # 6. 授权通过，环境执行动作并返回物理/数字后果
                result = self.E.step(proposed_action)
                self.H.update_memory(result)
            else:
                # 7. 越权或高风险，触发恢复机制或向委托人升级求助 (Human-in-the-loop)
                self.H.trigger_recovery_or_escalate(self.U)
                break
                
        # 8. 外部客观验证：禁止模型"自圆其说"，必须由外部传感器或独立状态机确认
        final_state = self.E.get_final_state()
        return self.H.external_verify(final_state, objective)
```

```python
import torch
import torch.nn.functional as F

def compute_pairwise_loss(features, pseudo_labels, margin=1.0):
    """
    计算像素级成对度量学习损失 (对应论文 Equation 11 & 12)
    features: [N, C] 归一化后的像素特征 (N为采样像素数)
    pseudo_labels: [N] 对应的伪实例标签 (0为背景)
    """
    # 计算所有采样像素对之间的欧氏距离
    dist_matrix = torch.cdist(features, features, p=2)
    
    # 构建标签匹配矩阵
    label_i = pseudo_labels.unsqueeze(1)
    label_j = pseudo_labels.unsqueeze(0)
    
    # 掩码条件
    is_same_instance = (label_i == label_j) & (label_i != 0)
    is_diff_instance = (label_i != label_j)
    
    # 相同实例的像素：拉近距离
    pull_loss = dist_matrix[is_same_instance] ** 2
    
    # 不同实例的像素：推开距离至 margin
    push_loss = F.relu(margin - dist_matrix[is_diff_instance]) ** 2
    
    # 忽略背景-背景对，计算总平均损失
    total_loss = (pull_loss.sum() + push_loss.sum()) / (is_same_instance.sum() + is_diff_instance.sum())
    
    return total_loss

def motion_verified_self_training(mask_proposal, optical_flow, features, tau_bdry=0.4, tau_int=0.05):
    """
    Cycle-2 运动验证逻辑简写 (对应论文 Equation 5-10)
    """
    # 1. 提取光流幅度边缘
    flow_mag = torch.norm(optical_flow, dim=0)
    flow_edges = compute_gradient_magnitude(flow_mag) > edge_threshold
    
    # 2. 形态学腐蚀获取可靠内部种子
    seed = morphological_erode(mask_proposal)
    seed_feature = compute_mean_feature(features, seed)
    
    # 3. 受限特征生长 (不跨越光流边缘)
    refined_mask = region_growing(seed, features, seed_feature, flow_edges)
    
    # 4. 边界与内部冲突验证
    boundary_pixels = get_boundary(refined_mask)
    interior_pixels = refined_mask ^ boundary_pixels
    
    rho_bdry = (boundary_pixels & flow_edges).sum() / boundary_pixels.sum()
    rho_int = (interior_pixels & flow_edges).sum() / interior_pixels.sum()
    
    if rho_bdry >= tau_bdry and rho_int <= tau_int:
        return refined_mask # 接受该伪标签
    else:
        return None # 拒绝该伪标签
```

### 第二模块：核心架构解释

ACT-Modified 的核心逻辑是在标准 ACT（Action Chunking with Transformers）的基础上，增加显式的视觉引导和注意力约束。其运行流程如下：

1.  **阶段预测与提示选择 (Phase-Gated Selection):** 根据机器人当前的本体感觉（如关节位置）和历史信息，预测当前处于哪个操作阶段（例如：正在抓取还是正在放置）。根据预测结果，从预先提供的视觉提示（目标物体或容器的无位置信息的图像裁剪）中选择当前相关的提示。
2.  **视觉编码 (Vision Encoding):** 将完整的相机观测图像和选中的视觉提示分别通过视觉编码器提取特征，加入位置编码后，作为视觉记忆（Visual Memory）输入给 Transformer 解码器。
3.  **注意力正则化 (Attention Regularization - 仅训练阶段):** 在 Transformer 解码器的交叉注意力层中，提取一个注意力头。计算损失时，强制该注意力头的权重向当前阶段真实目标的掩码（Mask）靠拢，并远离干扰物的掩码。
4.  **动作解码 (Action Decoding):** 解码器结合视觉记忆、学习到的查询向量（Learned Queries）和本体感觉，预测出未来的动作块（Action Chunk）。

**核心底层逻辑伪代码 (Python 风格):**

```python
import torch.nn as nn

class ACT_Modified(nn.Module):
    def __init__(self, vision_encoder, transformer_decoder, phase_predictor):
        super().__init__()
        self.vision_encoder = vision_encoder
        self.decoder = transformer_decoder
        self.phase_predictor = phase_predictor
        
    def forward(self, full_image, prompt_obj, prompt_rec, qpos, 
                target_mask=None, distractor_mask=None, is_training=True):
        
        # 1. 阶段预测：决定当前该关注物体还是容器
        phase_logits = self.phase_predictor(qpos)
        current_phase = torch.argmax(phase_logits, dim=-1) # 0: pick, 1: place
        
        # 2. 门控提示选择
        selected_prompt = torch.where(current_phase == 0, prompt_obj, prompt_rec)
        
        # 3. 视觉特征提取
        img_feat = self.vision_encoder(full_image)
        prompt_feat = self.vision_encoder(selected_prompt)
        visual_memory = torch.cat([img_feat, prompt_feat], dim=1) # 附加位置编码略
        
        # 4. 动作解码与交叉注意力提取
        # attention_maps 形状: [batch, num_heads, query_len, spatial_hw]
        action_chunk, attention_maps = self.decoder(visual_memory, qpos)
        
        if is_training:
            # 提取用于监督的特定注意力头
            supervised_attn = attention_maps[:, 0, :, :] 
            
            # 计算标准 ACT 动作重建损失
            L_act = compute_action_loss(action_chunk, ground_truth_actions)
            # 计算阶段预测损失
            L_phase = compute_cross_entropy(phase_logits, ground_truth_phase)
            
            # 5. 注意力正则化损失 (对应论文公式 1)
            # 鼓励关注目标区域 (1 - 相似度)
            L_pos = 1.0 - compute_overlap(supervised_attn, target_mask)
            # 惩罚关注干扰物区域
            L_neg = compute_overlap(supervised_attn, distractor_mask)
            
            total_loss = L_act + lambda_phi * L_phase + lambda_pos * L_pos + lambda_neg * L_neg
            return action_chunk, total_loss
            
        return action_chunk
```

### 第二模块：核心架构解释

CoLMIN 的整体架构是一个由感知驱动、LLM 居中协商、底层控制器执行的闭环系统。其核心运行流程如下：

1. **感知与冲突检测**：车辆将传感器数据转化为语义描述，预测初始意图。当检测到多车意图存在物理冲突时，触发协商机制。
2. **LMin (多意图协商与评估模块)**：采用 Negotiator-Evaluator 范式。Negotiator（LLM）根据当前状态生成多个候选驾驶方案（扩大解空间）；Evaluator 根据安全、效率和共识度对这些方案进行打分。若有方案达标，则输出共识；若无，则进入反思循环。
3. **ESRM (浅层反思模块)**：针对单轮协商失败，分析低分方案，生成具体的短期修改建议（如“车辆A应减速让行”），直接喂给下一轮的 Negotiator，加速局部收敛。
4. **LDRM (深层反思模块)**：当协商拖延超过预设轮数（陷入僵局），LDRM 介入。它通过审视全局协商历史，识别智能体的“过度自信”或“高频重复”行为，强制注入探索性建议，打破认知固化。
5. **底层控制**：达成共识的高层意图被送入 Waypoint 生成器，转化为几何可行的轨迹点，最终由高频 PID/MPC 控制器输出油门、刹车和转向信号。

```python
            best_score = current_score
            
        # 检查是否达到共识阈值
        if best_score >= THRESHOLD_SUCCESS:
            break
            
        # 3. ESRM 浅层反思 (短期纠错)
        feedback_esrm = ESRM.analyze_and_suggest(evaluated_plans)
        
        # 4. LDRM 深层反思 (长期防固化)
        negotiation_history.append(evaluated_plans)
        if round_idx >= deadlock_threshold:
            if LDRM.detect_cognitive_fixation(negotiation_history):
                feedback_ldrm = LDRM.generate_corrective_guidance(negotiation_history)
                
    # 5. 输出共识并执行底层控制
    return execute_low_level_control(best_so_far_plan)
```

### 第二模块：核心架构解释

LetOccVote 的整体架构分为四个核心步骤，其本质是一个从 2D 噪声观测到 3D 纯净表征的过滤与重建过程。

**1. 特征提取与深度投票 (Depth Vote)**
模型首先提取多帧图像的 2D 特征。为了防止错误的伪深度将特征投影到错误的 3D 位置，模型将当前帧的伪深度投影到 3D 空间，再重投影到相邻帧。如果重投影深度与相邻帧的伪深度在误差允许范围内，则记为“同意”；若差异过大，则记为“矛盾”。只有获得足够多帧“同意”的深度才会被保留并修正，矛盾的深度直接被丢弃。

**2. 特征提升与体素编码 (Feature Lifting)**
利用经过 Depth Vote 清洗后的可靠深度，将 2D 图像特征提升（Unproject）到统一的自我中心 3D 体素网格中。随后通过 3D 编码器（包含可变形自注意力机制）融合空间上下文，生成 3D 体素特征。

**3. 3D 高斯解码 (Gaussian Derivation)**
从被占据的体素中心初始化 3D 查询点，通过解码器与体素特征交互，预测出 3D 高斯原语的各项属性（中心坐标、协方差、不透明度、语义逻辑值）。

**4. 语义投票与掩码监督 (Semantic Vote & Supervision)**
在训练阶段，将多帧的 2D 语义伪标签投影到 3D 体素中进行多数投票。投票一致的特征被归入“可靠特征池”，投票冲突的特征被归入“争议特征池”。计算当前特征与这两个池的余弦相似度，若特征更接近争议池，则在计算语义损失时将该伪标签掩码（Mask）掉，从而避免模型拟合错误的语义。

**核心逻辑伪代码 (Python 风格)**：

```python
def depth_vote(pseudo_depths, poses, intrinsics, k_threshold):
    # pseudo_depths: 多帧伪深度图
    refined_depths = []
    valid_masks = []
    
    for t in range(num_frames):
        # 将当前帧深度投影到3D，再重投影到其他帧
        reprojected_depths = reproject_to_other_frames(pseudo_depths[t], poses, intrinsics)
        
        # 计算一致性与矛盾
        agreements = (abs(reprojected_depths - pseudo_depths) <= tau)
        contradictions = (reprojected_depths < pseudo_depths - tau)
        
        # 统计投票数
        num_agree = sum(agreements)
        num_contradict = sum(contradictions)
        
        # 决策逻辑
        if num_agree >= k_threshold:
            refined_depths.append(consensus_correction(pseudo_depths[t], reprojected_depths))
            valid_masks.append(True)
        elif num_contradict >= k_threshold and num_agree == 0:
            refined_depths.append(0) # 拒绝该深度
            valid_masks.append(False)
        else:
            refined_depths.append(pseudo_depths[t]) # 保持原样
            valid_masks.append(True)
            
    return refined_depths, valid_masks

def semantic_vote(features, pseudo_semantics, reliable_pool, contested_pool, margin):
    # 在3D体素中进行多数投票
    voted_semantics = majority_vote_in_3d(pseudo_semantics)
    
    # 更新特征池 (仅在初始化阶段)
    update_pools(features, pseudo_semantics, voted_semantics, reliable_pool, contested_pool)
    
    # 计算相似度并生成Mask
    sim_reliable = cosine_similarity(features, reliable_pool)
    sim_contested = max_cosine_similarity(features, contested_pool)
    
    # 如果特征更接近争议池，则掩码掉该伪标签
    delta = sim_contested - sim_reliable
    keep_mask = delta <= margin
    
    return keep_mask

# 训练主流程
refined_depths, valid_depth_masks = depth_vote(pseudo_depths, ...)
voxel_features = lift_to_3d(image_features, refined_depths)
gaussians = decode_gaussians(voxel_features)

# 渲染回2D进行监督

semantic_keep_mask = semantic_vote(image_features, pseudo_semantics, ...)

# 计算损失 (仅在有效掩码区域)
loss_depth = compute_l1_loss(rendered_depth, refined_depths, valid_depth_masks)
loss_semantic = compute_ce_loss(rendered_semantic, pseudo_semantics, semantic_keep_mask)
```
