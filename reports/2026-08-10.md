SimWAM 的架构设计奉行极简主义，其核心流程分为两个阶段：**联合流匹配预训练（Imitation Learning）**与**基于 SDE 的强化学习微调（Reinforcement Learning）**。

1. **输入表征**：当前帧图像通过 VAE 编码，导航指令通过 T5 编码，自车状态（速度、加速度等）通过 MLP 编码。
2. **双专家联合训练（Co-training）**：
   - **Video Expert**：预测未来 $N$ 帧的视频潜变量。
   - **Action Expert**：预测未来 $H$ 步的自车轨迹。
   - 两者通过 Flow Matching（流匹配）联合优化。关键在于**隔离注意力掩码**：未来视频 Token 和动作 Token 都可以 Cross-Attend 到当前帧的表征上，但视频 Token 和动作 Token 之间被 Mask 阻断。
3. **推理与强化学习（Inference & RL）**：
   - 训练结束后，直接丢弃 Video Expert。
   - 为了突破模仿学习的上限，将确定性的常微分方程（ODE）转换为随机微分方程（SDE）以引入轨迹采样的多样性。
   - 使用 Flow-GRPO 算法，基于 NAVSIM 的 PDM 奖励函数对 Action Expert 的 LoRA 权重进行强化学习微调。

```python
import torch
import torch.nn as nn

class SimWAM(nn.Module):
    def __init__(self, video_expert, action_expert):
        super().__init__()
        self.video_expert = video_expert # e.g., Wan2.2-5B DiT
        self.action_expert = action_expert # Lightweight DiT (hidden=1024)
        
    def generate_isolated_mask(self, num_obs, num_video, num_action):
        """
        构建隔离注意力掩码：
        - 视频和动作都可以看到观测 (obs)
        - 视频和动作彼此不可见
        """
        total_len = num_obs + num_video + num_action
        mask = torch.ones((total_len, total_len), dtype=torch.bool)
        
        # 阻断 Video 关注 Action
        mask[num_obs:num_obs+num_video, num_obs+num_video:] = False
        # 阻断 Action 关注 Video
        mask[num_obs+num_video:, num_obs:num_obs+num_video] = False
        return mask

    def forward_train(self, obs_tokens, noisy_video, noisy_action, t_video, t_action):
        """联合训练阶段"""
        num_obs = obs_tokens.shape[1]
        num_video = noisy_video.shape[1]
        num_action = noisy_action.shape[1]
        
        # 拼接所有 Token
        concat_tokens = torch.cat([obs_tokens, noisy_video, noisy_action], dim=1)
        attn_mask = self.generate_isolated_mask(num_obs, num_video, num_action)
        
        # 视频专家预测视频流 (Flow Matching)
        video_velocity = self.video_expert(concat_tokens, t_video, mask=attn_mask)
        
        # 动作专家预测轨迹流 (Flow Matching)
        action_velocity = self.action_expert(concat_tokens, t_action, mask=attn_mask)
        
        return video_velocity, action_velocity

    def forward_inference(self, obs_tokens, noisy_action, t_action):
        """推理阶段：完全丢弃 Video Expert"""
        # 仅拼接观测和动作 Token
        concat_tokens = torch.cat([obs_tokens, noisy_action], dim=1)
        
        # 仅运行轻量级动作专家
        action_velocity = self.action_expert(concat_tokens, t_action)
        return action_velocity
```

### 第二模块：核心架构解释

WorldTrace 的核心架构通过对 KV Cache 的结构化重组与特征空间的坐标系转换，实现了免训练的长程记忆保持。其处理流程分为以下客观步骤：

1. **缓存划分 (Cache Partitioning)**：将总容量固定的 KV Cache 划分为两个独立区域：保留最新生成帧原始特征的“近期窗口 (Recent Window)”，以及用于存储压缩历史特征的“摘要槽 (Summary Cache)”。
2. **虚拟位置分配 (Virtual Position Assignment)**：为每一个摘要槽分配一个固定的相对位置索引。该索引严格限制在模型预训练时见过的最大序列长度范围内，确保注意力机制始终能够正确计算权重。
3. **规范化空间还原 (Unrotation to Canonical Space)**：当近期窗口的特征被挤出时，提取其键值 (Key)，并应用逆向旋转矩阵，消除其原有的 RoPE 旋转角度，将其还原为不包含任何时间位置信息的纯内容特征。
4. **内容写入 (Content Writing)**：
   - **Field 模式**：将多个连续被挤出帧的纯内容特征进行数学平均，存入对应的摘要槽，用于保持长程的时间连贯性。
   - **Landmark 模式**：计算相邻帧纯内容特征的余弦距离，当距离超过阈值时判定为场景切换。直接将该帧的纯内容特征冻结并存入摘要槽，用于特定场景的精确召回。
5. **重新旋转与读取 (Re-rotation and Reading)**：在生成新帧计算注意力时，提取摘要槽中的纯内容特征，并根据步骤 2 中分配的虚拟位置，重新对其应用 RoPE 旋转矩阵。随后将其输入标准的注意力计算流程。

```python
    def update_cache_field_mode(self, new_kv, current_pos):
        self.recent_window.append((new_kv, current_pos))
        
        if len(self.recent_window) > self.N_r:
            # 挤出最旧的帧
            evicted_kv, evicted_pos = self.recent_window.pop(0)
            evicted_key = evicted_kv['key']
            
            # 还原为纯内容特征
            canonical_key = self.unrotate(evicted_key, evicted_pos)
            
            # 步骤4 (Field模式): 将纯内容特征平均合并到对应的摘要槽中
            target_slot_idx = compute_target_slot(evicted_pos) 
            if self.summary_slots[target_slot_idx] is None:
                self.summary_slots[target_slot_idx] = canonical_key
            else:
                self.summary_slots[target_slot_idx] = average_features(
                    self.summary_slots[target_slot_idx], canonical_key
                )

    def get_attention_keys(self, current_query_pos):
        # 构建供当前查询使用的最终 Key 集合
        final_keys = []
        
        # 处理摘要槽
        v_positions = self.get_virtual_positions(current_query_pos)
        for s in range(self.N_s):
            if self.summary_slots[s] is not None:
                # 重新旋转
                ready_key = self.re_rotate(self.summary_slots[s], v_positions[s])
                final_keys.append(ready_key)
                
        # 处理近期窗口 (保持原样)
        for kv, _ in self.recent_window:
            final_keys.append(kv['key'])
            
        return torch.cat(final_keys, dim=sequence_length_dim)
```

### 第二模块：核心架构解释

WNM-3D 的核心架构是一个联合流匹配（Joint Flow Matching）生成框架，其运行流程可拆解为以下三个阶段：

**1. 历史前缀构建 (History Prefix Construction)**
模型接收过去 $K$ 帧单目 RGB 图像。首先通过冻结的 VGGT-$\Omega$ 编码器提取多层级的 3D 几何特征网格。随后，通过可训练的 3D 场景到 Token 适配器（包含特征融合、可变形重采样和时空细化），将这些网格压缩为固定长度的 Token 序列 $C_t$。

**2. 联合潜在世界-动作建模 (Joint Latent World-Action Modeling)**
当前帧图像和语言指令通过交叉注意力编码为上下文 $G_t$。未来的视觉帧通过 VAE 编码为潜在变量，未来的动作序列被归一化并填充为固定宽度的向量。视觉和动作被划分为 $B$ 个对齐的时间块（Blocks），在训练时注入独立的连续时间步噪声。

**3. 块因果注意力去噪 (Block-Causal Attention Denoising)**
在 DiT 内部，历史前缀 $C_t$、当前帧上下文、以及加噪后的未来视觉与动作 Token 被拼接。注意力掩码被严格限制：前缀只能关注自身；第 $b$ 个时间块的视觉和动作 Token 可以双向交互，但只能关注前缀、第 0 块以及时间步 $\le b$ 的块。这保证了生成的因果性。

### 第二模块：核心架构解释

SimWAM 的架构设计奉行极简主义，其核心流程分为两个阶段：**联合流匹配预训练（Imitation Learning）**与**基于 SDE 的强化学习微调（Reinforcement Learning）**。

1. **输入表征**：当前帧图像通过 VAE 编码，导航指令通过 T5 编码，自车状态（速度、加速度等）通过 MLP 编码。
2. **双专家联合训练（Co-training）**：
   - **Video Expert**：预测未来 $N$ 帧的视频潜变量。
   - **Action Expert**：预测未来 $H$ 步的自车轨迹。
   - 两者通过 Flow Matching（流匹配）联合优化。关键在于**隔离注意力掩码**：未来视频 Token 和动作 Token 都可以 Cross-Attend 到当前帧的表征上，但视频 Token 和动作 Token 之间被 Mask 阻断。
3. **推理与强化学习（Inference & RL）**：
   - 训练结束后，直接丢弃 Video Expert。
   - 为了突破模仿学习的上限，将确定性的常微分方程（ODE）转换为随机微分方程（SDE）以引入轨迹采样的多样性。
   - 使用 Flow-GRPO 算法，基于 NAVSIM 的 PDM 奖励函数对 Action Expert 的 LoRA 权重进行强化学习微调。

**核心伪代码（Python 风格）**：

```python
import torch
import torch.nn as nn

class SimWAM(nn.Module):
    def __init__(self, video_expert, action_expert):
        super().__init__()
        self.video_expert = video_expert # e.g., Wan2.2-5B DiT
        self.action_expert = action_expert # Lightweight DiT (hidden=1024)
        
    def generate_isolated_mask(self, num_obs, num_video, num_action):
        """
        构建隔离注意力掩码：
        - 视频和动作都可以看到观测 (obs)
        - 视频和动作彼此不可见
        """
        total_len = num_obs + num_video + num_action
        mask = torch.ones((total_len, total_len), dtype=torch.bool)
        
        # 阻断 Video 关注 Action
        mask[num_obs:num_obs+num_video, num_obs+num_video:] = False
        # 阻断 Action 关注 Video
        mask[num_obs+num_video:, num_obs:num_obs+num_video] = False
        return mask

    def forward_train(self, obs_tokens, noisy_video, noisy_action, t_video, t_action):
        """联合训练阶段"""
        num_obs = obs_tokens.shape[1]
        num_video = noisy_video.shape[1]
        num_action = noisy_action.shape[1]
        
        # 拼接所有 Token
        concat_tokens = torch.cat([obs_tokens, noisy_video, noisy_action], dim=1)
        attn_mask = self.generate_isolated_mask(num_obs, num_video, num_action)
        
        # 视频专家预测视频流 (Flow Matching)
        video_velocity = self.video_expert(concat_tokens, t_video, mask=attn_mask)
        
        # 动作专家预测轨迹流 (Flow Matching)
        action_velocity = self.action_expert(concat_tokens, t_action, mask=attn_mask)
        
        return video_velocity, action_velocity

    def forward_inference(self, obs_tokens, noisy_action, t_action):
        """推理阶段：完全丢弃 Video Expert"""
        # 仅拼接观测和动作 Token
        concat_tokens = torch.cat([obs_tokens, noisy_action], dim=1)
        
        # 仅运行轻量级动作专家
        action_velocity = self.action_expert(concat_tokens, t_action)
        return action_velocity
        
    def sample_trajectory_sde(self, obs_tokens, num_steps=10):
        """RL阶段：使用 SDE 进行多样化轨迹采样以计算 GRPO Reward"""
        x_t = torch.randn(batch_size, action_seq_len, dim)
        for t in reversed(range(num_steps)):

            x_t = euler_maruyama_step(x_t, velocity, t) 
        return x_t
```

### 第二模块：核心架构解释

WorldTrace 的核心架构通过对 KV Cache 的结构化重组与特征空间的坐标系转换，实现了免训练的长程记忆保持。其处理流程分为以下客观步骤：

1. **缓存划分 (Cache Partitioning)**：将总容量固定的 KV Cache 划分为两个独立区域：保留最新生成帧原始特征的“近期窗口 (Recent Window)”，以及用于存储压缩历史特征的“摘要槽 (Summary Cache)”。
2. **虚拟位置分配 (Virtual Position Assignment)**：为每一个摘要槽分配一个固定的相对位置索引。该索引严格限制在模型预训练时见过的最大序列长度范围内，确保注意力机制始终能够正确计算权重。
3. **规范化空间还原 (Unrotation to Canonical Space)**：当近期窗口的特征被挤出时，提取其键值 (Key)，并应用逆向旋转矩阵，消除其原有的 RoPE 旋转角度，将其还原为不包含任何时间位置信息的纯内容特征。
4. **内容写入 (Content Writing)**：
   - **Field 模式**：将多个连续被挤出帧的纯内容特征进行数学平均，存入对应的摘要槽，用于保持长程的时间连贯性。
   - **Landmark 模式**：计算相邻帧纯内容特征的余弦距离，当距离超过阈值时判定为场景切换。直接将该帧的纯内容特征冻结并存入摘要槽，用于特定场景的精确召回。
5. **重新旋转与读取 (Re-rotation and Reading)**：在生成新帧计算注意力时，提取摘要槽中的纯内容特征，并根据步骤 2 中分配的虚拟位置，重新对其应用 RoPE 旋转矩阵。随后将其输入标准的注意力计算流程。

```python
# WorldTrace 核心逻辑伪代码
import torch

class WorldTraceCache:
    def __init__(self, num_summary_slots, recent_window_size, max_train_len):
        self.N_s = num_summary_slots
        self.N_r = recent_window_size
        self.max_train_len = max_train_len
        
        # 缓存初始化
        self.recent_window = [] # 存储原始 KV
        self.summary_slots = [None] * self.N_s # 存储规范化(纯内容) Key
        
    def get_virtual_positions(self, current_query_pos):
        # 步骤2: 分配分布内的固定虚拟位置
        virtual_positions = []
        for s in range(self.N_s):
            # 确保位置偏移在训练范围内
            v_pos = current_query_pos - (self.N_s + self.N_r - 1 - s)
            virtual_positions.append(v_pos)
        return virtual_positions

    def unrotate(self, key, original_pos):
        # 步骤3: 逆向消除 RoPE 旋转，还原为纯内容特征
        inverse_rope_matrix = get_rope_matrix(-original_pos)
        canonical_key = apply_rotation(key, inverse_rope_matrix)
        return canonical_key

    def re_rotate(self, canonical_key, virtual_pos):
        # 步骤5: 根据虚拟位置重新应用 RoPE 旋转
        rope_matrix = get_rope_matrix(virtual_pos)
        rotated_key = apply_rotation(canonical_key, rope_matrix)
        return rotated_key

    def update_cache_field_mode(self, new_kv, current_pos):
        self.recent_window.append((new_kv, current_pos))
        
        if len(self.recent_window) > self.N_r:
            # 挤出最旧的帧
            evicted_kv, evicted_pos = self.recent_window.pop(0)
            evicted_key = evicted_kv['key']
            
            # 还原为纯内容特征
            canonical_key = self.unrotate(evicted_key, evicted_pos)
            
            # 步骤4 (Field模式): 将纯内容特征平均合并到对应的摘要槽中
            target_slot_idx = compute_target_slot(evicted_pos) 
            if self.summary_slots[target_slot_idx] is None:
                self.summary_slots[target_slot_idx] = canonical_key
            else:
                self.summary_slots[target_slot_idx] = average_features(
                    self.summary_slots[target_slot_idx], canonical_key
                )

    def get_attention_keys(self, current_query_pos):
        # 构建供当前查询使用的最终 Key 集合
        final_keys = []
        
        # 处理摘要槽
        v_positions = self.get_virtual_positions(current_query_pos)
        for s in range(self.N_s):
            if self.summary_slots[s] is not None:
                # 重新旋转
                ready_key = self.re_rotate(self.summary_slots[s], v_positions[s])
                final_keys.append(ready_key)
                
        # 处理近期窗口 (保持原样)
        for kv, _ in self.recent_window:
            final_keys.append(kv['key'])
            
        return torch.cat(final_keys, dim=sequence_length_dim)
```

### 第二模块：核心架构解释

WNM-3D 的核心架构是一个联合流匹配（Joint Flow Matching）生成框架，其运行流程可拆解为以下三个阶段：

**1. 历史前缀构建 (History Prefix Construction)**
模型接收过去 $K$ 帧单目 RGB 图像。首先通过冻结的 VGGT-$\Omega$ 编码器提取多层级的 3D 几何特征网格。随后，通过可训练的 3D 场景到 Token 适配器（包含特征融合、可变形重采样和时空细化），将这些网格压缩为固定长度的 Token 序列 $C_t$。

**2. 联合潜在世界-动作建模 (Joint Latent World-Action Modeling)**
当前帧图像和语言指令通过交叉注意力编码为上下文 $G_t$。未来的视觉帧通过 VAE 编码为潜在变量，未来的动作序列被归一化并填充为固定宽度的向量。视觉和动作被划分为 $B$ 个对齐的时间块（Blocks），在训练时注入独立的连续时间步噪声。

**3. 块因果注意力去噪 (Block-Causal Attention Denoising)**
在 DiT 内部，历史前缀 $C_t$、当前帧上下文、以及加噪后的未来视觉与动作 Token 被拼接。注意力掩码被严格限制：前缀只能关注自身；第 $b$ 个时间块的视觉和动作 Token 可以双向交互，但只能关注前缀、第 0 块以及时间步 $\le b$ 的块。这保证了生成的因果性。

```python
    # 1. 构建 3D 几何历史前缀
    with torch.no_grad():
        geo_features = vggt_omega_encoder(history_rgb)
    # 适配器：融合 -> 可变形重采样 -> 时空自注意力 -> 投影
    prefix_tokens = scene_to_token_adapter(geo_features) # Shape: [Batch, Nc, d]
    
    # 2. 编码当前上下文
    context_tokens = cross_attention_encoder(current_rgb, instruction)
    
    # 3. 准备目标变量并加噪 (Flow Matching)
    video_latents = vae_encode(future_video)
    action_vectors = normalize_and_pad(future_actions)
    
    noisy_video = add_noise(video_latents, noise_levels['video'])
    noisy_actions = add_noise(action_vectors, noise_levels['action'])
    
    # 将变量按时间块 (Blocks) 序列化拼接
    # sequence = [Prefix, Block_0_Video, Block_1_Video, ..., Block_B_Video, Block_1_Action, ..., Block_B_Action]
    input_sequence = serialize_blocks(prefix_tokens, noisy_video, noisy_actions)
    
    # 4. 生成块因果注意力掩码
    # 规则：Block b 只能 attend 到 Prefix, Block 0, 以及 Block i (i <= b)
    causal_mask = generate_block_causal_mask(num_blocks=B, prefix_len=Nc)
    
    # 5. DiT 联合去噪预测速度场 (Velocity fields)
    pred_video_velocity, pred_action_velocity = shared_world_action_dit(
        input_sequence, 
        context=context_tokens, 
        mask=causal_mask
    )
    
    # 6. 计算 Flow Matching 损失
    loss_video = mse_loss(pred_video_velocity, target_video_velocity)
    loss_action = mse_loss(pred_action_velocity, target_action_velocity)
    
    return loss_video + lambda_a * loss_action
```

```python
    # 7. 总损失优化
    total_loss = loss_fm_nominal + loss_fm_perturbed + lambda_c * loss_consistency
    
    total_loss.backward()
    optimizer.step()
    
    return total_loss
```

### 第二模块：核心架构解释

DPWM 的核心逻辑是构建一个非递归的计算图，使得无论预测跨度 $K$ 有多大，梯度反向传播的深度始终固定。模型由四个标准组件构成：

1. **观测编码器 (Observation Encoder, $E$)**：将初始时刻的原始观测 $o_t$（状态向量或像素图像）映射为隐状态 $s_t$。
2. **动作序列编码器 (Action Sequence Encoder, $\phi$)**：接收变长动作序列 $a_{t:t+K-1}$。通过带有旋转位置编码（RoPE）的非因果 Transformer 处理，最后通过平均池化（Mean Pooling）将整个序列压缩为一个固定维度的动作嵌入向量 $z_a$。
3. **动力学模块 (Dynamics Module, $g$)**：一个基于 FiLM 调节的残差 MLP。它接收初始隐状态 $s_t$ 和动作嵌入 $z_a$，直接输出 $K$ 步后的预测隐状态 $\hat{s}_{t+K}$。此过程不生成任何中间状态。
4. **解码器 (Decoder, $D$)**：将预测的隐状态 $\hat{s}_{t+K}$ 映射回观测空间，得到最终预测 $\hat{o}_{t+K}$。

**伪代码实现逻辑**：

```python
import torch
import torch.nn as nn

class DPWM(nn.Module):
    def __init__(self, obs_encoder, action_encoder, dynamics_mlp, obs_decoder):
        super().__init__()
        self.E = obs_encoder       # e.g., CNN or MLP
        self.phi = action_encoder  # e.g., RoPE Transformer + Mean Pooling
        self.g = dynamics_mlp      # e.g., FiLM-conditioned MLP
        self.D = obs_decoder       # e.g., Transposed CNN or MLP

    def forward(self, o_t, actions_seq):
        # o_t: [batch_size, obs_dim]
        # actions_seq: [batch_size, K, action_dim]
        
        # 1. Encode initial observation
        s_t = self.E(o_t) 
        
        # 2. Compress the entire action sequence into a single embedding
        z_a = self.phi(actions_seq) 
        
        # 3. Predict endpoint latent state directly (No recursive loop)
        s_hat_tK = self.g(s_t, z_a) 
        
        # 4. Decode to endpoint observation
        o_hat_tK = self.D(s_hat_tK) 
        
        return o_hat_tK

# Training Loop Snippet
def train_step(model, optimizer, batch):
    # batch contains: initial_obs, action_sequence (length K), target_obs (at step K)
    o_t, actions_seq, o_tK_target = batch
    
    optimizer.zero_grad()
    
    # Single forward pass for endpoint
    o_tK_pred = model(o_t, actions_seq)
    
    # End-to-end endpoint reconstruction loss
    loss = nn.MSELoss()(o_tK_pred, o_tK_target)
    
    # Backward pass: gradient path depth is independent of K
    loss.backward()
    optimizer.step()
    
    return loss.item()
```

### 第二模块：核心架构解释

UniJEPA 的核心逻辑在于“多任务归一”。模型不再为不同模态设计复杂的独立管线，而是将所有预测行为抽象为潜在空间中的状态转移。

1.  **共享编码器 (Shared Encoder, $f_\theta$)**：将原始像素输入（图像或视频帧）映射到紧凑的潜在空间。
2.  **共享预测器 (Shared Predictor, $g_\psi$)**：接收当前潜在表征以及条件信号（光度变换参数 $\tau$ 或动作 $a_t$），预测目标潜在表征。
3.  **双分支预测 (Two-branch Prediction)**：
    *   **光度预测分支**：给定图像表征和变换参数（如亮度调整），预测变换后的图像表征。这迫使模型学习空间结构的不变性（Invariant structure）。
    *   **时序预测分支**：给定当前帧表征和动作，预测下一帧表征。这迫使模型学习动态演化的等变性（Equivariant dynamics）。
4.  **防坍塌正则化 (Anti-collapse Regularizer)**：强制共享潜在分布在随机投影方向上接近球形高斯分布，以此替代 EMA 等启发式技巧。

**核心伪代码 (Python 风格)：**

```python
import torch
import torch.nn as nn

def unijepa_train_step(encoder, predictor, batch, alpha=1.0):
    # batch 包含光度数据 (x, tau) 和时序数据 (x_t, a_t, x_t1)
    x, tau = batch['photo']
    x_t, a_t, x_t1 = batch['temp']
    
    # 1. 光度预测分支 (Photometric Prediction)
    z_photo = encoder(x)
    z_photo_target = encoder(apply_transform(x, tau)).detach() # 目标特征
    z_photo_pred = predictor(z_photo, condition=tau)
    loss_photo = nn.MSELoss()(z_photo_pred, z_photo_target)
    
    # 2. 时序预测分支 (Temporal Prediction)
    z_temp = encoder(x_t)
    z_temp_target = encoder(x_t1).detach() # 目标特征
    z_temp_pred = predictor(z_temp, condition=a_t)
    loss_temp = nn.MSELoss()(z_temp_pred, z_temp_target)
    
    # 3. 防坍塌高斯正则化 (Gaussian Regularizer)
    # 将特征投影到随机单位向量 u 上，计算与标准正态分布的马哈拉诺比斯距离偏差
    z_all = torch.cat([z_photo, z_temp], dim=0)
    u = torch.randn(z_all.size(-1), device=z_all.device)
    u = u / torch.norm(u)
    proj = torch.matmul(z_all, u)
    loss_reg = torch.mean((proj ** 2)) # 简化表示，迫使方差非零且分布均匀
    
    # 4. 统一目标函数
    total_loss = loss_photo + loss_temp + alpha * loss_reg
    
    total_loss.backward()
    return total_loss
```

### 第二模块：核心架构解释

PILOT 的架构设计体现了极强的工程与理论解耦思维。其核心在于将训练时的“重度监督”与推理时的“轻量生成”分离开来。

**模型架构与流程：**

1.  **世界模型分支 (World-Model Branch):** 基于 Wan2.2 架构，作为视觉-语言编码器。输入当前观测图像和文本指令，输出统一的视觉-语言上下文 Token。
2.  **动作感知分支 (Action-Perceiver Branch):** 这是动作生成的核心。引入一组可学习的 Query Token，通过“因果解耦注意力机制（Causally-decoupled attention）”从上下文中提取运动语义（Motion CoT）。解耦注意力的绝妙之处在于：它允许 Query 提取视觉信息，但严格阻断动作扩散过程中的噪声反向泄漏到 Query 中，保证了运动意图的纯粹性。随后，基于这些 Motion CoT，使用流匹配（Flow-matching）解码器生成底层动作轨迹。
3.  **表征推演分支 (Representational Deduction Branch, 仅训练时启用):** 引入一个轻量级的因果动力学引擎（CDE）。它接收当前帧的 VJEPA 隐特征和提取出的 Motion CoT，预测未来帧的 VJEPA 隐特征。因为 VJEPA 空间本身过滤了纹理细节而保留了物理结构，这一步强制 Motion CoT 必须学会“物理状态是如何转移的”。

**实验流程：**
训练阶段，三个分支联合优化，RD 分支和未来帧预测提供强大的物理与视觉监督信号。推理阶段，直接砍掉 RD 分支和未来帧生成，仅保留“编码器 -> 提取 Motion CoT -> 流匹配生成动作”的极简路径。

**核心逻辑伪代码 (Python 风格):**

```python
def pilot_forward_train(obs_t, obs_future, instruction, action_noisy, flow_time):
    # 1. World-Model Branch: 提取视觉-语言上下文
    context = wan2_2_encoder(obs_t, instruction) # [B, N_c, D]
    
    # 2. Action-Perceiver Branch: 提取 Motion CoT 并防止噪声泄漏
    # 初始化可学习的 Queries 和 状态 Token
    queries = learnable_queries # [B, K, D]
    state_token = get_state_token(robot_state)
    
    # 因果解耦注意力 (核心创新实现)
    # queries 仅关注 context 和自身，不关注 action_noisy
    motion_cot = decoupled_attention(
        query=concat([state_token, queries]), 
        key_value=context, 
        prevent_noise_leakage=True
    ) 
    
    # 动作 Token 关注 motion_cot 和 context，并注入 flow_time
    action_features = action_attention(
        query=action_noisy, 
        key_value=concat([context, motion_cot]), 
        time_emb=flow_time
    )
    
    # 流匹配预测速度场
    velocity_pred = flow_matching_decoder(action_features)
    loss_action = mse_loss(velocity_pred, target_velocity)
    
    # 3. Representational Deduction (RD) Branch: 动力学监督
    # 冻结的 VJEPA 提取当前和未来真实隐状态
    with torch.no_grad():
        latent_t = vjepa_encoder(obs_t)
        latent_future_gt = vjepa_encoder(obs_future)
    
    # CDE 预测未来隐状态，强制 motion_cot 包含状态转移信息
    latent_future_pred = causal_dynamics_engine(latent_t, motion_cot)
    loss_rd = smooth_l1_loss(latent_future_pred, latent_future_gt)
    
    return loss_action + lambda_rd * loss_rd

def pilot_inference(obs_t, instruction):
    # 推理时，完全丢弃 RD 分支和未来帧预测
    context = wan2_2_encoder(obs_t, instruction)
    motion_cot = decoupled_attention(concat([state_token, learnable_queries]), context)
    
    # 从纯噪声开始，基于 motion_cot 进行 Euler 积分求解动作轨迹
    action = sample_gaussian_noise()
    for t in flow_matching_steps:
        velocity = flow_matching_decoder(action, context, motion_cot, t)
        action = action + velocity * dt
        
    return action
```

### 第二模块：核心架构解释

TEMPO 的核心架构建立在模块化 VLA（本文实例化为 FLOWER 模型）之上，其运行与训练流程如下：

1. **状态编码（冻结）：** 视觉观察 $o_t$ 和语言指令 $l_t$ 输入到冻结的 VLM 中，输出多模态语义表征 $h_t$。
2. **语义投影（慢速更新）：** 语义投影层 $\pi_\theta^s$ 接收 $h_t$，输出潜在动作（Latent Action）$z_t$。该层由一个独立的 TD3 算法循环控制，更新频率较低，以保证潜在动作空间的稳定性。
3. **动作生成（快速更新）：** 动作专家层 $\pi_\phi^a$ 接收 $z_t$，输出机器人执行的物理动作块 $a_t$。该层由另一个独立的 TD3 算法循环控制，更新频率较高，以快速拟合环境的控制反馈。
4. **梯度隔离：** 在更新动作专家层时，输入的 $z_t$ 被执行停止梯度（Stop-Gradient）操作，确保动作层的误差不会反向传播到语义投影层。

```python
        actor_a_loss.backward()
        action_optimizer.step()
        update_target_networks(action_actor)

    if update_step % freq_semantic == 0:
        actor_s_loss = -semantic_critic.Q1(h_t, semantic_actor(h_t)).mean()
        semantic_optimizer.zero_grad()
        actor_s_loss.backward()
        semantic_optimizer.step()
```

```python
class CapekFramework:
    def __init__(self, shared_backbone):
        self.backbone = shared_backbone
        self.capabilities = ['spatial', 'temporal', 'action', 'verification']
        self.specialists = {}

    def train_specialists_via_rl(self, datasets, reward_funcs):
        # 阶段一：基于可验证奖励的 RL 训练独立专家
        for cap in self.capabilities:
            specialist = clone_model(self.backbone)
            # 使用 RL 算法针对特定能力进行优化，避免多任务梯度冲突
            self.specialists[cap] = rl_optimize(
                model=specialist,
                data=datasets[cap],
                reward_fn=reward_funcs[cap]
            )
        return self.specialists

    def weight_space_merge(self):
        # 阶段二：权重空间合并，初始化统一模型
        merged_weights = self.backbone.weights.copy()
        for cap, specialist in self.specialists.items():
            # 计算专家模型相对于骨干网络的权重增量
            delta_w = specialist.weights - self.backbone.weights
            merged_weights += merge_coefficient * delta_w
        unified_model = load_weights(merged_weights)
        return unified_model

    def routed_policy_distillation(self, unified_model, datasets):
        # 阶段三：路由策略空间蒸馏
        for batch in sample_mixed_batches(datasets):
            cap_type = batch.capability_type
            expert = self.specialists[cap_type]
            
            # 获取专家策略分布 (Teacher)
            expert_logits = expert.forward(batch.inputs)
            
            # 获取统一模型策略分布 (Student)
            student_logits = unified_model.forward(batch.inputs)
            
            # 计算 KL 散度损失并反向传播更新统一模型
            loss = kl_divergence(student_logits, expert_logits)
            unified_model.backward_and_step(loss)
            
        return unified_model
```

**冗余剪枝策略 (Layer Pruning)**
计算每一层对 Planning Token 的“旋转”程度（输入输出的余弦相似度）。余弦值越高，说明该层对 Token 的方向改变越小，冗余度越高。优先移除这些高余弦值的层，从而在不微调的情况下实现物理加速。

```python
import torch
import torch.nn.functional as F

def depth_wise_probing_and_pruning(decoder_layers, frozen_planner, perception_tokens, text_prompt, planning_token_emb):
    """
    核心逻辑：逐层探测 Planning Token 并计算层级冗余度用于剪枝
    """
    hidden_states = []
    # 拼接多模态输入与 Planning Token
    current_state = torch.cat([perception_tokens, text_prompt, planning_token_emb], dim=1)
    
    # 1. 逐层前向传播与探测 (Probing)
    layer_cosines = []
    for i, layer in enumerate(decoder_layers):
        input_state = current_state
        current_state = layer(input_state)
        
        # 提取当前层的 Planning Token (序列最后一个 Token)
        pt_in = input_state[:, -1, :]
        pt_out = current_state[:, -1, :]
        
        # 记录该层对 Planning Token 的旋转程度 (余弦相似度)
        # 余弦值越接近 1，说明该层对规划表征的改变越小 (越冗余)
        cos_sim = F.cosine_similarity(pt_in, pt_out, dim=-1)
        layer_cosines.append((i, cos_sim.item()))
        
        # 轨迹空间 Logit Lens: 用最终的冻结规划器解码中间层 Token
        # 观察早期层是否已经具备生成合理轨迹的能力
        intermediate_trajectory = frozen_planner(pt_out)
        hidden_states.append(intermediate_trajectory)
        
    # 2. 基于余弦相似度的剪枝 (Pruning)
    # 按余弦相似度降序排列 (优先剪枝改变最小的层)
    layer_cosines.sort(key=lambda x: x[1], reverse=True)
    
    # 设定剪枝层数 k=8
    k = 8
    pruned_layer_indices = [idx for idx, _ in layer_cosines[:k]]
    
    # 构建剪枝后的新解码器 (直接跳过冗余层)
    pruned_decoder = [layer for i, layer in enumerate(decoder_layers) if i not in pruned_layer_indices]
    
    return hidden_states, pruned_decoder
```

### 第二模块：核心架构解释

PSG-JEPA 的核心架构保留了标准 JEPA 的前向预测通路，并通过引入两个仅在训练阶段使用的预测头来实现物理状态对齐。

**架构与流程拆解**：
1. **基础前向预测 (Forward JEPA)**：给定上下文观测图像，共享编码器提取潜变量。动作条件预测器根据历史潜变量和动作，自回归地预测未来的潜变量。
2. **静态状态对齐 (Static State Grounding)**：引入一个轻量级的状态头（State Head）。该网络分支接收单个时间步的潜变量，直接回归对应的机器人本体感受状态（包含关节角度、夹爪状态、末端执行器位姿）。
3. **动态过渡对齐 (Dynamic Transition Grounding)**：引入一个过渡头（Transition Head）。该网络分支接收同一轨迹中不同时间步的两个潜变量（潜变量对），直接回归这两个时间步之间真实的关节角度变化量（$\Delta q$）。该对齐在多个时间跨度（horizon）上同时进行。
4. **推理部署 (Inference)**：训练完成后，状态头和过渡头被完全丢弃。下游的规划器或策略网络仅使用冻结或微调的共享编码器，推理架构和计算开销与基线模型完全一致。

**核心逻辑伪代码**：
```python
def compute_psg_jepa_loss(observations, actions, proprioceptive_states, joint_angles, 
                          encoder, predictor, state_head, transition_head, horizons):
    # 1. 基础前向预测 (Forward JEPA)
    latents = encoder(observations) # 提取所有帧的潜变量 [T, D]
    pred_latents = predictor(latents[:context_len], actions[:context_len]) 
    loss_fwd = mse_loss(pred_latents, latents[context_len:])
    loss_jepa = loss_fwd + sigreg_loss(latents) # 包含防坍塌正则化

    # 2. 静态状态对齐 (Static State Grounding)
    pred_states = state_head(latents)
    loss_static = mse_loss(pred_states, proprioceptive_states)

    # 3. 动态过渡对齐 (Dynamic Transition Grounding)
    loss_dynamic = 0
    for k in horizons: # 遍历不同的时间跨度，例如 k=1, 2, 3
        valid_pairs_count = 0
        for i in range(len(latents) - k):
            z_start, z_end = latents[i], latents[i+k]
            delta_q_true = joint_angles[i+k] - joint_angles[i] # 真实的关节角度变化
            delta_q_pred = transition_head(z_start, z_end)
            loss_dynamic += mse_loss(delta_q_pred, delta_q_true)
            valid_pairs_count += 1
        loss_dynamic /= valid_pairs_count # 对当前跨度求平均
    loss_dynamic /= len(horizons)

    # 4. 总体损失计算
    lambda_g = 0.1 # 对齐权重
    total_loss = loss_jepa + lambda_g * (loss_static + loss_dynamic)
    
    return total_loss
```

# 第二模块：核心架构解释

**基础架构 (JEPA Backbone)**
模型采用联合嵌入预测架构（JEPA）。编码器将当前观测映射到潜空间状态 $z_t$，预测器根据 $z_t$ 和执行的动作 $a_t$ 预测下一步的潜状态 $\hat{z}_{t+1}$。目标网络通过指数移动平均（EMA）进行动量更新，全程无解码器、无重建损失。

**动作分解预测器 (Action-Decomposed Predictor)**
传统的单体预测器 $P(z, a)$ 会将动作后果与环境自主演化（干扰）纠缠在一起。本文将其拆解为两个独立的头：
1. 被动头 $B(z_t)$：预测边缘化动作后的场景演化（即无论执行什么动作都会发生的变化）。
2. 动作偏移头 $\Delta(z_t, a_t)$：预测特定动作带来的状态偏移。

**动作均值中心化 (Action-Mean Centering)**
这是实现干扰抑制的核心代数操作。计算当前状态下所有候选动作的平均偏移 $\bar{\Delta}(z_t)$。最终的有效动作通道定义为 $u(z_t, a_t) = \Delta(z_t, a_t) - \bar{\Delta}(z_t)$。任何与动作无关的干扰（共模变化）在计算均值时会被保留，并在相减时被精确抵消。
- 对于离散动作：直接枚举所有动作求严格均值。
- 对于连续动作：通过蒙特卡洛采样（执行动作 + 重放缓冲区采样 + 高斯扰动）抽取 $K=16$ 个候选动作求近似均值。

**即插即用特性 (Plug-in Readout)**
由于中心化本质上是读出阶段的减法操作，它不仅可以作为架构内置，还可以直接应用于任何已冻结的、以动作为条件的第三方世界模型（如 RePo, TIA），在无需重新训练的情况下提取出隐藏的动作通道。

```python
def forward_predictor(z, a, action_space_type, candidate_actions=None):
    # z: 当前潜状态 (Current latent state)
    # a: 实际执行的动作 (Executed action)
    
    # 1. 被动流：预测与动作无关的场景演化
    passive_pred = B_head(z) 
    
    # 2. 动作偏移流：预测给定动作的原始偏移
    raw_offset = Delta_head(z, a)
    
    # 3. 计算候选动作的平均偏移 (共模抑制的核心)
    if action_space_type == "discrete":
        # 离散动作：严格枚举所有可能动作
        all_offsets = [Delta_head(z, act) for act in ALL_DISCRETE_ACTIONS]
        mean_offset = torch.mean(torch.stack(all_offsets), dim=0)
        
    elif action_space_type == "continuous":
        # 连续动作：对 K=16 个候选动作进行蒙特卡洛估计
        sampled_offsets = [Delta_head(z, act) for act in candidate_actions]
        mean_offset = torch.mean(torch.stack(sampled_offsets), dim=0)
        
    # 4. 中心化动作通道 (优势函数风格)
    # 任何与动作无关的干扰(存在于raw_offset和mean_offset中)在此处被减去
    centered_action_channel = raw_offset - mean_offset
    
    # 5. 最终的下一步状态预测
    z_next_pred = passive_pred + centered_action_channel
    
    return z_next_pred, centered_action_channel
```

### 第二模块：核心架构解释

TaskSense 的核心架构是对 DreamerV3 观测接口的侵入式修改，保留了原有的 RSSM 潜变量动力学模型，但在视觉信息进入编码器前增加了一道“智能闸门”。其运行流程可拆解为四个关键步骤：

1. **任务中心化空间注意力 (Task-Centric Spatial Attention)**：利用上一时间步的停止梯度隐状态 $s_{t-1}$，通过轻量级 MLP 预测一个粗粒度网格上的注意力分布，并使用 Binary Concrete 分布采样出离散的掩码 $m_t$。
2. **注意力感知编码 (Attention-Aware Encoding)**：将采样出的掩码上采样至原图分辨率，与原图 $o_t$ 进行逐元素相乘过滤背景。为了防止模型混淆“纯黑像素”和“被遮挡像素”，将掩码作为一个额外的通道拼接后送入编码器提取特征 $f_t$。
3. **辅助逆动力学 (Auxiliary Inverse Dynamics)**：为了防止注意力机制“偷懒”把所有画面都遮挡（导致特征全空），引入一个辅助任务：利用当前特征 $f_t$ 和上一帧特征 $f_{t-1}$ 预测上一时间步执行的动作 $a_{t-1}$。这迫使注意力必须保留与动作控制相关的视觉区域。
4. **条件化重建 (Attention-Conditioned Reconstruction)**：解码器不再重建全图，而是仅重建被过滤后的观测图像。同时，解码器以掩码 $m_t$ 作为条件输入，明确告知解码器哪些区域是被故意遮挡的，从而避免将遮挡归咎于潜变量的表征错误。

**核心逻辑伪代码 (Python 风格)**：

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class TaskSenseObservationInterface(nn.Module):
    def __init__(self, encoder, decoder, action_dim):
        super().__init__()
        self.encoder = encoder
        self.decoder = decoder
        self.attention_mlp = nn.Sequential(nn.Linear(latent_dim, 256), nn.ReLU(), nn.Linear(256, 8 * 8))
        self.inverse_dynamics_mlp = nn.Sequential(nn.Linear(feature_dim * 2, 256), nn.ReLU(), nn.Linear(256, action_dim))
        
    def forward(self, obs_t, state_t_minus_1, feature_t_minus_1, action_t_minus_1):
        # 1. 预测空间注意力 (基于上一帧的隐状态，切断梯度)
        sg_state = state_t_minus_1.detach()
        attn_logits = self.attention_mlp(sg_state).view(-1, 1, 8, 8)
        
        # 使用 Binary Concrete 采样注意力掩码 (训练时随机，推理时确定)
        if self.training:
            mask_t = self.sample_binary_concrete(attn_logits, temperature=1.0)
        else:
            mask_t = torch.sigmoid(attn_logits)
            
        # 上采样掩码至原图分辨率 (64x64)
        mask_up_t = F.interpolate(mask_t, size=(64, 64), mode='nearest')
        
        # 2. 注意力感知编码
        filtered_obs_t = obs_t * mask_up_t
        # 拼接掩码作为额外通道
        obs_with_mask = torch.cat([filtered_obs_t, mask_up_t], dim=1) 
        feature_t = self.encoder(obs_with_mask)
        
        # 3. 辅助逆动力学损失 (预测上一步动作)
        sg_feature_t_minus_1 = feature_t_minus_1.detach()
        action_pred = self.inverse_dynamics_mlp(torch.cat([feature_t, sg_feature_t_minus_1], dim=-1))
        loss_inv = F.mse_loss(action_pred, action_t_minus_1)
        
        # 4. 稀疏性正则化 (鼓励掩码尽可能小)
        loss_sparse = torch.mean(torch.sigmoid(attn_logits))
        
        return feature_t, filtered_obs_t, mask_t, loss_inv, loss_sparse

    def reconstruct(self, state_t, mask_t):
        # 4. 条件化重建 (解码器知道哪些地方被遮挡了)
        sg_mask_t = mask_t.detach()
        reconstructed_filtered_obs = self.decoder(state_t, sg_mask_t)
        return reconstructed_filtered_obs
```

1. **分层手术锚点构建 (Hierarchical Surgical Anchor, HSA)**：接收首帧图像和分层语义掩码（器械、前景组织、背景组织）。通过掩码注意力机制（Masked Attention），将首帧的外观特征与掩码的形状特征融合，输出两个表征：一个是密集的锚点提示（Dense Anchor Hint），用于后续的特征相加；另一个是紧凑的锚点库（Compact Anchor Bank），用于提供区域感知的键值参考。
2. **锚点相对模态专家 (Anchor-Relative Modality Experts)**：针对边缘、深度、光流分别设置独立的专家网络。每个专家首先通过 VACE 编码器提取特征，然后利用紧凑的锚点库对特征进行区域对齐（Region-grounded context），最后通过密集的锚点提示进行调制，输出相对于锚点的控制增量（Control Increments）。
3. **多模态控制专家 (Multimodal Control Expert, MCE)**：根据当前可用的模态输入，利用可学习的阶段缩放因子，将激活的模态增量与密集的锚点提示进行直接相加，生成最终的控制提示（Control Hint），并注入到 Wan2.2 的 DiT 块中。

```python
        self.experts = nn.ModuleDict({
            'edge': ModalityExpert(),
            'depth': ModalityExpert(),
            'flow': ModalityExpert()
        })
        self.mce = MultimodalControlExpert()
        
    def forward(self, first_frame, masks, optional_controls, dit_features):

        # dense_anchor: 密集锚点提示 (Ai)
        # anchor_bank: 紧凑锚点库 (Bi)
        dense_anchor, anchor_bank = self.hsa(first_frame, masks)

        increments = {}
        for modality_name, control_signal in optional_controls.items():
            if control_signal is not None:

                # 提取模态特征并利用 anchor_bank 进行区域对齐，利用 dense_anchor 进行调制
                increment = expert(control_signal, anchor_bank, dense_anchor)
                increments[modality_name] = increment

        # 将 dense_anchor 与各模态增量按阶段缩放因子相加
        control_hint = self.mce(dense_anchor, increments)
        
        # 4. 注入 DiT 骨干网络
        updated_dit_features = dit_features + control_hint
        
        return updated_dit_features

class ModalityExpert(nn.Module):
    def forward(self, control_signal, anchor_bank, dense_anchor):

        region_context = attention(q, k, v)

        increment = self.anchor_modulation(region_context, dense_anchor)
```

2. **策略端世界技能（World Skill）注入**：包含任务级先验策略（Task Skill）和步骤级纠错指导（Corrective Guidance）。在每个决策步，系统根据当前状态检索纠错规则，指导冻结的策略模型生成合法的候选动作。

4. **防御干预 (CPV Gate)**：在消息被下游重用前，强制拦截并校验该声明是否具有本地传感器证据支持，若无则打上“未验证”标签。

```python
def communication_attack_episode(attacker_type, architecture, target_slot, robot_team):
    # 1. 构建伪装成合法协作内容的恶意声明
    seed_claim = craft_malicious_claim(target_slot)
    
    if attacker_type == "EXTERNAL":
        # 外部攻击：只能接触边缘节点，需诱导其背书
        entry_robot = robot_team.get_exposed_node()
        response = entry_robot.query(seed_claim)
        carrier_msg = architecture.format_dispatch(entry_robot, response)
        
        # 检查边缘节点是否将恶意声明转化为内部协调消息
        if not is_endorsed(carrier_msg):
            return "Attack Failed at Entry"
            
    elif attacker_type == "PRIVILEGED":
        # 内部特权攻击：直接利用受控节点发送合法载体
        compromised_robot = robot_team.get_internal_node()
        carrier_msg = architecture.pack_legal_carrier(compromised_robot, seed_claim)

    # 2. 架构原生分发与下游吸收
    system_trace = architecture.propagate(carrier_msg, robot_team)
    
    # 3. 评估物理动作转化率
    unsafe_actions = extract_physical_violations(system_trace, target_slot)
    
    return calculate_propagation_metrics(unsafe_actions)

def cpv_gate_defense(message, local_sensor_evidence):
    # 核心防御逻辑：切断无物理证据的信任链
    if not verify_evidence_match(message.claim, local_sensor_evidence):
        message.annotate_metadata(status="UNVERIFIED", warning="Lack of local observation")
    return message
```
