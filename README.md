# Embodied Daily Papers

This repository is the generated data store for the arXiv daily papers workflow. It stores downloaded PDFs, Markdown daily reports, and the cumulative paper index for embodied AI, world models, and autonomous driving related papers.

## Contents

| Path | Purpose |
|---|---|
| `reports/` | Daily Markdown reports generated by the workflow |
| `pdfs/` | Downloaded paper PDFs grouped by report date |
| `papers_index.json` | Cumulative paper index used for deduplication and later analysis |
| `papers_index.json.bak` | Backup copy of the paper index |
| `.obsidian/` | Local Obsidian vault settings for browsing reports |

Current local contents include 58 report files from `2026-03-24.md` through `2026-06-23.md`, 861 downloaded PDFs, and a multi megabyte cumulative paper index.

## Relationship To The Workflow

This repository is consumed as the `data/` submodule of `research/arxiv-daily-papers-workflow/`. The workflow reads `papers_index.json` to avoid reprocessing papers, writes new Markdown reports under `reports/`, downloads PDFs under `pdfs/`, commits this repository, and then updates the parent workflow repository to the new submodule revision.

## Report Format

Each daily report starts with an overview table that summarizes paper counts, direction distribution, and top score. Papers are grouped into core and peripheral categories. Entries normally include the title, score, direction label, authors, arXiv link, PDF link, and optional Chinese translation link.

## Maintenance

Do not edit generated reports by hand unless the goal is to correct a known generation error. Manual edits can make future comparisons harder because the workflow treats this repository as generated state. If a report needs to be regenerated, update the workflow code or configuration first, then rerun the workflow with a controlled paper index state.

## Storage Notes

PDF files dominate repository size. Before adding new binary formats or local reader caches, check whether the file belongs in this generated data repository. Obsidian settings can stay local when they only affect personal viewing, but large plugin caches and workspace snapshots should not be added.
